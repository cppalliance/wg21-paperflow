## False-pass hypothesis

A conversion with **correct multiset unigram recall (≥0.85)**, passing structural gates, and **scrambled table cell content** passes the default score path. Evidence: `_decide` has no table or fact gate (`score.py:156-184`); Lane 3 designed to catch this (`CLAUDE.md:37-40`) but **not deployed** (`00` §4). `table_score` on the oracle path can still show high TEDS when both sides lack pipe tables (`bench.py:154-155` → `1.0`), masking table loss in displayed `ref_teds`/`ref_overall`.

## False-fail hypothesis

**P3941R2/R3/R4**: `uni=0.999`, `drift=0.001`, hard-fail solely on `heading_monotone` H2→H4 (`00` §3c; `gates.py` heading monotonicity gate). Docs say hard fail means "broken" or "content missing" (`CLAUDE.md:211-215`); code hard-fails on **structural pedantry** with near-perfect content metrics — undocumented tension between prose ("genuinely missing words") and gate breadth.

## What would change my mind

A **doc-audit CI check** that greps for known contradictions (oracle "primary/drives verdict" vs `_decide`, "verbatim"/"no external deps", Lane 3 "LLM" vs `facts.py`) and fails on drift; plus regenerating `data/whisker/report.json` at schema 3 with a README note that score artifacts are **write-only, never validated on read** — or adding schema rejection when loading reports for `--baseline` / human dashboards.
