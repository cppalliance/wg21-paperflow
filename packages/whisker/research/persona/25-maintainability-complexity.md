# 25 - The Maintainability / Complexity Reviewer

**Verdict:** usable-with-conditions — the reference-free gate path is coherent and small enough to trust in isolation, but the shipped package is a ~4145-LOC, 15-module, 3-lane benchmark suite whose lanes 1/2/3 and heavy metric stack are unit-tested yet inoperable on real data (empty corpus), inflating cognitive load and dependency surface without currently buying verdict accuracy.
**Confidence:** high

## Findings

- [HIGH] **~60% of source LOC is dead on the only operational path today.** Evidence: `00-EVIDENCE-BASELINE.md` §4 (corpus has only `README.md` + `EXAMPLE.facts.jsonl`; `golden`/`bench`/`facts` all error); module sizes in `00` §1 — `facts.py` 405, `guard.py` 376, `match.py` 248, `anchors.py` 197, `golden.py` 155, `calibrate.py` 161, plus the bulk of `metrics.py` 573 (TEDS/MHS APTED port) and `bench.py` 273 are reachable only via `whisker bench|guard|golden|facts|calibrate`, not `whisker [PID]` / `--all`. Impact: a maintainer must understand three lanes, Hungarian block matching, and guard baseline semantics to change a gate that only touches `gates.py` (134 LOC) + `score.py:_decide` (118–184) + tomd imports; the extra code is speculative infrastructure, not operational QA.

- [HIGH] **`__main__.py` (794 LOC) is a six-subcommand monolith with duplicated corpus wiring.** Evidence: `__main__.py:123-267` `_score_main` (~145 LOC operational); `288-341` bench, `344-459` guard, `587-652` golden, `671-732` facts, `795-885` calibrate — five additional CLI surfaces in one file; duplicate facts iteration at `493-499` (`_run_fact_checks`) vs `698-710` (`_facts_main`); duplicate `*.gt.md` corpus walks at `277-284`, `567-584`. Impact: any CLI fix (exit codes, `--fail-on-new`, anchor conjunctive guard at `426-444`) requires navigating ~670 LOC unrelated to the default score verb; regression risk is structural, and the file violates the package's own "library returns data; CLI persists" split by also owning five lane-specific renderers (`503-533`, `655-668`, `735-750`).

- [HIGH] **Default oracle path adds a second full conversion per paper for advisory signal that mostly creates review noise.** Evidence: `reference.py:45-65` runs markitdown on every scored paper when `reference_engine` is set (`score.py:283-284`); `_decide` only soft-flags `ref_nid` (`score.py:175-178`), never hard-fails; `00` §3b mean `ref_nid=0.836`, **147/382** advisory flags vs ref-free **205 review** (`00` §3a). Impact: operational complexity (markitdown dep, slower `--all`, teds/mhs computed at `score.py:213-215` but never gated per `CLAUDE.md`) without changing the trustworthy hard gate; maintainers must explain why default runs an expensive path the spec demotes to "LOOK, not wrong."

- [MED] **Heavy benchmark dependencies are bundled into the QA gate package even for `--no-reference`.** Evidence: `pyproject.toml:8-19` pulls `apted`, `lxml`, `grits-metric`, `numpy`, `scipy`, `mistune`, `pylatexenc`, `rapidfuzz`, `markitdown[pdf]` for all installs; ref-free `score_paper(..., reference_engine=None)` (`score.py:275`) never imports `match.py` or runs TEDS, yet `metrics.py` still loads APTED/lxml/mistune at import time. Impact: install surface, upgrade risk, and import-time cost for a CI gate that could be `tomd.check_content` + `gates.run_gates` + threshold compare (~400 LOC); the current layout optimizes for a labeled-corpus future that `00` §5 says was never calibrated.

- [MED] **Inverted module layering: metrics imports a private gate helper.** Evidence: `metrics.py:43` `from whisker.gates import _split_front_matter`; used at `metrics.py:594` inside `_parse_headings` (MHS path). Impact: `gates.py` (tier-0 structural checks) is coupled to the largest module (`metrics.py` 573 LOC); extracting or testing gates in isolation requires dragging the TEDS/MHS stack; a smaller tool would put shared front-matter parsing in one neutral helper, not a private symbol crossing tier boundaries.

- [MED] **`__init__.py` re-exports the entire 15-module public surface (104 LOC), maximizing coupling for any importer.** Evidence: `__init__.py:10-55` imports anchors, bench, calibrate, facts, golden, guard, match, metrics, guard baselines, etc.; `__all__` lists 40+ symbols (`57-106`). Impact: `import whisker` pulls every lane's types into one namespace; library consumers cannot depend on the operational core without inheriting dead-lane API promises; cognitive load for "what is whisker?" conflates a nightly QA gate with a full OmniDocBench-style benchmark framework.

- [LOW] **Scope expanded beyond the red-team guard/calibrate hardening pass without corpus validation.** Evidence: `notes/redteam-synthesis.md` Tier 3 deferred "exact golden lane" and "substring anchors" (~17/28 and ~8/28 agents); both are now built (`golden.py`, `anchors.py`, wired in `__main__.py:426-444`). `00` §4 shows zero real members. Impact: maintainability debt from implementing deferred Tier-3 features before the Tier-1 prerequisite (labeled micro-corpus) exists; each adds tests (`test_golden.py` 61, `test_anchors.py` 105) that green-light code paths never exercised on production data.

## False-pass hypothesis

A WG21 table with **one wrong body cell** (`| 1 | 9 |` vs `| 1 | 2 |`) on an otherwise clean paper: `unigram_coverage` stays ≥ 0.85 (`UNIGRAM_COVERAGE_FAIL_EDGE`, `constants.py:37`), structural gates pass (`gates.py:153-162`), and ref-free review may not fire if region count stays below noise. Lane 2 `teds` would catch it (`bench.py` table axis) but **bench cannot run** (`00` §4). Whisker **passes** on the only operational path while semantic table content is wrong — the 3-lane design would catch this, but it is not deployed.

## False-fail hypothesis

**P3941R2/R3/R4-class papers**: `uni=0.999`, `drift=0.001`, hard-fail solely on `heading_monotone` H2→H4 (`00` §3c; gate at `gates.py:105-109`). Separately, **186/382** papers hit review for `REGION_SOFT_COUNT=1` (`constants.py:47`, `score.py:164-166`; `00` §3a) despite spec marking misaligned regions as expected on clean papers (`CLAUDE.md` soft signals). Good conversions are buried in a 54% review majority — complexity in `_decide`'s soft-flag stack (`score.py:149-184`) without calibrated precision.

## What would change my mind

Either **(a)** a populated micro-corpus (≥10 labeled papers with `<pid>.gt.md` + facts) where lanes 1/2/3 demonstrably catch failures the ref-free gate misses, justifying the ~2500 LOC bench stack — or **(b)** a deliberate split into `whisker-core` (ref-free gate, ~800 LOC, tomd-only deps) and `whisker-corpus` (lanes 2/3, optional extra), with the default install/CI path using only (b)'s absence. Either proof would flip "over-built for current operational reality" to "right-sized for measured QA coverage."
