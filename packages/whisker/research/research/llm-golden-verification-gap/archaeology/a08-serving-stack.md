# a08 - Archaeologist: concurrency-381 + slots-32-regression

**Verdict:** usable-with-conditions (+ the two corpora precisely document throughput ceilings and MoE/batch-induced verdict drift, but they do not explain PR #286/#295 recall=0 misses; flip-rate mechanism is partially serving-mediated, not fixable by client tuning alone)
**Confidence:** high

## Findings

- [CRITICAL] **Serving stack has a proven optimal envelope: server `--max-num-seqs 16` + client `--concurrency 32`.** Evidence: `research/slots-32-regression/SYNTHESIS.md:7-14,53` (381 papers: 692.3 s at server=16/client=32 vs 1090.2 s at server=32/client=32; isolation test client c=16 on 32-slot server = 763.7 s); `packages/whisker/src/whisker/tapetum_llm/cli.py:115-121` (`_DEFAULT_CONCURRENCY = 32` with comment citing 692.3 vs 722.4 s). Impact: throughput is solved and documented; golden-PR verification failures are not latency-starvation artifacts under this config. Answer-class: **5**.

- [CRITICAL] **MoE expert-union decode scaling, not KV preemption or cold start, caused the slots-32 regression.** Evidence: `research/slots-32-regression/11-moe-batch-scaling.md:8-12` (ELDR: active-expert union drives per-step HBM traffic; +57% matches ~1.6× decode penalty); `research/slots-32-regression/10-kv-preemption.md:64-68` (15 GiB peak KV vs 111+ GiB pool; `num_preemptions_total 0`); `research/slots-32-regression/12-cold-start.md:16-22` (warm rerun 1465.2 s > cold 1090.2 s). Impact: "raise server slots for more recall parallelism" is a dead end; operator reverted to 16 (`research/slots-32-regression/SYNTHESIS.md:47-48`, `tapetum_llm.md:285`). Answer-class: **3** (infra ceiling on batch composition, not model IQ alone).

- [CRITICAL] **Unbounded client fan-out (c=381) is a documented catastrophic failure mode, separate from the >=25% flip rate.** Evidence: `research/concurrency-381/12-runpod-proxy.md:9-11` (~100 s Cloudflare origin-response ceiling on idle streams); `research/concurrency-381/11-client-timeouts.md:14-16` (600 s httpx read on tail queue); `packages/whisker/research/llm-batching/20-sweep-results.md:105-113` (live c=381: **257/381 errors**, `peer closed connection`). Impact: coverage gaps from infra errors are real but distinct from PR #286/#295 where runs completed with 0 generated claims (`00-baseline.md:50-55,74-75`). Answer-class: **4** (missing sidecar when timeout/proxy kills a paper; not the zero-claim pathology).

- [HIGH] **Verdict flips persist on identical reruns at the optimal config; serving research attributes mechanism to batch/MoE non-invariance, not queue depth alone.** Evidence: `packages/whisker/research/llm-batching/20-sweep-results.md:31-40` (identical c=32 reruns on 20 PIDs: 15 pass/5 review vs 10 pass/10 review; flips also between c=3 and c=8 baselines); `MODELS.md:77-78` (vLLM flips argmax tokens when batch size changes; fix is `VLLM_BATCH_INVARIANT_LEVEL`, not deployed on alliance-pod); `packages/whisker/src/whisker/CLAUDE.md:553-555` (>=25% flip rate documented). Impact: flip rate is **not** independent of serving (continuous batching + MoE routing are serving-layer phenomena) but **is not eliminated** by the proven 16/32 config or by avoiding c=381; it requires batch-invariant kernels or accepting advisory-only semantics. Answer-class: **3**.

- [HIGH] **Client-side mitigations were implemented; server-side batch-invariant mode and httpx timeout overrides were not.** Evidence: implemented — `cli.py:126-132` (`_PAPER_TIMEOUT_SECONDS = 900.0`), `cli.py:123-126` (`_MAX_TESTED_CONCURRENCY = 32` + warning at `1012-1018`), health gate and shared registry per `20-sweep-results.md:46-49`; documented dead ends — `tapetum_llm.md:281-289` (c>32, server 32, c=381, dual-pod); not implemented — `packages/pipeline/src/pipeline/model_backends.py:283` (still default `AsyncOpenAI` 600 s read, no `timeout=` override); no `VLLM_BATCH_INVARIANT` in `SERVICES.toml:64-74` or pod template references. Impact: wall-clock and proxy-timeout class partially mitigated; token-level rerun stability left to MoE/batch luck. Answer-class: **3**, **5**.

- [MED] **slots-32-regression measured verdict histogram drift co-timed with server config, confirming serving changes verdict distributions even without client code changes.** Evidence: `research/slots-32-regression/14-client-skeptic.md:18` (252/118/10 pass/review/fail at server=16 vs 237/130/13 at server=32; client diff ruled out); `research/slots-32-regression/13-prefill-interference.md:59-59` (+57% wall matches 1.57× MoE ratio, not pure 2× prefill stall). Impact: operator must keep server at 16 for both throughput **and** distribution stability; still does not explain missing table-cell or secno claims on successful runs. Answer-class: **3**.

- [MED] **Scheduler semantics cap GPU parallelism at 16 regardless of HTTP admission.** Evidence: `research/concurrency-381/10-vllm-scheduler.md:8-12` (`--max-num-seqs 16` caps sequences per step; unbounded FCFS queue); `research/concurrency-381/20-batch-alternatives.md:8-20` (no vLLM 0.24 batch API; bounded fan-out is optimal client pattern). Impact: "more concurrent papers" does not give the model more attention per unit; PR #286's `MAX_UNIT_CHECKS=5` displacement is a **whisker routing** cap, not a vLLM slot cap. Answer-class: **2** (orthogonal starvation mechanism).

- [LOW] **Prefix caching and prefill contention are second-order on this workload.** Evidence: `research/concurrency-381/10-vllm-scheduler.md:22` (<1 s/call warm prefix); `research/slots-32-regression/13-prefill-interference.md:87-89` (8192 token budget not co-raised with seq 32). Impact: tuning noise for full-corpus runs, not root cause of golden recall gap. Answer-class: **5**.

## False-pass hypothesis

Operator reruns golden-PR review at `--concurrency 381` expecting hourly-pod "free queue" (`research/concurrency-381/20-batch-alternatives.md:20`): RunPod proxy kills ~67% of connections (`20-sweep-results.md:108-109`), surviving tail gets sparse adjudication, footer shows errors not fails, and incomplete corpus is mistaken for "LLM cleared the rest." Serving corpora predict this; PR #286/#295 false-clears occurred on **successful** full adjudications, not timeout gaps.

## False-fail hypothesis

Paper adjudication succeeds but `suggested_verdict` flips `pass`→`review` on rerun solely because MoE batch composition changed at client c=32 (`20-sweep-results.md:31-37`, `MODELS.md:77-78`): operator treats advisory drift as a new defect signal. This is false-fail at the **verification-contract** layer (unstable judge), not a deterministic gate failure; serving research says batch-invariant mode or `--concurrency 1` is required for rerun-comparable distributions.

## What would change my mind

A triple rerun of the PR #286/#295 papers at `--concurrency 1` with pod `VLLM_BATCH_INVARIANT_LEVEL` enabled showing (1) flip rate ≤1% on verdict, (2) non-zero generated claims for poll-table and secno defects, and (3) grounded evidence surviving `grounding.py` — would downgrade class 3 and implicate serving as the dominant recall blocker. Without that, the concurrency/slots corpora stand as throughput/stability engineering, not a recall fix for the baseline's human-verified blockers.
