# a06 - Archaeologist: vlm-pdf-qa

**Verdict:** usable-with-conditions — the vlm-pdf-qa corpus correctly identifies token-preserving table corruption as the PDF-lane target and built a ~793 LOC dormant second-converter stack, but it never ran on P1068R11 pages 8–9 and the shipped diff uses whole-document text metrics that may not fire on localized wrapped-cell errors.
**Confidence:** high

## Findings

- [CRITICAL] The vlm-pdf-qa synthesis rejected VLM-as-judge (image+markdown) and recommended **Contender C**: olmOCR-class per-page transcription from pixels, then a **deterministic diff** vs tomd markdown, fused advisory-only. Evidence: `research/vlm-pdf-qa/SYNTHESIS.md:6-8,18-26`; `research/vlm-pdf-qa/opus-B-architecture.md:40-48,59-61`. Impact: the research directly names **token-preserving cell swap** as the defect class the PDF lane exists to catch (`SYNTHESIS.md:8`, `opus-B-architecture.md:76`), matching PR #286's wrapped `SF`→`S` poll-header failure in `research/llm-golden-verification-gap/00-baseline.md:41-55`. Answer-class: **1** (contract lives in human golden skill, not in lane prompts) plus **5** (incremental recall unproven without holdout).

- [CRITICAL] A full VLM stack was implemented but is **dormant**: rasterize → transcribe → diff, with whisker-local multimodal dispatch avoiding pipeline changes. Evidence: `packages/whisker/src/whisker/tapetum_llm/vlm_pipeline.py:8-15,39-93`; `vision.py:15-16,55-99`; `transcribe.py:25-26,100-141`; `vision_task.py:23-26,107-156`; `vlm_diff.py:21-22,124-200`; audit inventory `packages/whisker/research/Audit/Auditv1/code-c24-vlm-boundary.md:8-16`. Impact: the codebase already contains the architecture the corpus recommended, but zero production path invokes it. Answer-class: **2** (production lane chose text-layer judge instead) and **5** (goal of "always PDF" deferred pending infra).

- [CRITICAL] Production `whisker-tapetum-llm` dispatches PDF papers to **`pdf_judge` (PyMuPDF text layer)**, not `vlm_adjudicate_paper`. Evidence: `packages/whisker/src/whisker/tapetum_llm/cli.py:1034-1074,1111-1118` (`use_pdf_judge = kind == "pdf" and judge_agent is not None` → `judge_pdf_extraction(...)`); no import or call of `vlm_adjudicate_paper` anywhere in `cli.py` (confirmed `code-c24-vlm-boundary.md:38-39`). `textlayer.py:10-11` explicitly positions text extraction as the alternative to `vision.py + transcribe.py`. Impact: PR #286 pages 8–9 were eligible for **text-layer** unit judging but starved by `MAX_UNIT_CHECKS=5` (`00-baseline.md:46-49`); a wired VLM lane would not inherit that cap but was never an option at runtime. Answer-class: **2**.

- [HIGH] **No runtime experiment** shows VLM pages 8–9 would catch P1068R11's wrapped `SF` cell; Audit `*.readback*.md` files are **markdown comprehension readback**, not VLM pixel readback. Evidence: `readback.py:8-14` (blind Q&A on converted markdown + facts corpus); `p4182r0.readback.md:87-107` (table-cell questions PASS on **clean** converted markdown via text pod, no page images). `test_vlm_lane.py:94-95` states no test calls `vlm_adjudicate_paper` with a real PDF or vision endpoint (`code-c24-vlm-boundary.md:94-95`). Impact: the corpus **predicts** C should catch token-preserving swaps (`18-product-decision-skeptic.md:14`, `SYNTHESIS.md:35`) but the flip condition requires a ≥30-paper holdout (`SYNTHESIS.md:51-52`) that was never run on P1068R11. Answer-class: **3** and **5**.

- [HIGH] Even if wired, the built `diff_vlm_vs_tomd` compares **whole-document** `text_nid` / `content_recall` / optional `mhs`, not per-page or table-grid diff. Evidence: `vlm_diff.py:140-144,153-171` (concatenated `transcription.full_text` vs full tomd markdown; thresholds `NID_PASS_THRESHOLD=0.85`, `RECALL_FAIL_THRESHOLD=0.70` at `:50-59`). `transcribe.py:91-93` concatenates pages with `\n\n` but diff does not isolate pages 8–9. Impact: six `S` vs `SF` header errors across a multi-page WG21 paper may stay above pass thresholds (same failure mode as det `unigram_coverage` blindness, `18-product-decision-skeptic.md:14`); corpus v2 deferral explicitly triggers fallback judge **iff** C's diff misses token-preserving corruption (`opus-B-architecture.md:61`, `SYNTHESIS.md:32`). Answer-class: **1** (no table-cell compare contract in diff) and **3**.

- [HIGH] VLM was left dormant because **no vision-capable service exists** and wiring was blocked by package-boundary policy, while the text PDF judge shipped first. Evidence: `research/vlm-pdf-qa/00-baseline.md:72-74` (no `vision_capable` in `SERVICES.toml`); `vision_task.py:10-18,23-26` ("pipeline framework is text-only by design… stays unmodified"; "no vision endpoint deployed"); `.cursor/rules/package-boundary.mdc:7-14` (Jul 2026 revert of pipeline multimodal changes); `packages/whisker/src/whisker/CLAUDE.md` Known gaps #4 ("788 LOC… never reached integration"). Impact: the recall loss on PR #286 is explained by the **active** text-layer lane's routing starvation, not by a failed VLM run—the VLM lane was never in the race. Answer-class: **2** and **5**.

- [MED] The markdown-grounding contract that swallows image-only judge findings **does not apply** to Contender C, but the **production source-aware text lane still uses** `ground_spans` against markdown. Evidence: `research/vlm-pdf-qa/opus-B-architecture.md:15-16,76`; `grounding.py:170-240` cited in synthesis; `00-baseline.md:50-55,84-85` (PR #286: 0 accepted defect groups after evidence verification). Impact: wiring VLM diff would sidestep class **4** for the converter path, but the shipped lane remains verification-asymmetric for generated claims. Answer-class: **4**.

- [LOW] `readback.py` / `readback_cli.py` are a **separate** comprehension-validation tool (Lane 3), not part of the VLM PDF stack. Evidence: `readback_cli.py:8-12`; `CLAUDE.md` whisker-readback section. Impact: Audit readback artifacts validate facts-on-markdown, not PDF pixel QA; they cannot be cited as evidence that VLM would have caught PR #286. Answer-class: **5**.

## False-pass hypothesis

P1068R11 with VLM lane wired: olmOCR transcribes poll headers as `SF` from pages 8–9 pixels, tomd candidate has `S`; whole-document `diff_vlm_vs_tomd` returns `text_nid ≥ 0.85` and `verdict=pass` because six header tokens are drowned by thousands of agreeing tokens (`vlm_diff.py:136-137,207-208`), fusion sees det=pass + tapetum=pass → no escalation (`fusion.py:217-227`), operator ships the same golden-PR blocker the text lane missed.

## False-fail hypothesis

Faithful P1068R11 conversion where olmOCR at `TARGET_PIXELS=2_073_600` (`vision.py:40-45`) mis-reads a math glyph on page 13 while pages 8–9 are correct: whole-document `text_nid` drops into the ambiguous band → `verdict=review` (`vlm_diff.py:211-212`), fusion escalates a clean golden candidate to advisory review without naming the real wrapped-cell defect (noise in the wrong axis).

## What would change my mind

A recorded run of `vlm_adjudicate_paper("P1068R11", …)` against PR #286 head bytes with a live olmOCR-class vision pod, persisting per-page transcriptions for pages 8–9 showing `SF` in the VLM text and `S` in tomd, and either (a) `diff_vlm_vs_tomd` returning `fail`/`review` with axis notes citing those pages, or (b) a demonstrated per-page diff patch that fires while whole-document metrics stay green—would flip the verdict to **usable** and downgrade answer-class **5** for this defect class.
