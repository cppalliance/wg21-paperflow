# a05 - Archaeologist: per-page-judging

**Verdict:** usable-with-conditions — the swarm correctly refuted naive 33× per-page LLM and specified a sound deterministic-screen + scoped-escalation hybrid, but v6 source-aware unit routing (severity-then-lexical cap) landed outside that corpus and directly reproduces the PR #286 budget-displacement failure mode the research never scheduled.
**Confidence:** high

## Findings

- [CRITICAL] **The corpus verdict was explicit: NOT the planned 33× per-page LLM judge.** `research/per-page-judging/SYNTHESIS.md:4-6` records `adopt-partially - NOT the planned 33x per-page LLM judge; instead a deterministic per-page recall screen + scoped LLM escalation on flagged pages only, keeping the monolithic call for global checks.` Three independent refutation lines: worst-page-wins noise math (`1-(1-p)^n`, 1%/page → 28.1% doc review at n=33, `20-false-fail-hunter.md:8`), cost (33 serial calls ≈ 4.4–15 min/paper vs ~20 s monolith; 189-PDF corpus ~15.8 h vs ~1.3 h, `21-steelman-monolith.md:12`), and p0957r8 already closed by det+fusion (`21-steelman-monolith.md:8`). Impact: the research rejected exhaustive per-page absence detection as the primary architecture; PR #286's miss is not a failure to implement 33× judging but a failure mode in the successor design. Answer-class: 5.

- [CRITICAL] **What the corpus specified landed as the screen+escalation path, not as `source_router`/`unit_judge`.** Hybrid design at `SYNTHESIS.md:46-65`: (1) `screen_pages()` deterministic recall per page, (2) unchanged monolith, (3) scoped LLM only on flagged pages with full conversion contract, (4) aggregation where det screen cannot be silently upgraded. Implemented: `pdf_judge.py:311-336` (`screen_pages`, `PAGE_RECALL_FLOOR`), `pdf_judge.py:625-629` (screen before monolith, cites SYNTHESIS), `pdf_judge.py:721-751` (`MAX_PAGE_ESCALATIONS` cap, `_escalate_page`), `constants.py:167-197` (`PAGE_RECALL_FLOOR=0.90`, `PAGE_MIN_TOKENS=50`, `MAX_PAGE_ESCALATIONS=5`, calibration comment p0957r8 page 13 at 0.8810 vs healthy worst 0.9129). Impact: the per-page-judging recommendation is partially live on the PDF lane; PR #286 poll-table defect (token-preserving cell corruption) never triggers this screen (baseline: page screen flagged 0, recall not below floor). Answer-class: 2.

- [CRITICAL] **v6 unit routing is a separate layer the per-page-judging corpus did not design; it is what displaced pages 8/9 on PR #286.** `source_router.py:149-233` (`route_pdf_units`: `low_recall` severity `high` at `:196-204`, `token_delta`/`missing_captions`/`heading_drift` at `medium`; never reads `PageUnit.has_tables` though field exists at `textlayer.py:86-98`). `unit_judge.py:225-240` sorts signals by severity then **lexical `unit_id`**, takes first `MAX_UNIT_CHECKS`. `constants.py:223-226`: `MAX_UNIT_CHECKS = 5`. Runtime (baseline): P1068R11 routed pages 1,2,3,4,5,6,8,9,13; checked 1,2,3,4,13; **pages 8/9 routed but displaced** because `page:13` sorts before `page:2` lexically at equal severity. Impact: class-2 budget starvation is implemented code, not a model miss; the archaeology corpus cannot claim credit for this scheduler. Answer-class: 2.

- [HIGH] **Cost/quality tradeoff argued in the corpus favors ~1+k calls and deterministic triage over LLM enumeration.** SYNTHESIS `:69-70`: corpus stays ~1.5 h; wall-clock grows only when det flags a page. Steelman `:12-13`: per-page is overnight-batch, not same-session QA. False-fail hunter `:8`: fixing one 3% false-pass can trade for ~28% false-review if per-page precision is only 99%. Impact: raising `MAX_UNIT_CHECKS` without better signal precision (noted post-hoc in `PR286-LLM-FALSE-CLEAR.md:725,899`) repeats the same tradeoff the corpus already rejected for 33× calls. Answer-class: 2.

- [HIGH] **The corpus foresaw cap overflow on flagged pages but NOT v6 unit-check displacement of true-defect pages.** SYNTHESIS escalation path caps at 5 flagged pages (`constants.py:191`, `pdf_judge.py:726-738`: exceed cap → review without escalation calls). ## False-pass hypothesis

P1068R11 poll-table `SF`→`S` on pages 8–9: `route_pdf_units` emits nine medium `heading_drift` signals on pages 1–6 (`source_router.py:218-231`); `run_unit_checks` selects pages 1, 2, 3, 4, 13 under `MAX_UNIT_CHECKS=5` (`unit_judge.py:239`, baseline runtime); pages 8/9 never checked; no `table_cell` or `has_tables` signal exists (`source_router.py:149-233` vs `textlayer.py:94`); all five unit checks return empty defects; fusion `source_aware_review_cap` fires on incomplete coverage, not detection (baseline: 0/1 true-positive groups). Same outcome if the dropped 33× per-page design had been built: document recall stays high, attention lottery on page 8/9 calls still possible (`19-false-pass-hunter.md:10-11`).

## False-fail hypothesis

Implementing the rejected 33× worst-page-wins design on a 33-page wording paper: page 1 raw title block vs YAML front matter false-flags (`20-false-fail-hunter.md:10`), TOC pages false-flag dotted entries (`:12`), vector-figure axis labels false-flag as missing (`:18`); at 1%/page false-flag rate, document-level false-review ≈ 28.1% (`:8`). The adopted screen path avoids this by escalating only sub-floor recall pages with inherited contract (`SYNTHESIS.md:71-74`), but v6 unit routing reintroduces heading-noise false-work without the recall-floor filter.

## What would change my mind

A git archaeology showing `MAX_UNIT_CHECKS`, `route_pdf_units`, and severity-then-lexical selection were designed in the same commit series as `research/per-page-judging/SYNTHESIS.md` with an explicit displacement hazard analysis for table-heavy pages — or a labeled replay where the screen+escalation path alone (no unit router) catches P1068R11 pages 8/9 at ≤10% doc-level false-review. Neither exists in the per-page-judging corpus or baseline runtime.
