# r01 - Repo miner: olmocr

**Verdict:** usable-with-conditions — olmOCR-bench is the best open deterministic fact-assertion reference, but it achieves recall by pre-authoring ~7k JSONL facts (often LLM-drafted then human-reviewed), not by runtime LLM verification; it cannot be copied as a path to "100% LLM golden verification."
**Confidence:** high

## Findings

- [CRITICAL] **Eval never reads the PDF source; every scored check is `test.run(candidate_md)` on page-level markdown files.** `TableTest.run`, `FormatTest.run`, and all other types take only the converter output string (`tests.py:376-388`, `benchmark.py:109-116`). There is no PyMuPDF/text-layer pass, no coordinate geometry, and no HTML-source diff at score time. Impact: olmOCR would miss PR #286's wrapped `SF`→`S` defect unless a human (or LLM miner) already authored a `TableTest` with `"cell": "SF"` in JSONL; the same contract-encoding gap as whisker's missing table-cell compare (`00-baseline.md:54-55`). Answer-class: 1.

- [CRITICAL] **Markdown pipe-table parsing assumes every cell is 1×1; vertically stacked/wrapped glyphs become separate cells with no merge logic.** `parse_markdown_tables` builds row specs with hardcoded `"rowspan": 1, "colspan": 1` for every pipe cell (`table_parsing.py:304-311`, `328-331`). README acknowledges merged-cell facts need HTML `<table>` output (`README.md:265-266`). Impact: poll-header wrap where PDF geometry has `S`+`F` at one x-column but pipe output shows `S` in one cell cannot be asserted as a single `"SF"` cell without HTML spans or a human-authored fact; matches PR #286 blocker class. Answer-class: 1.

- [HIGH] **Table facts are LLM-produced during corpus mining, not verified against PDF text at authoring time.** `mine_tables_gpt.py` renders a page PNG, asks GPT-4o to emit HTML tables (`mine_tables_gpt.py:131-150`), flattens cells via `cell.get_text().strip()` (`mine_tables_gpt.py:171-172`), then asks GPT-4o again (with the same PNG) for neighbor strings (`mine_tables_gpt.py:266-287`). Expected values are vision-model readings, not PDF span assembly. Impact: if GPT misreads vertical wrap as `"S"`, the authored `TableTest` encodes the error; deterministic eval then "verifies" the wrong ground truth. Whisker tapetum_llm has the inverse failure (never generates the claim). Answer-class: 1.

- [HIGH] **No LLM/VLM acts as output verifier at benchmark or GRPO reward time; only deterministic `test.run()` decides pass/fail.** Benchmark loop: `passed, explanation = test.run(md_content)` (`benchmark.py:116-117`). Training reward: `test_passed, failure_reason = test.run(completion)` (`grpo_train.py:644-645`). README: "All facts checked about documents are either pass/fail" with no judge model (`README.md:250-251`). GPT/Gemini/Claude appear only in offline test curation (`README.md:218-234`). Impact: olmOCR confirms ecosystem norm (`00-baseline.md:82`): LLM for triage/authoring, not recall-complete verification; whisker's goal mis-spec if interpreted as LLM lane alone. Answer-class: 5.

- [HIGH] **`FormatTest` would false-clear bikeshed-style numbered headings the same way whisker `html_outline` does.** It regex-extracts heading body text (`tests.py:263-275`), runs `normalize_text` on both sides (`tests.py:311-314`), then `fuzz.partial_ratio(search_text, formatted_text)` (`tests.py:319-326`). A candidate `## 1. Abstract` matches a fact with `"text": "Abstract", "format": "heading"` because the secno prefix remains inside the extracted heading string. Impact: olmOCR has no golden-contract rule for secno stripping; PR #295 class defect would pass a format fact unless authors encode the stripped title explicitly. Port target: `packages/whisker/src/whisker/tapetum_llm/html_outline.py` needs explicit normalization, not copy-paste of `FormatTest`. Answer-class: 1.

- [MED] **Benchmark has no inspection budget or severity routing; default run evaluates every loaded test on every page (inverse of whisker starvation).** All tests submit to `ThreadPoolExecutor` (`benchmark.py:141-143`). `load_tests` does not filter on `checked: verified` (`tests.py:843-867`, `benchmark.py:223-230`). Optional `--sample N` randomly subsamples for dev only (`benchmark.py:189`, `256-262`). Corpus closure exits if any `(pdf, page)` lacks a test (`benchmark.py:246-251`). Impact: olmOCR recall comes from exhaustive pre-authored facts (~7,010), not selective LLM unit checks; whisker's `MAX_UNIT_CHECKS = 5` displacement (`00-baseline.md:47-48`, `constants.py:223`) is a self-inflicted cap olmOCR avoids by staying deterministic. Answer-class: 2 (contrast) + 5.

- [MED] **Short-cell fuzzy floor can false-pass truncated table headers when `max_diffs > 0`.** `TableTest` sets `threshold = max(0.5, 1.0 - max_diffs/len(cell))` (`tests.py:395-396`); neighbor checks reuse the same 0.5 floor (`tests.py:442-443`). For `cell="SF"` with `max_diffs=1`, threshold is 0.5 while `fuzz.ratio("SF","S")` ≈ 0.67, so `"S"` passes. Sample JSONL table facts use default `max_diffs=0` (`sample_data/dataset.jsonl:40-48`), but mined tests inherit defaults unless edited. Impact: even with an authored `"SF"` fact, lax `max_diffs` recreates PR #286 false-clear at deterministic precision layer. Answer-class: 4.

- [LOW] **Concrete ports to whisker (olmocr path → tapetum_llm / facts target).** (1) `TableTest` + `table_parsing.py` span-aware HTML grid → deterministic `packages/whisker/src/whisker/facts.py` / `tables.py` (P0 table-cell compare), optionally feeding table-page signals into `source_router.py:149-233` via existing `PageUnit.has_tables` (`00-baseline.md:54`). (2) Secno-stripped heading comparison rule (inverse of `FormatTest`) → `html_outline.py:66-81` + metadata prompt. (3) `first_n`/`last_n` zone-scoped presence (`tests.py:160-165`) → new HTML/PDF furniture signals in `source_router.py`. (4) Exhaustive per-page fact evaluation pattern → replace lexical `MAX_UNIT_CHECKS` scheduling in `unit_judge.py:225-241` with table-page priority, not an LLM verifier. Answer-class: 2.

## False-pass hypothesis

A mined `TableTest` with `"cell": "SF", "max_diffs": 1` on a poll table page where the candidate pipe table transcribes the wrapped header as `"S"` in the header cell passes at the 0.5 similarity floor (`tests.py:395-396, 414-418`) even though the human golden requires `"SF"`.

## False-fail hypothesis

A converter that emits only markdown pipe tables on a page whose JSONL facts require HTML `rowspan`/`colspan` neighbor relations fails every such `TableTest` (`README.md:265-266`, `table_parsing.py:390-444` vs `304-311`) despite visually correct content, because pipe parsing cannot represent merged/wrapped cells.

## What would change my mind

Finding any olmocr eval module that, at score time, compares candidate table cell strings to PDF text-layer coordinates or source HTML (not pre-authored JSONL expectations) and routes inspection by detected table geometry — none exists under `olmocr/bench/` or `olmocr/pipeline.py` in this clone.
