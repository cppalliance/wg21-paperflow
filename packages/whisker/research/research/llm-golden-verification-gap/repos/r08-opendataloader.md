- [HIGH] Multi-table documents concatenate all extracted tables into one HTML body but TEDS `evaluate()` scores only `body/table[0]`, silently dropping tables 2..N from the metric. Evidence: `opendataloader-bench-tmp/src/evaluator_table.py:209-214` (`extract_tables` + `wrap_tables_in_html`); `evaluator_table.py:239-246` (both sides wrapped together); `evaluator_table.py:146-148` (`pred.xpath("body/table")[0]`). ## False-pass hypothesis

PR #286 poll-header `SF`→`S` (`00-baseline.md:41-44`): an opendataloader-shaped pipeline passes `table_detection_f1` (pipe tables present, `evaluator_table_detection.py:43-51`), likely passes triage recall (table pages routed to BACKEND, `evaluator_triage.py:130-133`), and may keep `teds_mean` above the committed floor `0.49` (`thresholds.json:3`) while scoring only the first poll table (`evaluator_table.py:146-148`) — the same class of miss as whisker's LLM lane routing pages 8/9 but checking 0 true-positive groups under `MAX_UNIT_CHECKS=5` (`00-baseline.md:47-54`, `constants.py:223`).

## False-fail hypothesis

Whitespace-normalized TEDS treats insignificant HTML whitespace as perfect (`tests/test_evaluator_table.py:169-178`) while whisker's raw-token `teds()` kernel can score ~0.8 on semantically identical cells (persona 05 runtime note); adopting ODL's `_normalize` in whisker guard without a shared golden-vector CI suite would deterministic false-fail WG21 papers whose only delta is cell whitespace formatting.

## What would change my mind

A bench run on a synthetic pair where GT markdown encodes wrapped header cell `SF` and candidate has `S` in the matching cell, with `uv run src/run.py --check-regression` failing on `teds_mean` below `thresholds.json:3` (0.49) **and** per-document `teds` in `evaluation.json` reflecting all poll tables — if TEDS stays above floor because only `body/table[0]` is scored or APTED misaligns wrapped cells, that would flip this repo from "partially portable bench patterns" to "confirmed incapable of golden-PR cell defects even deterministically."
