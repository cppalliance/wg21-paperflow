# r07 - Repo miner: grobid

**Verdict:** usable-with-conditions (+ GROBID's end-to-end eval is the clearest deterministic counterexample to "100% LLM golden verification": per-field recall is engineered in XPath specs and string matchers, but the project explicitly disclaims absolute accuracy and never gates CI on eval)
**Confidence:** high

## Findings

- [CRITICAL] GROBID's golden QA path is **fully deterministic**: PDF in, TEI out, XPath field extraction, four string-matching tiers, precision/recall/F1 — **no LLM judge stage anywhere in the eval loop**. Evidence: `EndToEndEvaluation.java:452-466` (strict/soft/Levenshtein/Ratcliff stats objects), `doc/End-to-end-evaluation.md:109-128` (matching techniques documented), `build.gradle:631-658` (`jatsEval`/`teiEval` invoke `EndToEndEvaluation` only). Impact: supports baseline answer-class **5** — the ecosystem measures conversion fidelity with coded comparators, not generative verification; whisker's source-aware LLM lane is attempting something GROBID never tries. Answer-class: **5**.

- [HIGH] Ground truth is **paired artifacts per article**: one directory per paper containing PDF plus gold XML (NLM `.nxml` or Pub2TEI `.pub2tei.tei.xml`), canonical Hugging Face corpus `sciencialab/grobid-evaluation`. Field expectations are **XPath paths** in code, not prompt rediscovery. Evidence: `doc/End-to-end-evaluation.md:49-68` (directory layout), `FieldSpecification.java:36-42` (title: `nlmPath` vs `grobidPath`), `:267-297` (fulltext fields: `section_title`, `reference_table`, `reference_figure`). Impact: golden-contract rules live in **executable spec** (`FieldSpecification` + normalizers), directly refuting whisker's class **1** failure mode where secno stripping and wrapped-cell reading exist only in human skill docs (`00-baseline.md:93-94`, PR #295/#286 blockers). Whisker analogue: encode defect classes in `facts.py` assertions or deterministic preprocessors, not `tapetum_llm` prompts alone. Answer-class: **1**, **5**.

- [HIGH] Evaluation reports **per-field micro/macro precision, recall, F1, and support**, never a single collapsed score, stratified by structure type **HEADER / CITATION / FULLTEXT**. Evidence: `EndToEndEvaluation.java:488-497` (section switch), `Stats.java:232-268` (micro/macro P/R), `Benchmarking-pmc.md:42-51` (header field table with support column). Impact: portable pattern for whisker's per-defect-class recall — tag holdout rows by stratum (`corpus/holdout/manifest.json`) and regress `teds`/`content_recall`/table facts **within class** instead of letting `overall` or LLM metadata `pass` mask a table-only miss (PR #286: deterministic `pass`, 0 accepted defect groups per `00-baseline.md:54-55`). GROBID side: `FieldSpecification.java` + `Stats.java`; whisker side: `bench.py`, `guard.py`, `facts.py`. Answer-class: **2**, **5**.

- [HIGH] **Four parallel matching tiers** on normalized text catch defects strict equality misses: strict, soft (punctuation/case/space stripped), relative Levenshtein ≥ 0.8, Ratcliff/Obershelp ≥ 0.95; numeric/date fields skip fuzzy tiers. Evidence: `EndToEndEvaluation.java:66-67` (threshold constants), `:453-461` (tier definitions), `:1126-1134` (Levenshtein formula), `:2090-2159` (`basicNormalization`, `removeFullPunct`). Impact: a wrapped-header `SF`→`S` loss is a **field-level false negative** under strict/soft but may surface under Levenshtein if encoded as a `reference_table` or title substring field — whereas whisker's LLM lane has **no table-cell compare** (`00-baseline.md:54-55`) and guard uses one axis slack (`constants.py:94`, `guard.py:180-181`). Adopt GROBID's normalization-first + relative Levenshtein as a deterministic second tier before expecting LLM recall. Answer-class: **1**, **5**.

- [HIGH] **Instance-level recall** is reported separately from field-level aggregates and is far stricter: PMC header strict instance recall **10.55%** (205/1943) vs Levenshtein field micro recall **93.09%**. Evidence: `Benchmarking-pmc.md:98-110`, `EndToEndEvaluation.java:1174-1185` (all fields in one header/citation instance must pass), `ModelStats.java:67-68` ("one error is enough to have the whole instance false"). Impact: GROBID proves rolled-up field averages **hide** localized misses — the same shape as PR #286 (deterministic gates green, localized poll-table `S`/`SF` error invisible to LLM) and PR #295 (structure outline `pass`, 0/4 heading defects per `00-baseline.md:74`). Whisker analogue: conjunctive `facts.py` table/cell checks or instance-all-axes-pass guard mode, not `UnitCheck.verdict_matches_defects` accepting pass-with-empty-defects (`models.py:315-320`). Answer-class: **2**, **4**.

- [MED] **Structure vs content split** is first-class: HEADER, CITATION, and FULLTEXT sections run separate eval passes; FULLTEXT is explicitly **unreliable** because PMC gold annotation is inconsistent (section numbering sometimes in labels, sometimes not). Evidence: `EndToEndEvaluation.java:60-62`, `doc/End-to-end-evaluation.md:113` ("experimental evaluation for the structures of the full text body... not reliable"). Impact: mirrors PR #295 — `html_outline.py:66-81` compares heading **text** including bikeshed secno, achieving structure-channel parity while missing the human contract to strip labels; GROBID would false-pass the same way unless `section_title` normalization encodes the rule (`FieldSpecification.java:270-271` compares raw title text). Do not expect one LLM metadata call to cover both chrome stripping and body fidelity. Answer-class: **1**, **2**.

- [MED] **Regression testing at scale** is manual/off-CI: `./gradlew jatsEval -Prun=0|1` over thousands of PDFs, results pasted into committed `doc/benchmarks/*.md` snapshots; CI runs `assemble test` only. Evidence: `ci-build-unstable.yml:31-32`, `doc/End-to-end-evaluation.md:78-92` (`fileRatio` subsample), `doc/benchmarks/Benchmarking.md:11-13` ("relative indication... compare improvements over time"). Impact: GROBID explicitly rejects absolute verification — same honest ceiling as baseline class **5**. Whisker `guard` is **ahead** on automated per-PID diff (`guard.py:216-218`) but lacks GROBID's published per-field snapshot tables for human PR review (`redteam/grobid.md` §1.1). Answer-class: **5**.

- [LOW] **Per-field model confidence exists in extraction** (`BiblioItem.confidence`, `BibDataSet.confidence`) but **end-to-end eval never reads it** — no confidence-weighted recall, no routing of low-confidence fields. Evidence: `BiblioItem.java:171,526-527`; zero `confidence` references under `grobid-trainer/src/main/java/org/grobid/trainer/evaluation/`. Impact: parallel to whisker's anti-calibrated LLM confidence (96/96 clear firings ≥ 0.95 per `00-baseline.md:80-81`): scores attached to extractions are **not** trusted for verification or recall measurement in either system. Answer-class: **3**, **4**.

## False-pass hypothesis

PR #295 bikeshed secno headings (`## 1. Abstract`): GROBID's `section_title` field compares normalized XPath text from gold JATS and extracted TEI (`FieldSpecification.java:270-271`, `basicNormalization` at `EndToEndEvaluation.java:2090-2096`) with no secno-stripping rule — if gold XML also carries `1. Abstract`, the field matches and **strict/soft/Levenshtein tiers all pass**, same as whisker's `html_outline.py` false-clear (`00-baseline.md:62-64`). GROBID would false-pass unless the gold corpus or a preprocessor encodes the bikeshed contract.

## False-fail hypothesis

PMC header **strict** instance recall 10.55% (`Benchmarking-pmc.md:107-107`) while **Levenshtein** instance recall is 73.65%: punctuation, case, and PDF/XML glyph differences fail the strict tier on otherwise acceptable extractions (`doc/End-to-end-evaluation.md:173-175`). A whisker guard run using only strict axis slack without a GROBID-style soft/Levenshtein tier would false-regress on formatting-only churn on an otherwise correct WG21 paper.

## What would change my mind

Live `rg` finding **confidence- or probability-weighted field recall** wired into `EndToEndEvaluation.java` (routing low-confidence extractions to a separate review bucket or down-weighting them in P/R), or an **LLM-as-judge** stage in `jatsEval`/`teiEval` — neither exists in the cloned repo today.
