# r09 - Repo miner: HTML->MD converter family

**Verdict:** usable-with-conditions (Seven reference converters confirm the PR #295 miss is a contract-encoding problem, not an exotic HTML edge case; they also supply hook and golden-fixture patterns whisker can adopt, but none encode bikeshed `secno` semantics out of the box.)
**Confidence:** high

## Findings
- [CRITICAL] All seven surveyed converters flatten heading child text with no class-based stripping: turndown `commonmark-rules.js:21-35` uses `content` from recursive child walk; html2text `__init__.py:343-365` emits ATX from all in-header data; markdownify `convert_hN` `__init__.py:558-575` joins all child strings; node-html-markdown `config.ts:92-95` prefixes `#` on aggregated node text; html-to-markdown-go `render_heading.go:109-110` calls `RenderChildNodes`; html-to-markdown-py visitor receives flattened `text` (`test_visitor.py:136-149`); mdream collects full heading buffer (`output.rs:145-150`, `307-308`). Whisker `html_outline.py:66-81` matches this naive model. Impact: source outline and candidate both read `1. Abstract`, so metadata/outline passes with empty `heading_drift` on PR #295 (baseline `00-baseline.md:58-65`). Answer-class: 1.
- [HIGH] Zero repos ship default `secno`/bikeshed-class stripping; all require custom hooks. Portable hook surfaces: turndown `addRule`/`remove` (`turndown.js:88-115`); html-to-markdown-go plugin `Register.RendererFor` + tag-type remove (`base.go:29-35`, `register_test.go:79-95`); html-to-markdown-py `visit_heading` visitor override (`test_visitor.py:136-149`); mdream CSS `filter`/`extraction` plugins and `beforeNodeProcess` class checks (`CLAUDE.md:167-184`, `index.ts:69-72`). Impact: golden-contract rules (secno strip, TOC chrome) must be encoded in preprocessing or prompts; the LLM lane cannot rediscover them. Answer-class: 1.
- [HIGH] Five of seven exclude `<script>`/`<style>` from text extraction by default; whisker `_SectionExtractor` does not (baseline `00-baseline.md:71-72`). html-to-markdown-go `base.go:32-33` registers `TagTypeRemove` for both; html-to-markdown-py `structure_builder.rs:37-38` skips `script|style|head` when collecting text; markdownify `convert_script`/`convert_style` return empty (`__init__.py:710-714`); html2text increments `quiet` on `head/script/style` (`__init__.py:391-395`, output gated at `o()` `763`); node-html-markdown `defaultIgnoreElements` lists `SCRIPT, STYLE` (`config.ts:17-19`); mdream `tags.rs:54-55` sets `excludes_text_nodes: true` on script/style. Turndown is the outlier: script is not void (`utilities.js:43-46`) and no default `.remove('script')`, so script body would emit via `defaultReplacement`. Impact: section recall pollution on PR #295 is a whisker gap, not industry-normal behavior. Answer-class: 1 (plus baseline routing class 2 for the recall symptom).
- [MED] Construct-level golden fixtures are the norm for heading behavior, but none test structural chrome spans. html-to-markdown-go pairs `*.in.html` / `*.out.md` via `goldenfiles.go:16-17,44-78`; turndown `test/index.html:85-125` encodes h1-h4 input/expected; html2text pairs `header_tags.html` with `header_tags.md`; markdownify `test_conversions.py:159-204` asserts nested inline headings; node-html-markdown `default-tags.test.ts:83-88` asserts h1-h6 with inline bold. No fixture mentions `secno`, `no-toc`, or numbered span labels. Impact: even repos with strong golden coverage would not catch the PR #295 blocker unless the contract is added to fixtures. Answer-class: 1.
- [MED] Heading normalization patterns portable to `html_outline.py`: (a) collapse internal whitespace (markdownify `convert_hN` `571`, html-to-markdown-go `render_heading.go:132-137`); (b) ATX prefix from tag level only, not from child numbering; (c) optional visitor/plugin strip of `span.secno` or regex `^\d+\.\s+` applied only when comparing outlines, not when rendering candidate MD. html-to-markdown-go golden `heading.in.html:91-97` shows inline elements preserved but no section-number spans. Impact: P0 heading-normalization fix can mirror existing converter hygiene without inventing a new architecture. Answer-class: 1.
- [LOW] Turndown and node-html-markdown expose `remove`/`ignore` lists for tag-level suppression, but not CSS-class selectors on heading children. mdream alone documents class/id-based `skip` in plugins (`CLAUDE.md:176-179`). Impact: bikeshed-specific normalization belongs in whisker preprocessing or a dedicated HTML outline pass, not in expecting generic converters to infer WG21 semantics. Answer-class: 1.
- [LOW] html-to-markdown-py documents script/style stripping in both Tier-1 scanner and structure text collection (`convert_api.rs:88-91`, `structure_builder.rs:37-38`), confirming the pattern is treated as baseline HTML hygiene in the newer Rust stack. Impact: whisker `_SectionExtractor` omission is an implementation debt relative to peer converters, not a debatable design choice. Answer-class: 1.

## False-pass hypothesis
`<h2><span class="secno">1. </span>Abstract</h2>` vs candidate `## 1. Abstract`: every converter's default heading path (and whisker `extract_heading_outline`) yields `1. Abstract` on both sides, so outline comparison reports no drift exactly as PR #295 did (baseline `00-baseline.md:62-64`).

## False-fail hypothesis
Blind global strip of leading `^\d+\.\s+` from all h2 titles would false-fail legitimate headings whose prose starts with a number (e.g. `## 42 is the answer`) and papers where the golden contract requires keeping section numbers in the title text.

## What would change my mind
A default code path or committed golden fixture in any of these seven repos that strips `span.secno` (or equivalent bikeshed heading chrome) and asserts `Abstract` not `1. Abstract` without a custom visitor/plugin.
