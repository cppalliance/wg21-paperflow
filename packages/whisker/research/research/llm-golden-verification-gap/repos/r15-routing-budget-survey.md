# r15 - Cross-repo survey: inspection budgets and routing

**Verdict:** usable-with-conditions (+ the 31-clone sweep confirms no peer uses severity-then-lexical LLM unit caps; whisker's `MAX_UNIT_CHECKS=5` scheduling is indefensible for golden recall, but the fix is signal-class quotas plus deterministic table tripwires, not copying any repo's LLM verifier)
**Confidence:** high

## Findings

- [CRITICAL] **None of the 31 clones under `packages/whisker/research/repos/` implements "route many units → LLM-check top-K by severity then lexical id."** Whisker is alone: `run_unit_checks` sorts `(severity_rank, unit_id, signal_type, detail)` and takes `risky_unit_ids[:MAX_UNIT_CHECKS]` (`unit_judge.py:225-240`, `constants.py:223-226`). PR #286 routed nine PDF units including pages 8/9 but checked 1, 13, 2, 3, 4 because `"page:13" < "page:2"` lexically at equal `medium` severity (`00-baseline.md:46-49`). Impact: recall lost before model capability is tested; this is the primary class-**2** mechanism for the golden-PR misses. Answer-class: **2**.

- [CRITICAL] **0/31 repos gate conversion quality on an LLM verification stage** (baseline ecosystem fact, `00-baseline.md:82`). Surveyed QA surfaces are deterministic: exact fixture diffs (html2text, turndown, pandoc, markdownify, node-html-markdown, html-to-markdown-go), committed metric/golden trees (unstructured, docling, olmocr), substring anchors (firecrawl), or block-type assertions (MinerU). LLM calls in marker/langextract/firecrawl are **producers or offline miners**, not post-hoc recall auditors. Impact: "100% LLM verification of goldens" has no portable precedent; severity-then-lexical top-5 is not an industry pattern to defend. Answer-class: **5**.

- [HIGH] **Closed-corpus exhaustive check (inverse of whisker starvation): olmocr-bench runs every loaded test on every page by default.** `benchmark.py:246-251` exits if any `(pdf, page)` lacks a dataset entry; the default loop evaluates all tests (`benchmark.py:141-143`, `116-117`). Optional `--sample N` randomly subsamples **for dev only** (`benchmark.py:256-262`), not production gating. Macro score is mean of per-JSONL stratum pass rates (`benchmark.py:343-350`), not a merged headline. Impact: olmocr recall comes from ~7k pre-authored facts checked deterministically, not from selective LLM unit calls; whisker should either drop the pretense of partial LLM coverage or adopt **fail-closed completeness** (cap at `review` when routed > budget, which fusion already does) plus **deterministic table facts** for countable defects. Answer-class: **2**, **5**.

- [HIGH] **Stratified tolerance without LLM sampling: html-to-markdown-py and MinerU assign budgets by defect class, not by string sort.** `guardrails.json:4-10` maps fixture groups (`clean_large`, `adversarial`, …) to distinct `max_regression_pct`; `groups.toml` classifies fixtures before compare (`tools/benchmark-harness/`). MinerU requires `len(type_set) >= 4` block modalities (`test_e2e.py:157,220`) and parse-method-specific table hit floors (`0.9` txt/ocr vs `0.7` vlm, `test_e2e.py:198-201`). Nougat splits Text/Math/Tables strata with separate metrics (`metrics.py:63-117`); marker records scores per `block_type` and document `classification` (`benchmarks/overall/overall.py:37-71`). Impact: portable pattern for whisker scheduling is **minimum one slot per signal class** (`low_recall`, `token_delta`, `missing_captions`, `heading_drift`, future `table_cell`) before filling remainder — not lexical `unit_id`. Answer-class: **2**.

- [HIGH] **Whisker stacks three independent "cap at 5" schedulers, all fail-closed to `review` but none guarantees defect-bearing units are inspected.** (1) `MAX_UNIT_CHECKS=5` source-aware unit judge (`constants.py:223`, `unit_judge.py:239-240`); (2) `MAX_PAGE_ESCALATIONS=5` monolith page screen (`constants.py:191`, `pdf_judge.py:726-738`); (3) `select_candidates` triages **papers** for `--review-all` via deterministic sidecar heuristics, not units (`adjudicate.py:98-126`). Constants comment explicitly copies the page-screen pattern for unit checks (`constants.py:224-226`). Alliance pod billing is hourly, not per-token (`whisker/CLAUDE.md` tapetum section), so the cap is a latency guard, not fiscal prudence. Impact: PR #286 pages 8/9 were starved twice (unit budget + no table signal); raising cap alone to 9 still loses pages 8/9 if numeric sort without class quotas (top five = pages 1–5). Answer-class: **2**.

- [HIGH] **Confidence-threshold escalation to a more expensive model exists only in whisker tapetum — and the confidence band is dead in production.** Text-lane `_escalation_signals` fires on axis conflict, ungrounded evidence, or ambiguous-band confidence (`adjudicate.py:252-289`, `constants.py:16-30`); `tapetum_llm.md:259-265` documents 0/198 escalations from confidence alone. No surveyed conversion repo implements a two-tier LLM judge cascade for QA; olmocr/langextract use LLMs for extraction or corpus mining, not calibrated escalation on verification. Impact: copying "escalate on low confidence" from LLM-as-judge literature is not validated here; **signal-derived routing** (recall floor, table presence, caption miss) matches peer repos better than model self-confidence. Answer-class: **3**, **5**.

- [MED] **Langextract's "budget" is chunk throughput, not defect-class prioritization.** `extraction.py:57-58` defaults `batch_length=10`, `max_workers=10`; `annotation.py:366-392` batches chunks then calls `infer()`; chunking splits by `max_char_buffer` (`annotation.py:213`, `chunking.py:19-49`). Every chunk gets a generative call if the pipeline runs — there is no severity sort dropping table chunks. Impact: contrasts with whisker's **few calls, high miss risk** design; langextract does not solve enumeration (r06: no uncovered-span report) but shows recall via **more deterministic windows**, not top-5 lexical pick. Answer-class: **2**, **4**.

- [MED] **Anomaly/confidence scores in peer repos are diagnostic, not inspection routers.** Surya attaches per-block `confidence` and `error` on recognition output (`surya/recognition/__init__.py:221-251`) for benchmark reporting, not to choose which blocks get a second model pass. Firecrawl PDF shadow compare uses **joint** length-ratio and number-preservation tiers (`shadowComparison.ts:54-61`), not independent axis slack — a pattern for **composite routing scores**, not LLM unit caps. Unstructured pins the full eval corpus via `metrics-json-manifest.txt` and diffs the entire metrics tree (`check-diff-evaluation-metrics.sh:56-73`). Impact: score-ranked scheduling should combine specificity signals (e.g. `low_recall` > `heading_drift`, `has_tables` boost) like firecrawl's joint rule, not raw severity ties broken by string sort. Answer-class: **2**, **4**.

- [LOW] **Repos with no prioritization mechanism (deterministic all-or-nothing or minimal QA):** camelot, docling (801 goldens all diffed), Dolphin, grobid, html-to-markdown-go (14 goldie pairs), html2text (74 pairs), img2table, markitdown, mdream, node-html-markdown, opendataloader-pdf, opendataloader-bench-tmp, pandoc (~1760 command tests), PDF-Extract-Kit (no in-repo tests), pdf-to-markdown, pdfplumber, PyMuPDF, pymupdf4llm, surya (CI tier-split only), tabula-java, tabula-java-tmp, turndown. **Coverage guarantee analogue:** docling `verify_conversion_result_v2` walks every artifact per source file (`verify_utils.py:355-439`); olmocr closed page set (`benchmark.py:246-251`). **None** guarantees "every table cell must be LLM-checked." Answer-class: **5**.

## False-pass hypothesis

PR #286 with current scheduling: nine `heading_drift`/`medium` units sorted lexically; `MAX_UNIT_CHECKS=5` checks pages 1 and 13–4; pages 8/9 remain in `unchecked_unit_ids` while fusion emits coverage-capped `review`, not a table defect (`00-baseline.md:46-49`, `fusion.py:192-196`). No surveyed repo would replicate this failure mode because none LLM-samples routed units — but olmocr-style deterministic `TableTest` with strict `max_diffs=0` would still false-pass if the fact was never authored (class **1**).

## False-fail hypothesis

Adopting olmocr's default **run-all-tests** posture for LLM unit checks on every WG21 paper (~15 PDF pages + HTML sections × scoped prompts) without a cap would explode wall-clock (CLI budgets `(1 + MAX_UNIT_CHECKS) * UNIT_CHECK_TIMEOUT_SECONDS`, `cli.py:150-157`) and amplify the ≥25% verdict-flip rate across redundant heading-noise units — manufacturing advisory `review`/`fail` noise without raising table recall (class **3**, **5**).

## What would change my mind

A live sweep of all 31 clones finding production code that (a) routes heterogeneous QA units, (b) caps expensive model calls below routed count, and (c) breaks ties by lexical unit id rather than numeric page order or signal-class quota — plus a PR #286 replay showing that alternative schedule checks pages 8/9 before page 13.
