# r11 - Repo miner: PyMuPDF + pymupdf4llm + pdf-to-markdown

**Verdict:** usable-with-conditions (+ PyMuPDF `find_tables()` is the shortest deterministic cell-grid oracle already reachable from whisker's existing `pymupdf` dependency, but default line-based strategies miss borderless poll tables and in-cell vertical wrap is emitted as newline/`<br>`, not poll-header concatenation)
**Confidence:** high

## Findings

- [CRITICAL] **Shortest deterministic cell-grid oracle from whisker:** open PDF with existing `pymupdf`, call `page.find_tables(...)`, read `tab.extract()` (list of list of cell strings). No new dependency beyond what `textlayer.py` already imports. For borderless WG21 poll tables use `strategy="text"` (both axes) or pin column geometry with `vertical_strategy="explicit"` and `vertical_lines=[72.5, 95.5, 110.5, 127.5, 144.5, 167.5]` from baseline PR #286 geometry (`00-baseline.md:42-44`). Callable surface: `packages/whisker/research/repos/PyMuPDF/src/table.py:2593-2730` (`find_tables`), `1559-1595` (`Table.extract`). Impact: P0 table-cell compare can live in whisker core without pdfplumber/camelot/JVM. Answer-class: **2**, **5**.

- [CRITICAL] **With correct cell boundaries, PyMuPDF would NOT split wrapped `SF` into two columns.** Cell assignment uses char-center-in-bbox (`char_in_bbox`, `table.py:1563-1581`) and char overlap ≥50% (`extract_cells`, `table.py:280-286`). Baseline proves wrapped `S`+`F` share x≈77.25 while column-2 `F` sits at x≈100.5 (Δ≈23 pt). Grid snap/join tolerances are 3 pt (`DEFAULT_SNAP_TOLERANCE=3`, `table.py:354`; `find_tables` defaults `table.py:2600-2603`), far below 23 pt, so no default merges those x-clusters. `make_table_from_bbox` explicitly drops x-positions that cut through words (`table.py:214`), preventing a spurious column line between stacked glyphs at the same x. Impact: oracle would place both letters in cell 0; the PR #286 defect is a **column-boundary misread**, not something `find_tables()` reproduces when cells are found. Answer-class: **2**.

- [HIGH] **In-cell vertical wrap is newline-separated, not poll-concatenated.** `extract_cells` joins successive lines inside one cell with `\n` (plain) or `<br>` (markdown) (`table.py:263-264`; pymupdf4llm copy `pymupdf4llm/src/helpers/utils.py:860-861`). `extract()` clusters at `DEFAULT_Y_TOLERANCE=3` then `"\n".join(...)` (`table.py:832-850`). Expected oracle string for wrapped header: `"S\nF"` or `"S<br>F"`, not `"SF"`. PyMuPDF tests treat multiline cells as `<br>` in markdown goldens (`tests/test_tables.py:302-319`, `447-449`). Impact: deterministic compare needs golden-contract normalization (strip/join stacked single-char poll headers); otherwise oracle false-fails `"S\nF"` vs human `"SF"`. Answer-class: **1**, **5**.

- [HIGH] **Default strategies miss borderless poll tables.** `find_tables` defaults to `vertical_strategy="lines"` / `horizontal_strategy="lines"` (`table.py:2596-2597`). `test_add_lines` shows `page.find_tables().tables == []` on a table with no drawable grid until explicit lines are injected (`tests/test_tables.py:238-248`). pymupdf4llm RAG path defaults **`table_strategy="lines_strict"`** (`pymupdf4llm/src/helpers/pymupdf_rag.py:345`), stricter than PyMuPDF default; when `IGNORE_GRAPHICS` or empty strategy, table extraction is skipped entirely (`pymupdf_rag.py:1098-1100`). Impact: out-of-the-box pymupdf4llm/to_markdown likely emits poll rows as plain text, reproducing the same `|S|F|` column split tomd made; LLM lane never sees a table unit to judge. Answer-class: **2**.

- [HIGH] **Whisker LLM lane computes `has_tables` but never routes on it.** `PageUnit.has_tables` is set from `_block_looks_tabular` (multi-span line heuristic, `textlayer.py:160-170`, `256-261`), not `find_tables`. `route_pdf_units` emits only `token_delta`, `low_recall`, `missing_captions`, `heading_drift` (`source_router.py:149-233`); baseline records no table-cell signal type (`00-baseline.md:54-55`). Impact: even if PyMuPDF detects tables on pages 8/9, current routing would not prioritize table-cell checks; pages 8/9 were routed then displaced by `MAX_UNIT_CHECKS=5` (`00-baseline.md:47-49`). Answer-class: **2**.

- [MED] **pymupdf4llm markdown emission failure modes on wrapped cells.** Layout path pre-wraps cells with `textwrap.wrap(cell, width=base_width)` before `tabulate` (`document_layout.py:84-108`, defaults `table_max_width=100`, `__init__.py:167-168`), splitting strings at display width unrelated to PDF geometry. RAG/layout `table_to_markdown` embeds `<br>` inside pipe cells (`utils.py:957-979`; PyMuPDF `Table.to_markdown` `table.py:1640-1662`). `$...$` + `<br>` gets sanitized to `$ ` (`utils.py:948-953`). Tests gate whole-document markdown with byte-exact `.expected.md` (`tests/test_370.py:45`, `test_sce-150.py:21`) but **no poll-table / wrapped-header fixture** in mined tests. Impact: pymupdf4llm QA proves markdown stability, not WG21 poll-header semantics. Answer-class: **1**, **5**.

- [MED] **pdf-to-markdown has no table stage; vertical-wrap merge threshold excludes poll headers.** Pipeline is 12 transformations ending in `ToMarkdown` (`AppState.jsx:53-67`): text-item stats, line compaction, `VerticalToHorizontal`, TOC/headers/lists, blocks, markdown. **No table detector.** `VerticalToHorizontal` merges single-char vertical stacks only when `stash.length > 5` (`VerticalToHorizontal.jsx:38-47`); a two-glyph `S`/`F` stack (PR #286) stays separate lines. Tests cover string helpers only (`test/stringFunctions.spec.js`); no table goldens. Impact: prior art for per-stage intermediate goldens (`gap-matrix.md:23`) but zero cell-grid QA; documents why line-first JS converters inherit the same wrapped-header blind spot. Answer-class: **1**, **5**.

- [LOW] **PyMuPDF table fidelity test pattern is pickle + exact extract + geometry slack.** `test_table1` compares pickled `extracts` and cell tuples with `abs(c1-c0) < 0.2` and old-rect-contained-in-new (`tests/test_tables.py:15-37`). Version-keyed markdown expected strings for strikethrough dialect drift (`tests/test_tables.py:308-326`, cited in redteam `PyMuPDF.md`). Impact: whisker P0 should store **per-page cell grids** (extract output + bbox), not TEDS-only holistics; mirror PyMuPDF's split between exact text and approximate geometry. Answer-class: **5**.

## False-pass hypothesis

Run `page.find_tables(strategy="text")` on P1068R11 pages 8-9, take header cell `(0,0)` as `"S\nF"`, compare to candidate poll row `|S|F|N|A|SA|` using **first-line-only** or "does candidate contain `S`?" substring logic: reference and candidate both "have S", column split is ignored, check passes — same class of miss as LLM lane `accepted defect groups: 0/1` (`00-baseline.md:52-54`).

## False-fail hypothesis

Deterministic grid compare demanding exact `"SF"` in cell `(0,0)` flags PyMuPDF `"S\nF"` (correct geometry, default newline join) as a defect on a golden that already normalizes wrapped poll headers to `"SF"` per human skill contract (`00-baseline.md:93-95`) — oracle is right on boundaries, wrong on emission policy.

## What would change my mind

A reproducible run on PR #286 source bytes (pages 8-9) logging: (1) `find_tables(strategy="text")` or explicit `vertical_lines` at baseline x-coordinates returns a table with both wrapped glyphs in cell `(0,0)` as `"S\nF"`, (2) candidate markdown cell is `"S"`, and (3) a whisker `table_compare` hook on that grid flags the defect without LLM involvement — proving class **2** (routing/compare wiring) is the fixable gap, not PyMuPDF unavailability.
