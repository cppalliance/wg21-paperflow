# r10 - Repo miner: pdfplumber + camelot + img2table + tabula

**Verdict:** usable-with-conditions (+ pdfplumber and camelot expose callable Python cell grids suitable for a deterministic source reference lane, but none of their default tolerances would auto-merge PR #286's wrapped `S`+`F`; img2table is image-first; tabula-java is JVM-only)
**Confidence:** high

## Findings

- [CRITICAL] Whisker tapetum_llm has **no table-cell comparison** despite `PageUnit.has_tables` (`textlayer.py:86-98`); `route_pdf_units` never reads it (`source_router.py:149-233`, `00-baseline.md:54-55`). All four mined repos implement **geometry-first cell assignment + string fill**, the missing primitive for P0 table-cell compare, but the LLM lane never invokes any of them. Impact: PR #286 wrapped-header `SF`→`S` is invisible to routing and judging regardless of extractor choice. Answer-class: **2**.

- [HIGH] **pdfplumber** builds grids from ruled-line intersections, then assigns chars by **midpoint-in-bbox** and joins in-cell text with newlines, not stacked-glyph concatenation. Evidence: edge snap/join defaults `DEFAULT_SNAP_TOLERANCE=3`, `DEFAULT_JOIN_TOLERANCE=3`, `intersection_tolerance=3` (`pdfplumber/table.py:9-12`, `491-503`); `char_in_bbox` uses char center vs cell bbox (`table.py:426-432`, `442-451`); `extract_text` clusters words into lines at `y_tolerance` default 3 then `"\n".join(...)` (`pdfplumber/utils/text.py:27-28`, `750-764`). For baseline geometry (wrapped `S`+`F` at x=77.25 vs column-2 `F` at x=100.5, Δx≈23.25 pt): **no default tolerance merges those x-coordinates** (all grid tolerances are 3 pt). Vertical wrap in one cell yields `"S\nF"` at best, not `"SF"`. Impact: a reference grid catches missing `F` only if compare normalizes newlines; it does not fix the converter. Answer-class: **2**, **1**.

- [HIGH] **pdfplumber tests verify cell content with exact row/column lists**, including tolerance sensitivity, not fuzzy scores. Evidence: `test_edges_strict` pins last row cells exactly (`tests/test_table.py:64-74`); `test_rows_and_columns` asserts per-cell `extract_text` on cropped bboxes (`test_table.py:76-100`); `test_text_tolerance` shows `text_x_tolerance=1` splits `"CITIBANK-TRAVELCBACARD"` into `"CITIBANK - TRAVEL CBA CARD"` (`test_table.py:117-156`); NICS accounting invariant `colsum == total * 2` (`tests/test_nics_report.py:81-85`); WARN report pins first data rows after `fix_row_spaces` (`tests/test_ca_warn_report.py:59-77`). Impact: portable pattern for whisker P0 is **per-cell exact or normalized string diff on a reference grid**, matching pdfplumber's QA style, not LLM recall. Answer-class: **2**, **5**.

- [HIGH] **Camelot lattice** merges grid lines at `line_tol=2` (default), then assigns PDFMiner textlines to cells via **row overlap + per-column overlap ratio**; spanning uses `shift_text=['l','t']` and optional `copy_text`, not vertical-wrap reading. Evidence: `line_tol=2`, `joint_tol=2` defaults (`camelot/parsers/lattice.py:103-108`, `167-168`); joint x-merge when `x_left - line_tol <= x_right <= x_left + line_tol` (`lattice.py:536-547`); `get_table_index` picks row by y-mid, column by max width-normalized overlap (`camelot/utils.py:1486-1527`); `Cell.text` setter **concatenates** assigned strings (`camelot/core.py:498-500`); `apply_spans` opens interior edges for rowspan/colspan blocks (`camelot/parsers/ml.py:250-270`). Stream `column_tol` default **0** (`camelot/parsers/stream.py:53-55`, `428-468`). Tests: full `assert_frame_equal` on fixture PDFs (`tests/test_lattice.py:11-18`); issue #288 asserts wide text is **not silently dropped** even if column placement is wrong (`tests/test_common.py:448-485`). Impact: camelot would assign stacked header glyphs to one cell if grid lines are correct, but **23 pt column separation stays separate**; `SF` vs `S\nF` still needs contract normalization. Callable via `camelot.read_pdf(path, flavor='lattice', pages='8')` but pulls OpenCV/PDF raster deps. Answer-class: **2**, **1**.

- [MED] **img2table** separates **geometry** (OpenCV lines → `identify_cells` → adjacency clustering) from **text** (PdfOCR word boxes → >50% area overlap → lines joined with `\n`). Evidence: cell clustering adjacency thresholds `thresh_x/y = min(5.0, 0.05 * min(width/height))` (`tables/bordered/tables/creation/cell_clustering.py:44-49`); `get_text_table` assigns words where intersection/word_area > 0.5, sorts lines by `(y1, x1)`, joins with `"\n".join` (`ocr/_types.py:128-172`); PdfOCR builds words with vertical direction only after ≥3 chars and `h/w >= 2` (`ocr/pdf.py:52-58`, `86-91`). Tests: exact sorted `Cell` coordinate equality (`tests/tables/bordered/cells/test_cells.py:19-21`); extracted HTML/XLSX golden compare (`tests/tables/extraction/test_extraction.py:47-79`). Impact: useful **benchmark TEDS/GriTS reference** on rasterized pages, but coordinate space is **200 dpi pixels** (`ocr/pdf.py:153-157`), not PDF points; heavy for `textlayer.py` hot path. Answer-class: **2**, **5**.

- [MED] **tabula-java** lattice mode: collapse rulings → `findCells` at intersection points rounded to **2 decimals** → `page.getText(cell)` via `TextElement.mergeWords` (spacing tolerance `AVERAGE_CHAR_TOLERANCE=0.3` × avg char width, `wordSpacing * 0.5`). Evidence: `SpreadsheetExtractionAlgorithm.extract` (`extractors/SpreadsheetExtractionAlgorithm.java:47-96`, `132-180`); `compareRounded(..., 2)` (`SpreadsheetExtractionAlgorithm.java:32-37`); stream `BasicExtractionAlgorithm` infers columns from whitespace regions then assigns chunks where `tc.getLeft() <= columns.get(j)` (`extractors/BasicExtractionAlgorithm.java:46-96`, `112-150`). Repo is **Java only** (README documents `java -jar ...` CLI); no Python binding in whisker's clone. Impact: same algorithm family as pdfplumber (Tabula lineage, `table.py:584-585`), but **not directly callable** from `textlayer.py` without a subprocess/JVM bridge. Answer-class: **2**, **5**.

- [MED] **Library callability for planned `table_compare` from `textlayer.py`:** **pdfplumber** — best fit: pure Python, same PDF text layer, `page.extract_table(table_settings)` returns `list[list[str|None]]` (`table.py:421-457`, `page.py:481+`). **camelot** — viable with `read_pdf` → `tables[0].df`, heavier deps and raster path for lattice. **img2table** — conditional: requires page raster at 200/72 scale + `TableExtractor` + `PdfOCR` pipeline (`document/pdf.py:24-68`, `extractor.py:30-50`). **tabula-java** — not directly usable as a Python library in-repo; JVM subprocess only. Impact: P0 remediation should anchor on **pdfplumber or PyMuPDF-native grid + cell string map**, using camelot as cross-check, not img2table/tabula in the LLM lane. Answer-class: **2**.

- [LOW] None of the four repos gate runtime QA on **LLM verification of cell strings**; all use deterministic fixtures (pdfplumber row lists, camelot DataFrames, img2table HTML/XLSX goldens, tabula CLI golden CSVs in upstream). Aligns with baseline: 0/31 surveyed repos gate on LLM (`00-baseline.md:77-78`). Impact: supports class **5** — table defects are countable via reference grids, not rediscoverable by LLM recall. Answer-class: **5**.

## False-pass hypothesis

Run pdfplumber `extract_table` on P1068R11 pages 8-9, compare reference cell strings to candidate markdown with **first-line-only** or whitespace-stripped equality: reference cell reads `"S\nF"` (or `"F"` mis-assigned to column 2 at x=100.5 while column 1 shows `"S"`), candidate poll header shows `"S"` — a naive compare that treats newline as separator and checks only the first token would still **pass**, mirroring today's LLM false-clear (`00-baseline.md:41-44`, `accepted defect groups: 0`).

## False-fail hypothesis

Deterministic reference grid compare with **strict `"SF"` equality** flags pdfplumber/camelot output `"S\nF"` or `"S F"` as a defect on an otherwise human-acceptable golden that normalizes wrapped poll headers to `"SF"` (golden-contract rule lives in human skill docs, not extractor defaults — `00-baseline.md:93-95`).
