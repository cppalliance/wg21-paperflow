# r06 - Repo miner: langextract

**Verdict:** usable-with-conditions (+ the three-tier char-span aligner and multi-pass merge are real and partially portable, but langextract does not solve recall-by-enumeration; it shares whisker's generative-then-verify asymmetry and would not close PR #286/#295 on its own)
**Confidence:** high

## Findings

- [CRITICAL] Langextract does **not** force the model to account for every source span; coverage is generative-then-align, identical in shape to whisker's claim-then-verify funnel. Evidence: `prompting.py:136` injects each `chunk_text` as the sole `Q:` payload with no checklist of required spans; `annotation.py:400-428` runs resolve→align only on whatever the model returns per chunk; there is no pass that diffs tokenized source against extractions to surface **uncovered** intervals (confirmed by absence of any "uncovered"/"remaining span" logic in `annotation.py` and `resolver.py` at pinned SHA `0dff5479`). Impact: baseline PR #295 `generated defect claims: 0` and PR #286 `accepted defect groups: 0` are the same failure class as langextract's silent empty chunk — spans the model never names stay invisible. Answer-class: **4**.

- [CRITICAL] Char-offset grounding is a **post-hoc three-tier aligner** on model strings, not a source-first audit. Evidence: per chunk, `annotation.py:407-425` adds `token_offset`/`char_offset` from `TextChunk.char_interval`, then `resolver.align()` (`resolver.py:322-400`) runs (1) monotonic exact-occurrence DP (`resolver.py:1104-1175`, applied `1177-1243`) mapping repeated mentions to successive token runs, (2) difflib exact/lesser (`resolver.py:962-1019`), (3) LCS fuzzy with dual gates `_FUZZY_ALIGNMENT_MIN_THRESHOLD=0.75` and `_FUZZY_ALIGNMENT_MIN_DENSITY=1/3` (`resolver.py:57-58`, `1377-1404`), writing `char_interval` from tokenizer token spans (`resolver.py:776-779`). Impact: precision on **emitted** extractions only; aligns entity location, never validates extraction **completeness** — same subtractive contract as `grounding.py:248-335` (whisker already ported Tier-1 exact DP per module docstring `grounding.py:14-21`). Answer-class: **4**.

- [HIGH] `extraction_passes>1` is the primary **recall lever**, but it re-runs the full chunk→infer→align pipeline with **first-pass-wins** overlap merge and linear cost — not deterministic gap-filling. Evidence: `extraction.py:80-81` documents passes "to improve recall"; `annotation.py:443-526` `_annotate_documents_sequential_passes` materializes all documents, loops passes calling `_annotate_documents_single_pass`, then `_merge_non_overlapping_extractions` (`annotation.py:46-83`) keeps earlier-pass spans when `char_interval`s overlap. Impact: raises P(model emits an entity) but cannot invent defects the model skips on every pass; baseline PR #286 would need table-cell **generation**, not more alignment passes. Answer-class: **4**, **3**.

- [HIGH] Parallelism is **chunk batching + provider thread pool**, not exhaustive multi-view routing. Evidence: `extraction.py:57-58` defaults `batch_length=10`, `max_workers=10`; `annotation.py:366-392` serially batches chunks then calls provider `infer()`; `gemini.py:477-504` (per prior verified baseline) index-orders parallel results. Chunking defaults: `Annotator` `max_char_buffer=200` (`annotation.py:213`), `extract()` `max_char_buffer=1000` (`extraction.py:53`) — ~80–400 LLM calls per 80k-char WG21 paper vs whisker's scoped `MAX_UNIT_CHECKS=5` (`constants.py:223`). Impact: langextract buys recall via **more generative calls over smaller windows**, whisker via **fewer calls over router-selected units**; both still cap what gets checked and neither guarantees poll-table or secno units are in scope (baseline `00-baseline.md:47-55`, `54-55`). Answer-class: **2**, **4**.

- [HIGH] Controlled generation is provider-native strict schema, with **no schema-noncompliance retry** and fail-soft chunk drops — worsening silent recall loss when the model skips or garbles output. Evidence: Gemini/OpenAI `response_schema` / `response_format` strict paths (`00-baseline.md` DQ2); parse/schema failure → log + `return []` when `suppress_parse_errors=True` (`resolver.py:305-316`, forced default `extraction.py:365`); no re-prompt loop (contrast `model_backends.py:311-421`). Impact: a chunk that returns valid JSON with **zero** extractions looks like success; combined with baseline PR #295 zero claims, this is the langextract analogue of `UnitCheck.verdict_matches_defects` accepting pass-with-empty-defects (`models.py:315-320`) — internal consistency without coverage. Answer-class: **4**, **3**.

- [MED] Failure handling when content is skipped is **silent or pass-through**, never fail-closed completeness. Evidence: `suppress_parse_errors=True` drops failed chunks with only a log (`resolver.py:305-307`); failed alignment keeps extractions with `char_interval=None` / `alignment_status=None` in output (`resolver.py:1021-1068`, `core/data.py:87-88`); README consumer filter `[e for e in result.extractions if e.char_interval]` (`README.md:94-95`) is the documented way to discard ungrounded items — no document-level `partial` flag (persona 09). Impact: operators cannot distinguish "verified complete extraction" from "model omitted this chunk/entity"; mirrors baseline warning that fusion `source_aware_review_cap` fires on **coverage caution**, not detection (`00-baseline.md:52-53`, `74-75`). Answer-class: **4**, **5**.

- [MED] A whisker **enumeration-first inversion** is partially built (v6 router) but not completed; langextract maps cleanly as a **chunking analogue**, not a recall oracle. Evidence mapping — langextract side: deterministic `chunking.py` `TextChunk` intervals → one LLM call per chunk (`annotation.py:360-375`) → align extractions (`annotation.py:418-425`). Whisker side: deterministic `textlayer.py` `PageUnit` / `html_outline.py` `SectionUnit` → `source_router.py:149-233` `route_pdf_units` / `route_html_units` emit `RiskSignal`s → `unit_judge.py:208-323` `run_unit_checks` calls `_check_one_unit` only for `risky_unit_ids[:MAX_UNIT_CHECKS]` → `grounding.py` `verify_unit_evidence` filters model `DefectFinding`s. Full inversion would: (a) enumerate **all** units with source packets (drop severity filter or raise `MAX_UNIT_CHECKS`), (b) require structured per-unit verdict schema (already `UnitCheck`, `models.py:298-320`), (c) add deterministic contract checks before/alongside LLM (`facts.py` table/heading rules for secno strip, `textlayer.py:86-98` `has_tables` for cell compares — baseline P0 hypotheses), (d) keep `grounding.py` as precision gate on any quotes. Langextract's `extraction_passes` merge (`annotation.py:46-83`) could inform multi-pass unit checks, but first-pass-wins would **suppress** later-pass table findings — opposite of recall needs. Answer-class: **1**, **2**, **4**.

- [LOW] Whisker already selectively adopted langextract Tier-1 exact DP + char intervals in `grounding.py`; importing Tier-3 LCS fuzzy would **not** fix golden recall and would loosen precision. Evidence: `grounding.py:14-21` documents deliberate non-port of 0.75/1/3 LCS; SYNTHESIS pins wrong-span oracle at `fuzzy_alignment_cases_test.py:213-223`. Impact: further grounding work is inspect/locatability, not PR #286/#295 detection. Answer-class: **4**, **5**.

## False-pass hypothesis

PR #295 bikeshed secno headings: langextract-style chunking over HTML would still prompt "extract headings/defects from this chunk" (`prompting.py:136`) with no `span.secno` stripping rule in preprocessing or schema; model returns `pass`-equivalent empty extractions, aligner has nothing to ground, run completes with zero `char_interval` failures — same as baseline `heading_drift` empty sidecar (`00-baseline.md:62-64`).

## False-fail hypothesis

Langextract LCS fuzzy at density floor accepts a 3-token medication quote grounded to a 9-token clinical noise span (`fuzzy_alignment_cases_test.py:213-223`, `resolver.py:1403-1404`); whisker's `partial_ratio≥0.90` document floor (`constants.py:50`, `grounding.py:51`) might accept the quote but would not assert a localized wrong span — langextract would **over-trust** span locality if adopted wholesale as a verification stage.

## What would change my mind

A langextract release (or whisker prototype) that adds an explicit **uncovered-span report** after alignment — deterministic diff between chunk `char_interval` union and aligned extraction intervals, failing closed when coverage < threshold — demonstrated on a fixture planting PR #286 wrapped `SF` cells and PR #295 secno labels with **zero** reliance on the model voluntarily naming them first.
