# r02 - Repo miner: marker

**Verdict:** usable-with-conditions (+ marker's deterministic table geometry + TEDS eval are real portable patterns for whisker's P0 table-cell compare, but marker is a converter with LLM-as-producer, not an LLM verifier; it would not close PR #286/#295 recall on its own)
**Confidence:** high

## Findings

- [CRITICAL] Marker has **no LLM verification stage**; every LLM table/header processor **produces** corrected blocks and exits on "no corrections needed" with zero downstream audit. Evidence: `LLMTableProcessor.rewrite_single_chunk` returns early when `"no corrections needed" in corrected_html.lower()` (`marker/processors/llm/llm_table.py:207-209`); `LLMSectionHeaderProcessor` accepts `correction_type == "no_corrections"` and stops (`marker/processors/llm/llm_sectionheader.py:134-136`); `LLMPageCorrectionProcessor` same pattern (`marker/processors/llm/llm_page_correction.py:166-168`). Impact: identical subtractive funnel to whisker baseline PR #286 `accepted defect groups: 0/1` and PR #295 `generated defect claims: 0` — claims the model never generates are invisible (`00-baseline.md:50-51`, `74`, `84-85`). Answer-class: **4**, **5**.

- [CRITICAL] Table **cell-grid comparison exists only in offline benchmarks**, not in any runtime QA gate. Evidence: `benchmarks/table/scoring.py:92-106` `similarity_eval_html` runs APTED tree edit distance on `<td>` cells (Levenshtein on cell token lists via `CustomConfig.rename`, `43-48`); `benchmarks/table/table.py:21-25` scores predicted vs GT HTML with mean TEDS, CI floor `avg < 0.7` fails (`benchmarks/verify_scores.py:16-22`). Whisker side: `metrics.py` ports TEDS for Lane 2 bench, but tapetum_llm has **no table-cell comparison anywhere** (`00-baseline.md:54-55`); `PageUnit.has_tables` in `textlayer.py:86-98` is never read by `route_pdf_units` (`source_router.py:149-233`). Impact: marker proves cell-grid metrics are the right eval primitive; whisker's LLM lane never routes or checks table cells, so wrapped-header `SF`→`S` (PR #286) cannot be recalled. Answer-class: **2**, **1**.

- [HIGH] Wrapped/multi-line table cells are handled at **extraction geometry**, not by LLM verification: pdftext lines are assigned to cells by bbox intersection, then rows with equal multi-line counts are split. Evidence: `TableProcessor.assign_text_to_cells` maps text lines to cells via `matrix_intersection_area` (`marker/processors/table.py:427-455`); `split_combined_rows` splits when every cell in a row has the same `len(text_lines) > 1` (`marker/processors/table.py:312-343`); OCR path splits on `<br>` (`marker/processors/table.py:693`). `LLMTableProcessor` prompt allows `<br>` inside cells (`marker/processors/llm/llm_table.py:57`) but compares vision+HTML for **correction**, not candidate-vs-source QA. Impact: PR #286 failure is a **deterministic compare gap** in whisker, not something marker's LLM table pass would detect post-conversion; portable pattern is geometry+grid compare (`textlayer.py` + cell TEDS), not more table LLM judging. Answer-class: **1**, **2**.

- [HIGH] HTML-origin content is **rasterized to PDF** before any semantic handling; bikeshed `span.secno` structure is destroyed upstream. Evidence: `HTMLProvider.convert_html_to_pdf` uses WeasyPrint `HTML(...).write_pdf` (`marker/providers/html.py:26-32`); pipeline then runs PDF layout/OCR like any scan. `LLMSectionHeaderProcessor` prompt: "Only edit the h1…h6 tags. **Do not change any other tags or content in the headers.**" (`marker/processors/llm/llm_sectionheader.py:38-39`); example output keeps `"<h1>1 Vector Operations</h1>"` (`marker/processors/llm/llm_sectionheader.py:83`). Whisker mirror: `html_outline.py:66-81` collects **all** heading descendant text, so source `1. Abstract` matches candidate `1. Abstract` (`00-baseline.md:62-64`). Impact: secno stripping is a **golden-contract rule** encoded nowhere in either repo's LLM prompts or outline compare; marker's header LLM would preserve numbered labels by design. Answer-class: **1**.

- [HIGH] Marker benchmark **LLM scorer is holistic triage**, not cell/heading contract enforcement. Evidence: `benchmarks/overall/scorers/llm.py:15-44` rates overall/text/formatting/tables/section_headers on 0-5 from one page image + markdown; scoring notes "okay to omit… page numbers and chapter headings" (`llm.py:47`); failures are caught and **skipped** (`benchmarks/overall/overall.py:60-63`). Heuristic scorer (default CI path) uses pandoc round-trip + fuzzy block match + 20% Kendall-τ order (`benchmarks/overall/scorers/heuristic.py:39-40`, `clean.py:38-76`); `MarkdownCleaner` strips `<span>` but **keeps inner text** (`clean.py:27`), so numbered heading chrome survives normalization — same false-equivalence class as whisker outline. Impact: even marker's eval stack would not flag PR #295 secno retention as a defect unless GT explicitly omits numbers; supports baseline class **5** (LLM for triage, deterministic tripwires for countable defects). Answer-class: **5**, **1**.

- [MED] `LLMTableMergeProcessor` merges split tables via vision+json decision with deterministic `validate_merge` row/col count checks — portable **scoped unit** pattern, not verification. Evidence: merge prompt + `MergeSchema` (`marker/processors/llm/llm_table_merge.py:58-124`, `344-349`); `validate_merge` enforces row/col parity before join (`llm_table_merge.py:295-305`). Whisker analogue: scoped `unit_judge.py` calls with cap `MAX_UNIT_CHECKS=5` (`constants.py:223`, `unit_judge.py:225-241`) — marker shows structured merge decisions + geometry validators, but for **production extraction**, not golden QA. Answer-class: **2**, **3**.

- [MED] Marker CI gates **corpus means only** (heuristic ≥90, table TEDS ≥0.7), no per-item golden recall — aligns with whisker redteam finding. Evidence: `benchmarks/verify_scores.py:9-22`; no committed per-table baseline diff. Whisker `guard.py` is stricter per-paper but still lacks block-level/table-cell regression (`packages/whisker/research/redteam/marker.md:18-50`). Impact: neither ecosystem achieves "100% LLM verification of goldens"; marker reinforces deterministic aggregate gates + optional LLM diagnostics. Answer-class: **5**.

- [LOW] Internal table-rewrite **self-score retry** (1-5, retry if `<4`) is producer-side quality control, not external verification. Evidence: `llm_table.py:214-225`, `TableSchema` with `score: int` (`llm_table.py:323-327`). Whisker has no equivalent for table units; would not fix recall if the model scores a truncated `S` header as 5. Answer-class: **3**, **4**.

## False-pass hypothesis

PR #286 poll tables: marker-style `LLMTableProcessor` receives faithful-enough HTML where the wrapped header cell already reads `S` from upstream pdftext geometry; model returns `"No corrections needed."` (`llm_table.py:207-209`), `llm_error_count` stays 0, TEDS benchmark never runs at inference time — same false-clear as whisker LLM lane checking pages 1-4 and 13 while pages 8/9 are routed but displaced (`00-baseline.md:46-49`).

## False-fail hypothesis

Marker table benchmark TEDS uses char-token cell content without `<br>`/whitespace normalization (`scoring.py:43-48`, `51-64`); whisker's TEDS port matches OmniDocBench raw lists (`packages/whisker/research/persona/05-teds-port-fidelity.md:14`). A candidate with correct `SF` plus `<br>` vs GT `SF` could score below whisker's `TEDS_FLOOR` (0.80, `constants.py:56-58`) while humans pass — formatting-only table fail if cell-compare is added without marker/opendataloader-style content normalize.

## What would change my mind

A marker (or whisker) run showing **post-conversion** table QA — deterministic per-cell TEDS or geometry diff on PR #286 pages 8-9 **plus** HTML heading normalization that strips bikeshed secno before outline compare — catching both blockers **without** relying on an LLM to spontaneously name them, with measured recall on the dev-replay golden PRs.
