# r03 - Repo miner: MinerU + PDF-Extract-Kit

**Verdict:** usable-with-conditions — MinerU ships production-grade geometry for table-cell text assembly (PDF char fill, vertical-span merge, IoU OCR-to-cell matching) that whisker should port into a deterministic reference lane, but neither repo implements runtime output-vs-source cell verification or in-tree TEDS; PDF-Extract-Kit eval docs are empty stubs and its table path is VLM-only.
**Confidence:** high

## Findings

- [CRITICAL] **MinerU table HTML is built by IoU-matching OCR boxes to predicted cell bboxes, then concatenating matched tokens with spaces — no post-hoc diff against PDF text-layer coordinates.** `TableMatch.match_result` assigns each OCR box to a cell via pairwise IoU + distance (`matcher.py:132-158`); `get_pred_html` joins multiple OCR indices in one cell, inserting spaces between fragments (`matcher.py:181-201`). Wired-table path feeds sorted `ocr_result` into this matcher after wireless prediction (`batch_analyze.py:657-688`). Impact: PR #286's wrapped `S`+`F` failure mode is exactly "wrong tokens assigned/merged inside one cell"; MinerU solves it at **conversion** time, not at **QA** time. Whisker tapetum_llm has no equivalent hook (`00-baseline.md:54-55`). Answer-class: 2.

- [CRITICAL] **MinerU already implements vertical/wrapped glyph assembly from the PDF text layer — the portable pattern whisker's missing `table_compare` needs.** (a) Vertical spans: detect height/width ratio, then fill from pdfium lines top-to-bottom (`span_pre_proc.py:89-116`). (b) Vertical text blocks: group spans by x-overlap into columns, sort y within column (`span_block_fix.py:39-42`, `91-167`). (c) Horizontal char fill: assign page chars to spans by y-grid + x-center-in-bbox, then `chars_to_content` orders by `char_idx` and inserts spaces only when x-gap > 0.25× median char width (`span_pre_proc.py:243-296`, `537-579`). Impact: proves wrapped poll-header reading is a **deterministic geometry problem**, not something the LLM lane must rediscover; supports P0 table-cell compare anchored on PyMuPDF/pdfplumber reference + these merge rules. Answer-class: 1, 2.

- [HIGH] **Neither MinerU nor PDF-Extract-Kit contains an in-repo TEDS/GriTS (or any table metric) implementation; claimed table quality is external-benchmark only.** MinerU docs cite OmniDocBench End-to-End Overall scores (`docs/en/quick_start/index.md:99`); repo-wide `rg TEDS` on Python returns no metric module. PDF-Extract-Kit evaluation pages are placeholders (`docs/en/evaluation/table_recognition.rst:5`, `docs/en/evaluation/pdf_extract.rst:5`); `rg evaluation|TEDS` over `pdf_extract_kit/`, `project/`, `scripts/` Python finds **zero** eval code. Impact: ecosystem table QA is benchmark-time HTML-vs-GT (per `w2-table-cell-verification.md`), not live PDF-to-candidate diff; whisker cannot import a turnkey cell verifier from these clones. Answer-class: 5.

- [HIGH] **MinerU's only automated table QA is fuzzy substring presence on a toy fixture — it would false-clear PR #286-class defects.** `tests/unittest/test_e2e.py:171-199` checks `validate_html(table_body)` plus whether 10 target strings (e.g. `"Model"`, `"Linear"`) appear **anywhere** in `table_body`; no per-cell coordinate or `"SF"` assertion. Text blocks use `fuzz.ratio > 90` (`test_e2e.py:213-218`). Impact: even the upstream author's regression suite does not encode wrapped-cell contracts; aligns with baseline class 4 (verification subtracts only what tests encode). Answer-class: 4, 5.

- [MED] **Confidence scores gate model routing, not output-vs-source verification.** OCR spans below `OcrConfidence.min_confidence = 0.5` are dropped (`ocr_utils.py:10-11`, `380-381`). Table wired/wireless routing uses `cls_score` with 0.9 threshold (`batch_analyze.py:666-668`, `paddle_table_cls.py:147-149`). Layout blocks carry detection `score` in exported `model.json` (`docs/en/reference/output_files.md:68-79`). Post-hoc QA is **visual** (`layout.pdf`, `span.pdf` for human inspection, `output_files.md:17-51`), not scored cell diff. Impact: high cls/OCR confidence does not imply correct wrapped-header transcription; mirrors whisker anti-calibrated LLM confidence (`00-baseline.md:79-81`). Answer-class: 3, 5.

- [MED] **PDF-Extract-Kit table parsing is image→VLM transcription (StructEqTable), with span merge copied from MinerU but no PDF text-layer cell reference.** `StructEqTable.predict` calls `build_model(...).cuda()` and returns latex/markdown/html from page images only (`struct_eqtable.py:38-50`). Block/span assembly reuses MinerU-era y-overlap line grouping and overlap-ratio span-to-block assignment (`merge_blocks_and_spans.py:1`, `19-51`, `111-155`); paragraph merge strips/joins span text (`merge_blocks_and_spans.py:228-267`). Impact: same wrapped-cell risk as any OCR/VLM path; no secno/heading normalization (irrelevant to PDF table case); reinforces that PDF-Extract-Kit cannot supply HTML-outline fixes for PR #295. Answer-class: 1, 3.

- [LOW] **Concrete portable paths for whisker P0 table-cell compare (both sides of diff).** Source/reference side: MinerU `fill_char_in_spans` + `chars_to_content` (`span_pre_proc.py:243-579`) or vertical merge (`span_block_fix.py:91-167`) on PyMuPDF page chars at poll-table x-columns from baseline (`00-baseline.md:42-44`). Candidate side: parse markdown/HTML table cells on routed pages (`source_router.py:149-233` should prioritize `has_tables` pages). Comparator: per-(row,col) normalized string equality (pdfplumber-style exact lists per r10), **not** MinerU `matcher.py` IoU (that is converter logic). OCR sort order for table tokens: MinerU `batch_analyze.py:282-303` (y then x). Impact: closes class 2 without requiring LLM recall. Answer-class: 2.

## False-pass hypothesis

MinerU `test_e2e.assert_content` on a poll-style table whose `table_body` HTML contains `"Model"`, `"Testing"`, etc., but transcribes a wrapped header cell as `"S"` instead of `"SF"`: all substring checks pass (`test_e2e.py:194-199`) because no fact targets that cell; same acceptance pattern as whisker LLM lane `accepted defect groups: 0/1` (`00-baseline.md:52-53`).

## False-fail hypothesis

A whisker reference compare that strict-equals MinerU wired-table HTML cell text (space-joined OCR fragments from `matcher.py:199-200`) against a golden requiring `"SF"` with no whitespace normalization flags `"S F"` or `"S\nF"` as defects even when the human golden normalizes wrapped poll headers to concatenated letters (`00-baseline.md:93-95`).

## What would change my mind

Finding any Python module under `packages/whisker/research/repos/MinerU/` or `PDF-Extract-Kit/` that, at runtime, compares extracted table cell strings to PDF text-layer coordinates or source HTML and gates output on that diff (not OmniDocBench docs, not `XXX` eval stubs, not human `layout.pdf` inspection) — none exists in these clones as of 2026-07-22.
