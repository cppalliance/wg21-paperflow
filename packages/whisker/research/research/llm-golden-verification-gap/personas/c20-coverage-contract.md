# c20 - Coverage-contract designer

**Verdict:** usable-with-conditions (Deterministic exhaustive enumeration plus mechanical misalignment flags fixes answer classes 2 and 4 for the two incident defect types, but only after contract-encoded compare keys and PDF table-cell extraction; shipping the same design as an LLM yes/no lattice over every object at fixture scale is an over-engineered trap.)
**Confidence:** high

## Findings

- [CRITICAL] PDF source-side table-cell enumeration does not exist; the architecture's core P1068R11 fix depends on machinery we do not have. Evidence: baseline PR #286 states "no table-cell comparison exists anywhere in the lane" and proves cell boundaries only via external PyMuPDF geometry; `PageUnit.has_tables` is a page-level heuristic (`textlayer.py:256-272`, `272`) with no cell grid; `tables.py` parses candidate pipe/HTML grids only from markdown (`tables.py:50-83`, `86-120`), not from PDF source. Impact: forced accounting cannot mechanically flag six `|SF|`→`|S|` poll headers without a new source cell enumerator; LLM-per-object questions on table pages would still free-associate. Answer-class: 2 (routing bypass irrelevant without source objects), 1 (wrap reading is a contract rule). Measured: candidate snapshot `p1068r11.md` has 6 pipe tables / 60 cells (`packages/tomd/tests/fixtures/golden/snapshots/p1068r11.md`, counted 2026-07-22); PDF fixture has 10/15 pages with `has_tables=True` but zero enumerable source cells.

- [CRITICAL] HTML heading enumeration exists but uses the wrong contract key, so exhaustive alignment false-passes the P3953R0 blocker. Evidence: `extract_heading_outline` / `_HeadingExtractor.handle_data` concatenate all descendant text including `span.secno` (`html_outline.py:66-81`, `79-81`); baseline PR #295 records metadata/outline `pass` with empty `heading_drift` while four H2s retain `1.`–`4.` labels (`00-baseline.md:59-64`). Impact: enumerating every heading and aligning on raw outline text yields 4/4 false matches; forced accounting never fires unless secno stripping is encoded before object keys (answer-class 1), not unless an LLM re-asks yes/no on headings it was never told to normalize. Measured: candidate snapshot has 6 markdown headings, 4 of them the verified defect class (`p3953r0.md`); no `p3953r0.html` in `fixtures/golden/sources/` (fixture gap: source-side HTML counts unmeasured from fixtures).

- [HIGH] Roughly one-third of the enumeration stack exists for coarse units, under one-fifth for true per-object coverage with alignment. Evidence: exists — HTML/PDF unit extractors (`html_outline.py:84-91`, `179-184`; `textlayer.py:173-278`), candidate table grids (`tables.py`), block splitting and Hungarian match (`match.py:74-79`, block assignment elsewhere in module), facts assertion types including per-cell neighbors (`facts.py:69-77`, `tables.py` integration in facts), `draft_facts_scaffold` heading/table draft generation (`corpus_tools.py:162-223`, capped at two tables). Missing or not wired — tapetum has no import of `match.py` or exhaustive `facts.check_facts`; `golden_ideals.py:114-147` scores whole documents only; `chunking.py:8-18` splits on H2 for size, not object inventory; lists, inline code, and paragraph objects have no source enumerators in `source_router.py` or `html_outline.py`. Impact: ~35% reuse for "list all coarse units," ~15% for "every checkable object with source↔candidate alignment" as specified. Answer-class: 2, 5.

- [HIGH] Fixture-scale object counts explode LLM demand versus today's `MAX_UNIT_CHECKS = 5`. Evidence: `constants.py:223-226`; baseline PR #286 routed 9 PDF units but checked 5 (`00-baseline.md:46-48`). Measured on golden fixtures (2026-07-22): P1068R11 candidate snapshot ≈24 headings + 60 table cells + 22 code fences + 62 list markers + ~231 paragraph blocks ≈ **399 checkable objects**; P3953R0 candidate snapshot ≈6 headings + 2 code fences + 5 list markers + ~16 paragraphs ≈ **29 objects** (no source HTML in fixtures). Current v6 scoped lane budget: 1 metadata/outline call + up to 5 unit checks (`unit_judge.py:239-240`, `cli.py:154-157`) — **6 structured calls**, not 5, plus the separate monolith adjudication/PDF judge. Impact: even if only **10%** of P1068 objects stay ambiguous after mechanical rules, that is ~40 LLM calls vs 5 unit checks today; full per-object LLM accounting is 80× the current cap on the PDF incident paper alone. Answer-class: 2, 5.

- [HIGH] Forced accounting without contract normalization floods false misalignments on sanctioned conversions and PDF noise. Evidence: `_UNIT_CONVERSION_CONTRACT` explicitly sanctions TOC removal, front-matter YAML, and furniture drop (`unit_judge.py:67-75`); baseline PR #295 already routes spurious `heading_drift` "candidate missing" on YAML-mapped title sections (`00-baseline.md:68-70`). PDF side: P1068 fixture yields **74** font-heuristic `heading_candidates` vs **24** candidate markdown headings (`textlayer.py:246-250`, measured); `match.py:23-28` documents unported adjacency-merge so split/merged paragraphs misalign; baseline PR #286 wrap defect lives in geometry the text layer does not expose as a single cell token. Impact: naive "unaligned object = defect" would flag hundreds of benign items and drown the six real poll-table headers; LLM ambiguous-tranche would inherit class-3 false-clear/hallucination risk at scale. Answer-class: 1, 3, 5.

- [MED] The architecture correctly fixes verification asymmetry (class 4) only on the deterministic tranche. Evidence: baseline section on evidence verification — "zero RECALL power: claims the model never generates are invisible" (`00-baseline.md:84-85`); PR #295 had **0 generated defect claims** (`00-baseline.md:74`). Impact: mechanical misalignment records become first-class claims without model generation; the LLM tranche remains precision-only. If table-cell and normalized-heading compares land in deterministic preprocessing (P0 bundle hypotheses in baseline `00-baseline.md:115-118`), class 4 is solved without expanding LLM calls. Answer-class: 4.

- [LOW] `golden_ideals.py` is not an enumeration layer; it cannot substitute for object coverage. Evidence: `score_against_ideal` computes document-level nid/teds/mhs/recall only (`golden_ideals.py:114-147`); poll-table SF corruption preserves word tokens so ideal recall stays high (baseline PR #286, `00-baseline.md:41-44`). Impact: ideals remain advisory whole-doc scoring; exhaustive contract must live in new compare modules, not ideal panel reuse. Answer-class: 5.

## False-pass hypothesis

P1068R11 with PDF-only object keys: enumerate 74 font-sized "headings" and ~231 paragraph blobs from `extract_page_units`, align to 24 markdown headings and block-split candidate text without PDF cell grids; mechanical compare reports high agreement on poll pages because word tokens `S`,`F`,`N`,`A` are all present (`content_recall` stays above `PAGE_RECALL_FLOOR=0.90`, baseline `00-baseline.md:46-49`), ambiguous-tranche LLM receives no table-cell objects, and the lane again false-clears the six header-cell defects while claiming exhaustive coverage.

## False-fail hypothesis

P3953R0 after naive exhaustive enumeration without contract rules: every bikeshed chrome heading (`h2.no-num` subtitle, YAML-mapped `h1` title) and every `<script>`-polluted section body byte (`html_outline.py:168-172`, baseline recall `0.0437` on `section:6`) becomes an "unaligned object"; forced accounting emits dozens of mechanical defects and caps fusion at `review`/`fail` for coverage noise, none of which are the four secno-retention blockers humans care about.

## What would change my mind

A replay on the baseline PR #286/PR #295 hashes where a prototype enumerator emits source table-cell objects for all six poll headers (PDF geometry or equivalent), normalized HTML heading keys strip secno before align, mechanical flags produce deterministic defect records with zero LLM calls on those objects, and total LLM calls on the full paper stay ≤10 with measured ambiguous fraction <5% — proving the lattice shrinks to a small tranche instead of replacing 5 unit checks with hundreds.
