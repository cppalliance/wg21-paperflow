# c13 - Determinism auditor

**Verdict:** usable-with-conditions (+ pre-LLM stages are run-stable pure functions, but the lane is architecturally T3 non-guaranteed: >=25% measured verdict flips, zero multi-sample aggregation, and dev-replay CI never exercises live LLM output)
**Confidence:** high

## Findings

- [CRITICAL] The LLM stage is single-shot with no multi-sample, majority-vote, or rerun aggregation anywhere in `tapetum_llm`. Grep across all 24 lane modules finds no `majority`, `vote`, `ensemble`, `num_samples`, or k-of-n logic; each scoped unit check and monolith/metadata call goes through one `agent.run` / `run_judge_task` invocation (`judge_task.py:52-73`, `unit_judge.py:254-263`, `adjudicate.py:238-295`). Measured identical reruns on the alliance pod show >=25% verdict-flip rate (same paper, model, prompt; `00-baseline.md:78-79`, `CLAUDE.md:553-555`). Impact: a defect the model catches on run *t* may be missed on run *t+1* even when routing and packets are identical; "100% LLM verification" is not a stable target. Answer-class: 3. Fix paths: (a) k-of-n OR/majority voting on unit checks and monolith calls (3–5× LLM cost per paper); (b) server-side batch-invariant vLLM kernels (`tapetum_llm.md:31`, infra ask); (c) keep LLM advisory-only and move countable defects to deterministic tripwires (class 5).

- [HIGH] k-of-n voting math at the documented flip floor *f* = 0.25: treat per-run verdict stability as *P*(*same verdict*) <= 0.75. For a defect the model would catch on a stable run with single-trial probability *q*, a conservative per-run catch probability is *q*·(1−*f*) = 0.75*q*. Examples at *q* = 0.60 (optimistic when the right unit is checked): 1-of-1 recall ≈ 0.45; 2-of-3 majority ≈ 0.68 at 3× unit-call cost; 3-of-5 majority ≈ 0.74 at 5× cost; OR-any (flag if >=1 of 3 runs detects) ≈ 0.98 at 3× cost but raises false-alarm rate symmetrically. Coin Flip Judge literature (cited in `Auditv1/p10-llm-as-judge-eval.md`) needs ~11 trials for 95% majority recovery at 13.6% mean flip; our >=25% floor implies >=11 trials or acceptance of residual flip risk. Impact: voting improves recall only where the unit is actually checked; it cannot recover PR #286 pages 8/9 (never checked, `00-baseline.md:46-49`). Answer-class: 3 (+ class 2 interaction). Fix paths: raise `MAX_UNIT_CHECKS` / fix scheduling first (class 2), then add voting on checked units.

- [HIGH] Pre-LLM routing, packet construction, and grounding are run-to-run stable on fixed bytes: same inputs yield the same signals, packets, and dispositions. `route_pdf_units` iterates `_CPP_KEYWORDS` in fixed tuple order (`source_router.py:27-30,166-189`); page units come from sequential `range(doc.page_count)` with bbox-sorted blocks (`textlayer.py:193-213`); unit scheduling sorts `(severity_rank, unit_id, signal_type, detail)` before cap (`unit_judge.py:225-240`); grounding uses deterministic DP + fixed float floors (`grounding.py:327-329`, `constants.py:177,219`); sidecar serialization sorts collections (`models.py:370-380`). The PR #286 miss is **deterministic** starvation (lexical `page:13` < `page:2`, cap 5), not run-to-run variance (`00-baseline.md:46-49`, `constants.py:223-226`). Impact: rerunning tomorrow reproduces the same wrong unit set; flip noise applies only after routing. Answer-class: 2 (scheduling), not 3. Fix path: numeric unit-id sort + table-aware priority (P0 remediation scheduling hypothesis).

- [MED] D7 (sort before prompt/output) is largely satisfied in `tapetum_llm`: no unsorted `set`/`dict` keys feed LLM prompts. Residual unsorted iterations are non-prompt paths: `unit_text_map.values()` in mechanical counting only (`unit_judge.py:442-445`); `line_counts.items()` builds a membership set, order irrelevant (`textlayer.py:308-314`); `models.items()` in agent construction only (`adjudicate.py:654-661`). `fusion_report.py:280` and `cli.py:796` sort dict items for display. No filesystem-order dependence found (`cli.py:721,760` use `sorted(glob(...))`). Impact: pre-LLM nondeterminism from collection order is not a identified recall-loss vector; the LLM stage dominates variance. Answer-class: 3 (variance is downstream, not from D7 violations).

- [MED] Documented LLM variance exceeds sampling pins: `tapetum_llm.md:31` states token-level output on a hosted vLLM pod is not bit-stable under continuous batching and MoE routing even at serial per-paper concurrency; paper-level `--concurrency` default 32 (`tapetum_llm.md:29`, `cli.py` / `judge_task.py:17-23`) adds load-driven flip beyond the >=25% baseline. `judge_task.py:27-29` preserves D2 sampling pins but explicitly documents a variance budget. Impact: identical bytes + prompts can still flip verdicts when pod load or batch composition changes; fingerprint skip (`cli.py` incremental) freezes **one** stochastic draw, not truth. Answer-class: 3. Fix paths: batch-invariant server mode; serial pod runs for measurement; sidecar replay for regression tests (see below).

- [MED] `corpus/dev-replay` does **not** replay recorded LLM outputs; CI tests are hermetic on deterministic stages only. `test_dev_replay_acceptance.py:8-19` states "LLM verdict accuracy is measured separately in runtime replays"; tests cover label consistency and router signals (`route_pdf_units`, `extract_page_units`), not `run_unit_checks` or live model calls. `test_pdf_judge.py:502-505` "20-quote development replay" replays **inline candidate excerpts** through deterministic `classify_candidate_evidence`, not saved sidecar JSON. `test_tapetum_llm.py` mocks `run_agent` (`test_tapetum_llm.py:609+`). Impact: green CI proves router/grounding stability, not LLM recall; live drift and flip rate are invisible to automated gates. Answer-class: 3, 5. Fix paths: optional recorded sidecar replay fixtures for regression (deterministic but blind to live drift); holdout live replays for calibration only.

- [LOW] Float comparisons in routing and grounding use named constants with stable IEEE semantics on identical inputs (`PAGE_RECALL_FLOOR = 0.90`, `TOKEN_DELTA_THRESHOLD = 5`, `EVIDENCE_FUZZY_FLOOR` in `constants.py:177,219`; `content_recall` / `partial_ratio` thresholds in `source_router.py:194-195`, `grounding.py:327-329`). No epsilon-random or platform-dependent math found. Impact: threshold boundaries are reproducible; borderline recall values (e.g. PR #295 `section:6` recall 0.0437, `00-baseline.md:71-72`) route deterministically. Answer-class: 1 (contract) / 2 (routing signal quality), not flip-related.

## False-pass hypothesis

PR #286 head bytes, stable routing: pages 8/9 unchecked every run (deterministic cap displacement). On a checked unit (page 13), run A returns pass-with-empty-defects at conf 0.98; run B emits a false heading claim that dies as `ambiguous=1` (`00-baseline.md:50-51`). Fusion stays `review` via `source_aware_review_cap` both times (`00-baseline.md:52-53`), masking that the LLM never stably names the poll-table blocker. Operator reads coverage caution, not a reproducible defect finding.

## False-fail hypothesis

A clean paper where run A returns pass on all unit checks and run B hallucinates one scoped defect (page-13 false-claim pattern). Evidence verification refutes or abstains on B, but fusion caps at `review` (`fusion.py:183-196`); deterministic lane stays `pass`. Operator sees flip between advisory pass-equivalent and review without a deterministic fail, purely from LLM variance.

## What would change my mind

A controlled 20-paper × 10-rerun experiment on the alliance pod (serial, pinned manifest) reporting per-paper verdict flip rate **after** scheduling fixes check PR #286 pages 8/9, showing flip rate <=5% **or** demonstrating that 3-of-5 majority voting on those unit checks recovers >=95% of human-verified defect groups at documented cost—and that dev-replay gains a sidecar-replay test that fails when live drift exceeds the recorded envelope.
