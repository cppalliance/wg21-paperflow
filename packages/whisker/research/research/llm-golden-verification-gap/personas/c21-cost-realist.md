# c21 - Cost realist

**Verdict:** usable-with-conditions (+ the five-unit cap is a batch-pipeline latency guard misapplied to a rare, high-stakes golden-PR event; on alliance-pod hourly billing, raising recall is essentially free in dollars and cheap in wall-clock per PR)
**Confidence:** high

## Findings

- [CRITICAL] **Marginal LLM dollar cost is zero on the production pod; `MAX_UNIT_CHECKS=5` is not a budget constraint.** Evidence: `SERVICES.toml:62-63` ("Runs 24/7; billed per hour of uptime, NOT per token, so run size is not a cost question"); same statement in `packages/whisker/src/whisker/CLAUDE.md` tapetum availability section. Impact: every recall lever below is a wall-clock question, not a token-invoice question; rationing five unit checks to protect pod spend is category error for golden verification. Answer-class: 5.

- [CRITICAL] **Current source-aware v6 per-paper LLM load at `MAX_UNIT_CHECKS=5` is ~7 serial calls and ~54k tokens on a heavy PDF golden (PR #286 profile), ~3.5 min wall at measured batch load.** Token model (conservative, from measured corpora): text-lane monolith P50 input 8538 tok (`research/llm-batching/17-latency-decomposer.md:12-14`: P50 stripped md 22242 chars ≈ 5560 tok + shared system/schema ≈ 2916 tok); PDF monolith adds a second full-document payload (`pdf_judge.py:633-636`: RAW PDF TEXT + CONVERTED MARKDOWN) → ~14k in + ~800 out; metadata/outline ~2.7k in + ~250 out (`unit_judge.py:134-170`, `_SOURCE_METADATA_CHARS=4000` at `adjudicate.py:92`); each unit check repeats full candidate md (~5560 tok) plus one page/section source packet (`unit_judge.py:581-588`) → ~7.1k in + ~400 out per call. PR #286 executed 1 monolith + 1 metadata + 5 units = 7 calls (`00-baseline.md:46-49`). Wall: 7 × 30.4 s mean per-call at c=3 (`research/llm-batching/17-latency-decomposer.md:10`, `00-baseline.md:12-14`: 213 calls / 2159.8 s) ≈ 213 s (~3.5 min); solo golden-PR rerun is faster (~70 tok/s decode, `research/llm-batching/21-terse-output.md:24`, `pdf_judge.py:28`) → ~2–2.5 min realistic. Impact: the cap removed pages 8/9 for ~2 min saved on a merge-blocking review. Answer-class: 2.

- [HIGH] **Checking all routed units (9–12) adds ~4–7 calls, ~28–50k tokens, ~2–3.5 min serial per golden PDF; trivially feasible per PR, prohibitive if naively multiplied across a mailing.** PR #286 routed nine units, checked five (`00-baseline.md:46-49`); PR #295 routed three HTML sections, checked two (`00-baseline.md:66-73`). Increment over current: +4 unit calls on PR #286 → +~28k tok, +~122 s at 30.4 s/call. Upper bound "every page routed" on a 15-page PDF: ~17 calls (~125k tok, ~8.6 min serial). Mailing scale: ~160 papers per WG21 mailing (`packages/agora/reddit-design.md:15`); 160 × 8.6 min ≈ 23 h serial for exhaustive per-page LLM checks — fleet-infeasible, golden-PR-feasible. Answer-class: 2, 5.

- [HIGH] **k-of-3 voting per routed unit is ~3× unit-check cost: PR #286 would be ~29 calls, ~215k tokens, ~15 min serial — still cheap for one golden PR, absurd for a full corpus.** Arithmetic: 2 base calls + 9 routed × 3 votes = 29 calls; unit tier ≈ 9 × 3 × 7.1k ≈ 192k tok plus monolith/metadata ≈ 215k total; 29 × 30.4 s ≈ 882 s. Full converted fleet (~200 papers, `research/llm-batching/00-baseline.md:12`) at that profile: ~43M tokens and ~50 h serial — a batch-triage budget, not a golden gate. Answer-class: 3, 5.

- [HIGH] **P0 deterministic fixes (heading normalization, table-cell compare) cost zero LLM tokens; they are the cheapest recall levers.** Evidence: P0 spec in `PR286-LLM-FALSE-CLEAR.md:223-272` — normalize outlines/secno stripping and PyMuPDF column-boundary table-cell packets are preprocessing, not `run_judge_task` calls; baseline confirms no table-cell compare exists (`00-baseline.md:54-55`). Impact: wrapped `SF`→`S` on PR #286 should be caught deterministically before any unit budget is spent; arguing against P0 on LLM cost grounds is wrong. Answer-class: 1, 5.

- [MED] **P0 scheduling + full routed-unit LLM coverage per golden PR: ~83k tokens, ~5.5 min serial on PR #286 — roughly 1.5× current lane cost, not an order of magnitude.** Components: keep monolith + metadata (~17.5k tok); check all nine routed units instead of five (+4 × 7.1k ≈ +28k); optional ideal verifier when a tomd ideal exists (+1 call, ~3k tok, `cli.py:924-946`). Versus today's ~54k / ~3.5 min. HTML golden (PR #295): all three routed sections + fix empty `section:0` packet (`00-baseline.md:72-73`) → ~34k tok, ~4 calls, ~2 min. Impact: full coverage is affordable precisely because golden PRs are rare (below). Answer-class: 2.

- [MED] **Readback transcription of every table region and full-document checklist passes are the only recall levers that hurt per golden PR (~8–30 min) and explode at mailing scale.** Readback sends full `paper.md` per fact (`readback.py:67-68`, `_MAX_ANSWER_TOKENS=512`); comprehension corpus averages ~7.4 verified facts/paper (`whisker/CLAUDE.md`: 37 facts / 5 papers). Table-heavy PR #286 (six poll tables) could require tens of cell-level Q&A calls if modeled on readback → ~180–370k tok, ~8–30 min serial per paper. Full H2 checklist (20–30 sections × unit-check shape) → ~140–210k tok, ~10–15 min. Feasible for one pre-merge golden review; infeasible as default for ~160 papers/mailing or ~200-paper corpus refresh (`research/llm-batching/00-baseline.md:12`). Answer-class: 5.

- [MED] **Golden-PR events are rare; the five-check cap optimizes the wrong denominator.** Evidence: nine human-reviewed golden PRs in `packages/whisker/corpus/dev-replay/labels.json` and README (#282–#295); two recent branchless reviews (#286, #295) are the recall failures under study (`00-baseline.md:34-75`). Converted fleet ≈200 papers (`research/llm-batching/00-baseline.md:12`); mailing ≈160 papers (`packages/agora/reddit-design.md:15`). tomd `baselines.json` lists four QA-baseline fixtures (cwg1, p4020r0, p4182r0, p4228r0), not golden-PR count — do not conflate. Impact: saving four unit checks × 200 papers ≈ 800 calls (~6.8 h at 30 s) matters for batch triage; saving four calls on one merge-blocking golden PR does not. The cap is a batch-pipeline guard (`constants.py:223-226` mirrors `MAX_PAGE_ESCALATIONS=5` at `constants.py:185-191`) wrongly treated as golden-verification policy. Answer-class: 5.

## False-pass hypothesis

Operator runs current lane on PR #286, sees `review` with 0 defect groups, interprets hourly-pod "no token budget" guidance (`SERVICES.toml:62-63`) as "coverage caution is enough," merges without reading sidecar `unchecked_unit_ids` containing `page:8`/`page:9` (`00-baseline.md:46-49`, `unit_judge.py:239-240`). Cost framing falsely legitimizes shipping: "we already spent seven LLM calls."

## False-fail hypothesis

Patch raises `MAX_UNIT_CHECKS` to 12 and checks all routed units on a clean paper with nine medium `heading_drift` noise signals (`source_router.py:218-231`, PR #286 pattern): +7 extra calls (~49k tok, +3.5 min) with no merge blocker present; one hallucinated unit defect caps fusion at `review` anyway (advisory never hard-fails). False-fail is operator time and triage noise, not deterministic rejection — unless the team mistakenly treats advisory `review` as merge-blocking.

## What would change my mind

Measured alliance-pod invoice showing per-token billing for tapetum_llm (contradicting `SERVICES.toml:62-63`), or a golden-PR replay where P0 deterministic table-cell compare plus checking all nine routed units still costs >30 min wall and misses the SF→S blocker — proving recall is capability-bound (class 3), not cost-bound.
