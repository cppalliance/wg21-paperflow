# c04 - PDF textlayer attacker

**Verdict:** usable-with-conditions (Flat `get_text("text", sort=True)` linearization is adequate for coarse prose/heading loss, but table-cell golden defects are information-destroying on this representation: geometry is parsed then discarded, wrapped poll headers appear as separate line fragments, and prompts falsely imply table-structure fidelity the packets cannot support.)
**Confidence:** high

## Findings

- [CRITICAL] Every LLM-facing source packet is a flat string from `page.get_text("text", sort=True)`, not structured table geometry. Evidence: monolith injection uses `normalize_textlayer(pages)` built from `extract_textlayer` → `get_text("text", sort=True).strip()` per page (`textlayer.py:111-113`, `141`, `341-355`); unit checks map `f"page:{unit.page}": unit.text` where `PageUnit.text` is `clean_pages(raw_text)` and `raw_text` is the same mode (`textlayer.py:196-197`, `256`, `267-270`, `pdf_judge.py:837-838`, `unit_judge.py:585-586`). Impact: vertically wrapped poll header `SF` (baseline PR #286: `S`+`F` stacked at x=77.25 vs column `F` at x=100.5) reaches the model as separate line/token fragments, not a recoverable cell string; even a perfect model cannot reliably infer "same cell, concatenate" without x-coords or an explicit wrapped-cell contract. Answer-class: 1 (contract gap) and 5 (100% LLM table verification is the wrong metric on this input).

- [CRITICAL] PyMuPDF `get_text("dict")` computes span-level layout, then almost all of it is discarded before any LLM call. Evidence: `extract_page_units` calls both modes per page (`textlayer.py:196-198`); dict traversal reads `blocks`/`lines`/`spans` with `bbox` and per-span `size` (`textlayer.py:204-239`), but only derives booleans and string lists—`has_images`, `_block_looks_tabular`, `heading_candidates`, `caption_lines`, `code_token_count`—while `PageUnit.text` comes solely from the parallel `get_text("text")` string (`textlayer.py:256-275`); span x/y positions and block bboxes are never serialized into packets. Impact: the baseline's proven column-x discrimination (72.5/95.5/…/167.5) exists transiently in memory and cannot reach unit checks or grounding; table-cell defect detection is structurally untestable on the fed representation (class 3 moot for this defect class). Answer-class: 1, 5.

- [HIGH] `has_tables` detects multi-span rows or "Table N" captions but has zero downstream consumers in the PDF lane. Evidence: `_block_looks_tabular` flags blocks with ≥2 lines each having ≥2 nonempty spans (`textlayer.py:160-170`, `221-224`); `has_table_caption` ORs caption prefix (`textlayer.py:253-260`, `272`); grep shows `route_pdf_units` never reads `unit.has_tables` (`source_router.py:191-231`); baseline confirms "no table-cell comparison exists anywhere in the lane" (`00-baseline.md:53-54`). Impact: pages 8-9 are known table pages at extraction time yet receive no table-targeted routing or richer packets; PR #286 table blockers depend on incidental heading/recall noise and budget luck. Answer-class: 2.

- [HIGH] Prompts claim table fidelity judgment, but SOURCE TEXT lacks grid/cell structure the rubric assumes. Evidence: monolith prompt asks the model to judge "sections, prose, tables, code blocks, math, references" against "RAW PDF TEXT" with only line-break noise called out (`pdf_judge.py:198-205`); unit prompt lists `table_corruption` as a defect type (`unit_judge.py:104-105`) while SOURCE TEXT is one bounded page string with no column delimiters (`unit_judge.py:94-96`, `585-586`); module docstring admits text-layer path is "block-sorted reading order" independent of tomd (`textlayer.py:12-13`). Impact: the lane invites table-cell findings the input cannot ground; model capability (class 3) cannot be measured for wrapped-cell defects when the test fixture destroys the discriminating information. Answer-class: 1, 4.

- [HIGH] Multiset `content_recall` on linearized page text cannot fire on PR #286-style single-character cell truncation. Evidence: `content_recall` matches reference word-token multisets only (`metrics.py:376-393`); baseline blocker keeps tokens `S`, `F`, `N`, `A`, `SA` present in source and candidate while mis-assigning `F` across poll columns (pages 8-9); per-page screen uses the same metric (`pdf_judge.py:311-335`, `constants.py:177`). Impact: table pages may never get `low_recall` signals; pages 8/9 were routed for other reasons then displaced (`00-baseline.md:46-48`, `MAX_UNIT_CHECKS=5` at `constants.py:223`). Answer-class: 2.

- [MED] Conversion contract explicitly sanctions line-break/dehyphenation differences that mask vertical cell wrap. Evidence: `_CONVERSION_CONTRACT` states "Prose paragraphs are unwrapped… differing line breaks are not defects" (`pdf_judge.py:186-188`); per-page screen applies `_dehyphenate` before recall (`pdf_judge.py:120-132`, `323`). Impact: a model following the contract treats stacked `S`/`F` lines as sanctioned reflow, not evidence that the candidate should read `SF`; works against golden wrapped-cell reading rules that live only in human skill docs (baseline answer-class 1). Answer-class: 1.

- [MED] `table_corruption` unit defects are never mechanically verified—only `qualifier_omission` keyword counts get `count_status=verified`. Evidence: `verify_defect_counts` marks all non-qualifier groups `count_status: unverified` (`unit_judge.py:467-469`); grounding checks verbatim `source_quote` substring presence (`unit_judge.py:524-542`), which succeeds for `"S"` or `"F"` fragments whether or not the candidate merged them into `SF`. Impact: even a generated table claim would face class-4 verification asymmetry (precision without recall power per baseline §Evidence verification). Answer-class: 4.

- [LOW] `extract_page_units` re-opens the PDF and re-extracts text after the monolith already consumed `extract_textlayer`, doubling I/O without reconciling dict-derived metadata into the LLM string. Evidence: `judge_pdf_extraction` calls `extract_textlayer` then later `extract_page_units(source_path)` (`pdf_judge.py:597-600`, `653-654`); both paths use `get_text("text", sort=True)` for strings but only the second pass parses dict layout (`textlayer.py:104-157` vs `173-280`). Impact: engineering waste, not the primary recall loss, but confirms layout parsing is side-channel metadata only. Answer-class: 2.

## False-pass hypothesis

P1068R11 pages 8-9: `PageUnit.text` linearizes poll tables as whitespace/newline-separated fragments including both `S` and `F` tokens; candidate pipe tables show `|S|` in wrapped header cells while source multiset recall stays ≥ `PAGE_RECALL_FLOOR=0.90`; `has_tables=True` is ignored; unit packets for `page:8`/`page:9` are displaced by lexical unit-id sort under `MAX_UNIT_CHECKS=5` (baseline routed 9, checked 5, true-positive groups 0/1). The lane caps at coverage `review`, never naming the six `|SF|`→`|S|` instances.

## False-fail hypothesis

Any PDF page where PyMuPDF `sort=True` reading order interleaves multi-column table rows as consecutive plain lines: a model could emit `table_corruption` comparing ragged source lines to a well-formed pipe table, but the conversion contract declares differing line breaks non-defects (`pdf_judge.py:186-188`), so faithful markdown table structure could be flagged as corruption despite correct cell content.

## What would change my mind

A reproducible extract of P1068R11 pages 8-9 at baseline source SHA showing `get_text("text", sort=True)` emits contiguous `SF` on one line for the wrapped poll-header cells (contradicting baseline geometry at x=77.25), OR a patched lane that serializes span x-coords/cell groupings into the unit packet and still fails to detect the verified defect— that would shift blame toward class 3 instead of representation.
