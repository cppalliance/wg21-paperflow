# c02 - Budget scheduler attacker

**Verdict:** usable-with-conditions (+ scheduling/budget design is a proven recall killer on golden PRs; fixable without abandoning the lane, but `MAX_UNIT_CHECKS=5` with lexical tie-break is indefensible against 9+ routed units on hourly pod billing)
**Confidence:** high

## Findings

- [CRITICAL] PR #286 pages 8/9 were routed then displaced by the five-unit cap under severity-then-lexical unit-id sort: nine medium `heading_drift` signals (`source_router.py:218-231`) produced routed units `{page:1..6, page:8, page:9, page:13}`; `run_unit_checks` sorts `(severity_rank, unit_id, signal_type, detail)` (`unit_judge.py:225-234`), groups by first-seen unit_id (`unit_judge.py:235-238`), takes `risky_unit_ids[:MAX_UNIT_CHECKS]` (`unit_judge.py:239-240`, `constants.py:223-226`). Equal medium severity yields lexical order `page:1, page:13, page:2, page:3, page:4, page:5, page:6, page:8, page:9` because `"page:13" < "page:2"` (char `'3' < '2'` after shared `"page:1"` prefix). Top five checked: 1, 13, 2, 3, 4; unchecked: 5, 6, 8, 9 (`00-baseline.md:46-49`, `PR286-LLM-FALSE-CLEAR.md:138-140,585-591`). Impact: the human-verified poll-table blocker on pages 8-9 never received an LLM unit call; recall lost before model capability is tested. Answer-class: 2.

- [HIGH] Numeric page ordering alone would not have saved pages 8/9 on PR #286: even with `page:1..13` numeric sort, top five are pages 1-5; pages 8/9 sit at positions 8-9 and still require `MAX_UNIT_CHECKS >= 8` or routing-noise reduction (`unit_judge.py:239`, nine routed units). Impact: the common "fix lexical sort" patch is necessary but insufficient; cap raise or signal deduplication is also mandatory. Answer-class: 2.

- [HIGH] `MAX_UNIT_CHECKS=5` is misaligned with observed route cardinality and with the lane's own timeout budget: PR #286 routed 9 units; PR #295 routed 3 HTML sections (`00-baseline.md:66-73`). CLI wall-clock budgets `(1 + MAX_UNIT_CHECKS) * UNIT_CHECK_TIMEOUT_SECONDS` = 6×120s = 720s for metadata plus unit calls (`cli.py:150-157`, `constants.py:223-229`), implying the authors expected up to six scoped calls, not nine. Yet whisker CLAUDE.md states alliance-pod billing is per hour of uptime, not per token, with no rationing ("run the full corpus freely"). Impact: the cap is a latency guard copied from `MAX_PAGE_ESCALATIONS=5` (`constants.py:185-191`), not a cost constraint; keeping it at 5 while routing 9+ units is a recall defect, not fiscal prudence. Answer-class: 2, 5.

- [HIGH] Low-precision `heading_drift` signals crowd high-value units: `route_pdf_units` emits one medium signal per page when any `heading_candidates` line is absent from candidate ATX keys (`source_router.py:218-231`); PR #286 produced nine such signals including prose-heavy false positives on pages 4-6 (`PR286-LLM-FALSE-CLEAR.md:583-584`). No dedupe, specificity score, or `has_tables` boost exists despite `PageUnit.has_tables` (`textlayer.py:86-98`) being unread by `route_pdf_units` (`00-baseline.md:54-55`). Impact: same-severity noise units consume finite slots; table-bearing defect pages lose by sort lottery. Answer-class: 2.

- [MED] HTML `section:N` IDs suffer the same lexical trap as PDF pages: unit ids are `f"section:{index}"` (`source_router.py:250,278`); tie-break order is `section:0, section:1, section:10, section:11, ..., section:2` (string compare on the suffix). PR #295 checked `section:1` and `section:6` while `section:0` was routed-but-unchecked due to empty source packet (`00-baseline.md:72-73`, `unit_judge.py:248-252`). Impact: multi-section HTML papers with >5 risky sections will displace later-index sections (often body content) under cap identically to PR #286's page lottery. Answer-class: 2.

- [MED] Unchecked routed units are persisted and fail-closed in fusion, but human inspect output drops the IDs: `unit_judge.py` appends cap-overflow and empty-packet units to `unchecked_unit_ids` (`unit_judge.py:240,251,332`); sidecar stores them (`pdf_judge.py:851-854`); `_source_aware_requires_review` caps fusion at review when `unchecked_unit_ids` non-empty (`fusion.py:192-196`). `inspect_report.py` reads `checked_unit_ids`/`unchecked_unit_ids` but renders only counts (`complete=…, checked=N, unchecked=M`), never listing which units (`inspect_report.py:184-196`). Impact: programmatic consumers see displacement; operators reading `--inspect` see "unchecked=4" without `page:8`/`page:9`, so coverage caution looks generic, not localized. Answer-class: 2.

- [LOW] Document-wide `token_delta` signals attach to the first page containing a keyword, not every deficit page (`source_router.py:166-189`), and share the same severity-lexical queue as page-local signals. A single `constexpr` delta on an early page can consume a slot that would otherwise reach a later table page. Impact: secondary displacement path independent of heading noise. Answer-class: 2.

## False-pass hypothesis

PR #286 with current scheduling: nine medium heading-drift routes, lexical top-five checks pages 1/13/2/3/4 only; pages 8/9 (poll-table `SF`→`S` wrapped-cell defect) stay unchecked; all five unit checks return pass-with-empty-defects; evidence verification has zero claims to refute; fusion emits `review` via `source_aware_review_cap` (`fusion.py:183-196`, `00-baseline.md:50-52`) which is indistinguishable from "found something" in the merged verdict label. Deterministic lane remains `pass` (`00-baseline.md:41-43`). Operator sees conservative `review` without a named table defect: effective false-clear on the blocker.

## False-fail hypothesis

A clean 20-page PDF where pages 1-5 and page 13 emit medium `heading_drift` from PDF font extraction noise (large-font prose fragments misclassified as headings, same mechanism as PR #286 §6.2): numeric-unaware lexical sort selects `page:1, page:13, page:2, page:3, page:4`; five LLM calls burn budget on chrome; if any call hallucinates a heading defect (page-13 false claim pattern, `00-baseline.md:50-51`), evidence verification may abstain (`ambiguous=1`) and cap at `review` even though no real golden defect exists. False-fail is fusion-level triage noise, not deterministic fail.

## What would change my mind

A replay of PR #286 head bytes with patched scheduling (numeric unit-id sort + `has_tables` priority or `MAX_UNIT_CHECKS` ≥ routed count) that checks pages 8/9 and either emits a verified table defect group or a logged, inspect-visible `unchecked_unit_ids` entry with explicit displacement reason—proving the blocker was reachable under budget, not model-blind.
