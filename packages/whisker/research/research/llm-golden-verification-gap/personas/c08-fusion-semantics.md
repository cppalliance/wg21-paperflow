# c08 - Fusion semantics attacker

**Verdict:** usable-with-conditions (Fusion faithfully implements advisory fail-closed triage and correctly capped both golden PRs at `review`, but the merged label and primary reports collapse coverage caution and verified-defect detection into one rule name, so operators cannot infer recall failure from the fused output alone.)
**Confidence:** high

## Findings

- [CRITICAL] Every merged `fail` is whisker-locked; the LLM lane never hard-fails when deterministic verdict is not already `fail`. Evidence: `fuse_verdicts` docstring (`fusion.py:22-23`) states merged never goes to `fail` when det is not fail; the only `VERDICT_FAIL` return is the `det == VERDICT_FAIL` branch with `FUSION_RULE_WHISKER_FAIL_LOCKED` (`fusion.py:364-388`), except heading-monotone-only rescue demotes to `review` (`fusion.py:366-377`). Baseline PR #286/PR #295 both had deterministic `pass`. Impact: fusion cannot close the golden-verification gap by naming blockers; it can only demote or preserve. Answer-class: 5.

- [CRITICAL] Both failing papers got `review` via `source_aware_review_cap` from coverage-only triggers, with zero accepted defect groups. Evidence: baseline PR #286 — metadata/outline `pass`, accepted defect groups 0/1, pages 8/9 routed but unchecked under `MAX_UNIT_CHECKS=5`; PR #295 — metadata/outline `pass` with empty `heading_drift`, generated defect claims 0, `section:0` routed but unchecked. `_source_aware_requires_review` returns true when `coverage_complete` is not true or `unchecked_unit_ids`/`failed_unit_ids` are non-empty (`fusion.py:192-196`) without requiring any defect group; accepted-defect paths at `fusion.py:198-214` were unused. Impact: the lane's only non-pass signal on both goldens was "something was not fully checked," not "defect found." Answer-class: 4.

- [HIGH] Complete enumeration of `fuse_verdicts` exit paths (12 rules, 3 verdicts). Evidence: (1) `whisker_only` → merged=`det` when tapetum absent/error/stub (`fusion.py:346-357`); coverage-driven when det=`pass`/`review`, detection-neutral. (2) `whisker_fail_locked` → merged=`fail` when det=`fail` and not heading-only rescue (`fusion.py:378-388`); deterministic-driven. (3) `llm_rescue_heading` → merged=`review` when det=`fail`, heading-only hard flags, llm `pass`/`review` (`fusion.py:366-377`); deterministic-driven demotion. (4) `source_aware_review_cap` → merged=`review` when det in (`pass`,`review`) and `_source_aware_requires_review` (`fusion.py:391-404`); **coverage-driven** subpaths: metadata not `pass` (`fusion.py:188-190`), incomplete coverage / unchecked / failed units (`fusion.py:192-196`); **detection-driven** subpaths: verified high/critical count groups (`fusion.py:205-210`), accepted unit defects or flat dispositions (`fusion.py:211-214`). (5) `ideal_review_cap` → merged=`review` when ideal verifier verdict is `review` (`fusion.py:406-417`); detection-driven (ideal discrepancies). (6) `clear_blocked_missing_region` → merged=`review` when det=`review`, soft-only, llm `pass`, `missing_region_count>0` (`fusion.py:424-438`); deterministic-driven. (7) `clear_blocked_ideal_flag` → merged=`review` when det=`review`, soft-only, ideal soft flag, llm `pass` (`fusion.py:441-456`); deterministic-driven. (8) `llm_clear_soft_review` → merged=`pass` when det=`review`, soft-only, llm `pass`, confidence floor, ref_nid guard (`fusion.py:458-496`); LLM-driven promotion. (9) `llm_escalate_major` → merged=`review` when det=`pass`, llm `fail`, `_has_major_axis_fail` on `axis_findings` (`fusion.py:499-512`); detection-driven without defect groups. (10) `agree` / (11) `whisker_only` (usable tapetum) → merged=`det` when no prior rule matched (`fusion.py:514-526`); passthrough. Impact: only rules 4 (partial), 5, and 9 encode LLM-found problems; rule 4 also fires on lane-local deterministic coverage alone. Answer-class: 4.

- [HIGH] Fusion can cap at `review` without any accepted LLM defect group; lane-local deterministic sidecar fields suffice. Evidence: `_source_aware_requires_review` gates on `unit_coverage.coverage_complete`, `unchecked_unit_ids`, and `failed_unit_ids` (`fusion.py:192-196`) computed upstream in `unit_judge.py`/`pdf_judge.py`/`adjudicate.py`, not on whisker sidecar; `test_incomplete_coverage_caps_pass_at_review` pins this (`test_fusion.py:633-654`). Refuted or unaccepted high/critical groups explicitly do not demote (`fusion.py:26`, `test_fusion.py:526-631`, `test_fusion.py:610-631`). Impact: deterministic scheduling/budget signals alone produce the same fused verdict shape as verified omission detection. Answer-class: 4.

- [HIGH] A human reading only the fused `review` label cannot distinguish "LLM found something" from "LLM did not cover everything." Evidence: both PRs share one rule string `source_aware_review_cap` (`constants.py:137`, `fusion.py:396`); `render_merged_report_md` table columns omit `combined_rule` despite capturing it in row JSON (`fusion_report.py:119-123`, `fusion_report.py:210-232`); `format_paper_section` in `inspect_report.py` never renders `fusion.combined_verdict` or `combined_rule` per paper (fusion appears only in header rollup at `inspect_report.py:339-346`); `render_terminal_fusion_line` exposes `[rule]` but not subreason (`fusion_report.py:246-255`). Inspect shows `Unit coverage: complete=..., checked=N, unchecked=M` (`inspect_report.py:190-195`) but not **which** unit IDs were unchecked (baseline: `page:8`, `page:9`, `section:0`). Impact: PR #286/PR #295 `review` reads as successful conservative triage, not as a miss on poll tables or secno headings; recall loss is invisible in the primary merged surface. Answer-class: 5.

- [MED] `llm_escalate_major` is the sole pass→review path that does not require accepted defect groups, but it still cannot fail the paper and did not fire on either baseline run. Evidence: requires `llm == VERDICT_FAIL` plus major `axis_findings` (`fusion.py:284-289`, `fusion.py:499-512`); baseline PR #286/PR #295 tapetum `suggested_verdict` was `review` with conf 0.98, metadata/outline `pass`, zero defect groups. Impact: even axis-level LLM alarm is capped at `review`, not `fail`; on these goldens the escalation path was inert. Answer-class: 3 (model did not emit major axis fail) with class 4 (verification never aggregates undetected defects).

- [MED] By the lane's own advisory design, `review` on both papers was correct behavior, not a fusion bug; the failure is diagnostic reporting, not triage direction. Evidence: module docstring mandates incomplete source-aware coverage caps non-fail merge at `review` without consulting confidence (`fusion.py:24-26`); whisker CLAUDE.md "source-aware routing (v6) is wired end-to-end and fail-closed" (`CLAUDE.md` Known gaps §7); baseline deterministic `pass` on both PRs while human blockers existed — fusion `review` was strictly safer than agreeing with det. Neither run pointed review reason at pages 8/9 poll tables (PR #286) or secno-prefixed H2s (PR #295) because `_source_aware_requires_review` has no subreason field and reports do not surface unchecked unit IDs. Impact: treating fused `review` as "LLM verification attempted and found issues" overstates recall; treating it as "human must look" understates **where** to look. Answer-class: 5.

- [LOW] `fusion_report.py` footer aggregates rule counts (`fusion_report.py:265-281`) but the markdown table operators actually read hides the rule column, forcing JSON or terminal-only forensics. Evidence: `build_merged_json` stores `"rule"` (`fusion_report.py:119-123`); `render_merged_report_md` header/table omit it (`fusion_report.py:176-232`). Impact: corpus-wide triage audits cannot sort coverage-capped vs defect-capped papers from `report-merged.md` alone. Answer-class: 5.

## False-pass hypothesis

P1068R11 at baseline hashes: deterministic `pass`, tapetum `suggested_verdict` `review` conf 0.98, metadata/outline `pass`, `coverage_complete=false` with pages 8/9 unchecked, zero accepted defect groups — if an operator equates fused `review` with defect detection (or reads only `report-merged.md` merged column without sidecar `unit_coverage`), they falsely conclude the LLM lane validated the poll-table corruption when fusion only asserted incomplete checks.

## False-fail hypothesis

A paper with deterministic soft-review only, complete source-aware coverage, metadata `pass`, llm `pass` at conf ≥ floor, and `ref_nid` above `FUSION_REF_NID_FLOOR` clears to merged `pass` via `llm_clear_soft_review` (`fusion.py:458-476`) even if the LLM never inspected table cells or secno normalization — structurally the inverse false-pass, not observed on PR #286/PR #295.

## What would change my mind

Persisted fusion subreasons (as proposed in improvement-bugs §P1 fusion reasons: `coverage_incomplete`, `unchecked_units`, `verified_defects`) rendered in `report-merged.md` and `inspect_report.py` per-paper sections with explicit `unchecked_unit_ids`, plus one replay sidecar where PR #286 shows `verified_defects` (not `unchecked_units`) as the cap trigger — proving the reporting layer can separate detection from coverage without changing the advisory ceiling.
