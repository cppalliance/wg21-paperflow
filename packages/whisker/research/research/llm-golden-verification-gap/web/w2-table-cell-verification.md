# W2 — Table cell verification (web forage)

Date collected: 2026-07-22. Topic: vertically wrapped / multi-line PDF table cells; extraction strategies; cell-content QA metrics.

---

- pdfplumber splits a single cell into two rows when invisible horizontal lines exist inside the cell; maintainer fix is filtering hidden `rect` strokes before `extract_tables`, not automatic text merging. URL: https://github.com/jsvine/pdfplumber/issues/488 — 2021 — Directly matches poll-header cells where wrapped "S"+"F" can become separate rows/cells.
- pdfplumber maintainer recommends post-processing: join multiline cell text with `" ".join([cell.replace("\n", "") for cell in row])` after `extract_table()`. URL: https://github.com/jsvine/pdfplumber/issues/259 — 2020 — Shows ecosystem default is manual newline stripping, not semantic reassembly of stacked glyphs.
- pdfplumber documents no automatic text-direction detection; users must pass explicit rotation params (`char_dir_rotated="btt"`, formerly `vertical_ttb=False`) for non-horizontal cell text. URL: https://github.com/jsvine/pdfplumber/issues/942 — 2024 — Explains why vertically stacked poll labels need per-PDF tuning; no generic "read SF from two lines" logic.
- pdfplumber issue #942 reports multi-line vertical headers still merge lines incorrectly even after direction fix; maintainer suggests lowering `text_y_tolerance` to 0 or negative. URL: https://github.com/jsvine/pdfplumber/issues/942 — 2024 — Confirms wrapped/stacked header text remains an open edge case for rule-based extractors.
- pdfplumber commit 8a5d858 segregates upright vs rotated chars before clustering for `extract_text`, adding `horizontal_ltr` / `vertical_ttb` controls. URL: https://github.com/jsvine/pdfplumber/commit/8a5d858b — 2020-04-01 — Early evidence that vertical text is a separate code path, not default table behavior.
- PyMuPDF table finder warns that missing row-separator graphics cause "multi-line cells may be treated as separate rows"; mitigation is `horizontal_strategy="text"` or explicit clip/lines. URL: https://medium.com/@pymupdf/solving-common-issues-with-table-detection-and-extraction-4df5de2b8d88 — undated Medium post — Same failure mode as wrapped poll headers when grid lines are absent or ambiguous.
- Camelot `split_text=True` cuts words that span column boundaries after user supplies `columns=[x-coords]`; without column hints, adjacent glyphs merge into one word. URL: https://stackoverflow.com/questions/53231585/no-tables-found-and-merged-column-text-when-extracting-data-from-this-pdf-using-camelot — undated — Column x-position hints are required; no built-in vertical-wrap reading order.
- Camelot docs: `row_tol` groups rows closer vertically; `shift_text`/`copy_text`/`replace_text` kwargs fix specific cell-assignment defects post hoc. URL: https://camelot-py.readthedocs.io/en/latest/user/advanced.html — Camelot 2.0.0 docs — Tuning knobs exist but are manual; no QA layer validates final cell strings.
- Camelot comparison page states it handles "multi-row column headers, merged spanning cells" better than Tabula via kwargs like `copy_text` and `shift_text`. URL: https://camelot-py.readthedocs.io/en/latest/user/comparison.html — Camelot 2.0.0 docs — Suggests spanning/wrapped headers are known hard cases addressed by heuristics, not guarantees.
- Tabula stream mode infers columns from whitespace gaps; blog comparison notes variable column spacing causes misalignment and merged adjacent fields. URL: https://invoicedataextraction.com/blog/python-pdf-table-extraction-invoices — undated — Stream tools can drop or merge characters when poll columns are tight.
- TEDS (Tree Edit Distance-based Similarity) tokenizes each `<td>` node's text character-by-character into the HTML tree before APTED comparison. URL: https://github.com/ibm-aur-nlp/PubTabNet/blob/master/src/metric.py — PubTabNet repo — Would score "S" vs "SF" as partial credit via edit distance, but only if ground-truth HTML cell exists and is aligned to the same grid cell.
- TEDS-S (`structure_only=True`) omits all cell text from the tree, measuring layout/colspan/rowspan only. URL: https://huggingface.co/datasets/upstage/dp-bench/raw/3d48dac72db300e561a3d4007f7916e2ff08a467/README.md — DP-Bench README — Structure-only eval would not catch missing "F" in a poll header at all.
- PubTabNet paper (arxiv 1911.10683) introduces TEDS specifically to capture "multi-hop cell misalignment and OCR errors" better than prior adjacency metrics. URL: https://arxiv.org/abs/1911.10683 — submitted 2019-11-24 — Foundational cell-content metric; requires paired HTML ground truth, not live PDF geometry.
- GriTS evaluates tables as 2D matrices with three factored scores: GriTS-Con (cell text via normalized LCS), GriTS-Top (span topology via IoU), GriTS-Loc (bbox IoU). URL: https://github.com/kensho-technologies/grits — repo README — Content leg uses LCS, so "S" vs "SF" penalizes but needs pre-aligned cell pairing, not PDF-to-Markdown diff.
- GriTS paper (arxiv 2203.12555) unifies cell topology, location, and content recognition in one framework; validated on PubTables-1M. URL: https://arxiv.org/abs/2203.12555 — 2022 — Benchmark-grade metric; still needs annotated grid ground truth, not converter output vs source PDF.
- PubTables-1M README reports GriTS-Con ~0.985 and Acc Con ~0.824 for TATR-v1.0 on canonical test data; canonicalization fixes oversegmentation in spanning headers. URL: https://github.com/microsoft/table-transformer/blob/main/README.md — repo README — Shows even SOTA models miss ~18% of cell content on scientific tables; oversegmentation in GT was a known failure mode.
- PubTables-1M paper notes non-canonical (oversegmented) training data hurts models on complex spanning headers. URL: https://openaccess.thecvf.com/content/CVPR2022/papers/Smock_PubTables-1M_Towards_Comprehensive_Table_Extraction_From_Unstructured_Documents_CVPR_2022_paper.pdf — CVPR 2022 — Spanning/wrapped header cells are an explicit dataset-design problem, not just extraction noise.
- Marker ships `benchmarks/table/scoring.py` implementing TEDS with optional `structure_only` flag for table benchmark runs. URL: https://github.com/datalab-to/marker/blob/d63e3d94/benchmarks/table/scoring.py — Marker repo — Pipeline tools self-evaluate against HTML GT via TEDS, not against original PDF text layer.
- OmniDocBench converts all tables to HTML before TEDS and normalized edit distance; reports TableTEDS alongside TableEdit in end-to-end scores. URL: https://ar5iv.labs.arxiv.org/html/2412.07626 — arXiv v1 Dec 2024 — Document-level benchmark uses TEDS on extracted HTML vs human HTML/LaTeX GT, not cell-by-cell PDF coordinate diff.
- OmniDocBench table subset tags 150 tables with merged cells, 7 vertical tables, 81 with formulas; attribute breakdown shows rotation hurts all models, merged cells hurt VLMs more than pipeline tools. URL: https://ar5iv.labs.arxiv.org/html/2412.07626 — arXiv v1 Dec 2024 — Closest public eval axis to WG21 poll tables; no dedicated "stacked single-character wrap" attribute.
- olmOCR-Bench uses binary unit tests for tables: verify a cell value exists and neighbor cells satisfy relations; HTML tables required for rowspan/colspan cases. URL: https://olmocr.allenai.org/papers/olmocr.pdf — olmOCR paper 2025 — Pass/fail cell checks exist but depend on pre-authored tests, not open-ended golden diff vs PDF.
- olmOCR README reports olmOCR v0.4.0 Table category 84.9 vs MinerU 2.5.4 84.9 vs Marker 1.10.1 72.9 on olmOCR-Bench (1,402 PDFs, 7,010 tests). URL: https://github.com/allenai/olmocr?tab=readme-ov-file — repo README 2025 — Table fidelity is benchmarked via curated tests, not full cell-grid equality to source.
- Docling TableFormer post-process matches predictions back to PDF cells to avoid re-transcribing table images; handles empty cells, spans, partial borders. URL: https://arxiv.org/html/2408.09869v3 — Docling technical report Aug 2024 — Extraction merges vision output with PDF text layer, but no published per-cell verification against source geometry.
- docling-eval CLI evaluates TableFormer on FinTabNet/PubTabNet/Pub1M with separate TEDS struct-only and TEDS struct-with-text reports. URL: https://github.com/docling-project/docling-eval/blob/main/docs/FinTabNet_benchmarks.md — docling-eval repo — Official Docling QA is benchmark TEDS vs HTML GT, not runtime PDF-to-output diff.
- MinerU/OmniDocBench end-to-end: MinerU v0.9.3 TableTEDS 0.577 vs Marker v1.2.3 0.278 on OmniDocBench overall table metric. URL: https://ar5iv.labs.arxiv.org/html/2412.07626 — arXiv v1 Dec 2024 — Large spread shows table eval is benchmark-sensitive; still GT-HTML-based.
- RaV-IDP reconstructs extracted tables to HTML raster + structural signature (row/col counts, header texts, row-major cell texts) and compares SSIM/CER to original crop; fires gate when spanning cells truncate content. URL: https://arxiv.org/pdf/2604.23644 — arXiv 2026 — Closest published "reconstruction-as-validation" cell QA; demonstrated failure on row-span "Llama 1"/"Llama 2" cells.
- validated-table-extractor (Docling + vision LLM) compares extracted Markdown table to a screenshot crop; outputs JSON confidence and issue list, marketed for audit trails. URL: https://github.com/2dogsandanerd/validated-table-extractor — repo README 2025 — Example of VLM cell verification, not deterministic grid diff; would catch "S" vs "SF" if prompted.
- "Benchmarking PDF Parsers on Table Extraction with LLM-based Semantic Evaluation" (arxiv 2603.18652): TEDS Pearson r=0.68 and GriTS r=0.70 vs human judges; LLM-as-judge reaches r=0.93. URL: https://huggingface.co/papers/2603.18652 — 2026 — Rule-based cell metrics under-correlate with human cell-content judgment; no tool cited does automatic PDF cell-grid diff to Markdown.
- Same paper notes TEDS/GriTS are string-based and penalize format differences; SCORE uses cell tuples with edit distance but still not semantic equivalence. URL: https://huggingface.co/papers/2603.18652 — 2026 — Explains why golden HTML/Markdown string compare may miss or over-penalize poll-header defects.
- Nanonets guide: TEDS text mismatches use edit distance between corresponding cells; row removal penalized more than column removal due to HTML tree hierarchy. URL: https://nanonets.com/blog/the-ultimate-guide-to-assessing-table-extraction/ — undated — Useful for scoring partial "S"/"SF" errors if cells align; asymmetric row/column penalties affect poll-table scoring.
- No surveyed open-source tool performs automatic cell-grid diff between PDF source coordinates and Markdown pipe tables; ecosystem relies on HTML/LaTeX GT + TEDS/GriTS or LLM/VLM judges. URL: synthesis of above sources — 2026-07-22 — Supports baseline gap: whisker lacks table-cell compare; industry mirrors that absence at QA time.
