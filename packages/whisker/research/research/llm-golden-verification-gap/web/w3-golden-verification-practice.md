# W3 — Golden / reference verification practice (web forage)

Topic: industry practice for verifying golden/reference files in document-conversion and eval pipelines.
Foraged: 2026-07-22. Searches: 8.

---

- Golden file tests compare full program output to a committed reference artifact; the human review of diffs in version control is treated as the actual quality gate, not the automated equality check. — https://www.application-architect.com/posts/golden-file-testing-output-comparison/ — undated (accessed 2026-07-22) — Relevance: matches tomd/whisker golden-ideal workflow; supports answer-class 5 (LLM cannot replace explicit human approval of reference bytes).
- CI must never auto-update golden files: pipelines should fail on mismatch and require local regeneration plus committed diff review (`UPDATE_GOLDEN=0` / no update flags in CI). — https://www.application-architect.com/posts/golden-file-testing-output-comparison/ — undated (accessed 2026-07-22) — Relevance: production discipline for golden-PR candidates; accidental bulk snapshot accept is a known false-pass path.
- Golden testing guidelines classify every serialized field as stable (exact compare) or unstable (filtered/normalized); without that taxonomy, snapshot suites become flaky. — https://github.com/jlevy/tbd/blob/main/packages/tbd/docs/guidelines/golden-testing-guidelines.md — undated (accessed 2026-07-22) — Relevance: tomd golden diffs mix stable content with formatting noise; normalization policy is part of verification, not optional hygiene.
- Snapshot discipline: never run update/accept-all to green a failing suite; review every diff as a potential bug; run `--ci` mode so missing/stale snapshots fail rather than silently rewrite. — https://agenticdevelopercookbook.com/guidelines/testing/snapshot-testing — undated (accessed 2026-07-22) — Relevance: directly applicable maintenance strategy for golden markdown corpora under active converter development.
- Jest documents that snapshot files are versioned behavioral specs: intentional output changes require explicit `-u` regeneration after fixing real bugs, then PR review of the snapshot diff. — https://jestjs.io/docs/30.0/snapshot-testing — 2025 (Jest 30 docs) — Relevance: mainstream snapshot-maintenance pattern mirrored by pytest-snapshot/syrupy ecosystems used in Python doc pipelines.
- CI/CD snapshot maintenance recommends CODEOWNERS on `__snapshots__/` directories and optional bot-driven update commits that still require human diff review before merge. — https://helpmetest.com/blog/snapshot-testing-ci-cd-pipelines/ — 2025 — Relevance: operational model for golden-file PRs where converter authors cannot self-approve reference churn.
- OCR gold-standard validation used stratified random sampling (~170k characters per fold), dual native-speaker proofreading against facsimile crops, and agreement analysis: >50% of snippet edits were made by both proofreaders. — https://aclanthology.org/L16-1155.pdf — 2016 — Relevance: classic double-review + sample-based audit protocol for large transcription corpora analogous to WG21 paper goldens.
- FinCriticalED requires 20% double annotation, reports Fleiss' κ = 0.8837 overall, and queues low-overlap entities for lead-adjudicator consensus meetings. — https://arxiv.org/pdf/2511.14998 — 2025-11 — Relevance: modern financial-document OCR benchmark shows IAA thresholds and adjudication queues used before trusting ground truth.
- DeTEXT OCR benchmark used two-pass annotation (independent label, then cross-check/conflict resolution) and measured >97% text+location agreement on 10 double-annotated figures using ≥85% bounding-box overlap. — https://pmc.ncbi.nlm.nih.gov/articles/PMC4423993/ — 2015 — Relevance: spatial OCR ground truth relies on IoU-style overlap gates, not string diff alone.
- MasterSet validates LLM-generated corpus labels by human expert study (510 instances, 2–6 raters each): Gemini 2.5 Flash judge–human agreement falls within pairwise human–human disagreement, justifying scaled LLM labeling after human calibration. — https://arxiv.org/html/2604.17680v1 — 2026 — Relevance: rare published case of LLM used to *produce* labels then *validated against* humans before corpus trust, not LLM verifying human goldens post hoc.
- InduOCRBench claims 3-stage human-in-the-loop QC on Hybrid Markdown annotations reaching 98% accuracy across 570 PDFs / 3,402 pages. — https://huggingface.co/datasets/qihoo360/InduOCRBench — undated (dataset card, accessed 2026-07-22) — Relevance: document-conversion eval corpus explicitly markets multi-stage human verification, not single-pass authoring.
- OHR-Bench (ICCV 2025) builds human-verified structured ground truth by Mathpix pre-parse plus expert revision across 8,561 pages before downstream QA generation. — https://openaccess.thecvf.com/content/ICCV2025/papers/Zhang_OCR_Hinders_RAG_Evaluating_the_Cascading_Impact_of_OCR_on_ICCV_2025_paper.pdf — 2025 — Relevance: hybrid machine-draft + human-fix is the dominant OCR/PDF ground-truth construction pattern.
- ParseBench (~2,000 enterprise pages) uses frontier-VLM auto-labeling followed by human verification per capability dimension, then 167k+ deterministic rule checks (not fuzzy text similarity) for scoring. — https://www.llamaindex.ai/blog/parsebench — undated (accessed 2026-07-22) — Relevance: separates golden *construction* (human verified) from golden *verification* (rule engine), aligning with deterministic+human hybrid.
- SCORE-Bench (Dec 2025) releases expert-manually-annotated real-world documents and SCORE metrics designed to tolerate multiple valid generative representations while penalizing true extraction errors. — https://unstructured.io/blog/introducing-score-bench-an-open-benchmark-for-document-parsing — 2025-12-02 — Relevance: industry acknowledgment that byte-identical goldens mis-score modern parsers; supports contract-encoding gap (answer-class 1).
- docling-eval standardizes benchmark workflows as `create-gt` → `create-eval` → `evaluate` with separate modalities (layout, tables, reading order, markdown text) against published human GT datasets. — https://github.com/docling-project/docling-eval — undated (accessed 2026-07-22) — Relevance: reference implementation pattern for reproducible golden comparison in document parsing QA.
- OmniDocBench v1.5 uses component segmentation, hybrid text/formula matching, and optional md2md full-page comparison against human-markdown ground truth. — https://github.com/opendatalab/OmniDocBench — 2025-01-16 (repo changelog) — Relevance: open OCR/PDF-to-markdown benchmark explicitly versioning evaluation methodology as parsers evolve.
- GoldenSetAuditor audits evaluation datasets (duplicates, conflicting labels, ambiguous prompts, weak references) and explicitly does *not* score model outputs or verify factual correctness of expected answers. — https://github.com/SidharthKriplani/goldensetauditor — undated (accessed 2026-07-22) — Relevance: LLM-adjacent tooling targets *dataset integrity* checks, not semantic verification of golden content vs source PDF.
- DocIngestQA runs 11 deterministic pre-index checks on chunk JSONL (missing pages, OCR noise, duplicates, mojibake, bad split boundaries) and states it is not a RAG correctness or answer-faithfulness checker. — https://github.com/sidharthkriplani/docingestqa — undated (accessed 2026-07-22) — Relevance: upstream structural QA for corpora mirrors whisker deterministic lane scope; stops before semantic golden verification.
- GroundEval scores agent trajectories deterministically from artifacts, access rules, and tool traces—explicitly not from another model's judgment—and rejects correct answers reached via invalid evidence paths. — https://github.com/msradam/GroundEval — undated (accessed 2026-07-22) — Relevance: production pattern where deterministic verification has recall/power LLM judges lack.
- AWS FMEval guidance: ground truth review depth scales with incorrect-GT risk; human-in-the-loop SME review remains required even when LLMs generate GT at enterprise scale. — https://aws.amazon.com/blogs/machine-learning/ground-truth-generation-and-review-best-practices-for-evaluating-generative-ai-question-answering-with-fmeval/ — undated (AWS blog, accessed 2026-07-22) — Relevance: enterprise eval practice treats HITL as non-optional for high-risk goldens, not LLM self-certification.
- AWS FMEval curation flywheel: LLM may act as *judge of golden-dataset quality* against domain criteria, but humans must sample-verify and raise the bar as task complexity increases. — https://aws.amazon.com/blogs/machine-learning/ground-truth-curation-and-metric-interpretation-best-practices-for-evaluating-generative-ai-question-answering-using-fmeval/ — undated (AWS blog, accessed 2026-07-22) — Relevance: closest enterprise pattern to "LLM validates ground truth"—meta-QA on the eval set, not line-by-line source transcription proof.
- NeurIPS 2025 work on LLM-as-judge validation shows forced-choice gold labels can select suboptimal judges (up to 31% worse) when rating indeterminacy exists; multi-label response sets are recommended. — https://neurips.cc/virtual/2025/poster/117308 — 2025 — Relevance: warns that single-label golden contracts (e.g., one acceptable heading form) under-specify valid outputs and break judge calibration.
- ACL 2025 "Alternative Annotator Test" provides statistical criteria for when an LLM judge may replace human annotators by comparing each to a collective human distribution when true gold is unavailable. — https://aclanthology.org/anthology-files/pdf/acl/2025.acl-long.782.pdf — 2025 — Relevance: formal framework for LLM-as-judge *validation*, not production gating; gold still approximated from humans.
- Label Studio workflow: compute inter-annotator agreement, derive consensus ground truth, then compare model predictions to that consensus and bulk-route low-agreement tasks to QA. — https://labelstud.io/tutorials/how_to_measure_inter_annotator_agreement_and_build_human_consensus — undated (accessed 2026-07-22) — Relevance: standard HITL toolchain for building and auditing eval goldens before any automated scoring.
- Triage-and-Voice architecture: LLM classifies intent, pure-Python deterministic gate injects verified facts, LLM voice synthesizes only gate-approved fields—gate tests are fully deterministic, zero LLM calls. — https://github.com/svetkis/triage-and-voice — undated (accessed 2026-07-22) — Relevance: reference hybrid where deterministic layer owns data truth; LLM cannot add defects the gate never surfaced.
- Deterministic-LLM Sandwich pattern: deterministic pre-check, bounded LLM generation, deterministic post-validation; failed post-check returns prior state unchanged. — https://www.agentpatternscatalog.org/patterns/deterministic-llm-sandwich/ — undated (accessed 2026-07-22) — Relevance: architectural template for whisker fusion: deterministic tripwires bracket advisory LLM triage.
- Hybrid RAG support agent runs deterministic BM25 retrieval and rule-based triage first; LLM used only for low-confidence expansion and synthesis, with self-eval fallback to extractive mode below confidence 0.45. — https://github.com/yerramsettysuchita/hybrid-rag-support-agent — undated (accessed 2026-07-22) — Relevance: production cascade where LLM never owns routing or ground-truth selection—matches baseline answer-class 5 ceiling.
- OCR-Quality dataset (1,000 pages) pairs VLM OCR output with human 4-level quality scores and documents use for training/evaluating OCR *verification* systems and human-in-the-loop prioritization. — https://arxiv.org/html/2510.21774v1 — 2025-10 — Relevance: explicit research line on models that assess extraction quality vs models that perform extraction; adjacent to tapetum_llm judge role.
