# 02 - marker-hybrid

**Verdict:** usable-with-conditions — marker’s `--use_llm` hybrid is a **conversion correction layer** (deterministic blocks first, LLM rewrites selected blocks with fallback), and its benchmark runs **parallel** heuristic vs LLM-judge scorers with **no fused composite**; portable for whisker goals 1–3 are the lane-separation, structured-output validation, and deterministic fallback patterns, not score merging.
**Confidence:** high

## Findings

- [CRITICAL] LLM invocation is gated globally by `use_llm`, then selectively by block-type heuristics — not by a document-level confidence score. `BaseLLMProcessor.__init__` returns early when `use_llm` is false (`marker/processors/llm/__init__.py:64-65`); `BaseLLMComplexBlockProcessor.__call__` no-ops when `use_llm` is false or service is None (`:137-139`). Per-processor filters: forms require TableCell children (`marker/processors/llm/llm_form.py:65-74`); tables skip when `row_count > max_table_rows` (175) (`llm_table.py:134-135`); equations skip small blocks unless `redo_inline_math` (`llm_equation.py:79-83`, tied to `use_llm` in `benchmarks/overall/methods/marker.py:19-20`); image descriptions run only when `extract_images=False` (`llm_image_description.py:42-46`); inline-math redo requires `redo_inline_math` plus page math-density ratio (`llm_mathblock.py:77-78`, `:127-131`); page correction runs only if `block_correction_prompt` is set (`llm_page_correction.py:268-270`). Impact: whisker can adopt **candidate gating** (like tapetum `select_candidates`) but marker has **no analog** to whisker’s coverage/drift thresholds for deciding when to call the LLM lane.

- [HIGH] LLM output is validated with Pydantic schemas and merge guards; failures silently keep deterministic output. Gemini calls use `response_schema` + JSON parse with retries (`marker/services/gemini.py:64-93`, `:112-125`); on exhaustion returns `{}` (`:131`). Processors treat missing keys / `"no corrections needed"` as no-op (`llm_table.py:201-209`, `llm_form.py:98-106`, `llm_equation.py:110-117`). Pre-merge rejection heuristics: form HTML shorter than 33% of original (`llm_form.py:109-111`); equation unbalanced `<math>` tags or `<30%` length (`llm_equation.py:119-126`); table parse yields `<=1` cells or missing `</table>` (`llm_table.py:228-238`); page reorder requires block-ID set equality with page structure (`llm_page_correction.py:222-242`). Failures increment `llm_error_count` on the block (`llm_form.py:99`, `gemini.py:89-92` via `llm_tokens_used`/`llm_request_count`). Impact: directly portable for **goal 1** (tapetum fidelity): structured output + reject-and-keep-deterministic matches C1 (LLM never overwrites whisker verdict on record) if merge is report-only; also models handling **6 tapetum errors** from baseline §Runtime facts (LLM lane absent → deterministic stands).

- [HIGH] Benchmark eval runs **two independent scorers**, not a fused score. `SCORE_REGISTRY` registers `heuristic` and `llm` separately (`benchmarks/overall/registry.py:11-14`); CLI default is `--scores heuristic` (`overall.py:93`). Loop scores each `(method, score_type)` independently (`overall.py:56-65`); heuristic blends 80% length-weighted fuzzy alignment + 20% Kendall-τ order (`benchmarks/overall/scorers/heuristic.py:39-40`); LLM judge returns `response["overall"]` on 0–5 scale plus eight sub-scores (`benchmarks/overall/scorers/llm.py:89-91`, `:131-133`). CI gates **heuristic mean ≥ 90 only** (`benchmarks/verify_scores.py:9-13`; `.github/workflows/benchmarks.yml:30-31`); LLM scorer failures are caught and skipped (`overall.py:60-63`). README reports heuristic and LLM columns side-by-side, not merged (`README.md:472-477`). Impact: supports **goal 3** as **dual visible lanes**, explicitly **not** a combined score — whisker merged composite must be a new reported field, not marker’s pattern.

- [HIGH] Conversion `--use_llm` and eval `--use_llm` are the same flag but different roles: conversion enables 12 LLM processors in the PdfConverter pipeline (`marker/converters/pdf.py:74-99`, `:138-139`); benchmark passes `use_llm` into `MarkerMethod` (`benchmarks/overall/methods/marker.py:16-23`, `overall.py:135-137`). Table bench shows structural lift (TEDS 0.816 → 0.907) when conversion uses LLM (`README.md:511-515`), but scoring remains deterministic TEDS (`benchmarks/table/table.py:19-25`, `verify_scores.py:20-22`). Impact: marker separates **LLM-as-corrector** (pipeline) from **LLM-as-judge** (optional scorer) — analogous to whisker deterministic `score.py` vs tapetum advisory lane (baseline §Our substrate, C1–C2).

- [MED] Block-level LLM metadata exists in the conversion document model, not in whisker-style sidecars. `BlockMetadata` tracks `llm_request_count`, `llm_error_count`, `llm_tokens_used` (`marker/schema/blocks/base.py:16-19`); `update_metadata` accumulates on blocks (`:324-329`); Gemini service writes token/request counts per call (`marker/services/gemini.py:89-92`). Benchmark `result.json` stores per-sample `{method: {score_type: {score, specific_scores}}}` and hub export adds `{method}_{score_type}` + `_detail` JSON (`benchmarks/overall/display/dataset.py:41-49`); no field records which blocks invoked LLM. Impact: for **goal 2**, marker shows **embedding LLM stats in the primary artifact** (block metadata in JSON output) vs whisker’s separate `<pid>.whisker.tapetum.json` — a schema bump could add `tapetum` + `llm_meta` keys inside `<pid>.whisker.json` without violating C2.

- [MED] Only one processor uses LLM self-score for iterative retry (not global confidence routing). `LLMTableProcessor.rewrite_single_chunk` re-prompts when LLM returns `score < 4`, up to `max_table_iterations=2` (`llm_table.py:214-225`). No other processor gates on model confidence; `LLMScorer` has no confidence field, only discrete 0–5 axis scores (`llm.py:69-77`). Impact: whisker’s tapetum `confidence [0..1]` and two-tier cascade (baseline §tapetum_llm/models.py) are **richer** than marker’s retry-on-low-self-score pattern — adopt table-style retry for specific axes, not as merge logic.

- [LOW] Simple LLM processors are batched via `LLMSimpleBlockMetaProcessor` with concurrent Gemini calls (`llm_meta.py:28-63`, `max_concurrency=3` at `__init__.py:42-45`); complex processors run in their own thread pools (`llm_table.py:283-291`). Exceptions log and continue (`llm_meta.py:60-61`, `BaseLLMSimpleBlockProcessor.__call__` `:186-191`). Impact: conflicts with whisker determinism invariant D11 / serial tapetum default (baseline §Hard constraints C3) — do not adopt marker’s default concurrency for tapetum.

## False-pass hypothesis

A merged deterministic+LLM composite that weights LLM judge upward would **false-pass** a paper where marker’s heuristic scorer already misses a regression: CI only enforces heuristic corpus mean ≥ 90 (`verify_scores.py:9-13`), failed benchmark samples are dropped from averages (`overall.py:72-77`), and table-only collapse can hide inside a healthy overall mean (redteam §1.2). An LLM judge scoring 4+/5 on page-image resemblance (`llm.py:47-48`: “minor mistakes okay”) would not catch missing cross-page table merge or subtle GT block misalignment that heuristic fuzzy match still flags weakly.

## False-fail hypothesis

A merged score that **requires** LLM lane presence would **false-fail** when Gemini returns `{}` after retries (`gemini.py:131`) or benchmark skips LLM scores on exception (`overall.py:60-63`) — deterministic output is unchanged and heuristic may pass. Mirrors baseline §Runtime facts: 6 tapetum errors left no tapetum sidecar; marker’s pattern keeps deterministic markdown and only increments `llm_error_count`.

## What would change my mind

Finding a code path where marker **fuses** heuristic and LLM judge scores into a single gated composite (e.g., `combined = f(heuristic, llm_overall)` used in `verify_scores.py` or CI). Current evidence shows parallel columns only (`README.md:472-477`, `verify_scores.py:9-13`).
