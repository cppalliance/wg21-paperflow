# 06 - Dolphin Scoring

**Verdict:** usable-with-conditions — Dolphin ships no in-repo scoring, confidence, eval scripts, or hybrid fusion; its value for goals 1–3 is limited to deterministic pre-score normalization (`truncate_repeated_tail`) and external-benchmark axis stratification philosophy, plus negative lessons on silent failure and absent sidecars.
**Confidence:** high

## Findings
- [CRITICAL] No in-repo eval/benchmark/score computation exists: repo is inference demos + utils only (~15 Python files); published OmniDocBench numbers live in `README.md:58-106` with no scripts to reproduce them. Evidence: `packages/whisker/research/repos/Dolphin/README.md:58-106`; repo tree has no `tests/`, no `.github/workflows`, no `eval*.py`. Impact: goal 1 cannot adopt Dolphin LLM scoring mechanics (there are none); whisker must keep tapetum as the LLM lane and treat Dolphin as a normalization/routing reference, not a scoring peer.
- [CRITICAL] Two-stage analyze-then-parse has heuristic routing only, no stage-output scoring or confidence. Stage 1 layout (`demo_page.py:185-186`) is validated by (a) malformed layout string → full-page `distorted_page` fallback (`demo_page.py:204-205`), (b) IoU overlap heuristic → `distorted_page` (`demo_page.py:207-209`, `utils/utils.py:489-533` with `iou_threshold=0.1`, `overlap_box_ratio=0.25`). Stage 2 batches elements by label with fixed prompts (`demo_page.py:268-282`). No numeric quality gate between stages; no per-element confidence field in output schema (`demo_page.py:312-318`: `label`, `bbox`, `text`, `reading_order`, `tags` only). Impact: goal 3 merge design cannot borrow inter-stage fusion; tapetum's explicit `confidence [0..1]` on `Adjudication` (00-baseline:27-28) is strictly ahead.
- [HIGH] Optional `--post_process` normalization is the only in-pipeline QA-adjacent machinery, aimed at external metric stability not runtime verdicts. `MarkdownConverter(post_process=True)` applies `truncate_repeated_tail(text, threshold=20, keep=1)` on every element (`markdown_utils.py:320-321`), LaTeX canonicalization (`markdown_utils.py:291-296`), and table HTML attr strip (`markdown_utils.py:14-16`, `271-280`); wired via CLI `--post_process` (`demo_page.py:339`, `utils/utils.py:243-244`). Impact: portable to deterministic lane before merge (reduces false det fail on VLM repetition tails); pin `normalizer_version` in merged sidecar so det and LLM lanes score comparable text (extends redteam `Dolphin.md` §1.1).
- [HIGH] Failure handling is continue-on-error with placeholders, not fidelity fail — anti-pattern for C5 and merge goal 3. Per-element exceptions log and skip (`demo_page.py:262-264`); per-file exceptions log and `continue` (`demo_page.py:389-391`); converter inserts `*[Error processing content]*` (`markdown_utils.py:347-350`). No retry, no structured error artifact, no partial-result flag. Impact: mirrors whisker's 6 tapetum JSON errors leaving no sidecar (00-baseline:51); merged score must treat `llm_lane: absent|error` explicitly, not Dolphin-style silent omission.
- [MED] External benchmark uses six modality axes (Text Edit↓, Formula CDM↑, Table TEDS/TEDS-S↑, Read Order Edit↓, Overall↑) reported separately (`README.md:67-73`). Dolphin element prompts stratify by `tab`/`equ`/`code`/text (`demo_page.py:251-282`, `markdown_utils.py:328-345`). Impact: supports goal 3 reporting both lanes per-axis (whisker already has 7 tapetum axes + det nid/teds/mhs); adopt null-eligibility per axis when GT lacks modality (redteam `Dolphin.md` §1.3), do not collapse to single merged scalar without lane visibility.
- [MED] Deterministic decode only (`do_sample=False`, `temperature=None` at `demo_page.py:106-108`); `repetition_penalty` commented out (`demo_page.py:108`). No logprobs, no self-consistency, no LLM-as-judge. Impact: goal 1 confirms tapetum adjudication (structured pydantic + cascade) is the correct LLM-scoring pattern; Dolphin offers no upgrade path for LLM confidence calibration.
- [LOW] `demo_element.py` omits deterministic generation flags present in `demo_page.py` (`demo_element.py:100-104` vs `demo_page.py:103-108`), a minor reproducibility inconsistency. Impact: none for whisker merge; reinforces that Dolphin inference plumbing is demo-grade, not production QA.

## False-pass hypothesis
Deterministic whisker pass on a paper whose converter emitted a long repeated tail (no `truncate_repeated_tail` in whisker bench path) while tapetum errored out (Dolphin-style silent `continue` on parse failure, cf. `demo_page.py:389-391`). A naive merge rule `pass if det=pass AND (tapetum absent OR tapetum=pass)` would accept the paper with no LLM cross-check and inflated-looking det metrics — exactly the external-benchmark-only risk Dolphin embodies.

## False-fail hypothesis
Deterministic fail/review driven by benign VLM repetition or LaTeX env mismatch (Dolphin strips via `truncate_repeated_tail` + `aligned_to_array` at `markdown_utils.py:52-79,291-296`) while tapetum adjudicates semantic fidelity as pass with high confidence. A merge rule that requires both lanes to agree without normalization pinning would wrongly reject papers Dolphin would score well after `--post_process`.

## What would change my mind
Discovering an undocumented eval subtree (e.g. OmniDocBench driver under `deployment/` on another branch) that emits per-element confidence scores and documents how stage-1 layout quality gates stage-2 parsing — none exists on current `master` (32 tracked files, zero grep hits for `confidence`, `benchmark` scripts, or `judge` outside PyTorch `model.eval()` and README tables).
