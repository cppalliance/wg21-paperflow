# 10 - grobid-confidence

**Verdict:** usable-with-conditions (+ GROBID's consolidation provenance and multi-tier evaluation patterns are portable; main-path CRF/DeLFT per-entity confidence for score fusion is absent.)
**Confidence:** high

## Findings

- [CRITICAL] Main header/citation extraction does not attach CRF or DeLFT confidence to extracted entities or tell consumers how to threshold them. `WapitiTagger.label()` returns a label string only via `wapitiModel.label(data)` with no probability side channel (`grobid-core/src/main/java/org/grobid/core/engines/tagging/WapitiTagger.java:29-30`; `grobid-core/src/main/java/org/grobid/core/jni/WapitiModel.java:45-46`). `DeLFTModel.label()` likewise returns relabeled features only (`grobid-core/src/main/java/org/grobid/core/jni/DeLFTModel.java:217-230`). `BibDataSet.confidence` defaults to `1.0` and is not populated on the standard citation path (`grobid-core/src/main/java/org/grobid/core/data/BibDataSet.java:26-27`). The only systematic token-probability parse is patent-specific (`label/prob` suffix in `ReferenceExtractor.java:636-647`, wired to `bds.setConfidence` at `:849`; main citation NPL path has this call commented out at `:1399`).
  Impact: Goal 1 (keep LLM scoring) gets no ML-confidence mechanics to adopt from GROBID core; tapetum's explicit `confidence [0..1]` remains the right lane. Do not expect GROBID-style per-field model scores in a merged whisker artifact.

- [HIGH] Consolidation is GROBID's hybrid second-opinion merge: model extraction first, then CrossRef or biblio-glutton lookup, then selective in-place merge on the original object. `Consolidation.consolidate()` queries external services, runs `postValidation()` (Ratcliff on first-author surname, floor 0.8 at `Consolidation.java:493-502`), and tags accepted hits with `status="consolidated"` and `source` (`Consolidation.java:375-376`, `:458-459`). Callers merge via mode switch: `consolidate == 1 || 3` calls `BiblioItem.correct()` (broad field override from external metadata, `:4277-4507`), `consolidate == 2` calls `injectIdentifiers()` (identifiers only, `:4260-4268`), wired in `HeaderParser.java:1527-1530` and `CitationParser.java:472-475`. Failed or rejected consolidation leaves model output unchanged (no merge call when `bib == null`, `HeaderParser.java:1525-1531`).
  Impact: Goal 3 merge should mirror this structurally: deterministic lane stays authoritative (C1), advisory/LLM lane applies a named merge function (full correct vs identifier-only), and conflicts resolve by rejection (postValidation) not silent override. Record which lane won per field.

- [HIGH] Provenance is explicit in persisted output so consolidated results do not look like pure model extraction. TEI `<biblStruct>` carries `status` and `source` when set (`TEIFormatter.java:443-446`; `BiblioItem.toTEI()` at `:2281-2283`). Documentation defines `status="consolidated"` vs `status="extracted"` and `source="crossref"|"glutton"` (`doc/Consolidation.md:119-131`). After merge, `BiblioItem.correct()` copies status and consolidation service onto the destination item (`BiblioItem.java:4506-4507`).
  Impact: Goal 2 (persist both lanes in one artifact) should add lane provenance fields (e.g. `det_verdict`, `tapetum_verdict`, `merged_verdict`, `merge_source`) analogous to GROBID's status/source, not a single collapsed verdict without attribution.

- [HIGH] Evaluation never collapses to one operating-point score; it reports four parallel match tiers with fixed engineering thresholds. Constants: `minLevenshteinDistance = 0.8`, `minRatcliffObershelpSimilarity = 0.95` (`EndToEndEvaluation.java:66-67`). Each run accumulates separate `Stats` for strict, soft, Levenshtein, and Ratcliff tiers (`EndToEndEvaluation.java:463-466`, `:1121-1160`). Reports include per-label precision/recall/F1 with support, micro and macro averages (`Stats.java:357-422`), plus instance-level recall across tiers (`EndToEndEvaluation.java:2052-2074`; committed snapshot `doc/benchmarks/Benchmarking-pmc.md:98-110`). Sections stratify as HEADER / CITATION / FULLTEXT (`EndToEndEvaluation.java:60-62`, `:488-497`). Thresholds are documented, not ROC-fit (`doc/End-to-end-evaluation.md:115-128`; baseline buildvsbuy note at `packages/whisker/research/buildvsbuy/calibration-roc.md:81`).
  Impact: Goal 3 merged reporting should show deterministic, LLM, and merged values side by side across tiers (strict + fuzzy), not one composite that hides axis collapse. Whisker `guard`/`calibrate.py` already exceed GROBID on calibration methodology; borrow the multi-tier report shape.

- [MED] Context-specific fuzzy floors gate hybrid decisions rather than a global confidence score. CrossRef consolidation post-validation uses Ratcliff >= 0.8 on author surname (`Consolidation.java:498-499`). End-to-end field eval uses Ratcliff >= 0.95 (`EndToEndEvaluation.java:1159-1160`). DOI-matching eval uses Ratcliff >= 0.5 (`EvaluationDOIMatching.java:56`). Funder consolidation uses Ratcliff > 0.9 (`Consolidation.java:550-553`, `:611-613`). DeLFT license classification uses scoreField > 0.5 internally (`LicenseClassifier.java:121-122`, `:157-158`) without surfacing it in main TEI consumer output.
  Impact: A whisker merge can use tiered, axis-specific thresholds (det strict, LLM advisory, merged soft tier) instead of weighting a nonexistent GROBID model confidence. Aligns with baseline C4 (named constants).

- [MED] GROBID avoids presenting garbage extraction as authoritative via structural rejection, not low-confidence labeling. `BiblioItem.rejectAsReference()` drops items missing minimal core metadata (`BiblioItem.java:4515-4527`). Consolidation failure or post-validation rejection simply omits merge; TEI without `status="consolidated"` signals model-only extraction per docs (`doc/Consolidation.md:121-122`). Runtime facts: 6 tapetum errors in baseline run leave no LLM sidecar (`00-baseline.md:51`); GROBID analog is null consolidation result with original extraction retained.
  Impact: Goal 2 must record LLM lane absence/error explicitly in the merged artifact; never synthesize a merged pass from deterministic-only when tapetum errored (C5 fidelity).

- [LOW] Committed benchmark snapshots are the release QA ritual, not CI auto-gates. End-to-end eval is manual `./gradlew jatsEval` (`doc/End-to-end-evaluation.md:78-88`); CI runs unit tests only (`ci-build-unstable.yml:31-32`). Frozen numbers live in `doc/benchmarks/Benchmarking-pmc.md`.
  Impact: Whisker hybrid scoring should pair machine JSON sidecars with human-readable multi-lane benchmark tables for release review, matching GROBID's publication ritual alongside whisker `guard --update`.

## False-pass hypothesis

With `consolidateCitations=1`, CrossRef `postValidation: false` (`doc/Consolidation.md:94-98`), and a false-positive CrossRef hit on author surname, `BiblioItem.correct()` overwrites title/journal/authors from the wrong record (`BiblioItem.java:4298-4307`) while TEI emits `status="consolidated" source="crossref"` (`BiblioItem.java:4506-4507`, `TEIFormatter.java:443-446`). A whisker-style merged score that treats consolidation/LLM agreement as uplift would falsely pass a paper whose deterministic extraction was better than the external override.

## False-fail hypothesis

CrossRef returns the correct DOI but first-author surname Ratcliff similarity is 0.75; `postValidation()` rejects (`Consolidation.java:498-499`), merge never runs, header stays model-only without `status="consolidated"`. A whisker merge that requires LLM fail to override deterministic review would keep a review/fail band even though an external identifier lane had the right record (mode 2 `injectIdentifiers()` would have fixed DOI only, `BiblioItem.java:4260-4268`, but is not attempted after failed post-validation).

## What would change my mind

Discovery that main-path `CitationParser` or `HeaderParser` parses Wapiti/DeLFT token probabilities, exposes them in TEI or API responses, and documents consumer threshold guidance (today `WapitiTagger.java:29-30` and `BibDataSet.java:26-27` show this does not exist on the standard bibliographic path).
