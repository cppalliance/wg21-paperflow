# 11 - surya-nougat

**Verdict:** usable-with-conditions — neither repo fuses deterministic and model scores into one number, but both implement exactly the pattern our merge needs: cheap deterministic guards that veto, truncate, or fall back around untrusted model output, with failure persisted as explicit in-band data instead of silence.
**Confidence:** high

## Findings

- [CRITICAL] Nougat runs a DETERMINISTIC logit-variance self-check on every generated page and classifies failures into two distinct kinds: repetition (truncated output) vs out-of-domain (page unlike training data). Evidence: `packages/whisker/research/repos/nougat/nougat/model.py:614-651` — after generation, `logits = torch.stack(decoder_output.scores, 1).cpu().max(-1)` (line 614); a sliding variance-of-variance (`varvar`, line 627) below `0.045` (line 635) marks repetition; if the degenerate region starts before token 30 the whole page is rejected as out-of-domain (`small_var[0] < 30` → `idx = 0`, lines 642-643). The consumer maps `repeats > 0` → `[MISSING_PAGE_FAIL:n]` and `repeats == 0` → `[MISSING_PAGE_EMPTY:n]` with the explicit comment "the document page is too different from the training domain" (`packages/whisker/research/repos/nougat/predict.py:181-191`). A second live-stopping variant (`StoppingCriteriaScores`, `model.py:442-474`) aborts generation when max-logit variance flatlines (threshold `0.015`, window 200, line 443).
  Impact: this is the model-output-sanity pattern for goal 1 and goal 3: a deterministic signal derived from the model's own generation statistics decides whether the model output may be trusted at all, BEFORE any score is computed. Our tapetum lane has confidence (baseline: `Adjudication.confidence [0..1]`) but no independent deterministic check on the LLM output itself; nougat proves the guard can be pure arithmetic on logits/text, no second model.

- [HIGH] Nougat persists failure IN the score artifact, not as absence: failed pages are written into the output `.mmd` as `[MISSING_PAGE_FAIL:n]` / `[MISSING_PAGE_EMPTY:n]` markers, and the API variant appends the truncated remainder inside a visible `+++ ==WARNING: Truncated because of repetitions==` block. Evidence: `packages/whisker/research/repos/nougat/predict.py:178-191`; `packages/whisker/research/repos/nougat/app.py:131-149` (disclaimer strings, `close_envs` recovery of the cut tail at line 139).
  Impact: directly answers baseline runtime fact line ~52 (6 tapetum errors "leave NO tapetum sidecar verdict"). For goal 2 the merge design should adopt nougat's rule: an errored LLM lane writes an explicit `status: error` record into the persisted file, so "LLM lane absent" and "LLM lane failed" are distinguishable downstream, satisfying C5 (never a partial result mistakable for complete).

- [HIGH] Surya emits a calibrated numeric confidence per block from token logprobs and persists it in the score format: `mean_token_prob` is "Mean of exp(logprob) across response tokens" (`packages/whisker/research/repos/surya/surya/inference/schema.py:32-35`, computed in `packages/whisker/research/repos/surya/surya/inference/backends/openai_client.py:52-56`, enabled by default via `SURYA_INFERENCE_LOGPROBS: bool = True`, `packages/whisker/research/repos/surya/surya/settings.py:70`). The persisted `results.json` block schema carries `confidence` (0-1), `skipped`, `error` per block (`packages/whisker/research/repos/surya/README.md:155-167`), with honest degenerate values: failed block → `error=True, confidence=0.0` (`packages/whisker/research/repos/surya/surya/recognition/__init__.py:226-238`), deliberately-skipped block → `confidence=1.0` (`recognition/__init__.py:213-222`), successful block → `confidence=mean_token_prob` (`recognition/__init__.py:241-252`).
  Impact: model for goals 2-3: per-item records that carry BOTH the payload and the lane's self-assessed confidence plus explicit `error`/`skipped` booleans in ONE schema. Maps onto extending the `<pid>.whisker.json` sidecar with a tapetum block (`verdict`, `confidence`, `status`) rather than the separate `.tapetum.json` file (baseline anchors, tapetum `cli.py _persist_result`).

- [HIGH] Surya wraps its generative model in a chain of deterministic guards with fallback, never silent accept: `_detect_repeat_loop` (pure string arithmetic, tail-repetition scan with length-scaled repeat budget, `packages/whisker/research/repos/surya/surya/recognition/__init__.py:81-108`; twin `detect_repeat_token` at `packages/whisker/research/repos/surya/surya/inference/util.py:61-91`) plus `is_blank_region` pixel heuristics (`packages/whisker/research/repos/surya/surya/common/blank.py:40-64`, named constants at 22-27). The full-page OCR path applies them in order: server error → fallback; empty output on a genuinely blank page → accepted as correct; empty output on a NON-blank page → fallback; repetition loop detected → fallback to layout + per-block OCR (`recognition/__init__.py:286-315`). Layout drops text blocks the model hallucinated over blank regions (`packages/whisker/research/repos/surya/surya/layout/__init__.py:103-115`).
  Impact: this is "deterministic guards AROUND an LLM score" in production form (the tapetum grounding analogy in the mandate). The design lesson for goal 3: deterministic checks should VETO or REROUTE the model lane (fallback, demote, mark error), not be averaged with it. Neither repo ever computes `w1*det + w2*model`.

- [MED] Both repos handle uncertainty honestly rather than silently, in complementary ways. Nougat's postprocessing deterministically strips its own hallucinations: `truncate_repetitions` (longest repeating tail, `packages/whisker/research/repos/nougat/nougat/postprocessing.py:102-165`), `remove_hallucinated_references` (fuzzy-repeated reference lines → `[MISSING_PAGE_POST]`, `postprocessing.py:301-329`), likely-hallucinated trailing titles (`postprocessing.py:351-359`). Surya's layout returns `error=True` with empty bboxes on parse failure instead of coercing (`packages/whisker/research/repos/surya/surya/layout/__init__.py:79-95`). Counterexample inside surya: the OCR-error classifier is a raw `argmax` with no confidence or threshold sweep (`packages/whisker/research/repos/surya/surya/ocr_error/__init__.py:47`).
  Impact: goal 1 upgrade candidates: a deterministic repetition/self-copy scan over tapetum-audited markdown is ~25 lines (surya's `_detect_repeat_loop`) and would guard our LLM lane against degenerate converter output that inflates unigram coverage.

- [MED] Surya's benchmark story: thresholds are hand-set named constants, never fitted (`DETECTOR_TEXT_THRESHOLD=0.6`, `DETECTOR_BLANK_THRESHOLD=0.35`, `packages/whisker/research/repos/surya/surya/settings.py:112-113`), but detection thresholds are scaled per-image from heatmap intensity (`get_dynamic_thresholds`, `packages/whisker/research/repos/surya/surya/detection/heatmap.py:13-23`) and per-line detection confidences exist (`heatmap.py:103-110`). The surya-2 checkout has NO in-repo benchmark suite (top-level dirs: `.github`, `signatures`, `static`, `surya`, `tests`); quality is reported against external olmOCR-bench as one headline score (83.3) PLUS a per-source stratified table (ArXiv 88.3 ... OldScan 41.8 ... Tables 86.6) (`packages/whisker/research/repos/surya/README.md:389-408`).
  Impact: for goal 3's reporting shape: surya publishes the composite AND the per-stratum breakdown side by side, never composite-only. Our merged verdict must ship next to both lane verdicts (report.md leaderboard + JSON), which the baseline template already anticipates. Caveat for adopting confidence: `heatmap.py:108-109` normalizes confidences by the page max, so a uniformly-weak page still shows a 1.0 top confidence — never normalize lane confidence relative to the same document.

- [MED] Nougat's score persistence is recompute-friendly but has a NaN trap: `test.py` dumps one JSON with per-sample metric arrays, per-metric means, AND the raw predictions + ground truths (`packages/whisker/research/repos/nougat/test.py:81-95`); metrics are `edit_dist`, `bleu`, `meteor`, set-based `precision/recall/f_measure` with a `minlen=4` eligibility gate that OMITS unscorable samples instead of zeroing them (`packages/whisker/research/repos/nougat/nougat/metrics.py:27-44`). But `meteor` returns `np.nan` on missing NLTK data (`metrics.py:36-38`) and `np.mean(vals)` at `test.py:84` silently poisons the aggregate.
  Impact: two rules for the merged-score artifact (goals 2-3): (a) persist per-lane raw values alongside any mean so the merge is auditable and recomputable; (b) reject non-finite lane values before any composite arithmetic — one NaN from an errored LLM lane must fail loudly (C5), not propagate into a merged number.

- [LOW] Neither repo implements LLM-as-judge or det+LLM score fusion of the kind goal 3 asks for; both are model-QA infrastructures where the deterministic side gates the model side. Evidence: absence — no fusion code anywhere in either checkout (greps for score/confidence/threshold across all `.py` files, this session); nougat's eval never merges Text/Math/Tables strata into one gate (`packages/whisker/research/repos/nougat/nougat/metrics.py:104-117`).
  Impact: negative result worth recording: the two most battle-tested OCR pipelines chose veto/fallback/marker semantics over weighted averaging. A whisker merge that arithmetic-averages the deterministic verdict with tapetum confidence has no precedent here; a merge that lets deterministic guards cap or demote the LLM lane has two.

## False-pass hypothesis

A paper whose converted markdown contains a converter repetition loop (a section duplicated N times, the classic decoder failure both repos guard against). Every source word is present, so `unigram_coverage` stays above 0.95 and the deterministic lane says pass; tapetum's chunked triage samples around the duplicated region (or reads it as benign emphasis) and passes with high confidence; a merged pass+pass composite accepts. Nougat would have caught it deterministically (`truncate_repetitions`, `postprocessing.py:102-165`; logit varvar, `model.py:635`) and surya would have rerouted it (`_detect_repeat_loop`, `recognition/__init__.py:309-315`); whisker has no repetition axis in either lane.

## False-fail hypothesis

The "LLM lane errored" case the baseline documents (6 of 194 papers, truncated/invalid JSON after retries, baseline runtime facts). If the merge treats a missing/errored tapetum record as an implicit fail or zero-confidence vote (the natural arithmetic default), a deterministically-passing paper gets dragged to review/fail purely because the model endpoint hiccuped — the analog of nougat misclassifying a valid cover page as `[MISSING_PAGE_EMPTY]` because it is "too different from the training domain" (`predict.py:186-191`). The merge must encode surya's distinction: `error` (lane broken, merged verdict = deterministic verdict + visible error flag) vs `skipped` vs a genuine low-confidence adjudication.

## What would change my mind

Evidence that our serving path cannot expose per-token logprobs to the tapetum lane (pydantic-ai + vllm_thinking backends dropping `logprobs`): that would kill the single most portable mechanism here — surya's `mean_token_prob` / nougat's logit-variance as a deterministic, model-independent trust signal on LLM output — and reduce both repos' contribution to just the failure-marker persistence pattern, downgrading my verdict toward the low end of usable-with-conditions.
