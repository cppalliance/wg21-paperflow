# 03 - opendataloader-hybrid

**Verdict:** usable-with-conditions (+ opendataloader-pdf is a strong reference for page-level hybrid routing, enrichment merge, and per-lane artifact persistence, but it does not implement merged QA scoring; whisker must not treat its 0.907 benchmark as a score-fusion recipe)
**Confidence:** high (routing/merge/artifacts read in source); medium (overall 0.907 formula lives in external opendataloader-bench repo, not cloned here)

## Findings
- [CRITICAL] Hybrid "merge" is page-level partition, not lane score fusion. `mergeResults` assigns each page exclusively from `javaResults` OR `backendResults` (`HybridDocumentProcessor.java:1417-1439`); there is no per-document composite of deterministic vs AI quality scores. Impact: satisfies whisker goal 3 only by analogy (combine outputs), not by copying their scoring math; a whisker merged verdict must be designed separately while keeping C1 (deterministic verdict on record unchanged).
- [HIGH] Routing is conservative page triage: `TriageProcessor.classifyPage` evaluates signals in priority order (CID replacement ratio ≥0.3 → confidence 1.0; `hasTableBorder` → 1.0; vector table signals → 0.95; text table patterns → 0.9; large image ≥11% area + aspect ≥1.75 → 0.85; line ratio >0.3 → 0.8; else JAVA at 0.9) at `TriageProcessor.java:656-707`. `--hybrid-mode full` skips triage and sends all pages to backend (`HybridConfig.java:48-51`, `HybridDocumentProcessor.java:273-287`). Impact: portable pattern for goal 1 (keep LLM lane) as selective escalation, similar to tapetum `select_candidates`, with explicit confidence attached to each routing decision.
- [HIGH] Within backend-routed pages, Java and AI outputs are enriched, not re-scored. Backend owns structure (headings, tables, reading order); Java supplies StreamInfo/OCR provenance via bbox overlap (`HybridDocumentProcessor.java:1103-1109`, `892-990`). Text conflict resolution: Levenshtein similarity ≥0.5 trusts PDF stream text, else keeps OCR (`TextSimilarity.java:24-49`, `HybridDocumentProcessor.java:1209-1235`). Image alt: author `/Alt` beats AI caption (`HybridDocumentProcessor.java:917-924`). Impact: maps to whisker C1+C2 — one lane authoritative for structure, other lane advisory/enrichment only; no overwriting of deterministic record.
- [HIGH] Published benchmark compares final extraction output, not hybrid vs local lane scores side-by-side. README reports hybrid overall 0.907 vs local 0.831, with per-axis reading order 0.934, table 0.928, heading 0.821 (`README.md:103-113`); CI gates separate `nid_mean`, `teds_mean`, `mhs_mean`, table_detection F1, and triage recall/FN (`test-benchmark.yml:152-182`). Bench harness clones external `opendataloader-bench` (`scripts/bench.sh:19-84`). Impact: whisker goals 1-3 can reuse the same axis names (already in `WhiskerResult` ref_nid/ref_teds/ref_mhs per `00-baseline.md:17`) but must add an explicit merged composite in whisker; opendataloader has no equivalent.
- [MED] Per-document hybrid decision artifacts are persisted. `TriageLogger` writes `<outputDir>/triage.json` with per-page `decision`, `confidence`, `signals`, and summary counts (`TriageLogger.java:72-186`, invoked from `HybridDocumentProcessor.java:293-296`, `1515-1527`). Backend element metadata (`ai_score`, `source_label`, `text_source`, `stream_ocr_similarity`) is embedded in output JSON via `SerializerUtil.writeMetadataIfPresent` (`HancomAISchemaTransformer.java:471-524`, `SerializerUtil.java:47-64`, `ElementMetadata.java:28-70`). Impact: direct template for goal 2 — extend `<pid>.whisker.json` with a `tapetum` block + `triage`-style routing metadata rather than a second sidecar.
- [MED] Hancom AI object `confidence` (0..1) is detection quality metadata, not triage routing input. Mapped to `correctSemanticScore` and `ElementMetadata.aiScore` (`HancomAISchemaTransformer.java:471-482`); distinct from page triage confidence (`TriageProcessor.java:142-149`). Impact: whisker can persist LLM `confidence` alongside deterministic metrics without letting either overwrite the deterministic verdict (C1).
- [LOW] Backend failure defaults to fail-fast; `--hybrid-fallback` re-routes failed pages to Java (`HybridConfig.java:126-141`, `HybridDocumentProcessor.java:253-355`, `HybridBackendFailureIntegrationTest.java:132-224`). Impact: whisker merge design must handle absent/errored tapetum lane (6 errors in 2026-07-06 run per `00-baseline.md:51`) the same way — merged score absent or marked incomplete, never a silent pass.

## False-pass hypothesis
Conservative triage sends ~55 false-positive pages to the backend on the 200-doc benchmark set (43 FP before Experiment 005, rising to 55 with large-image recall tuning at `docs/hybrid/experiments/triage/triage-experiments.md:290-311`). Those pages get full AI re-extraction; benchmark scores only the final merged document output (`README.md:103`), not whether Java would have been sufficient. A whisker merged det+LLM score that upgrades deterministic `review` to `pass` when tapetum says pass would false-pass papers where the LLM missed a deterministic gate signal (123/194 tapetum disagreements in `00-baseline.md:49`).

## False-fail hypothesis
With default fail-fast (no `--hybrid-fallback`), a backend timeout on one triaged page aborts the whole run (`HybridBackendFailureIntegrationTest.java:165-192`). Triage at ~95-100% table recall still misses 1-2 table docs per experiment log (`triage-experiments.md:248-255`, `290-311`); those pages stay on Java where table accuracy is 0.489 vs hybrid 0.928 (`README.md:107-113`), depressing extraction scores without surfacing a separate "AI lane absent" flag. A whisker merge that downgrades to fail when tapetum errors (6 papers with no sidecar per `00-baseline.md:51`) would false-fail papers that deterministic scoring already passed.
