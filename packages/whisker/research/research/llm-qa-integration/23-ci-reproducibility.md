# 23 - CI-Reproducibility-Engineer

**Verdict:** usable-with-conditions (+ LLM verdicts are not CI-stable on our current alliance-pod stack and must never gate; the det-first + advisory split is the only architecture that survives measured MoE/batch variance, but quote-level and confidence drift remain real even when verdicts hold)
**Confidence:** high

## Findings

- [CRITICAL] **An LLM verdict cannot be a CI-hard gate on our stack today.** Repo `CLAUDE.md:74` sets quality-stability, not bit-exact, and names batch-invariant kernels as the prerequisite for hosted bit-exact reproducibility. `MODELS.md:77-78` documents that vLLM-class servers flip greedy argmax tokens when batch composition changes; `tapetum_llm.md:29` states token output on alliance-pod is not bit-stable under continuous batching and MoE routing. `packages/whisker/tests/test_tapetum_llm_eval.py:12` explicitly marks the lane "NOT a CI gate: the LLM is non-deterministic." Impact: promoting tapetum `suggested_verdict` to CI would inherit 25-35% per-PID flip rates measured below; the architecture question is answered: advisory-only is not timidity, it is the only reproducible contract.

- [HIGH] **Measured verdict-level variance on identical inputs: 25% of borderline papers flip between runs.** Evidence: `packages/whisker/research/llm-batching/20-sweep-results.md:31-40` — two identical c=32 runs on the same 20-PID set produced 15 pass / 5 review vs 10 pass / 10 review (5/20 = 25% flip rate); corpus histogram on 200 papers shifted 100/87/10 to 118/75/11 within the same MoE drift band (`20-sweep-results.md:64-66`). Client pins are already maximal: D2/D5 via `packages/pipeline/src/pipeline/model_backends.py:310-312` (`temperature=0.0`, `seed=0`); per-paper cascade serial at `adjudicate.py:409` (`default_concurrency=1`). Residual variance is server-side MoE + batch non-invariance, not missing client pins. Impact: even with everything pinned, rerun distributions drift; only distribution-level comparison is honest, not per-PID regression baselines.

- [HIGH] **p0533r9 A/B (same paper, same prompts, serial re-run) shows evidence-level variance with verdict-level stability — the measured micro-example from the baseline runs.** Evidence: `%TEMP%\toc-fix\ws-baseline\whisker\llm\` sidecars (2026-07-16 TOC prompt A/B). Run 1 (baseline): `suggested_verdict=review`, `confidence=0.95`, grounded quotes `logb` / `modf` / `scalbn` / `scalbln` / `nextafter` (5 quotes, all `// see [library.c]` variants). Run 2 (after prompt update): `suggested_verdict=review`, `confidence=0.90`, grounded quotes `frexpf` / `ilogbf` / `ldexpf` / `logbf` / `modff` (5 quotes, wording-section F variants); reasoning additionally names CONTENTS TOC leak. Verdict unchanged; 0/5 quote overlap; confidence delta 0.05. Prompt caps 5 quotes × 20 words (`pdf_judge.py:199-201`), so the model samples different exemplars from the same ~31-function constexpr omission. Impact: **residual variance risk for tapetum is ~0% verdict flip and ~100% quote identity flip on this paper**; defect class (constexpr loss) is stable, localization is not.

- [HIGH] **Greedy "pin everything" does not kill the fix — it IS the fix for stability, and the Q2 tradeoff cuts the other way.** Evidence: `05-web.md / Q2 / An Empirical Study of LLM-as-a-Judge` — greedy decoding gives zero sampling variance but **lower human correlation** than multi-sample averaging; `05-web.md / Q2 / Necessary but Not Sufficient: Temperature Control` — temp=0 reduces but does not eliminate pass/fail flips (~50% at temp 1.0). We already run greedy (`MODELS.md:28`, D5 forbids per-call override). Impact: adopting multi-sample averaging to recover judge accuracy would **increase** CI flake; the tradeoff means pinned greedy is correct for an advisory lane, and wrong only if you need judge accuracy on marginal cases **and** mechanical gating — which is exactly why 0/31 repos gate on LLM scores (`00-baseline.md:43-44`). Pinning does not solve server-side MoE flips; it prevents making variance worse.

- [HIGH] **Verdict-level vs evidence-level stability: acceptable for advisory, fatal for a gate — and our code already encodes that split.** Evidence: fusion keys on `suggested_verdict` and `confidence`, never on quote text (`fusion.py:124-252`); `combined_verdict` is explicitly advisory (`fusion.py:76-77`, `tapetum_llm.md:3`). Gates decide from pure functions of markdown (`gates.py:209-218`, `score.py:177-185`); `whisker --gate` never reads tapetum (`whisker/CLAUDE.md:475-477`). Decide demotes ungrounded non-pass but allows sanctioned empty-evidence pass (`adjudicate.py:299-310`). Impact: p0533r9-style quote churn is **triage noise** for humans reading sidecars, not a ship/no-ship defect, **provided** operators treat `whisker` verdict as authority. If fusion `combined_verdict` were CI authority (`fusion.py:192-226` can clear soft review to pass), a 25% verdict flip on borderline papers becomes a false-pass/false-fail gate — the documented false-pass vector in persona 02.

- [MED] **Default batch concurrency (c=32) amplifies variance beyond per-paper serial cascade.** Evidence: `cli.py:68-76` (`_DEFAULT_CONCURRENCY = 32`, D11 carve-out); `20-sweep-results.md:36-37` — flips occur between ANY two runs, concurrency amplifies incrementally; `16-determinism-auditor.md:10-12`. Per-paper adjudication stays serial (`adjudicate.py:189-210`, `tapetum_llm.md:25-26`), but 32 papers co-batch on the pod. Impact: corpus reruns are throughput-optimized, not regression-baseline-optimized; `VLLM_BATCH_INVARIANT` (~50% throughput cost, `MODELS.md:77-78`) is the infra path to bit-stable advisory baselines if ever needed.

- [MED] **External evidence confirms LLM-judge CI gates are structurally flaky even with mitigations.** Evidence: `05-web.md / Q1 / What Happens When LLM-Judge CI Gates Are Treated as Hard Blockers` — same code passes then fails; recommended pattern is deterministic assertions first; `05-web.md / Q4 / Deterministic Guardrails` — named pattern "the model proposes, deterministic checks decide." Aligns with 31-repo matrix (`00-baseline.md:43-55`) and our MC2 closure where all 4 new hard fails came from det gate, LLM confirmed (`00-baseline.md:61-63`). Impact: our path matches industry guardrail pattern; LLM-integrated alternatives that look "smarter" inherit the same non-reproducibility unless they gate on deterministic facts (olmOCR `checked: verified`, `00-baseline.md:53-55`).

- [LOW] **Confidence numbers are not a stability signal and drift run-to-run.** Evidence: p0533r9 0.95→0.90 across A/B; production band 0.85-1.00 with 18/18 fails at ≥0.95 (`adjudicate.py:233-234`, `00-baseline.md:85`); `05-web.md / Q2 / Overconfidence in LLM-as-a-Judge`. Impact: pinning confidence thresholds for CI would be doubly unstable; fusion guardrails correctly use det signals (`missing_region_count`, `fusion.py:177-190`) over LLM confidence.

## False-pass hypothesis

A paper with `unigram_coverage` just above 0.85 and token-preserving table corruption passes `whisker --gate` identically every rerun. On rerun B (MoE routing shift, `20-sweep-results.md:31-40`), tapetum tier-1 returns `pass`/0.98 with empty evidence, escalation signals do not fire (`adjudicate.py:230-253`), and fusion `llm_clear_soft_review` (`fusion.py:192-207`) upgrades det=review to combined=pass. Whisker gate stays green; operator treating fusion as ship authority gets a run-dependent false pass.

## False-fail hypothesis

A clean paper with only `heading_monotone` hard fail gets det=fail on every rerun (`score.py:177-179`, `gates.py:96-112`). Tapetum may flip between pass and review on pod variance (`tapetum_llm.md:29`), but fusion never hard-fails (`fusion.py:148-170`) and cannot change the recorded whisker verdict. No run-to-run false-fail from LLM nondeterminism in the gate itself; false-fail here is threshold design, not variance.

## What would change my mind

A controlled triple rerun on alliance-pod with `VLLM_BATCH_INVARIANT` (or equivalent) enabled showing ≤1% per-PID verdict flip rate on the fixed 20-PID borderline set AND the p0533r9 pair producing identical grounded quote sets — would upgrade "never CI-gate" to "CI-gate acceptable with batch-invariant infra + quote-agnostic fusion rules only."
