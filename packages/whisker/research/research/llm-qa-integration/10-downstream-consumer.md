# 10 - Downstream-Consumer

**Verdict:** usable-with-conditions — the deterministic verdict + sidecar chain is the only artifact a CI integrator should gate on; the advisory LLM/fusion layer adds human-triage signal but is not yet a turnkey defect locator comparable to olmOCR's per-test failures or docling's page-graded workflow hints.
**Confidence:** high

## Findings

- [CRITICAL] Default CI (`--gate review`) collapses pass and review into exit 0, so "review" does not block merge unless the integrator tightens to `--gate pass`. Evidence: `_GATE_ACCEPTS["review"] = {"pass", "review"}` (`packages/whisker/src/whisker/__main__.py:88-91`); `_verdict_exit_code` returns `EXIT_REVIEW` (3) only when review is outside the accepted set (`__main__.py:130-136`); default `--gate review` (`__main__.py:175-178`). Impact: a downstream consumer treating exit 0 as "ship" silently accepts ~54% of the ref-free corpus that whisker labeled review (`00-baseline.md` §2, persona 29 synthesis in `research/persona/29-product-decision-skeptic.md`); the trichotomy exists in sidecars and color but not in the default CI contract.

- [CRITICAL] `combined_verdict` is explicitly advisory and never drives `whisker --gate` or tapetum exit codes; naively wiring it as a ship gate is a footgun. Evidence: fusion docstring (`packages/whisker/src/whisker/tapetum_llm/fusion.py:12-13`); `FusionResult.advisory: bool = True` and `"advisory": True` in `to_dict()` (`fusion.py:63,76`); merged report banner (`fusion_report.py:118`); tapetum CLI contract "exit code always 0" (`tapetum_llm/cli.py:11-13`, `930`); whisker verdict on record unchanged (`inspect_report.py:146-148`). Impact: an integrator who reads `report-merged.md` or tapetum sidecar `fusion.combined_verdict` and auto-promotes to pass can override deterministic review without touching the authoritative `whisker/det/<pid>.whisker.json` verdict field.

- [HIGH] The whisker sidecar → inspect report chain gives *where to look* for deterministic defects but not a single prescribed action for "review". Evidence: sidecar carries `verdict`, threshold-qualified `hard_flags`/`soft_flags`, and `missing_regions`/`extra_regions` with page + 60-char snippet (`score.py:97-133`, `constants.py:172`); terminal summary prints semicolon-joined flags via `_flags_text` (`report.py:45-47`) but caps sections and defers overflow to `report.md` (`report.py:297-299`, `CLAUDE.md:145-147`); full region tables live in `report.md` "Region detail" (`report.py:148-163`), not default stdout; `_decide` soft flags are heterogeneous (unigram band, regions, drift, qa, ref_nid advisory, ideal axes) with no priority or next-step field (`score.py:186-215`). Impact: "review" means "open the sidecar or report.md and interpret flags," not "fix X at line Y"; compared to olmOCR's binary fact tests that name the failing assertion (`00-baseline.md:18`, `05-web.md / Q5 / olmOCR-Bench README`), whisker's review queue is triage-rich but action-poor.

- [HIGH] The tapetum sidecar localizes LLM findings via grounded evidence char spans, but inspect_report still mixes trusted spans with unverified narrative. Evidence: sidecar schema documents `grounded_evidence` with `quote`, `status`, `start`/`end` (`models.py:137-139,177-180`); inspect report renders `[exact at chars start-end] 'quote'` (`inspect_report.py:103-107`) and per-axis table (`inspect_report.py:78-88`); reasoning labeled "LLM reasoning (unverified narrative)" (`inspect_report.py:110-112`); known rubric-bleed case documented (`research/tapetum-golden-review-findings-2026-07-14.md:39-58`). Impact: a human can jump to markdown offsets for grounded quotes, but must ignore `reasoning` and treat `primary_concern` as model prose; defect localization is better than docling's document-level grades alone but worse than olmOCR's test-name + expected fact pin.

- [MED] Artifact chain is well-defined on disk but split across two lanes with different authority. Evidence: deterministic `whisker/det/<pid>.whisker.json` + `report.json`/`report.md` (`score.py:371-395`, `CLAUDE.md:396-404`); advisory `whisker/llm/<pid>.whisker.tapetum.json` with embedded `fusion` block written at persist time (`cli.py:408-411,433-436`); human join via `whisker-tapetum-llm --inspect` → `whisker/llm/tapetum-inspect.md` (`cli.py:192,913-915`, `inspect_report.py:117-165`); three-lane rollup `report-merged.md/json` (`fusion_report.py:113-158`). Impact: integrators must know which file gates CI (det sidecar `verdict` only) vs which files steer human review (llm sidecar, inspect, merged); the chain is actionable once documented but easy to misread if merged columns are treated as authoritative.

- [MED] Compared to docling's ConfidenceReport, whisker gives sharper structural fail reasons but weaker conversion-quality workflow routing. Evidence: docling exposes `mean_grade`/`low_grade` (POOR→EXCELLENT) and per-page scores (`base_models.py:557-577,609-612`); docs tell consumers to "focus on quality grades" for batch routing, numerics advisory (`docling/docs/concepts/confidence_scores.md:11-20,46-56`); grades never block conversion (`00-baseline.md:29`); whisker hard fails name the gate and embed detail (`score.py:177-179`, e.g. `gate:heading_monotone:...`) and region snippets anchor content loss (`report.py:156-162`). Impact: docling integrators get a coarse "reroute pipeline / manual review" signal without a defect pointer; whisker integrators get gate-level WHY and optional page snippets on det fail/review, but no page-level grade rollup unless they run the PDF per-page screen inside tapetum (lane-local, not in whisker JSON).

- [MED] Compared to olmOCR-Bench, whisker lacks machine-checkable per-defect test IDs in the default consumer path. Evidence: olmOCR gates on 7,010 verified binary facts, pytest CI (`00-baseline.md:18`, `05-web.md / Q1 / olmOCR-Bench`); whisker's closest analogue is Lane 3 `facts.jsonl` (`checked: verified` only gates in `whisker facts`/`guard`, `CLAUDE.md:316-318`) covering 5/381 papers (`CLAUDE.md:486-488`); default `whisker [PID]` does not surface fact failures. Impact: olmOCR consumers get `pytest` output naming the failing fact; whisker consumers on the default path get aggregate flags and optional LLM quotes, not a enumerated checklist of what broke.

- [LOW] Batch scoring errors are visible in logs/footer but invisible to exit-code-only CI and `--json` consumers. Evidence: scorer exceptions increment `errored`, continue batch (`__main__.py:226-231`); footer mentions errored count (`report.py:266-267`) but `_verdict_exit_code` inspects only scored verdicts (`__main__.py:283`); `--json` emits only `[r.to_dict() for r in results]` (`__main__.py:267-269`). Impact: a broken paper can leave a stale prior sidecar on disk while CI stays green; downstream automation must parse footer or check sidecar freshness, not rely on exit code alone.

## False-pass hypothesis

An integrator scripts on `whisker/llm/report-merged.json` `merged` column and treats `llm_clear_soft_review` as clearance: a paper with only soft flags, no `missing_region_count`, high LLM confidence, and `ref_nid is None` (`--no-reference` path) can fuse to `pass` (`fusion.py:211-226`) while token-preserving semantic corruption (MC1 class, `00-baseline.md` §4 selection gap) never triggered deterministic or LLM review under default full-run selection (`CLAUDE.md:490-492`). The deterministic sidecar still says `review` or `pass`, but the consumer never reads it.

## False-fail hypothesis

An integrator sets `--gate pass` expecting strict CI and receives exit 5 for benign heading-monotone-only fails (`gates.py:215`, `_decide` hard path `score.py:217-218`) on otherwise excellent conversions (documented P3941R2/R3/R4 pattern, `research/persona/30-steelman.md`); fusion can only rescue to merged `review`, not pass (`fusion.py:150-160`), so the consumer blocks merge with no automated clearance path unless they manually downgrade or run tapetum for cosmetic confirmation.

## What would change my mind

A timed integrator study (N≥10 real review/fail sidecars) measuring median minutes from opening `whisker/det/<pid>.whisker.json` + `tapetum-inspect.md` to locating the defect in source markdown/PDF, compared to the same papers run through olmOCR-style fact tests or docling page-grade inspection — if whisker's chain consistently matches or beats olmOCR's "failing test → exact fact" pin, the advisory stack would be adoptable as primary triage, not just second opinion.
