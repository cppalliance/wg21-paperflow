# 03 - API-Contract-Design

**Verdict:** usable-with-conditions (+ the deterministic-gates-decide + advisory-LLM split is mechanically honored on the CI `--gate` path, but fusion/gating surfaces still treat human-readable flag strings as a machine API and the sidecar schema does not discipline what consumers may rely on the way docling does)
**Confidence:** high

## Findings

- [HIGH] **`--gate` exit codes ignore fusion; the documented CI contract holds.** Evidence: `packages/whisker/src/whisker/__main__.py:283` returns `_verdict_exit_code([r.verdict for r in results], args.gate)`; `_verdict_exit_code` at `:130-136` maps only `WhiskerResult.verdict` tiers. `fusion.py` / `fuse_verdicts` are not imported in `__main__.py`. `tapetum_llm/cli.py:12-13` and `:930` (`sys.exit(_EXIT_OK)`) keep the LLM lane advisory-only. `fusion.py:12-13` and `WhiskerResult` persistence (`score.py:106`) never write `combined_verdict` back to the deterministic sidecar. Impact: architecture claim in `00-baseline.md:70-74` and `CLAUDE.md:34-35,475-477` is true for `whisker --gate`; adopters can gate CI on det verdict without fusion leakage.

- [HIGH] **Fusion matrix matches its docstring for the 2026-07-16 heading rescue fix; TOC-leak false-rescue is closed.** Evidence: `fusion.py:17-24` (asymmetric matrix); `_is_heading_only_fail` at `:105-116` uses `f.startswith("gate:heading_monotone")` with explicit comment that substring `"heading"` in gate *detail* must not qualify (`:108-111`, citing `no_toc_leak` duplicate-heading detail). `test_fusion.py:131-146` replays PR #290: `gate:no_toc_leak:duplicate heading '1. introduction'...` stays `whisker_fail_locked`. Rescue caps at `VERDICT_REVIEW` (`:151-160`, `test_fusion.py:123-129`). Impact: the MC2-class contract break (LLM path treating flag prose as gate identity) is fixed on the rescue branch; architecture remains sound for that failure mode.

- [HIGH] **The CLASS of bug (flag-string matching as API) persists: structured `gates[]` is serialized but fusion/candidate paths read denormalized `hard_flags` prose instead.** Evidence: sidecar emits both `gates: [{name, passed, detail}]` (`score.py:128`, `gates.py:26-29`) and `hard_flags: ["gate:{name}:{detail}"]` (`score.py:177-179`). No production reader calls `.get("gates")` outside display (`__main__.py:295-298`, `test_score_file.py:57-83`). Fusion rescue (`fusion.py:113-116`) and `select_candidates` RESCUE population (`adjudicate.py:140-151`) parse `hard_flags` strings, not `gates[].name`. Impact: every new gate whose `detail` embeds document text remains a footgun for any future substring matcher; the stable contract is `GateResult.name`, but consumers are not wired to it. Docling avoids this by grading on categorical fields, not parsed prose (`05-web.md / Q5 / Docling confidence scores`).

- [MED] **Substring flag taxonomy still lives on the advisory selection path (same API smell, lower severity than heading).** Evidence: `_is_benign_region_only` in `score.py:234-238` and `adjudicate.py:128-137` classifies soft flags via `"misaligned region" in f` / `f.lower()`. Heading rescue was fixed to prefix-match; region/benign logic still substring-matches machine-generated flag templates. Impact: low immediate risk (templates are fixed at `score.py:191`), but the pattern is the same anti-contract as the pre-fix heading matcher; a renamed or compound soft flag could desync benign-fold vs `--review-all` candidate selection.

- [MED] **Sidecar schema is not docling-disciplined about what consumers may rely on; numerics and verdicts are commingled without stability guarantees.** Evidence: docling docs (`05-web.md / Q5`): "Numerical scores are informational and unstable across releases; categorical grades drive workflow decisions" (IBM `confidence_scores.md`). Whisker det sidecar mixes gating numerics (`unigram_coverage` hard-fails at `score.py:181-185`) with informational reading-order proxies (`coverage`/`drift` reported, explicitly non-gating per `score.py:155-158`, `CLAUDE.md:318-322`) with no schema-level `informational`/`gating` partition. Tapetum sidecar marks `advisory: True` (`models.py:184`, `fusion.py:63,76`) but `confidence` (float) mechanically drives fusion clear (`fusion.py:196-197`) and adjudicate demotion (`adjudicate.py:311-312`) with no "unstable across model releases" consumer warning. Impact: downstream automation that thresholds on `confidence` or `ref_nid` without reading `verdict`/`combined_rule` will break silently on model/threshold churn; docling's explicit grade-first contract is absent.

- [MED] **Fusion can emit `combined_verdict=pass` while det stays `review`; docs promise this is advisory, but the field name invites misuse.** Evidence: `fusion.py:200-207` (`llm_clear_soft_review`); `fusion_report.py:61-62,118` surfaces `merged` alongside det `verdict` with footer disclaimer. `WhiskerResult.verdict` on disk unchanged (`score.py:106`). Impact: correct for human triage; incorrect if any consumer treats `fusion.combined_verdict` or `report-merged.md` `merged` column as a ship gate without reading `advisory: true` and `whisker_verdict`. Ecosystem precedent (`00-baseline.md:26-29`, marker CI on deterministic means only) supports keeping this advisory, but the schema does not enforce it.

- [LOW] **Interactive menu swallows deterministic non-zero exit after LLM (operator trap, not `--gate`).** Evidence: `menu.py:168-186` runs `_score_main` then `tapetum_main` and `return 0` regardless of det `EXIT_FAIL`/`EXIT_REVIEW`. Direct `whisker --gate` unaffected (`__main__.py:283`). Impact: operators using `whisker menu` option 2 as a pseudo-CI entry may think the combined run passed when only the advisory lane finished cleanly.

## False-pass hypothesis

A clean **det `pass`** with token-preserving table corruption (known selection gap, `CLAUDE.md:490-492`) receives **fusion `combined_verdict=pass`** under `llm_clear_soft_review` if an operator manually re-scores det to `review` with only soft flags and the LLM returns grounded `pass` at `confidence >= CONFIDENCE_DECISION_FLOOR` (`fusion.py:192-207`). This does not affect `whisker --gate` (det pass exits 0 under default `--gate review`), but a consumer reading `whisker/llm/report-merged.md` `merged=pass` could ship without human review. Concrete case: `missing_region_count=0`, soft flags only `ideal nid ... (advisory)`, LLM pass/0.95 on a swapped table cell that preserves unigrams.

## False-fail hypothesis

**det `fail`** on `gate:no_toc_leak` with detail containing the word `"heading"` is **not** downgraded by fusion rescue after the 2026-07-16 prefix fix (`test_fusion.py:131-146`). **det `fail`** on heading-monotone-only is downgraded only to **fusion `review`**, never `pass` (`fusion.py:151-160`), and still **det `fail`** on record for `--gate` with `--gate fail` or stricter. No false-fail found on the CI gate path for the repaired contract.

## What would change my mind

A committed contract test suite that (1) asserts `whisker --gate` exit codes are invariant when `whisker/llm/<pid>.whisker.tapetum.json` carries `fusion.combined_verdict` opposite to det, and (2) refactors `fuse_verdicts` / `select_candidates` to classify failed gates exclusively via `gates[].name` (or a stable `failed_gate_names: list[str]` field), with a regression vector per gate where `detail` embeds ambiguous substrings (`"heading"`, `"misaligned region"`). Passing that would flip to **usable** without conditions on API-contract grounds.
