# 16 - Retry-Loop-Architect

**Verdict:** usable-with-conditions — deterministic gates stay the decider; the adoptable lesson from the 31 repos is mechanical retry/fallback loops around conversion (triggered by structural or deterministic signals), not LLM-signal gating of accept/reject.
**Confidence:** high

## Findings

- [CRITICAL] **Reference repos uniformly use LLM/structural signals to RETRY or REROUTE conversion, never to gate document accept.** Marker table processor re-prompts when self-score `< 4` up to `max_table_iterations=2` (`llm_table.py:214-225`, `00-baseline.md:26`); on parse/structural reject (`parse_html_table` yields `<=1` cells or missing `</table>`) it keeps prior deterministic HTML (`llm_table.py:227-238`, `research/per-page-judging/12-marker-analyst.md:12`). Surya full-page OCR: server error / empty-on-non-blank / repeat-loop / parse exception each reroute to layout+block fallback (`recognition/__init__.py:292-315`, `350-366`, `00-baseline.md:30`); `mean_token_prob` is telemetry only (`inference/schema.py:33-35`). olmOCR escalates temperature across page retries then substitutes `pdftotext` (`pipeline.py:289-291`, `329-332`, `371-375`, `TEMPERATURE_BY_ATTEMPT` at `:84-85`, `00-baseline.md:28`). **Zero repos** use LLM quality as mechanical CI accept gate (`00-baseline.md:43-44`, `05-web.md / Q1 / olmOCR-Bench`). Impact: the ecosystem's "LLM-integrated" middle ground is **conversion continuity**, not **QA authority transfer** — validates our det-decides + advisory-LLM split; the gap is we lack a bounded **re-convert** loop upstream of gates.

- [HIGH] **Marker's retry loop is the closest analogue to "det gate fail → re-attempt → re-gate" — but it retries the LLM rewrite, not a second deterministic conversion pass.** Flow: accept LLM html → structural sanity (`</table>`, cell count) → on fail increment `llm_error_count` and **retain OCR/layout original** (`llm_table.py:201-203`, `227-238`); only self-score `< 4` triggers another LLM call (`:214-225`). Service JSON parse failures bump temperature to `0.2` on retry (`gemini.py:112-113`, `12-marker-analyst.md:18`). Impact: portable pieces for whisker are (a) **bounded iteration budget** (max 2), (b) **reject-and-keep-prior** on merge failure (matches root Fidelity), (c) **structural validators before accepting any rewrite** — not the in-place block mutation model. A whisker port applies these to **tomd parameter variants**, not tapetum adjudication retries.

- [HIGH] **Surya's fallback lane is deterministic-signal-triggered rerouting with explicit degeneracy guards — directly relevant to whisker's missing repeat-loop axis.** Chain at `recognition/__init__.py:292-315`: HTTP error → fallback; blank page via `is_blank_region` → accept empty (`:300-301`); empty on non-blank → fallback (`:303-307`); `_detect_repeat_loop` (`:81-108`, `:309-314`) → fallback; parse exception → fallback (`:316-323`). Fallback scope is page-local: layout + block-mode OCR (`:350-366`). Inference layer adds temp-bump retries on `detect_repeat_token` up to `0.8` (`openai_client.py:141-202`, `:190-191`, `15-nougat-surya-analyst.md:18`). Confidence never gates accept (`00-baseline.md:30`). Impact: whisker should wire `facts.auto_baseline_checks` repeat-ngram detection (`facts.py:648-688`, currently unwired per `CLAUDE.md:665`) into `run_gates` or a pre-gate degeneracy check; surya proves **deterministic veto → alternate lane** beats averaging model confidence (`hybrid-llm-scoring/11-surya-nougat.md:17-18`).

- [HIGH] **olmOCR's page retry + pdftotext fallback is conversion-yield engineering, not a QA pattern — and parts conflict with our determinism contract.** Page loop: up to 8 attempts with `TEMPERATURE_BY_ATTEMPT` ramp (`pipeline.py:85`, `289-291`); exhausted retries call `make_fallback_result` (pdftotext anchor, `:233-250`, `:372-375`); document discarded only if fallback rate > `max_page_error_rate` 0.004 (`:559-563`). Acceptance gates are transport/schema (`finish_reason`, rotation YAML, `:200-206`), not content fidelity (`11-olmocr-pipeline-v2.md:10`). Impact: adopt **bounded retry + fallback-rate cap + provenance counters** for a whisker convert loop; **reject** temperature escalation (`research/vlm-pdf-qa/12-api-contract-analyst.md:20`, D5) and **reject** silent pdftotext substitution as pass (`06-error-handling-robustness.md:61` — defensible for conversion yield, not QA accept).

- [HIGH] **Our codebase has convert parameterization but no gate-triggered re-convert orchestration.** tomd `run_pipeline` exposes `ml_tables`, `extract_vector`, `whiteout_text` (`packages/tomd/src/tomd/lib/pdf/pipeline.py:1380-1387`); `convert_paper_full` dispatches by suffix (`packages/tomd/src/tomd/api.py:339-366`, `:375+`); CLI forwards vector flags via `convert_one_paper` (`packages/cli/src/cli/orchestrator.py:25-77`) but **always single attempt**. whisker `run_gates` + `_decide` run post-hoc on whatever markdown exists (`gates.py:209-218`, `score.py:136-186`); tapetum fusion cannot override det fail (`fusion.py:124-252`, `00-baseline.md:70-72`). Impact: the mechanical loop belongs **between convert and score** — a whisker-local or `paperflow convert --retry-policy` wrapper, not inside tapetum.

- [MED] **Concrete adoptable design: det fail/review → bounded tomd re-convert with named parameter variants → re-gate (gate unchanged as decider).** Proposed trigger map (all deterministic): `gate:no_empty_table` → retry with `ml_tables=True`; `gate:heading_monotone` on HTML → retry with alternate heading classifier path (future); `unigram_coverage` in review band + `auto_baseline_checks` repeat fail → retry with `extract_vector=True` or alternate table pass (tomd-side). Cap at 2 attempts (marker `max_table_iterations=2`, `llm_table.py:214-225`). Persist `convert_attempts[]` with params + gate snapshot per attempt (surya `error`/`skipped`/`confidence` block schema, `README.md:155-167`). On exhaustion: keep best attempt by `unigram_coverage` or last passing structural gate — **never** auto-pass. Matches `05-web.md / Q4 / Deterministic Guardrails` ("model proposes, deterministic checks decide") and `05-web.md / Q4 / AI Guardrails 2026` (deterministic first, expensive probabilistic last).

- [MED] **What NOT to port: LLM self-score as retry trigger inside whisker QA.** Marker's `score < 4` retry is for **its own table rewrite quality** (`llm_table.py:215-218`), analogous to tapetum's bounded `output_retries` (D10), not document accept. Benchmark `LLMScorer` is advisory and skipped on failure (`overall.py:61-63`, `05-web.md / Q5 / Marker CI gates heuristic only`). Impact: tapetum may retry schema validation; it must not trigger tomd re-convert based on LLM verdict — that would invert the lane order our architecture and 31-repo survey both reject.

- [LOW] **Industry cascade literature names the same layering we should implement mechanically.** `05-web.md / Q4 / Deterministic vs LLM-Judge Evals 2026` and `05-web.md / Q4 / Deterministic Guardrails` describe deterministic gates catching 30-60% at sub-ms cost, LLM reserved for semantic remainder. Our remainder is already advisory (`tapetum_llm`); the missing layer is **deterministic-gated convert retry** before the first `whisker` score — the olmOCR/marker/surya pattern applied to tomd, not to tapetum.

## False-pass hypothesis

**olmOCR-style silent fallback after retry exhaustion.** A table-heavy page where VLM retries fail gets `pdftotext` substitution; page marked `is_valid=True` (`pipeline.py:372-375`, `11-olmocr-pipeline-v2.md:26`). Mapped to whisker: a convert retry loop that accepts a weaker fallback engine (e.g. markitdown oracle only) on gate fail would raise `unigram_coverage` while destroying table structure — `teds` drops but structural gates and unigram floor may still pass (`score.py:181-185`). Guard: fallback variants must be **tomd-only** with **stricter** post-retry gates (enable `auto_baseline_checks`, table facts on retry path), never a looser engine.

## False-fail hypothesis

**Retry loop on cosmetic `heading_monotone` fails.** Nine papers hard-fail solely on heading level with `uni≈0.999` (`12-steelman-llm-first.md:17`, `gates.py:105-109`). Re-converting with alternate parameters will not fix HTML heading drift (MC5, `golden-qa-gap/00-baseline.md:63`) and wastes two full conversions per paper. Guard: retry policy should key on **content-loss signals** (`unigram_coverage` review band, `no_empty_table`, `no_toc_leak`, repeat-ngram) — not heading-only fails where fusion rescue already demotes advisory (`fusion.py:149-160`).

## What would change my mind

An instrumented pilot on 10 gate-failed WG21 papers showing a 2-attempt `convert → whisker score` loop with a **fixed, named** parameter schedule (e.g. default → `ml_tables=True` → `extract_vector=True`) recovers human-verified pass on ≥3 papers **without** any attempt passing on degraded fallback markdown, with bit-identical re-runs on the golden hermetic set (`test_comprehension_corpus.py`). Failure to improve would downgrade convert-retry from HIGH to LOW and confirm advisory-only LLM is the correct post-gate layer.
