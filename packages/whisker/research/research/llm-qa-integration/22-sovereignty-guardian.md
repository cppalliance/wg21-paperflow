# 22 - Model-Sovereignty-Guardian

**Verdict:** usable-with-conditions — model sovereignty does not contradict the ecosystem evidence (every reference repo keeps LLM signals non-gating); it **tightens** the case for det-first by forbidding the cloud-first LLM-QA patterns the references actually use, while self-hosted LLM gating remains theoretically possible but unproven at comparable quality on our Gemma/Qwen/DeepSeek stack.
**Confidence:** high

## Findings

- [CRITICAL] **No reference repo mechanically gates CI/accept on LLM QA**, even where LLM lanes exist. The 31-repo matrix shows zero mechanical LLM gates; marker's Gemini LLMScorer is explicitly advisory with failures skipped (`00-baseline.md:24-26`, `benchmarks/overall/scorers/llm.py:94-134`, `overall.py:61-63`); olmOCR benches on human-verified facts, not judge output (`00-baseline.md:18`, `05-web.md / Q1 / olmOCR-Bench`). Impact: sovereignty is not fighting an industry norm of LLM-gated shipping; it aligns with observed practice while blocking the cloud APIs those repos use for their **non-gating** lanes.

- [CRITICAL] **Reference LLM-QA/bench lanes are cloud-native and not drop-in portable to our stack.** Marker optional Gemini processors and in-loop table self-QA (`00-baseline.md:26`, `processors/llm/__init__.py:50-67`, `llm_table.py:213-225`); olmOCR fact mining drafts via Gemini/Claude (`05-web.md / Q3 / olmOCR-Bench GT methodology`); langextract defaults to `gemini-3.5-flash` with `google-genai` as a core dependency (`00-baseline.md:34`, `research/langextract/14-portability-platform.md:7-9`). Impact: adopting their LLM-integration **patterns** without their cloud endpoints requires re-engineering transport, schema enforcement, and provider routing — not a config swap.

- [HIGH] **Self-hosted Gemma/Qwen on our pod lacks the schema/reproducibility contract cloud judges implicitly carry.** Production tapetum binds to `alliance-pod` / `deepseek-v4-pro` (`SERVICES.toml:64-68`, `tapetum_llm.md:19-21`), not Gemma/Qwen slots (`SERVICES.toml:87-97`, `99-108`, `129-133`). `VllmThinkingBackend` relies on schema-in-prompt + raw JSON retry (`MODELS.md:113-120`); structured output on thinking models needed vLLM ≥0.20.1 fixes (#41199, #42287) per `research/llm-stack/19-schema-compliance-auditor.md:12`. MoE routing and continuous batching flip tokens even at `temperature=0` (`MODELS.md:67-77`, `tapetum_llm.md:29`). Impact: **comparable quality** to Gemini/Claude judge lanes is unverified; sovereignty-compatible inference exists, sovereign **judge-grade** inference does not.

- [HIGH] **Repo `CLAUDE.md` model sovereignty forbids cloud dependence for defensible analytical output** (`CLAUDE.md:64-70`: open-weight, self-hosted, schema issues solved with retries not cloud retreat). Whisker encodes the split: deterministic gate is LLM-free (`whisker/CLAUDE.md:34-35`, `gates.py:209-218`); tapetum is advisory-only (`fusion.py:12-13`, `whisker/CLAUDE.md:475-477`). Impact: copying reference cloud LLM-QA into **gating** would violate a non-optional invariant; into **advisory** it is allowed only on self-hosted endpoints.

- [HIGH] **Pod outage behavior today: deterministic CI unaffected; advisory lane fails loud at start, soft mid-batch.** `whisker --gate` exit codes derive from deterministic verdicts only (`__main__.py:130-136`, `constants.py:154-157`); CI runs whisker without tapetum (`whisker/CLAUDE.md:488-492`, `.github/workflows/tests.yml:65`). Tapetum pre-flight `GET {base_url}/models` → `sys.exit(1)` on failure (`cli.py:545-584`, invoked at `632`); per-paper LLM failures increment `counts["error"]` but CLI **always exits 0** (`cli.py:12-13`, `865-892`, `930`). Documented infra: twin pod `h200x8-deepseek-v4-pro` returned 404 on all probes while `alliance-pod` was live (`research/llm-batching/18-load-splitter.md:8`). Impact: today's split isolates infra fragility from CI; an LLM-gated design would convert probe failure into merge-blocking.

- [HIGH] **Sovereignty makes det-first NECESSARY for gating, not merely prudent.** Necessity chain: (1) gating decisions must be defensible under our control (`CLAUDE.md:64-66`); (2) reference LLM-QA patterns run on cloud models we cannot gate on (`00-baseline.md:26-28`, `05-web.md / Q3`); (3) self-hosted judges retain run-to-run variance and schema fragility (`05-web.md / Q2 / Necessary but Not Sufficient`, `MODELS.md:72-77`). Prudent-alone would allow optional cloud advisory; **necessary** means LLM cannot be the mechanical accept/reject authority without either violating sovereignty (cloud) or accepting non-reproducible infra coupling (pod) — the exact failure mode 05-web documents for LLM-judge CI gates (`05-web.md / Q1 / What Happens When LLM-Judge CI Gates Are Treated as Hard Blockers`).

- [MED] **Steelman counter: sovereignty-compatible LLM gating is architecturally possible with vendored open weights + pinned versions.** Deploy invariants already specify `min-replica-count = max-replica-count = 1`, session affinity, direct routing (`MODELS.md:79-87`); olmOCR's precedent is LLM **mines**, humans **verify**, bench gates on verified facts only (`00-baseline.md:18`, `05-web.md / Q5 / olmOCR-Bench README`). A sovereign variant could gate on human-verified fact JSONL (olmOCR pattern) with self-hosted mining — but that is det-first with LLM as extractor, not LLM-as-judge gating. Pure LLM-gate steelman still must beat judge variance (`05-web.md / Q2`) and our retry budget (`MODELS.md:128-130`); ecosystem maintainers chose not to (`05-web.md / Q5 / Marker CI gates heuristic only`).

- [LOW] **Fusion degrades cleanly when tapetum is absent/unusable** (`fusion.py:86-94`, `133-142`), preserving deterministic verdict — the correct sovereignty-safe failure mode. Gap: exception paths may leave stale sidecars (`research/llm-qa-integration/06-error-handling-robustness.md:8-14`), so advisory degradation is sound in code but not always honest on disk.

## False-pass hypothesis

Operator treats `fuse_verdicts` `combined_verdict=pass` from `FUSION_RULE_LLM_CLEAR_SOFT_REVIEW` (`fusion.py:192-207`) as ship authority after a pod outage mid-batch: stale `*.tapetum.json` still shows LLM pass (`06-error-handling-robustness.md:8-9`), deterministic gate stayed green (`gates.py:209-218`), but the latest run never persisted. Under LLM-gated CI the same stale artifact would false-pass merge; under det-first it false-passes only human workflow discipline.

## False-fail hypothesis

Cold `alliance-pod` at batch start: `_probe_llm_endpoint` exits 1 before any paper runs (`cli.py:577-584`). Entire advisory batch blocked though deterministic `whisker --all` would pass every paper. If that probe guarded CI merge in an LLM-gated design, a 30 s infra blip becomes a spurious pipeline failure — the flaky-CI class documented in `05-web.md / Q1 / What Happens When LLM-Judge CI Gates Are Treated as Hard Blockers`.

## What would change my mind

An empirical parity run on a human-labeled WG21 subset (≥30 papers): execute marker-style LLM judge prompts and olmOCR-style fact-mining prompts against **both** a cloud ceiling (Gemini/Claude) and our self-hosted stack (`alliance-pod` DeepSeek-V4 plus at least one Gemma and one Qwen service from `SERVICES.toml:87-133`), measuring human-aligned pass/fail agreement and 20× rerun stability at pinned sampling (`MODELS.md:22-33`). If self-hosted matches cloud within 5 pp on pass/fail AND rerun flip rate ≤5%, sovereignty-compatible LLM **gating** becomes adoptable-with-guardrails rather than necessary det-first — and I would downgrade the necessity claim to prudent.
