# 04 - Test-Suite-Auditor

**Verdict:** usable-with-conditions — the deterministic-gates + advisory-LLM architecture is sound per the 31-repo matrix (00-baseline §2, 05-web Q1/Q4), but gate-adjacent tests include blessed known failures, unpinned edge-case holes, and no meta-test layer comparable to olmOCR; green CI overstates gate trustworthiness.
**Confidence:** high

## Findings

- [CRITICAL] **`score-baseline.json` pins known gate failures as the expected state; pinning does not require goldens to pass gates.** Evidence: `test_score_pinning.py:153-155` asserts `actual["gates"] == expected["gates"]` with no `all(passed)` invariant; baseline commits `no_toc_leak: false` for PR-replay papers `p0533r9`, `p1122r3`, `p3968r0` and `heading_monotone: false` for `p2040r0` (`tests/fixtures/score-baseline.json:9,101,121,262`). `WHISKER_PIN_UPDATE=1` rewrites the baseline from whatever is current (`test_score_pinning.py:133-138`) with no `CI=true` guard (contrast pandoc: CI never runs `--accept`, local refresh only — `research/redteam/pandoc.md:60-61`, `CONTRIBUTING.md:272-279` cited there). Impact: the suite detects drift in blessed broken goldens but gives false security that committed ideals satisfy the gate contract; a gate regression that accidentally "fixes" a pinned failure would fail CI, but a gate weakening that matches already-leaky goldens would be silently accepted on refresh.

- [HIGH] **`no_toc_leak` has untested false-pass holes on localized labels and table-only TOC shapes.** Evidence: `_TOC_LABEL_RE` matches only `table of contents|contents` (`gates.py:132-134`); runtime probe: plain `Inhaltsverzeichnis` passes, pipe-table TOC rows without a Contents label pass, roman-numeral duplicate lines pass. Tests cover English `CONTENTS` / `## Contents` and page-numbered heading pairs only (`test_gates.py:102-161`); no multi-row TOC table fixture beyond one-line `| a | 3 |` (`test_gates.py:131-134`); no `Table of Contents` heading case despite regex support. Impact: German/localized TOC leaks and table-rendered TOC leaks (common in WG21 PDFs) can ship while `test_gates.py` stays green; aligns with 00-baseline §4 heading-level / TOC blind spots.

- [HIGH] **No meta-tests on the gate engine or its fixtures (olmOCR ships 148 on the bench assertion engine alone).** Evidence: olmOCR pattern in 00-baseline §1 (`bench/tests.py:114-125`) and `research/redteam/olmocr.md:6` (`tests/test_tests.py`, 148 `def test_`); whisker has 17 gate unit tests in `test_gates.py` and zero tests that validate fixture completeness, gate-name registry, or "every gate has at least one fail + pass case." `test_clean_document_passes_all_gates` (`test_gates.py:35-37`) only asserts `all(g.passed)` on `_GOOD`, not `len(results)==6` or expected gate names — adding/removing a gate in `run_gates` (`gates.py:209-218`) would not fail a registry test. Impact: test count (~995 collected vs 616 cited in 00-baseline §2) measures breadth elsewhere, not gate-engine rigor; gate logic can rot without a pandoc/olmOCR-style "tests of the tests" layer (05-web Q5: machine-checkable facts need a tested checker).

- [HIGH] **Fusion rescue/lock tests omit mixed hard-flag combinations.** Evidence: `_is_heading_only_fail` requires ALL hard flags start with `gate:heading_monotone` (`fusion.py:105-116`); `test_rescue_heading_only_fail` and `test_toc_leak_fail_is_not_rescued` cover single-flag paths (`test_fusion.py:110-146`) but there is no test for `{heading_monotone, non_empty}` mixed fail (runtime: stays `whisker_fail_locked`). `test_fail_locked_non_heading` uses only `gate:non_empty` (`test_fusion.py:102-108`). Unknown gate names are implicitly locked (good) but untested. Impact: a refactor of `_is_heading_only_fail` prefix logic could re-open the PR #290 substring-rescue bug (`test_fusion.py:131-146` documents the fix) without CI catching mixed-flag regressions.

- [MED] **`test_score.py` coverage-floor test is comment-stale and substring-vacuous.** Evidence: `test_coverage_still_hard_fails_with_reference_on` (`test_score.py:241-250`) comment claims shingle "coverage below the floor is the trustworthy hard gate"; `_decide` hard-fails only on `unigram_coverage` (`score.py:181-185`), not shingle coverage. `_content(0.50)` sets both to 0.50 (`test_score.py:47-64`); assert `any("coverage" in f for f in r.hard_flags)` matches `"unigram coverage ..."` by substring. Impact: test passes but does not guard the documented invariant; a revert to shingle-gating would not be caught by this test's intent (only by `test_reflow_high_unigram_low_shingle_not_fail` at `test_score.py:89-96`).

- [MED] **Score pinning does not cross-check gate outcomes against dedicated gate tests.** Evidence: PR-replay regressions live in `test_gates.py:102-111` (synthetic markdown), while the same defect class is committed as `no_toc_leak: false` in the baseline for real goldens (`score-baseline.json:94-101` for `p1122r3`). No test asserts `run_gates(golden_md).passed` for all gates on any stem. Impact: gate unit tests and pinning evolve independently; fixing a golden TOC without updating gate logic (or vice versa) splits the regression story.

- [LOW] **Pandoc golden discipline partially mirrored in Lane 1 (`golden.py`) but not in gate pinning.** Evidence: pandoc fail-closes on missing goldens and forbids CI auto-accept (`research/redteam/pandoc.md:36-40,82-84`); whisker Lane 1 has canaries in `test_comprehension_corpus.py:84-142` but gate pinning lacks an adversarial canary (no test that deliberately corrupts a golden and expects pin failure except implicit via separate modules). Impact: gate pinning is a diff alarm, not a correctness oracle — acceptable if documented, currently overstated in `test_score_pinning.py:10-15` ("any change ... shows up") without noting blessed failures.

## False-pass hypothesis

A German paper whose body retains `## Inhaltsverzeichnis` plus a multi-page pipe-table TOC (no page-numbered heading duplicate): `run_gates` returns `no_toc_leak: passed` (regex miss at `gates.py:132-134`; table rows are not headings). `test_gates.py` has no case; if the golden predates the gate, `score-baseline.json` may pin `no_toc_leak: true` after a refresh that never exercised the shape. Whisker hard-passes; olmOCR would encode a `present`/`absent` fact on the TOC label (05-web Q3/Q5).

## False-fail hypothesis

Committed golden `p2040r0` pins `heading_monotone: false` (`score-baseline.json:117-125`) while other gates pass: a human-blessed ideal with a cosmetic H-level jump is permanently flagged by the gate and pinned as the expected state. Scoring against that golden via `score_markdown` hard-fails on `gate:heading_monotone` even when content is otherwise shippable — fusion can rescue to review only when the LLM lane runs (`fusion.py:149-160`, `test_fusion.py:110-121`), not in reference-free CI.

## What would change my mind

An olmOCR-style `tests/test_gate_engine.py` (~20–40 meta-tests) that (1) asserts `run_gates` always returns exactly the registered gate names, (2) parametrizes every gate with synthetic pass/fail fixtures including localized TOC + table-only TOC, and (3) requires every tomd golden in `_GOLDEN_STEMS` either pass all gates or carry an explicit `expected_gate_failures` object — plus `WHISKER_PIN_UPDATE` blocked when `CI=true` unless a dedicated env var is set (pandoc `--accept` discipline).
