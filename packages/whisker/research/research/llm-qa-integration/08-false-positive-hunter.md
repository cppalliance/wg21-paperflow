# 08 - False-Positive-Hunter

**Verdict:** usable-with-conditions — the deterministic-gates-decide + advisory-LLM architecture matches the 31-repo pattern (thresholds as false-positive valves, LLM never mechanical gate), but two whisker gates carry measurable false-fail surface: `no_toc_leak` rejects legitimate WG21/meta headings, and `heading_monotone` drives 64% of ref-free hard fails with only partial advisory rescue.
**Confidence:** high

## Findings

- [CRITICAL] **`no_toc_leak` false-fails papers that legitimately discuss or title a table of contents.** `_TOC_LABEL_RE` matches any standalone line `^(?:#{1,6}\s+)?(?:table\s+of\s+contents|contents)\s*:?\s*$` case-insensitively (`gates.py:132-134`, `162`). Runtime verify: `## Table of Contents` (meta section about indexing) → `passed=False`, detail `TOC label in body: '## Table of Contents'`; standalone prose line `Table of Contents` → fail. Impact: a WG21 paper whose body includes a normative "Table of Contents" section (not a leaked PDF TOC block) is hard-failed identically to PR #290/#293 true leaks (`test_gates.py:123-134`); the gate cannot distinguish topic-from-artifact.

- [HIGH] **`no_toc_leak` pairwise logic false-fails versioned headings where a longer title shares a shorter prefix plus trailing digits.** `_PAGE_SUFFIX_RE` treats any heading whose normalized text ends with `\s+\d{1,4}` as TOC page-numbered (`gates.py:136-137`, `167-176`); plain duplicate detection fires when the stem reappears without the suffix (`gates.py:177-183`). Runtime verify: `## C++ 26` then `## C++` → fail `duplicate heading 'c++' previously seen as 'c++ 26'`; reverse order → fail `page-numbered duplicate heading 'c++ 26' after 'c++'`; `## ISO C++ 2026` / `## ISO C++` → same. `## C++26` (no space) passes — arbitrary boundary. Impact: standard WG21 headings that name a revision year then a shorter stable name collide with the TOC-leak signature the gate was built for (`golden-qa-gap/00-baseline.md:40-42`, MC2 closed at `00-baseline.md:95`); false-positive pressure is structural, not test-gap.

- [MED] **`no_toc_leak` correctly spares "Contents of the proposal" but still fails bare `## Contents`.** `_TOC_LABEL_RE` requires `contents` as the entire heading text (optional `#` prefix, optional trailing colon) (`gates.py:132-134`). Runtime: `## Contents of the proposal` → pass; `## Contents` → fail (`TOC label in body`). Impact: appendix titles with trailing words are safe; any appendix literally titled "Contents" (common in long proposals) is indistinguishable from a leaked TOC label — asymmetric precision within the same semantic family.

- [CRITICAL] **`heading_monotone` is the dominant deterministic false-fail driver: 9/14 ref-free hard fails (64%), all with near-perfect content metrics.** Corpus rollup (`packages/whisker/research/persona/00-EVIDENCE-BASELINE.md` §3a): hard flags `heading_monotone` 9, unigram `< floor` 3, `no_empty_table` 2; examples `P3941R2/R3/R4` fail solely on H2→H4 with `uni=0.999, drift=0.001`. Gate logic: any `level > prev + 1` on fence-skipped ATX lines (`gates.py:96-112`, `_HEADING_RE` at `33`). Runtime reproduce: `## 4 Wording Changes` → `#### 4.0.1 execution::...` → `passed=False`, `H2 -> H4`. Impact: 64% of hard fails are typography pedantry, not missing words — inflates CI noise and contradicts tomd QA's soft MD001 treatment (`research/tapetum-golden-review-findings-2026-07-14.md:60-82` cited in `00-baseline.md:82`).

- [HIGH] **RESCUE population quantified: 9 heading-only fails routed to advisory LLM; fusion softens all 9 to `review`, never to `pass`.** Selector: `select_candidates` RESCUE branch when sole hard flag prefix is `gate:heading_monotone` (`adjudicate.py:88-108`, `_is_heading_only_fail` at `141-151` with prefix guard against `no_toc_leak` details containing "heading"). Fusion: `fuse_verdicts` upgrades heading-only `fail` + LLM `pass|review` → combined `review` (`fusion.py:148-160`, `FUSION_RULE_LLM_RESCUE_HEADING`); test asserts never upgrades to pass (`test_fusion.py:110-129`). Reproduced cross-tab: 9/9 whisker-fail → tapetum `review`, 0 `pass` (`packages/whisker/research/llm-stack/16-product-decision-skeptic.md:13`). Impact: advisory lane partially absorbs heading false-fails but humans still review every RESCUE paper; deterministic gate remains the CI blocker (`00-baseline.md:61-63`: all 4 new PR hard fails were deterministic, LLM confirmed).

- [HIGH] **Reference repos treat numeric thresholds as false-positive valves, not precision instruments — same architectural move as whisker.** Marker CI blocks only on corpus **means**: heuristic ≥ 90, TEDS ≥ 0.7 (`00-baseline.md:26`, `packages/whisker/research/redteam/marker.md:20`, `verify_scores.py:9-22`); LLM benchmark scorer is advisory and skipped on failure (`00-baseline.md:26`, `05-web.md` Q5 / Marker CI gates heuristic only). MinerU e2e uses `fuzz.ratio > 90` for text blocks but **0.7** table substring hit-rate on VLM path vs **0.9** on text path (`00-baseline.md:27`, `research/per-page-judging/14-mineru-dolphin-analyst.md:16`, `test_e2e.py:163-201`) — modality-specific loosening admits VLM false-pass risk to avoid false-fail churn. Langextract fuzzy LCS gate at 0.75 coverage + 1/3 density (`00-baseline.md:34`, `resolver.py:57-58`) deliberately accepts gapped spans. Docling drops layout clusters below per-label thresholds (`00-baseline.md:29`). Impact: ecosystem consensus is "tune thresholds to bleed borderline cases through," not "LLM score gates accept"; whisker's `heading_monotone` hard gate is **stricter** than peer FP valves (no corpus-mean slack, no modality split).

- [MED] **Marker's in-path LLM table retry (`score < 4`) is a false-positive valve on rewrite, not a document reject gate.** Table processor re-prompts when self-score < 4 up to `max_table_iterations=2` but keeps deterministic original on reject (`research/per-page-judging/12-marker-analyst.md:14`, `llm_table.py:214-225` per `00-baseline.md:26`). Impact: even the repo closest to "LLM QA of output" uses LLM score to **retry its own rewrite**, never to fail the document — supports our "LLM advises, deterministic decides" split (`00-baseline.md:41-55`, `05-web.md` Q4 / Deterministic Guardrails pattern).

## False-pass hypothesis

A WG21 paper with `## C++ 26` and later `## C++` as legitimate section titles (no TOC leak) passes human review but **`no_toc_leak` hard-fails** under current pairwise logic (`gates.py:167-183`); if a future regression removes the gate or weakens `_PAGE_SUFFIX_RE` without a topic-vs-leak classifier, the architecture would wrongly **accept** true TOC leaks (PR #290 shape in `test_gates.py:102-111`) to avoid this false-fail — trading MC2 recall for FP relief.

## False-fail hypothesis

**P3941R2** (and R3/R4): `uni=0.999`, `drift=0.001`, hard-fail solely on `heading_monotone` H2→H4 at stable-name heading under a wording section (`00-EVIDENCE-BASELINE.md` §3c, `gates.py:105-109`). Separately, a meta paper with body section `## Table of Contents` explaining indexing policy is hard-failed by `no_toc_leak` (`gates.py:132-134`, runtime-verified this session) despite zero duplicate page-numbered heading pairs.

## What would change my mind

A WG21-stratified false-positive audit (≥30 human-shippable conversions) measuring **FPR of `no_toc_leak` and `heading_monotone`** on approved papers: if `no_toc_leak` FPR > 5% on non-leak "Contents"/version-heading cases OR `heading_monotone` FPR > 10% on shippable wording papers, demote one or both to soft/review (matching tomd QA) or add WG21 exemptions — without that labeled set, the 9/14 (64%) heading share from `00-EVIDENCE-BASELINE.md` §3a is the best available quantification and already exceeds acceptable CI noise for cosmetic structure.
