# 29 - golden-pr-operator

**Verdict:** usable-with-conditions — the planned `--all-pages` mode (required `page:N` units, fail-closed `page_count` audit, sidecar fields) is the right contract for golden-PR review, but today's operator surface (`tapetum-inspect.md` + `/pr-golden-review` step 3) cannot prove it ran; the report must render page-level audit data the sidecar already carries, and step 3 must stop equating `--inspect` with full PDF coverage.
**Confidence:** high

## Findings

- [CRITICAL] The inspection report the operator actually reads omits every page-level audit field the PDF sidecar already emits. `pdf_judge.py` writes `page_count`, `page_screen` (per-page tokens/recall/flagged/skipped), and `page_escalations` into the sidecar (`pdf_judge.py:437-440`, `549-550`), but `inspect_report.py::format_paper_section` never reads or renders them (no references to `page_screen`, `page_count`, `textlayer_diff`, or `page_escalations` anywhere in that module). Impact: holding the all-pages report in hand, the operator still cannot answer "which pages did the LLM judge?" — only whisker vs tapetum verdict lines and routed-unit counts.

- [CRITICAL] `/pr-golden-review` step 3 documents a coverage story that is false for PDFs. Step 3 invokes `whisker-tapetum-llm ... --inspect` (`pr-golden-review.md:61`) and describes unit checks as bounded LLM calls on "flagged units" with pass valid when "all flagged units were checked" (`pr-golden-review.md:64`, `72`). Baseline runtime: P1068R11 got 5/15 page unit checks under `--inspect` (`00-baseline.md:19`). Root cause: PDF branch calls `judge_pdf_extraction` with no exhaustive/all-pages kwarg (`cli.py:1120-1127`), while the text lane passes `exhaustive=args.exhaustive_units or args.inspect` (`cli.py:1186-1187`); `run_unit_checks` is invoked without `exhaustive` (`pdf_judge.py:843-850`), capping at `MAX_UNIT_CHECKS = 5` (`constants.py:223`, `unit_judge.py:304`). Impact: the golden-review playbook certifies coverage the tool does not perform; a merge recommendation on LLM `pass` is unwarranted.

- [HIGH] `unit_coverage.coverage_complete=True` is not synonymous with "every page LLM-checked." Default before any unit work is `coverage_complete: True` with empty id lists (`pdf_judge.py:831-836`); fusion fail-closes only when `coverage_complete is not True` or ids remain unchecked/failed (`fusion.py:191-195`). Docstring defines coverage as "every routed risky unit" (`pdf_judge.py:453-454`), and `run_unit_checks` returns `None` when routing yields no signals (`unit_judge.py:287-288`). Impact: a paper where the LLM never scoped-checked a single page can still show `complete=True, checked=0` in `inspect_report.py:192-195` — a false green coverage line.

- [HIGH] For operator trust, coverage must be expressed against physical pages, not routed units alone. The sidecar already has a deterministic per-page screen (`screen_pages`, `pdf_judge.py:311-336`; serialized `page_screen`, `549`). Planned `--all-pages` (baseline `00-baseline.md:44`) must add an explicit audit, e.g. `pages_llm_checked / page_count` with fail-closed mismatch, plus a per-page table: page number, tokens, recall, screen skipped/flagged, LLM unit check status (checked / skipped-no-signal / capped / failed), defect-group count for that page. The headline line "15/15 pages checked" is necessary but not sufficient — it must reconcile with the table and list every non-checked page with a reason (below `PAGE_MIN_TOKENS`, no router signal in capped mode, quota cap, LLM call failure, timeout). Impact: without the table + reasons, the operator cannot distinguish "all pages judged" from "monolith saw full text once + 5 routed units."

- [MED] Findings are partially triageable today but split across redundant layers. Defect groups are correctly aggregated by type with `source_unit`, counts, and verification status (`unit_judge.py:457-505`; rendered `inspect_report.py:224-248`). Evidence dispositions are also dumped as a second full table (`inspect_report.py:267-297`). For golden-PR triage the operator needs: (1) a per-page findings rollup (count + top defect types), (2) defect groups grouped by type with verified `affected_count` and 1–3 source quotes plus candidate disposition (`present_in_candidate` / `candidate_not_found`), (3) page-level drill-down only for pages with non-zero findings — not two parallel flat tables. Impact: current layout forces eyeballing duplicate quote rows instead of "page 7: 2 heading_drift, 0 verified missing content."

- [MED] Step 3 must be rewritten for PDF golden review once `--all-pages` lands: use `--all-pages` (not `--inspect` alone) for PDF sources; extend the staging timeout beyond `_pdf_judge_timeout_seconds()` which budgets `1 + MAX_UNIT_CHECKS` unit calls (`cli.py:146-151`), not `page_count` serial calls (`00-baseline.md:25`); add an explicit operator gate — abort LLM `pass` unless sidecar reports `pages_llm_checked == page_count` and fusion is not capped for incomplete coverage (`fusion.py:182-195`); keep deterministic whisker, LLM, and fusion verdicts separate (`pr-golden-review.md:74`) but add a fourth row "page coverage" sourced from sidecar audit fields, not inferred from `--inspect`. Impact: fixes the documented lie and aligns review-mode cost assumptions (`00-baseline.md:36`) with runtime budget.

- [LOW] Noise mechanisms already present will dominate an all-pages report if uncapped. `inspect_report.py` surfaces self-reported uncalibrated confidence prominently (`105`), dumps unverified LLM reasoning (`316-318`), lists only five risk signals then ellipses the rest (`257-264`), and renders every evidence disposition row (`267-297`). At 15–40 pages × multiple claims, the report becomes a scroll of refuted monolith quotes the operator learns to ignore. Impact: even correct full coverage will be dismissed unless refuted/abstained claims collapse to counts and page-level summaries.

## False-pass hypothesis

P1068R11-class case: 15-page PDF, monolith `pass`, only 5 `page:N` units checked (`00-baseline.md:19`), 10 pages never in any scoped LLM call; `unit_coverage` shows `complete=True, checked=5` or, if routing is sparse, `complete=True, checked=0` (`pdf_judge.py:831-836`); `inspect_report.py` prints `complete=True` without a page table; step 3 operator records LLM `pass` because the command text says flagged units were checked (`pr-golden-review.md:72`). A heading-level defect on an unrouted page ships in the golden.

## False-fail hypothesis

`--all-pages` forces 15–40 serial unit checks (`00-baseline.md:25-26`). Pages with high recall but subtle formatting drift still route on `heading_drift` or `token_delta` (`source_router.py:200-260`, cited in baseline). Worst-page-wins noise (`00-baseline.md:32`: ~28% doc-level false review at 33 pages, 1%/page) produces many `review` defect groups on a hand-built ideal that is structurally correct; operator burns time refuting refutable groups (`present_in_candidate`) that the report lists but does not de-emphasize (`inspect_report.py:273-277`).

## What would change my mind

One golden-PR replay on P1068R11 with implemented `--all-pages`, producing `tapetum-inspect.md` that shows a 15-row page audit table, headline `15/15 pages LLM-checked`, zero unchecked pages without an explicit reason, and fusion capped at `review`/`fail` (never `pass`) when any page is missing — with step 3 updated to require that table before LLM `pass` counts.
