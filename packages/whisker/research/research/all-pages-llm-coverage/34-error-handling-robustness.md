# 34 - error-handling-robustness

**Verdict:** usable-with-conditions (+ per-unit failure continuation with `failed_unit_ids` and `coverage_complete=False` is the right all-pages primitive, but the planned design inherits three fail-not-partial gaps: capped outer timeout writes a tombstone with no partial page audit, `KeyboardInterrupt` bypasses the error firewall, and monolith/escalation/metadata failures abort while unit failures persist `status=ok` sidecars that exit 0)
**Confidence:** high

## Findings

- [CRITICAL] Outer CLI timeout on a 40-page all-pages run writes an error tombstone and drops all in-flight unit progress: `_pdf_judge_timeout_seconds()` budgets only `(1 + MAX_UNIT_CHECKS)` unit slots (`cli.py:146-151`, `constants.py:223`), `asyncio.wait_for(..., timeout=_pdf_judge_timeout_seconds())` wraps the entire `judge_pdf_extraction` call (`cli.py:1121-1126`), and on expiry the broad `except Exception` path calls `_write_error_tombstone` (`cli.py:1255-1264`, `674-698`) with no `_persist_lane_result`. Impact: timeout at page 30 of 40 is fail-closed as `status=error`, but operators lose an enumerated `checked_unit_ids`/`unchecked_unit_ids` audit; the planned design must scale timeout with `page_count` and either persist a partial coverage sidecar before tombstoning or treat timeout as `coverage_complete=False` review, not opaque error-only.

- [CRITICAL] All-pages accounting has no required-units path today, so zero routed pages still emits `coverage_complete=True`: `run_unit_checks` returns `None` when `risk_signals` is empty (`unit_judge.py:287-288`); `pdf_judge.py` keeps the pre-unit default `unit_coverage={"coverage_complete": True, ...}` (`pdf_judge.py:831-836`, `839-850`). Impact: a "complete" sidecar with empty `checked_unit_ids` is mistakable for full page coverage; planned `--all-pages` must inject every `page:N` as required, always materialize a `UnitJudgeResult`, and reconcile against `textlayer_diff.page_count` (`pdf_judge.py:544-548`).

- [HIGH] One failed unit out of N correctly forces review and honest partial evidence when unit checks actually run: `_check_one_unit` failures are caught, logged, appended to `failed_unit_ids`, and the loop continues (`unit_judge.py:325-341`); `coverage_complete` requires zero failed/unchecked and full checked set (`unit_judge.py:376-380`); unit verdict becomes `review` when incomplete (`unit_judge.py:390-394`); PDF lane demotes pass→review (`pdf_judge.py:884-885`); sidecar carries `unit_checks`, `failed_unit_ids`, and `coverage_complete` (`pdf_judge.py:854-859`, `553-555`); fusion caps at review on incomplete coverage or non-empty `failed_unit_ids` (`fusion.py:191-195`, `398-411`). Impact: the continuation primitive is sound for all-pages; tests lock the contract (`test_unit_judge.py:160-172`).

- [HIGH] Pod-down or LLM outage on monolith, metadata, or page escalation fails loudly (no partial sidecar); pod-down on a unit check does not: monolith/metadata failures raise `PdfLaneError` (`pdf_judge.py:588-589`, `650-651`, `677-679`); page escalation failures abort the whole lane (`pdf_judge.py:751-754`); CLI maps any such exception to `_write_error_tombstone` and skips `_persist_lane_result` (`cli.py:1255-1264`). Unit-scoped outages are swallowed into `failed_unit_ids` and the run completes with `status=ok` (`unit_judge.py:337-341`, `pdf_judge.py:515`). Impact: asymmetric fidelity—critical-path failures are loud; per-page failures are honest in sidecar fields but CLI exits 0 (`cli.py:1311`) with `suggested_verdict=review`, not `status=error`; all-pages should document this as intentional degrade-to-review, not silent pass.

- [HIGH] Debug transcript survives outer failures via the inner `finally`, including timeout/tombstone path: PDF lane allocates `judge_debug` when `--debug` (`cli.py:1119`); `finally` at `cli.py:1129-1151` calls `write_debug_file` before the outer firewall; tests assert partial debug is flushed before tombstone (`test_incremental.py:671-678`, `645-650`). Impact: operator forensics for mid-run failures are preserved; all-pages long runs depend on this block.

- [MED] `KeyboardInterrupt` and other `BaseException`s bypass the error tombstone, risking a stale pass sidecar: the per-paper firewall catches only `Exception` (`cli.py:1255`); `KeyboardInterrupt` propagates from `asyncio.run(_run(args))` (`cli.py:1325-1326`) without `_write_error_tombstone`; prior successful run's sidecar and fingerprint remain on disk (`cli.py:581-585`, `1098-1105`). Impact: Ctrl+C mid-run can leave a capped-mode pass sidecar while the operator believes the all-pages rerun failed; planned design should tombstone or mark incomplete on interrupt.

- [MED] Sidecar writes are single-shot `write_text`, not atomic rename: `_persist_lane_result` and `_write_error_tombstone` both use direct `out_path.write_text(...)` (`cli.py:626-628`, `692-694`). Impact: kill during write is low probability but could yield a truncated JSON sidecar; all-pages 40-call runs increase exposure; write-to-temp-then-rename would harden.

- [LOW] Unit calls have backend-level transient retry only; no tapetum-level re-invocation after budget exhaustion: `run_judge_task` delegates to `agent.run` with no local retry loop (`judge_task.py:68-74`); `model_backends.py` retries at most twice on transient API errors (`model_backends.py:300`, `341-351`); exhausted retries surface as `Exception` → `failed_unit_ids` (`unit_judge.py:337-341`). Impact: adding a second unit-level retry would multiply wall-clock on 40-page serial runs; current finite budget is adequate if timeout scales; do not add unbounded unit retry.

## False-pass hypothesis

Operator runs planned `--all-pages` on a 15-page PDF with zero router signals before required-units wiring ships: monolith completes, `run_unit_checks` returns `None` (`unit_judge.py:287-288`), sidecar persists `unit_coverage.coverage_complete=true` with empty ID lists (`pdf_judge.py:831-836`), fusion passes the coverage gate (`fusion.py:192-193`), CLI exits 0 (`cli.py:1311`). Operator reads `suggested_verdict=pass` and treats all 15 pages as individually LLM-verified.

## False-fail hypothesis

Operator enables `--all-pages` on a 40-page paper without rescaling `_pdf_judge_timeout_seconds()`: serial unit checks exceed the capped budget (`cli.py:146-151`), `asyncio.wait_for` raises `TimeoutError` (`cli.py:1121-1126`), CLI writes `{status: error}` tombstone (`cli.py:674-698`, `1264`) with no `unit_coverage` listing pages 1–29 checked, debug transcript survives (`cli.py:1129-1151`) but the operator sees only `error: TimeoutError`, not a review with enumerated gaps.

## What would change my mind

An implemented all-pages branch where (1) `_pdf_judge_timeout_seconds(page_count)` prevents outer timeout during a 40-page fixture test, (2) one injected unit failure at page 17 yields `coverage_complete=false`, `failed_unit_ids=["page:17"]`, 39 entries in `unit_checks`, `suggested_verdict=review`, and CLI exit 0, (3) outer timeout or `KeyboardInterrupt` at page 30 either persists partial coverage audit or tombstones without leaving a stale pass fingerprint, and (4) pod-down on the monolith call still produces only `{status:error}` with no `status=ok` sidecar.
