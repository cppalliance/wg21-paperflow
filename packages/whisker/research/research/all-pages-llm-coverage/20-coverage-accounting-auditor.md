# 20 - coverage-accounting-auditor

**Verdict:** usable-with-conditions (+ the baseline planned `--all-pages` design targets the right extension points—required `page:N` units, `page_count` reconciliation, sidecar audit fields, separate fingerprint—but today’s accounting primitives measure *routed-risk completion*, not *physical-page completion*, and several defaults emit `coverage_complete=True` when zero pages were individually judged; the plan is fail-closed only if it replaces those semantics end-to-end, not if it merely wires a flag through the existing router/cap path.)
**Confidence:** high

## Findings

- [CRITICAL] PDF lane never receives exhaustive/all-pages intent: `cli.py:1120-1127` calls `judge_pdf_extraction(...)` with no coverage-mode kwarg, while the text lane passes `exhaustive` at `cli.py:1186-1187`. Impact: `--exhaustive-units` and `--inspect` are dead for PDF golden review (baseline root cause 1); an `--all-pages` flag wired the same way would repeat the defect.

- [CRITICAL] `run_unit_checks` bails out before any accounting when the router finds nothing: `unit_judge.py:287-288` returns `None` if `risk_signals` is empty; `pdf_judge.py:831-836` then leaves the default `unit_coverage={"coverage_complete": True, ...}`. Impact: a paper where every page is “clean” to deterministic heuristics reports full unit coverage while **zero** pages received a scoped LLM check—exact opposite of all-pages verification. All-pages mode must inject `required_unit_ids = [f"page:{i}" for i in 1..page_count]` and never take the no-signals shortcut.

- [CRITICAL] `coverage_complete` is defined over *routed* units, not pages: `unit_judge.py:376-380` sets complete only when `len(checked_unit_ids) == len(risky_unit_ids)` with no `unchecked_unit_ids`/`failed_unit_ids`; `risky_unit_ids` comes from `route_pdf_units` (`pdf_judge.py:837`), which only fires on token_delta/low_recall/missing_captions/heading_drift/table_presence (`source_router.py:184-263`). Impact: on P1068R11 (15 pages, 5 routed) capped mode can honestly report `coverage_complete=True` for those 5 while 10 pages were never individually judged (00-baseline.md:19). All-pages mode must compare `len(checked_unit_ids)` to `page_count` (or `len(required_unit_ids)`) and list every missing `page:N` in `unchecked_unit_ids`.

- [HIGH] `MAX_UNIT_CHECKS` cap is always active on the PDF path: `unit_judge.py:304` uses `MAX_UNIT_CHECKS` unless `exhaustive=True`; `pdf_judge.py:843-850` omits `exhaustive`; cap value `constants.py:223`. Impact: even with CLI wiring fixed, PDF lane still stops at 5 routed units. All-pages mode must pass `exhaustive=True` *and* set `max_checks = page_count` (or bypass quota selection entirely when `required_unit_ids` is the full page list).

- [HIGH] Quota selection creates systematic unchecked units before any LLM failure: `unit_judge.py:305-311` builds `unchecked_unit_ids` from units not selected by `_select_units_with_quotas` (`unit_judge.py:136-166`); non-exhaustive runs always fail closed on *routed* subset only. Impact: capped mode correctly demotes via `unit_judge.py:390-393` and `fusion.py:192-195`, but that fail-closed behavior never applies to unrouted pages. All-pages mode must skip quota selection and treat any `page:N` not in `checked_unit_ids` as unchecked.

- [HIGH] Missing source packets are silently unchecked, not failed: `unit_judge.py:319-323` appends to `unchecked_unit_ids` and `continue`s when `unit_text_map` lacks the unit; `coverage_complete` becomes False (`unit_judge.py:376-379`). Impact: fail-closed for *routed* units is sound, but all-pages mode must decide policy for empty `page:N` text (blank/image-only pages): either explicit `skipped_with_reason` audit entries still counted against `page_count`, or hard `review` with the page listed unchecked—never drop from the required set.

- [HIGH] `failed_unit_ids` fail closed on routed checks but do not propagate to PDF verdict unless unit_result exists: `unit_judge.py:337-341` records failures; `unit_judge.py:390-393` sets verdict `review`; `pdf_judge.py:884-885` demotes only when `unit_result.verdict == "review"`. Impact: mechanism works when unit checks run; useless when `run_unit_checks` returned `None`. All-pages mode must always materialize a `UnitJudgeResult` (never `None`) and cap `pdf_judge` verdict at `review` whenever `not unit_coverage["coverage_complete"]` or `failed_unit_ids`/`unchecked_unit_ids` non-empty—mirror `fusion.py:192-195`.

- [MED] Default `coverage_complete=True` when no risk signals is honest for *routed-absence* semantics but dishonest for all-pages: `pdf_judge.py:831-836`, `pdf_judge.py:453-454` docstring (“every routed risky unit”); same pattern in text lane `adjudicate.py:435-440`. Impact: sidecar and fusion (`fusion.py:191-195`) treat “nothing to check” as complete coverage. All-pages sidecar must emit `required_page_count`, `checked_page_count`, `unchecked_unit_ids` spanning all gaps, and set `coverage_complete=False` until `checked_page_count == page_count`.

- [MED] Per-page recall screen skips (`PAGE_MIN_TOKENS`) and escalation cap (`MAX_PAGE_ESCALATIONS`) are parallel uncovered paths: `pdf_judge.py:325-329` marks pages `skipped=True` with no recall/escalation; `pdf_judge.py:729-742` caps escalation and only demotes verdict without LLM calls when flagged count exceeds cap (`constants.py:183`, `constants.py:191`). Impact: all-pages unit checks may cover these pages, but recall-screen audit still shows `skipped` with no LLM escalation—operators may conflate screen coverage with unit coverage. All-pages orchestration should either fold screen skips into required units or add sidecar fields `page_screen_unchecked` reconciled against `page_count`.

- [MED] Timeout budget is sized for capped mode, not all-pages: `cli.py:146-151` budgets `(1 + MAX_UNIT_CHECKS) * UNIT_CHECK_TIMEOUT_SECONDS` with `MAX_UNIT_CHECKS=5` (`constants.py:223`); a 40-page serial run needs `(1 + page_count)` unit slots plus monolith. Impact: `--all-pages` would hit `asyncio.wait_for` timeout (`cli.py:1126`) and write an error tombstone (`cli.py:1255-1264`)—fail-closed as error, not as partial coverage audit. Plan must add `_pdf_all_pages_timeout_seconds(page_count)` and a separate fingerprint so incremental skip cannot reuse capped-mode results (`cli.py:515-565`, baseline comparison anchor).

- [LOW] `--inspect` help claims exhaustive units (`cli.py:257-261`) but PDF path ignores it; inspect report reads `unit_coverage` (`inspect_report.py:180-193`) without cross-checking against `textlayer_diff.page_count` (`pdf_judge.py:544-548`). Impact: operator-facing report can show `complete=True` while most pages were never unit-checked. All-pages inspect output must print `checked/required/page_count` explicitly.

## False-pass hypothesis

A 15-page golden PDF where deterministic routing flags exactly 5 pages: operator runs `whisker-tapetum-llm --inspect` on the PDF lane. Monolith sees all pages once in bulk; only 5 scoped unit checks run (`unit_judge.py:304-307`, `pdf_judge.py:843-850`). Sidecar reports `unit_coverage.coverage_complete=True` (all 5 routed units checked), `textlayer_diff.page_count=15`, fusion passes coverage gate (`fusion.py:192-193`). Operator concludes every page was LLM-verified; 10 pages never received an individual judge call.

## False-fail hypothesis

Operator enables planned `--all-pages` on a 40-page paper without timeout rescale: serial unit checks exceed `cli.py:146-151` budget, `asyncio.wait_for` raises at ~page 31, CLI writes error tombstone (`cli.py:1264`) with no partial `unit_coverage` audit listing pages 1-30 checked and 31-40 unchecked—failure mode is opaque timeout, not a capped `review` with enumerated gaps.

## What would change my mind

An implemented `--all-pages` branch (in `cli.py`, `pdf_judge.py`, `unit_judge.py`) checked into the workspace where a test exercises a 15-page fixture with zero router signals and asserts: `required_unit_ids` has 15 entries, `len(checked_unit_ids)==15`, `coverage_complete=True` only after all 15 LLM calls, verdict stays `review` if any `page:N` is unchecked/failed/missing packet, sidecar fingerprint differs from capped mode, and `_pdf_judge_timeout_seconds` scales with `page_count`.
