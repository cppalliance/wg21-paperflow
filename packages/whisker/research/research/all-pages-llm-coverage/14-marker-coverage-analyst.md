# 14 - marker-coverage-analyst

**Verdict:** usable-with-conditions — marker's reject-and-keep validation gates and structured-output merge guards are portable prior art for tapetum unit-check fidelity, but its block-selective `--use_llm` architecture and optional page correction explicitly optimize away full-page LLM coverage and offer no verification-coverage certificate.
**Confidence:** high

## Findings

- [CRITICAL] `--use_llm` is block-selective extraction correction, not per-page verification. `PdfConverter.default_processors` registers 12 LLM processors gated by global `use_llm` (`marker/converters/pdf.py:70-99`, `:138-139`); `BaseLLMProcessor.__init__` no-ops when `use_llm` is false (`marker/processors/llm/__init__.py:64-65`); `BaseLLMComplexBlockProcessor.__call__` returns early when service is None (`:137-139`). Per-processor skip filters: forms need TableCell children (`llm_form.py:65-74`); tables skip when `row_count > max_table_rows` (175) (`llm_table.py:134-135`); equations skip small blocks unless `redo_inline_math` (`llm_equation.py:79-83`); image descriptions only when `extract_images=False` (`llm_image_description.py:42-46`); inline-math redo needs `redo_inline_math` plus page math-density ratio (`llm_mathblock.py:77-78`, `:127-131`). 05-web.md Q5 confirms a text-only page may incur zero LLM calls. Impact: marker is the wrong comparison anchor for "every page verified by LLM"; copying its gating would reproduce whisker's current 5/15-page defect, not fix it.

- [HIGH] Reject-and-keep validation preserves deterministic output on bad LLM responses. Processors increment `llm_error_count` and return without mutating block HTML on schema miss (`llm_form.py:98-100`, `llm_equation.py:110-112`, `llm_table.py:201-203`, `llm_mathblock.py:178-180`); Gemini service returns `{}` after retry exhaustion (`marker/services/gemini.py:131`). Pre-merge gates: form HTML `<33%` original length (`llm_form.py:109-111`); complex region `<50%` (`llm_complex.py:84-86`); handwriting `<50%` (`llm_handwriting.py:77-79`); equation unbalanced `<math>` tags or `<30%` length (`llm_equation.py:119-126`); math block `<60%` length (`llm_mathblock.py:191-193`); table parse `<=1` cells or missing `</table>` (`llm_table.py:228-238`); page reorder requires block-ID set equality with page structure (`llm_page_correction.py:222-242`). Table-only self-score retry: re-prompt when `score < 4`, up to `max_table_iterations=2` (`llm_table.py:214-225`). Impact: adopt this pattern for `--all-pages` unit checks so a hallucinated or truncated judge response cannot overwrite the deterministic whisker verdict (00-baseline §Comparison anchors, C1 advisory non-leakage).

- [HIGH] `LLMPageCorrectionProcessor` is the closest per-page LLM pass but is optional correction, not golden review. When `block_correction_prompt` is unset, `rewrite_blocks` returns immediately (`llm_page_correction.py:268-270`); when set, it submits one call per page with page image + normalized block JSON (`:150-159`, `:286-288`). README documents `--block_correction_prompt` for custom page-level correction (05-web.md Q5, https://github.com/datalab-to/marker). No comparison to external markdown, no fail-closed coverage check against `page_count`. Impact: useful orchestration reference (page raster + scoped context + Pydantic `PageSchema`) for whisker `unit_judge.py::run_unit_checks`, but the prompt contract and default-off gate are extraction-oriented, not verification-oriented.

- [MED] Block-level LLM telemetry exists; no LLM coverage accounting or completion certificate. `BlockMetadata` tracks `llm_request_count`, `llm_error_count`, `llm_tokens_used` (`marker/schema/blocks/base.py:16-19`); `update_metadata` accumulates (`:324-331`); Gemini writes counts per call (`gemini.py:89-92`). Renderers emit `page_stats` with per-page aggregated `block_metadata` into `*_meta.json` (`renderers/__init__.py:100-115`, `output.py:92-97`). Issue #804 (05-web.md): token totals in meta JSON, not a coverage guarantee. No code path asserts `pages_with_llm_requests == page_count` or fails closed on zero-coverage pages. Impact: whisker should add explicit sidecar audit fields (`pages_checked`, `page_count`, fail-closed mismatch) rather than treating marker's post-hoc stats as prior art for coverage guarantees.

- [MED] Marker "coverage" elsewhere means layout/OCR geometry, not LLM lane completeness. `LineBuilder.check_layout_coverage` compares layout blocks to provider lines (`marker/builders/line.py:281-322`); PDF provider `image_threshold` skips image-heavy pages (`providers/pdf.py:67-70`). These gate deterministic OCR/layout quality, unrelated to LLM invocation. Impact: do not conflate marker layout coverage with the swarm's verification-coverage question; 00-baseline distinguishes extraction vs verification coverage and marker sits firmly in extraction.

- [MED] Benchmark LLM judge is a separate optional lane scoring one page per sample, not exhaustive document QA. `LLMScorer.__call__` renders only `doc[0]` (`benchmarks/overall/scorers/llm.py:101-105`); `SCORE_REGISTRY` keeps heuristic and LLM scorers parallel (`benchmarks/overall/registry.py:11-14`); benchmark failures skip LLM score (`benchmarks/overall/overall.py:60-63`). README reports heuristic and LLM columns side-by-side, CI gates heuristic only (05-web.md Q4/Q5). Impact: marker's eval LLM-as-judge is even less coverage-complete than whisker's planned `--all-pages` mode; parallel-lane separation is adoptable, exhaustive judging is not present.

- [LOW] Simple LLM processors batch through `LLMSimpleBlockMetaProcessor` with `max_concurrency=3` thread pools (`marker/converters/__init__.py:43-63`, `llm_meta.py:44-49`, `processors/llm/__init__.py:42-45`). Impact: conflicts with workspace determinism rule D11 (00-baseline §Runtime facts, serial tapetum); do not adopt concurrency defaults for golden-review mode.

## False-pass hypothesis

A 15-page golden PR where pages 6-15 are plain text with no Table/Form/Equation blocks: marker `--use_llm` leaves `llm_request_count=0` on those pages in `page_stats` (`renderers/__init__.py:106-112`) while conversion succeeds and benchmark heuristic score stays high. If whisker copied block-selective gating instead of mandatory `page:N` units, the operator would believe "LLM was used" because `--use_llm` / tapetum ran, while 10 pages never received an individual judge call (mirrors 00-baseline §Runtime facts: 5/15 pages checked).

## False-fail hypothesis

A legitimate tapetum unit-check response that is shorter than the routed page excerpt (e.g. concise "no defects" with fewer tokens than source text) would be rejected if whisker blindly copied marker's 33-50% length-ratio gates without a structured no-op path like `"no corrections needed"` (`llm_form.py:105-106`, `llm_equation.py:116-117`). Marker avoids this via explicit no-op strings and Pydantic schemas; whisker must mirror that contract, not the raw length thresholds alone.

## What would change my mind

Finding a fail-closed post-run check in the marker clone that aborts or flags the document when any page in `document.pages` has zero `llm_request_count` while `use_llm=True` and a coverage mode is enabled (analogous to whisker's planned `pages_checked == page_count` sidecar audit). Current evidence shows only telemetry aggregation (`page.py:360-367`, `output.py:92-97`) with no enforcement.
