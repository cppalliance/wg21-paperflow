# 31 - steelman-current-design

**Verdict:** usable-with-conditions — the routed hybrid (deterministic per-page recall screen + monolith + scoped escalation + risk-routed unit checks) already delivers the verification coverage that matters for golden-PR review; `--all-pages` LLM unit checks would mostly add theater, cost, and judge noise, but the PDF lane must wire `--inspect`/`--exhaustive-units` and surface page-screen audit data before the operator can trust it.
**Confidence:** high

## Findings
- [CRITICAL] Every physical page is already touched deterministically before any LLM call: `screen_pages` iterates all `cleaned_pages`, computes `content_recall(tomd_md, page)` for each non-trivial page, and records per-page recall/flag/skip in the sidecar. Evidence: `pdf_judge.py:311-336`, `pdf_judge.py:629`, `pdf_judge.py:549`. Impact: this is full **verification** coverage (olmocr-bench class), not sampling; the operator's "every page validated" requirement is met by deterministic metrics, not by N serial LLM calls.
- [CRITICAL] The recall floor is calibrated, not arbitrary: `PAGE_RECALL_FLOOR = 0.90` was fitted with a 107-control-page flip-check (8 golden PDFs, worst healthy page 0.9129) that flags the known p0957r8 defect (page 13, recall 0.8810) with zero false flags on controls. Evidence: `constants.py:167-177`. Impact: the screen isolates localized absence that document-level `PDF_JUDGE_RECALL_FLOOR` (`constants.py:164`, `pdf_judge.py:711-716`) mathematically cannot see — the exact failure mode that motivated per-page work in `research/per-page-judging/SYNTHESIS.md`.
- [HIGH] The monolith LLM call sees the entire PDF text layer plus full markdown in one structured pass, preserving global checks (order, structure, cross-page joins) that per-page calls structurally lose. Evidence: `pdf_judge.py:603-637`, `pdf_judge.py:576-586`. Impact: prior synthesis ranked cross-page reordering and rubber-stamping as monolith strengths; `--all-pages` unit checks would fragment context without replacing this pass.
- [HIGH] Prior art for verification rejects exhaustive LLM-as-judge: olmOCR-Bench uses programmatic per-page baseline tests with no LLM in the eval loop (https://github.com/allenai/olmocr/tree/main/olmocr/bench); ParseBench scores ~2,000 pages with 169K+ rule-based tests and explicitly rejects LLM-as-judge (https://github.com/run-llama/ParseBench); Agreeableness-bias work reports judge TNR typically <25% (https://arxiv.org/html/2510.11822v2). Impact: forcing an LLM onto every page optimizes the wrong metric (LLM touch count) and imports documented false-pass bias; deterministic coverage plus routed deep validation matches the clinical multi-stage pattern (https://arxiv.org/pdf/2604.06028) cited in `05-web.md` Q4.
- [HIGH] Scoped escalation and unit routing concentrate LLM spend where deterministic signals already fired: recall-screen flags trigger page-scoped calls with the full conversion contract (`pdf_judge.py:724-750`, `_escalate_page` at `pdf_judge.py:385-398`); `route_pdf_units` emits `low_recall`, `token_delta`, `missing_captions`, `heading_drift`, `table_presence` per page (`source_router.py:199-263`); caps (`MAX_PAGE_ESCALATIONS = 5`, `constants.py:191`; `MAX_UNIT_CHECKS = 5`, `constants.py:223`) fail closed to `review` when signals exceed budget (`pdf_judge.py:729-742`, `constants.py:224-226`). Impact: on a typical golden, 0-2 escalations and ≤5 unit checks suffice; `--all-pages` on a 40-page paper is ~40 serial calls under D11 with timeout budget sized for capped mode (`cli.py:138-151`), trading wall-clock for no proven recall gain.
- [HIGH] No surveyed verification pipeline runs an LLM per page; the user's extraction-pipeline comparison is a category error. Evidence: `research/per-page-judging/SYNTHESIS.md` summary bullets 2 and 10-21 survey; Docling VLM per-page coverage is **extraction**, not post-conversion QA (`05-web.md` Q1); marker `--use_llm` is block-selective with zero LLM on text-only pages (https://github.com/datalab-to/marker/blob/master/marker/converters/pdf.py, `05-web.md` Q5). Impact: `--all-pages` mimics extraction architectures, not verification prior art; the current hybrid already implements the olmocr/ParseBench lesson (deterministic page scope + routed depth).
- [CRITICAL] The unwired `--inspect` / `--exhaustive-units` path for PDFs is indefensible for golden-PR review trust: the text/HTML lane passes `exhaustive=args.exhaustive_units or args.inspect` to `adjudicate_paper` (`cli.py:1186-1187`), but the PDF branch calls `judge_pdf_extraction` with no exhaustive parameter (`cli.py:1120-1127`), and `run_unit_checks` is invoked without `exhaustive=True` (`pdf_judge.py:843-850`), so `MAX_UNIT_CHECKS = 5` always applies (`unit_judge.py:304`). Impact: the operator who runs `--inspect` on P1068R11 correctly observes only 5/15 LLM unit checks (`00-baseline.md:19-22`); the **design** promises exhaustive routed checks in review mode (`unit_judge.py:283-285`, `constants.py:227`) but the **implementation** silently caps — this is a wiring bug, not evidence that routed design lacks coverage.
- [MED] Review-mode trust gap: sidecar stores full `page_screen` (`pdf_judge.py:439`, `pdf_judge.py:549`) but `inspect_report.py` renders unit coverage only (`inspect_report.py:180-208`) and never surfaces per-page recall/escalation — so the operator sees "LLM checked 5 pages" and not "deterministic screen validated all 15." Impact: `--all-pages` looks like the fix only because audit UI under-reports the coverage that already ran; wiring + reporting would address trust without N× LLM theater.

## False-pass hypothesis
Page 7 recall stays ≥0.90 while a token-preserving semantic corruption survives (e.g., wrong table cell values, near-verbatim wording swap): deterministic recall and the monolith both pass, no `low_recall` signal fires (`source_router.py:212-213`), and no unit check runs if `route_pdf_units` emits nothing for that page (`unit_judge.py:287-288`). The routed design misses the narrow corruption class the prior synthesis already identified as incremental value beyond det+monolith (`research/per-page-judging/SYNTHESIS.md` summary bullet 1, p0957r8 class closed by det but token-preserving swap noted).

## False-fail hypothesis
Naive `--all-pages` LLM unit checks on every page would reintroduce page-1 YAML, TOC removal, and figure-internal-text false fails unless each call inherits the full conversion contract — the traps documented in `research/per-page-judging/SYNTHESIS.md` findings on page-1/TOC/figure. The current design routes LLM depth only after deterministic flags and uses `_CONVERSION_CONTRACT` on escalation (`pdf_judge.py:191`, `pdf_judge.py:396-398`); exhaustive per-page LLM judging without that routing repeats worst-page-wins noise: at n=33 and p=1%/page, document false-review rate is 28.1% (`research/per-page-judging/SYNTHESIS.md` summary bullet 1).

## What would change my mind
A labeled holdout (≥30 golden papers with verified defects) showing the current routed stack (screen + monolith + escalation + exhaustive routed units, once wired) misses ≥10% of defects that exhaustive per-page LLM unit checks catch **with** conversion-contract prompts and calibrated judge TNR — i.e., incremental recall gain that survives the <25% TNR and worst-page-wins math from `05-web.md` Q4 and `research/per-page-judging/SYNTHESIS.md`.
