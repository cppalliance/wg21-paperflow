# 11 - olmocr-bench-methodology

**Verdict:** usable-with-conditions — olmOCR-Bench's fail-closed per-page coverage audit, zero-authoring BaselineTest, and page-scoped deterministic fact units are the strongest open prior art for our `--all-pages` golden-review mode as a deterministic layer (not LLM-per-page judging), but the mechanism assumes single-page corpus PDFs and English-centric charset rules that must be adapted for multi-page WG21 papers.
**Confidence:** high

## Findings

- [CRITICAL] **Every physical page must have at least one test or the benchmark aborts.** After loading JSONL facts, `benchmark.py` walks each PDF with `PdfReader`, iterates `page in range(1, len(pdf_doc.pages)+1)`, and `sys.exit(1)` if no test matches `(test.pdf == pdf and test.page == page)` unless `--force` (`benchmark.py:246-251`). This is a hard coverage certificate, not a sampling heuristic. Impact: directly portable as our planned fail-closed check against `page_count` in `pdf_judge.py` sidecar audit (`00-baseline.md:44`).

- [CRITICAL] **Mandatory BaselineTest is auto-injected, not manually authored for every page.** Before the coverage loop, for each PDF lacking any test with `type == "baseline"`, the harness appends `BaselineTest(id=f"{pdf}_baseline", pdf=pdf, page=1, type="baseline")` (`benchmark.py:241-244`). Default BaselineTest enforces non-empty alphanumeric output, tail n-gram repeat cap (`max_repeats=30`), and optional blank-page `max_length` (`tests.py:484-545`; sample blank fact at `sample_data/blanks.jsonl:1`). The olmOCR paper states every page gets a mandatory baseline test (`05-web.md` olmOCR paper card). Impact: zero-authoring baseline per page is the cheap coverage floor we should copy; whisker already has a partial port as `auto_baseline_checks()` (`facts.py:648-674`) but it is not wired into tapetum_llm per-page review (`whisker/CLAUDE.md:880`).

- [CRITICAL] **Tests are page-bound via `(pdf, page, id)` and evaluated against one page's markdown only.** `BasePDFTest` requires `pdf`, `page`, `id`, `type`, `max_diffs` (`tests.py:84-112`). `process_test` filters candidate files with `_pg{test.page}_` in the basename and passes only that file's text to `test.run(md_content)` (`benchmark.py:93-116`). Missing page output is an immediate fail `(test, False, "Missing MD files")` (`benchmark.py:95-101`). Impact: proves the eval unit is page, not document; maps to slicing candidate markdown or textlayer by page before deterministic checks, replacing monolith LLM prompts (`00-baseline.md:19`).

- [HIGH] **Eight deterministic test classes; no LLM in the scoring loop.** `TestType` enum: `baseline`, `present`, `absent`, `order`, `table`, `math`, `format`, `footnote` (`tests.py:23-34`). Factory dispatches to `TextPresenceTest`, `TextOrderTest`, `FormatTest`, `TableTest`, `BaselineTest`, `MathTest`, `FootnoteTest` (`tests.py:789-802`). Eval uses `rapidfuzz`, `fuzzysearch`, KaTeX rendering, table parsers only (`tests.py:10-17`; `05-web.md` bench/tests.py card). Impact: this is verification prior art via deterministic fact assertions, not LLM-as-judge; supports our review mode running deterministic per-page facts instead of or before scoped LLM escalation.

- [HIGH] **Corpus design collapses multi-page sources into single-page PDFs, which is how "every page covered" scales.** README: bench "operates on single page PDFs directly" (`README.md:12`). Miners extract one page per file (`mine_long_tiny_text.py:218-219` sets `page=1` on extracted PDF); `cleanup_data.py` rewrites tests to `{base}_pg{N}.pdf` with `page=1` (`cleanup_data.py:113-114`). Auto BaselineTest injection uses `page=1` only (`benchmark.py:243`). Impact: olmOCR's per-page guarantee is real but achieved by corpus normalization, not by iterating pages inside one multi-page PDF; our `--all-pages` must inject baseline (and audit) for every page index inside one WG21 paper without splitting PDFs.

- [MED] **LLMs appear only in test mining; human review is a separate gate.** Miners call GPT/Gemini to propose facts (`mine_blank_pages_gpt.py:1-13`, `mine_headers_footers.py:1-13`; `05-web.md` Issue #307). Flask `review_app.py` tracks `checked: null|verified|rejected` per test (`review_app.py:26-34`), but `checked` is stored on `BasePDFTest` (`tests.py:101`) and **not filtered at score time** (no `checked` reference in `benchmark.py`). Impact: portable pattern is "LLM proposes, human verifies, deterministic engine scores"; we should not treat olmOCR's miner pipeline as runtime review, but the deterministic scorer + coverage audit is adoptable for golden PRs where facts come from ideals, not live mining.

- [MED] **Aggregation is macro-average over JSONL strata, majority-over-repeats per test.** Per stochastic repeat, `test.run()` is binary; test passes if `test_avg > 0.5` (`benchmark.py:125-126`). Corpus score is mean of per-JSONL pass rates, not micro-average over all tests (`benchmark.py:44-45`, comment at top). Impact: for single-paper golden review, adopt worst-page or all-pages-must-pass rollup, not unweighted mean that hides one blank page among many passes.

- [LOW] **Load-time schema gates reject malformed facts before any candidate runs.** Empty pdf/id, invalid `max_diffs`, unknown `type` raise `ValidationError` (`tests.py:104-112`); duplicate IDs rejected after parallel load (`tests.py:860-865`). Impact: mirrors whisker fact schema discipline; low lift to require every `page:N` unit has non-empty anchors before review starts.

## False-pass hypothesis

A page with model-collapse garbage that still contains alphanumeric characters and no tail n-gram above 30 repeats passes auto-injected BaselineTest (`tests.py:514-515, 520-526`) even when all substantive prose, tables, and equations are missing. A `present` fact with `max_diffs > 0` can match repeated boilerplate elsewhere on the page via `fuzz.partial_ratio` (`tests.py:168-173`), same class of false pass as monolith LLM "content present" without context.

## False-fail hypothesis

Default `max_diffs=0` fails when `normalize_text` strips formatting the anchor relied on (`tests.py:54-65, 74-78`). BaselineTest `check_disallowed_characters` rejects CJK and emoji (`tests.py:528-543`), which would false-fail legitimate WG21 Unicode identifiers if copied verbatim. Blank-page BaselineTest with `max_length` fails if alt-text alnum exceeds cap unless `max_length_skips_image_alt_tags=True` (`tests.py:503-512`).

## What would change my mind

Discovering that `benchmark.py:246-251` is bypassed in normal runs (e.g., all production JSONL corpora pre-split so the loop never sees multi-page PDFs, and auto BaselineTest is the only test on most pages with no semantic recall check). That would downgrade the mechanism from "full page verification" to "non-empty output audit only." A direct read of the coverage loop and BaselineTest body refutes full semantic recall; the honest ceiling is deterministic sanity + authored facts, which still beats our current 5-page LLM cap.
