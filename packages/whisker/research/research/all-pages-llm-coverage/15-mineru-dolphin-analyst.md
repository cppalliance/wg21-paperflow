# 15 - MinerU / Dolphin analyst

**Verdict:** usable-with-conditions (+ Both repos architecturally iterate every PDF page through a VLM stack for extraction, but neither implements verification coverage, fail-closed page accounting, or per-page LLM-judge semantics suitable to copy wholesale into `--all-pages` golden review.)
**Confidence:** high

## Findings
- [CRITICAL] MinerU VLM and hybrid backends iterate all physical pages in fixed processing windows (default 64), calling `batch_two_step_extract` (or hybrid layout+VLM) once per page image in each window; coverage is structural, not audited post-run. Evidence: `packages/whisker/research/repos/MinerU/mineru/backend/vlm/vlm_analyze.py:462-500`, `packages/whisker/research/repos/MinerU/mineru/backend/hybrid/hybrid_analyze.py:942-1008`. Impact: Confirms extraction pipelines can guarantee every page enters the model stack, but offers no pattern for proving every page was LLM-verified against a candidate golden.
- [HIGH] MinerU has no fail-closed check that `len(middle_json["pdf_info"]) == page_count`; pages are appended by zipping VLM outputs to loaded images with no length assertion, so a short batch response would silently drop trailing pages. Evidence: `packages/whisker/research/repos/MinerU/mineru/backend/vlm/model_output_to_middle_json.py:92-104`. Impact: Our `--all-pages` mode must add an explicit page-count reconciliation sidecar; MinerU's append loop is a counterexample for verification trust.
- [HIGH] MinerU per-page/window failures abort the whole document; there is no per-page retry or empty-page placeholder inside the window loop. HTTP-client backend only gets transient retries (`max_retries=3`). Evidence: `packages/whisker/research/repos/MinerU/mineru/backend/vlm/vlm_analyze.py:462-500`, `packages/whisker/research/repos/MinerU/mineru/backend/vlm/vlm_analyze.py:74-75`. Impact: Extraction fail-fast is opposite of review-mode needs (record per-page judge outcome, continue siblings); adopt iteration shape, not failure semantics.
- [MED] MinerU degrades quality silently at sub-page granularity: invalid VLM blocks are skipped (`continue`), hybrid OCR below `OcrConfidence.min_confidence` writes empty span content, and PDFium rewrite can drop broken source pages with only a warning. Evidence: `packages/whisker/research/repos/MinerU/mineru/backend/vlm/vlm_magic_model.py:60-62`, `packages/whisker/research/repos/MinerU/mineru/backend/hybrid/hybrid_model_output_to_middle_json.py:154-161`, `packages/whisker/research/repos/MinerU/mineru/cli/common.py:219-221`. Impact: Partial/empty pages still look "processed"; golden review must treat missing or empty judged units as failures, not accept silent degradation.
- [MED] MinerU operational accounting is throughput-oriented: tqdm progress to `page_count`, CLI `Processed {completed_pages}/{total_pages}`, per-page `page_idx` in middle JSON, optional span OCR scores in hybrid. No completion certificate or per-page success flag. Evidence: `packages/whisker/research/repos/MinerU/mineru/backend/vlm/vlm_analyze.py:485-500`, `packages/whisker/research/repos/MinerU/mineru/cli/client.py:362`, `packages/whisker/research/repos/MinerU/mineru/backend/vlm/model_output_to_middle_json.py:74`. Impact: Borrow progress and page-index sidecar fields for operator visibility; do not mistake logging for verification coverage.
- [MED] MinerU hybrid `medium` effort can skip VLM text extraction on many block types via `not_extract_list` (text, title, header, footer, etc.), routing them to OCR sidecars instead; every page image still runs layout+VLM layout pass but not every textual region gets a generative VLM call. Evidence: `packages/whisker/research/repos/MinerU/mineru/backend/hybrid/hybrid_analyze.py:73`, `packages/whisker/research/repos/MinerU/mineru/utils/enum_class.py:120-133`, `packages/whisker/research/repos/MinerU/mineru/backend/hybrid/hybrid_analyze.py:984-985`. Impact: Analogous to our routed unit checks; reinforces that "page seen" ≠ "every semantic unit LLM-judged."
- [LOW] MinerU's optional `llm_aided` title optimizer is document-level, retries up to 3 times, and returns `None` on failure without aborting conversion. Evidence: `packages/whisker/research/repos/MinerU/mineru/utils/llm_aided.py:169-217`. Impact: Irrelevant to per-page verification; shows LLM usage is post-hoc enrichment, not coverage gate.
- [HIGH] Dolphin walks every PDF page sequentially: convert all pages to images, then for each page run Stage 1 layout VLM (`model.chat` once) and Stage 2 element-type batched VLM calls (`max_batch_size` default 4). Evidence: `packages/whisker/research/repos/Dolphin/utils/utils.py:69-86`, `packages/whisker/research/repos/Dolphin/demo_page.py:140-157`, `packages/whisker/research/repos/Dolphin/demo_page.py:185-191`, `packages/whisker/research/repos/Dolphin/demo_page.py:288-317`. Impact: Same extraction-coverage lesson as Docling's one-VLM-call-per-page pattern (05-web Q1); not a verification benchmark.
- [HIGH] Dolphin per-element failures inside a page are swallowed (`continue` after print); layout failure falls back to `distorted_page` full-image reparsing; file-level failures skip to the next input file. No per-page retry, no abort-if-page-empty, no cross-check that output page count matches PDF page count beyond `total_pages: len(all_page_results)`. Evidence: `packages/whisker/research/repos/Dolphin/demo_page.py:204-209`, `packages/whisker/research/repos/Dolphin/demo_page.py:262-263`, `packages/whisker/research/repos/Dolphin/demo_page.py:389-390`, `packages/whisker/research/repos/Dolphin/utils/utils.py:110`. Impact: Worse silent-gap behavior than MinerU for verification prior art; our mode must not copy continue-on-element-error semantics.
- [MED] Neither repo evaluates with LLM-as-judge per page; public eval is OmniDocBench-style reference matching (Dolphin README table) or external bench aggregation, aligning with 05-web Q3-Q4 trend toward deterministic exhaustive scoring over LLM judges. Evidence: `packages/whisker/research/repos/Dolphin/README.md:62-104`, 05-web.md Q3 (olmOCR-Bench deterministic per-page tests), Q4 (ParseBench exhaustive rule tests). Impact: User complaint comparing us to extraction pipelines is category error for verification; honest prior art for all-pages review is closer to olmOCR/ParseBench deterministic page coverage than MinerU/Dolphin runtime.

## False-pass hypothesis
MinerU VLM returns structurally valid but empty `page_blocks` for a damaged page; `append_page_blocks_to_middle_json` still appends a `page_info` entry with empty `preproc_blocks` (`model_output_to_middle_json.py:92-104`), and the run completes with progress bar at 100%. An `--all-pages` golden review that only checks page-index presence, not non-empty judged content or recall floor, would pass a blank page as "reviewed."

## False-fail hypothesis
MinerU `convert_pdf_bytes_to_bytes` skips PDFium-broken source pages with a warning (`common.py:219-221`) while processing the remainder; our reviewer compares candidate markdown against the original 15-page PDF and flags 10 pages as missing from output. That is a true source defect, but without sidecar note of skipped source pages the operator may blame the golden candidate rather than the PDF ingest path.

## What would change my mind
A post-run fail-closed guard in either clone (e.g., assert `len(pdf_info) == source_page_count` and emit per-page `{page_idx, vlm_status, empty_output}` audit records that block export on mismatch or any `failed` page) would upgrade the verdict to `usable` for verification-mode prior art.
