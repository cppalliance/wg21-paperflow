# 12 - docling-coverage-analyst

**Verdict:** usable-with-conditions (+ Docling's page-coverage and confidence machinery is strong prior art for extraction QA and audit sidecars, but it is not an LLM-per-page verification comparator for our golden-review mode; adopt partial-success semantics and per-page score maps, not the "docling runs an LLM on every page" framing.)
**Confidence:** high

## Findings
- [CRITICAL] Default PDF conversion uses `StandardPdfPipeline`, not a generative LLM: OCR + layout + table-structure neural stages only (`docling/document_converter.py:200-201`, `docling/pipeline/standard_pdf_pipeline.py:590-614`). Evidence: `PdfFormatOption.pipeline_cls = StandardPdfPipeline`. Impact: the user's belief that "docling runs an LLM over all PDF pages" is false for the default path; our extraction-vs-verification comparison must not treat docling default as exhaustive LLM coverage.
- [CRITICAL] Full-page VLM/LLM inference exists only on the opt-in `VlmPipeline`: each page image is sent through `VlmConvertModel` (batched, one engine call per page in the batch) with the model-spec prompt (`docling/pipeline/vlm_pipeline.py:83-130`, `docling/models/stages/vlm_convert/vlm_convert_model.py:130-213`). Evidence: `PaginatedPipeline._build_document` iterates all pages in `page_range`, then `_apply_on_pages` runs `build_pipe` models. Impact: docling's "all pages seen by a VLM" claim holds only when the operator explicitly selects VLM pipeline (https://docling-project.github.io/docling/examples/agent_skill/docling-document-intelligence/pipelines/); it does not describe default PDF behavior.
- [HIGH] Page iteration is explicit and bounded by `page_range`, not probabilistic sampling: standard pipeline builds `expected_page_nos` from `limits.page_range` and enqueues every listed page through a producer thread (`docling/pipeline/standard_pdf_pipeline.py:755-792`, `docling/pipeline/base_pipeline.py:256-266`). Evidence: `range(max(1, start_page), min(page_count, end_page)+1)`. Impact: within configured range, coverage is architectural; outside it, pages are intentionally excluded (policy, not silent random skip).
- [HIGH] Pages are not silently dropped on per-page failure: failed pages become `ErrorItem` records with `page_no`, set `ConversionStatus.PARTIAL_SUCCESS`, and (standard pipeline) placeholder `PageItem` entries preserve numbering in output (`docling/datamodel/base_models.py:85-91,288-296`, `docling/pipeline/standard_pdf_pipeline.py:940-984,1090-1134`). Evidence: `_integrate_results` and `_add_failed_pages_to_document`. Impact: adoptable pattern for our `--all-pages` audit sidecar: record every physical page as checked, failed, or skipped-with-reason.
- [HIGH] Timeout is the main silent-coverage gap: both pipelines break on `document_timeout`, mark remaining pages failed or filter uninitialized pages (`page.size is None`), and downgrade to `PARTIAL_SUCCESS` (`docling/pipeline/base_pipeline.py:294-339`, `docling/pipeline/standard_pdf_pipeline.py:847-925`). Evidence: `FailureCategory.TIMEOUT` errors with processed/total counts. Impact: docling does not guarantee all pages were processed if timeout fires; our review mode must fail-closed on incomplete page sets, not accept partial timeout success.
- [MED] Confidence scores are post-conversion deterministic heuristics, not LLM verification: per-page `layout_score`, `ocr_score`, `parse_score` are computed from layout clusters, OCR cells, and PDF text-quality regex heuristics (`docling/models/stages/layout/layout_model.py:233-239`, `docling/models/stages/page_preprocessing/page_preprocessing_model.py:75-89`); doc-level aggregation uses nanmean plus worst-10% quantile for `parse_score` (`docling/pipeline/standard_pdf_pipeline.py:1068-1087`). Evidence: https://docling-project.github.io/docling/concepts/confidence_scores/. Impact: useful as a cheap per-page screen before scoped LLM escalation (analogous to our recall floor), not as golden-PR equivalence judging.
- [MED] Grades (`POOR`/`FAIR`/`GOOD`/`EXCELLENT`) derive from score thresholds but no in-repo auto-routing to human review: grades are computed fields on `PageConfidenceScores`/`ConfidenceReport` (`docling/datamodel/base_models.py:557-577,609-674`); HTTP API exposes document-level `ConfidenceScores` only, with per-page breakdown deferred (`docling/datamodel/service/responses.py:27-61`). Impact: docling documents the review-routing intent in docs but leaves enforcement to the operator; our `--all-pages` mode must wire coverage checks in CLI, not rely on scores alone.
- [LOW] Optional VLM enrichment on standard pipeline is element-scoped, not page-scoped: picture description, chart extraction, and code/formula VLM run in `enrichment_pipe` over filtered document elements (`docling/pipeline/base_pipeline.py:111-133`, `docling/pipeline/standard_pdf_pipeline.py:621-641`, `docling/models/stages/code_formula/code_formula_vlm_model.py:37-48`). Evidence: `BaseItemAndImageEnrichmentModel`, `elements_batch_size`. Impact: even with enrichment flags on, a text-only page may receive zero VLM calls, mirroring marker's block-selective pattern.

## False-pass hypothesis
A 20-page PDF hits `document_timeout` after page 8: docling returns `PARTIAL_SUCCESS` with markdown containing placeholder page slots for failed pages, and document-level `mean_grade` may still read FAIR from the eight processed pages (`docling/pipeline/standard_pdf_pipeline.py:966-984`, `docling/datamodel/base_models.py:650-661`). An operator who checks only export text and aggregate grade, not `errors[]` or `confidence.pages`, would accept a document where 12 pages never completed inference.

## False-fail hypothesis
A clean digital PDF page with three `/G` glyph artifacts in one footnote cell gets `parse_score` from the 10th-percentile of cell scores (`docling/models/stages/page_preprocessing/page_preprocessing_model.py:85-89`, `rate_text_quality` returns 0.0 for `/G` at line 126-131), pulling doc-level `parse_score` (worst-10% across pages) below 0.5 and `low_grade` to POOR even when layout/OCR are excellent (`docling/pipeline/standard_pdf_pipeline.py:1073-1077`).

## What would change my mind
Evidence that docling's HTTP service or CLI rejects or quarantines any conversion where `len(confidence.pages) != input.page_count` or any expected page lacks a non-NaN score entry, with no `TIMEOUT`/`INFERENCE_FAILURE` escape hatch. Current code records gaps but still emits `PARTIAL_SUCCESS` and export artifacts.
