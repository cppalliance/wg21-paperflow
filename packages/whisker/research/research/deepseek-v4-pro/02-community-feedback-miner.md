# 02 - Community-Feedback-Miner

**Verdict:** usable-with-conditions — Community reports show non-trivial structured-output fallthrough, evidence fabrication in agent loops, and vLLM serving correctness traps that wg21-paperflow mitigates partially via schema-in-prompt but cannot fully ignore.
**Confidence:** medium

## Findings

- [CRITICAL] DeepSeek-V4-Pro intermittently writes tool invocations as plain text in `content` instead of structured `tool_calls` (~11% in a 19-turn API session with ~40 tools; OpenClaw users report ~10–35% with large schemas). Evidence: [deepseek-ai/DeepSeek-V3#1244](https://github.com/deepseek-ai/DeepSeek-V3/issues/1244) (reproduction table: 15/19 correct, 2/19 bug, 2/19 expected text). Impact: Direct analog to tapetum_llm's schema-in-prompt path — the model sometimes "thinks aloud" in natural language, then appends JSON-like payloads in free text rather than committing to the structured channel. Backend extraction may succeed sometimes, but finish_reason and field routing are unreliable.

- [CRITICAL] vLLM DSML tool parser leaks malformed/partial DSML markers into `content` under `tool_choice=auto` + streaming, and leaked turns contaminate later conversation state. Evidence: [vllm-project/vllm#40801](https://github.com/vllm-project/vllm/issues/40801) (community note: parser only extracts well-formed `<｜DSML｜tool_calls>` blocks; partial markers from NVFP4-quantized generation fail extraction). Impact: Our RunPod stack uses vLLM with thinking + tools enabled. Even though tapetum_llm avoids native tool calling, DSML leakage patterns suggest the model can emit markup-like artifacts inside free-text fields, polluting markdown fidelity review.

- [HIGH] Multi-turn `reasoning_content` replay contract breaks most agent frameworks on V4 (inverted vs R1). Omitting `reasoning_content` on assistant messages after tool calls yields HTTP 400: "The reasoning_content in the thinking mode must be passed back to the API." Evidence: [openclaw/openclaw#71455](https://github.com/openclaw/openclaw/issues/71455), [BerriAI/litellm#26395](https://github.com/BerriAI/litellm/issues/26395), [anomalyco/opencode#24190](https://github.com/anomalyco/opencode/issues/24190), [DeepSeek thinking mode docs](https://api-docs.deepseek.com/guides/thinking_mode). Impact: Confirms V4 is permanently in thinking mode with strict replay semantics. Single-turn tapetum triage avoids this, but any future multi-turn adjudication or tool loop on the same session inherits a brittle contract.

- [HIGH] MTP speculative decoding + reasoning + structured output can miss `` boundary, leaving JSON grammar unenforced; post-reasoning markdown fence tokens can be accepted in the same speculative batch. Evidence: [vllm-project/vllm#34650](https://github.com/vllm-project/vllm/issues/34650) (223 tokens generated, both `reasoning_content` and `content` empty); [vllm-project/vllm#43388](https://github.com/vllm-project/vllm/issues/43388) (regression test gap for `[reasoning_end_token, markdown_fence]` in same batch). Impact: Baseline cites #41132 (JSON in reasoning field); these are distinct, still-open failure modes when MTP/spec-decode is enabled on the serving pod. Markdown fences breaking JSON extraction directly threaten Adjudication schema compliance.

- [HIGH] FlashInfer MoE autotune can silently corrupt V4-Pro outputs (GPQA eval failures, garbage tokens) until disabled or patched. Evidence: [flashinfer-ai/flashinfer#3197](https://github.com/flashinfer-ai/flashinfer/issues/3197) ("without `--no-enable-flashinfer-autotune` it won't work"); [vllm-project/vllm#41524](https://github.com/vllm-project/vllm/pull/41524); NVIDIA Dynamo recipe recommends `--no-enable-flashinfer-autotune` because autotuner "currently produces tunings that regress GSM8k accuracy." Impact: Inference-stack correctness bug, not model weights. Can cause confident wrong adjudications on otherwise identical prompts if RunPod image/autotune state differs between runs — determinism risk (D1-D11 adjacent).

- [HIGH] Community agent users report V4 fabricating tool arguments, file paths, and function payloads under uncertainty (consistent with AA-Omniscience abstention failure, but observed in production agent loops). Evidence: [techjacksolutions.com DeepSeek V4 agentic guide](https://techjacksolutions.com/ai-tools/deepseek/deepseek-v4-coding-and-agentic-workflows/) ("fabricate tool inputs, file paths, or arguments and then act on them"); OpenClaw comment on [#1244](https://github.com/deepseek-ai/DeepSeek-V3/issues/1244) ("thinking aloud then appending" pattern). Impact: Maps directly to tapetum_llm `evidence_spans` — model may produce plausible but non-verbatim quotes. `ground_spans` catches these, but high ungrounded-drop rate wastes the advisory call and inflates false "review" demotions.

- [MED] Held-out agentic benchmarks show large gaps vs public SWE-bench Verified scores; community evaluators attribute Pro variant instability to custom harness + provider issues. Evidence: [CodingFleet SWE-bench Pro table](https://codingfleet.com/blog/swe-bench-pro-explained-the-new-standard-for-ai-coding-benchmarks-2026/) (V4-Pro: 80.6% Verified → 55.4% Pro, −25.2 pp); [HN discussion on AA eval](https://news.ycombinator.com/item?id=47910388) ("Pro variant struggling with our custom harness in agentic tasks"); NIST CAISI [PortBench 44% vs frontier 78%](https://www.nist.gov/news-events/news/2026/05/caisi-evaluation-deepseek-v4-pro). Impact: Public coding parity numbers overstate real multi-step document/agent reliability relevant to conversion fidelity review.

- [MED] Practical long-context cliff reported below advertised 1M window: community testing on production codebases cites degradation past ~300K tokens and recommends chunking. Evidence: [bittide aggregator citing r/LocalLLaMA](https://bittide.aicompass.dev/article/de1691eb-b72e-47ee-91b9-c7c43549f42e) ("optimal performance at 150–250k tokens, with degradation past 300k"); [aimadetools MRCR table](https://www.aimadetools.com/blog/deepseek-v4-million-token-context-guide/) (66% MRCR at 1M). Impact: Baseline notes random-position Lightning Indexer misses; community adds a practical operating band well below our 393K configured window. H2-chunking at 500K chars (~125K–187K tokens) is prudent, but within-chunk misses remain possible near chunk upper bound.

- [LOW] No recurring community reports specifically about markdown table parsing, code-fence integrity judgment, or LaTeX/math fidelity on V4-Pro were found in the searched channels (GitHub, Reddit mirrors, HuggingFace discussions, agent blogs). Impact: Absence of signal is not evidence of capability — these axes are under-reported in community channels, not confirmed clean.

## False-pass hypothesis

A tapetum triage call on a paper with a subtly broken pipe table returns `verdict: pass` with `confidence: 0.72` and an `evidence_span` that paraphrases table cell text ("the table shows X=3") rather than quoting a verbatim substring — structurally valid Adjudication JSON that passes schema extraction but fails grounding only if `ground_spans` fuzzy floor catches the paraphrase; if the paraphrase accidentally matches a nearby substring, the false pass stands.

## False-fail hypothesis

A correct triage finding on code-fence integrity cites a span with U+0120/U+010A BPE artifacts (HF Transformers v5 regression, per 00-baseline §2) that differs by invisible characters from the markdown source — grounding rejects the span, demotes to review, and wastes a valid advisory signal.

## What would change my mind

Thirty-day production metrics from our RunPod `vllm_thinking` lane: ≥98% Adjudication JSON parse success on first attempt (no retry), ≤3% ungrounded evidence span drop rate on real WG21 papers, and stable verdict distribution across pod restarts — would downgrade these community reports from blocking risks to operational noise.
