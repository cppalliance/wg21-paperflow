## Personas with systematic provenance problems (if any)

None. Across ~28 sampled findings spanning 17 personas (01, 02, 03, 05-maint, 06, 07, 08, 09, 11, 12, 13, 17, 18, 19, 20, 21, 22), every code anchor into the pinned clone resolved and supported the claim, including exact-quote docstrings (SSRF text in `extraction.py:175-179`, "Debug logging remains enabled..." at `extraction.py:149-151`, empty-string padding at `gemini_batch.py:650-651`, `FormatModeSchema` "doesn't enforce structure" at `core/schema.py:121-124`) and precise constants (`resolver.py:57-58`, `_normalize_token` `lru_cache(10000)` at `1275-1281`). No fabricated anchors, no stale line numbers of consequence. Only two trivial defects: one **MISQUOTED** anchor in a persona-21 false-fail aside (`openai.py:186` labeled "strict provider schemas" when it is the JSON system-message string) and one off-by-one in persona-22 (`^deepseek-ai/` is line 58, cited within a "42-43,57" grouping). Both are cosmetic and neither backs a ranked CRITICAL/HIGH finding.

Baseline consistency: no persona contradicts a *verified* baseline fact. The one recurring divergence is corrective, not contradictory: `00-baseline.md` §3/DQ1 frames the serial `Annotator` default (`batch_length=1`, `annotation.py:214`) as "the default," while personas 03 (MED), 06, 08, 18 (LOW), and 22 correctly point out that the public `extract()` API ships `batch_length=10`/`max_workers=10` (`extraction.py:57-58`). Both anchors are true; personas 03 and 18 explicitly flag the baseline as *understating* default parallelism. This is the personas being more precise than the baseline, and it is itself anchored, so it strengthens rather than undermines provenance.

Web-anchored claims (`05-web.md`) were used consistently as issue/PR references (e.g. #50, #245, #260, #287, #334, #414, PR #442/#444/#480) and matched the code state at the pinned SHA (e.g. no `guided_json`/`vllm` hits; LCS DP present alongside surviving legacy difflib path). URLs were not re-fetched here, but every code-side counterpart the personas paired with a web card was verified in-tree.

## Net assessment (can synthesis trust the citations?)

Yes. The persona corpus is exceptionally well-grounded: of ~28 sampled findings (heavily weighted to CRITICAL/HIGH), 27 have fully valid, verbatim-accurate anchors and the sole defect is a mislabeled line in a non-ranked false-fail aside. The high-stakes technical claims that synthesis will lean on, the parallel-inference defaults and index-ordered yield, the absence of schema-retry and vLLM guided decoding, the three-tier aligner with 0.75/0.333 gates, the SSRF and plugin-RCE surfaces, the mandatory Google Cloud dependency, the README overselling "exact location", all resolve exactly as cited. Personas also correctly self-correct the one baseline imprecision (public `extract()` parallelism defaults) with their own anchors rather than inventing conflict. Synthesis can treat these citations as trustworthy without re-verification, with the only housekeeping note being to prefer `extraction.py:57-58` over the baseline's `annotation.py:214` when describing shipped default concurrency.
