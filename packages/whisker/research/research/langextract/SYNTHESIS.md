# langextract - Research Synthesis

**Verdict band:** usable-with-conditions   **Confidence:** high
**Decision vs our codebase:** adopt-partially

The split is by unit of adoption. As a dependency or wholesale library, langextract is garbage-tier for us (cloud SDKs hard-required, no working self-hosted schema path, worsens our dominant JSON-failure mode, injection-blind, unlandable under the read-only `pipeline`/`paperstore` constraint). As the source of ONE well-tested algorithm, it is usable-with-conditions: port the monotonic exact-occurrence DP + graded `char_interval`/`AlignmentStatus` return into `packages/whisker` only, keep our 0.90 `partial_ratio` floor, reject the library as a dep.

## Summary
- The three-tier aligner is real and exactly where the personas said: monotonic exact-occurrence Pareto-frontier DP (`resolver.py:1113-1243`) -> difflib exact/lesser (`resolver.py:962-1019`) -> LCS-DP fuzzy fallback (`resolver.py:1287-1363`), with graded status enum (`core/data.py:43-47`, four members incl. `MATCH_GREATER`, correcting `00-baseline.md:15`) and dual gates `_FUZZY_ALIGNMENT_MIN_THRESHOLD = 0.75` / `_FUZZY_ALIGNMENT_MIN_DENSITY = 1/3` (`resolver.py:57-58`). Meta-A/B/D all CONFIRMED verbatim.
- **The load-bearing defect is self-blessed** (Meta-B): Tier-3 LCS accepts gapped composite spans at the density floor, and langextract's own oracle test pins the wrong answer as correct: a 3-token extraction grounds to a 9-token span with six intervening unrelated tokens, `3/9 == 0.333 == floor` (`tests/fuzzy_alignment_cases_test.py:213-223`, gate `resolver.py:1403-1404`). Any `char_interval` from Tier 3 is untrustworthy provenance without a post-alignment substring recheck.
- Cloud-first and sovereignty-hostile (Meta-C CONFIRMED): `google-genai` + `google-cloud-storage` are UNCONDITIONAL core deps (`pyproject.toml:35-36`), default model is live Gemini (`extraction.py:49`, `model_id="gemini-3.5-flash"`), and there is **no vLLM/guided-decoding path anywhere** (grep 0 hits for `guided_json|guided_decoding|vllm|extra_body`, Meta-A CONFIRMED). Self-hosted structured output is Ollama JSON-mode only, format-not-structure (`core/schema.py:118-149`); OpenAI-compatible self-hosted parse success is <20% per web Issue #414.
- Fail-soft defaults collide head-on with our Fidelity rule (Meta-C/D CONFIRMED): `extract()` forces `suppress_parse_errors=True` (`extraction.py:365`) so failed chunks are silently dropped (`resolver.py:309-321`, log + `return []`) with no `partial` flag; there is NO schema-noncompliance retry (transient-HTTP retry only, `gemini.py:351-391`); parallel `infer()` is all-or-nothing (`gemini.py:490-497`).
- Engineering debt is real but bounded to code we would not vendor (Meta-C): 1213-LOC god-module `resolver.py`, copy-pasted-and-already-drifted provider `infer()` loops under `pylint disable=duplicate-code` (`gemini.py:475-509` vs `openai.py:355-389`, drift at `openai.py:373-374`), frozen `_compat` debt, six dead runtime deps. Offsetting positive the personas missed: enforced `import-linter` layering contracts (`pyproject.toml:137-162`).
- Citations are trustworthy (Meta-D): 27/28 sampled anchors verbatim-accurate, one cosmetic MISQUOTE in a non-ranked persona-21 aside. Metrics trustworthy (Meta-A): 34 target-side numbers reproduced EXACTLY. Web trustworthy: repo active (v1.6.0 tagged 2026-07-02, ~37K stars, not archived).

## Bugs / edge-cases in OUR code (surfaced by the comparison)
- `packages/whisker/src/whisker/tapetum_llm/grounding.py:49` (`norm_quote in norm_md`): occurrence-blind. A quote that appears N times in the paper always grounds to the FIRST substring hit and returns no position at all. Scenario: recurring normative wording, a repeated section title, or "This paper proposes" mentioned in multiple sections all collapse to occurrence #1; a reviewer following the `--inspect` pointer lands on the wrong instance. Fix direction (whisker-local): the ported monotonic DP disambiguates repeated mentions to successive non-overlapping positions in model-output order, and returns the actual `char_interval`.
- `packages/whisker/src/whisker/tapetum_llm/grounding.py:56` returns only `(grounded_spans, dropped_count)`, no location. Scenario: the `--inspect` artifact can say "kept 4, dropped 1" but never "exact at chars 4120-4187", so a human auditing a fidelity finding cannot jump to the evidence. Fix direction: return `(quote, char_interval, AlignmentStatus)` per span.
- `grounding.py:51` (`partial_ratio(norm_quote, norm_md) >= 0.90`, `constants.py:50`): document-level fuzzy with no density/coverage notion. Scenario: a short quote whose tokens are scattered across the whole document can clear `partial_ratio` without being a contiguous span. Fix direction: keep the 0.90 floor as the fuzzy tier (do NOT import langextract's looser 0.75/0.333), but add a one-line post-alignment guard on any EXACT span: reject if `markdown[char_interval]` != quote after normalization. This is the mitigation that neutralizes the langextract Tier-3 CRITICAL for our port.

## Top portable detail
Re-implement (port, do not import) the **monotonic exact-occurrence DP + graded span return** as a span-emitting upgrade to `ground_spans`, ~150 LOC landing entirely in `packages/whisker/src/whisker/tapetum_llm/grounding.py`. Anchor: `resolver.py:1113-1243`.

- Tokenize normalized quote and normalized markdown; run the `_select_monotonic_matches` equivalent so repeated evidence phrases map to successive non-overlapping positions in model-output order instead of always the first substring hit (`resolver.py:1113-1185`).
- Return `(quote, char_interval, AlignmentStatus)` per span so `--inspect` reports "exact at chars X-Y" instead of a bare kept/dropped count (`resolver.py:1235-1241`).
- Keep `EVIDENCE_FUZZY_FLOOR = 0.90` `partial_ratio` (`constants.py:50`) as the fuzzy fallback; do NOT port the 0.75/0.333 LCS gate (wrong-span CRITICAL, uncalibrated for us, CJK-fragile).
- Add the post-alignment guard: reject any exact span whose `markdown[char_interval]` != quote after normalization.
- Optional +7 LOC: `_normalize_token` plural stem before the exact pass (`resolver.py:1275-1281`).

No new dependency, no cloud SDK, no change to `pipeline`/`paperstore`. Attribution obligation only: retain "Copyright Google LLC" / add a `THIRD_PARTY_NOTICES` entry (Apache-2.0 permits the port; Meta-E).

## Flip conditions
- **Down to reject:** if the ported DP cannot be made deterministic/serial and self-hosted-clean inside `packages/whisker` without touching the read-only packages; or if a labeled tapetum corpus shows the exact-DP + 0.90-floor combination underperforms the current substring+partial_ratio path on precision.
- **Up to usable (library, not just algorithm):** if langextract ships a first-class vLLM `guided_json`/guided-decoding path AND moves the Google Cloud SDKs behind an optional extra AND drops `suppress_parse_errors=True` from the `extract()` default (or adds a `partial` flag). The open community-plugin state (Issue #236, draft PR #393 closed unmerged) and the <20% self-hosted parse rate (Issue #414) are the current blockers; a merged built-in vLLM guided path would be the single strongest up-signal.
- **Confidence stays high** as long as the pinned SHA holds: 34 metrics reproduced exactly, 27/28 anchors verbatim, and both self-inflicted risks (the density-floor oracle test, the cloud-dep default) are code-anchored, not inferred.
