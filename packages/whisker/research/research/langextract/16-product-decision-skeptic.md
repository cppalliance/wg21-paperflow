# 16 - Product-Decision-Skeptic

**Verdict:** garbage — none of the three DQ4 adoption candidates address tapetum's measured pain (9/200 JSON hard failures, ~1.5–2 h serial batch runtime); importing langextract would add ~10,715 LOC, cloud SDK deps, and weaker schema recovery than we already ship.
**Confidence:** high

## Findings
- [CRITICAL] Langextract has no schema-noncompliance retry; parse failures raise or drop to `[]` (`resolver.py:309-321`), while our 9/200 batch failures are `"Raw JSON completion failed after 2 attempt(s)"` fixed by raising `_RAW_JSON_MAX_ATTEMPTS` to 3 (`model_backends.py:76-85`, `llm-stack/00-baseline.md:49`). vLLM self-hosted success on langextract stays below 20% per maintainer guidance (`05-web.md` Issue #414). Impact: adopting their structured-output path would **worsen** our dominant failure mode, not fix it.
- [HIGH] The index-keyed ordered-concurrency pattern is already in our stack and unused by tapetum, not missing. `gather_concurrent` preserves index order via `(index, result)` sort (`runner.py:133-162`); langextract mirrors this with pre-sized `results[index]` (`gemini.py:487-504`). Tapetum triage still runs a serial `for` loop (`adjudicate.py:187-191`); grep shows zero `gather_concurrent` call sites under `tapetum_llm/`. Impact: copying langextract buys nothing; wiring our existing primitive is a ~20-line local change with no new dependency.
- [HIGH] Char-span `AlignmentStatus` grounding solves a problem tapetum does not have. Our lane verifies quote presence (substring or `partial_ratio >= 0.90`, `grounding.py:49-52`, `constants.py:50`) and drops ungrounded spans; 9/197 sidecars exercised a drop (`llm-stack/00-baseline.md:47`), but the inspect artifact surfaces quote strings, not offsets. Langextract's 1213-LOC resolver adds LCS DP O(n·m²) alignment (`00-baseline.md:36`, `resolver.py:1287-1363`) with open CJK wrong-span bugs (`05-web.md` Issue #334). Impact: large complexity import for trace prettiness, zero effect on JSON failures or the 1.5–2 h runtime wall.
- [MED] First-pass-wins overlap merge is the wrong fold for adjudication. Langextract merges entity extractions by overlapping `char_interval` with earlier-pass wins (`annotation.py:46-84`); overlaps require both intervals non-None (`annotation.py:99-100`). Tapetum already folds chunked triage with severity-aware worst-axis, min confidence, and deduped evidence union (`chunking.py:154-220`), which is what rescued P3941R4 (`tapetum-sighting-run-2026-07-01.md:41-45`). Impact: swapping merges would discard worse-axis signal from later chunks.
- [MED] Dependency surface is cloud-first and conflicts with model sovereignty. Core deps include `google-genai` and `google-cloud-storage` (`pyproject.toml:35-36`); no vLLM guided path (`00-baseline.md:35`, `05-web.md` Issues #236/#414). Our mandate is open-weight self-hosted (`CLAUDE.md` model sovereignty). Impact: even cherry-picking resolver code drags cloud assumptions; full package import is disqualifying.
- [MED] Langextract lacks prompt-injection defense we already require. Source text enters prompts without delimiter wrapping (`00-baseline.md:37`, `annotation.py:360-375`); tapetum uses `ctx.inject_untrusted` (`adjudicate.py:327,348`). Impact: adopting their prompt assembly would regress a non-negotiable invariant for marginal extraction UX.
- [LOW] Their default parallel defaults (`max_workers=10`, `gemini.py:129`) correlate with 429 storms (`05-web.md` Issue #50), while our serial 1.5–2 h runtime (`llm-stack/00-baseline.md:49`) needs bounded, per-package opt-in (`adjudicate.py:409`, D11), not their cloud thread-pool defaults. Impact: copying their concurrency knobs without our semaphore discipline risks throughput gains traded for MoE routing variance on `alliance-pod` (`MODELS.md:69`).

## False-pass hypothesis
A short generic evidence quote (e.g. `"the following"`) passes `partial_ratio >= 0.90` against the whole normalized markdown haystack (`grounding.py:51-52`), grounding a fabricated span; char-span alignment would not fix this because tapetum never emits or consumes offsets today.

## False-fail hypothesis
A valid math/table defect whose quote normalizes away under `normalized_text` (LaTeX folded, punctuation stripped, `grounding.py:39-44` via `whisker.metrics.normalized_text`) could ground a corrupted span; langextract's token resolver would face the same normalization mismatch if ported without re-tuning thresholds (0.75/0.333 vs our 0.90, `00-baseline.md:47`).

## What would change my mind
A measured A/B on the 9 failing PIDs (N5044, P2728R11/R12, P3725R2, P3842R1 per `tapetum-sighting-run-2026-07-01.md:52-56`) showing langextract's provider+resolver path achieves higher parse success than our `_RAW_JSON_MAX_ATTEMPTS=3` loop on the same `alliance-pod` backend — none of the baseline or web evidence suggests that.
