# 14 - False-Pass-Hunter

**Verdict:** usable-with-conditions — a page-image VLM lane can catch semantic defects the deterministic lane misses (table cell swaps, code-garble), but at olmocr-default 1288 px and page-only aggregation it will falsely accept the exact failure modes we need it for; it must pair image+markdown, raise DPI for code/table crops, and gate on structured findings, not holistic "looks fine."
**Confidence:** high

## Findings

- [CRITICAL] **At olmocr's default 1288 px longest edge, 9 pt C++ code resolves to ~7.6–8.3 px per monospace character and ~3.4 px for a backtick — below reliable glyph discrimination after VLM patch downsampling.** Evidence: scale `target_longest_image_dim * 72 / longest_dim` (`renderpdf.py:52`); default `target_longest_image_dim=1288` (`pipeline.py:1229`); runtime on A4 (842 pt height): **110.14 DPI**, **910×1288 px**, **~8.3 px/char** at 9 pt mono, **~3.4 px** for a thin backtick; Qwen2.5-VL uses **28×28** patches (`05-web.md` Q3 pixel-control guide). HQH reports OCR as the hardest VLM category with **~60% average hallucination** across models (`05-web.md` Q4 HQH card). Impact: a dropped `` ` `` around `` `std::vector<T>` `` or a mangled `` `<typename T>` `` template argument preserves the word multiset (det `unigram_coverage` stays ~1.0, `score.py:156-160`) while the page image is too coarse for the judge to prove the punctuation error; the VLM lane returns **pass** on the defect class tapetum was built to catch (`CLAUDE.md` tapetum_llm: "code garbling that survives order-blind unigram_coverage").

- [CRITICAL] **Table row/column swaps are invisible to the deterministic hard gate and poorly served by page-image QA at benchmarked accuracy.** Evidence: `_decide` hard-fails only structural gates + `unigram_coverage < 0.85` (`score.py:152-160`); `ref_teds`/`ref_mhs` never flag (`score.py:145-147`); Opus redteam reproduced **96% (24/25)** passing table-papers surviving adversarial row-swap as `pass` (`QA-RELIABILITY-VERDICT.md:79`). MTabVQA: **GPT-4.1 37.0% EM / 61.7% F1** zero-shot on rendered table images (`05-web.md` Q4 MTabVQA card). Impact: a WG21 feature-comparison table with two body rows swapped (same tokens, wrong semantics) is the canonical false-pass for det; a VLM judging whole pages at ~110 DPI inherits the same table-image weakness and will **accept** swaps det already missed — zero marginal value on ~44% table-bearing papers unless the lane uses table crops + explicit cell-neighbor checks.

- [HIGH] **Markdown front matter and mailing-derived metadata are not grounded in page images, so a VLM-on-PDF lane cannot verify them and will accept silent corruption there.** Evidence: planned output includes YAML fields `intent`, `audience`, `reply-to` not rendered on the PDF body (`CLAUDE.md` front matter, `00-baseline.md:59-63`); LLM lane today loads markdown only, no PDF (`adjudicate.py:175-199`); `normalized_text` does not strip YAML keys (`metrics.py:118-126`, persona 06). Impact: wrong `document:` id, corrupted `reply-to` email, or swapped `audience:` values pass any judge that compares page raster to body prose only; det's `ref_nid` can surface some metadata drift as advisory review (`score.py:175-178`) but a VLM lane scoped to page images **adds no coverage** for front-matter defects and may falsely certify body fidelity while metadata is wrong.

- [HIGH] **Page-by-page VLM judging breaks cross-page dependencies that WG21 papers use routinely.** Evidence: olmocr processes each page independently then aggregates (`pipeline.py:548-554`, `00-baseline.md:18`); M3DocDep multi-page dependency chunking improves QA ANLS **+4.5 to +15.3** points vs naive chunking (`05-web.md` Q4 M3DocDep card). Impact: footnotes on page *N* referencing text on page *N+1*, table continuations, and "see below" straw-poll rows split across pages each look locally consistent; per-page VLM QA **accepts** globally broken conversions det also does not localize (region flags are soft only, `score.py:164-166`).

- [MED] **DOCR-Inspector's 28-type taxonomy covers element-level parsing errors but maps incompletely onto our markdown-QA task and measured table detection remains weak.** Evidence: taxonomy includes text (17), table (6, e.g. `cell_content_error`, `missing_row_or_column`), equation (5) types with Chain-of-Checklist reasoning (`05-web.md` Q5 DOCR-Inspector card, `https://arxiv.org/abs/2512.10619`); DOCR-Inspector operates on **element crops + parsed output**, not full-page markdown (`05-web.md` Q5). Gaps for our plan: no YAML front-matter type, no cross-page footnote link type, no fenced-code/backtick axis, no WG21 mailing-field class; table-image QA benchmarks (MTabVQA **37% EM**) sit far below DOCR's text-case scores. Impact: adopting the taxonomy verbatim gives checklist coverage on paper but **does not eliminate** the false-pass classes above; without element-level table/code crops the taxonomy cannot be applied faithfully.

- [MED] **A VLM lane that only re-checks "are the words on the page present in the markdown?" duplicates det and catches nothing new.** Evidence: hard gate is `unigram_coverage` token-set recall against source PDF/HTML text (`score.py:130-133,156-160`, `constants.py:37-38`); tapetum_llm already targets "token-preserving semantic corruption" (`CLAUDE.md` tapetum_llm section). coarse/extraction_qa and DOCR-Inspector both send **image + parsed text together** (`05-web.md` Q5 coarse + DOCR cards). Impact: prompts like "does this page match the markdown?" collapse to the same multiset test det runs cheaper and deterministically; marginal value requires **structured axes** (tables, code fences, math) on **targeted crops**, not holistic page pass/fail.

- [LOW] **Default raster stack inherits olmOCR-class parsing accuracy, not inspection accuracy — ~15–18% residual error on the conversion task itself.** Evidence: olmOCR-Bench **82.4%** overall, tables **84.9%** (`05-web.md` Q1 olmOCR card); olmocr is finetuned for PDF→markdown conversion, not open-ended QA (`00-baseline.md:13-19`). Impact: reusing the same 1288 px + Qwen2.5-VL-7B stack for judging risks **accepting defects the conversion model family already systematically misses**; QA model must be task-finetuned (DOCR-Inspector path) or prompted with checklists + mandatory evidence, not a generic pass/fail.

## False-pass hypothesis

**P4182R0-class straw-poll table, adversarially edited:** swap two numeric cells in a 6×4 feature matrix (all cell words still present → `unigram_coverage` ≈ 1.0, `score.py:156-160` passes) and drop one backtick in a 9 pt `\verbatim` line so `` `std::expected<T,E>` `` renders as `` std::expected<T,E> ``. Deterministic whisker passes (table semantics ungated per `score.py:152-160`; Opus row-swap survival **96%**, `QA-RELIABILITY-VERDICT.md:79`). VLM lane at **1288 px / ~110 DPI** (`renderpdf.py:52`, `pipeline.py:1229`) judges page-by-page (`pipeline.py:548-554`): table structure confusable at **37% EM** table-QA baseline (`05-web.md` MTabVQA), backtick at **~3.4 px** width unreadable after 28×28 patching (`05-web.md` Q3). Judge returns **pass** on both defects.

## False-fail hypothesis

A clean conversion where tomd correctly strips page furniture (header "Document #: P1234R0", page numbers, repeated meeting title): page image still shows the footer line; markdown omits it by design (`CLAUDE.md`: "tomd deliberately strips furniture"). Per-page VLM flags "missing text" / `segment_lost` (DOCR text type) while `unigram_coverage` ≥ 0.95 and benign-region fold would pass (`score.py:183-190`). False **fail/review** on cosmetic furniture, not semantic loss.

## What would change my mind

An adversarial holdout (≥30 pages from real WG21 PDFs: row-swap tables, template/backtick edits, cross-page footnotes, front-matter typos) run through the proposed pipeline at **≥192 DPI table/code crops** (marker highres reference `00-baseline.md:22`) with **image+markdown pairing** and DOCR-style per-element checklists, showing **≤5% false-pass** on semantic defects that survive det `pass` today — with measured false-fail rate on the 163-paper pass tier (`QA-RELIABILITY-VERDICT.md:49`).
