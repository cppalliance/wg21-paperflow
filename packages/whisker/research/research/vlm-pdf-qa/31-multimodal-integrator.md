# 31 - multimodal-pipeline-integrator

**Verdict:** usable-with-conditions — the existing `pipeline` stack can carry page images end-to-end with one backward-compatible optional kwarg threaded through four call sites plus a new `vllm_vision` backend class; structured output on multimodal vLLM must initially follow the `VllmThinkingBackend` schema-in-prompt raw-completions path, not pydantic-ai native `output_type` guided decoding, until a live endpoint proves both simultaneously.
**Confidence:** high

## Findings

- [CRITICAL] The LLM entry chain is text-only today: `run_agent(ctx, spec, user_msg: str)` at `packages/pipeline/src/pipeline/runner.py:219-225` forwards a bare string to `AgentBackend.run(system, user_msg, output_type, ...)` at `runner.py:266-272`; `AgentBackend.run` types `user_message: str` at `packages/pipeline/src/pipeline/agents.py:110-114` and logs it verbatim to debug at `agents.py:152-160`; `ModelBackend.run` ABC requires `user_message: str` at `packages/pipeline/src/pipeline/model_backends.py:191-203`. `StepContext.inject_untrusted(content: str)` is text-only at `runner.py:119-121`; `inject_untrusted` / `guard_instruction` in `tools.py` accept only `str` at `tools.py:49-62`. Impact: every downstream package (dissect, agora, whisker tapetum_llm) compiles against `str`; any widening of the positional `user_msg` type would force churn; an optional keyword-only extension leaves all existing callers untouched.

- [HIGH] Installed pydantic-ai is **1.89.1** (`uv.lock:2882-2883`; runtime `pydantic_ai 1.89.1`). `BinaryContent` and `ImageUrl` exist in `pydantic_ai.messages` (runtime import). `Agent.run` accepts `user_prompt: str | Sequence[UserContent] | None` (runtime `inspect.signature(Agent.run)`); `UserContent` is `str | TextContent | BinaryContent | ImageUrl | ...` (runtime `typing.get_args(UserContent)`). Verified call shape: `asyncio.run(agent.run(['hello', BinaryContent(data=b'...', media_type='image/png')]))` succeeds (runtime test, 2026-07-07). Impact: no new message-type invention inside `pipeline`; backends can compose `[user_message, *user_media]` and hand it to pydantic-ai `Agent.run` on the OpenAI-compatible path.

- [HIGH] **Narrowest signature change (zero existing-caller edits):** keep `user_message: str` everywhere; add a keyword-only `user_media: Sequence[UserContent] | None = None` to `run_agent` (`runner.py:219`), `run_task` (`tasks.py:41-50`), `AgentBackend.run` (`agents.py:110`), and `ModelBackend.run` (`model_backends.py:191`). Thread rule: when `user_media is None`, behavior is bit-identical to today (pass `user_message` str through); when set, backends build `user_prompt = [user_message, *user_media]` for pydantic-ai backends, or an OpenAI `content` parts list for the raw HTTP path. `dispatch()` parallel/default modes that call `run_agent(ctx, spec, msg)` at `runner.py:370-381` need no edits. agora's `run_task(..., user_message, ...)` at `packages/agora/src/agora/pipeline.py:343` and whisker's `run_agent(ctx, spec, user_msg)` at `packages/whisker/src/whisker/tapetum_llm/adjudicate.py:212,222,269` remain valid without import or call-site changes.

- [HIGH] Backend wiring split is mandatory. **Non-tool `VllmThinkingBackend`** posts `messages=[{"role":"user","content": user_message}]` with `content` as a plain string at `model_backends.py:288-291`; multimodal requires switching to OpenAI content-parts (`{"type":"text","text":...}` + `{"type":"image_url","image_url":{"url":"data:image/png;base64,..."}}`), matching olmocr (`00-baseline.md:16`) and docling (`00-baseline.md:44`). **pydantic-ai backends** (`VllmThinkingBackend._run_with_tools` at `model_backends.py:467-470`, `Llama3Backend` at `model_backends.py:560-563`, `Qwen3Backend` at `model_backends.py:655-658`, `AnthropicBackend` at `model_backends.py:733-736`) already call `agent.run(user_message, ...)`; they only need to pass the composed sequence when `user_media` is non-empty. Impact: two mechanical branches (raw parts vs pydantic-ai sequence), both localized inside `model_backends.py`.

- [HIGH] A **new** `VllmVisionBackend` (registry key `vllm_vision`, registered beside `vllm_thinking` at `model_backends.py:752-757`) is required; retargeting text-only `alliance-pod` (`SERVICES.toml:64-74`, `backend = "vllm_thinking"`) would be a capability lie. `00-baseline.md:73-74` records no `vision_capable` flag in `SERVICES.toml` today; add `vision_capable = true` on the VLM service entry and extend `validate_capabilities` (`packages/pipeline/src/pipeline/validate.py:75-121`) mirroring the `tools_capable` / `thinking_capable` pattern so vision steps fail at construction time on text backends. Impact: whisker tapetum_llm binds a dedicated VLM slot without touching dissect/agora slot maps.

- [MED] **Structured output + multimodal on vLLM:** our production thinking path deliberately avoids guided decoding — `VllmThinkingBackend` appends `_schema_instruction(output_type)` to the system prompt and parses raw JSON (`model_backends.py:285-286,361-364`), because tool calling / constrained decoding is broken on thinking models (`model_backends.py:227-232`). olmocr sends multimodal `image_url` + free-text YAML, not Pydantic schema (`00-baseline.md:16-18`). docling's `api_image_request.py` packages `image_url` for conversion calls, not schema-guided QA (`00-baseline.md:44-45`). MinerU's `http-client` backend is remote inference, no structured-output coupling (`00-baseline.md:29`). `05-web.md` Q3 confirms vLLM `/v1/chat/completions` accepts `image_url` data URIs (`05-web.md:42-43`) but does not claim guided JSON + vision compose cleanly. `Llama3Backend` / `Qwen3Backend` use pydantic-ai `output_type=` (`model_backends.py:547-551,642-646`), which may engage vLLM constrained decoding — **unverified with images in this repo**. **Recommendation:** ship `VllmVisionBackend` on the schema-in-prompt raw-completions branch (clone `VllmThinkingBackend.run` multimodal messages + `_extract_json`); treat pydantic-ai `output_type` on multimodal as phase-2 after a live Qwen2.5-VL / olmOCR endpoint test. Impact: D6 (`output_type=PydanticModel`) is preserved at the framework boundary; only the backend-internal encoding strategy differs for vision.

- [MED] **Whisker-side placement (outside `pipeline`, but consumes the new kwarg):** rasterization belongs in `packages/whisker/src/whisker/tapetum_llm/vision.py` (new module), not `tomd`. `tomd` owns conversion figure extraction (`packages/pipeline/src/pipeline/process.py:241-316` is mailing→tomd image handoff, not model input); tapetum_llm owns independent fidelity judging (`00-baseline.md:69-72`). Library contract: `vision.rasterize_pages(pdf_path: Path, *, dpi, max_longest_dim) -> list[PageRaster]` returns bytes + width + height + page index; **no writes** (library returns data; CLI persists — root `CLAUDE.md` invariants). PDF access via existing `backend.get_source_path(pid)` (`packages/paperstore/src/paperstore/sqlite_backend.py:1119-1135`). PyMuPDF is already in the workspace through `whisker -> tomd -> pymupdf~=1.27.0` (`packages/tomd/pyproject.toml:10`; `00-baseline.md:82-83`); reuse `fitz.Matrix(dpi/72, dpi/72)` per baseline rasterizer guidance (`00-baseline.md:84`). `adjudicate.py` `_custom_select` loads markdown only today (`adjudicate.py:187-199`); vision calls happen in `_build_triage_message` / `run_agent(..., user_media=[BinaryContent(...)])` without changing dissect/agora. Add `pymupdf` as a direct `tapetum-llm` optional dep if import stability matters; transitive import works today.

- [LOW] **Debug/trace convention for image-bearing calls** (`<pid>.debug.<tool>.md`, full-fidelity I/O per root `CLAUDE.md`): extend `render_debug_prompt` (`tasks.py:72-80`) and `AgentBackend.run` debug append (`agents.py:152-160`) to emit one HTML comment per image, never inline base64. Proposed line (append after `<!-- user -->` text block): `<!-- user-image i=N page=P sha256=<hex> width=W height=H bytes=B media_type=image/png source=<pid>.pdf#pageP -->`. Compute `sha256` over the exact bytes passed to `BinaryContent`; set `BinaryContent.identifier=f"page{P}"` for pydantic-ai correlation. Text portions stay untruncated (existing contract); images are referenced by digest + geometry, which is the honest ground truth for "what entered the model" without megabyte dumps. Raw PNG sidecar optional later (`backend.get_debug_md_path` namespacing already exists per `packages/paperstore/src/paperstore/CLAUDE.md:14-15`); not required for minimal ship.

## False-pass hypothesis

A low-DPI raster (client-side resize is mandatory per `05-web.md:52-55` because per-request `max_pixels` on `image_url` is ignored under vLLM) hides a table cell swap that remains visible in the markdown; the VLM answers "pass" on wording axis because both modalities look plausible at thumbnail resolution while the PDF original differs — the lane would wrongly accept a token-preserving semantic corruption the text-only gate was built to catch.

## False-fail hypothesis

`VllmVisionBackend` uses schema-in-prompt + `max_tokens` shared with visual encoder tokens; a 13-page paper escalated to per-page calls hits `finish_reason=="length"` (`model_backends.py:377-387`), JSON extraction fails after retry, and the pipeline raises `MalformedModelOutputError` / `StepError` (`runner.py:273-274`) even though a human would call the page readable — a infrastructure budget false-fail, not a conversion defect.

## What would change my mind

One green pytest (or `_debug_` script) on a live self-hosted Qwen2.5-VL / olmOCR vLLM endpoint showing `Agent.run([wrapped_text, BinaryContent(...)], output_type=Adjudication)` returning a validated `Adjudication` twice in a row with identical verdicts (D6 + D11 satisfied) would flip the structured-output recommendation from schema-in-prompt-only to pydantic-ai native `output_type` on the vision backend.
