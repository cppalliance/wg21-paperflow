# 21 - marker-LLM-refinement-analyst

**Verdict:** usable-with-conditions — marker's `--use_llm` path is the best open-source structural analogue for "image + existing extraction → structured verdict," but it REFINES conversion blocks rather than independently judging whisker's already-finished markdown; port the prompt/schema/reject-and-keep patterns, not the block-rewrite pipeline or concurrent execution.
**Confidence:** high

## Findings

- [CRITICAL] Marker is a **correction layer**, not a fidelity judge. Every LLM processor takes a cropped block image plus the current HTML/markdown representation and emits a **replacement** (`block.html = corrected_*`) or `"no corrections needed"` no-op — there is no pass/review/fail verdict axis. Evidence: `llm_table.py:47-64,199-209,227-240`, `llm_complex.py:14-16,69-90`, `llm_equation.py:106-128`, `llm_form.py:94-114`. Impact: closest structural match to our task (multimodal + prior extraction), but the **role must be inverted** to judge-only (DOCR-Inspector / coarse `extraction_qa.py` pattern from `05-web.md:76-83`) rather than copied as a rewriter.

- [HIGH] **Service layer:** all providers encode images as **WEBP base64** via `BaseService.img_to_base64(..., format="WEBP")` (`services/__init__.py:22-25`); OpenAI-compatible path wraps `data:image/{webp|png};base64,...` (`openai.py:28-31,49-58`, default `webp`); Gemini sends raw WEBP bytes as `image/webp` parts (`gemini.py:28-40`); Claude uses `media_type: image/webp` (`claude.py:27-37`); Ollama passes base64 strings in `"images"` (`ollama.py:23-54`). **No client-side resize/DPI cap** beyond whatever pixel size the crop already has. Shared defaults: `timeout=30`, `max_retries=2`, `retry_wait_time=3` (`__init__.py:13-17`). OpenAI/Azure use `beta.chat.completions.parse` + Pydantic `response_format` (`openai.py:92-100`, `azure_openai.py:74-82`); Gemini uses native `response_schema` + `response_mime_type: application/json` at `temperature=0` (`gemini.py:64-67`); Claude injects JSON schema into system prompt + manual parse (`claude.py:81-88,114-115`); Ollama uses `/api/generate` with JSON `format` derived from schema (`ollama.py:39-53`) — **Ollama has zero retries** (`ollama.py:56-73`). All services return `{}` on exhaustion (silent keep-deterministic). Impact: WEBP base64 + Pydantic structured output is portable to a self-hosted OpenAI-compatible VLM; Ollama path proves local serving works but lacks retry parity.

- [HIGH] **Verification prompt pattern** (image + extraction + compare + optional self-score) is directly adaptable. Tables: image + `{block_html}`, step "write comparison… if correct output `No corrections needed`", self-score 1-5 with retry when `score < 4` (`llm_table.py:47-64,213-225`, `TableSchema` at `:323-327`). Equations/forms/complex regions follow the same "examine image → analyze extraction → correct or no-op" template (`llm_equation.py:28-46,110-117`, `llm_form.py:14-24,104-106`, `llm_complex.py:14-16,79-81`). Page-level variant sends **full-page lowres image** + JSON block list with normalized bboxes 0-1000 (`llm_page_correction.py:37-48,150-159,82-105`). Impact: for whisker judge, port the **comparison-then-verdict** steps and table-style self-score retry; replace HTML rewrite fields with axis verdicts + evidence quotes.

- [HIGH] **Quality gates reject bad LLM merges; failures never fail the document.** Pre-merge guards: table `len(parsed_cells) <= 1` or missing `</table>` (`llm_table.py:228-238`); equation unbalanced `<math>` or `<30%` original length (`llm_equation.py:119-126`); form HTML `<33%` original length (`llm_form.py:109-111`); complex markdown `<50%` length (`llm_complex.py:84-86`); page reorder requires block-ID set equality (`llm_page_correction.py:221-242`). Missing/empty LLM response increments `llm_error_count` on block metadata (`schema/blocks/base.py:16-19`, e.g. `llm_table.py:201-203`). Impact: matches whisker fidelity invariant (fail not partial at lane level): LLM lane should emit structured findings or demote to review, never silently overwrite deterministic verdict.

- [MED] **Rasterization:** pypdfium2 `page.render(scale=dpi/72).to_pil()` (`providers/pdf.py:404-413,415-420`); `lowres_image_dpi=96` for layout, `highres_image_dpi=192` for OCR/LLM block crops (`builders/document.py:18-25,41-42`). Block crops rescale polygon to page image size then `crop(bbox)` with default `image_expansion_ratio=0.01` (`processors/llm/__init__.py:46-49,69-79`, `schema/blocks/base.py:128-148`). Page correction alone uses **lowres full page** (`llm_page_correction.py:152`). Benchmark LLM **judge** scorer renders page 0 at **96 DPI** only (`benchmarks/overall/scorers/llm.py:102-105,47-48` "minor mistakes okay" → rubber-stamp risk per `05-web.md:58-61`). Impact: 192 DPI block crops are reasonable for tables/equations; whole-page QA should use higher DPI (olmocr 1288px longest edge per `00-baseline.md:15`) — marker's 96 DPI judge path is too coarse for dense WG21 tables.

- [MED] **Block-level vs page-level granularity:** default LLM path is **per-block cropped highres images** (tables further sub-crop by row batch, `:144-169`). Whisker has **no pixel bboxes in det sidecar**: `MisalignedRegion` carries `page`, `token_start/end`, `sample` only (`tomd/lib/check_content.py:119-131`; serialized in `score.py:235-240`). Whisker explicitly omits bbox visualization (`whisker/CLAUDE.md:270-272`). `packages/whisker/src/whisker/extract.py` **does not exist**; tomd holds internal section bboxes (`tomd/lib/pdf/types.py:43`) but they are not exported to whisker JSON. Impact: block-crop QA is **not drop-in** without new geometry (tomd section bboxes, det region→page mapping, or coarse page+H2-chunk like `coarse/extraction_qa.py`). Pragmatic v1: **page-level** images + markdown chunks aligned by page/H2; v2: crop around `MisalignedRegion.page` + sample text search on rendered page.

- [MED] **What to port vs what to skip.** **Port:** (1) multimodal message shape — images first, then text prompt (`gemini.py:81-84`, `openai.py:79-86`); (2) Pydantic response schemas per task (`TableSchema`, `PageSchema`, etc.); (3) `"no corrections needed"` / empty-response → no-op semantics mapped to `pass` or abstain; (4) post-response validation gates before accepting LLM output (`llm_table.py:228-238` pattern); (5) benchmark `LLMScorer` page+markdown rating prompt structure for axis scores (`benchmarks/overall/scorers/llm.py:15-52,128-134`) adapted to whisker fidelity axes. **Skip:** (1) in-place `block.html` rewrites; (2) `ThreadPoolExecutor` / `max_concurrency=3` (`processors/llm/__init__.py:42-45,163-172`, `llm_meta.py:44-49`) — violates D11 serial tapetum; (3) Gemini-default cloud coupling (`converters/pdf.py:104,138-139`); (4) block-type gating as substitute for whisker coverage/drift thresholds (`llm_table.py:134-135`, `llm_equation.py:79-83`); (5) 96 DPI judge rasterization (`llm.py:102`).

- [LOW] **Self-host path:** `OllamaService` defaults `http://localhost:11434`, model `llama3.2-vision`, JSON schema via `format` (`ollama.py:16-21,39-53`); OpenAI service accepts arbitrary `openai_base_url` for vLLM (`openai.py:19-21,129-130`). Default converter still wires `GoogleGeminiService` (`converters/pdf.py:104`). Impact: marker proves OpenAI-compatible + Ollama multimodal works; whisker should target alliance-pod / vLLM with Qwen-VL per model-sovereignty (`00-baseline.md:66`, `05-web.md:40-55`).

## False-pass hypothesis

Table processor accepts `"no corrections needed"` when the 192 DPI crop is too small to read cell boundaries, or when the LLM self-scores ≥4 after a wrong rewrite (`llm_table.py:207-209,215-225`). Mapped to whisker: a page-level judge at 96 DPI (`llm.py:102`) plus "minor mistakes okay" (`llm.py:47-48`) would **false-pass** a straw-poll table where markdown permutes column headers but preserves token multiset — matching the HQH ~60% OCR-category hallucination risk (`05-web.md:58-61`) and whisker's known false-pass lane (token-preserving semantic corruption, `whisker/CLAUDE.md` tapetum section).

## False-fail hypothesis

Equation processor rejects corrections when output length `<30%` of original (`llm_equation.py:119-124`) even if the image-backed fix is shorter because inline math was collapsed to proper `<math>` tags. Mapped to whisker: strict length-ratio merge guards would **false-fail** faithful condensations (reflow, heading normalization) unless the judge emits verdicts without requiring corrected text length to exceed extraction length.

## What would change my mind

Finding a marker code path that **scores conversion fidelity without mutating blocks** and gates shipping on that score (not just optional benchmark `LLMScorer` parallel to heuristic). Today conversion `--use_llm` always rewrites (`llm_table.py:227-240`) and CI gates heuristic-only (`research/hybrid-llm-scoring/02-marker-hybrid.md:12-13`); the benchmark judge at `benchmarks/overall/scorers/llm.py` is the only true image-vs-markdown scorer and it is eval-only, first-page, 96 DPI.
