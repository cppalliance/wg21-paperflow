# 17 - Downstream-Consumer

**Verdict:** usable-with-conditions — fusion and sidecar shape can absorb a paper-level aggregated VLM verdict (same `suggested_verdict` / `axis_findings` contract), but the plan as stated traps operators on HTML-only sources, silent re-runs, missing page attribution in human reports, and sidecars with no schema versioning.
**Confidence:** high

## Findings

- [CRITICAL] **"Always PDF" is impossible for 198/387 staged papers; the lane must degrade or half the corpus is undefined.** Evidence: `00-baseline.md` §4 (189 PDFs in `data/paperstore/`); runtime query via `get_source_path` on all 387 DB rows → 189 `.pdf`, 198 `.html`, 0 papers with both; sample HTML-only PIDs include `N5034`, `P1040R10`. `get_source_path` returns whatever is staged (`.pdf` or `.html`) — `packages/paperstore/src/paperstore/sqlite_backend.py:927,1119-1135`. Current tapetum lane never opens either file — `_custom_select` loads markdown only — `packages/whisker/src/whisker/tapetum_llm/adjudicate.py:175-199`. Impact: integrators who wire VLM to PDF without an explicit HTML branch will fail closed on 51% of papers or, worse, skip them while `report-merged.md` still lists them with `llm: -` (looks like "not selected," not "no PDF").

- [CRITICAL] **Per-page VLM findings collapse to paper-level axes with no page field; fusion accepts the shape but human reports cannot act on it.** Evidence: fusion reads only `suggested_verdict`, `confidence`, and `axis_findings[].{verdict,severity,axis}` — `packages/whisker/src/whisker/tapetum_llm/fusion.py:96-101,137-215`; aggregation precedent folds many calls into one `Adjudication` via `aggregate_adjudications` (worst axis, min confidence) — `packages/whisker/src/whisker/tapetum_llm/chunking.py:226-292`; `TapetumResult` / `axis_findings` dicts have no `page` key — `packages/whisker/src/whisker/tapetum_llm/models.py:63-70,310-313`. `report-merged.md` shows verdict columns only, no findings or pages — `packages/whisker/src/whisker/tapetum_llm/fusion_report.py:143-155`; `inspect_report.py` prints evidence as char intervals, not PDF pages — `packages/whisker/src/whisker/tapetum_llm/inspect_report.py:95-107`. Whisker deterministic sidecars *do* carry page on region detail — `packages/whisker/src/whisker/score.py:238`. Impact: a VLM flagging "table wrong on page 7" becomes an axis `note` with no page in any operator-facing artifact; reviewers must grep markdown, not open the PDF at the defect.

- [HIGH] **Tapetum sidecars have no `schema_version`; a VLM extension will silently break `_fuse-only` and external readers.** Evidence: `TapetumResult.to_dict()` emits pid, status, axis_findings, fusion block, etc., but no schema field — `packages/whisker/src/whisker/tapetum_llm/models.py:118-141`; whisker deterministic sidecars stamp `schema_version: 3` — `packages/whisker/src/whisker/constants.py:173`, `packages/whisker/src/whisker/score.py:82-90`; fusion block alone versions via `fusion_schema_version: 1` — `packages/whisker/src/whisker/tapetum_llm/constants.py:129`, `fusion.py:61-74`. `_fuse_only` and `build_merged_json` load JSON with no validation — `packages/whisker/src/whisker/tapetum_llm/cli.py:313-330`, `fusion_report.py:42-73`. Impact: adding per-page arrays or image-grounded evidence without a version bump guarantees stale sidecars masquerade as current after partial re-runs.

- [HIGH] **CLI has no resume/skip/error recovery for long VLM runs; every invocation re-adjudicates and overwrites.** Evidence: `_adjudicate_one` always calls `adjudicate_paper` then `_persist_result` (overwrite) — `packages/whisker/src/whisker/tapetum_llm/cli.py:506-517,250-266`; no `--skip-existing`, no per-page checkpoint, no partial sidecar. Failures log one line and increment `counts["error"]` — `cli.py:532-566`; pipeline error stub sets `status: "error"`, `confidence: 0.0` — `packages/whisker/src/whisker/tapetum_llm/adjudicate.py:507-519`. Contrast olmocr: per-page retry with rotation path, parallel retries, and `make_fallback_result` pdftotext fallback — `packages/whisker/research/repos/olmocr/olmocr/pipeline.py:233-248,281-375`; document discarded when fallback rate exceeds `max_page_error_rate` — `pipeline.py:557-561`. Impact: a 13-page paper (baseline sample `n5036.pdf`, 13 pages — `00-baseline.md` §4) at ~30 s/page (olmOCR README, https://github.com/allenai/olmocr — `05-web.md` Q2) is ~6.5 min; interrupt at page 9 loses all work and `--review-all` recomputes from scratch.

- [HIGH] **Operator UX hides the latency cliff; menu chains deterministic + LLM with no time budget or HTML/PDF split.** Evidence: `menu.py` option 2 runs `_run_score` then `tapetum_main(["--review-all"])` with no duration warning — `packages/whisker/src/whisker/menu.py:142-160`; default `--concurrency 8` tuned for text (~30 s/paper at c=8 — `cli.py:49-56,53-54`) is hostile to VLM (12 GB GPU OOM at default vLLM settings — https://github.com/allenai/olmocr/issues/424 — `05-web.md` Q2). Per-paper wall timeout `_PAPER_TIMEOUT_SECONDS = 900` — `cli.py:63-67` — may fit serial text cascade but not serial per-page vision on multi-page papers without raising timeout or lowering concurrency. Impact: operators who today wait seconds for `--review-all` will hit multi-hour batch runs and GPU thrash with no menu guardrail.

- [MED] **Fusion treats pipeline errors as "tapetum absent," indistinguishable from never-run in merged reports.** Evidence: `_tapetum_is_usable` returns False when `status == "error"` — `fusion.py:89-90`; merged row then shows `llm: -`, `merged = det`, rule empty — `fusion_report.py:57-68`. Errored sidecar still on disk with `status: "error"` — `adjudicate.py:518`. Impact: operator sees 177/381 with `llm: -` in live `report-merged.md` (204/381 covered); cannot tell selection skip vs VLM failure vs HTML-no-PDF without opening each sidecar.

- [MED] **Image-sourced VLM evidence cannot satisfy today's markdown grounding contract; fusion escalation may miss real PDF-only defects.** Evidence: `EvidenceSpan` requires quote be exact substring of converted markdown — `models.py:51-55`; `ground_spans` searches `state.paper_md` only — `adjudicate.py:279`; ungrounded non-pass demoted to `review` — `adjudicate.py:295-296`; fusion escalates det=pass only when `llm == fail` and `_has_major_axis_fail` — `fusion.py:204-215`. DOCR-Inspector/RaV-IDP pattern (image + parsed output, no markdown quote) — https://arxiv.org/abs/2512.10619, https://arxiv.org/pdf/2604.23644 — `05-web.md` Q5. Impact: the main value of PDF vision (cell swap visible on page image but token-identical in md) gets demoted or dropped before fusion sees a major fail.

- [LOW] **Tier-2 escalation is already absent for multi-call paths; per-page VLM inherits the same ceiling.** Evidence: `_custom_adjudicate` returns immediately when `state.chunked` — `adjudicate.py:257-261`; documented in `tapetum_llm.md` — `packages/whisker/src/whisker/tapetum_llm/tapetum_llm.md:161`. Per-page loop is the same structural class as chunking. Impact: fusion and inspect report label `escalated: false` while the lane made N vision calls; operators may over-trust a fast-model-only per-page rollup.

## False-pass hypothesis

VLM per-page pass on pages 1–2, markdown-only tier1 pass on remaining pages; `aggregate_adjudications` worst-axis fold keeps pass if no major axis fail — `chunking.py:258-259`; fusion `llm_clear_soft_review` upgrades det=review to merged pass when only soft flags — `fusion.py:166-201`. Operator sees merged pass in `report-merged.md` while an unscanned middle page still has a table OCR swap visible only on the PDF image.

## False-fail hypothesis

HTML-only paper (`get_source_path` → `.html`): plan forces PDF rasterization, implementation raises or returns empty pages, pipeline emits `status: "error"` stub — `adjudicate.py:507-519`; fusion falls back to whisker_only — `fusion.py:126-135`. Deterministic det=pass paper stays pass on record but operator interprets missing LLM coverage as "VLM rejected conversion" and manually re-reviewes a clean HTML conversion.

## What would change my mind

A written degradation matrix committed to the plan: for each of {PDF, HTML-only, missing source, partial page failure}, the sidecar fields (`status`, `suggested_verdict`, `page_findings[]`, `schema_version`) and the corresponding `report-merged.md` / inspect rows — verified on 3 HTML-only and 3 PDF papers with runtime output pasted — would flip the verdict to **usable** and downgrade the HTML and schema findings to addressed.
