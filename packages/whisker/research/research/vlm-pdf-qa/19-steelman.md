# 19 - Steelman

**Verdict:** usable-with-conditions — feeding original PDF page images to a self-hosted VLM for independent conversion-QA closes a structural blind spot the markdown-only LLM lane cannot fix in principle, and the existing asymmetric fusion layer already absorbs imperfect VLM judges without letting them auto-fail papers.
**Confidence:** high

## Findings
- [CRITICAL] The tapetum_llm lane is structurally blind to the source document: `_PipelineState` holds only `paper_md` and whisker det sidecar signals, and `_custom_select` loads markdown exclusively via `backend.get_paper_md(pid)` with no PDF accessor anywhere in the cascade. Evidence: `packages/whisker/src/whisker/tapetum_llm/adjudicate.py:153-169,175-199`. Impact: the lane judges conversion fidelity by re-reading the conversion artifact plus statistical overlap metrics derived from the same artifact chain; it cannot observe omissions or transpositions that leave token-level statistics green.
- [CRITICAL] Concrete error class invisible in principle: tomd drops an entire boilerplate section (e.g., revision history, acknowledgements) while the body survives — `unigram_coverage` stays high because order-invariant token recall still covers most PDF words, and whisker explicitly gates content on `unigram_coverage` not reading-order `coverage`. Evidence: `packages/whisker/src/whisker/CLAUDE.md` (content gate on unigram, not shingle coverage); candidate selection only escalates pass-tier papers when `(uni - cov) > COV_UNIGRAM_GAP_TRIGGER`, not when a section is simply absent (`adjudicate.py:114-126`, `constants.py:79-80`). Impact: a dropped low-information section is exactly the false-pass population the advisory lane was built to catch (`CLAUDE.md`: "token-preserving semantic corruption" blind spot) yet markdown-only adjudication cannot see it because the missing section never enters the prompt (`adjudicate.py:391,423`).
- [HIGH] A second concrete blind spot: table cell transposition — all cell tokens remain in the markdown, so `unigram_coverage` is unchanged, while semantic table fidelity is destroyed. Evidence: `packages/whisker/research/persona/18-wg21-domain-expert.md` (table cell transposition: all tokens present, gate passes); tapetum prompts inject only converted markdown (`adjudicate.py:389-392`). Impact: only a judge that sees the rendered table in the PDF page image can compare row/column geometry against the pipe-table output; this is the task DOCR-Inspector and coarse target.
- [HIGH] Prior art confirms VLM-as-judge for conversion fidelity is a recognized pattern, not a novelty bet. Evidence: DOCR-Inspector — page/element images plus parsed output, 28-type error taxonomy, no ground truth (`05-web.md` Q5 → https://arxiv.org/abs/2512.10619); RaV-IDP — reconstruction-as-validation loop anchored to source image (`05-web.md` Q5 → https://arxiv.org/pdf/2604.23644); coarse `extraction_qa.py` — renders PDF pages, sends images WITH markdown chunks to a vision LLM for good/acceptable/poor rating (`05-web.md` Q5 → https://github.com/Davidvandijcke/coarse/blob/dev/src/coarse/extraction_qa.py). Impact: we are adopting a validated architecture class; olmOCR in our own baseline is the closest in-repo analogue (`00-baseline.md:13-19`).
- [HIGH] Feasibility on our stack is already partially wired: paperstore exposes staged PDFs via `get_source_path(pid) -> Path` for `.pdf`/`.html` sources (`sqlite_backend.py:1119-1135`, ABC `backend.py:357-362`); PyMuPDF is already a tomd dependency (`packages/tomd/pyproject.toml:10`, runtime PyMuPDF 1.27.2.3 per `00-baseline.md:82`); olmOCR-2 weights are public Apache-2.0 FP8/BF16 finetunes served via vLLM (`05-web.md` Q2 → https://huggingface.co/allenai/olmOCR-2-7B-1025-FP8, https://github.com/allenai/olmocr). Impact: rasterization reuses existing `fitz` (`00-baseline.md:84`) instead of adding poppler/pypdfium2; model sovereignty and licensing constraints are satisfied without cloud dependency.
- [MED] vLLM serving path matches infrastructure we already speak: `SERVICES.toml` runs multiple `vllm_thinking` backends on alliance-pod (`SERVICES.toml:48-133`); vLLM `/v1/chat/completions` accepts `image_url` base64 content parts (`05-web.md` Q3 → https://docs.vllm.ai/en/latest/features/multimodal_inputs/); olmOCR pipeline already posts page PNGs to OpenAI-compatible chat completions (`00-baseline.md:16-18`). Impact: adding a vision-capable vLLM service is an incremental SERVICES.toml entry plus a multimodal message type (`00-baseline.md:73`), not a new inference stack.
- [MED] Per-paper VLM cost is bounded on WG21 corpus: 189 PDFs, typical 3–13 pages (`00-baseline.md:80-81`: `n5035.pdf` 3 pages, `n5036.pdf` 13 pages). olmOCR runs ~12 GB+ VRAM per page at longest-dim 1288 px (`00-baseline.md:15`, `05-web.md` Q2 → https://github.com/allenai/olmocr). Impact: serial per-page loop (D11-compatible) over single-digit page counts is tractable on alliance-pod; token-budget risk scales with pages, not corpus size per invocation.
- [HIGH] The fusion layer is already asymmetric-advisory by design, so a noisy VLM lane cannot auto-fail papers: `fuse_verdicts` is pure, advisory (`fusion.py:10-13,62`); det=pass + LLM fail(major) escalates only to merged `review`, never `fail` (`fusion.py:203-215`); det=fail stays locked except heading-monotone rescue to `review` (`fusion.py:141-163`); unusable tapetum sidecars fall back to whisker-only (`fusion.py:126-135`). Impact: VLM hallucination risk (OCR category ~60% average per `05-web.md` Q4 → https://arxiv.org/html/2406.17115v1) is mitigated at the verdict layer — the VLM adds signal, it does not become the gate (`fusion.py:120-121`).

## False-pass hypothesis
A VLM judge hallucinates a missing table row on a clean conversion (OCR-category hallucination rates average ~60% across models per HQH benchmark, `05-web.md` Q4 → https://arxiv.org/html/2406.17115v1), emits fail+major on the tables axis, and fusion escalates det=pass to merged review (`fusion.py:206-209`) — a human must inspect, but the deterministic pass is not overwritten and `whisker --gate` exit codes stay unchanged (`fusion.py:12-13`).

## False-fail hypothesis
A VLM flags cosmetic PDF-vs-markdown typography differences (font-weight heading levels, hyphenation) as structure defects on a faithful conversion; fusion keeps merged=det when det=pass and the LLM verdict is not fail+major (`fusion.py:217-227`), so the paper is not downgraded unless `_has_major_axis_fail` fires (`fusion.py:96-101`).

## What would change my mind
A labeled holdout of ≥30 WG21 papers where VLM-on-PDF adjudication, fused through `fuse_verdicts`, fails to catch any conversion defect that markdown-only tapetum_llm also missed — i.e., measured incremental recall ≈ 0 over the existing lane on the exact false-pass population (`adjudicate.py:114-126` risk signals) — would flip this from usable-with-conditions to garbage.
