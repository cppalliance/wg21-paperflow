# 22 - MinerU-VLM-backend-analyst

**Verdict:** usable-with-conditions (http-client remote-VLM wiring and page rasterization are portable; conversion prompts, token markup parsing, and concurrent batching are not)
**Confidence:** high

## Findings

- [HIGH] MinerU centralizes all VLM backends behind `ModelSingleton.get_model()` → `MinerUClient` (`mineru-vl-utils>=1.0.5`, `MinerU/pyproject.toml:53`), with a single `backend` switch among `transformers`, `mlx-engine`, `vllm-engine`, `vllm-async-engine`, `lmdeploy-engine`, and `http-client`; local engines load `Qwen2VLForConditionalGeneration` or vLLM/LMDeploy handles, while `http-client` skips `model_path` download and passes `server_url` through unchanged (`MinerU/mineru/backend/vlm/vlm_analyze.py:54-252`). Impact: the abstraction pattern (one client, pluggable transport) matches our SERVICES.toml slot model; we should mirror the factory, not the MinerU model weights.

- [HIGH] Public CLI backend `vlm-http-client` strips the `vlm-` prefix to internal `http-client` and only then keeps `server_url`; non-client backends force `server_url=None` (`MinerU/mineru/cli/common.py:445-446,725-739`). `server_url` is mandatory when the backend name ends with `http-client` (`MinerU/demo/demo.py:113-114`). The HTTP client posts OpenAI-style chat completions to `{server_url}/v1/chat/completions` (trailing slash preserved, else base URL stripped), with optional `MINERU_VL_SERVER`, `MINERU_VL_API_KEY` (Bearer), and `MINERU_VL_MODEL_NAME` env overrides (`mineru-vl-utils 1.0.5:mineru_vl_utils/vlm_client/http_client.py:80-86,119-120,88-94`). Impact: directly maps to a new `[services.*]` vLLM vision endpoint at `/v1/chat/completions`; our judge lane can reuse the same URL/header contract without MinerU installed.

- [HIGH] Remote request body: system message + user `content` parts with `{"type":"image_url","image_url":{"url":"data:image/png;base64,..."}}` then text prompt (images-before-text default), plus sampling fields including `temperature`, `top_p`, `top_k`, `max_tokens`/`max_completion_tokens`, and `skip_special_tokens: false` (`mineru-vl-utils 1.0.5:mineru_vl_utils/vlm_client/http_client.py:231-299`). PIL page images are converted to PNG bytes before base64 encoding (`mineru-vl-utils 1.0.5:mineru_vl_utils/vlm_client/utils.py:54-57,123-134`). Impact: aligns with vLLM multimodal docs in `05-web.md` Q3; portable envelope for whisker judge calls once pipeline gains multimodal `content` parts.

- [HIGH] Page rasterization before any VLM call uses pypdfium2 (not PyMuPDF): `DEFAULT_PDF_IMAGE_DPI = 200`, `scale = dpi / 72`, long-edge clamp at 3500 px, output as PIL dicts `{img_pil, scale}` (`MinerU/mineru/utils/pdf_image_tools.py:35,50-77`; `MinerU/mineru/utils/pdf_reader.py:11-33`). Windows are loaded in chunks of up to 64 pages (`MINERU_PROCESSING_WINDOW_SIZE`, default 64) via a persistent `ProcessPoolExecutor` for parallel PDF render only (`MinerU/mineru/backend/vlm/vlm_analyze.py:446-470`; `MinerU/mineru/utils/config_reader.py:158-169`). Impact: 200 DPI / ~3500 px long side is a concrete reference for WG21 page budgets; we can reuse PyMuPDF with the same scale math from `00-baseline.md` section 4 instead of adding pypdfium2.

- [HIGH] VLM stage is a two-step **conversion** pipeline, not QA: step 1 layout prompt `"\nLayout Detection:"` emits custom token markup (`<|box_start|>…<|box_end|><|ref_start|>type<|ref_end|>…`) parsed by regex into `ContentBlock` bboxes normalized 0–1000 (`mineru-vl-utils 1.0.5:mineru_vl_utils/mineru_client.py:58-66,26-31,238-269`); step 2 per-block prompts like `"\nText Recognition:"`, `"\nTable Recognition:"`, `"\nFormula Recognition:"` with block crops (`mineru-vl-utils 1.0.5:mineru_vl_utils/mineru_client.py:953-972,286-363`). Default sampling pins near-greedy layout (`temperature=0.0`, `top_k=1`, `no_repeat_ngram_size=100`) (`mineru-vl-utils 1.0.5:mineru_vl_utils/mineru_client.py:34-55,68-76`). Impact: **not portable** to a judge role; DOCR-Inspector / coarse-style image+markdown prompts (`05-web.md` Q5) replace this entirely.

- [CRITICAL] `http-client` sets `batching_mode = "concurrent"`: `batch_two_step_extract` fans out pages with `asyncio.Semaphore(max_concurrency)` default **100**, and block-level extracts within a page also batch concurrently (`mineru-vl-utils 1.0.5:mineru_vl_utils/mineru_client.py:666-668,1179-1186,1038-1053`; wired from `MinerU/mineru/backend/vlm/vlm_analyze.py:71,479-482`). `vlm_analyze` only serializes MLX via a threading lock, not http-client (`MinerU/mineru/backend/vlm/vlm_analyze.py:379-397`). Impact: violates our D11 serial dissect contract; judge lane must force `max_concurrency=1` and one page (or one block) in flight, abandoning MinerU batch APIs.

- [MED] Error handling is HTTP-retry + fail-forward, not fidelity-fail: httpx `RetryTransport` with `max_retries=3`, `retry_backoff_factor=0.5` (`MinerU/mineru/backend/vlm/vlm_analyze.py:74-75`; `mineru-vl-utils 1.0.5:mineru_vl_utils/vlm_client/http_client.py:131-137`); truncated responses raise unless `allow_truncated_content=True` (set for MinerUClient, `mineru-vl-utils 1.0.5:mineru_vl_utils/mineru_client.py:625`); post-process exceptions log a warning and return partially cleaned blocks (`mineru-vl-utils 1.0.5:mineru_vl_utils/mineru_client.py:365-379`). There is **no** per-page retry loop and **no** fallback from VLM to pipeline on VLM failure—hybrid medium skips VLM layout entirely and hybrid high runs full VLM then adds pipeline OCR sidecars, but never compares or votes between backends (`MinerU/mineru/backend/hybrid/hybrid_analyze.py:965-1033`). Impact: opposite of whisker fidelity (fail not partial); judge must fail the paper on VLM error, not MinerU-style degrade.

- [LOW] Hybrid `effort` mirrors a two-lane **orchestration** (pipeline det layout vs full VLM), not a fusion verdict: `medium` runs pipeline layout → maps labels to VLM block types → `batch_extract_with_layout` (VLM content only); `high` runs full `batch_two_step_extract` (VLM layout+content) then pipeline OCR/MFR sidecars (`MinerU/mineru/backend/hybrid/hybrid_analyze.py:117-121,965-1033,83-107`). Invalid medium blocks are skipped with warnings, not escalated (`MinerU/mineru/backend/hybrid/hybrid_analyze.py:387-388`). Impact: analogous to det+llm lanes in shape only; there is no agreement logic to port—whisker `fuse_verdicts` stays our fusion layer.

- [MED] **Portable to a judge (not converter) role:** (1) `vlm-http-client` → `server_url` + OpenAI `image_url` PNG base64 request shape; (2) DPI/scale clamp reference (200 DPI, 3500 px long edge) for page raster before send; (3) optional `ScoredOutput`/perplexity hooks exist on local vLLM clients (`mineru-vl-utils 1.0.5:mineru_vl_utils/vlm_client/base_client.py:39-65`) but **not** on `http-client`—confidence scoring would need a separate vLLM logprob endpoint or text-only checks. **Do not port:** layout/extract prompts, token markup parser, concurrent batching, hybrid OCR sidecars, middle-json assembly, or partial post-process fallbacks.

## False-pass hypothesis

A whisker judge that reused MinerU layout+extract prompts would false-pass a bad conversion whenever the VLM emitted well-formed `<|box_start|>…` tokens and plausible block text that omits or distorts WG21 table/math content—the model is trained to **produce** structure, not verify markdown against the PDF.

## False-fail hypothesis

Applying MinerU's 200 DPI render with a 3500 px long-edge cap (`MinerU/mineru/utils/pdf_reader.py:14-21`) could false-fail fine footnotes, small superscripts, or dense two-column WG21 text that remain readable in the original PDF at full resolution.

## What would change my mind

Evidence of a MinerU (or mineru-vl-utils) code path that takes **both** page image and external text (markdown) and returns a structured fidelity verdict—not layout tokens—with serial, temperature-pinned calls; none exists today (closest prior art remains DOCR-Inspector / coarse in `05-web.md` Q5).
