# 12 - API-Contract-Design

**Verdict:** usable-with-conditions — the portable wire format (OpenAI `image_url` data URIs) and pydantic-ai 1.89.1 multimodal types exist, but every layer from `run_agent` through debug logging hard-codes `str`; a design that "adds images" without widening that contract will silently break D1, D6 fidelity, evidence grounding, and the tier-2 escalation promise.
**Confidence:** high

## Findings

- [CRITICAL] **The public pipeline contract is text-only at four layers; multimodal cannot pass without a typed widening, not a workaround.** `run_agent(ctx, spec, user_msg: str)` — `packages/pipeline/src/pipeline/runner.py:219-225`. `AgentBackend.run(..., user_message: str)` — `packages/pipeline/src/pipeline/agents.py:110-114`. `ModelBackend.run` ABC: `user_message: str` — `packages/pipeline/src/pipeline/model_backends.py:191-195`. `run_task(..., user_message: str)` — `packages/pipeline/src/pipeline/tasks.py:41-45`. `VllmThinkingBackend` materializes `messages: list[dict[str, str]]` with `{"role":"user","content": user_message}` — `model_backends.py:288-290`, which is a lie the moment `content` becomes a part list. Impact: embedding base64 in the string or bypassing `run_agent` breaks D1 ("all calls through `run_agent`") and makes debug/trace unusable; the contract must become `user_message: str | Sequence[UserContent]` (or an optional `images=` sibling) on all four surfaces.

- [HIGH] **Least-invasive extension: widen the type, add one vision backend, leave text callers untouched.** pydantic-ai **1.89.1** is pinned (`uv.lock:2882-2895`; `packages/pipeline/pyproject.toml:11` lists `pydantic-ai-slim`, resolved with OpenAI extra). Runtime: `Agent.run(user_prompt: str | Sequence[UserContent] | None, ...)` and `UserContent = str | TextContent | ImageUrl | BinaryContent | ...` (verified via `uv run python -c "from pydantic_ai import Agent; ..."`). **Do not** retrofit `VllmThinkingBackend`'s raw-JSON path (schema-in-prompt + `_extract_json`, `model_backends.py:285-410`); add `VllmVisionBackend` that routes through pydantic-ai `Agent` + `OpenAIChatModel`, passing `[BinaryContent(data=png_bytes, media_type="image/png"), user_text]` the same way `Llama3Backend` already passes `output_type` to `agent.run` — `model_backends.py:547-563`. Wire format to vLLM stays OpenAI-compatible: olmocr `{"type":"image_url","image_url":{"url":"data:image/png;base64,..."}}` — `olmocr/olmocr/pipeline.py:133-146`; docling identical — `00-baseline.md:44`; marker `OpenAIService.process_images` — `marker/marker/services/openai.py:48-58`; vLLM docs — https://docs.vllm.ai/en/latest/features/multimodal_inputs/ (`05-web.md` Q3). Pre-resize PNG client-side; per-request pixel fields are ignored under vLLM — https://github.com/QwenLM/Qwen3-VL/issues/1434 (`05-web.md` Q3).

- [HIGH] **Structured output (D6) on vision calls: our fail-loud contract is right; marker/olmocr patterns must not be copied verbatim.** marker OpenAI path: `client.beta.chat.completions.parse(..., response_format=response_schema)` then `json.loads` — `openai.py:92-108`; any exception returns `{}` — `openai.py:124-127`. marker Ollama: top-level `"images": [base64]` on `/api/generate`, not chat content parts — `ollama.py:36-54`; different API surface. olmocr: YAML free text + optional `guided_regex`, validated via `FrontMatterParser`, not Pydantic — `pipeline.py:179-212`; finish-reason checks at `:202-206`. Our path: `_schema_instruction` + `_extract_json` + `output_type.model_validate`, raises `MalformedModelOutputError` — `model_backends.py:361-410`. Impact: vision backend must keep pydantic-ai `output_type` + D10 retries; expect higher JSON-parse failure rate on OCR-heavy pages (HQH benchmark: ~60% OCR hallucination avg — https://arxiv.org/html/2406.17115v1, `05-web.md` Q4). Do not adopt marker's silent `{}` or olmocr's temperature ramp (`TEMPERATURE_BY_ATTEMPT` — `pipeline.py:85,164-177`) without violating D5.

- [HIGH] **Tapetum sidecar schema cannot absorb per-page VLM verdicts without new fields; paper-level `Adjudication` alone will drop page-local defects.** Current LLM `output_type`: `Adjudication` with `axis_findings`, `evidence_spans` — `packages/whisker/src/whisker/tapetum_llm/models.py:72-86`. `EvidenceSpan.quote` MUST be an exact substring of converted markdown — `models.py:51-55`; `ground_spans` searches `state.paper_md` only — `adjudicate.py:279`, `grounding.py:51-59`. Library return `TapetumResult.to_dict()` emits paper-level `axis_findings`, `grounded_evidence` (quote/status/start/end only, no page) — `models.py:118-141`, `adjudicate.py:315-318`. Precedent for folding: `aggregate_adjudications` merges per-chunk `Adjudication` (worst axis, min confidence, union spans) — `chunking.py:226-292`. **Required contract additions for per-page loop:** (a) `PageAdjudication` or `page: int` on `AxisFinding`/`EvidenceSpan`; (b) `source: Literal["markdown","page_image"]` on evidence when quote is visual; (c) optional `page_verdicts: list[dict]` in `TapetumResult.to_dict()` for inspect/fusion audit, even if fusion still consumes one folded verdict. Image-only findings that fail markdown grounding currently demote to `review` — `adjudicate.py:295-296`; without dual-source grounding (DocVAL-style — https://arxiv.org/html/2511.22521v2, `05-web.md` Q4), fusion will under-react to real PDF-only defects.

- [MED] **Design promises tier-2 deep re-read on escalation; code contract already violates that for multi-call paths.** `_custom_adjudicate` returns immediately when `state.chunked` — `adjudicate.py:257-261` ("tier2 would 413 again"). Yet `TapetumResult.escalated = state.tier2 is not None` — `adjudicate.py:306-307`, and fusion treats the folded tier-1 as final (`fusion.py:15-24`). A per-page VLM loop inherits the same trap: tier-2 cannot re-inject full markdown without images unless the message contract carries page PNGs + page-scoped markdown. Impact: either extend `_build_adjudicate_message` to attach per-page images, or document `escalated=false` + `partial=true` for multi-call paths so downstream consumers do not assume a deep read happened.

- [MED] **Debug and prompt-injection contracts assume text; images are untrusted but unwrapped.** `AgentBackend.run` debug appends `user_message.rstrip()` — `agents.py:158-159`; `render_debug_prompt` same — `tasks.py:72-79`. `StepContext.inject_untrusted(content: str)` — `runner.py:119-121`. Baseline: page images are untrusted like markdown — `00-baseline.md:76`. Impact: debug must log image placeholders (page, sha256 prefix, byte length), not raw base64; multimodal user content needs a text envelope through `inject_untrusted` even when images ride alongside (images are not delimiter-injectable but are adversarial OCR/prompt carriers).

- [LOW] **Capability validation has no vision slot today.** `validate_capabilities` checks `tools_capable` / `thinking_capable` only — `validate.py:74-76`; `SERVICES.toml` entries declare `thinking_capable` / `tools_capable`, no `vision_capable` — `00-baseline.md:73`. `BACKEND_REGISTRY` keys: `vllm_thinking`, `llama3`, `qwen3`, `anthropic` — `model_backends.py:752-757`; none are vision-class. Impact: add `vision_capable` ClassVar + validation gate before a VLM service can bind to tapetum steps.

## False-pass hypothesis

A plan says "send page PNG + markdown through existing `run_agent`" but implements it by base64-in-string inside `inject_untrusted` markdown. `VllmThinkingBackend` posts that string as plain text (`model_backends.py:290`); vLLM serves a text-only model slot from `SERVICES.toml` (`00-baseline.md:73-74`). The call succeeds, returns a syntactically valid `Adjudication` with `verdict=pass` and empty `axis_findings`, and `_custom_decide` accepts it via the no-axis-findings fallback — `adjudicate.py:287-290`. Fusion sees a pass; the PDF was never visually judged.

## False-fail hypothesis

Per-page VLM returns `tables: fail(major)` with `EvidenceSpan.quote` copied from the page image ("Cell (3,2) reads 42"); `ground_spans` cannot locate it in markdown (`models.py:51-55`), quote is dropped, and severity-aware logic demotes — but if the schema requires markdown quotes, the model fabricates a near-match markdown substring that grounds fuzzy, producing a false `llm_escalate_major` fusion path (`fusion.py:22-23`) for a hallucinated table defect.

## What would change my mind

One end-to-end proof on a single WG21 page: `run_agent` (widened type) → new `VllmVisionBackend` → validated `Adjudication`, with debug showing structured multimodal parts (not a megabyte string), existing text-only tapetum tests unchanged, and a sidecar field proving which page number grounded each evidence span.
