# 12 - API-Contract-Analyst

**Verdict:** usable-with-conditions — OpenAI `image_url` content parts are the portable wire format across olmocr, docling, and marker, and vLLM documents the same contract, but our `run_agent` → `ModelBackend.run` stack is text-only end-to-end; a VLM lane requires a backward-compatible multimodal extension plus new aggregation and evidence schemas before any vision call can ship without breaking existing text callers or fusion consumers.
**Confidence:** high

## Findings

- [CRITICAL] **Pipeline message contract is `str`-only; vision cannot pass today.** `run_agent(ctx, spec, user_msg: str)` forwards a plain string to `agent.run(system, user_msg, output_type)` — `packages/pipeline/src/pipeline/runner.py:219-272`. `ModelBackend.run` ABC takes `user_message: str` — `packages/pipeline/src/pipeline/model_backends.py:191-203`. `VllmThinkingBackend` builds `messages: list[dict[str, str]]` with `{"role":"user","content": user_message}` — `model_backends.py:288-290`. `StepContext.inject_untrusted(content: str)` and debug rendering (`render_debug_prompt(system, user_msg, ...)`, `tasks.py:72-79`) assume text only. Impact: any VLM call that stuffs base64 into the string or bypasses `run_agent` violates D1 and breaks determinism/debug fidelity; the contract must grow, not be worked around.

- [HIGH] **Convergent wire format: OpenAI `image_url` + base64 data URI; HF-native `type:image` leaks backend.** olmocr: `{"type":"image_url","image_url":{"url":"data:image/png;base64,..."}}` alongside text — `olmocr/olmocr/pipeline.py:133-146`. docling: identical shape in `api_image_request` — `docling/docling/utils/api_image_request.py:192-206,285-291`. marker `OpenAIService.process_images`: same — `marker/marker/services/openai.py:48-58`. Dolphin uses HuggingFace chat template `{"type":"image","image": <PIL>}` — `Dolphin/demo_page.py:63-72`; not portable to vLLM `/v1/chat/completions`. marker `OllamaService` uses Ollama `/api/generate` with top-level `"images": [base64,...]` — `marker/marker/services/ollama.py:36-54`; a different API surface. vLLM docs confirm `image_url` data URIs on `/v1/chat/completions` — https://docs.vllm.ai/en/latest/features/multimodal_inputs/ (05-web Q3). Impact: adopt docling/olmocr/marker OpenAI path for self-hosted Qwen-VL; do not copy Dolphin's HF message dict into `ModelBackend`.

- [HIGH] **Required contract extension (backward-compatible sketch).** Keep `user_msg: str` as the text part; add optional `images: Sequence[VisionImage] | None = None` on `run_agent` and `ModelBackend.run`, where `VisionImage` carries pre-resized `data_uri: str` (PNG base64) and optional `page: int`. Backend builds OpenAI multipart user content: `[*image_parts, {"type":"text","text": user_msg}]` (image-first matches docling/marker). Text-only callers unchanged. Add `vision_capable: ClassVar[bool]` on backend classes and extend `validate_capabilities` (today only checks `tools_capable` / `thinking_capable` — `validate.py:74-76`; SERVICES.toml has no `vision_capable` — `00-baseline.md:73`). Add `VllmVisionBackend` sibling to `VllmThinkingBackend`, not a flag on thinking backends. Pre-resize client-side: vLLM ignores per-request `min_pixels`/`max_pixels` on content parts — https://github.com/QwenLM/Qwen3-VL/issues/1434 (05-web Q3). Impact: one new backend class + one optional param preserves all existing text pipelines and satisfies model-sovereignty.

- [HIGH] **Structured output on vision calls is unreliable in repos; our fail-loud pattern is correct but untested on images.** marker: `client.beta.chat.completions.parse(..., response_format=response_schema)` then `json.loads(response_text)` — `openai.py:92-108`; on any failure returns `{}` — `openai.py:127`. Ollama: JSON schema via `"format"` key, same `{}` fallback — `ollama.py:68-73`. olmocr: free-text YAML front matter parsed by `FrontMatterParser`, optional vLLM `guided_regex` — `pipeline.py:179-212`; validates `finish_reason == "stop"` and token budget — `pipeline.py:202-206`; **not** Pydantic/JSON schema. docling API path: raw `generated_text` + `VlmStopReason` (incl. `CONTENT_FILTERED`) — `api_image_request.py:91-94,250-254`; no structured adjudication schema. Our `VllmThinkingBackend`: schema-in-prompt + `_extract_json` + `output_type.model_validate`, raises `MalformedModelOutputError` after retries — `model_backends.py:361-410`. Web: OCR is hardest hallucination category (~60% avg) — https://arxiv.org/html/2406.17115v1 (05-web Q4). Impact: copy our raise-on-failure contract, not marker's silent `{}`; expect more JSON-parse retries on vision and budget `request_limit` accordingly (D10).

- [HIGH] **Per-page results vs document verdict: aggregation is mandatory and our precedent exists, but evidence grounding contract breaks.** olmocr returns `PageResult(s3_path, page_num, response: PageResponse, is_valid, is_fallback)` per page — `pipeline.py:94-103`; document markdown assembled downstream. Dolphin folds `page_results: [{page_number, elements}]` — `demo_page.py:152-157`. tapetum_llm already aggregates per-chunk `Adjudication` → one via `aggregate_adjudications` (worst axis, min confidence, union spans) — `chunking.py:226-292`; same pattern needed for per-page VLM (`aggregate_page_adjudications`). **Contract mismatch:** `EvidenceSpan` docstring requires `quote` be an exact substring of converted markdown — `models.py:51-55`; `ground_spans` locates quotes in `state.paper_md` only — `adjudicate.py:279`, `grounding.py:51-59`. A VLM judging page images against PDF visuals will cite text visible on the image that may not appear verbatim in markdown (or may hallucinate OCR). Impact: extend schema with `source: Literal["markdown","page_image"]`, `page: int | None`, and split grounding: markdown quotes keep `ground_spans`; image-sourced findings need page-level acceptance or RaV-IDP-style re-render validation — https://arxiv.org/pdf/2604.23644 (05-web Q5).

- [MED] **Docstring vs behavior: tier-2 escalation silently absent for chunked (and would be for per-page) paths.** `_custom_adjudicate` returns early when `state.chunked` — `adjudicate.py:257-261` with comment that tier2 would 413 on full markdown. Chunked papers therefore never get deep-model re-read despite `escalation_signals` firing on aggregated tier1. `TapetumResult.escalated` is `state.tier2 is not None` — `adjudicate.py:306-307`; consumers (fusion via `fuse_verdicts`, `fusion.py:15-24`) see a tier1-only verdict labeled as final. Impact: per-page VLM loop must either (a) send images + chunk markdown per page to tier2, or (b) document `escalated=false` + `partial=true` as the contract for multi-call paths; do not let fusion treat a chunked/per-page adjudication as a full-document deep read.

- [MED] **olmocr temperature escalation on retry violates our determinism contract.** `TEMPERATURE_BY_ATTEMPT` overrides the initial `temperature: 0.0` — `pipeline.py:164-177`. Our D2/D5 pin `temperature=0, seed=0` inside backends — `model_backends.py:310-312`, root `CLAUDE.md` D5. Impact: portable retry logic is finish-reason/token-budget checks (olmocr `is_valid`) and JSON retry (ours), not temperature ramps.

- [LOW] **Marker `BaseService.__call__` signature promises `response_schema: type[BaseModel]` but returns `dict` or `{}`, not validated models.** `marker/marker/services/__init__.py:46-55` vs `openai.py:108,127`. Impact: anti-pattern for our fidelity rule; if we borrow marker's service abstraction, wrap with `output_type.model_validate` and fail on empty.

## False-pass hypothesis

Marker-style silent failure: a vision LLM call times out or returns unparseable JSON, the service returns `{}`, and downstream `handle_rewrites` skips the block (`processors/llm/__init__.py:110-128`) leaving the pre-LLM conversion unchanged. Our equivalent would be a per-page VLM that returns a malformed `Adjudication` parsed as `verdict=pass` with empty `axis_findings`, which `_custom_decide` would accept because it falls back to `working.verdict` when no axis findings — `adjudicate.py:287-290`. Mitigation: require non-empty `axis_findings` or explicit `verdict=review` on parse failure; never default to pass.

## False-fail hypothesis

Per-page VLM flags a table cell mismatch visible only on the PDF image; `EvidenceSpan.quote` is grounded against markdown (`ground_spans`), the quote is dropped as ungrounded (`adjudicate.py:295-296`), and severity-aware logic demotes to `review` — but fusion may still treat it as low-confidence noise while the real defect was image-only. Conversely, chunk-boundary instructions (`_build_triage_message` chunk_note — `adjudicate.py:372-377`) prevent false fails on split markdown; a per-page loop without analogous "judge only this page" prompt would false-fail missing cross-page references. Mitigation: page-scoped prompts (olmocr pattern: "one page out of several" — `prompts.py:43-44`) plus dual-source evidence schema.

## What would change my mind

A merged prototype where (1) `run_agent(..., images=[VisionImage(...)])` through a new `VllmVisionBackend` returns a validated `Adjudication` on one WG21 page image + markdown chunk, (2) all existing tapetum_llm text-only tests pass unchanged, and (3) debug trace shows image placeholder + text parts (not dropped), would flip the verdict to **usable** and downgrade the CRITICAL finding to implemented.
