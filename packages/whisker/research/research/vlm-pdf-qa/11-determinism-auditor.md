# 11 - Determinism-Auditor

**Verdict:** usable-with-conditions — VLM-on-PDF QA can meet our quality-stability bar only with a new multimodal backend that pins sampling, serializes every page call, pre-resizes images client-side, and copies tapetum's pure aggregation; olmocr/marker retry-and-parallel patterns are anti-patterns and must not be ported.
**Confidence:** high

## Findings
- [CRITICAL] Self-hosted VLM inference is explicitly **quality-stable, not rerun-identical**: even at `temperature=0.0` and `seed=0`, vLLM-class servers flip tokens when batch composition or floating-point reduction order changes (MoE routing, non-batch-invariant kernels). Evidence: `MODELS.md:7-8,69-77`, `CLAUDE.md:74`, `05-web.md` Q3 (vLLM multimodal serving docs). Impact: per-page axis verdicts can drift between runs; the lane must stay advisory (like existing tapetum) and the VLM service must enable batch-invariant / `--max-num-seqs=1` server flags before we claim semantic stability.
- [CRITICAL] olmocr's closest-match pipeline **deliberately breaks determinism on retries**: `TEMPERATURE_BY_ATTEMPT = [0.1, …, 1.0]` overrides the initial `temperature=0.0`, and failed pages can fire **parallel retry races** (`asyncio.as_completed`) that return whichever completion wins first. Evidence: `packages/whisker/research/repos/olmocr/olmocr/pipeline.py:85,145,164-165,343-360`; default `--max_concurrent_requests=1600` at `:1224`. Impact: copying olmocr's retry loop would violate D5 and D11; our lane must use `output_retries` with identical sampling pins, never temperature escalation.
- [HIGH] Our pipeline has **no multimodal message path** today; a VLM QA lane cannot call vLLM around the framework without losing D1/D2. Evidence: `00-baseline.md:73`, `packages/pipeline/src/pipeline/runner.py:219-225` (`user_msg: str` only), `packages/pipeline/src/pipeline/model_backends.py:288-291` (text-only `messages`). Impact: requires a vision-capable `ModelBackend` with content-parts + the same `temperature=0.0, seed=0` pins as `VllmThinkingBackend` (`model_backends.py:310-312,333-335`), not a raw HTTP client.
- [HIGH] **Rasterization must be client-pinned and pre-sized**; server-side pixel control is unreliable. PyMuPDF `get_pixmap` produced **identical PNG SHA256 across two back-to-back runs** on `n5035.pdf` (runtime, section 4), but upstream PyMuPDF gates pixmaps with **version-keyed goldens and RMS tolerance**, not cross-version byte identity. Evidence: `00-baseline.md:82-84`, `packages/whisker/research/redteam/PyMuPDF.md:3,15`; vLLM ignores per-request `min_pixels`/`max_pixels` per `05-web.md` Q3 (QwenLM/Qwen3-VL Issue #1434). Impact: fix DPI/`fitz.Matrix` as named constants, pin `pymupdf~=1.27`, pre-resize to a fixed longest-edge before base64 encode; do not depend on request-time pixel fields.
- [HIGH] Surveyed VLM services diverge on sampling under failure. **marker** starts at `temperature=0` but bumps to `0.2` on `JSONDecodeError` retry (`marker/services/gemini.py:62-65,112-113`). **docling** pins `temperature=0.0` across `vlm_model_specs.py` entries (`:35,66,…`) but sets `concurrency=4` on the API VLM path (`vlm_model_specs.py:67`), and adds an `X-Temperature` header workaround when servers ignore payload temperature (`api_image_request.py:311-313`). Impact: marker's retry-temperature pattern is not portable; docling's page concurrency violates our D11 serial default for the tapetum lane.
- [MED] **Per-page verdict aggregation can be deterministic** if we mirror the existing chunk fold: sorted axis keys, severity-aware worst-axis, min confidence, deduped evidence union. Evidence: `packages/whisker/src/whisker/tapetum_llm/chunking.py:226-292`, `adjudicate.py:205-223` (serial chunk loop, D11 comment). Page order is naturally `0..page_count-1` from `fitz`; `gather_concurrent` already sorts results by index (`runner.py:139-162`). Impact: aggregation math is ready; instability enters only from non-frozen per-page LLM outputs, not from the fold itself.
- [MED] **Downstream fusion stays deterministic** given frozen sidecars: `fuse_verdicts` is a pure function with sorted JSON fingerprint (`fusion.py:8-13,117-227`). Impact: VLM variance is isolated to the tapetum sidecar; merged advisory verdicts remain replayable once the LLM lane output is pinned.
- [LOW] PIL `LANCZOS` resize is deterministic for fixed inputs at a fixed Pillow version (used in tomd pixmap fingerprinting: `packages/tomd/tests/test_vector_golden.py:83-87`). olmocr's PIL rotation re-encode (`pipeline.py:127-128`) is deterministic given the same decoded PNG bytes. Impact: resize/rotate steps are not the primary variance source; VLM sampling and concurrent batching dominate.

## False-pass hypothesis
A table cell swap in the markdown (e.g., two adjacent numeric cells transposed) survives the deterministic whisker gate; the VLM judges the page image at reduced DPI/longest-edge and returns `pass` on consecutive runs because visual tokenization blurs the cell boundary and greedy decoding consistently misses the swap.

## False-fail hypothesis
A cosmetic heading-level jump (H2→H4) that tapetum already folds to `review`/minor on the text lane flips to `structure: fail` on one VLM run and `pass` on the next for the same frozen page PNG, because vLLM batch non-determinism changes the axis verdict at a decision boundary despite identical inputs and `temperature=0`.

## What would change my mind
A 10-run replay harness on 5 committed page PNGs through the target self-hosted VLM (`--max-num-seqs 1`, batch-invariant kernels enabled, `temperature=0`, `seed=0`, serial per-page calls) producing **byte-identical structured JSON** (verdict + axis_findings) across all 10 runs for every page.
