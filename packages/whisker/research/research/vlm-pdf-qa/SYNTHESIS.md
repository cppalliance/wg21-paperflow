# vlm-pdf-qa - Research Synthesis

**Verdict band:** usable-with-conditions   **Confidence:** med
**Decision vs our codebase:** adopt-partially

## Summary
- **The operator directive has a single most-literal fulfillment, and it is not the direct judge.** "LLM receives the PDF, judges independently, compare afterward" is honored end-to-end only by contender **C** (VLM transcribes the PDF from pixels alone -> deterministic diff vs tomd markdown -> fuse). The VLM sees the PDF and nothing else (max input independence); the "comparison" is an explicit deterministic step; then fusion compares verdicts. Meta-reviewer E's v1 (per-page image+markdown-slice judge = opus-B's contender B) instead feeds the model the tomd markdown as input, so the "independent" lane consumes the very artifact the deterministic lane scores, and the compare collapses INTO the LLM call. Evidence: `opus-B-architecture.md:40-48` (C), `:32-38` (B rejected), `opus-E-balance.md:197`.
- **The markdown-grounding contract structurally swallows the exact defect class the PDF lane exists to catch - this is decisive against the judge and free for C.** `ground_spans` binds `EvidenceSpan.quote` to `state.paper_md` (`grounding.py:170-240`, `models.py:50-60`); an ungrounded non-pass is demoted to `review` (`adjudicate.py:295-296`), so `llm_escalate_major` never fires (`fusion.py:206`). A defect present in the PIXELS but absent/wrong in the markdown (a dropped section, a token-preserving cell swap) produces evidence that cannot ground -> demoted -> swallowed. A judge (B/E-v1) is hobbled on precisely the image-only defects that motivate opening the PDF; C emits deterministic agreement scores and never touches `EvidenceSpan`/`ground_spans`. Evidence: `opus-B-architecture.md:15,76`.
- **Hallucination: a finetuned converter beats a zero-shot judge, and fusion caps the blast radius of both.** Zero-shot VLM-as-judge sits on HQH ~60% OCR-category hallucination and MTabVQA 37% EM (frontier) / 2.1-11.8% (open-source) on rendered tables (`05-web.md:60,63`). olmOCR-2-7B-1025-FP8 is a purpose-built, Apache-2.0 conversion finetune, olmOCR-Bench 82.4%, tables 84.9 (`05-web.md:15,26`). Independently, `fuse_verdicts` is asymmetric-advisory: a VLM verdict moves the combined result in only 3 narrow branches, never fails a paper, never touches `whisker --gate` (`fusion.py:12-13,142-227`; `opus-E-balance.md:19-42`). So hallucination is a signal-quality and queue-noise problem, not a safety blocker - and C has the cleaner signal.
- **opus-B's headline cost advantage for C is CONDITIONAL on a D1 carve-out that the repo's own rules argue against; corrected here.** opus-B claims C avoids the multimodal plumbing because "olmOCR runs on its OWN vLLM endpoint and returns markdown that whisker diffs" (`opus-B-architecture.md:45,78`). But olmOCR is a VLM: it consumes page IMAGES, not PDF bytes (`00-baseline.md:14-19`). Calling it through our pipeline needs the same `user_media` multimodal widening + a `VllmVisionBackend` that a judge needs (`opus-C-engineering.md:36-54`). Calling it OUTSIDE `run_agent` (raw OpenAI client / olmOCR toolkit) is a literal `chat.completions.create` - the exact thing D1 forbids ("Every LLM call goes through `run_agent`", root `CLAUDE.md`) - and forfeits the temp/seed pins, the D11 serial discipline, the prompt-injection floor (the PDF pixels are untrusted, `CLAUDE.md` prompt-injection defense), and the debug/trace fidelity artifacts, on the single highest-risk surface. **A converter LLM is exempt in letter (its markdown is not an analytical "finding"; the finding is the pure-Python diff) but not in spirit for a model eating untrusted pixels.** Net: route olmOCR THROUGH `run_agent`; C does NOT dodge the plumbing. The plumbing is a shared prerequisite for any VLM lane - build it once.
- **51% of the corpus has no PDF; "always PDF" is undefined for half of it and needs an explicit policy, not a silent skip.** 189 `.pdf`, 198 `.html`, 0 with both, 387 total (`opus-D-provenance.md:113-119`). VLM-on-PDF is structurally inapplicable to 198/387. v1 keeps HTML papers on the existing markitdown-oracle / text lane, LABELED via a `source_kind` (pdf|html|none) field so `report-merged.md` never shows an ambiguous `llm: -` (`opus-B-architecture.md:69`, `opus-E-balance.md:162-184`).
- **Fusion stays UNCHANGED and consumes verdicts only - verified.** `fuse_verdicts` reads exactly `verdict`/`soft_flags`/`hard_flags`/`ref_nid`/`suggested_verdict`/`confidence`/`axis_findings[].{verdict,severity}`/`status`, zero prompt text (`fusion.py:117-227`; `opus-B-architecture.md:14`). C drops in as an advisory `ref_*` axis / `suggested_verdict`+`axis_findings` with no fusion change.
- **The metric that everyone reported without its governing variable: DPI legibility is a SERVER `max_pixels` lever, not a client render-size lever.** Under the generic Qwen2.5-VL default `max_pixels`=1.003M, client renders at 1288/1684/2048 px ALL collapse to 840x1176 (~100 DPI, ~1.40 px/stroke); per-request `max_pixels` is ignored under vLLM (`05-web.md:52`). To actually get 144-DPI legibility you raise the SERVER cap (to ~2.0M px, ~2,014 tokens), not the client render. Evidence: `opus-A-metric-validity.md:91-105`.
- **No surveyed repo ships a QA-of-conversion judge prompt - the judge path is write-from-scratch with unmeasured FPR; C extends a pattern we already run.** olmocr/docling/MinerU prompts are all CONVERSION (`opus-C-engineering.md:104`). C instead extends whisker's existing second-converter oracle (`score.py` already runs markitdown as a second converter; `reference.py` `REFERENCE_ENGINES` is pluggable - `opus-B-architecture.md:45`).

## Recommended architecture

**Resolution of the C-vs-B tension: adopt C as the target; it wins on directive-literalism, hallucination-signal, and the grounding contract, and loses only on an engineering-cost claim that evaporates under a faithful reading of D1.** opus-E's v1 (direct image+markdown-slice judge) is opus-B's rejected contender B: it is not input-independent (consumes tomd markdown), it folds the compare into the LLM call, and - decisively - its evidence must ground against markdown, so image-only defects are demoted and swallowed by fusion. opus-E's own escape hatch (a `source=page_image` grounding carve-out) is a real patch but it modifies the escalation-feeding path and still runs a zero-shot judge with no repo prior art and unmeasured false-pass rate. C sidesteps all of it. opus-E's genuinely correct contribution - the asymmetric-advisory fusion cap - bounds the downside of EITHER design and is preserved: it is why we can ship without hallucination-paralysis, not a reason to prefer the judge.

**v1 (the target, PDF papers only, 189):**
- **Model + infra:** olmOCR-2-7B-1025-FP8 (Apache-2.0, `05-web.md:26`) on a NEW vision GPU pod. `SERVICES.toml` has no vision service today and `alliance-pod` runs a text MoE (`opus-D-provenance.md:76`); add a `[services.*]` entry with a new `vision_capable` capability flag + a `validate_capabilities` gate (`opus-C-engineering.md:52,99`). (Note: "alliance-pod VRAM is full" is an inference from a pod name, not a recorded fact - `opus-D-provenance.md:77`; the verified fact is only "no vision service exists".)
- **Call path honors D1:** route olmOCR THROUGH `run_agent`. Add a backward-compatible keyword-only `user_media: Sequence[UserContent] | None = None` threaded through `run_agent`/`run_task`/`AgentBackend.run`/`ModelBackend.run` (`None` == bit-identical to today), plus a fresh `VllmVisionBackend` registered at `BACKEND_REGISTRY` (`opus-C-engineering.md:36-54,95-100`). pydantic-ai 1.89.1 already exposes `BinaryContent`/`ImageUrl` and `agent.run([text, BinaryContent(...)])` is a supported shape (`opus-C-engineering.md:28-34`) - this is a typed widening, not an invention. `output_type=PageTranscription` keeps D6 at the boundary.
- **Rasterize:** new library-pure `tapetum_llm/vision.py`, PyMuPDF (already a dep, no poppler/pypdfium2) `page.get_pixmap(matrix=Matrix(z,z), colorspace=csRGB, alpha=False)`, PDF via `backend.get_source_path(pid)`; pattern-reference tomd's inline `get_pixmap` (`opus-C-engineering.md:81-88`). **Set the SERVER `max_pixels` to the legibility target and pre-resize client-side** (per-request pixel caps are ignored under vLLM) - legibility is a server-cap + token-cost decision, not a client render bump (`opus-A-metric-validity.md:91-105`).
- **Compare deterministically:** per-page olmOCR transcription -> deterministic diff vs the tomd markdown for that paper, reusing whisker's existing agreement scoring (`text_nid`/`teds`/table scoring). No `EvidenceSpan`, no `ground_spans` - sidesteps the grounding contract entirely.
- **Determinism/fidelity:** `temperature=0, seed=0`, serial per page (D11), `--max-num-seqs 1`, `output_retries` for JSON self-correction. Do NOT port olmocr's `TEMPERATURE_BY_ATTEMPT` ramp, `as_completed` parallel-retry race, 1600-wide concurrency, or its `pdftotext` + `max_page_error_rate` yield-optimizing fallback (`opus-C-engineering.md:56-63,119`). Fail-the-paper (`status=error`, no partial aggregate, no partial sidecar) on any raster / transcription / page-count / encrypted failure (`opus-D-provenance.md:94`; root `CLAUDE.md` fidelity). Page-count cap ~50 to kill the 2679-page outlier tail (one PDF is 42.8% of all pages, `opus-A-metric-validity.md:109`).
- **Schema/fusion:** result enters fusion as an advisory `ref_*` axis / `suggested_verdict`+`axis_findings`. Add `page` provenance and a `schema_version` to the tapetum sidecar; add the explicit `source_kind` branch. **Fusion code UNCHANGED** (`opus-B-architecture.md:65-70`). Keep the lane OFF the `whisker --gate` contract; it stays advisory.

**How the operator directive is honored:** C is the most literal reading. The olmOCR lane sees ONLY the rasterized PDF (never tomd's markdown, never det's verdict/flags - so no verdict contamination, which the current prompt lane has at `adjudicate.py:379-392`). The deterministic diff is the explicit, independent "compare the results afterward" step. Then `fuse_verdicts` compares the det verdict against the diff-derived verdict. Three independent things (whisker det signals, the tomd artifact under test, the olmOCR transcription) meet only at deterministic compare points. That is "deterministisch ist deterministisch und LLM ist LLM, die pruefen unabhaengig voneinander und vergleichen dann die Ergebnisse."

**HTML-only policy (198/387):** v1 - HTML papers keep the existing markitdown-oracle / text lane, explicitly labeled `source_kind=html` / `lane=text`; never `status=error`, never a silent skip, never `llm: -`. v2 - render staged HTML to page images and run the same olmOCR diff for pixel-parity. "Half the corpus has no PDF; v1 gives those papers the existing labeled text-lane judgment and adds rendered-HTML QA in v2."

**v2 deferrals (opus-B fallback D + opus-E deferrals):** the escalation judge - a decontaminated, image-only-inventory (contender A) VLM judge fired ONLY on papers where C's diff DISAGREES or det risk-signals fire, with mandatory page attribution and (if it emits `EvidenceSpan`s) a `source=page_image` grounding carve-out so image-only findings are not swallowed; dual grounding (`quote_pdf` subset of `page.get_text()`, DocVAL-style); rendered-HTML VLM; full-corpus batching with det-guided page sampling and resume/checkpoint; renderer decorrelation. **Trigger D iff** a >=30-paper labeled WG21 holdout shows C's diff misses the token-preserving semantic-corruption class or false-fails on formatting drift beyond ~10% (`opus-B-architecture.md:61`).

## Bugs / edge-cases in OUR code (surfaced by the comparison)
- `adjudicate.py:163-166` - `_PipelineState.partial` docstring claims the flag is set "or a chunk call failed", but NO code path sets `partial=True` on a failed chunk; a failed chunk aborts to `status=error` (stronger, so safety is intact). Fix direction: correct the docstring to match the code (`opus-D-provenance.md:98-105`).
- `adjudicate.py:379-392,413-424` - the current LLM prompt injects the det verdict, hard/soft flags, and metrics (`uni=/cov=/lossy_tables=/...`) and tells the model to focus on the flagged dimension = verdict contamination that violates the "judge independently" directive. Fix direction: strip all det signals from any surviving prompt lane; C inherits this for free by not using the prompt lane (`opus-B-architecture.md:66`, `opus-E-balance.md:67-75`).
- `models.py:50-141` - no `page` field anywhere in `EvidenceSpan`/`AxisFinding`/`TapetumResult`, so per-page findings cannot be attributed ("table wrong on page 7"). Fix direction: add `page: int` + `schema_version` before extending the sidecar (`opus-B-architecture.md:67-68`).
- Report/consumer ambiguity: HTML-only papers currently conflate "no PDF, judged by text lane" / "not selected" / "VLM failed" into one `llm: -` state. Fix direction: explicit `source_kind` (pdf|html|none) + `lane` (vlm|text) on the sidecar (`opus-E-balance.md:176-178`).
- `docling api_image_request.py:231,235,258,260` (import target, not ours) fail-silent returns empty `("",0,UNSPECIFIED)`; if any of its logic is ported, INVERT it - raise/fail the paper, never return empty (`opus-C-engineering.md:24,111`).

## Top portable detail
**olmOCR-2-7B-1025-FP8 as an Apache-2.0, self-hostable, finetuned CONVERSION model used as the independent PDF lane, plugged into whisker's existing pluggable second-converter oracle instead of a from-scratch judge.** It is the one asset that simultaneously satisfies model-sovereignty (open weights, self-hosted vLLM), dodges the grounding contract (deterministic diff, no `EvidenceSpan`), and minimizes hallucination exposure (olmOCR-Bench 82.4% vs a zero-shot judge's ~60% OCR-category hallucination). Code anchor for the extension point: whisker `reference.py` `REFERENCE_ENGINES` (pluggable) + `score.py` markitdown second-converter agreement scoring (`opus-B-architecture.md:45`); weights + serving recipe at `05-web.md:26,32`.

## Flip conditions
- **Up to `usable` (high):** a >=30-paper labeled WG21 holdout shows C's deterministic diff yields non-trivial incremental recall of real conversion defects over the current text lane at an operator-acceptable false-fail rate.
- **Down to `garbage`:** the same holdout shows incremental recall ~= 0 (`opus-E-balance.md:221-227`), OR a live self-hosted olmOCR endpoint cannot return rerun-stable transcriptions at `--max-num-seqs 1` (breaks the determinism invariant, `opus-E-balance.md:248`).
- **Re-open C-vs-judge:** if the operator formally rules a converter LLM is D1-exempt AND accepts calling olmOCR outside `run_agent`, C's cost advantage returns and it becomes strictly the smallest build; conversely, if two independent converters are shown to make correlated errors on the WG21 class beyond ~10%, escalate to fallback D (add the decontaminated image-only-inventory judge on disagreements only).
