# 141 - litellm-Retry-Fallback

**Verdict:** usable-with-conditions — litellm's layered retry→weighted-intra-group-failover→cross-group-fallback pattern is the right blueprint for whisker cross-pod transport rescue, but archived fleet logs show **0/6 error tombstones** from transient 404/timeout; failover is resilience insurance paired with persona 21 sharding, not a cold-run speed lever.
**Confidence:** high

## Findings

- [CRITICAL] **litellm separates retry policy by exception class; rate-limit gets exponential backoff, generic API errors get constant retry.** Evidence: async wrapper maps `openai.RateLimitError` → `retry_strategy="exponential_backoff_retry"`, other `openai.APIError` → `"constant_retry"` (`research/repos/litellm/litellm/utils.py:1829-1833`); tenacity implements exponential `wait_exponential(multiplier=1, max=10)` vs bare attempt cap (`research/repos/litellm/litellm/main.py:5712-5719`, `5738-5745`). Per-class budgets live in `RetryPolicy`: `TimeoutErrorRetries`, `RateLimitErrorRetries`, `InternalServerErrorRetries`, etc. (`research/repos/litellm/litellm/types/router.py:95-108`), resolved by exception type in `get_num_retries_from_retry_policy` (`research/repos/litellm/litellm/router_utils/get_retry_from_policy.py:42-54`). Our lane: single 2-attempt loop for all transport classes with fixed `2 ** (attempt+1)` sleep (`packages/pipeline/src/pipeline/model_backends.py:300-350`), no rate-limit backoff differentiation. Impact: **0 s** on 3003 s baseline (55 JSON/BPE retries already succeed at 2.4%, `00-baseline.md:60-61`); quality risk **none** for transport-only tuning.

- [CRITICAL] **Router retry stack: same-deployment retries first, then weighted intra-group failover, then cross-group fallback — bounded by `max_fallbacks`.** Evidence: `async_function_with_fallbacks` calls `async_function_with_retries` first (`research/repos/litellm/litellm/router.py:6380-6382`); on exhaustion enters `async_function_with_fallbacks_common_utils` which tries `_maybe_run_weighted_failover` when `enable_weighted_failover=True` (`router.py:6186-6197`, `6019-6072`: exclude `failed_deployment_id`, skip cooldown'd deployments via `_async_get_cooldown_deployments`, re-pick from remaining same model group); then cross-group `run_async_fallback` (`research/repos/litellm/litellm/router_utils/fallback_event_handlers.py:124-165`). Defaults: `num_retries` → `openai.DEFAULT_MAX_RETRIES` (`router.py:559-564`), `max_fallbacks` → `ROUTER_MAX_FALLBACKS=5` (`research/repos/litellm/litellm/constants.py:9`). Our lane: one pod, 2 attempts, paper tombstone (`packages/whisker/src/whisker/tapetum_llm/cli.py:747-769`, `1382-1387`); **no second deployment try**. Impact: **0 s** today (no transport-killed papers in logs, see below); prevents future mid-run pod-hiccup tombstones when persona 21 dual-pod sharding is live. Quality risk **LOW-MED** (same model, different scheduler — within persona 21 variance budget, `21-dual-pod-sharder.md:16`).

- [HIGH] **404 is NOT retried on the same deployment in litellm router; it triggers cooldown and failover instead.** Evidence: `should_retry_this_error` raises immediately on `litellm.NotFoundError` (`research/repos/litellm/litellm/router.py:6707-6708`); `_is_cooldown_required` puts HTTP 404 into cooldown (`research/repos/litellm/litellm/router_utils/cooldown_handlers.py:80-81`); `APIConnectionError` strings skip cooldown (`cooldown_handlers.py:57-61`). Our backend **does** retry `openai.NotFoundError` twice on the **same** pod before tombstone (`model_backends.py:341-350`) — the wrong pattern for RunPod proxy 404 storms (`packages/whisker/research/llm-batching/18-load-splitter.md:8`: twin pod returned 404 on every path). Impact: cross-pod failover after first 404 (not second same-pod retry) would rescue papers that today tombstone; **0 papers rescued in v10 logs** (no transport errors logged). Quality risk **none** for transport-only failover.

- [HIGH] **`num_retries` × `cooldown_time` interaction: retries burn same deployment; cooldown evicts it from healthy pool; failover picks alternates.** Evidence: `async_function_with_retries` loop (`router.py:6555-6616`) re-picks healthy deployments each attempt; `_async_get_healthy_deployments` excludes cooldown cache entries (`router.py:6052-6058`); `cooldown_time` defaults 5 s (`constants.py:32`), `allowed_fails` gates percent-fail threshold before cooldown (`cooldown_handlers.py:151-194`). Request timeout layers: router `timeout` / `stream_timeout` (`router.py:313-314`), global `litellm.request_timeout` default 6000 s (`constants.py:385-390`), per-attempt resolver in `request_timeout_resolver.py:20-28`. Our timeouts: unit/page 120 s (`constants.py:197,241`), paper budget 900 s + additive (`cli.py:152`, `00-baseline.md:53-55`); no deployment cooldown concept. Impact: failover design should **not** cooldown primary pod (whisker has no deployment registry); one alternate-pod attempt per failed call suffices. **0 s** wall saving.

- [HIGH] **Minimal whisker failover design (judge_task path, whisker-local, no pipeline edit).** Mirror litellm `enable_weighted_failover` at call granularity: extend `run_judge_task` (`packages/whisker/src/whisker/tapetum_llm/judge_task.py:52-74`) with optional `fallback_agents: Sequence[AgentBackend]` (same-model alternate pods from persona 21's `live_pods` set). On primary `agent.run` failure, catch **only** transport exceptions matching backend retry set (`NotFoundError`, `APIConnectionError`, `InternalServerError`, `APITimeoutError` — `model_backends.py:341-342`); **do not** catch `MalformedModelOutputError` / `ValidationError` (JSON/schema stays fail-closed). Try each fallback agent once (each inherits backend's 2-attempt retry). Wire in `cli.py`: when `--shard-pods` active, pass `[assigned_pod_agent, *other_live_pods_agents]` into all `run_judge_task` call sites (pdf_judge, unit_judge, metadata). Fingerprint unchanged: encode shard **set** not per-call pod (`21-dual-pod-sharder.md:14-15`, `cli.py:566-619`). Determinism: fallback changes which pod served a rescued call — same weights, acceptable within documented ≥25% advisory flip budget (`21-dual-pod-sharder.md:16`, `tapetum_llm.md:31`); per-paper primary assignment stays stable, failover only on transient error. Impact: **0 s** on current 3003 s run; eliminates false `error` tombstones on future pod blips. Quality risk **LOW** (transport rescue only).

- [MED] **Fleet log quantification: transient pod errors killed 0 papers in archived runs.** Grep `_scratch/whisker-fullrun/` (v10-cold-stderr, llm-stderr, stderr, v10-warm-stderr): **0** lines matching `Transient API error`, `NotFoundError`, `APITimeoutError`, `APIConnectionError`, HTTP 502/503/524, or `health probe failed`. All error tombstones are semantic: JSON exhaustion (P3850R0, P3984R0, P4093R1), metadata validator (P4178R0, P3400R3), ideal verification (P4182R0, P4228R0) — not transport. The 404 storms referenced in persona 21/18 are **infra probe** failures on `h200x8-deepseek-v4-pro` at batch start (`18-load-splitter.md:8`), not mid-run per-call kills. Impact: failover is **correctness/resilience**, not the path to 5-10 min; stacked with sharding (~1.9×, persona 21) it prevents reliability regressions.

- [LOW] **Pre-batch health gate probes one pod only; litellm probes deployment health continuously via cooldown cache.** Evidence: `_probe_llm_endpoint` runs once on effective `fast` slot before gather (`cli.py:910-951`, `_HEALTH_PROBE_TIMEOUT_SECONDS=30.0` at `cli.py:205`); does not re-probe mid-run or per shard pod. litellm `_async_get_cooldown_deployments` filters unhealthy deployments on every retry/failover pick (`router.py:6052-6058`). Extend persona 21's dual-probe pre-gather (`21-dual-pod-sharder.md:12`) — no continuous cooldown registry needed for two static RunPod endpoints. Impact: **0 s**; avoids assigning ~50% of papers to dead pod at batch start.

## False-pass hypothesis

Cross-pod failover on a **JSON truncation** that happens to succeed on the alternate pod's different batch composition: primary pod returns truncated JSON (fail-closed today), fallback pod completes the object, paper passes with a verdict that would have been `review`/`fail` on consistent re-run. Mitigation: restrict failover to transport exceptions only; never failover on `MalformedModelOutputError` / `ValidationError` (`model_backends.py:371-410`).

## False-fail hypothesis

Failover retries a **404 on a permanently dead twin pod** before tombstoning, adding ~40-80 s (2 pods × 2 backend attempts × ~20 s/call, `00-baseline.md:24-25`) to papers that would have failed fast — inflating wall on bad infra days without saving coverage. Mitigation: persona 21 pre-gather dual health probe; skip dead pods from `live_pods` before assignment (`21-dual-pod-sharder.md:12`).
