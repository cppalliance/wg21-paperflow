# 46 - Warm-Run-Auditor

**Verdict:** usable-with-conditions — the 64.8 s warm run is dominated by six full re-cascades forced by fingerprintless error tombstones; tombstone fingerprints plus `--retry-errors` cut steady-state nightly wall to roughly hashing plus report (<30 s) without weakening fail-closed semantics, provided transient `PdfLaneError` papers stay retry-eligible.
**Confidence:** high

## Findings

- [CRITICAL] **Warm wall is ~85% LLM re-cascade, not fingerprint overhead.** Log footer: `381 total: 6 evaluated, 0 pass, 3 review, 0 fail, 3 error, 375 skipped (incremental) (2 model retries) in 64.8s` (`v10-warm-stderr.txt`). Only six papers left the skip path; the other 375 matched an existing sidecar fingerprint (`cli.py:1175-1202`). At ~6 serial calls/paper and ~20 s/call (`00-baseline.md:22-25`), six parallel papers imply **~42–48 LLM calls ≈ 52–60 s fleet-equivalent** at 16 server slots, closing the measured 64.8 s with startup, hashing, and report. Impact: tombstone skip fixes **~50–58 s/night** on steady warm runs; **0 s** on the 3003 s cold fleet unless paired with call-cut levers. Quality risk: **none** if error sidecars stay `status="error"`.

- [HIGH] **64.8 s decomposition (log-grounded).** (1) **Startup + health probe ~1–2 s:** service inventory lines, then `GET .../health` → `LLM endpoint 'alliance-pod' healthy` (`v10-warm-stderr.txt`; probe at `cli.py:910-951`, budget `_HEALTH_PROBE_TIMEOUT_SECONDS = 30.0` at `cli.py:205`). (2) **381-paper fingerprint pass ~5–8 s:** every worker calls `_compute_fingerprint` (SHA-256 of markdown + source via `_sha256_file`, `cli.py:439-445`, `597-598`) and `_fingerprint_matches` (read sidecar JSON, `cli.py:622-661`) before skip or adjudicate; 375 exit early with no LLM. Batch mode suppresses per-skip INFO (`cli.py:1089`, `1196-1198`), so this phase is silent in the log. (3) **Six full cascades ~52–58 s:** only logged outcomes are P4178R0/P3850R0/P4093R1 `pdf-judge verdict=review` plus three ERROR lines (`v10-warm-stderr.txt`). (4) **Merged report ~1–2 s:** `_build_merged_report` after footer (`cli.py:1431-1432`, `797-838`) → `Merged report -> ... report-merged.md/json` and fusion footer (`v10-warm-stderr.txt`). Impact: after tombstone fix, phases (1)+(2)+(4) alone set steady-state ceiling **~8–15 s**; (3) drops to zero when all fingerprints match.

- [CRITICAL] **Error tombstones have no fingerprint, so they ALWAYS re-run the full cascade.** `_write_error_tombstone` emits only `pid`, `status`, `error`, optional `partial_progress` — no `fingerprint` key (`cli.py:747-769`). `_read_existing_fingerprint` returns `None` when absent (`cli.py:631-632`), so `_fingerprint_matches` is always False (`cli.py:648-650`) even when markdown, source, prompts, and `_LANE_VERSION` are unchanged. Warm log confirms three persistent failures: **P3984R0** `PdfLaneError` (monolith JSON truncated after 2 attempts), **P4182R0** and **P4228R0** `IdealVerificationError` (ideal quote ungrounded after judge completed) (`v10-warm-stderr.txt`; ideal raise at `ideal_verify.py:107-109`). **P4182R0** logged `verdict=review` then failed on ideal — judge output discarded, tombstone replaces sidecar (`cli.py:1373-1387`). Impact: **≥3 papers × ~6–8 calls ≈ 18–24 calls/night forever** (~25–35 s wall at 16 slots after the three one-time review papers gain fingerprints); **2 IdealVerificationError** paths are deterministic until ideal/candidate edits. Quality risk: **none** for skip-if-unchanged; **LOW–MED** for **P3984R0** if JSON parse is transient (2 retries in footer).

- [HIGH] **Tombstone fingerprint + error-class skip is compatible with fail-not-partial.** Fail-closed requires honest error surfacing, not nightly re-proving the same failure (`CLAUDE.md` Fidelity). Skipping re-adjudication while retaining `status="error"` sidecars keeps fusion unusable (`fusion.py:154-159`, `142-143`) and exit 1 when any error tombstone remains (`cli.py:1434`). Store at failure time: full `_compute_fingerprint(...)` plus `error_class: type(exc).__name__` and optional `error_fingerprint` hash of the message. Incremental match on `(fingerprint, error_class)` → skip LLM, preserve tombstone. **`--retry-errors`** (or `--force`) bypasses error skip for operator-driven retry after pod fixes or prompt bumps (`_LANE_VERSION` already invalidates all sidecars on logic change, `cli.py:99-117`). Impact: steady-state **381/381 skip**, **~8–15 s** nightly (hash + report), vs **~25–35 s** with three eternal re-cascades. Quality risk: **LOW** if transient errors expose `--retry-errors`; **HIGH** if skip hides a fixable mid-cascade failure without retry flag.

- [MED] **Warm run also burned judge work before two deterministic ideal failures.** P4182R0 completed pdf-judge (`conf=0.98`, `risk_signals=5`) then ideal failed (`v10-warm-stderr.txt`). Ideal runs after full cascade (`cli.py:1239`, `1317`); exception path writes tombstone only (`cli.py:1382-1387`), not the completed judge payload. **~8 judge calls wasted** before the same `IdealVerificationError` (`37-ideal-verifier-accountant.md:12-13`). Fingerprint skip on tombstones avoids repeat judge spend; **ideal-first** or **persist-judge + ideal-only retry** are orthogonal saves (~12–18 s/warm) but do not replace tombstone fingerprints for mid-cascade `PdfLaneError`. Impact: combined tombstone fingerprint + ideal-first on 3 ideal-bearing papers saves **~40–50 s** on warm reruns vs status quo. Quality risk: **HIGH** if ideal `review` short-circuits source-aware judge (`37-ideal-verifier-accountant.md:22`).

- [MED] **Three review outcomes were one-shot warm cost; they will skip next night.** P4178R0, P3850R0, P4093R1 persisted review sidecars with fingerprints on success (`cli.py:1273-1275`, `1358-1360`). Second warm run evaluates only the three error tombstones unless tombstone fix lands. Impact: without fix, steady-state warm **~25–35 s** (3 papers), not 64.8 s. Quality risk: none.

- [LOW] **Merged report is cheap and mandatory on full runs.** Pure disk I/O over 381 sidecars (`cli.py:797-802`); log shows immediate post-footer write (`v10-warm-stderr.txt`). `--fuse-only` can rebuild without LLM (`cli.py:841-887`). Impact: **~1–2 s** either way; not a speedup target. Quality risk: none.

## False-pass hypothesis

Skipping re-adjudication when an error tombstone’s fingerprint matches but the underlying bug was a **transient** `PdfLaneError` (JSON truncation, `v10-warm-stderr.txt` P3984R0): the sidecar stays `status="error"`, so fusion still treats tapetum as unavailable — no false pass. A false pass would require promoting error to pass without re-run; this design does not.

## False-fail hypothesis

Storing fingerprint on tombstone without `--retry-errors` after a **fixed** pod outage: inputs unchanged, lane logic unchanged, tombstone still says `ConnectionError` while the pod is healthy — nightly skip preserves a stale error class until operator runs `--retry-errors` or bumps inputs. That is honest stale error, not a false fail of a good conversion, but it blocks automatic recovery from transient infra faults.

## What would change my mind

A second warm run log showing **>3 evaluated papers** with unchanged inputs (proving extra tombstone classes or fingerprint false misses), or measured fingerprint phase **>15 s** on the same 381-paper corpus (would shift the “<30 s steady state” ceiling upward).
