# 92 - vllm-APC-Internals

**Verdict:** usable-with-conditions — vLLM APC is real and matches our DeepSeek-V4-Pro pod, but tapetum's per-call random guard tag at the system-prompt tail currently breaks hash-chain reuse for the full document across all 6 serial calls; fix prompt layout + set `VLLM_PREFIX_CACHE_RETENTION_INTERVAL=32768` before expecting PR-#43447-class hit rates.
**Confidence:** high

## Findings

- [CRITICAL] Block-level prefix identity is **token-exact from position 0**: each hash is `hash((parent_block_hash, tuple(block_token_ids), extra_keys))` chained from the prompt start; only **full** hash blocks are stored (`kv_cache_utils.py:596-623`, `get_request_block_hasher` at `705-746`, design note at `docs/design/prefix_caching.md:22-22`). Impact: our 6 serial calls share **zero document KV** today because each call appends a fresh `SRC{hex}` guard to the system prompt (`unit_judge.py:767-768`, `pdf_judge.py:638-639`), and any divergence in an earlier block poisons **all** downstream block hashes including identical `candidate_md` bytes (`kv_cache_utils.py:596-623`). Quality risk: **none** if we only move the guard (same delimiters, same injection defense); **high** if we drop guards or reuse tags across tenants.

- [CRITICAL] DeepSeek-V4 APC requires **both** hybrid coordinator convergence **and** selective SWA retention. DSV4 uses `HybridKVCacheCoordinator` with multiple `UniformTypeKVCacheSpecs` groups (full MLA + sliding-window MLA) (`kv_cache_utils.py:1741-1748`, `kv_cache_coordinator.py:521-708`); cache hits must satisfy **every** group via iterative fixed-point (`685-708`). SWA layers use `reachable_block_mask` + `VLLM_PREFIX_CACHE_RETENTION_INTERVAL`: dense default evicts local SWA checkpoints under concurrency → **0% prefix hits** on DSV4 traces; `32768` retains segment tails + replay boundaries (`single_type_kv_cache_manager.py:1000-1027`, `envs.py:1109-1118`, `05-web.md` PR #43447). Impact: without `VLLM_PREFIX_CACHE_RETENTION_INTERVAL=32768` on `alliance-pod`, APC is effectively off for our model regardless of prompt layout. Quality risk: **none** (KV reuse only); mis-set interval can reduce hit rate, not change logits.

- [HIGH] Default **hash granularity is 16 tokens** (`CacheConfig.DEFAULT_BLOCK_SIZE`, `cache.py:47-48`, `254-255`); `hash_block_size` equals `block_size` unless `--prefix-match-unit` is set (`kv_cache_utils.py:637-688`, `cache.py:56-66`). DSV4 MLA pages are **584 B/storage token** with `fp8_ds_mla` (`kv_cache_interface.py:399-403`, `attention.py:614-624`). Impact: after fixing guard placement, calls 2–6 reuse monolith doc KV in **16-token block steps**; a one-token tokenizer drift (whitespace, punctuation) breaks sharing at that boundary. At ~20 s/call × ~5 redundant full prefills/paper × 381 papers, guard fix + retention is on the order of **~15–20 min wall** if hits reach the PR #43447 ~74% regime (3003 s → ~600–900 s band, quality-stable). Quality risk: **low** if tokenizer input strings are unchanged.

- [HIGH] **Observability**: Prometheus counters `vllm:prefix_cache_queries` and `vllm:prefix_cache_hits` (`loggers.py:584-601`, `docs/design/metrics.md:29`); per-request stats accumulate at schedule time as `num_new_local_computed_tokens` (`scheduler.py:959-963`, `kv_cache_manager.py:214-223`, `PrefixCacheStats.record` at `stats.py:131-142`). Hit rate = `hits / queries` (`stats.py:107-111`). Impact: validate any lever by comparing hit rate on a 10-paper canary before/after guard move; target **>50% queries hit** on serial 6-call papers. Quality risk: **none** (read-only metrics).

- [HIGH] **LRU eviction** pops the free-queue head; cached blocks at the head are evicted on allocation pressure (`block_pool.py:664-667`, `679-700`, `FreeKVCacheBlockQueue` ordering at `kv_cache_utils.py:193-200`). Freed request blocks re-enter tail **reverse order** (tail blocks evicted first) (`block_pool.py:719-740`, `docs/design/prefix_caching.md:196-208`). Impact: at **client concurrency 32** × **16 server slots**, 381 distinct papers create scan pollution; hot shared-document prefixes survive only while `(num_gpu_blocks − active blocks)` stays large. Quality risk: **none**; cold misses cost time only.

- [MED] **Cache capacity math** (startup logs `GPU KV cache size: {tokens}` from `get_kv_cache_capacity`, `kv_cache_utils.py:2155-2163`, `1801-1811`): one shared block pool (`num_blocks` from packed DSV4 layout, `kv_cache_utils.py:1384-1388`); max concurrent **full-length** requests ≈ `num_blocks / Σ_g cdiv(max_memory_usage_bytes_g, page_size_g)` (`kv_cache_utils.py:937-958`). Prefix-cache **residency** for whole documents ≈ `floor((num_blocks − blocks_in_use) / blocks_per_paper)` where `blocks_per_paper ≈ Σ_g cdiv(prompt_tokens, block_size_g)` for full-attention groups plus SWA cap (`SlidingWindowSpec.max_admission_blocks_per_request`, `kv_cache_interface.py:567-588`). Example: **P ≈ 40k prompt tokens**, `block_size=16` → ~2.5k full-MLA blocks/paper; with **~200k–400k** total blocks typical post-weights on H200, expect **~10–30 full papers' prefixes** simultaneously if idle, but **1–3 hot papers** under 32-way churn without identical prompts. Impact: cross-paper reuse negligible; **in-paper serial reuse** is the lever. Quality risk: **none**.

- [MED] **Prompt layout conditions for 6-call reuse** (after guard fix): (1) identical `all_token_ids` prefix through shared content (`request.py:257-260`, `668-668`); (2) same `cache_salt`/LoRA/MM extras or none (`kv_cache_utils.py:430-447`, `558-593`); (3) `enable_prefix_caching=True` default (`cache.py:93-94`); (4) `skip_reading_prefix_cache=False` (`request.py:286-296`); (5) last prompt token always recomputed (`max_cache_hit_length = num_tokens - 1`, `kv_cache_manager.py:249-255`); (6) MTP/EAGLE drops last matched block (`FullAttentionManager.find_longest_cache_hit`, `742-744`). Target shape: `[static system + CONVERSION_CONTRACT] + [full candidate_md] + [call-specific suffix]`, guard delimiters **inside** injected untrusted regions only (`pipeline/tools.py:55-62`). Metadata call still misses monolith prefix (different system prompt, `unit_judge.py:245`). Impact: **~5/6 calls** can share doc KV per paper (~80–85% prefill skip on doc body), not 6/6. Quality risk: **none** if guard stays on untrusted spans.

- [LOW] APC overhead when prefixes do not match: hash management adds throughput cost at low hit ratio (`05-web.md` squeezebits ~37% overhead). Impact: until guard/retention fixes land, enabling APC may **hurt** slightly. Quality risk: **none**.

## False-pass hypothesis

Moving `guard_instruction(tag)` from the system tail into only the untrusted user spans would let calls 2–6 skip document prefill while the model still sees per-call guard text inside `<<<SRC…>>>` envelopes; if we accidentally remove guards from system entirely, prompt-injection via `candidate_md` reaches the judge contract without the framework floor's delimiter discipline — defects could be missed or hallucinated (CLAUDE.md prompt-injection defense). Guard must stay on injected content, not disappear.

## False-fail hypothesis

Setting `VLLM_PREFIX_CACHE_RETENTION_INTERVAL=32768` without aligning to `scheduler_block_size` (must be a non-negative multiple, `kv_cache_coordinator.py:30-57`) causes startup `ValueError` and takes the pod offline — fleet run fails closed with 6 errors, not silent quality drift.

## What would change my mind

A 10-paper canary on `alliance-pod` with `--kv-cache-dtype fp8`, `VLLM_PREFIX_CACHE_RETENTION_INTERVAL=32768`, guard moved off the system tail, logging `vllm:prefix_cache_hits / vllm:prefix_cache_queries` per paper through all 6 serial calls: if hit rate stays **<10%** on call 2+, APC is not the bottleneck and payload-scoping/call elimination dominate.
