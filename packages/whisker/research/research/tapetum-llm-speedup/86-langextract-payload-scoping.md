# 86 - langextract-Payload-Scoping

**Verdict:** usable-with-conditions — langextract proves bounded-chunk LLM calls plus mechanical char-offset alignment is a sound extraction pattern, but our post-hoc `ground_spans` only validates emitted quotes; it cannot replace full-candidate unit-check payloads for defect detection without a scoped window plus full-document presence oracle (persona 13/75 hybrid).
**Confidence:** high

## Findings

- [CRITICAL] **LangExtract never sends the full document to the LLM; chunk size is a first-class cost knob with a 5× default split.** Evidence: high-level `extract()` defaults `max_char_buffer=1000` and documents that smaller buffers increase API call count (`extraction.py:53`, `95-96`, `109-110`); low-level `Annotator.annotate_documents` / `annotate_text` default **200 chars** (`annotation.py:213`, `536-552`); `ChunkIterator` breaks on sentence boundaries then token boundaries when a sentence exceeds the buffer (`chunking.py:343-383`, `425-439`). Impact: an 80k-char WG21 paper at Annotator defaults → **~400 LLM calls** vs our **~6 calls/paper** (`00-baseline.md:22-23`); raising buffer toward our scale is the inverse lever (fewer calls, larger prefill per call). Quality risk: langextract README warns accuracy drops with very large buffers; our unit checks are judge tasks, not open extraction, so the tradeoff differs.

- [CRITICAL] **Global document coordinates are recovered mechanically after each scoped call, not by LLM context.** Evidence: per chunk, `resolver.align(extractions, text_chunk.chunk_text, token_offset, char_offset, ...)` aligns against **chunk text only** (`annotation.py:422-429`); `token_offset = text_chunk.token_interval.start_index` and `char_offset = text_chunk.char_interval.start_pos` lift intervals to document-global indices (`annotation.py:411-419`); `get_char_interval` maps token spans to `CharInterval(start_pos, end_pos)` on the full tokenized document (`chunking.py:216-243`); tokenizer attaches per-token `char_interval` (`core/tokenizer.py:108-131`). Impact: this is the exact architecture persona 13/75 sketch — **LLM sees a window, presence is verified mechanically against the full doc**. We already implement the alignment half post-hoc via `ground_spans` on full markdown (`grounding.py:248-335`, monotonic DP port at `147-214`). Quality risk: langextract alignment runs **per chunk against chunk text**; extractions whose verbatim span crosses a chunk boundary may fail all three tiers unless the model emits text that fits entirely inside one chunk's aligned region.

- [HIGH] **Three-tier fuzzy alignment: monotonic exact DP → difflib lesser → LCS subsequence with coverage/density gates.** Evidence: defaults `_FUZZY_ALIGNMENT_MIN_THRESHOLD = 0.75`, `_FUZZY_ALIGNMENT_MIN_DENSITY = 1/3` (`resolver.py:57-58`); `Resolver.align()` runs exact DP first (`exact_alignment_algorithm="dp"`, `resolver.py:948-959`, `327-341`), then difflib `get_matching_blocks` for `MATCH_LESSER` (`resolver.py:962-1018`), then LCS fuzzy on unaligned extractions (`resolver.py:1027-1065`, `_accept_lcs_match` at `1377-1404`, `_best_lcs_spans` O(n·m²) at `1287-1293`); plural normalization via `_normalize_token` (`resolver.py:1275-1281`). Impact: we ported **Tier 1 only** into `ground_spans` and deliberately rejected LCS Tier 3 (`grounding.py:14-21`, `309-308` post-alignment guard). Naïvely copying langextract fuzzy tiers would **loosen** quote grounding vs our `EVIDENCE_FUZZY_FLOOR=0.90` document-level check. Quality risk: LCS accepts gapped wrong spans when three tokens match as a subsequence inside noise (`resolver.py:1287-1363`, `1377-1404`).

- [HIGH] **Cross-chunk boundary handling is opt-in and partial, not automatic.** Evidence: `context_window_chars` defaults **None (disabled)** (`extraction.py:65`, `161-164`); when enabled, `ContextAwarePromptBuilder` prepends `"[Previous text]: ..."` plus the **tail** of the previous chunk (`prompting.py:191-261`, `_update_state` at `268-276`); live test uses `max_char_buffer=60` + `context_window_chars=50` to extract pronoun-linked facts from two chunks (`tests/test_live_api.py:788-854`); within a single pass, extractions from all chunks append to `per_doc[document_id]` with **no deduplication** (`annotation.py:309-311`, `431-432`); `extraction_passes>1` re-runs the full chunk pipeline and merges with first-pass-wins on overlapping `char_interval` (`annotation.py:477-491`, `_merge_non_overlapping_extractions` at `46-84`). Impact: langextract accepts **recall loss at boundaries** unless operators pay extra context-window chars or multi-pass cost; our ANYWHERE unit-check rule (`unit_judge.py:137-139`) is stricter — content on page N may live under page N-1's heading after tomd join. Quality risk: **HIGH** if we drop full markdown without an equivalent presence oracle.

- [HIGH] **Post-hoc `ground_spans` is sufficient for quote verification/refutation but NOT sufficient to drop full-doc unit-check payloads today.** Evidence: `ground_spans` / `classify_candidate_evidence` run on the **full** on-disk candidate after the LLM returns (`unit_judge.py:713`, `728-729` → `grounding.py:419-438`); mechanical keyword counts already scan full `candidate_md` post-call (`unit_judge.py:634`); but `_check_one_unit` embeds entire `candidate_md` in the prompt (`unit_judge.py:769-776`) because the model must judge ANYWHERE presence **before** emitting defects. Impact: scoped payload saves **~7% fleet wall** at P50 (~198 s of 3003 s on unit prefill alone, persona 13 model); **cannot** reach 5–10 min target by scoping alone (`00-baseline.md:92-94`, decode still ~93% per-call wall). Quality risk: if we shrink the LLM payload to a section window **without** a compact full-doc presence index, cross-page join tails false-pass silently when the model returns `pass` with no quotable defect (`13-payload-scoper.md:26-27`).

- [MED] **LangExtract's parallel batching amplifies call volume independently of chunk size.** Evidence: `extract()` ships `batch_length=10`, `max_workers=10` (`extraction.py:57-58`); Annotator itself defaults `batch_length=1` (`annotation.py:214`); docstring warns `extraction_passes>1` linearly multiplies token reprocessing (`extraction.py:154-160`, `annotation.py:237-241`). Impact: our portable lesson is **payload bounding + mechanical alignment**, not their default concurrency; in-paper serial chain stays (`00-baseline.md:36-42`). Quality risk: none for scoping analysis; copying their worker defaults would violate D11 quality-stability.

- [MED] **Hybrid path aligned with langextract + persona 13/75: scoped source/page window in the prompt, full-doc mechanical checks unchanged.** Pattern: (1) send H2-bounded candidate section ± neighbor for the routed page (olmocr-style bounded auxiliary, `75-olmocr-payload-design.md:16`); (2) add sorted normalized phrase hashes or token-set sketch so ANYWHERE semantics survive (`13-payload-scoper.md:18-19`); (3) keep `ground_spans`, `classify_candidate_evidence`, and `_mechanical_count` on full `candidate_md` (`grounding.py:248-335`, `unit_judge.py:634`). Impact: captures most prefill win on P90 papers (~139K chars, `13-payload-scoper.md:12`) while preserving fail-closed quote verification. Quality risk: **MEDIUM** if presence index normalization misses dehyphenated or wording-markup forms that fuzzy grounding abstains on (`grounding.py:521-531`).

## False-pass hypothesis

Drop full `candidate_md` from unit checks and rely on post-hoc `ground_spans` only: on a cross-page join, page-13 tail text sits under page-12's heading; the LLM sees only a page-local window, returns `verdict=pass` with zero defect groups, and grounding never runs because there are no quotes to verify — the same silent-miss class persona 13 documents for section-only scoping (`unit_judge.py:137-139`, `13-payload-scoper.md:26-27`). Langextract avoids this for **extraction** by re-scanning every chunk and merging offsets; we judge **conversion fidelity**, so undetected defects do not surface as unaligned extractions.

## False-fail hypothesis

Keep full-doc post-hoc grounding but add a mechanical presence index in the prompt: model flags a dangling join fragment as missing; index shows the normalized phrase exists document-wide; model caps at pass/review per ANYWHERE rule; `classify_candidate_evidence` still refutes any emitted missing-quote against full markdown — verdict unchanged, prefill drops. Langextract's `context_window_chars` tail alone would **not** suffice for our join case because the missing tail may be two pages back, not just the previous chunk (`prompting.py:258-261` vs tomd cross-page join semantics).

## What would change my mind

Holdout replay (48-paper protocol, persona 47) showing unit checks rewritten with langextract-style bounded windows (≤8K chars candidate slice + compact full-doc presence index) while **only** post-hoc `ground_spans`/`classify_candidate_evidence` touch the full candidate achieves **≥25% cold-fleet wall reduction** with **≤1% fused-verdict diff** vs full-md control — that would elevate "drop full-doc payload today" from blocked to shippable.
