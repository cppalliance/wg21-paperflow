Impact: **0 s** judge wall saving; citing unstructured as an "LLM pipeline speed" comparator mislabels the workload. Quality risk: none if treated as out-of-scope; high if synthesis conflates partition with verification.

- [CRITICAL] **LLM appearances in the clone are optional, off-path extras — not a judge fleet.** (1) Embedding encoders only: OpenAI/Bedrock/Vertex/HuggingFace via langchain wrappers (`embed/__init__.py:11-18`, `embed/openai.py:17-30`); post-partition RAG indexing, never invoked by `partition_pdf`. (3) Whisper STT for audio partition only, serialized by a process-wide lock (`whisper_stt.py:17-24,57`). (4) Chunking `max_tokens` references `gpt-4` only as a tiktoken encoding name (`chunking/base.py:69-73`), zero API calls. Impact: unstructured has **~0 LLM calls/document** on default PDF partition vs our **6.0 calls/paper** census (`00-baseline.md:22-23`). Quality risk: none for honest scoping.

- [CRITICAL] **Speed is not comparable to tapetum-llm judge economics.** Our cold run is decode-bound MoE inference: **2284 calls × ~20 s / 16 slots ≈ 2855 s** closes the measured **3003 s** wall (`00-baseline.md:17-25`). Unstructured's hot path is synchronous Python partition: pdfminer loops, optional per-page OCR, optional CV layout — no vLLM slot accounting, no structured-output retries, no serial 6-call paper chain (`00-baseline.md:36-42`). Impact: any "they're fast" claim without naming partition-vs-judge is a category error; **0 s** portable judge saving. Quality risk: high if Enterprise SaaS latency is mistaken for our open-weight fleet model.

Impact: no lever maps to cutting our **1510** unit checks or **70%** zero-defect waste (`00-baseline.md:29-30,90-91`). ## False-pass hypothesis

Synthesis treats unstructured `hi_res` layout+OCR output as "good enough conversion" and cuts tapetum unit checks, assuming partition speed implies verification headroom. A swapped table cell or missing `##` section passes unstructured element extraction (source-only, no candidate) while our deterministic+LLM lane catches it on the **16/381** verdict-changing path (`00-baseline.md:29-30`); faster by skipping checks = silent defect pass.

## False-fail hypothesis

Porting unstructured hash `element_id` (`elements.py:800-801`) as tapetum unit fingerprints without including candidate-md hash and `_LANE_VERSION`: any tomd re-run changes element text hashes and forces full re-judge of unchanged semantic content, or conversely stale hashes skip re-judge after a real conversion fix — false stale pass, not a gate false-fail, but a quality-stability violation on warm-run economics (`00-baseline.md:18-20`).

## What would change my mind

A measured benchmark on our 381-paper holdout where unstructured (OSS or Enterprise) performs **post-tomd two-sided LLM verification** with evidence quotes, fail-closed coverage, structured verdict schemas, and **≤600 s** cold wall at ≥95% verdict agreement with current tapetum-llm — with per-unit fingerprints, not whole-document partition only. No such code path exists in `research/repos/unstructured` at clone HEAD (partition grep above; embed/chunking are downstream of ingestion, not verification).
