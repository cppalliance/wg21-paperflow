# 38 - Speculative-Decoding-Scout

**Verdict:** usable-with-conditions — MTP on alliance-pod is a low-risk pod-restart lever worth ~220–470 s on the 3003 s cold run (7–16% wall), but it cannot reach the 5–10 min target alone and must ship with CUDA graphs (or verified batch-invariant mode) before we trust quality-stability.
**Confidence:** medium

## Findings

- [CRITICAL] **Our output lengths sit above the GB300 short-OSL failure mode (OSL=64); MTP amortizes on this workload.** Evidence: GB300 blog mixed-context ISL=2k, OSL=64 — "decode proportion is extremely low … MTP overhead cannot be amortized" ([gb300-deepseek.html](https://blog.vllm.ai/2026/02/13/gb300-deepseek.html)); measured P50 model outputs from 377 sidecars: monolith **283 tok**, metadata **112 tok**, unit check **77 tok** (`research/tapetum-llm-throughput/11-output-token-decode-auditor.md:10-14,26-31`); fleet sum **~303,447 output tokens** across 2284 calls. Impact: OSL caveat is **weak** for monolith/metadata; only sub-64-token tails (rare pass-path unit JSON ~55 tok) see overhead risk — use **k=1**, not recipe k=2. Quality risk: **low** on OSL grounds; **medium** if k=2 on short calls.

- [CRITICAL] **Expected wall saving: ~220 s conservative to ~470 s upper bound on 3003 s (~7–16%), not a path to 5–10 min.** Evidence: fleet **303,447 output tok** (`11-output-token-decode-auditor.md:8`); effective decode **~28 tok/s** under c=16 load (`00-baseline.md:26-27`, `17-latency-decomposer.md:14`) ⇒ serial decode **10,837 s**, decode wall **/16 ≈ 677 s** (**22.6%** of 3003 s). HF benchmark **1.49× decode** at bs=1, k=1, **89% calibrated / 70% random acceptance** ([canada-quant MTP card](https://huggingface.co/canada-quant/DeepSeek-V4-Flash-W4A16-FP8-MTP), lines 13–14). Savings: **677 × (1 − 1/1.49) ≈ 222 s**. User back-solve (decode **50%** of **20 s**/call, **1.4×**): **2284 × 10 × (1 − 1/1.4) / 16 ≈ 408 s (~14%)** — valid for monolith-like calls where decode is **10.1 s / ~20 s** (`11-output-token-decode-auditor.md:28`). Impact: **~4–8 min** shaved at best; **~42–48 min** remains without call-count / prefix / dual-pod levers.

- [HIGH] **Determinism: algorithmically lossless at temperature 0, but our pod path can diverge without CUDA graphs.** Evidence: client pins **`temperature=0.0`, `seed=0`** (`packages/pipeline/src/pipeline/model_backends.py:310-312`); vLLM `RejectionSampler` implements speculative sampling per [arxiv:2211.17192](https://arxiv.org/abs/2211.17192) (`research/repos/vllm/vllm/v1/sample/rejection_sampler.py:38-59`); docs claim **greedy speculative = greedy non-speculative** (`research/repos/vllm/docs/features/speculative_decoding/README.md:186-204`). **Counter-evidence:** GitHub [#42517](https://github.com/vllm-project/vllm/issues/42517) — MTP vs non-MTP **token mismatch at temp=0** in **eager** mode (first flip ~pos 99); **`enforce_eager=False` (CUDA graph) → 100% identical**; root cause is batch-size-2 verification vs batch-size-1 decode GEMM paths. Current launch [H200SXM.txt](https://raw.githubusercontent.com/cppalliance/runpod/master/templates/deepseek/H200SXM.txt) has **no** `--compilation-config '{"mode": 3, "cudagraph_mode": "FULL_DECODE_ONLY"}'` (recipe recommends it). `VLLM_BATCH_INVARIANT=1` lists DeepSeek V3/R1 but **not V4** (`research/repos/vllm/docs/features/batch_invariance.md:99-104`). Baseline already **≥25% verdict flip** on identical reruns (`packages/whisker/src/whisker/CLAUDE.md:556-558`). Impact: MTP is **not fingerprint-safe** for quality-stability until CUDA graphs verified; cold `--force` A/B required. Quality risk: **medium** (borderline JSON/schema tokens flip).

- [HIGH] **Enablement is pod-restart only; no client or fingerprint schema change if outputs stay token-identical.** Evidence: official flag `--speculative-config '{"method":"mtp","num_speculative_tokens":N}'` (`research/repos/vllm/docs/features/speculative_decoding/mtp.md:64-67`, [DeepSeek-V4-Pro recipe](https://recipes.vllm.ai/deepseek-ai/DeepSeek-V4-Pro)); **not** in current [H200SXM.txt](https://raw.githubusercontent.com/cppalliance/runpod/master/templates/deepseek/H200SXM.txt). Fingerprint keys: markdown, source, prompt, **model name**, schema, `_LANE_VERSION` — **no server flags** (`packages/whisker/src/whisker/tapetum_llm/cli.py:579-618`). OpenAI client unchanged. MTP weights load from checkpoint `mtp.{i}.*` or startup **raises** (`research/repos/vllm/vllm/models/deepseek_v4/nvidia/mtp.py:480-486`). Impact: operator edits RunPod start command + restart; whisker code **0-line**. Quality risk: **none** from client; **medium** if server tokens drift (sidecars invalidate on rerun, not on skip).

- [HIGH] **Concurrency interaction at `--max-num-seqs 16`: inside GB300 “MTP helps” band, but competes on already-stretched MoE KV budget.** Evidence: GB300 blog — MTP beats no-MTP at concurrency **≤256**, degrades at very high concurrency ([gb300-deepseek.html](https://blog.vllm.ai/2026/02/13/gb300-deepseek.html)); alliance-pod **`--max-num-seqs 16`** ([H200SXM.txt](https://raw.githubusercontent.com/cppalliance/runpod/master/templates/deepseek/H200SXM.txt), `00-baseline.md:66`); measured **16→32 slots +57% wall** (`00-baseline.md:82-83`). MTP adds draft-head forward + extra KV per step; monitor `/metrics` **`vllm:spec_decode_draft_acceptance_rate`**, **`vllm:num_requests_waiting`** (`research/repos/vllm/docs/design/metrics.md:563-567`). Impact: at c=16 client / 16 server slots, expect **net decode gain** if acceptance **>~70%**; tail latency risk if acceptance collapses under prefill-heavy batches. Quality risk: **low**; throughput risk **medium**.

- [MED] **vLLM version: pod v0.24.0 is sufficient; DeepSeek-V4 MTP is registered in that release.** Evidence: alliance-pod image **`cppalliance/vllm-openai:v0.24.0`** (`packages/whisker/research/llm-batching/CTO-REQUEST.md:9`); v0.24.0 registry maps **`DeepSeekV4MTPModel` → `vllm.models.deepseek_v4.DeepSeekV4MTP`** ([registry.py:624](https://github.com/vllm-project/vllm/blob/v0.24.0/vllm/model_executor/models/registry.py#L624)); HEAD clone confirms NVIDIA MTP module (`research/repos/vllm/vllm/models/deepseek_v4/nvidia/mtp.py:264-489`). Recipe k=2 is optional; docs default **k=1** (`research/repos/vllm/docs/features/speculative_decoding/mtp.md:72-74`). Impact: **no image upgrade required** for MTP itself; **may** need rebuild ≥ PR #43447 for co-deployed prefix caching (separate lever). Quality risk: **none** on version.

- [LOW] **Acceptance on judge JSON may sit between “calibrated” and “random” HF bounds — measure before assuming 89%.** Evidence: HF **89% calibrated / 70% random** at bs=1 k=1 ([canada-quant card](https://huggingface.co/canada-quant/DeepSeek-V4-Flash-W4A16-FP8-MTP)); GB300 **>80%** on DeepSeek-R1 MTP k=1 ([gb300-deepseek.html](https://blog.vllm.ai/2026/02/13/gb300-deepseek.html)); judge prompts are structured, repetitive system prefixes, variable user tails (guard tag breaks prefix, separate issue). Impact: if acceptance **<60%**, MTP net-negative per GB300 short-output curve. Quality risk: **none**; performance risk **high** if unmeasured.

## False-pass hypothesis

Enable MTP **without** `FULL_DECODE_ONLY` CUDA graphs on a pod already showing **≥25% advisory verdict flip**: speculative verification uses batch-size-2 GEMMs ([#42517](https://github.com/vllm-project/vllm/issues/42517)), flipping argmax on a borderline `DefectFinding.source_quote` or `confidence` threshold while fingerprints still match prior sidecars — operators trust incremental skip and miss a silent finding-quality drift on re-judged papers.

## False-fail hypothesis

Deploy recipe-default **k=2** on metadata calls (P50 **112 tok**, often `<64` effective JSON body): GB300 shows MTP **underperforms disabled** when decode share is tiny ([gb300-deepseek.html](https://blog.vllm.ai/2026/02/13/gb300-deepseek.html)); fleet wall **rises** with no quality change, and operators disable all recipe flags including beneficial MBT/prefix tuning.

## What would change my mind

A cold **`--force`** 381-paper A/B on alliance-pod with **`--speculative-config '{"method":"mtp","num_speculative_tokens":1}'` + `FULL_DECODE_ONLY`**, logging **`vllm:spec_decode_draft_acceptance_rate`** and **`flip_AB` vs dual-run `flip_AA`** (`research/tapetum-llm-speedup/47-quality-equivalence.md`): **`flip_AB ≤ flip_AA + margin`** and **≥15% measured decode TPOT reduction** would flip verdict to **usable**; acceptance **<60%** or **`flip_AB` above margin** would flip to **garbage** for this fleet.
