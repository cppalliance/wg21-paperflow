# 42 - Text-Lane-Accountant

**Verdict:** usable-with-conditions (+ text lane owns ~50% of fleet wall and mirrors PDF levers, but unit-check volume on metadata-non-pass HTML papers blocks the 5–10 min target without the same metadata short-circuit plus prefix-cache reorder applied fleet-wide)
**Confidence:** high

## Findings

- [CRITICAL] **Text lane is half the cold fleet.** Measured v10 sidecars (`data/whisker/llm/*.tapetum.json`, 2026-07-23): **197 HTML/text papers** (fingerprint `lane=="text"`, `cli.py:585-602`), **181 PDF**, **3 error tombstones** (`P3984R0`, `P4182R0`, `P4228R0`). Text-lane call census: **1200 LLM calls** = **197 tier-1 triage** + **18 tier-2 adjudicate** + **197 metadata/outline** + **788 section unit checks** + **1 ideal verify** (`P4020R0`). Formula matches code: `1 + I(escalated) + 1 + |unit_checks|` (`adjudicate.py:232-531`, `01-call-count-accountant.md:13-14`). **50.8% of 2362 fleet calls**; linear slot model (20 s/call, 16 slots, `00-baseline.md:24-25`) → **~1500 s (~49.9% of the 3003 s wall)**. Impact: any fleet-wide speed lever that ignores HTML is capped at ~2× best case.

- [CRITICAL] **`fast` and `deep` hit the same pod today — tier-2 buys context, not capacity.** `tapetum_llm.md:21-23` maps both slots to `alliance-pod`; sidecars record `tier1_model=alliance-pod` on all 197 text papers and `tier2_model=alliance-pod` on all **18 escalations**. Code binds slots at `adjudicate.py:760-767` (`_SLOT_MAX_TOKENS`: fast=1024, deep=2048, `adjudicate.py:88-91`) but `_resolve_model_name` resolves the same service (`adjudicate.py:719-724`). Authority doc states escalation is “a careful second read with Tier 1's findings in context, not a larger model” (`tapetum_llm.md:283`). Impact: repointing `deep` to a second pod/model is infra-only; **18 tier-2 calls (~22 s wall)** cannot materially move 3003 s without also cutting unit volume.

- [CRITICAL] **Unit checks dominate text-lane wall; 73% return zero defects.** **788/1200 (65.7%)** of text-lane calls are section unit checks (`unit_id` prefix `section:` on all 788; `_run_html_unit_checks` at `adjudicate.py:519-530`). **575/788 (73.0%)** unit calls have empty `defects` arrays; only **8/197** papers carry paper-level `defect_groups`. **131/197 (66.5%)** papers saturate `MAX_UNIT_CHECKS=5` (`constants.py:191`). Median **7 calls/paper** (min 2, max 8). At 20 s/call → **~985 s (~65.7% of text-lane wall)** in units alone. Impact: router precision / metadata short-circuit on HTML is the text-lane equivalent of PDF unit elimination (`00-baseline.md:90-91`).

- [HIGH] **Tier-2 escalation rate is 9.1% — low absolute cost, structurally text-lane-specific.** **18/197** papers escalated (`escalated=true` in sidecar). Signals: **10 `axis_conflict`**, **8 `ungrounded_evidence`**, **0 `confidence_ambiguous`** (`adjudicate.py:256-279`, triggers at `adjudicate.py:293-299`). Chunked papers skip tier-2 (`adjudicate.py:290-291`; **0 chunked** in this fleet). Prior doc cited **0/198** pre-TOC-fix (`tapetum_llm.md:277`); post-v10 rate is higher but still **1.5% of text calls (~22 s fleet)**. PDF lane has no tier-2; it pays a mandatory monolith instead (`pdf_judge.py:646-657`). Impact: tier-2 tuning is not a regression driver; do not spend lever budget here.

- [HIGH] **Metadata-fail short-circuit mirrors PDF and is the largest text-lane elimination lever.** Metadata always runs in `_run_html_unit_checks` (`adjudicate.py:501-508`); fold logic mirrors PDF at `adjudicate.py:371-378`. Measured text metadata verdicts: **97 pass**, **99 review**, **1 fail**. **100/197** metadata-non-pass papers still ran **458 unit checks** (avg **4.58**/paper; **fail-only: 1 paper / 5 calls**). Fusion already caps when metadata ≠ pass (`fusion.py:187-189`; same path as `17-metadata-short-circuit.md:8`). Impact: skipping units after metadata non-pass saves **458 text-lane calls (~572 s on the 3003 s run, 19.1% fleet / 38.1% text-lane wall)** with **LOW merged-verdict risk** (identical demotion-only fold). Fail-only skip saves **5 calls (~6 s)** — negligible on HTML where review dominates.

- [HIGH] **Prefix caching with section payloads mirrors PDF unit anti-pattern; reorder is portable.** Each unit call sends **unique section SOURCE TEXT before full candidate markdown** (`unit_judge.py:769-776`), breaking APC leading-prefix identity (`00-baseline.md:46-47`, `15-prefix-cache-enabler.md:10-11`). Text lane has **592 “2nd+ unit per paper” calls** (cacheable if `[static system + per-paper tag] → [CANDIDATE MD] → [Unit/Risk/SECTION]`). Tier-1 and tier-2 also embed full markdown (`adjudicate.py:684`, `adjudicate.py:715`). Estimated text-lane prefix reorder + server APC (`05-web.md:69-73`, PR #43447): **~333 s (11.1% of 3003 s fleet)** assuming ~75% hit on 2nd–5th section checks. Impact: **combined text-lane levers (metadata skip + prefix reorder) ≈ 905 s (~30% fleet) → text-lane wall ~595 s, fleet ~2098 s** — still above 5–10 min without PDF-side cuts and/or dual-pod sharding.

- [MED] **Text-lane levers that do NOT mirror PDF.** No per-page recall screen or page escalations (PDF: **18 page-esc calls**, `pdf_judge.py:733-763`). No `--all-pages` / exhaustive runs on HTML (**0** non-`default` `coverage_mode` in fingerprints, `tapetum_llm.md:134`). Tier-1 injects HTML heading outline for triage (`adjudicate.py:666-673`) — PDF injects raw text layer instead. Ideal verification: **1 call** on text (`P4020R0`, `review`) vs sparse PDF ideal set. Impact: PDF page-escalation and all-pages levers are **N/A** on HTML; text-lane savings concentrate on metadata short-circuit + section-unit prefix cache + router precision.

- [LOW] **Exhaustive / zero-risk routing waste is small on HTML.** **1/197** papers ran **0 unit checks** (router found no `risk_signals`; `adjudicate.py:516-517`). **0** `--exhaustive-units` fingerprint runs. Median **13 risk_signals/paper** (max **341**), so the router fires broadly but units are capped at 5. Impact: unlike PDF saturation (179/180 at 5 units, `01-call-count-accountant.md:30`), HTML’s cap bind is **66.5%** — still high, but 34% of papers run ≤4 units.

## False-pass hypothesis

**P4020R0** (ideal verifier `review`, metadata `pass`, **5 section unit checks** all zero-defect): applying metadata-fail short-circuit on a misclassified metadata `review` that should have been `fail` would skip units that corroborate ideal discrepancies. On this fleet metadata `fail` is rare (**1/197**); the realistic false-pass path is **review-tier short-circuit** on a paper where units alone surface accepted `candidate_not_found` evidence that metadata summarized only as heading drift — merged verdict stays capped at `review`, but `--inspect` loses localized section quotes.

## False-fail hypothesis

**Tier-2 elimination** on a paper with `axis_conflict` where tier-1 emitted a cosmetic `fail` axis and tier-2 folded it to `review` (`adjudicate.py:313-320`, severity-aware worst-axis): forcing tier-1-only would leave a spurious axis `fail` in the sidecar reasoning path and demote more aggressively via escalation-signal demotion (`adjudicate.py:355-356`). Measured: **10** axis-conflict escalations; removing tier-2 without re-running decide logic risks **review inflation**, not hard-fail — low severity but inspect-noisy.

## What would change my mind

Sidecar replay showing **>8 text-lane papers** where a section unit check (not tier-1/tier-2/metadata) supplied the **sole** evidence that changed `suggested_verdict` or fusion rescue on a metadata-`review` paper would make the **458-call / 572 s** metadata short-circuit too aggressive for HTML; current count supports the PDF-mirror lever.
