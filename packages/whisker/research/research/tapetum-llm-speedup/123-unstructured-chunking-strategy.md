# 123 - unstructured-Chunking-Strategy

**Verdict:** usable-with-conditions — unstructured's two registered strategies (`basic`, `by_title`) encode principled soft/hard size bounds, optional overlap, and semantic-boundary isolation that **inform** tapetum payload-scoping windows (persona 13), but they target post-partition RAG chunking at **500-char defaults**, not LLM-judge verification; no standalone path to 5–10 min without call elimination plus scoped unit payloads.
**Confidence:** high (full `unstructured/chunking/` read at clone HEAD; cross-checked tapetum `chunking.py`, `unit_judge.py`, persona 13/30); medium on transfer ROI (H2 boundaries already exist locally)

## Findings

- [CRITICAL] **Only two chunking strategies exist; there is no "contextual chunking" in this repo.** Registry: `"basic"` → `chunk_elements`, `"by_title"` → `chunk_by_title` (`research/repos/unstructured/unstructured/chunking/dispatch.py:140-143`). Decorator docs list `'basic'` or `'by_title'` only (`dispatch.py:59`). "Contextual" appears only in VoyageAI **contextualized embeddings** (`embed/voyageai.py:85,145`), unrelated to document chunking. Impact: **0 s** fleet saving from a non-existent strategy; do not cite "contextual chunking" as an unstructured lever. Quality risk: none (clarity).

- [HIGH] **Two-tier size bounds: soft max stops growth; hard max forces mid-text split.** `ChunkingOptions.soft_max` defaults to `hard_max` when `new_after_n_chars` unset, disabling soft window (`base.py:249-278`). `hard_max` defaults to **500 chars** via `CHUNK_MAX_CHARS_DEFAULT` (`base.py:33-40,187-188`). `PreChunkBuilder.will_fit` refuses new elements once `_text_length > soft_max`, and never exceeds `hard_max` (`base.py:575-611`). Oversized single elements go through `_TextSplitter`, trying separators `("\n", " ")` then char-slice with overlap tail (`base.py:1396-1460,300-307`). Token mode mirrors this with `max_tokens` + `tokenizer` (`base.py:183-188,320-324`). Impact: pattern portable to persona-13 **scoped candidate windows** (e.g. soft cap ~8K chars, hard cap ~12K) but unstructured's **500-char default is wrong scale** for WG21 papers (our monolith budget is `MAX_PAPER_MD_CHARS = 500_000`, `constants.py:61`). Quality risk: LOW if soft/hard copied at judge-relevant sizes; HIGH if 500-char defaults applied to verification.

- [HIGH] **Overlap is opt-in, split-biased, and explicitly warns against semantic pollution.** `overlap` draws a tail from each chunk prefixed to the next; default applies only to **text-split** boundaries, not whole-element chunks (`base.py:117-124,229-246`). `overlap_all=True` extends overlap to normal semantic chunks with explicit caution: "pollution of otherwise clean semantic chunk boundaries" (`base.py:121-124`, `title.py:82-85`). Implementation: `PreChunk.overlap_tail` → `PreChunkBuilder._overlap_prefix` on flush (`base.py:564-572,724-732`); `_TextSplitter` prepends tail on remainder (`base.py:1617-1624`). Impact: **negligible fleet wall** for tapetum (overlap increases prefill, does not cut calls). For payload scoping: ±1 H2 neighbor window (persona 13 hybrid) is safer than unstructured-style `overlap_all`. Quality risk: MEDIUM if `overlap_all` blurs unit boundaries and duplicates evidence across scoped calls.

- [HIGH] **`by_title` semantic boundaries: Title elements + optional page breaks + table isolation.** Boundary predicates: `is_title` always; `is_on_next_page()` when `multipage_sections=False` (default **True**, page boundaries off) (`title.py:144-158,172-176`). `PreChunker._is_in_new_semantic_unit` flushes on any predicate (`base.py:472-500`). Tables isolated by default: `isolate_table=True` stages `Table`/`TableChunk` alone, never merged with narrative (`base.py:396-420,587-595`). `combine_text_under_n_chars` (by_title only) recursively merges undersized pre-chunks up to `hard_max` (`title.py:160-170`, `PreChunkCombiner` at `base.py:1734-1809`). **`basic` has empty `boundary_predicates`** — sequential fill only (`basic.py:1-14,123-125`, `base.py:158-163`). Impact: **conceptual mirror** of our H2 `chunk_markdown` (`chunking.py:129-164`) and HTML-lane section units (`source_router.py:88-160`), but unstructured keys off **partitioner `Title` elements**, we key off **`## ` markdown** (tomd contract). For persona 13: map `page:N` / `section:title` units to **H2 section text** from `_split_sections`, not unstructured Title detection. Quality risk: LOW for boundary choice; HIGH if Title-from-layout assumed correct for verification (same circularity as marker scoping, persona 60).

- [MED] **Our `chunking.py` already implements a subset; it does not scope unit checks.** H2 fence-aware split, greedy pack under `max_chars`, line hard-split with `partial=True` (`chunking.py:129-220`). Used only for **text-lane oversize triage** (`adjudicate.py:239`, `MAX_PAPER_MD_CHARS=500_000`). Unit checks send **full** `candidate_md` per call (`unit_judge.py:769-776`); PDF units are **pages**, HTML units are **markdown sections** from `_parse_markdown_sections` (`source_router.py:88-160,269+`), not `chunk_markdown` output. Persona 30: **0/381 papers chunk** post `strip_binary_payloads` today. Impact: unstructured patterns add **soft max, overlap policy, table isolation docs** — not a new boundary primitive. Fleet saving from copying unstructured chunking alone: **~0 s** on current cold run. Quality risk: none from status quo.

- [MED] **Portable improvements if persona-13 payload scoping lands (modest lever, ~7% wall ceiling).** (1) **Soft/hard window** on scoped candidate slice: `new_after_n_chars` analogue prevents stuffing unrelated H2s into one window. (2) **`combine_text_under_n_chars` analogue** for tiny adjacent sections under one page's risk signal. (3) **Table isolation**: never merge table HTML blocks with prose in a scoped payload (unstructured `isolate_table`, `base.py:217-226`). (4) **Token-based caps** (`max_tokens` + tiktoken) align windows to model context instead of char heuristics (`base.py:54-78,315-318`). (5) **Do not copy** `overlap_all` for judges; use explicit ±1 section neighbor in persona-13 hybrid plus full-doc presence index (`13-payload-scoper.md:18`). Impact: scoped unit payload P50 **~9259 → ~2675 user tok** → **~198 s wall / 16 slots** (~7% of 3003 s, persona 13); chunking logic is **necessary but not sufficient** — ANYWHERE rule still needs mechanical oracle. Quality risk: MEDIUM without index; LOW with unchanged post-hoc grounding on full `raw_tomd_md`.

- [LOW] **unstructured chunking is not on the LLM-judge hot path.** Chunking runs post-`partition_*` via `@add_chunking_strategy` decorator when `chunking_strategy` kwarg set (`dispatch.py:43-99`); purpose is RAG/embed indexing, not verification call reduction. No overlap with tapetum's **2284-call** census (`00-baseline.md:22-23`). Impact: treat as **boundary-design reference**, not a competitor pipeline to copy wholesale. Quality risk: none.

## False-pass hypothesis

Adopt unstructured `by_title` boundaries by trusting partitioner `Title` elements to scope unit-check candidate windows: a mis-leveled or missing `Title` in the converted markdown places a table defect outside the scoped window; the LLM passes the unit while `verify_unit_evidence` never runs on a quote the model did not emit — same class as marker block-scoping false-pass (persona 60), unless full-doc grounding/index remains authoritative.

## False-fail hypothesis

Apply unstructured-style `overlap_all` between H2 scoped windows without persona-13 presence index: duplicated prose at chunk edges inflates "extra content" or wording-drift findings; alternately, strict H2 windows without ±1 neighbor miss tomd cross-page join tails (`tomd/CLAUDE.md:231-232`), producing `content_omission` false alarms (persona 13 false-fail hypothesis).

## What would change my mind

A holdout A/B where unit checks use H2-scoped candidate slices sized with unstructured soft/hard rules **plus** persona-13 presence index, post-hoc grounding unchanged, shows **≥30% cold-fleet wall reduction** with **≤1% verdict diff** on the 48-paper holdout — would upgrade chunk-boundary design from "modest enabler" to "co-primary lever" alongside prefix-cache reorder.
