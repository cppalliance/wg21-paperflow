# 19 - Incremental-Granularity-Designer

**Verdict:** usable-with-conditions (+ call-class fingerprint splitting is a safe ~37–84% cold-run cut on prompt-only edits; per-unit LLM skip is sound only with mandatory deterministic re-grounding and monolith/metadata re-run on any candidate change)
**Confidence:** high

## Findings

- [CRITICAL] **Today’s skip is whole-paper only.** `_compute_fingerprint` keys on `md_sha256`, `source_sha256`, one monolithic `prompt_sha256`, one `schema_sha256`, `lane_version`, `coverage_mode`, and ideal fields (`cli.py:566-619`). `_fingerprint_matches` compares every key; any mismatch re-runs the full serial cascade (`cli.py:638-661`, `pdf_judge.py:646-890`). Warm run: **375/381 skipped in 64.8 s** when only fingerprints differ (`00-baseline.md:19-20`). Impact: a one-line tomd fix on one paper still pays **~6 serial LLM calls (~120 s)** per changed paper (`00-baseline.md:38-39`, `22-23`); a `UNIT_CHECK_SYSTEM_PROMPT` edit invalidates **all 381 papers → ~3003 s** because `_pdf_prompt_contract()` concatenates all four prompts into one hash (`cli.py:476-483`, `599`).

- [CRITICAL] **Call-class versioning is the large prompt-only win and is architecturally straightforward.** Split the monolithic contract into per-class entries stored in the sidecar, e.g. `monolith_prompt_sha256` + `monolith_schema_sha256`, `metadata_*`, `page_escalation_*`, `unit_*`, `ideal_*` (ideal already separate at `cli.py:605-617`). Bump only the class whose prompt/schema changed; skip LLM calls whose class hash matches. Call census (`10-call-graph-accountant.md:42-49`, `00-baseline.md:22-23`): **1510 unit (~1888 s), 377 metadata (~471 s), 381 first-pass (~476 s), 16 page (~20 s)** at 20 s/call / 16 slots (`00-baseline.md:24-25`). Impact on a **single-class prompt-only cold run**: unit-only → **~1888 s (~31 min, −37%)**; metadata-only or monolith-only → **~471–476 s (~8 min, −84%)**; page-only → **~20 s (−99%)**. Quality risk: **LOW** if merge re-runs deterministically from cached class outputs; **MEDIUM** if a logic change in `_fold_monolith_verdict` or unit aggregation ships without bumping the affected class or `lane_version` (`pdf_judge.py:343-367`, `927-928`).

- [HIGH] **ANYWHERE-presence makes naive per-unit skip unsound; deterministic re-grounding is the fix.** Unit and page prompts explicitly state content counts as present if it appears **ANYWHERE** in candidate markdown (`unit_judge.py:137-138`, `pdf_judge.py:225-226`). Post-processing already searches the **full** candidate via `classify_candidate_evidence(grounded, raw_tomd_md)` (`pdf_judge.py:697`, `783-786`, `grounding.py:419-434`). Cross-page refutation: page-5 “missing” quote can become `CANDIDATE_PRESENT` when unrelated page-10 text is added, without re-invoking the unit LLM. **Sound per-unit skip conditions:** (1) `source_page_sha256` unchanged for that `unit_id`; (2) unit-class prompt/schema/`lane_version` unchanged; (3) router `risk_signal` fingerprint for that unit unchanged (`source_router.py:200-259`); (4) on **any** `md_sha256` change, **always** re-run deterministic re-ground + verdict fold on cached LLM outputs, never trust stale `candidate_status`; (5) **always** re-LLM monolith + metadata when candidate changes (both ingest full markdown: `pdf_judge.py:640-643`, `677-681`, `unit_judge.py:769-776`). Optional: skip unit **LLM** when (1–3) hold and only re-ground; skip unit entirely only when prior unit verdict was `pass` with zero defects **and** re-ground finds no new refutations. Quality risk: **HIGH** without (4); **LOW–MEDIUM** with (4)+(5).

- [HIGH] **Sidecar shape for per-unit fingerprints.** Extend tapetum sidecar with `call_cache: { "monolith": {prompt_hash, schema_hash, llm_output}, "metadata": {...}, "units": { "page:7": {source_sha256, risk_signal_sha256, prompt_hash, llm_output} }, "page_escalations": { "page:3": {...} } }`. Whole-paper gate becomes: skip paper only if `source_sha256`, `coverage_mode`, ideal fields, **and** all required unit/page entries hit. On partial invalidation, run missing classes/units only, then deterministic merge (`pdf_judge.py:710-928`, `unit_judge.py:311-385`). Impact for a **typical surgical tomd re-conversion** (one changed paper, routed mode, median 5 units): **6 → ~3 LLM calls** (monolith + metadata + ~1 changed unit; unchanged units re-ground only) ≈ **−50% wall per changed paper** (~60 s vs ~120 s). Fleet impact scales with count of re-converted papers; unchanged papers still skip in **<1 s** via existing fingerprint (`00-baseline.md:19-20`).

- [MED] **Typical tomd reconversion scope (golden snapshot diffs, working tree 2026-07-23).** Line churn on 5 fixture diffs: **p4012r0-page-10** 44/69 lines (**64%**, single-page scope); **p4012r0-codeblock** 8/59 (**14%**, one construct); **p4016r0** 64/2022 (**3.2%**); **p1068r11** 136/473 (**29%**); **p2040r0** 194/350 (**55%**). Pattern: surgical emit fixes cluster on **1 page or one code/table block**; larger snapshot refreshes touch **~30–55%** of lines (often multi-section reflow). Page attribution: PDF lane units are `page:N` (`source_router.py:210`, `pdf_judge.py:852-853`); HTML uses `section:N` (`source_router.py:287`). Expect **1–2 source units** invalidated per surgical fix, **≥30% of pages** on structural reflow papers. Impact: per-unit skip saves **~0.8–4 unit calls per changed paper** in routed mode (`MAX_UNIT_CHECKS=5`, `constants.py:223`); it does **not** shrink the **381-paper prompt-bump cold run** unless paired with call-class versioning.

- [MED] **`lane_version` bump remains a fleet-wide invalidation today and should become class-scoped where possible.** `_LANE_VERSION = 10` is a single integer in every fingerprint (`cli.py:99-117`, `601`). Logic changes in unit quota selection (v10) or page-screen caps force **full 381-paper re-run** even when only unit routing changed. Split into `lane_version_monolith`, `lane_version_unit`, etc., or hash the specific Python contract functions. Impact: v10-style routing fixes re-run **~1510 unit calls only** (~1888 s) instead of 2284 (~3003 s). Quality risk: **MEDIUM** if merge/fusion logic changes without bumping the class that owns aggregation (`fusion.py:187-189` reads metadata from sidecar).

- [LOW] **Incremental skip does not attack the 3003 s “first cold run” target alone.** Even perfect per-unit skip on markdown edits leaves prompt/schema/lane bumps at fleet scale. Reaching **5–10 min** on prompt-only edits to monolith/metadata/page classes is achievable (~8 min); unit-prompt-only remains **~31 min** unless stacked with call elimination (metadata-fail short-circuit ~1350 s, `10-call-graph-accountant.md:20-21`), dual-pod sharding, or prefix caching (`05-web.md:6-12`). Quality risk: call elimination is **separate** from fingerprint granularity.

## False-pass hypothesis

Paper **P0533R9-class**: unit check cached `pass` on `page:12` while an older candidate had `constexpr` instances on page 18 that satisfied ANYWHERE presence; a tomd re-convert removes page-18 matches but leaves page-12 source unchanged. Per-unit LLM skip without re-grounding preserves stale `pass`; deterministic `classify_candidate_evidence` against the new full markdown would surface `candidate_not_found` and fold to `review` (`pdf_judge.py:697-706`, `_fold_monolith_verdict` at `343-367`). **Mitigation:** mandatory re-ground on any `md_sha256` change makes this a false-pass only if re-ground is skipped or bypassed.

## False-fail hypothesis

Paper with **metadata `pass`** and **unit cached `review`** on unchanged `page:4`: a prompt-only tightening of `UNIT_CHECK_SYSTEM_PROMPT` bumps unit-class hash but monolith/metadata hashes match. Re-running only unit checks on flagged units is correct; blindly re-running monolith because `md_sha256` unchanged would waste calls, not false-fail. Real false-fail: **skipping monolith** when `md_sha256` changed only in front matter causes missed TOC-leak detection in monolith `reasoning` (`pdf_judge.py:180-202`, `tapetum_llm.md:48`). **Mitigation:** always re-LLM monolith + metadata on candidate change (finding 3, condition 5).

## What would change my mind

Sidecar replay on the 381-paper fleet showing **>5 papers** where a **cached unit LLM `pass`** flipped to **`fail` after re-ground-only** (no unit re-LLM) when another page’s markdown changed would prove per-unit LLM skip is unsafe even with re-grounding; that would force full unit re-LLM on any `md_sha256` change and reduce the lever to call-class versioning only.
