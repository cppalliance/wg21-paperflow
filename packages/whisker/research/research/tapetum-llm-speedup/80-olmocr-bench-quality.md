# 80 - olmocr-Bench-Quality

**Verdict:** usable-with-conditions — olmOCR-bench is the quality gate that lets Allen AI ship throughput levers without LLM-as-judge fleet runs; we should adopt its deterministic fact harness, page scope, macro-strata rollup, and `--sample` cheap gate, but our tapetum LLM lane still needs persona-47 A/B for call-graph changes until we grow a WG21 facts corpus to comparable density.
**Confidence:** high

## Findings

- [CRITICAL] **Quality proof is a deterministic fact harness, zero LLM in the eval loop.** Each JSONL row is a `(pdf, page, id)` unit; `process_test` filters candidate files to `{stem}_pg{page}_repeat*.md` and calls `test.run(md_content)` only on that page's markdown (`benchmark.py:91-116`, `tests.py:114-125`). Pass/fail is pure Python + rapidfuzz/fuzzysearch/KaTeX (`tests.py:10-17`, `README.md:250-251`). The same `test.run()` drives RLVR training rewards (`grpo_train.py:638-645`). Impact: a speed lever (e.g. `--workers 20`, `--max_concurrent_requests 1600`, `--pages_per_group 500` at `pipeline.py:1220-1224`) is validated by re-converting bench PDFs and re-scoring; eval wall is CPU-bound ThreadPool over ~7k tests (`benchmark.py:141-145`), not a 50-min VLM judge fleet. Quality risk if skipped: throughput changes ship on latency alone.

- [CRITICAL] **Assertion classes mirror whisker facts lane: present/absent/order/table/math + auto baseline.** Eight typed tests in `TestType` (`tests.py:23-33`): `TextPresenceTest` uses `fuzz.partial_ratio` with `threshold = 1 - max_diffs/len(text)` and inverted logic for absent (`tests.py:167-182`); `TextOrderTest` uses `find_near_matches` position pairs (`tests.py:214-225`); `TableTest` checks cell + neighbor relations with `threshold = max(0.5, ...)` (`tests.py:394-468`); `MathTest` KaTeX render + geometric symbol layout (`tests.py:549-613`); `BaselineTest` auto-injected per PDF lacking explicit baseline (`benchmark.py:241-244`, `tests.py:483-545`: non-empty alnum, repeat n-grams, CJK/emoji). Header/footer zone scoping via `first_n`/`last_n` char windows (`tests.py:160-165`). Impact: olmOCR proves speed did not trade quality by **regression on the same fact multiset**, not by asking a judge model. Whisker already has parallel types in `facts.py` but evaluates **whole-document** markdown per fact (no page field in `check_facts`, `facts.py:491-507`), so our equivalent gate is structurally coarser.

- [CRITICAL] **Corpus scale and closure: ~7,010 facts over ~1,403 single-page PDFs in 7+ JSONL strata (HF dataset).** Published scale is on the HuggingFace dataset linked at `bench/README.md:275-276`; in-repo code loads every `*.jsonl` under `--dir`, unions tests, and **exits if any `(pdf, page)` lacks a test** unless `--force` (`benchmark.py:217-230`, `246-251`). Results table in `bench/README.md:22-35` shows eight macro strata (ArXiv, Old scans math, Tables, Old scans, Headers & footers, Multi column, Long tiny text, Base) with per-release scores (e.g. v0.4.0 → 82.4±1.1 overall, `bench/README.md:199-209`). Impact: exhaustive pre-authored facts replace selective LLM unit checks (`MAX_UNIT_CHECKS=5`, `00-baseline.md:56-57`); recall comes from corpus density, not runtime inspection budget. Our dev-replay has **29 labeled defect groups across 9 papers** (`corpus/dev-replay/labels.json`); holdout has **48 anchors across 3 papers / 7 strata** (`corpus/holdout/README.md:48-50`); Lane 3 facts corpus is **37 verified facts on 5 papers** (`whisker/CLAUDE.md` comprehension section). Maturity gap: ~200× fewer deterministic assertions than olmOCR-bench.

- [HIGH] **Rollup rubric: macro-average of per-JSONL pass rates, not micro-average over all tests.** Final score = mean of stratum pass rates (`benchmark.py:380-388`; design note at `benchmark.py:44-45`). Bootstrap CI resamples **within each JSONL category independently** then averages category means (`utils.py:47-60`, `benchmark.py:328-330`). RLVR can use the same macro-average over `TestType` categories (`grpo_train.py:1153-1161`). Majority-over-repeats per test: pass if `repeat_passes/num_repeats > 0.5` (`benchmark.py:125-126`). Impact: a speed change that hurts one hard stratum (e.g. Tables) cannot hide inside an easy-stratum majority; whisker persona 47's fleet flip rate is **verdict-level** on 381 papers without stratum macro structure. Adopt macro strata rollup for any expanded WG21 facts JSONL (e.g. per PR class or source type).

- [HIGH] **Cheap validation path: `--sample N` subsamples tests for dev iteration.** `benchmark.py:189`, `256-262` randomly samples N of `len(all_tests)` before eval. Combined with ThreadPool eval (`benchmark.py:141-145`) and no LLM calls, a sampled run is **minutes on CPU**, not two 50-min tapetum fleets. Meta-tests: **148** pytest cases exercise matchers independently of corpus size (`tests/test_tests.py`, counted at repo HEAD). Impact: olmOCR engineers can iterate pipeline/serving knobs with sampled bench + unit meta-tests; our persona 47 protocol requires **~100-150 min** (A1+B1 or A1+A2+B1) per non-exempt lever on the 381-paper LLM fleet (`47-quality-equivalence.md:16-17`). Recommendation: add `--sample` + stratum-aware sampling to whisker facts/bench runner; run full corpus only pre-merge.

- [HIGH] **CI gates the assertion engine, not the 7k corpus bench.** `.github/workflows/main.yml:32-35` runs `pytest -v -m "not nonci" tests/` (includes `tests/test_tests.py` matcher regressions); installs `[bench]` extras (`main.yml:182`) but **does not** download HF bench data or run `python -m olmocr.bench.benchmark`. GPU CI (`main.yml:109-161`) runs Beaker `gpu-ci-script.sh` on inference smoke, not full bench scoring. Release process (`RELEASE_PROCESS.md:7-14`) tags → PyPI/docker; quality tracking is **manual**: maintainers re-run bench locally and publish scores in `bench/README.md` version rows (`bench/README.md:151-209`, root `README.md:40` v0.4.0 +4 pt claim). Impact: olmOCR separates **fast deterministic CI** (matcher correctness) from **periodic full-bench acceptance** (human/ release cadence). We should mirror: CI = facts matcher + dev-replay schema; full 381 fleet reserved for LLM-lane equivalence only.

- [MED] **Speed-affecting changes validated by bench delta + version history, not A/B noise floor.** Pipeline throughput levers (`pipeline.py:1223-1224` workers/concurrency; page-group batching `pipeline.py:1314-1315`, `1404`) ship when re-converted `{pdf}_pg{N}_repeat*.md` files meet or beat prior macro stratum scores (README tracks v0.1.60→v0.4.0 monotonic improvement on hard categories like Tables 62.3→84.9, `bench/README.md:151-209`). Training uses bench facts as RLVR reward without a second model (`grpo_train.py:655-656`). `checked: verified` is stored (`tests.py:36-38`, `101`) but **not enforced at score time** — all loaded tests run (`benchmark.py:223-230`). Impact: olmOCR accepts corpus curation discipline over runtime provenance filtering; whisker is stricter (`facts.py:494-496` gates only `checked: verified`) but at 37 facts vs ~7k. For speedup study: **deterministic bench regression** can gate server-only levers (prefix cache, FP8 KV, scheduling) in minutes; persona 47 A/B remains mandatory for call elimination, model swap, payload scoping.

- [LOW] **Permutation test machinery exists but is not wired into `benchmark.py main`.** `perform_permutation_test` in `utils.py:70-194` supports category-aware pairwise significance; docstring at `benchmark.py:13` mentions pairwise tests but `main()` does not call it. Impact: olmOCR relies on bootstrap CI ± half-width for release tables (`benchmark.py:399-400`); we could port permutation pairing for A/B on macro stratum scores when comparing two tapetum configs on a shared facts subset.

## False-pass hypothesis

A throughput lever that increases pdftotext fallback rate without tripping bench: fallback pages still produce markdown that passes `TextPresenceTest` on body facts while silently losing math/table strata — olmOCR caps doc-level fallback at `max_page_error_rate` 0.004 (`pipeline.py:1222` per prior coverage audit) but per-page fallback is not serialized in Dolma output, so bench-only validation on converted MD could miss **which pages** degraded unless table/math facts fail on those pages. A sampled `--sample N` run (`benchmark.py:256-262`) could miss the failing stratum entirely.

## False-fail hypothesis

`TableTest` with `threshold = max(0.5, ...)` (`tests.py:395-396`) and markdown-only pipe tables (`table_parsing.py` via `tests.py:399-401`) false-fail visually correct HTML-table pages whose JSONL facts require rowspan/colspan neighbors (`bench/README.md:265-266`). A speed lever that changes table emit format (MD vs HTML) could drop stratum score without semantic quality loss — olmOCR README explicitly documents this ceiling.

## What would change my mind

Finding a CI workflow or release hook in `research/repos/olmocr` that automatically downloads the full HF bench, runs `python -m olmocr.bench.benchmark`, and blocks merge on macro score regression below a pinned baseline — `.github/workflows/main.yml:32-35` and `RELEASE_PROCESS.md:7-14` show no such gate today; olmOCR's speed-quality contract is **process + published scores**, not automated bench CI.
