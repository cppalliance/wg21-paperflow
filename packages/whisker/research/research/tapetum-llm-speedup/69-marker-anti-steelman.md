# 69 - marker-Anti-Steelman

**Verdict:** garbage (+ marker's published fast path is VLM conversion throughput without `--use_llm`; it is not an LLM-judge verification fleet and cannot be cargo-culted to cut our 3003 s cold run to 5–10 min at tapetum quality)
**Confidence:** high

## Findings

- [CRITICAL] Marker has **no post-conversion LLM verification lane** — every `--use_llm` processor is a **producer/corrector** that stops when the model says nothing is wrong, with no downstream audit, grounded quotes, or candidate-vs-source defect schema. Evidence: `marker/processors/llm/llm_table.py:246-247` returns on `"no corrections needed"`; `marker/processors/llm/llm_sectionheader.py:135-136` exits on `correction_type == "no_corrections"`; `marker/processors/llm/llm_page_correction.py:269-270` is a no-op unless `block_correction_prompt` is set. Contrast our two-sided lane: `packages/whisker/src/whisker/tapetum_llm/grounding.py:248-259` (`ground_spans`), `unit_judge.py:36-45` (`classify_candidate_evidence`, `ground_spans`). Impact: **0 s applicable wall saving** on the 3003 s run — different problem — and **quality risk = total**: copying marker eliminates fail-closed missing-content semantics and the ~143 calls/paper that actually change merged verdicts (`00-baseline.md:29-30`).

- [CRITICAL] The **headline speed numbers are not `--use_llm` hybrid mode**. README competitive throughput (balanced **2.9 pg/s**, fast **7.4 pg/s**, effective latency **341 ms/page**) measures **surya VLM + text-layer pipeline** on olmOCR-bench (`README.md:469-479`, `518-528`); README states production throughput comes from **many workers sharing one inference server**, not per-block cloud LLM calls (`README.md:520-521`). The HTTP API **does not expose** `--use_llm` (`README.md:436`). `benchmarks/inference.py:101-108` can pass `use_llm=True`, but that harness is not what produced the published pg/s table. Impact: cargo-culting marker's **2.9 pg/s** against our **~6 LLM calls/paper × 381 papers** (`00-baseline.md:22-24`) is apples-to-oranges; **false expectation of 40–50 min → 5–10 min** with no measured quality bridge.

- [HIGH] **`--use_llm` latency reality is slow-by-design for cloud quotas**, not fleet-judge optimized. Default **`max_concurrency = 3`** on all LLM processors (`marker/processors/llm/__init__.py:42-45`); simple processors batch through `ThreadPoolExecutor(max_workers=self.max_concurrency)` (`marker/processors/llm/llm_meta.py:44-48`); complex processors (tables, page correction) use the same cap (`llm_page_correction.py:283-284`). Default service **`timeout = 30`** s (`marker/services/__init__.py:13`); Gemini retries 429/503 with **`wait_time = tries * retry_wait_time`** (3 s steps, `gemini.py:94-108`). User reports: issue [#642](https://github.com/datalab-to/marker/issues/642) — table LLM **4–5 s/it**, 2200-page doc abandoned; [#490](https://github.com/datalab-to/marker/issues/490) — Gemini **~15 req/min** limit, repeated 429 storms. Impact: adopting marker's **3-wide** LLM concurrency on our **16 server slots** would **increase** wall time vs our `_DEFAULT_CONCURRENCY = 32` papers (`cli.py:125-127`); quality risk low for concurrency alone, but speed lever is inverted.

- [HIGH] **No determinism / quality-stability guarantees on LLM calls** — no `seed`, no project-wide temperature pin, and retry paths **raise temperature**. Gemini: `temperature = 0` then **`temperature = 0.2`** on JSON decode retry (`marker/services/gemini.py:62-65`, `112-113`). OpenAI path: `chat.completions.parse` with **no temperature or seed** (`marker/services/openai.py:93-101`). Claude: `messages.parse` with **no temperature or seed** (`marker/services/claude.py:77-82`). Ollama: `/api/generate` payload has **no temperature or seed** (`marker/services/ollama.py:46-52`). Impact: violates our D-rules (`CLAUDE.md` D5); if copied, **verdict-drift risk is unbounded** — no wall-clock saving justifies it under the 00-baseline quality-stability constraint.

- [HIGH] **Extraction quality on the shared WG21-relevant benchmark is lower than olmOCR**, the system we already treat as the quality ceiling reference. olmOCR-Bench overall **82.4 vs marker 76.1** (`05-web.md:49`, citing [olmocr.pdf](https://olmocr.allenai.org/papers/olmocr.pdf)); current marker README reports **76.0 overall**, **73.4 Tables**, balanced mode (`README.md:469`, `497-500`). Impact: marker is a **worse** fidelity anchor, not proof that "fast + same quality" is achievable on technical PDFs; any lever copied from marker trades **already-measured** recall headroom for speculative speed.

- [MED] **Fail-open / incomplete coverage** vs our fail-closed judge. Tables with **`row_count > max_table_rows` (175)** are silently skipped (`marker/processors/llm/llm_table.py:132-133`). LLM service exhaustion returns **`{}`** and leaves deterministic output unchanged (`marker/services/gemini.py:131`). No analog to **`MAX_UNIT_CHECKS` overflow → review**, **`MAX_PAGE_ESCALATIONS` cap → review without calls** (`pdf_judge.py:738-750`, `constants.py:191-223`). Impact: marker-style skip-on-empty would **false-clear** large WG21 poll tables; on our fleet, mimicking skip logic saves calls but **quality risk = silent false-pass** on uncovered units.

- [MED] **Swarm levers marker lacks** (each portable lever in `00-baseline.md:89-103` has no marker counterpart): (1) **call elimination** — marker gates LLM on block type/threshold, not zero-defect prediction or metadata-fail short-circuit (`pdf.py:97-107`, no router); (2) **payload scoping** — table prompts send block HTML + image per chunk (`llm_table.py:235-237`), not full-document resend 6×, but also **no** scoped source-aware unit packets like `unit_judge.py:389-398`; (3) **cross-paper concurrency at 32** vs marker LLM **3** (`cli.py:125` vs `__init__.py:42-45`); (4) **per-paper fingerprint skip** (`cli.py:566-599`, `1092-1095`) vs marker **`--skip_existing` output-file only** (`marker/scripts/convert.py:72-73`); (5) **prefix-cache-friendly prompts** — marker has no shared static system prefix across calls (each processor embeds its own prompt string, e.g. `llm_table.py:43-88`); (6) **dual-pod / offline batch vLLM** — LLM services are per-request HTTP to Gemini/OpenAI/Ollama (`gemini.py:79-86`), not vLLM offline batch (`05-web.md:53-58`).

- [LOW] **Block-selective LLM coverage** means many pages get **zero** `--use_llm` calls unless optional page correction is enabled — unlike our fixed **~6 calls/paper** cascade (`00-baseline.md:22-24`). Text-only pages with no Table/Equation/Form/etc. blocks invoke no LLM processor (`pdf.py:97-107`; page correction gated at `llm_page_correction.py:269-270`). Impact: marker's call count is **unbounded below** ours on easy pages (irrelevant to our judge fleet) and **unbounded above** on table-heavy docs (issue #642); not a template for predictable 5–10 min budgeting.

## False-pass hypothesis

Adopt marker's **`max_concurrency=3` + `"no corrections needed"` early exit** (`llm_table.py:246-247`): on PR #286-style wrapped poll headers, upstream pdftext already renders a plausible cell, the table LLM returns **"No corrections needed."**, `llm_error_count` stays 0, and no downstream verifier exists — identical false-clear class to tapetum checking routed pages while missing table-cell swaps (`00-baseline.md:29-30`, zero-defect unit checks). **Wall saving ~15–20 s × table blocks** if we dropped checks; **quality risk = critical**.

## False-fail hypothesis

Copy marker's **JSON-retry temperature bump to 0.2** (`gemini.py:112-113`) into our judge backends: a BPE/parse retry could change structured findings run-to-run, manufacturing spurious `review` flags on clean papers without catching real defects — **false-fail via verdict drift**, not via stricter detection. No wall-clock win under D5.

## What would change my mind

A reproducible run: **marker `--use_llm` on our 381-paper WG21 corpus** (or olmOCR-bench table/math splits), using **self-hosted vLLM at ≥16 concurrent slots**, with **post-hoc candidate-vs-source verification** (grounded quotes, fail-closed on cap overflow) matching tapetum recall on dev-replay PRs — plus measured wall ≤600 s. No such path exists in marker today (`config/parser.py:134-142`, `llm_table.py:246-247`, `gemini.py:131`).
