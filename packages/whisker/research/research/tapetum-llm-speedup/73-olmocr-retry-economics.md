# 73 - olmocr-Retry-Economics

**Verdict:** usable-with-conditions — olmOCR's retry ladder and document discard optimize conversion yield under non-deterministic sampling; we are already ahead on retry call overhead (2.4% vs ~12% page retry rate, 2 vs 8 attempts), but their post-page fallback-rate gate is a portable fail-fast pattern for doomed papers if adapted without pdftotext substitution or temperature ramps.
**Confidence:** high

## Findings

- [CRITICAL] **olmOCR page retry budget: 8 attempts, temperature ramp 0.1→1.0, indexed per attempt.** Evidence: `TEMPERATURE_BY_ATTEMPT = [0.1, 0.1, 0.2, 0.3, 0.5, 0.8, 0.9, 1.0]` (`research/repos/olmocr/olmocr/pipeline.py:84-85`); applied via `temp_idx = min(attempt, len(TEMPERATURE_BY_ATTEMPT) - 1)` and `query["temperature"] = temperature` (`pipeline.py:164-177`); `MAX_RETRIES = args.max_page_retries` default **8** (`pipeline.py:289`, `1221`); attempt 0 plus `retry_attempts = list(range(1, MAX_RETRIES))` yields **8 total tries** (`pipeline.py:289-290`, `296`). Measured fleet anchor: **12% page retry rate** on production runs (`05-web.md:40-41`, olmOCR technical report). Impact: at 12% pages retried, even **one** extra attempt per retried page adds **~12% VLM call volume** on top of the 1-call/page baseline; with up to **7** follow-on attempts and parallel retry bursts (`pipeline.py:345-363`), tail pages can cost **8×** a clean page. Our lane: **55 retries / 2284 calls = 2.4%** (`00-baseline.md:17-18,22-23,60-61`). **We are ahead on retry economics** (~5× lower retry incidence, **4× smaller per-call retry cap**).

- [CRITICAL] **Temperature ramp trades determinism for robustness — explicitly forbidden for us (D5).** Evidence: olmOCR comment at `pipeline.py:84` ("higher temperature helps overcome repetition issues"); ramp spans **0.1→1.0** across attempts (`pipeline.py:85`, `164-177`); non-rotation failures may fire **parallel** remaining attempts when `vllm_queued_requests == 0` (`pipeline.py:343-363`), compounding sampling variance. Our contract: `temperature=0.0`, `top_p=1.0`, `seed=0` on every backend call (`packages/pipeline/src/pipeline/model_backends.py:310-312`, D5 in `00-baseline.md:86`); tapetum judge dispatch preserves backend pins via `AgentBackend.run` (`packages/whisker/src/whisker/tapetum_llm/judge_task.py:25-29,68-74`). Impact: porting olmOCR's ramp would violate quality-stability (`00-baseline.md:77-78`) and documented ≥25% advisory verdict-flip risk under MoE batch variance; **0 s** cold-run saving, **HIGH** verdict-drift risk. Not portable.

- [HIGH] **JSON/YAML parse failure → plain retry, no guided decoding by default.** Evidence: `--guided_decoding` is opt-in; default path parses free-form YAML front matter via `FrontMatterParser` (`pipeline.py:179-182`, `210-212`); missing required YAML fields raise `ValueError` (`research/repos/olmocr/olmocr/train/front_matter.py:71-72`); any exception in `try_single_page` logs and returns **`None`** (`pipeline.py:228-230`), triggering the retry loop in `process_page` (`pipeline.py:335-341`); `finish_reason != "stop"` or `total_tokens > MODEL_MAX_CONTEXT` sets `is_valid=False` but still returns a parsed result when possible (`pipeline.py:200-206`), which also enters retry paths when rotation/validity checks fail (`pipeline.py:302-341`). Report App. D.2 (cited `05-web.md:47-48`): no guided JSON at inference — parse failures simply retry. Our analogue: `json.loads` / `ValidationError` → second attempt at fixed temperature (`model_backends.py:371-406`), **max 2 attempts** (`model_backends.py:300`). Impact: olmOCR's **8-attempt plain retry** buys conversion yield; our **2-attempt** path keeps retry wall at **~100 s / 3003 s (~3%)** (`00-baseline.md:60-61`) vs olmOCR's measured **12% page retry rate** with up to **7** extra full-page VLM calls each.

- [HIGH] **Document discard gate: `max_page_error_rate=0.004` (1/250 pages) after all pages finish.** Evidence: CLI default `--max_page_error_rate 0.004` (`pipeline.py:1222`); after every page completes, `num_fallback_pages = sum(page_result.is_fallback ...)` (`pipeline.py:557-558`); if `num_fallback_pages / num_pages > args.max_page_error_rate`, log error and **`return None`** — entire Dolma document discarded (`pipeline.py:559-563`); otherwise proceed with warning (`pipeline.py:564-567`). Fallback pages come from `make_fallback_result` (pdftotext anchor) after exhausted retries (`pipeline.py:233-250`, `329-332`, `371-375`). Pages run **concurrently** via `asyncio.TaskGroup` before the gate (`pipeline.py:548-554`); this is **post-hoc document abort**, not mid-flight cancellation of sibling pages. Impact: olmOCR wastes VLM calls on all pages of a doomed doc but **avoids shipping** bad corpus rows; on a 250-page doc, **≥2 fallback pages** triggers discard. For our 381-paper judge fleet, an analogous deterministic gate (e.g. metadata fail + N consecutive transport errors) could skip **~1047 unit checks** on metadata-non-pass papers (`17-metadata-short-circuit.md:8`) — est. **~1341 s** — without olmOCR's pdftotext false-pass path.

- [HIGH] **Our fail-closed tombstones waste full cascades before failing; olmOCR's gate fires earlier in the pipeline lifecycle only at document assembly.** Evidence: error path writes `status="error"` tombstone with **no fingerprint**, forcing full re-cascade on warm retry (`packages/whisker/src/whisker/tapetum_llm/cli.py:747-769`, `00-baseline.md:19-20`; `37-ideal-verifier-accountant.md:18`); **6 error** papers on v10 cold run (`00-baseline.md:17-18`); **≥2/6** failed only after completing judge work (`IdealVerificationError` on P4182R0, P4228R0 — **~11-13 wasted calls**, `research/tapetum-llm-throughput/07-retry-timeout-auditor.md:14-16`); **≥4/6** mid-cascade `PdfLaneError` still paid monolith and/or metadata before tombstone (`07-retry-timeout-auditor.md:14`). olmOCR never runs a second verification cascade — one page failure becomes pdftotext fallback, then document-level discard. Impact: olmOCR wastes **fewer calls on permanently bad documents** once fallback rate exceeds 0.4% (discard before `build_dolma_document`, `pipeline.py:569`); we waste **~2-8 LLM calls per error paper** plus **full re-run on retry** (warm **64.8 s ≈ 6 papers × ~7 calls**, `00-baseline.md:19-20`). Portable piece: **metadata-fail unit-check short-circuit** (persona 17) matches olmOCR's "stop investing in a doomed doc" economics without yield-style pdftotext (`pipeline.py:233-250`).

- [MED] **olmOCR parallel retry burst inflates tail throughput cost beyond the 12% retry rate.** Evidence: when `vllm_queued_requests == 0`, remaining attempts fire as concurrent tasks (`pipeline.py:345-350`); first valid result cancels siblings (`pipeline.py:355-360`); metric `finished_on_parallel_retry` (`pipeline.py:358`). Under low queue depth, one stubborn page can occupy **multiple** of `--max_concurrent_requests` default **1600** slots (`pipeline.py:1224`, `1287-1289`). Our lane: serial per-paper judge chain (`00-baseline.md:36-38`), cross-paper concurrency only (`cli.py:125`, `1096`). Impact: olmOCR's retry design optimizes **corpus completion time** under massive concurrency; our **2.4% retry rate at serial paper depth** is cheaper in total VLM spend even if per-retry latency is higher (~20 s/call, `00-baseline.md:24-25`).

- [LOW] **Connection backoff is separate from model retry budget (up to 10× exponential sleep per attempt).** Evidence: `try_single_page_with_backoff` loops `MAX_BACKOFF_ATTEMPTS = 10` with `sleep_delay = 10 * (2**backoff_count)` (`pipeline.py:264-275`); hard `sys.exit(1)` after exhaustion (`pipeline.py:277-278`). This is transport-layer retry inside each of the 8 page attempts. Our backend retries transient API errors once with `2 ** (attempt + 1)` delay (`model_backends.py:341-350`). Impact: olmOCR can hold worker slots through **long transport backoffs**; not a cold-run lever for us (zero timeout tombstones tonight, `26-timeout-budget-auditor.md:8`).

## False-pass hypothesis

Copying olmOCR's exhausted-retry path: after two judge JSON failures, substitute deterministic text (olmOCR's `get_anchor_text(..., pdf_engine="pdftotext")` at `pipeline.py:239`) and mark the call successful with `is_valid=True`, `is_fallback=True` (`pipeline.py:233-249`). A table-heavy WG21 page could **false-pass** when poppler text multiset matches but cell structure is wrong — same failure mode as `research/vlm-pdf-qa/20-olmocr-pipeline-analyst.md:43`.

## False-fail hypothesis

Porting olmOCR's document discard literally: abort a paper when **any** scoped judge call errors, using a threshold of **0.004** failed units. A 5-unit paper would fail closed on **one** transient JSON retry exhaustion (`model_backends.py:394-406`), tombstoning papers that would succeed on warm re-run (`00-baseline.md:19-20`) — **false-fail** via over-tight error-rate gate without olmOCR's pdftotext safety net.

## What would change my mind

Measured olmOCR retry accounting on a matched workload: per-page histogram of attempts-to-success (not just the 12% headline) showing mean extra calls ≤ our **2.4%** fleet overhead **and** document-discard gate triggering before the **75th percentile** page on ≥50% of discarded docs — proving their early-abort saves more VLM calls than our metadata-fail short-circuit would, without pdftotext or temperature ramps.
