# 78 - olmocr-Fallback-Design

**Verdict:** usable-with-conditions (+ olmocr's graceful-degradation philosophy is the wrong trade for tapetum fidelity, but its fail-fast *shape* — preflight gates, per-stage abort, skip doomed retries — ports cleanly as tombstone fingerprints + ideal-first ordering; saves ~50 s on the 64.8 s warm rerun and ~14 s on the 3003 s cold fleet, not minutes)
**Confidence:** high

## Findings

- [CRITICAL] **olmocr degrades per-page, discards whole documents above a fallback-rate ceiling; tapetum fails closed with no partial sidecars.** After up to `--max_page_retries 8` VLM attempts with temperature ramp (`olmocr/pipeline.py:84-85`, `275-369`), exhausted pages become `make_fallback_result` pdftotext output (`229-246`, `326`, `369`) marked `is_fallback=True` (`101`, `244`). All pages run concurrently in a `TaskGroup` (`538-544`); when `num_fallback_pages / num_pages > args.max_page_error_rate` (default **0.004**, `1199-1200`), the document is **discarded** (`549-553`) — no Dolma artifact. Below the threshold, partial fallback pages are **accepted** and merged (`554-557`, `590-618`). Tapetum: any lane failure raises `PdfLaneError` with explicit "no partial results" (`pdf_judge.py:556-586`); CLI writes `status="error"` tombstone only (`cli.py:747-769`, `1382-1387`); fusion treats error sidecars as unusable (`fusion.py:154-159`). Impact: olmocr trades quality for throughput on bad pages; we cannot adopt pdftotext fallback without violating fail-closed semantics. Quality risk: **HIGH** if fallback output were ever surfaced as advisory coverage.

- [HIGH] **olmocr's document-level abort is post-batch, not mid-page; our waste is post-cascade ideal placement and fingerprintless tombstones.** The `max_page_error_rate` check runs **after** all page tasks finish (`547-553`), not incrementally per page — a 500-page PDF still pays parallel retry/fallback work on every page before discard. Our analog waste is different: **6/381 error papers** on the v10 cold fleet (`00-baseline.md:17-18`) ran **full serial cascades** (~6 calls/paper, `00-baseline.md:36-38`) before tombstoning; **≥2/6** (`P4182R0`, `P4228R0`) completed the judge lane then failed deterministic ideal grounding (`ideal_verify.py:159`, `_require_raw_exact_evidence` at `114-131`) because `_attach_ideal` runs **after** `judge_pdf_extraction` / `adjudicate_paper` return (`cli.py:1239`, `1317`). Wasted cold-run judge calls before ideal fail: **~11-13 calls ≈ 220-260 s serial ≈ 14-16 s fleet-equivalent** at 16 slots (`37-ideal-verifier-accountant.md:12`, `07-retry-timeout-auditor.md:16`). Impact: reordering ideal **first** on ideal-bearing papers (3/381, `37-ideal-verifier-accountant.md:8`) recovers **~14 s** on the 3003 s cold run; **quality risk: LOW** for reorder-only, **HIGH** if ideal `agree` short-circuits source-aware judge.

- [HIGH] **Fail-FAST design (a): preflight gates that predict failure before LLM spend.** Already shipped: PDF text-layer extract before any LLM (`pdf_judge.py:595-598`), context-budget refuse without truncation (`615-626`), deterministic `screen_pages` before monolith (`636`), fleet health probe before fan-out (`cli.py:910-951`), ideal file readability check (`1131-1144`). **Port from olmocr, adapted fail-closed:** (1) **Ideal-first** when `ideal_path()` resolves (`golden_ideals.py:94-106`, `cli.py:1124-1128`): `verify_against_ideal` needs only candidate + ideal markdown, zero source dependency (`ideal_verify.py:134-158`) — `IdealVerificationError` can fire after **1 LLM call** instead of **6-8**. (2) **Tombstone fingerprint at failure time:** extend `_write_error_tombstone` (`747-769`) to persist `_compute_fingerprint(...)` plus `error_class: type(exc).__name__`; incremental match skips re-adjudication while keeping `status="error"` (`46-warm-run-auditor.md:14`). (3) **Deterministic ideal preflight (0 LLM):** validate ideal/candidate readability and empty-document guards before `run_task` (reuse `_require_raw_exact_quotes` pattern at `ideal_verify.py:97-111`). Impact on **warm rerun (64.8 s, 375/381 skipped, 6 re-evaluated, `00-baseline.md:19-20`):** tombstone fingerprint alone drops steady-state warm from **~64.8 s → ~8-15 s** (hash + report only, `46-warm-run-auditor.md:10`); ideal-first saves **~12-18 s** on warm if ideal errors still re-run (`37-ideal-verifier-accountant.md:18`). Cold fleet: **≈14 s** from ideal-first; tombstone fp **0 s** on first cold run. Quality risk: **LOW** for fingerprinted error skip + `--retry-errors` escape hatch (`46-warm-run-auditor.md:14`).

- [HIGH] **Fail-FAST design (b): mid-cascade abort on unrecoverable error classes — keep fail-closed, stop paying downstream.** Map olmocr's "stop investing in doomed document" to **exception-class abort**, not partial output. **Already abort correctly:** monolith retry exhaustion → `PdfLaneError` (`pdf_judge.py:658-659`); metadata failure → `PdfLaneError` before units (`686-688`); page escalation failure → `PdfLaneError` (`761-763`). **Gap to close:** ideal-stage `IdealVerificationError` after full judge chain (`cli.py:1382-1387` discards completed judge work — e.g. P4182R0 logged `verdict=review` then tombstoned, `46-warm-run-auditor.md:12`). **Do not port:** olmocr per-page pdftotext acceptance (`pipeline.py:229-246`) — equivalent would be emitting partial tapetum sidecars, forbidden by `pdf_judge.py:586` and `fusion.py:154-159`. **PdfLaneError papers (≥4/6 including P3400R3 metadata fail, P3977R0 monolith schema exhaustion, P3984R0 monolith JSON truncation, `07-retry-timeout-auditor.md:14`, `46-warm-run-auditor.md:12`)** already stop mid-cascade at **~2 calls** each — no unit-check waste. Impact: mid-cascade abort fixes **ideal-placement only** on cold fleet; combined with tombstone fp, warm **~63 s LLM component** (`44-debug-io-auditor.md:10`) falls to **~0 s** on unchanged persistent errors after first fingerprinted tombstone write. Quality risk: **none** for exception-class abort; **HIGH** for any partial sidecar persist on error.

- [MED] **Fail-FAST design (c): quantified savings on 6 error papers and the ~63 s warm LLM block.** Warm decomposition (personas 44/46): **64.8 s total** ≈ **~63 s LLM** on six fingerprintless tombstone re-cascades — model **~42 calls × ~20 s / 16 slots ≈ 52 s** plus probe/merge (`44-debug-io-auditor.md:10`, `46-warm-run-auditor.md:8-10`, `00-baseline.md:24-25`). Per-paper cold-run call spend on measured errors (`07-retry-timeout-auditor.md:16`): P3400R3 **~2**, P3977R0 **~2**, P4182R0 **~8**, P4228R0 **~4-7**, plus v10 additions P3984R0 **~2** (`46-warm-run-auditor.md:12`) and one further v10 error (**~2-8**, class unknown) → **~20-23 calls wasted** on cold ≈ **25-29 s fleet**. **Package savings:** (1) ideal-first: **~11-13 calls ≈ 14-16 s cold**, **~12-18 s warm** on ideal-error retries; (2) tombstone fingerprint skip: **~18-24 calls ≈ 22-30 s** on repeat warm for **3 persistent** errors (P3984R0, P4182R0, P4228R0, `46-warm-run-auditor.md:12`); (3) combined steady-state warm: **~8-15 s** vs **64.8 s** (`46-warm-run-auditor.md:10`). **Cannot move 3003 s → 5-10 min:** error-path savings are **<1% cold wall** even if all 6 errors aborted at call 0. Quality risk: **none** for measurement; **LOW** if `--retry-errors` preserves recovery from transient `PdfLaneError`.

- [MED] **olmocr retry/fallback policy is throughput-oriented; our retry budget is quality-oriented.** olmocr: `--max_page_retries 8`, parallel retry burst when vLLM queue empty (`339-357`), no guided JSON at inference (parse failure → retry, `05-web.md:47-48`), 12% measured retry rate (`05-web.md:37-40`). Tapetum: backend `output_retries` with BPE-corruption recovery; cold fleet **55 retries ≈ 100 s total (~4%)** (`00-baseline.md:60-61`). Shrinking olmocr-style retry fan-out without equivalent quality evidence is forbidden (`00-baseline.md:84-86`). Impact: retry reduction is **not** a lever from this persona. Quality risk: **HIGH** if retries cut on schema-exhaustion papers like P3977R0 (`07-retry-timeout-auditor.md:24`).

- [LOW] **olmocr preflight we already mirror; repo clone absent locally.** `--apply_filter` English/spam/form gate before any VLM (`pipeline.py:530-532`); poppler/GPU checks in `olmocr/check`. We probe LLM health once pre-gather (`cli.py:910-951`). `research/repos/olmocr` is not cloned; citations are from `https://github.com/allenai/olmocr/blob/main/olmocr/pipeline.py` (fetched 2026-07-23). Impact: no additional preflight to port beyond ideal-first + tombstone fp. Quality risk: none.

## False-pass hypothesis

Storing fingerprint on error tombstones and skipping re-adjudication when inputs are unchanged: fusion still sees `status="error"` (`fusion.py:158-159`), so no advisory pass is emitted — false-pass requires promoting error to pass, which this design forbids. A separate false-pass path: **ideal-first + short-circuit** when ideal returns `verdict="agree"` skips the source-aware judge; a candidate can match ideal structure while missing PDF-sourced content the monolith would catch (`37-ideal-verifier-accountant.md:20-22`).

## False-fail hypothesis

Tombstone fingerprint skip without `--retry-errors` after a **transient** monolith JSON failure (P3984R0, `46-warm-run-auditor.md:28`): inputs unchanged, pod healthy, sidecar stays `status="error"` until operator forces retry — honest stale error, not a false fail of a good conversion, but blocks automatic recovery from infra glitches.

## What would change my mind

Warm-run log with tombstone fingerprints enabled showing **>3 evaluated papers** with unchanged inputs (proving skip false-misses), or cold-run sidecar inventory showing **>3 ideal-bearing fleet papers** with **>2 IdealVerificationError** tombstones — would raise ideal-first + selective-retry to a first-class cold-fleet lever above **~1% wall**.
