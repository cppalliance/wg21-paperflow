# 23 - Small-Judge-Evaluator

**Verdict:** usable-with-conditions (unit-check + metadata/outline offload to a dense 131k pod is architecturally sound and model-sovereign, but it saves ~850–1200 s on the 3003 s cold run, not the 5–10 min target, and must not ship without a full-fleet A/B that proves same findings and same verdicts)
**Confidence:** medium

## Findings

- [CRITICAL] **Unit checks are the only high-volume call class movable to h200-qwen3-32b / b200x2-gemma4 / b300-qwen36-27b; monolith cannot move.** Census: ~1510 unit checks vs 381 monolith + 377 metadata/outline + ~16 page escalations = 2284 total (`00-baseline.md:22–23`). Monolith sends full PDF text + full markdown and hard-fails above `max_context_window * CONTEXT_SAFETY_MARGIN` (`pdf_judge.py:615–626`, `pdf_judge.py:108–111`); only `alliance-pod` / `h200x8-deepseek-v4-pro` declare `max_context_window = 393216` (`SERVICES.toml:52`, `SERVICES.toml:69`). Dense pods cap at 131072 (`SERVICES.toml:92`, `SERVICES.toml:105`, `SERVICES.toml:134`). Impact: moving ~66% of calls off the MoE pod; quality risk HIGH if treated as a silent swap (see verdict-drift finding).

- [HIGH] **Context-window fit for unit checks: 373/381 papers fit 131k with the lane’s 0.80 safety margin; 8 need MoE fallback.** Unit payload = one page source + FULL `candidate_md` per call (`unit_judge.py:769–776`, `00-baseline.md:43–44`). Measured on 381 fleet markdown files (`$WG21_DATA_DIR/paperstore/*.md`, 2026-07-23): p50 22,837 chars, p95 133,957, p99 632,012, max 2,554,424; token estimate uses `chars/4.0*1.5` (`SERVICES.toml:70–71`). With `CONTEXT_SAFETY_MARGIN = 0.80` (`pdf_judge.py:108–111`), effective 131k budget ≈ 104,858 tokens (~279,620 chars): **8/381 (2.1%) exceed**; **3/381 (0.8%) exceed** the 393k monolith budget. Impact: a dual-service router (small judge default, MoE fallback for oversize) is mandatory; mis-routing those 8 papers fails closed (`pdf_judge.py:622–626`) or truncates quality.

- [HIGH] **Metadata/outline checks are a second easy offload (377 calls, tiny payload).** `run_metadata_outline_check` sends bounded source metadata, source outline, candidate front matter, and heading list only (`unit_judge.py:241–256`), not full markdown. Fits any 131k pod with large headroom. Same structured schema and guard-tag pattern as unit checks (`unit_judge.py:244–245`). Impact: +377 calls (~16.5% of fleet) off the MoE queue; combined with unit checks, **1887/2284 (82.6%)** of LLM calls could leave `alliance-pod`; quality risk same as unit checks if model changes without A/B.

- [HIGH] **Quality gate before switch: full-fleet A/B on verdict + findings, not SLMJury’s 89.55% headline alone.** SLMJury reports Phi-4 14B at **89.55% oracle agreement at 10 output tokens**; Qwen3-4B is 1.74% behind (`05-web.md:88–90`). Our unit checks emit structured `UnitCheck` with up to 5 `DefectFinding` objects and 40-word reasoning (`models.py:298–313`), not a 10-token verdict; SLMJury also notes quick verdicts **lose up to 23% on general tasks** (`05-web.md:90`). Baseline shows only **16/381 papers** had merged verdict changed by LLM findings at all (`00-baseline.md:29–30`), so even ~90% agreement would miss several verdict-changing papers. Required protocol: rerun all 381 papers (or holdout + dev-replay superset) with DeepSeek-V4-pro vs candidate dense judge on unit (+ metadata) calls only; accept only **100% paper-level verdict parity** and **equivalent defect_groups / evidence_dispositions** on every paper that currently fails or reviews; log disagreements on the 1057/1510 zero-defect checks (`00-baseline.md:29`) for silent false-clear detection. Impact: weeks of validation before `_LANE_VERSION` bump (`cli.py:99–117`); shipping below parity changes lane semantic identity.

- [MED] **Determinism and model-sovereignty: compliant in infrastructure, non-compliant in semantic identity if swapped without revalidation.** All candidate pods use `vllm_thinking` on open-weight models (`SERVICES.toml:48–137`); CLAUDE.md model-sovereignty rule satisfied. Calls already go through `run_judge_task` → `AgentBackend.run`, not raw APIs (`judge_task.py:52–73`, D1). No per-call temperature/seed override required. Fingerprinting already binds service + model identity (`cli.py:106–107`, `cli.py:1056–1061`); a judge swap without bumping `_LANE_VERSION` poisons incremental skip. Measured **≥25% verdict-flip rate on reruns with the same model** (whisker CLAUDE.md advisory section); a different model adds independent drift. Impact: `_LANE_VERSION` bump + full cold rerun mandatory; “same quality” claim is false until A/B passes.

- [MED] **Expected wall-clock saving: ~850–1200 s on the 3003 s run if 1510 unit checks move to a 2–2.5× faster dense pod with a dedicated queue.** Proportional model: unit checks are **1510/2284 = 66.1%** of calls (`00-baseline.md:22–23`); implied unit-check wall share ≈ **1985 s** of 3003 s. At **2×** per-call speed (20 s → 10 s, consistent with dense-vs-MoE decode gap cited in `00-baseline.md:69–71`): save **~992 s** → **~2011 s** (~33.5 min). At **2.5×** (20 s → 8 s): save **~1191 s** → **~1812 s** (~30 min). Adding metadata/outline (377 calls) at similar speedup saves another **~250–300 s** optimistic. Separate pod also shortens MoE queue for monolith/page (~774 calls); no local `num_requests_waiting` trace, but persistent queue inflation is documented as a TTFT lever (`05-web.md:65–66`). Impact: **material but insufficient alone** for 5–10 min; must pair with call elimination, in-paper parallelism, or dual-pod sharding (`00-baseline.md:90–97`).

- [LOW] **Page escalations (~16 calls) and ideal verifier are movable but irrelevant to fleet wall time.** Page escalation payload mirrors unit checks (one page + full markdown, `pdf_judge.py:389–395`); volume **~16/2284 (0.7%)** (`00-baseline.md:22–23`). Ideal verifier is conditional and separate (`cli.py:140–142`). Impact: <30 s fleet savings even at 3× speedup.

## False-pass hypothesis

P0957R8-style localized omission: a page passes the monolith, routes to a unit check, and **h200-qwen3-32B returns zero defects** (joining the 70% zero-defect cohort, `00-baseline.md:29`) while DeepSeek-V4-pro would emit a `candidate_not_found` missing-content disposition. The paper stays advisory-pass/review-cap instead of surfacing the defect that currently requires the stronger judge on hard conversion-fidelity rubrics (`05-web.md:90` general-task penalty).

## False-fail hypothesis

Wording-markup false alarm: Gemma-4-31B or Qwen3-32B mis-reads sanctioned `:::wording-remove` / `<del>` blocks (explicitly ruled non-defects in `CONVERSION_CONTRACT`, `unit_judge.py:93–102`) and emits a structure defect, forcing review on a clean wording paper that V4-pro passes at high confidence.

## What would change my mind

A completed cold-fleet A/B (381 papers, same prompts/schemas, unit + metadata on `h200-qwen3-32b` vs `alliance-pod`) showing **381/381 identical fused advisory verdicts** and **matching defect_groups + evidence_dispositions** on all 16 verdict-changing papers (`00-baseline.md:29–30`), plus measured per-call latency ≥2× improvement on unit checks with the 8 oversize papers correctly falling back to MoE.
