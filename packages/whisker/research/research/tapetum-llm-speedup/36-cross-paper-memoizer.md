# 36 - Cross-Paper-Memoizer

**Verdict:** garbage (+ cross-revision memo keys on `(unit source hash, candidate section hash, prompt hash)` are unsound under ANYWHERE semantics, and measured revision overlap yields <3% cold-fleet wall savings while incremental whole-paper fingerprint already skips 375/381 warm papers)
**Confidence:** high

## Findings

- [CRITICAL] **Revision density in `data/paperstore/` is real but mostly coexisting siblings, not reusable clones.** Counted 583 `*.md` files; **371** match `P1234R{n}` / `N1234R{n}`; **255** unique document bases; **85** bases carry **2–5** revisions (**116** extra revision PIDs beyond the first in each chain). Distribution: **170** bases ×1, **63** ×2, **15** ×3, **5** ×4, **2** ×5 (e.g. `P2583R0–R4`, `P3856R4–R8`). The tapetum fleet (381 sidecars) includes **201/381** PIDs in those 85 multi-revision bases. **212** paths lack an `R{n}` suffix (mostly `N####` editorial/debug artifacts, not revision chains). Impact: cross-paper memo could theoretically apply to **116** “follow-on” fleet PIDs per cold run, but only if source/candidate slices actually match (they do not; see below). Quality risk: N/A until a hit exists.

- [CRITICAL] **Adjacent revisions never share identical source or candidate on disk.** Measured all **116** adjacent `(R{n}, R{n+1})` pairs in multi-revision chains: **0/116** identical full markdown SHA-256, **0/116** identical body after stripping YAML front matter, **0/116** identical staged PDF/HTML source file. PDF pairs with page-level stats (**61/116**): unchanged page text-layer fraction **p50=0.00**, **mean=0.092**; only **4/61** pairs have ≥50% unchanged pages; **0/116** identical whole source files. Impact: a memo keyed on `(unit_source_hash, full_candidate_md_hash, prompt_hash)` has **0% hit rate** across revisions in this corpus today. A `(unit_source_hash, candidate_section_hash, …)` key would raise a false hit rate but violates ANYWHERE correctness (`unit_judge.py:137-138`, `pdf_judge.py:225-226`). Quality risk: **HIGH** for section-scoped keys (stale pass when unrelated pages satisfy or refute presence; see `19-incremental-granularity.md:12`).

- [CRITICAL] **ANYWHERE-presence makes the FULL candidate part of the memo identity; only post-LLM re-grounding can relax it.** Unit and page prompts explicitly judge one source region against content that counts as present if it appears **ANYWHERE** in the full markdown (`unit_judge.py:137-138`, `pdf_judge.py:225-226`). Each unit call sends the **entire** `candidate_md` in the user message (`unit_judge.py:769-776`); monolith and page escalation do the same (`pdf_judge.py:640-643`, `215-222`). The pipeline already re-searches the full candidate after the LLM via `classify_candidate_evidence(grounded, raw_tomd_md)` (`pdf_judge.py:697`, `783-786`). **Memoizable call classes (with mandatory re-ground on any candidate change):** unit checks and page escalations *if* the memo key includes `candidate_md_sha256` + `unit_source_sha256` + canonical `prompt_sha256` (excluding per-call `guard_instruction` tags at `unit_judge.py:767-768`, `pdf_judge.py:638-639`) + `schema_sha256` + `risk_signal_sha256` + `lane_version`. **Not memoizable across revisions without full candidate match:** monolith (whole PDF text changes every revision, `pdf_judge.py:640-643`), metadata/outline (front matter and outline always change on `document:` bump, `unit_judge.py:246-255`), HTML tier-1/2 (full-document triage, `adjudicate.py:232-253`), ideal verify (candidate+ideal pair, `ideal_verify.py:142-143`). Impact: even a perfect cross-revision store skips **at most** unit/page LLM calls; monolith+metadata (**~947 calls / ~947 s wall**, `10-call-graph-accountant.md:44-46`) still run per revision. Quality risk: **LOW** with `(full candidate + re-ground)`; **HIGH** without full candidate in the key.

- [HIGH] **Proposed storage: shared memo table under `whisker/llm/`, keyed by call class, not by PID.** Sidecars already live in `whisker/llm/<pid>.whisker.tapetum.json` via `_llm_output_dir` (`cli.py:429-436`). Add `whisker/llm/memo.sqlite` (or `memo/` shard JSON) with rows: `(call_class, unit_id, unit_source_sha256, candidate_md_sha256, prompt_sha256, schema_sha256, risk_signal_sha256, lane_version, model, llm_output_json, created_at)`. Lookup before `run_judge_task`; insert after success. Whole-paper fingerprint stays per-PID (`cli.py:566-619`); memo table is cross-PID. On hit: skip HTTP; still run deterministic merge/re-ground (`pdf_judge.py:696-710`, `unit_judge.py:604-648`). Invalidate on any key mismatch; bump `lane_version` (`cli.py:99-117`) clears class rows. Impact: engineering cost is moderate; **fleet wall savings near zero** until revision overlap rises. Quality risk: **MEDIUM** if re-ground is skipped; **LOW** if re-ground is mandatory (same contract as persona 19).

- [HIGH] **Estimated hit rate vs the 3003 s cold fleet and nightly incremental skip.** Upper-bound cold-fleet model: **116** follow-on revision PIDs × median **5** unit checks × **9.2%** mean unchanged-page fraction (PDF adjacent pairs) ≈ **53 unit LLM calls** saved even with an *unsound* source-only key and mandatory re-ground ≈ **53×20/16 ≈ 66 s (~2.2% of 3003 s)** (`00-baseline.md:17-18`, `24-25`). Monolith+metadata still run (**~2 calls × 116 ≈ 232 calls / ~290 s**). Realistic sound key `(unit_source, full candidate, prompt)`: **0 calls saved** (0/116 identical candidates). Nightly operations: warm rerun already skips **375/381** papers in **64.8 s** via whole-paper fingerprint (`00-baseline.md:19-20`, `cli.py:638-661`); new revisions arrive as **new PIDs months apart**, each triggering a full cascade once. Cross-paper memo does not accelerate the dominant cold path and duplicates persona-19 per-unit incremental work with strictly weaker keys. Impact: **does not move 3003 s → 5–10 min**; at best **~1 min** in optimistic cold-run fantasy, **~0 s** in sound mode. Quality risk: **HIGH** if pursued as a substitute for per-unit fingerprints; **LOW** as a dedup cache when keys include full candidate.

- [MED] **Random guard tags are irrelevant to memo lookup but explain zero prefix-cache sharing today.** Every LLM call appends `guard_instruction(tag)` with `tag = SRC{secrets.token_hex(4)}` (`unit_judge.py:767-768`, `pdf_judge.py:638-639`, `387-388`). Memo lookup must hash canonical prompts *without* the tag; storing outputs does not fix APC (`00-baseline.md:48-52`, `05-web.md:76-77`). Impact: memo table and prefix cache are orthogonal levers. Quality risk: **LOW** for memo; tag randomization stays a separate prefix-cache fix (`15-prefix-cache-enabler.md`).

- [LOW] **Revision chains are long-tailed; most fleet papers are singleton revisions.** **296/381** fleet PIDs sit in bases with only one converted revision in the store (**170** unique-base singletons cover most). Multi-revision bases cluster in recent mailing waves (`P2583`, `P3856`, `P3941`, …). Impact: memo ROI scales with how many sibling revisions you judge in one batch; our nightly job judges **latest converted set**, not full historical chains. Quality risk: none (measurement only).

## False-pass hypothesis

**P0533R9-class cross-revision reuse:** `P0533R9` unit check on `page:12` memoized from `P0533R8` keyed only on `(page:12 source hash, prompt hash)` while `P0533R9` candidate drops unrelated `constexpr` matches that had satisfied ANYWHERE presence in R8. Cached unit `pass` skips LLM; without mandatory `classify_candidate_evidence` on the R9 full markdown, mass keyword loss survives (`19-incremental-granularity.md:24`, `unit_judge.py:137-138`). **Mitigation:** require `candidate_md_sha256` in the key (→ no cross-revision hits here) or store LLM output but always re-ground + fold on the new candidate (`pdf_judge.py:697-710`).

## False-fail hypothesis

**Front-matter-only revision bump:** `P4007R2→R3` changes only YAML `document:` / `date:` while body pages are unchanged. Monolith/metadata re-run (correct: TOC/metadata rules, `pdf_judge.py:180-202`, `unit_judge.py:114-127`) flags spurious outline drift; cross-paper memo does **not** reduce those calls. A false-fail appears only if memo **blocks** metadata re-run while reusing stale outline verdict—avoid by never memoizing metadata/monolith across PIDs. **Mitigation:** restrict memo to unit/page classes only; always fresh monolith+metadata per PID.

## What would change my mind

A remeasurement after the next mailing dump showing **≥30%** of adjacent revision pairs with **identical staged source files** *or* **≥50%** unchanged PDF page hashes **and** identical post-front-matter candidate bodies (currently **0/116** and **0/116**, **mean page unchanged 9.2%**) would justify a pilot `whisker/llm/memo.sqlite` for unit/page classes with full-candidate keys. Until then, invest in persona-19 per-unit fingerprints + call-class versioning (~37–84% on prompt bumps, `19-incremental-granularity.md:8-10`) instead.
