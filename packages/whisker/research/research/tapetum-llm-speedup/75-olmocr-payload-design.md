# 75 - olmocr-Payload-Design

**Verdict:** usable-with-conditions — olmOCR proves bounded per-page payloads and hard truncation do not block 82.4 bench quality, but v4 production dropped runtime anchoring entirely; our portable lever is scoped unit-check windows plus mechanical full-document presence (already partially wired), not copying their 8192-token pdftotext cap (which does not exist in inference code).
**Confidence:** high

## Findings

- [CRITICAL] **Production inference payload is image + short static prompt only; no document anchoring at runtime.** Evidence: `build_page_query` sends `build_no_anchoring_v4_yaml_prompt()` (~500 chars) plus one PNG, no `get_anchor_text` call (`pipeline.py:133-144`, `prompts.py:164-170`). CLI flag `--target_anchor_text_len` is explicitly deprecated: "not used for new models" (`pipeline.py:1230`, `README.md:463-464`). Impact: olmOCR's 82.4±1.1 bench score (`README.md:180`, `80-olmocr-bench-quality.md:12`) was achieved **without** runtime full-doc or even capped anchor text; quality lives in the trained 7B VLM, not per-call document context. For our advisory lane: bounded payloads are safe **if** mechanical verification stays on full markdown (we already do at `unit_judge.py:425,728-729`). Quality risk: none from olmocr precedent; risk is only if we scope LLM input without keeping post-hoc grounding.

- [CRITICAL] **Anchoring builder: `get_anchor_text` in `prompts/anchor.py`; truncation is character-based, not 8192-token pdftotext.** Evidence: entry point `get_anchor_text(..., pdf_engine=..., target_length=4000)` (`anchor.py:17-18`); production path uses `pdfreport` → `_linearize_pdf_report(..., max_length=target_length)` (`anchor.py:46-47`); separate `pdftotext` engine calls `_get_pdftotext` with **no length cap** — full page stdout (`anchor.py:22-23`, `52-60`). The `8192` constant in-repo is **quantization calibration** `max_seq_length=8192` (`train/compress_checkpoint.py:115,298`), not inference anchoring. Impact: persona mandate "8192-token pdftotext cap" is **not literal in olmocr inference**; the real invariant is **hard bounded auxiliary text** (default **4000 chars**, training **6000 chars** at `train/config.py:41`, `dataloader.py:206-212`). Our middle ground should cap **candidate section windows in chars/tokens**, not assume olmocr's pdftotext path. Quality risk: over-truncating candidate context without presence oracle (persona 13).

- [HIGH] **Truncation algorithm: edge-first greedy fill under `max_length`, per-element head/tail split.** Evidence: `_linearize_pdf_report` always emits page dimensions, then if `total_length > max_length` keeps min/max x/y text and image edge elements, shuffles remaining elements, adds until budget exhausted (`anchor.py:256-357`); individual text spans capped at **250 chars** via `_cap_split_string` head `...` tail (`anchor.py:229-252`, `243-252`). Tests assert `len(anchor_text) <= target_length` for 2000/4000/6000 (`tests/test_anchor.py:83-134`). Impact: olmocr accepts **lossy truncation by design** (random mid-page fill after edges) yet bench quality holds — direct counterexample to our fail-closed "never truncate, fail the paper" instinct for **generation** tasks. For advisory unit checks: equivalent pattern is **deterministic window** (matched H2 section ± neighbor) plus **token-set / n-gram presence index** over full candidate, not random shuffle. Est. prefill savings on **1510 unit calls** with P50 **34 336-char** md (`00-baseline.md:43-47`, `13-payload-scoper.md:12`): scoped window ~8K chars → **~−6584 tok/call** → **~198 s wall** at 16 slots (`13-payload-scoper.md:14-15`). Quality risk: **MEDIUM** without presence index; **LOW** with unchanged `classify_candidate_evidence` on full md.

- [HIGH] **Hard caps elsewhere: 8000 output tokens, 16384 model context, invalid responses retried not truncated.** Evidence: `MAX_TOKENS = 8000` on every page request (`pipeline.py:107,144`); `MODEL_MAX_CONTEXT = 16384`, responses with `total_tokens > MODEL_MAX_CONTEXT` marked `is_valid=False` (`pipeline.py:162,202-203`); vLLM default `--max_model_len 16384` (`pipeline.py:1255`). Bench runner mirrors `max_tokens: 8000` (`bench/runners/run_server.py:78`). Fallback path uses uncapped pdftotext only after VLM failure (`pipeline.py:234-239`). Impact: olmocr bounds **decode** aggressively (8000 tok/page) while keeping **prefill** small (no anchoring in v4); our unit checks cap output at **1536 tok** (`00-baseline.md:27-28`) but leave **input unbounded**. Trimming input to olmocr-scale (~4–8K chars candidate slice) attacks the right side of the latency equation for long papers; combined with prefix-cache reorder (persona 15) could reach **~400 s** fleet savings without call elimination. Quality risk: **LOW** for input scoping with full-doc mechanical refutation; output cap already tighter than olmocr.

- [HIGH] **Per-call unit = one page image + scoped auxiliary text; fleet parallelism is cross-page, not cross-document context.** Evidence: each `build_page_query` renders **one page** PNG (`pipeline.py:109-111`, `data/renderpdf.py` via import); work queue submits all pages in a PDF concurrently (`05-web.md:37-40`, `pipeline.py:1220-1224` `--workers 20`, `--max_concurrent_requests 1600`). Legacy anchored prompts (`build_finetuning_prompt`, `build_openai_silver_data_prompt`) wrap anchor in `RAW_TEXT_START…RAW_TEXT_END` (`prompts.py:147-153`, `7-17`; `bench/runners/run_server.py:48-55` still calls `get_anchor_text` with default **4000-char** pdfreport cap). Impact: olmocr never prefills a 500-page document into each page call; our unit judge prefills **full candidate_md** per routed page (`unit_judge.py:769-776`). Middle ground aligned with olmocr + persona 13/54: send **one page source packet** (already scoped) + **matched candidate section window** + **compact presence sketch**; keep `verify_unit_evidence`/`verify_defect_counts` on full md (`unit_judge.py:604-660,681-729`). Metadata call already demonstrates bounded candidate pattern (`unit_judge.py:220-256`). Quality risk: cross-page join false-fail unless ANYWHERE rule paired with mechanical presence (`unit_judge.py:137-139`).

- [MED] **Prompt template sizes: static v4 ~500 chars; legacy anchored templates ~1.5–2.5K chars + variable anchor.** Evidence: `build_no_anchoring_v4_yaml_prompt()` (`prompts.py:164-170`); `build_finetuning_prompt(base_text)` adds fixed wrapper + unbounded `base_text` (`prompts.py:147-153`); silver-data v1/v2 add ~800-char instruction block + anchor (`prompts.py:7-31`). Training pipeline `StaticLengthDocumentAnchoring(target_anchor_text_len=6000)` before prompt build (`dataloader.py:206-212`, `1341`). Impact: system/instruction overhead is negligible vs our **~3.7K-char** `CONVERSION_CONTRACT` × every call (`00-baseline.md:48-49`); olmocr's speed win is **input document bytes**, not prompt boilerplate. Quality risk: none.

- [MED] **Mechanical checks outside the VLM mirror our post-LLM grounding layer.** Evidence: olmOCR-bench `test.run()` is pure Python (rapidfuzz, table neighbors, KaTeX) with **no LLM in eval** (`80-olmocr-bench-quality.md:9-10`); pipeline fallback substitutes pdftotext without re-invoking VLM (`pipeline.py:234-239`). Our lane already separates LLM triage from mechanical refutation (`unit_judge.py:681-729`, `source_router.py:167-265` token-set deltas and `content_recall` pre-gates). Impact: olmocr's quality proof is **deterministic facts on scoped page markdown** (~7k tests); our speed lever should move presence/count work to the same layer (expand token-set intersection before LLM, scope LLM to ambiguous spans only — spinov pattern in `05-web.md:99-100`). Est. skipping LLM on the **70% zero-defect unit checks** (`00-baseline.md:29-30`) via stronger mechanical pre-gate: **~1057 calls × ~20 s / 16 ≈ 1320 s wall** if router precision improves (orthogonal to payload, but olmocr-bench density motivates it). Quality risk: **HIGH** if mechanical gate false-clears; **LOW** if only suppresses calls with proven token-set parity.

- [LOW] **8192 appears in unrelated IO/miner paths, not payload policy.** Evidence: S3 chunk reads `8192` bytes (`s3_utils.py:363`); Gemini miners `max_output_tokens=8192` (`bench/miners/mine_tables_gemini.py:159`, etc.). Impact: do not cite these as anchoring policy. Quality risk: none.

## False-pass hypothesis

Scoped candidate window without full-document presence index: a cross-page join tail lives under an earlier heading (tomd join rule); the LLM sees only the page-local window, returns pass or low-severity review, and no defect group triggers — olmocr avoids this by **page-scoped generation** (output is only that page's text) whereas we **verify** cross-page presence; copying olmocr's scope without our `classify_candidate_evidence` on full md reproduces persona 13's silent miss (`unit_judge.py:137-139`, `13-payload-scoper.md:26-27`).

## False-fail hypothesis

Strict section window + unchanged ANYWHERE prompt: dehyphenated or wording-markup-wrapped text exists document-wide but outside the window; model flags `content_omission`; mechanical refutation saves only when the model emits a grounded `source_quote` — otherwise review inflation. olmocr's random anchor truncation (`anchor.py:339-340`) can drop mid-page tokens yet bench still passes because **generation** does not ask "is phrase X anywhere in doc"; our **verification** task needs token-set intersection pre-check (like `source_router.py:173-206` document-wide token deltas) before the LLM call.

## What would change my mind

Holdout replay (48-paper holdout, persona 47 protocol) showing unit checks rewritten with olmocr-style bounded windows (≤8K chars candidate slice) + mechanical token-set presence index + unchanged post-hoc grounding achieves **≥25% cold-fleet wall reduction** with **≤1% fused-verdict diff** vs full-md control — that would elevate payload scoping from "necessary complement to prefix cache" to "primary lever toward 5–10 min."
