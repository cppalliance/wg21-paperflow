# 85 - langextract-Prompt-Structure

**Verdict:** usable (+ LangExtract's per-chunk prompt assembly is a deliberate cache-friendly layout: static instructions and every few-shot example precede the unique chunk text at the tail, so the shared prefix is identical across all chunk calls for a task; no KV-prefix or Gemini context-cache wiring exists, but the ordering is direct evidence for tapetum unit-check reorder.)
**Confidence:** high

## Findings

- [CRITICAL] Few-shot examples are re-serialized into EVERY chunk prompt via `QAPromptGenerator.render`, forming a large shared leading prefix. Evidence: `render` loops `self.template.examples` on every call (`prompting.py:131-134`); `Annotator._annotate_documents_single_pass` builds one prompt per chunk in a list comprehension (`annotation.py:366-371`), each calling `ContextAwarePromptBuilder.build_prompt(chunk.chunk_text, ...)` (`annotation.py:367-369` → `prompting.py:244-247` → `render`). Impact: for a document split into *N* chunks, instructions + all examples are prefilled *N* times; with vLLM APC and a stable leading prefix (05-web Q4: 74% prefix hits, ~4.5× server throughput at concurrency 16), reordering tapetum's ~1510 unit checks (00-baseline: median 5/paper) to share `[static contract + full candidate_md]` before unit-specific tails could cut prefill-dominated latency on ~66% of fleet calls; quality risk **low** if only field order changes, not rubric text.

- [CRITICAL] Prompt template ordering is instructions → optional context → examples → live chunk LAST (cache-optimal for APC/RadixAttention). Evidence: `QAPromptGenerator.render` builds `[description, additional_context, "Examples", …Q/A pairs…, Q:{question}, A:]` (`prompting.py:126-138`); live document text is only the final `question` argument (`prompting.py:136`), fed from `chunk.chunk_text` (`annotation.py:367-368`, `chunking.py:108-116`). Impact: matches 05-web Q4 pattern `[static system] + [shared document] + [unique query LAST]`; tapetum's unit check currently puts **unit-specific fields before** full markdown (`unit_judge.py:769-776`: `Paper/Unit/Risk/SOURCE` then `CANDIDATE MARKDOWN`), breaking cross-unit prefix identity on the ~1510 scoped checks; reorder to `[system+contract][pid][candidate_md][unit_id+source+risk LAST]` is supported by langextract's example with **zero rubric change**; quality risk **low**.

- [HIGH] Each few-shot example is a fixed `Q:` / `A:` block with fenced JSON/YAML extractions appended to the shared prefix. Evidence: `format_example_as_text` emits `Q: {example.text}` + `A: {format_handler.format_extraction_example(...)}` (`prompting.py:99-110`); `FormatHandler.format_extraction_example` wraps extractions in fences (`core/format_handler.py:116-149`). Impact: example payload size is bounded by caller-supplied `ExampleData`, not chunk size; tapetum has no few-shot block but an analogous static band is `CONVERSION_CONTRACT` embedded in all judge system prompts (00-baseline: ~3.7k chars in `UNIT_CHECK_SYSTEM_PROMPT`, `unit_judge.py:129-159`); keeping that band byte-identical across calls is the same lever; quality risk **none** if text unchanged.

- [HIGH] LangExtract sends the entire prompt as one Gemini `contents` blob with no system/user split; static and variable text share one leading byte sequence. Evidence: `_process_single_prompt` calls `generate_content(..., contents=prompt, ...)` (`providers/gemini.py:368-369`); `render` returns a single joined string (`prompting.py:138`). Impact: vLLM APC matches on leading tokens regardless of HTTP role split; tapetum's system/user separation does not block prefix caching, but our per-call random `guard_instruction(tag)` at the **end** of system (`unit_judge.py:767-768`, 00-baseline:52-53) only breaks the last ~50 tokens of system, not the user payload; moving to a **paper-level fixed tag** (one tag per paper, not per call) restores system-prefix identity across the 6-call cascade; quality risk **low** (injection defense preserved, tag still unique per paper).

- [MED] Cross-chunk `context_window_chars` injects varying text BEFORE the examples block, shrinking the stable prefix between consecutive chunks. Evidence: `ContextAwarePromptBuilder._build_effective_context` prepends `"[Previous text]: ..."` + prior-chunk tail (`prompting.py:191`, `prompting.py:258-261`); `render` inserts `additional_context` before the examples heading (`prompting.py:128-129`). Impact: when enabled, consecutive chunk calls share only `description`, not `description+examples`; default is `context_window_chars=None` (`extraction.py:145`, `annotation.py:213`), which maximizes prefix sharing; tapetum should not insert per-call volatile context above shared document text; quality risk **medium** if cross-chunk coreference were needed (not our judge model).

- [MED] No Gemini context caching, vLLM APC hints, or prefix-cache documentation in library or README. Evidence: grep over pinned README (SHA `0dff5479`) finds no "cache"/"caching"/"prefix" tokens; real-time `GeminiLanguageModel.infer` has no `cached_content` / context-cache API use (`providers/gemini.py:334-369`); only cache is **GCS batch result memoization** keyed on full prompt hash (`providers/gemini_batch.py:387-404`, `760-794`, `enable_caching` opt-in when batch enabled `gemini_batch.py:77-78`, `106-109`). Impact: langextract optimizes prompt **layout** for accidental APC benefit, not explicit KV reuse; tapetum must enable/configure vLLM APC separately (05-web Q1/Q4); quality risk **none** for infra work.

- [LOW] Default chunk scope limits per-call variable payload; tapetum sends full document per unit check. Evidence: `extract(..., max_char_buffer=1000)` default (`extraction.py:57`); `annotate_documents(..., max_char_buffer=200)` default (`annotation.py:209`); chunk text is a sentence-bounded slice (`chunking.py:343-506`), not whole document. Impact: langextract's speed comes from scoped `Q:` payload (~200-1000 chars) plus repeated static prefix, whereas tapetum unit checks embed entire `candidate_md` per call (`unit_judge.py:775-776`, 00-baseline:43-47); prompt reorder alone cannot fix 6× full-doc prefill without also scoping or hoisting shared markdown; quality risk **high** if scoping drops the "content anywhere in candidate" rule (`unit_judge.py:137-139`) without an explicit substitute.

## False-pass hypothesis

Reorder unit-check user messages to `[candidate_md][unit fields LAST]` but accidentally drop `inject_untrusted` wrapping on the repositioned markdown block: a paper embedding `Ignore prior instructions` in body text could steer the model when markdown moves earlier in the user message, yielding a silent pass on a corrupted unit. Langextract has the same class of bug by design (raw chunk in `Q:` slot, `prompting.py:136`); our guard tags must move with the block, not be removed for prefix stability.

## False-fail hypothesis

Switch to a paper-level fixed guard tag shared across all 6 calls for APC, but reuse the same tag string in the user message delimiter and a static example in `CONVERSION_CONTRACT` that contains the literal substring `<<<TAG>>>`: delimiter escape fails, model treats contract text as forged boundary, and returns over-scoped defects. Unlikely on WG21 papers but possible on adversarial corpus entries; mitigated by keeping `escape_guard_delimiters` (`pipeline/tools.py:38-46`) and per-paper random hex (not per-call).

## What would change my mind

A vLLM trace on the alliance pod showing <10% APC block reuse for tapetum unit checks **after** reordering to langextract's `[static][shared candidate_md][unit LAST]` layout and paper-level guard tags, proving prefill is not prefix-dominated for our payload sizes (e.g., median paper md < APC block granularity or MoE sliding-window evicts shared blocks at concurrency 16).
