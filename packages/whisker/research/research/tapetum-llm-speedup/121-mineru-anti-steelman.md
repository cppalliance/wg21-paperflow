# 121 - mineru-Anti-Steelman

**Verdict:** garbage (+ MinerU's published fast path is batched 1.2B VLM page extraction or zero-LLM CNN pipeline inference; it performs no post-conversion LLM verification, so it cannot anchor a 3003 s → 5-10 min *judge* speedup at tapetum fidelity.)
**Confidence:** high

## Findings

- [CRITICAL] **MinerU performs no LLM-judge verification of an already-produced conversion against source.** Production paths emit markdown from layout/OCR/VLM atom models or `batch_two_step_extract` page images; none compare rendered markdown to the PDF with grounded defect quotes. Repo-wide `rg judge|verification|verify.*markdown|compare.*source|grounded|defect` over `mineru/**/*.py` returns only geometric table-matcher comments (`matcher_utils.py:242`), not QA. Optional `llm-aided-config` title leveling calls an external chat API to assign heading levels (`llm_aided.py:352-382`, `title_level_postprocess.py:17-38`) — post-process **enhancement**, disabled unless config enables (`title_level_postprocess.py:27-28`), not conversion verification. Impact: **0 s** judge wall-clock saving by copying MinerU wholesale; quality risk if synthesis treats "fast extraction" as "fast verification."

- [CRITICAL] **Headline throughput numbers measure extraction, not MoE reasoning over 40k-token judge payloads.** Primary VLM is `MinerU2.5-Pro-2604-1.2B` (`README.md:126-127`); changelog claims "<1B" params and ">10,000 tokens/s" on a single 4090 via sglang (`docs/en/reference/changelog.md:274-276`) — historical peak on **dense page-image decode**, not our **deepseek-v4-pro** MoE at **393216** context (`00-baseline.md:65-67`) with **~6 serial calls/paper** resending full candidate markdown (`00-baseline.md:43-47`, `unit_judge.py` pattern in `00-baseline.md:44`). VLM path: one `batch_two_step_extract(images_pil_list)` per 64-page window (`vlm_analyze.py:479-482`, window default `config_reader.py:158-169`, `api_protocol.py:4`). Pipeline path: CNN layout + OCR + MFR + table atom models only, **zero VLM/LLM calls** (`batch_analyze.py:426-450`, `pipeline_analyze.py:336-386`). Speed logs are `page/s` over infer windows (`vlm_analyze.py:509-511`, `pipeline_analyze.py:320-322`, `hybrid_analyze.py:1072`). Impact: citing MinerU "shows it can be done fast" without naming backend conflates **~1.2B image→markdown** with **~20 s/call MoE judge** (`00-baseline.md:24-25`). False comparison.

- [CRITICAL] **Latency math closes only if task parity is ignored.** Corpus estimate: 381 papers × ~13 pages ≈ **4953 pages**. MinerU VLM/hybrid: **~1 generative touch/page** (batched within window). Our fleet: **2284 calls / 381 papers = 6.0 calls/paper** (`00-baseline.md:22-23`), **~120 s serial paper wall** regardless of 32 cross-paper slots (`00-baseline.md:38-39`). Even at optimistic **3.8 pages/s** (Docling-class VLM bench, `57-docling-anti-steelman.md`) on 4953 pages: **~1303 s extraction-only** — still not verification, and still on **1.2B dense VLM**, not 6× DeepSeek monolith/metadata/escalation/unit passes. MinerU's default API caps **3 concurrent documents** (`api_protocol.py:3`, `config_reader.py:172-192`, `client.py:765-768`) while fanning up to **100 in-doc page requests** on http-client (`vlm_analyze.py:71,231`) — the opposite of our bottleneck (high cross-paper concurrency, zero in-paper parallelism). Impact: copying MinerU concurrency defaults **slows** our fleet; copying page fan-out without call elimination cannot reach **300 s** on 2284 judge calls. Quality risk: treating page/s as per-call judge latency.

- [HIGH] **MinerU is worse than tapetum-llm on determinism guarantees, incremental skip, and audit trails.** Title LLM uses `temperature: 0.7`, no seed, `json_repair.loads` on free text (`llm_aided.py:178-204`) — violates D5 (`00-baseline.md:86`). No whole-paper or per-unit fingerprint skip: `hash_utils.py` names image assets only (`hash_utils.py:7-30`; used at `pdf_image_tools.py:506`, not fleet skip). No trace/debug LLM I/O artifacts — only `logger.debug` on raw title output (`llm_aided.py:176,202`). Fail-open: broken PDF pages skipped and partial docs emitted (`common.py:204-221`); OCR confidence drops spans below 0.5 (`117-mineru-quality-speed.md` cites `ocr_utils.py:10-11`) without document-level fail-closed. Contrast our warm **64.8 s** / **375/381 skipped** fingerprint path (`00-baseline.md:19-20`, `cli.py:566-591`) and fail-closed coverage caps (`constants.py:191-223`). Impact: MinerU's speed partly buys **best-effort emit**; porting their error posture would recreate false-pass on missing pages/units. Quality risk: **HIGH**.

- [HIGH] **Default hybrid `effort=medium` is a measured quality-speed trade on conversion, not a judge cascade.** Medium forces `image_analysis=False` (`hybrid_analyze.py:117-121`, per `117-mineru-quality-speed.md`); README documents **−0.13** OmniDocBench vs high and **+35%–+220%** speed (`README.md:105-109`, accuracy table `241-246`). Code path: medium uses pipeline layout → `batch_extract_with_layout`; high uses full `batch_two_step_extract` (`hybrid_analyze.py:965-1033`). Impact: tiering pattern is portable for **our** dense→MoE escalation (`05-web.md:88-100`), but MinerU's −0.13 bench delta is **conversion** accuracy, not defect-class recall on WG21 goldens. Blindly mirroring medium-default could save **~700–1320 s** on unit checks (70% zero-defect, `00-baseline.md:29-30`) but risks silent loss of image/chart defect classes. Quality risk: **MED–HIGH**.

- [MED] **What we should still take: engine configs, batch dispatch, tiering — all conversion-scoped.** (1) **VRAM-tiered batch_ratio**: 16/8/4/2/1 by GPU memory for pipeline (`pipeline_analyze.py:353-363`) and hybrid OCR/layout/MFR (`hybrid_analyze.py:835-876`) — portable as auto-tuning for dense judge batch size. (2) **Two-level batching**: 64-page memory windows (`vlm_analyze.py:446-482`) + in-window `batch_two_step_extract` / `batch_predict` stepping vs concurrent modes (`114-mineru-pipeline-batching.md`, `mineru-vl-utils` client) — analog for in-paper parallel unit checks (advisory D11 exemption, MoE variance risk `00-baseline.md:96`). (3) **vLLM server recipe**: default `--gpu-memory-utilization` 0.5 (0.7 if ≤8 GB, `utils.py:83-92`), optional `MinerULogitsProcessor` (`vllm_server.py:45-53`), param passthrough (`docker/compose.yaml:15,45,80`) — no MinerU-specific `--max-num-seqs`; our `--max-num-seqs 16` already matches DeepSeek recipe (`05-web.md:15-17`). (4) **Corpus dispatch**: `plan_pipeline_tasks` bin-packs small docs into 64-page tasks longest-first (`client.py:609-647`); `mineru-router` load-balances workers (`router.py:763-785`). (5) **API concurrency split**: server slot limit (3) separate from in-doc fan-out (100) — validates raising in-paper parallelism before cross-paper slots (`114-mineru-pipeline-batching.md`). Impact: infrastructure levers may contribute **~950–1500 s** combined with call elimination (`114-mineru-pipeline-batching.md` estimates), not alone to **≤600 s**. Quality risk: low if applied as infra, HIGH if confused with "drop verification."

- [LOW] **Regression QA is fuzzy fixture assert, not golden fleet replay.** `test_e2e.py` checks one synthetic PDF via `fuzz.ratio > 90` on captions/tables (`test_e2e.py:152-178`) after pipeline-only parse — no LLM, no 381-paper holdout, no verdict schema. Impact: MinerU proves deterministic tripwires on toy fixtures; our 1510 unit-check calls (`00-baseline.md:22-23`) remain irreplaceable for advisory fidelity. Quality risk: none for speed study; HIGH if fuzzy asserts replace golden contract.

## False-pass hypothesis

Synthesis adopts MinerU hybrid **`effort=medium`** (skip `image_analysis`, `hybrid_analyze.py:117-121`) plus **`temperature=0.7` title LLM** (`llm_aided.py:181`) as the tapetum default, and cuts unit checks on "easy" papers. Chart-in-table and cross-page figure defects pass silently — the same blind spot MinerU accepts for −0.13 OmniDocBench (`README.md:105-109`) — while our deterministic lane already caught PR-class table/header swaps that LLM missed (`57-docling-anti-steelman.md` class-5 pattern).

## False-fail hypothesis

Copy MinerU **broken-page skip** (`common.py:218-221`) into tapetum: a single corrupt PDF page drops from source comparison scope, unit checks still run on full markdown but escalation source text is incomplete — legitimately good conversions **false-fail** on "missing content" defects that are actually source-load gaps, inflating review rate without catching real tomd bugs.

## What would change my mind

A cold benchmark on our **381-paper corpus** where MinerU (any backend) performs **post-tomd LLM verification** with evidence-grounded per-page defect quotes, fail-closed coverage on cap overflow, structured Pydantic output, and **≥95% merged-verdict agreement** with current tapetum-llm on a 50-paper stratified holdout including the **16/381** LLM-changing papers (`00-baseline.md:29-30`) in **≤600 s** wall — without `temperature=0.7` title calls, broken-page skip, or partial-document emit. No such code path exists in `mineru/` today (`llm_aided.py:352` is title polish only; `vlm_analyze.py:479` is extract-only).
