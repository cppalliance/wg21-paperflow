# 32 - Structured-Output-Mechanic

**Verdict:** usable-with-conditions — vLLM `response_format` / xgrammar constrained JSON is worth a holdout A/B after pod upgrade (#41199), but it saves ~100 s (~3%) on the measured cold run and cannot move 3003 s toward 5–10 min; reject as a primary fleet speed lever until verdict drift is ruled out.
**Confidence:** high (current mechanism + retry census); medium (guided-json latency/drift on alliance-pod without live probe)

## Findings

- [CRITICAL] Production tapetum judge calls use **schema-in-prompt + free-text parse**, not server-side guided decoding. `alliance-pod` maps to `backend = "vllm_thinking"` (`SERVICES.toml:64-74`). `VllmThinkingBackend.run()` appends `_schema_instruction(output_type)` to the system prompt (`model_backends.py:285-286`), streams `chat.completions.create` with no `response_format` / `guided_json` / tool binding (`model_backends.py:307-316`), strips `<think>` (`model_backends.py:352`), brace-depth extracts JSON (`model_backends.py:104-122,362-364`), then `json.loads` + `output_type.model_validate` (`model_backends.py:363-364`). Docstring explicitly cites "Schema-in-prompt structured output (tool calling broken #28219)" (`model_backends.py:231`). `judge_task.py` adds no enforcement; it forwards `output_type` to `AgentBackend.run` (`judge_task.py:68-74`). Impact: structural compliance is voluntary cooperation + client-side repair, not token-level guarantees. Quality risk: low for current baseline; changing mechanism shifts token distributions (see below).

- [HIGH] Retry budget is **2 attempts max** on the judge path, not pydantic-ai's `output_retries=3`. `max_attempts = min(2, request_limit)` (`model_backends.py:300`); judge calls use default `request_limit=500` via `AgentBackend.run` (`agents.py:121`, `judge_task.py` passes none). Failure triggers: `MalformedModelOutputError`, `JSONDecodeError`, `ValidationError` → conversational nudge retry (`model_backends.py:371-406`); `finish_reason=="length"` → 1.5× `max_tokens` regrow without nudge (`model_backends.py:377-387`); transient API errors → exponential backoff (`model_backends.py:341-350`). BPE cleanup runs before parse (`model_backends.py:77-90,106`). Impact: one repair loop per call; exhausted attempts raise `MalformedModelOutputError` and fail the paper call.

- [HIGH] Measured failure/retry rate on the v10 cold fleet: **55 model retries / ~2284 LLM calls ≈ 2.4%**, adding **~100 s wall (~3.3% of 3003 s)**. Baseline: "55 model retries" and "attempt 2 succeeds" for BPE-corruption artifact (`00-baseline.md:18,60-61`). CLI counts backend warnings `"Raw JSON parse failed"`, `"Raw JSON output truncated"`, `"Transient API error"` (`cli.py:218-227,1414`). Impact: eliminating all retries saves **≤~100 s**, not the ~2400 s needed for a 5–10 min target. Retries are a rounding error on wall clock, not the bottleneck.

- [HIGH] Judge schemas are short but **nested and validator-gated**, not trivial flat objects. `PdfJudgment`: 4 top-level fields (`pdf_judge.py:252-269`). `PageJudgment`: 4 fields + `@model_validator` (`models.py:191-228`). `UnitCheck`: 5 top-level + nested `DefectFinding` + validator (`models.py:298-320`). `MetadataOutlineCheck`: 7 top-level + validator (`models.py:262-295`). `MODELS.md` documents ≥5-field stability for **constrained decoding on Qwen3** (`MODELS.md:35-53`); our V4 path explicitly avoids constrained decoding (`MODELS.md:119-120`). Impact: guided JSON would enforce syntax, not semantic validators (`verdict_matches_defects`, etc.); Pydantic validators still run client-side after decode.

- [MED] vLLM guided JSON (`response_format: json_schema` / xgrammar) is the documented retire-when for schema-in-prompt but is **not wired in pipeline today**. `MODELS.md:119-120` lists "Schema-in-prompt JSON" and "Raw JSON + retry" retire-when as "vLLM unified parser OR pydantic-ai VLLMProvider". vLLM 0.24 docs: legacy `guided_json` removed v0.12+; use `response_format` with `--reasoning-parser`; xgrammar **defers grammar masking until reasoning `end_token_id`** (https://docs.vllm.ai/en/stable/features/structured_outputs/, cited in `05c-web-prefix-guided.md:47-53`). Benchmark direction (not our pod): structured-output serving +31.5% req/s, −21% TPOT on Qwen3-8B (`05c-web-prefix-guided.md:57-63`; https://github.com/vllm-project/vllm/pull/24300). Impact: per-call decode may improve under batching; first-attempt parse success likely rises; **wall savings capped at retry elimination (~100 s)** unless combined with other levers.

- [MED] **Verdict-drift risk is real and contradicts D6/D10's current contract.** Constrained decoding narrows valid token sequences and changes distributions (`MODELS.md:47-49`: "More fields = more structural checkpoints"). SOB ablation: constrained decoding +8–10 pp JSON pass, **Value Accuracy ±0.03** (`deepseek-v4-pro/10-structured-output-schema.md:16`). olmOCR deliberately avoids guided JSON at inference ("repetition collapse; parse failures just retry", 12% measured retry) (`05-web.md:47-48`, https://olmocr.allenai.org/papers/olmocr.pdf). Advisory lane already documents **≥25% verdict-flip rate** on identical reruns (`whisker/CLAUDE.md` tapetum section). Impact: flipping to guided JSON without holdout diff risks silent quality change while saving ~3% wall — violates "same findings, same verdicts" (`00-baseline.md:77-78`).

- [MED] **Thinking-mode interplay is the gating dependency**, not schema size. Judge agent omits `thinking_budget`; comment: "pod ignores it (live probe 2026-07-07)" (`cli.py:1032-1036`). When `thinking_budget is None`, `VllmThinkingBackend` sends no `enable_thinking` override (`model_backends.py:294-298`) — server default thinking applies. Current path reads only streamed `delta.content`, then strips think blocks (`model_backends.py:322-328,352`). vLLM #41132: with `response_format` + thinking, JSON landed in `reasoning` while `content=None` on DeepSeek-V4-Pro; fixed #41199 (https://github.com/vllm-project/vllm/issues/41132). Qwen3 constrained-decoding + thinking instability documented separately (`model_backends.py:584-587`, vLLM #39677). Impact: guided JSON requires pod on vLLM ≥ #41199, correct `--reasoning-parser deepseek_v4`, and smoke test that JSON is extractable from `content` after thinking — otherwise both paths fail closed with empty parse.

- [LOW] Alternative backends (`Llama3Backend`, `Qwen3Backend`, `AnthropicBackend`) use pydantic-ai `Agent(output_type=..., retries=3)` which engages provider/vLLM JSON-schema tooling (`model_backends.py:547-551,642-646,720-725`) — **not the tapetum judge path**, which resolves `deep`/`default` to `vllm_thinking` (`cli.py:1026-1036`, `SERVICES.toml:64-74`). Impact: migrating judge to a non-thinking backend would change enforcement mechanism and model behavior simultaneously — confounded experiment.

## False-pass hypothesis

Guided JSON guarantees syntactically valid `UnitCheck` JSON on attempt 1; a model fills `defects: []` with `verdict: "pass"` while omitting a table swap that free-form decoding occasionally caught via longer `reasoning` tokens before JSON commit. Schema validity passes; grounding post-process finds nothing to refute; advisory pass where review was warranted.

## False-fail hypothesis

Pod runs pre-#41199 vLLM: guided JSON emits valid `PdfJudgment` inside the `reasoning` channel while `content` stays empty. Client still reads `delta.content` only (even with `response_format`), `_extract_json` fails twice, paper marks `error` despite the model having produced correct structured output in an unobserved field — same failure mode documented for `response_format` + thinking (#41132).

## What would change my mind

Holdout re-run (48 verified anchors, `corpus/holdout`, no threshold tuning): alliance-pod with `response_format json_schema` on `UnitCheck`/`PdfJudgment`, vLLM version logged, **≥98% first-attempt parse**, **≤1 pp shift in pass/review/fail histogram vs schema-in-prompt baseline**, and **zero new missed defects** on the 7-strata holdout — would upgrade to **usable** and justify a pipeline `VllmThinkingBackend` flag flip; if first-attempt parse rises but histogram shifts ≥2 pp, keep schema-in-prompt for quality-stability.
