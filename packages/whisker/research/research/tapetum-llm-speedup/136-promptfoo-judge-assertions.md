# 136 - promptfoo-Judge-Assertions

**Verdict:** usable-with-conditions (documented tiered/preflight patterns and terse rubric schema are portable; runtime does NOT auto-gate LLM after deterministic checks unless the user opts in)
**Confidence:** high

## Findings

- [CRITICAL] promptfoo runs every assertion in YAML list order with no built-in "deterministic first, skip LLM on fail" gate. `runAssertions` maps the full `test.assert` array and dispatches all entries via `async.forEachOfLimit` without checking prior results (`src/assertions/index.ts:749-822`). Docs explicitly say classifier + LLM judge in the same list both run and either failure fails the row (`site/docs/guides/llm-as-a-judge.md:305-306`). Impact: the "LLM as expensive last resort" pattern is **convention** (put `is-json`/`regex`/`javascript` above `llm-rubric` in YAML), not engine enforcement. Against our 2284-call census: whisker already has deterministic gates but still fires monolith + metadata + up to 5 unit checks unconditionally per paper (~6 calls/paper); promptfoo offers no magic switch—only user-config ordering plus optional short-circuit (below). Quality risk if we copy the doc pattern without short-circuit: zero savings; if we add short-circuit: must prove no token-preserving corruption escapes (whisker documents a "selection gap" for clean-pass papers).

- [HIGH] Opt-in short-circuit exists but is off by default. On first failing assertion, `AssertionsResult.addResult` throws when `PROMPTFOO_SHORT_CIRCUIT_TEST_FAILURES` is true (`src/assertions/assertionsResult.ts:133-141`, env read via `getEnvBool` at line 139). Without that env var, failed deterministic checks do **not** stop later LLM assertions from running. Impact: portable pattern = ordered asserts + `PROMPTFOO_SHORT_CIRCUIT_TEST_FAILURES`-equivalent before any model-graded step. On 381 papers × median 5 unit checks: if deterministic+screen already cap at `review`/`fail`, skipping downstream LLM could cut up to ~1510 unit-call equivalents (~1890 s wall at 20 s/call ÷ 16 slots) **only if** gating criteria match promptfoo's fail semantics; quality risk = missing LLM-only defects on papers deterministic lane passes (16/381 papers had merged verdict changed by LLM today per 00-baseline).

- [HIGH] Assertion-level concurrency defaults to 3 parallel handlers per test case (`ASSERTIONS_MAX_CONCURRENCY = getEnvInt('PROMPTFOO_ASSERTIONS_MAX_CONCURRENCY', 3)` at `src/assertions/index.ts:114`; applied at `797-822`). When a provider grouping queue is active, concurrency drops to 1 to preserve same-judge batching (`791-795`). Deterministic handlers (`contains`, `regex`, `levenshtein`) are synchronous/local (`src/assertions/regex.ts:5-32`, `levenshtein.ts:6-28`); LLM types are in `MODEL_GRADED_ASSERTION_TYPES` (`122-134`). Impact: promptfoo parallelizes cheap and expensive asserts up to 3× within a row—opposite of our serial per-paper chain (`pdf_judge.py:753`, `unit_judge.py:389`). Not directly portable under D11/quality-stability without MoE variance analysis; eval-level default is separate: `DEFAULT_MAX_CONCURRENCY = 4` test rows (`src/constants.ts:8`, evaluator uses at `4566-4567`).

- [HIGH] Model-graded work can be **deferred and provider-grouped** for throughput, not skipped. Tests with any `MODEL_GRADED_ASSERTION_TYPES` (plus `g-eval`, `conversation-relevance`) set `deferGrading: true` (`src/evaluator.ts:488-504`, `1249-1268`). Grouping activates only when eval concurrency is 1, no per-step timeout, no conversation vars (`4668-4669`, `3718-3727`); grader jobs batch by `providerId` via `ProviderGroupedCallQueue` (`src/scheduler/providerCallQueue.ts:35-56`, `runGroupedGradingForRows` at `2819-2883`). Impact: saves local-model reload latency, **zero call elimination**. Our dual-pod sharding is closer to this than to gating.

- [MED] Tiered evaluation is documentation/workflow, not a single-pass scheduler. Guide recommends Tier 1 deterministic always-on, Tier 2 cheap judge always-on, Tier 3 expensive judge only on failures/borderline/high-risk via **separate filtered evals** (`site/docs/guides/llm-as-a-judge.md:1005-1060`, e.g. `--filter-metadata risk=high`). No code path skips `llm-rubric` based on prior tier results inside one `runAssertions` call. Impact: maps to whisker running a cheap preflight fleet (metadata-only or small model) before DeepSeek unit checks; 70% zero-defect unit checks (1057/1510 per 00-baseline) suggests a second-stage filter could drop ~46% of total calls (~1057/2284) if zero-defect prediction is calibrated—quality risk proportional to false-skip rate on the 16/381 verdict-changing papers.

- [MED] Terse LLM rubric schema is first-class. Default grading prompt demands JSON `{reason: string, pass: boolean, score: number}` with few-shot examples (`src/prompts/grading.ts:11-29`); `runJsonGradingPrompt` parses first JSON object, coerces pass/score, optional assertion threshold (`src/matchers/rubric.ts:737-878`). Closed-QA legacy path ends with single `Y`/`N` line (`src/matchers/llmGrading.ts:401-417`). Doc template caps reason to one sentence (`site/docs/guides/llm-as-a-judge.md:519-521`). Impact: aligns with 05-web SLMJury/LLMTrace (short outputs); our unit-check cap is 1536 tokens with 40-60 word reasoning (`00-baseline:27-28`)—output-token reduction lever is orthogonal to gating but same rubric design family. Wall saving: decode-bound; not quantified here without A/B.

- [LOW] G-Eval is the one in-framework serial short-circuit: criteria evaluated one-by-one, breaks on grader transport failure (`src/assertions/geval.ts:36-55`). Impact: partial model for multi-criterion whisker unit checks (stop spending calls after hard grader failure); does not skip criteria on pass. Minor wall saving, low quality risk.

- [LOW] Within-assert-set aggregation uses weighted score/threshold, not early exit (`src/assertions/assertionsResult.ts:144-164`). `assert-set` with `threshold: 0.66` implements 2-of-3 judge majority (`site/docs/guides/llm-as-a-judge.md:828-860`) but still runs all nested asserts unless short-circuit env is set. Impact: voting pattern for multi-judge, not call reduction.

## False-pass hypothesis

Implement YAML-style ordering without short-circuit: deterministic whisker pass + monolith `pass` still runs 0-5 unit checks; a token-preserving table swap or math collapse that survives `unigram_coverage` and the per-page recall screen (`pdf_judge.py:631-636`) would keep a clean deterministic footprint while LLM unit checks are skipped—exactly the documented whisker "selection gap" (clean-pass papers with semantic corruption). Any gate that skips unit checks when deterministic verdict is `pass` must exclude that population or accept silent quality loss.

## False-fail hypothesis

Enable promptfoo-style short-circuit on first deterministic failure (e.g. `is-json` fail) before monolith/unit LLM runs: structurally invalid markdown would never reach scoped unit judges that might still catch unrelated defects, but for tapetum the monolith already runs first regardless; short-circuiting **after** monolith/metadata on metadata-fail would wrongly skip unit checks that sometimes rescue borderline structure-only issues (RESCUE population in whisker). Lower risk than false-pass if gate is "deterministic fail hard + monolith fail" only.

## What would change my mind

A whisker holdout run (48 anchors / dev-replay labels) comparing current fleet vs (1) ordered deterministic+screen gates with fail-closed short-circuit before unit checks, and (2) tier-2 cheap-judge triage before DeepSeek unit calls—reporting verdict drift on the 16/381 historically LLM-changed papers and zero-defect skip precision/recall. Without that, promptfoo proves pattern vocabulary, not safe call budget for our census.
