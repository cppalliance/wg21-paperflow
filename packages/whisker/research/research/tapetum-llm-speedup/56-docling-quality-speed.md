# 56 - docling-Quality-Speed-Tradeoffs

**Verdict:** usable-with-conditions (+ docling's speed wins come from skipping optional stages and gating expensive work, not from defaulting core extractors to minimum quality; the switch taxonomy ports to tapetum as a `--profile fast|thorough` CLI, but flipping the fleet default to fast without holdout replay violates the study's same-quality constraint)
**Confidence:** high

## Findings

- [CRITICAL] **Pipeline choice defaults to STANDARD, not VLM.** `ProcessingPipeline.STANDARD` is the CLI default (`docling/cli/main.py:769-772`), service default (`docling/datamodel/service/options.py:453-456`), and PDF `FormatOption` wires `StandardPdfPipeline` (`docling/document_converter.py:216-218`). VLM is opt-in via `--pipeline vlm`, swapping separate layout/OCR/table stages for one VLM pass per page (`docling/datamodel/pipeline_options.py:1341-1352`, `docling/cli/main.py:1316-1337`). Impact: docling's out-of-box path avoids the heaviest single switch; our lane has no VLM equivalent, but the lesson is "default = cheapest complete path, premium path explicit." Quality risk if we copied blindly: VLM and STANDARD are different defect profiles, not a strict superset.

- [CRITICAL] **Enrichments all default OFF; core extractors stay on.** `do_code_enrichment`, `do_formula_enrichment`, `do_picture_classification`, `do_picture_description`, and `do_chart_extraction` default `False` (`docling/datamodel/pipeline_options.py:1780-1286`, mirrored CLI `docling/cli/main.py:867-891`, service `docling/datamodel/service/options.py:532-585`). `HeadingHierarchyOptions.enabled` defaults `False` (`docling/datamodel/pipeline_options.py:1670-1679`). Preset configs exist but only activate when flags flip (`docling/datamodel/pipeline_options.py:1047-1065`). Impact: docling's largest speed lever is "do not run VLM enrichments unless asked"; on the 3003 s cold run our analog is skipping ~1510 unit-check calls (~67% of call volume, `00-baseline.md:22-23`) while keeping monolith+metadata. Quality risk: token-preserving table/cell corruption (PR #286 class) lives in the unit-check residue docling never had to judge.

- [HIGH] **OCR defaults ON but is selectively gated ("auto"), not full-page.** `do_ocr=True` (`docling/datamodel/pipeline_options.py:1770-1779`, `docling/cli/main.py:812-817`, `docling/datamodel/service/options.py:340-349`) with `force_full_page_ocr=False` (`docling/datamodel/pipeline_options.py:185-191`, `docling/cli/main.py:818-824`). Engine defaults to `OcrAutoOptions` (`docling/datamodel/pipeline_options.py:201-224`, `825`, `docling/cli/main.py:842`). OCR rectangles are emitted only when bitmap coverage exceeds `bitmap_area_threshold=0.05`, or full-page when coverage exceeds `max(0.75, threshold)` (`docling/models/base_ocr_model.py:52,111-127`, threshold defined `docling/datamodel/pipeline_options.py:192-198`). Impact: "OCR on" in docling means "run the OCR stage when needed," not "OCR every page"; analogous tapetum switch is deterministic pre-gate before unit checks (page screen + router hard signals), not `--no-ocr`. Wall saving if we gate unit checks like docling gates OCR: up to ~1510 calls removable only when router precision improves (`00-baseline.md:29-30`); today n=1 strict-clean paper (`24-cascade-designer.md:8`). Quality risk: soft router signals (`table_presence`, `heading_drift`) currently carry real unit findings on zero-flag pages.

- [HIGH] **TableFormerMode defaults ACCURATE, not FAST.** Enum documents FAST = "speed over precision," ACCURATE = "higher quality, slower, recommended for production" (`docling/datamodel/pipeline_options.py:93-107,135-143`). CLI `--table-mode` default `TableFormerMode.ACCURATE` (`docling/cli/main.py:863-866`); service API same (`docling/datamodel/service/options.py:432-443`). Impact: docling does **not** ship minimum table quality by default; speed comes elsewhere. Our lane already runs maximum judge depth always (`pdf_judge.py:880-890`, `MAX_UNIT_CHECKS=5` at `constants.py:223`); a docling-faithful `--profile fast` must **not** shrink quote budgets or schemas (forbidden by `00-baseline.md:84-86`) but may skip optional checks. Quality risk: setting `--table-mode fast` equivalent (lower MAX_UNIT_CHECKS without evidence) drops complex-table defects.

- [HIGH] **Image scale: library 1.0, service/VLM 2.0, CLI bumps on export.** `PdfPipelineOptions.images_scale=1.0` with doc "1.0 standard, 2.0 high resolution, 0.5 previews" (`docling/datamodel/pipeline_options.py:1846-1855`, `1311-1319`). Remote service defaults `images_scale=2.0` (`docling/datamodel/service/options.py:516-522`). `VlmConvertOptions.scale=2.0` (`docling/datamodel/pipeline_options.py:950-952`). CLI sets `images_scale=2` when image export modes require it (`docling/cli/main.py:1206-1214`). Optional picture-description `scale=2.0`, `picture_area_threshold=0.05` skip small figures (`docling/datamodel/pipeline_options.py:648-666`). Impact: resolution is a explicit cost knob; our analog is scoped payloads (`13-payload-scoper`) and suppressing thinking tokens (`31-thinking-token-auditor`), not sending full markdown 6× (`00-baseline.md:43-47`). Quality risk: lower image scale in VLM path loses fine table/code detail.

- [MED] **Device/threads/batching defaults favor throughput without quality tiers.** `AcceleratorOptions`: `device="auto"`, `num_threads=4` (`docling/datamodel/accelerator_options.py:32-55`); CLI mirrors (`docling/cli/main.py:981-994`). `page_batch_size=4`, `doc_batch_concurrency=1` (`docling/datamodel/settings.py:29-33`, CLI `docling/cli/main.py:1001-1007`). Threaded PDF pipeline: `ocr_batch_size=layout_batch_size=table_batch_size=4`, `batch_polling_interval_seconds=0.5`, `queue_max_size=100` (`docling/datamodel/pipeline_options.py:1908-1960`). `force_backend_text=False` keeps layout-model text; `True` bypasses layout for embedded-text PDFs (`docling/datamodel/pipeline_options.py:1798-1807,1351-1352`). Impact: portable as dual-pod sharding + in-paper parallel unit checks (`00-baseline.md:96-97`, `20-in-paper-parallelist`); mostly latency, not verdict drift, if MoE batch variance controlled. Quality risk: parallel in-paper checks raise quality-stability variance per D11 exemption note (`00-baseline.md:39-42`).

- [MED] **Proposed tapetum switch set (docling-isomorphic).** (1) **`--profile fast` (new default):** monolith + metadata/outline only; skip unit checks and page escalations unless hard router signals (`low_recall`, `token_delta`, `missing_code`) or page screen flags (`pdf_judge.py:753+`, `880-890`). (2) **`--profile thorough` (today's behavior):** current serial cascade, `--all-pages` maps to docling `--force-ocr` / full enrichment. (3) **`--max-unit-checks` / `--coverage-mode`:** already exist (`constants.py:223`, `cli.py:303`); keep caps, expose like `--table-mode`. (4) **Selective routing threshold:** analog to `bitmap_area_threshold` — route units only when per-page recall < `PAGE_RECALL_FLOOR` or hard signal, not soft `table_presence` alone. (5) **Metadata-fail short-circuit:** skip units when metadata already caps verdict (docling never runs table structure when `do_table_structure=False`; we should not run units when metadata fail is decisive). Impact: if router retune expands strict-clean set from 1 → ≥50 papers, wall approaches **~1000 s** (758/2284 × 3003 s) before infra levers; without retune, **~0 s** on measured fleet. Advisory-lane argument FOR fast default: lane never gates CI (`tapetum_llm.md`); docling returns `PARTIAL_SUCCESS` on timeout (`docling/datamodel/pipeline_options.py:1171-1182`) — documented degradation is acceptable advisory-only. Argument AGAINST: study mandate is **same finding quality** (`00-baseline.md:3-4,77-78`); 31/167 zero-flag PDFs have unit-only findings (`24-cascade-designer.md:10-12`); fast default without labeled holdout reopens PR #286 blind spot.

## False-pass hypothesis

**PR #286 / poll-table truncation:** Docling-equivalent `--profile fast` runs monolith+metadata only. Monolith already passes with 0.98 confidence while screen flags 0/15 pages; unit checks supply the six table defects (`24-cascade-designer.md:28`, `c06-grounding-asymmetry.md`). Skipping units on soft-router silence (docling-style "no bitmap above threshold") merges advisory `pass` while token-preserving corruption survives — exactly the defect class the LLM lane exists to catch.

## False-fail hypothesis

**Fusion-dead unit spend on metadata-failed papers:** Docling never runs optional enrichments when flags are off (`pipeline_options.py:1780-1797`). Today tapetum runs up to five unit checks on papers whose metadata/outline call already forces `review`, burning ~120 s serial wall (`12-false-economy-hunter.md:14`, `00-baseline.md:37-38`) without changing the fused outcome. A metadata-fail short-circuit (docling `do_table_structure=False` analog) removes calls without rejecting good conversions — false **fail** risk is low; false **economy** is the current bug.

## What would change my mind

Holdout replay (48 anchors + dev-replay 9, never tune on holdout) showing `--profile fast` (monolith+metadata + hard-signal-only units) matches `--profile thorough` verdicts on every labeled token-preserving table/math/code defect, while cutting measured cold-run LLM calls by ≥500 and wall to ≤600 s, would flip to **usable** without conditions.
