# 33 - Prompt-Compressor

**Verdict:** garbage — compressing system prompts saves ≤13 s on a 3003 s cold fleet run while any prompt edit forces a full ~3003 s fingerprint cold revalidation; ROI is negative unless bundled with unrelated prompt work.
**Confidence:** high (live HEAD imports + tiktoken `cl100k_base`, 2026-07-23)

## Findings

- [CRITICAL] **System-prompt compression is a sub-0.5% wall lever on the 3003 s cold run; call count × decode dominates.** Measured runtime system+guard (prompt + `guard_instruction(tag)`, `pipeline/tools.py:55-62`): monolith **872 tok** × 381 calls = **332,232 tok** (`pdf_judge.py:180-213`, `639`); metadata **189 tok** × 377 = **71,253 tok** (`unit_judge.py:114-127`, `245`); unit check **851 tok** × 1510 = **1,285,010 tok** (`unit_judge.py:129-159`, `768`); page escalation **878 tok** × 16 = **14,048 tok** (`pdf_judge.py:215-249`, `388`). Fleet aggregate system prefill: **1,702,543 tok**. A **50%** system shrink saves **851,271 tok** → **213 s** aggregate prefill @ 4000 tok/s → **~13 s wall** @ 16 slots (**0.44%** of 3003 s). Prior persona `02-prompt-token-auditor.md` reached the same conclusion: prompt bloat **<5%** of the 4.2× regression; Event A call multiplication owns **~85%** (`06-regression-bisector.md:8`). Impact: **do not prioritize compression for the 5–10 min target**. Quality risk: none from measurement; semantic loss risk if compression cuts contract rules (see false-pass).

- [HIGH] **`CONVERSION_CONTRACT` is 2096 chars / 469 tok, not ~3.7k; the ~3.7k figure is the full role prompt.** Evidence: `unit_judge.py:70-106` measured **2096 chars, 469 tiktoken**; embedded in `JUDGE_SYSTEM_PROMPT` **3751 chars / 820 tok** (`pdf_judge.py:180-213`, contract at `192`), `PAGE_JUDGE_SYSTEM_PROMPT` **3833 / 826** (`215-227`), `UNIT_CHECK_SYSTEM_PROMPT` **3696 / 799** (`unit_judge.py:129-159`, contract at `140`). Contract share: **56.8%** of UNIT chars, **55.9%** of JUDGE, **54.7%** of PAGE. Repeated across **2284 PDF-lane calls**: **1,071,196 contract-only aggregate tok**. Impact: contract is the largest compressible block, but even halving it saves **~7 s wall** (469→235 tok × 2284 / 4000 / 16). Quality risk: HIGH if TOC-leak inverse, figure-text, or wording-markup rules are trimmed (`research/improvement-bugs/PR286-LLM-FALSE-CLEAR.md:615`).

- [HIGH] **Prefix caching (persona 15) supersedes compression: shared static prefix is ~820 tok; guard tag breaks only the last 52 tok.** Evidence: `JUDGE_SYSTEM_PROMPT` static **820 tok**; `guard_instruction` **52 tok** (`pipeline/tools.py:55-62`); per-call random tag appended at system tail (`pdf_judge.py:639`, `unit_judge.py:768`). APC on DeepSeek-V4-Pro at c=16: **0%→74.3% prefix hits**, throughput **44→196 tok/s** after vLLM PR #43447 (`05-web.md:6-12`). With APC + per-paper stable tag, **~768 tok of ~872** monolith system prefix becomes cache-eligible; compression of that block yields **near-zero marginal prefill** on hits. Impact: if persona 15 lands, **prompt compression is moot** for wall time; pursue cache/reorder first (`15-prefix-cache-enabler.md:8-10`). Quality risk: none for server-only APC; low-unmeasured for user-block reorder.

- [HIGH] **User payload dwarfs system prompts on every call; compression does not touch the 6× full-markdown prefill.** Evidence: `_check_one_unit` sends entire `candidate_md` per call (`unit_judge.py:769-776`); baseline P50 candidate **~34K chars (~8584 tok)** vs unit system **851 tok** (~**10%** of input tokens, `13-payload-scoper.md:8-12`). ## False-pass hypothesis

Compressing `CONVERSION_CONTRACT` by removing the wording-markup "cap at review, never fail on placement alone" clause (`unit_judge.py:100-101`) or shortening the TOC-leak inverse (`78-85`) could restore TOC-blind false-clears (baseline: p1122r3 pass/0.98 before the rule, `whisker/CLAUDE.md` leaked-TOC section) without moving fleet wall meaningfully.

## False-fail hypothesis

Reverting `UNIT_CHECK_SYSTEM_PROMPT` to the c59139c short `_UNIT_CONVERSION_CONTRACT` (~511 chars per `02-prompt-token-auditor.md:12`) would save ~0.4 s prefill/paper but re-expose page-1/TOC false flags that full contract suppresses; decode time unchanged, so false-fail rate could rise with zero speedup.

## What would change my mind
