# 104 - vllm-APC-Determinism

**Verdict:** usable-with-conditions — vLLM's design treats APC as output-preserving and reuses physically stored KV tensors (not re-executing prefill kernels), but there is no formal bit-identical guarantee, known intra-step stale-hit lifecycle gaps on full-attention and sliding-window groups, and our DeepSeek-V4 + FP8 + concurrency-16 fleet needs PR #43447 retention tuning before APC is even effective; enable only after a bounded A/B on judge outputs, not as a zero-revalidation flip.
**Confidence:** medium

## Findings

- [CRITICAL] vLLM documents APC as not changing model outputs: "prefix caching is almost a free lunch and won't change model outputs" (`research/repos/vllm/docs/design/prefix_caching.md:3`). This is design intent, not a tested formal guarantee. Impact: theoretical ~40-70% prefill wall savings on shared-prefix judge calls (per 05-web.md gingerlabs card) if guard-tag placement is fixed; quality risk is silent verdict drift if the intent is wrong.
- [HIGH] Cached KV blocks are the same GPU-resident tensors written by prior forward passes; on hit, `get_computed_blocks()` skips recomputation and only schedules the suffix (`research/repos/vllm/vllm/v1/core/kv_cache_manager.py:225-260`, `research/repos/vllm/docs/design/prefix_caching.md:139-155`). In principle cached vs fresh prefill of the same tokens should be numerically identical when the hit is correct. Impact: zero extra compute on hit blocks; corruption only if the hit is wrong or stale.
- [HIGH] Prefix blocks are registered in the hash table at **schedule time**, before the GPU forward writes KV data: `allocate_slots()` calls `cache_blocks()` immediately (`research/repos/vllm/vllm/v1/core/kv_cache_manager.py:550-559`). Intra-step reuse of those blocks by a concurrent request with the same prefix can read stale memory. Mamba groups defer such hits via `cached_blocks_this_step` (`research/repos/vllm/vllm/v1/core/single_type_kv_cache_manager.py:1431-1439`), but **FullAttentionManager and SlidingWindowManager have no equivalent guard** (grep shows `cached_blocks_this_step` only in `MambaManager`). PR #38715 described this corruption path; PR #41400 proposed a broader fix but was **closed unmerged** (https://github.com/vllm-project/vllm/pull/41400). Impact: at fleet concurrency 16-32, shared `CONVERSION_CONTRACT` leading blocks across simultaneous judge calls could silently corrupt KV; this is the primary reason A/B is required.
- [HIGH] DeepSeek V4 sliding-window + APC required PR #43447 (merged 2026-06-04): without selective retention, concurrent SWA block allocation evicted APC entries → **0% prefix hits** at concurrency 16 (https://github.com/vllm-project/vllm/pull/43447, `research/tapetum-llm-speedup/05-web.md:5-12`). Fix: `VLLM_PREFIX_CACHE_RETENTION_INTERVAL=32768` plus free-queue prioritization (`research/repos/vllm/vllm/v1/core/block_pool.py:727-740` prepends non-cached blocks, appends cached). GSM8K exact_match stayed ~95.6% on the PR branch vs ~95.5% on main — a quality-preservation signal, not structured-judge equivalence. Impact: APC is inert without this env var on our pod; with it, ~4.5x server output throughput in trace replay (05-web.md).
- [MED] Last-token recomputation on full cache hit: even when all prompt tokens hit cache, vLLM recomputes the last token (or a whole block due to block alignment) to obtain logits (`research/repos/vllm/vllm/v1/core/kv_cache_manager.py:249-254`). This is intentional and should not change decode outputs vs a full prefill path, but it means "100% prefix hit" still runs some prefill kernels.
- [MED] Chunked prefill and APC compose (both enabled by default in V1: `research/repos/vllm/docs/configuration/optimization.md:53`, `research/repos/vllm/docs/features/automatic_prefix_caching.md:12`). vLLM FAQ states batching composition changes can alter logits via numerical instability in batched Torch ops (`research/repos/vllm/docs/usage/faq.md:20-29`). APC changes how many tokens enter each prefill chunk, so cached vs uncached paths can diverge at MoE scale even when KV reuse is correct. Impact: quality-stability risk additive to MoE batch-composition variance already flagged in 00-baseline.md constraints.
- [MED] Hash-collision and namespace bugs are documented corruption modes: default `sha256` since v0.11 (`research/repos/vllm/docs/design/prefix_caching.md:24-31`); `xxhash` warns collisions cause "undefined behavior" (same file :30). LoRA hash still keys on `lora_name` not `lora_int_id` in clone HEAD (`research/repos/vllm/vllm/v1/core/kv_cache_utils.py:517-529`; issue https://github.com/vllm-project/vllm/issues/30931) — irrelevant to our no-LoRA judge fleet but shows the failure class. Stale-hash leak on eviction collision path fixed via unconditional `block.reset_hash()` (`research/repos/vllm/vllm/v1/core/block_pool.py:571-589`; PR https://github.com/vllm-project/vllm/pull/44237).
- [LOW] FP8 KV (`--kv-cache-dtype fp8` on our pod per 05-web.md:16-17) stores quantized cache entries; docs note sliding-window layers are more sensitive and may need `--kv-cache-dtype-skip-layers sliding_window` (`research/repos/vllm/docs/features/quantization/quantized_kvcache.md:54-60). APC amplifies exposure to any FP8 SWA drift because bad blocks are reused across requests. Impact: ≤1-2 pt accuracy loss cited for FP8 generally (05-web.md:25-27); judge structured-output drift unmeasured.

## False-pass hypothesis

Two concurrent unit-check calls share the first several block-aligned tokens of `CONVERSION_CONTRACT` (guard tag differs only at the system-prompt tail per `00-baseline.md:48-52`). Request B hits request A's prefix blocks in the same scheduler step before A's GPU write completes (`kv_cache_manager.py:559`), reads stale SWA/full-attention KV, and returns a clean structured verdict while a full recompute would flag a real conversion defect — a silent false-pass on the merged fleet verdict.

## False-fail hypothesis

Sparse SWA retention with `VLLM_PREFIX_CACHE_RETENTION_INTERVAL=32768` misses an intermediate checkpoint; the suffix prefill runs with a different concurrent batch shape than a no-APC baseline, MoE expert routing shifts under FP8 KV on sliding-window layers, and a borderline pass paper gets extra defect groups — a false-fail that disappears when APC is off or batch-invariance is enabled (`research/repos/vllm/docs/features/batch_invariance.md:7-16`, `vllm/envs.py:603`).

## What would change my mind

A paired run on our production pod: same 381-paper cold sample, same seeds and schemas, `--enable-prefix-caching` on vs off (with `VLLM_PREFIX_CACHE_RETENTION_INTERVAL=32768`, guard tag moved to a fixed suffix per 00-baseline lever #2), comparing merged verdicts and structured finding hashes — if 0/381 verdict changes and 0 finding-hash changes, APC becomes a zero-revalidation lever.

**Recommended version floor:** vLLM release containing PR #43447 merge (2026-06-04, https://github.com/vllm-project/vllm/pull/43447) on clone HEAD `c8db00b` or newer; keep default `--prefix-caching-hash-algo sha256` (`prefix_caching.md:27-28`); do not use `xxhash`; verify `block_pool.py:589` unconditional `reset_hash()` present (post-#44237).
