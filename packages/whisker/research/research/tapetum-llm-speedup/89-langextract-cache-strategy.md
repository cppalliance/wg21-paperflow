# 89 - langextract-Cache-Strategy

**Verdict:** usable-with-conditions (+ langextract confirms the ecosystem norm of full re-pay per run on the realtime/Ollama path; its only LLM response reuse is opt-in GCS per-prompt memoization on Vertex batch jobs, so our whole-paper fingerprint incremental is already ahead on fleet skip and persona 19 per-unit design remains the right next lever)
**Confidence:** high

## Findings

- [CRITICAL] **No document-level or cross-run extraction skip in core library.** Every `lx.extract()` / `Annotator.annotate_documents()` call materializes the full document list and re-runs chunk → infer → align for all inputs; `extraction_passes>1` repeats the entire pipeline per pass with no changed-chunk shortcut (`annotation.py:468-491`, `477-491`, `extraction.py:154-160`). `io.save_annotated_documents` / `load_annotated_documents_jsonl` persist outputs for the caller but nothing in the extraction path reads prior results to skip work (`io.py:85-192`). Impact: **0 s** on the 3003 s cold fleet from langextract-style conversion memoization (mechanism absent on our judge workload). Quality risk: none (nothing to mis-skip). **Negative result matters:** Google’s production extractor also re-pays full price per run; incremental fleets like ours are ahead of the ecosystem on invalidation-aware skip.

- [CRITICAL] **Realtime and Ollama/local paths have zero LLM response caching.** `OllamaLanguageModel.infer()` issues one serial HTTP POST per prompt with no lookup layer (`ollama.py:291-310`, `_ollama_query` at `540-655`). Gemini realtime falls through when batch threshold not met (`gemini.py:465-473`); no disk or in-memory response store on that path. Impact: **0 s** on cold fleet; confirms our warm **375/381 skipped in 64.8 s** via sidecar fingerprint (`00-baseline.md:19-20`, `cli.py:566-661`) is a capability langextract lacks for self-hosted judges. Quality risk: none.

- [HIGH] **Only LLM response reuse: `GCSBatchCache`, Vertex batch + explicit opt-in.** `BatchConfig.enable_caching` defaults unset; when batch is enabled it must be set explicitly (`gemini_batch.py:79-89`, `107-111`). Cache keys SHA-256 canonical JSON of `{model_id, prompt, system_instruction, gen_config, safety_settings, schema}` (`408-416`, `792-801`); hits skip batch submission for those indices (`787-813`, `897-904`). Documented as re-run / interrupted-job reuse (`docs/examples/batch_api_example.md:98-102`, `134-135`). Gates: Vertex AI client only (`754-760`), prompt count ≥ `threshold` (default 50, `84`, `gemini.py:424-425`). Impact: **~0 s** on our 381-paper MoE judge pod (different provider, realtime default, no GCS); if ported as a pattern, savings scale with **identical chunk-prompt** repetition only, not whole-paper or per-unit invalidation. Quality risk: **MEDIUM** if cache keys omit prompt/schema bumps (see false-pass).

- [HIGH] **URL fetch is always cold HTTP; no fetch cache or corpus dedup.** `fetch_urls=True` (default `False`, SSRF-safe) calls `download_text_from_url` once per invocation with `requests.get(stream=True)` and no If-None-Match, disk store, or content-hash dedup (`extraction.py:70`, `175-179`, `251-256`; `io.py:265-353`). Romeo-and-Juliet batch example downloads Gutenberg via raw `requests` outside the library (`docs/examples/batch_api_example.md:28-31`). Impact: **0 s** on tapetum-llm (we read staged sources from paperstore); langextract offers **no pattern** for URL-backed corpus resume. Quality risk: none.

- [MED] **In-run dedup is error prevention, not reuse.** Duplicate `document_id` in one batch raises (`annotation.py:317-321`); `restrict_repeats=True` errors on revisiting the same id in one iterator (`147-150`). Provider registry dedup prevents double plugin registration (`router.py:62`). Impact: **0 s** wall-clock; prevents mis-attribution, not incremental fleets. Quality risk: none.

- [MED] **CPU/tokenization caches are in-process only, not cross-run memoization.** `Document.tokenized_text` lazily tokenizes once per object (`core/data.py:250-253`); `_normalize_token` uses `@lru_cache(maxsize=10000)` for fuzzy alignment (`resolver.py:1275-1281`); lazy import `_CACHE` in `__init__.py:50-97`. Impact: shaves regex/difflib work **within** a run; **negligible** vs LLM seconds on 3003 s fleet. Quality risk: none.

- [MED] **`ContextAwarePromptBuilder` “prefix” is coreference prompt text, not vLLM APC.** Injects `"[Previous text]: ..."` + trailing chars from the prior chunk into each subsequent chunk prompt (`prompting.py:179-191`, `258-261`), increasing unique suffix per chunk rather than stabilizing a shared leading prefix for KV reuse. Impact: **0 s** from langextract prompt structure for our guard-tag-broken APC (`00-baseline.md:48-52`, `05-web.md:69-77`); do not confuse with server-side prefix caching. Quality risk: none for caching; separate recall tradeoff if copied for judging.

- [LOW] **No core vLLM provider or prefix-caching documentation.** Local path is Ollama only in README (`README.md:373-394`, `examples/ollama/README.md:1-48`); `keep_alive` keeps model weights loaded (`ollama.py:108`, `587-588`) but is not cross-request KV/prefix cache. vLLM is an external community plugin (`COMMUNITY_PROVIDERS.md:17`, `langextract-vllm`); repo-wide search finds **zero** `prefix_cach`, `enable_prefix`, `APC`, or `vllm` in core Python. Impact: **0 s** portable infra lever from langextract docs; our `05-web.md` DeepSeek APC cards (`6-12`) remain the server-side source. Quality risk: none.

- [LOW] **Comparison vs our fingerprint + persona 19.** Whole-paper gate: `_compute_fingerprint` keys `md_sha256`, `source_sha256`, monolithic `prompt_sha256`, `schema_sha256`, `lane_version`, ideal fields (`cli.py:566-619`); `_fingerprint_matches` skips entire 6-call cascade on hit (`638-661`). Langextract has no equivalent content-addressed paper skip. Persona 19 proposes per-call-class and per-unit sidecar `call_cache` with mandatory re-ground on `md_sha256` change (`19-incremental-granularity.md:8-14`): surgical tomd fix **6 → ~3 LLM calls** (~50% per changed paper). Langextract’s GCS cache is **per chunk prompt hash**, blind to “one page changed in same document,” and unavailable on Ollama/vLLM realtime. **We are strictly ahead** on fleet incremental skip; persona 19 closes the partial-reconversion gap langextract never addresses.

## False-pass hypothesis

Enabling Vertex `enable_caching=True` and re-running after a tightening of few-shot examples or schema without changing chunk text would still hit GCS entries keyed only on the rendered prompt blob (`gemini_batch.py:792-801`), returning stale extractions while the task spec changed — analogous to copying docling’s “output file exists → skip” without hashing judge prompts (`55-docling-cache-strategy.md:28`). **Mitigation:** version the cache key with prompt/schema revision ids (our `prompt_sha256` / call-class hashes at `cli.py:599`, `19-incremental-granularity.md:10`).

## False-fail hypothesis

None found for langextract cache patterns themselves (langextract does not skip extractions in-library on the paths we use). A mistaken port of GCS per-prompt cache into tapetum without deterministic re-ground on candidate change could false-fail unchanged units when another page’s markdown changes ANYWHERE-presence (`19-incremental-granularity.md:12`, `unit_judge.py:137-138` cited in persona 19) — that is a persona-19 hazard, not a langextract bug.

## What would change my mind

A langextract core release adding content-addressed skip before `infer()` (document or chunk fingerprint including examples + schema + model) on the Ollama or a merged vLLM provider path, or official vLLM provider docs recommending `--enable-prefix-caching` / APC prompt layout — absent in the cloned repo as of HEAD.
