# 21 - Dual-Pod-Sharder

**Verdict:** usable-with-conditions — identical-model dual-pod sharding is the lowest-risk fleet parallelism lever (~1.9× wall on the 3003 s cold run) but requires a small cli.py-only change (per-paper service map + shard-set fingerprint), both pods probed healthy, and acceptance that verdict drift stays within the existing advisory variance budget, not zero.
**Confidence:** high

## Findings

- [CRITICAL] **Paper→pod assignment belongs inside `_adjudicate_one`, not at batch startup.** Today one `overrides` dict is parsed once (`cli.py:972`) and passed unchanged to every `adjudicate_paper(..., service_overrides=overrides)` (`cli.py:1298-1306`) and a single batch-level `judge_agent` (`cli.py:1024-1036`, `1222-1224`). Minimal fix (~25 lines, cli.py only): add `--shard-pods NAME[,NAME...]`; after `async with sem:` in `_adjudicate_one` (`cli.py:1120`), compute `pod = live_pods[index % len(live_pods)]` where `index` is the stable enumerate index from `asyncio.gather(*(_adjudicate_one(i, pid) for i, pid in enumerate(pids)))` (`cli.py:1397-1398`) and `pids` is `sorted(...)` for full runs (`cli.py:983-986`). Build `per_paper = {**overrides, "fast": pod, "deep": pod, "default": pod}`; pass to `adjudicate_paper(..., service_overrides=per_paper)` and construct a per-paper `AgentBackend` for `judge_pdf_extraction` (same slots bound together per `packages/whisker/research/llm-batching/18-load-splitter.md:16`). Impact: **~3003 s → ~1600 s** (2284 calls × 20 s / 32 effective slots vs /16 today, `00-baseline.md:24-25`) when both pods absorb load; **quality risk: LOW-MED** (same weights, different batch neighbors).

- [CRITICAL] **Deterministic assignment: sorted-index parity on a sorted PID list.** Full-run PID order is `sorted(backend.list_all_paper_ids())` filtered by converted markdown (`cli.py:983-986`); explicit-PID runs use caller order (`cli.py:980-981`). Parity sharding `live_pods[index % len(live_pods)]` is stable across reruns as long as the PID list and `--shard-pods` set are unchanged. Tie-break: sort `shard_pods` lexicographically before indexing (`SERVICES.toml:47-74` names are stable). Impact: reproducible pod ownership per paper; **quality risk: none** for assignment itself.

- [HIGH] **Health probe both pods; fall back to single-pod, never half-dead round-robin.** Current gate probes only the effective `fast` slot once (`cli.py:910-951`, `_HEALTH_PROBE_TIMEOUT_SECONDS = 30.0` at `cli.py:205`). Extend pre-gather: for each name in `sorted(shard_pods)`, `GET {base_url}/health` with that service's credential (`cli.py:895-907`, `934-935`). If **≥1** pod returns 200: run with `live_pods` (one pod → all papers on it, log warning); if **0**: `sys.exit(1)` as today (`cli.py:943-950`). Prior probe found `h200x8-deepseek-v4-pro` 404 while `alliance-pod` 200 (`packages/whisker/research/llm-batching/18-load-splitter.md:8`); fallback prevents the false-fail of assigning ~50% of papers to a dead proxy. Impact: avoids inflated `error` tombstones (`cli.py:1382-1387`); **0× savings** when only one pod is live, **~1.9×** when both live.

- [HIGH] **Fingerprints must encode the shard SET, not the per-paper pod, or incremental skip breaks.** `_compute_fingerprint` stores `model` as the full `_effective_model_contract` JSON string (`cli.py:566-619`, `1177-1178`), computed once from batch-level `effective_services` (`cli.py:1056-1061`). Naively baking per-paper `pod` into `model` would still skip on warm rerun (same index → same pod) but would **invalidate all sidecars** when toggling single-pod ↔ dual-pod. Correct fix: when `--shard-pods` is active, pass the **union** of all configured shard services into `_effective_model_contract` (`cli.py:543-554` already iterates `sorted(set(slots.values()))`; extend to `sorted(set(slots.values()) | set(shard_pods))`). Per-paper assignment stays out of the fingerprint. Impact: warm rerun after cold dual-pod run keeps **375/381 skip** behavior (`00-baseline.md:19-20`); enabling sharding forces one cold pass (expected `_LANE_VERSION`-class invalidation). **Quality risk: none** for skip semantics.

- [HIGH] **Verdict drift from different instances is within the documented advisory variance budget, not within strict quality-stability.** Same `deepseek-v4-pro` on two RunPod proxies (`SERVICES.toml:47-74`) still means independent vLLM schedulers and prefix-cache state (`18-load-splitter.md:24`, `05-web.md:69-77`). Documented lane policy: token output is not bit-stable under MoE batch composition (`tapetum_llm.md:31`); measured **≥25% pass↔review flip** on borderline papers across identical reruns on one pod (`packages/whisker/research/llm-batching/20-sweep-results.md:31-40`, `research/llm-qa-integration/23-ci-reproducibility.md:10`). Sharding adds a **second variance axis** (which pod drew the paper) but per-paper pod is **fixed across reruns**, so incremental reruns do not shuffle instances. Versus a hypothetical all-`alliance-pod` baseline, some papers may get different advisory verdicts on first adoption; that is indistinguishable from existing rerun drift and **does not violate** the advisory-only contract (`fusion.py:76-77`, `tapetum_llm.md:3`). Impact: **no gate/fusion hard-fail risk**; **MED** triage noise for operators comparing cross-pod A/B. Exceeds **production** quality-stability (`00-baseline.md:77-78`) if interpreted as bit-identical verdicts — same as today.

- [MED] **Keep `--concurrency` at 32 (or raise modestly); do not expect linear 2× without filling both pods.** Client default `_DEFAULT_CONCURRENCY = 32` already overfills one pod's `--max-num-seqs 16` (`cli.py:119-127`, `00-baseline.md:33-35`). With even split, ~190 papers per pod ≈ 16 in-flight each — concurrency 32 is sufficient; raising toward 64 is unmeasured (`cli.py:1100-1107`, `research/concurrency-381`). Impact: **~1428-1600 s** modeled wall vs 3003 s; remaining gap to 5-10 min requires stacked levers (`10-call-graph-accountant.md:51`).

- [LOW] **N-pod generalization with the other four pods is forbidden under the same-model constraint; relaxing it is a different lever.** Live non-twin pods run **different** weights (`SERVICES.toml:76-138`: R1-70B, Gemma-31B, Qwen3.6-27B, Qwen3-235B, Qwen3-32B). `resolve_pipeline_models` binds slot → service → `model` string (`adjudicate.py:753-768`); different `model` in `_effective_model_contract` changes fingerprints (`cli.py:545-551`) and **changes verdicts** (cascade/small-judge levers in `00-baseline.md:100-101`, `05-web.md:88-90`). Homogeneous N-pod sharding generalizes as `live_pods[index % N]` with N identical replicas only. Heterogeneous pods belong in a **cascade** (cheap first, DeepSeek on flags), not fleet sharding — forbidden for determinism unless verdict drift is explicitly accepted.

## False-pass hypothesis

Paper **p1122r3-class TOC leak** (`whisker/CLAUDE.md` advisory section): assigned to `h200x8-deepseek-v4-pro` with a sparser batch composition, the monolith returns `pass`/high confidence while the same paper on `alliance-pod` would cap at `review` under different MoE routing (`18-load-splitter.md:24`). Fusion stays green; speedup looks successful while advisory distribution shifts by **shard luck**, not conversion quality.

## False-fail hypothesis

`h200x8-deepseek-v4-pro` partially routes (proxy up, vLLM not ready): without pre-gather health filtering, ~190 papers hit connection errors, `_write_error_tombstone` (`cli.py:1382-1387`) inflates `error` count — operators read a broken fleet, not bad conversions (`18-load-splitter.md:27-28`).

## What would change my mind

Live dual probe (`GET .../health` or `/v1/models` 200 on both `alliance-pod` and `h200x8-deepseek-v4-pro`) followed by a 381-paper cold run with `--shard-pods alliance-pod,h200x8-deepseek-v4-pro --concurrency 32` showing wall **≤1700 s** and **≤1.3×** the measured single-pod borderline verdict-flip rate (`20-sweep-results.md:31-40`) would flip verdict to **usable** with quantified savings; sustained single-pod fallback only keeps **usable-with-conditions**.
