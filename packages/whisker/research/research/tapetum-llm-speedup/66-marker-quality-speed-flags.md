# 66 - marker-Quality-Speed-Flags

**Verdict:** usable-with-conditions — marker's quality/speed flag inventory is authoritative and directly portable as a *tiering vocabulary*, but adopting its default inversion (fast baseline, LLM opt-in) on our advisory lane still leaves a monolith+metadata-only nightly at ~16 min on one pod; 5–10 min needs dual-pod sharding or per-call latency levers, not flag semantics alone.
**Confidence:** high

## Findings

- [CRITICAL] **`use_llm` defaults OFF; LLM is opt-in quality mode.** `PdfConverter.use_llm` defaults `False` (`marker/converters/pdf.py:71-74`); `ConfigParser.get_llm_service()` returns `None` unless CLI passes `--use_llm` (`marker/config/parser.py:135-136`); `BaseLLMProcessor.__init__` exits without injecting a service when `use_llm` is false (`marker/processors/llm/__init__.py:64-67`); complex processors no-op at entry (`__init__.py:138-139`). README documents hybrid mode as explicit `--use_llm` for table merges, inline math, forms (`README.md` Hybrid Mode section). Impact: marker inverts our economics — default path is deterministic+VLM-OCR only; ~12 LLM block processors never fire. Porting this to tapetum means nightly `--thorough` (full 6-call cascade) becomes weekly/on-demand, cutting call volume 67% (1510 unit + 16 page calls removed from census `00-baseline.md:22-23`). Quality risk: the 16/381 papers whose merged verdict changed only after unit checks (`00-baseline.md:29-30`) would not surface on nightly runs; acceptable only because our lane is advisory and never gates.

- [CRITICAL] **`--mode balanced|fast` is the primary VLM quality/speed switch; default is device-dependent.** Annotated on `PdfConverter.mode` with docstring "Defaults by device: 'balanced' on GPU, 'fast' on CPU/MPS" (`pdf.py:75-81`); resolved at init when unset: `"balanced" if settings.TORCH_DEVICE_MODEL == "cuda" else "fast"` (`pdf.py:126-134`). `LayoutBuilder.use_fast_layout()` returns true for `mode=="fast"` OR `disable_ocr`, selecting rf-detr `fast_layout_model` over VLM `layout_model` (`marker/builders/layout.py:88-93`). README bench: balanced **76.0%** olmocr-bench / **2.9 pg/s**; fast **66.6%** / **7.4 pg/s**; fast+`--disable_ocr` **43.6%** / **23.7 pg/s** (`README.md` Competitive comparison table). Impact: no direct tapetum analogue (we have no VLM conversion tier), but the *pattern* — cheap default, expensive mode explicit — is the structural lesson. Quality risk: fast mode arXiv-math **23.4%** vs balanced **83.9%** per category table (`README.md` Marker modes table); irrelevant to our judge lane but warns against "fast judge" without evidence.

- [HIGH] **`force_ocr` default False; when set, skips pdftext and forces full-document VLM OCR.** Default `force_ocr=False` on `PdfProvider` (`marker/providers/pdf.py:47-50`); when true, provider skips pdftext extraction and assigns page bboxes manually (`pdf.py:110-112`). In balanced mode, layout pass is skipped because full-page OCR rebuilds structure (`marker/builders/layout.py:99-105`). README: "Set `--force_ocr` to force OCR on all pages" (`README.md` Configuration). Impact: not portable to tapetum (we judge, not OCR), but shows marker treats forced full re-processing as an explicit quality tax. Quality risk: none for our lane; analog would be forcing full 6-call cascade on every paper (what we do today).

- [HIGH] **`disable_ocr` default False; when set, pure text-layer path with zero VLM calls.** Gates at `DocumentBuilder` (`marker/builders/document.py:27-30,63-64`), `LineBuilder` treats all pages as good pdftext (`line.py:200-203,235-236`), `LayoutBuilder` forces rf-detr layout (`layout.py:88-90`), `EquationProcessor` returns immediately (`equation.py:84-86`). README: "`--disable_ocr` turns off **all** VLM calls (including equations)" (`README.md` Configuration). Impact: marker's fastest tier (23.7 pg/s CPU) — our analog is skipping the entire LLM judge lane (deterministic whisker score only). Quality risk: equations and scans silently degrade; our lane would lose all LLM defect detection.

- [HIGH] **`redo_inline_math` default False; requires `--use_llm` to activate LLM inline-math rewrite.** Defaults on `LLMEquationProcessor` (`marker/processors/llm/llm_equation.py:20-25`) and `LLMMathBlockProcessor` (`llm_mathblock.py:17-23`); equation processor skips small blocks unless `redo_inline_math=True` (`llm_equation.py:79-87`); mathblock processor returns immediately when false (`llm_mathblock.py:79-80`). Balanced mode already VLM-OCRs inline math via `EquationProcessor.ocr_inline_math` auto-on (`equation.py:48-53,79-81`). README: "`--redo_inline_math`: absolute highest quality inline math … along with `--use_llm`" (`README.md` Options). Impact: marker stacks quality — VLM inline math (balanced default) PLUS optional LLM re-polish. Our analog: monolith+metadata nightly catches doc-level issues; unit checks (--thorough) catch page-local math/table defects the monolith missed. Quality risk: dropping unit checks loses the 70% zero-defect calls that still occasionally matter for the 16/381 verdict-changed papers.

- [MED] **`--disable_image_extraction` default False (`extract_images=True`); inverted gate on LLM image descriptions.** CLI flag maps to `config["extract_images"]=False` (`marker/config/parser.py:58-62,122-124`). `LLMImageDescriptionProcessor.inference_blocks` returns **empty** when `extract_images=True` (default), only fires LLM when images are NOT extracted (`llm_image_description.py:17,44-46`). README: "If you also specify `--use_llm`, then images will be replaced with a description" (`README.md` Options). Impact: marker couples image extraction OFF with LLM description ON — a quality fallback, not a speed win. Our lane sends full markdown including image refs; no direct port.

- [MED] **Fast/quality model variants split across VLM tier (`mode`) and LLM service tier (`--llm_service`).** VLM: `create_model_dict` documents balanced uses VLM `layout_model`+`recognition_model`; fast uses rf-detr `fast_layout_model` + minimal block OCR (`marker/models.py:18-22,44-54`). LLM defaults: Gemini `gemini-3.5-flash` (`marker/services/gemini.py:21-23`), OpenAI-compatible `gpt-5-mini` (`openai.py:22-24`), Ollama `gemma3` (`ollama.py:19`), OpenRouter `google/gemini-3.5-flash` (`openrouter.py:30-31`). Table reconstruction confidence bar: 0.75 balanced vs 0.5 fast before VLM fallback (`table.py:121-124`). LLM concurrency capped at 3 per processor (`__init__.py:42-45`). Impact: marker uses cheap flash models for LLM polish, not reasoning models — aligns with 05-web SLMJury/LLMTrace cascade evidence that short structured verdicts suffice for triage. Quality risk: swapping our DeepSeek-V4 judge to flash for nightly tier without calibration could drift the 16/381 verdict-changed rate.

- [HIGH] **Nightly monolith+metadata-only wall: ~948 s (~15.8 min) on one pod; ~474 s (~7.9 min) dual-pod.** Call census: 381 monolith + 377 metadata = **758 calls** (`00-baseline.md:22-23`). Baseline closed-form: wall ≈ calls × latency / slots = 758 × 20 / 16 ≈ **947.5 s** (`00-baseline.md:24-25`). Measured-ratio check: 3003.4 s × (758/2284) ≈ **997 s**. Neither hits 5–10 min on single `alliance-pod` (`00-baseline.md:65-66`, `--max-num-seqs 16`); second pod (`h200x8-deepseek-v4-pro`, `00-baseline.md:67-68`) halves wall to ~8 min. Quality risk: monolith+metadata still sends full candidate markdown per call (`00-baseline.md:43-47`); prefix-cache guard-tag breakage (`00-baseline.md:48-52`) applies unchanged — latency lever, not call-count lever.

## False-pass hypothesis

Nightly default = monolith+metadata only (--thorough weekly): a table cell transposition or single-page wording swap that deterministic whisker score misses, and that the monolith judge flags weakly but a scoped unit check would catch with page-local source text, ships undetected in the advisory report until the weekly full cascade. Evidence: 70% of unit checks return zero defect groups yet 16/381 papers had verdict changed by LLM findings (`00-baseline.md:29-30`) — the long tail is real even when most checks are empty.

## False-fail hypothesis

Weekly `--thorough` full cascade on papers already flagged review/fail by nightly monolith+metadata over-weights serial 6-call re-runs on unchanged markdown: fingerprint skip helps warm runs (`00-baseline.md:19-20`) but any markdown edit re-runs all 1510 unit-check slots (`00-baseline.md:57-59`), producing redundant review noise without new defects — advisory false alarm, not a gate false-fail.

## What would change my mind

A measured tapetum ablation on the 381-paper fleet: run monolith+metadata only vs full cascade, report (a) wall time, (b) count of papers whose merged verdict differs, (c) count of unit-check-only defects that monolith+metadata missed with severity ≥ review. If (c) ≤ 2% of papers and all are low-severity wording, nightly inversion is free; if (c) ≥ 10%, keep full cascade default.
