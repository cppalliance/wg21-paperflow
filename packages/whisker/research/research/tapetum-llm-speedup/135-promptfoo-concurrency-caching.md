# 135 - promptfoo-Concurrency-Caching

**Verdict:** usable-with-conditions (+ port promptfoo-style call-level response memo for dev reruns and `_LANE_VERSION` bumps that leave other call classes untouched; do not copy `maxConcurrency=4`; guard-tag normalization is mandatory)
**Confidence:** high

## Findings

- [CRITICAL] **`maxConcurrency` default is 4 for cloud rate-limit safety, not throughput tuning.** Evidence: `constants.ts:8` (`DEFAULT_MAX_CONCURRENCY = 4`); evaluator applies it at `evaluator.ts:4566`, `3135`; CLI documents default at `commands/eval.ts:89-90`; HTTP connection pool size follows the same default (`util/fetch/index.ts:42-54`: env `PROMPTFOO_FETCH_CONNECTIONS` > CLI `-j` > 4). Adaptive AIMD scheduler (`adaptiveConcurrency.ts:17-27`, `rate-limits.md:45-53`) halves concurrency on 429 and recovers after 5 successes. **Why so low:** promptfoo targets shared OpenAI/Anthropic/Azure APIs where free/low tiers tolerate only a few concurrent RPM; 4 is a conservative starting ceiling the scheduler can raise within a run, not a decode-bound self-hosted optimum. Impact: **0 s portable saving** for tapetum (we already run `_DEFAULT_CONCURRENCY = 32` at `cli.py:127`, 16 server slots, uptime billing per `00-baseline.md:64-67`). Quality risk: none if we ignore this default.

- [CRITICAL] **Eval queue is two-tier: cross-test concurrency + per-provider slot FIFO with rate-limit gating.** Evidence: concurrent test steps run via `async.forEachOfLimit(concurrentRunEvalOptions, concurrency, ...)` at `evaluator.ts:3853-3867`; serial steps (conversation var, `storeOutputAs`, browser session) force `concurrency = 1` at `evaluator.ts:2763-2785`; `ProviderGroupedCallQueue` batches deferred grading calls by `providerId` (`providerCallQueue.ts:35-57`, used at `evaluator.ts:3693-3731`); each provider gets a `SlotQueue` FIFO with quota-aware `acquire`/`release` (`slotQueue.ts:54-104`, `248-259`); `RateLimitRegistry` isolates pools by provider id + api key tail/region (`rateLimitKey.ts:9-41`, `rateLimitRegistry.ts:105-126`). Queue timeout default 5 min (`slotQueue.ts:18`, `rateLimitRegistry.ts:34-35`). Impact: pattern validates our **cross-paper parallel + in-paper serial** design (`00-baseline.md:36-42`); adopting promptfoo's adaptive 429 backoff could shave **~69 s** on retry storms (`00-baseline.md:60-61`) but is orthogonal to the 3003 s cold path. Quality risk: **LOW** for retry policy; **MEDIUM** if adaptive downshift were applied to our MoE pod without remeasurement (cf. `00-baseline.md:82-83` slots-32 regression).

- [CRITICAL] **Response cache is disk-backed exact-match memoization at the HTTP request layer, enabled by default.** Evidence: `PROMPTFOO_CACHE_ENABLED` default true (`cache.ts:34`); disk store `~/.promptfoo/cache/cache.json` via KeyvFile (`cache.ts:76-95`, `85`); TTL 14 days (`cache.ts:39-47`); CLI `--no-cache` at `commands/eval.ts:95-97`. Cache key for LLM calls: `fetch:v3:` + SHA-256 of `{format, headers, method, options.body, url}` (`cache.ts:522-550`, `440-442`); secrets HMAC'd not embedded (`cache.ts:301-322`, `416-437`). Successful responses cached after read (`cache.ts:717-758`); HTTP errors and `data.error` not cached (`cache.ts:727-750`); inflight coalescing prevents duplicate concurrent fetches (`cache.ts:298`, `870-889`). OpenAI chat path: `fetchWithCache(..., shouldBustCache(context))` at `providers/openai/chat.ts:523-537`; bust on `context.bustCache || context.debug` (`providers/openai/index.ts:166-167`). Impact: on **re-run with identical request bodies**, provider calls become disk reads (~ms) instead of ~20 s LLM (`00-baseline.md:24-25`). On **empty cache cold fleet**: **0 s** (still 2284 calls). Quality risk: **LOW** on hits (verbatim replay); **MEDIUM** if post-processor logic changes without cache key update.

- [HIGH] **Cache invalidation is implicit: any request-material change = miss; no fleet `lane_version` concept.** Evidence: key includes full JSON body (model, messages, temperature, tools, etc.) via `getBodyForFetchCacheKey` (`cache.ts:459-489`, `492-519`); provider config edits change URL/headers/body → new hash; TTL expiry only other auto-inval (`site/docs/configuration/caching.md:53-56`); manual `clearCache()` (`cache.ts:940-950`). Repeat runs use `withCacheNamespace('repeat:N')` so repeat indices do not collide (`evaluator.ts:425-432`, `1404-1407`, `3316-3318`; tested at `test/evaluator/repeatCache.test.ts:126-135`). Config YAML change that alters prompt text or provider model → automatic miss without cache admin. Impact: equivalent to persona 19's **per-class prompt hash** (`19-incremental-granularity.md:10`): a unit-only prompt edit misses only unit requests in promptfoo; our monolithic `_pdf_prompt_contract()` hash invalidates all 381 papers (`cli.py:476-483`). A **`_LANE_VERSION` bump with unchanged prompts** misses in promptfoo (body unchanged → **HIT**) but misses in tapetum (whole-paper fingerprint includes `lane_version`, `cli.py:601`). Quantified v10-class bump (routing-only, unchanged md/prompts): **758 LLM calls** (381 monolith + 377 metadata) could hit cache → **758×20/16 ≈ 948 s saved → ~2055 s wall (~34 min)**, not 5–10 min (`00-baseline.md:17-18`, `22-23`). Quality risk: **MEDIUM** if v10 routing changes which units run but cached monolith/metadata outputs are replayed — mitigated by bumping only `call_class_version` for affected classes in the cache key.

- [HIGH] **Compared to tapetum paper-level fingerprint: promptfoo caches at call granularity; simpler than persona 19 sidecar surgery but insufficient alone for partial markdown edits.** Evidence: our skip compares full sidecar `fingerprint` dict (`cli.py:638-661`); warm run **375/381 skipped in 64.8 s** (`00-baseline.md:19-20`); changed markdown reruns all ~6 serial calls per paper (`00-baseline.md:57-59`). Promptfoo would cache each HTTP call independently — same as persona 19's proposed `call_cache` LLM output store (`19-incremental-granularity.md:14`) but **without** mandatory re-ground rules. For **single-page tomd fix**: call-level cache hits unchanged unit calls only if keys include `unit_source_sha256` + scoped payload, not whole-paper `md_sha256`; naive full-body hash still misses when any page changes. Impact: surgical re-conversion **6 → ~3 calls (~60 s vs ~120 s per paper)** requires persona 19 re-ground contract (`19-incremental-granularity.md:12-14`), not promptfoo-style cache alone. Quality risk: **HIGH** without re-ground on `md_sha256` change (ANYWHERE-presence, `unit_judge.py:137-138`).

- [MED] **Guard-tag randomization blocks promptfoo-style exact cache unless normalized out of the hash input.** Evidence: we append `SRC{secrets.token_hex(4)}` per call (`pdf_judge.py:638-639`, `unit_judge.py:767-768`); baseline notes this breaks prefix identity (`00-baseline.md:48-52`). Promptfoo keys hash the literal HTTP body (`cache.ts:532-549`); random tags → **0% hit rate** on any re-run. Impact: implementing call cache without stripping guard tags from `sha256(messages)` saves **0 s**; with normalization (live prompt keeps tag, hash uses fixed sentinel), cross-run memo works like promptfoo. Quality risk: **LOW** if tag remains in live prompt (injection defense preserved).

- [MED] **Design sketch: `CallResponseCache` beside tapetum sidecars (promptfoo + persona 19 hybrid).** Store under `whisker/llm/cache/` (disk JSON or sqlite, mirroring `cache.ts:76-95`). Key: `sha256(model, service, call_class, prompt_sha256, schema_sha256, user_payload_sha256, call_class_version)` — **exclude global `_LANE_VERSION`**, use per-class versions (`monolith_v`, `unit_v`, …). Lookup in `judge_task.py` before HTTP; on hit return cached Pydantic JSON, still run deterministic post-processors (`pdf_judge.py:697-706`, `unit_judge.py:604-648`) when post-processor version bumps. `--no-llm-cache` mirrors `--no-cache` (`commands/eval.ts:95-97`). Inflight dedup map per key (cf. `cache.ts:298`). Impact summary on 3003 s cold run:

  | Scenario | Calls skipped | Est. wall | vs 3003 s |
  |---|---:|---:|---:|
  | True cold (empty cache) | 0 | 3003 s | 0% |
  | Warm fingerprint (today) | ~2250 | 65 s | −98% |
  | `_LANE_VERSION` bump, prompts unchanged (v10-class) | 758 | ~2055 s | −32% |
  | Unit-prompt-only edit | 774 (mono+meta+page) | ~2035 s | −32% |
  | Monolith-prompt-only edit | 1903 (meta+unit+page) | ~476 s | −84% |
  | Single-page md change + per-unit keys + re-ground | ~3/paper changed | ~60 s/paper | partial fleet |

  Reaching **5–10 min** still requires call elimination, dual-pod, or prefix caching (`00-baseline.md:89-103`), not cache alone.

- [LOW] **promptfoo concurrency default is irrelevant; our bottleneck is in-paper serial chains and call count, not client paper concurrency.** Evidence: 6 calls × ~20 s serial ≈ 120 s/paper regardless of 32-wide fleet (`00-baseline.md:38-39`); promptfoo tests are independent prompt×provider rows with no within-document cascade. Impact: copying `maxConcurrency=4` would **increase** our wall time; keep 32. Quality risk: none.

## False-pass hypothesis

**v10 routing bump with cached monolith/metadata:** replay cached monolith `pass` while new unit pre-filter logic would have capped at `review` for papers that previously burned quota on unrouted units. Cached LLM outputs are unchanged, but **merge/fusion** might differ if aggregation code changes without `call_class_version` bump on the aggregator. Mitigation: bump `unit_v` (and re-run units) on routing changes; replay monolith/metadata only when their inputs and class versions match.

## False-fail hypothesis

**Stale cached unit `review` after prompt tightening:** new stricter `UNIT_CHECK_SYSTEM_PROMPT` changes hash → cache miss → fresh LLM call; no spurious fail. False-fail arises only if cache key omits `prompt_sha256` and replays an old lenient verdict under a stricter operator expectation — not a model error, a cache-key bug. Mitigation: always include prompt+schema in key (mirrors `_compute_fingerprint`, `cli.py:599-603`).

## What would change my mind

A measured dev rerun after `_LANE_VERSION` v10 bump with call-level cache (guard-normalized keys, class-scoped versions) that shows **<500 s** fleet wall while **>10 papers** change advisory verdict vs uncached v10 run would prove cache replay is unsafe for routing-only bumps and force full paper re-LLM despite identical prompts.
