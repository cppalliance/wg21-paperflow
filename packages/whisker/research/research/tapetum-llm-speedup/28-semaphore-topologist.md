# 28 - Semaphore-Topologist

**Verdict:** usable-with-conditions (+ the paper-level semaphore already overfills 16 server slots and the measured fleet bubble is only ~4%; a call-level semaphore above 16 cannot fill the GPU and risks proxy 524s; the real plumbing gap is sync CPU on the asyncio event loop during `screen_pages` / grounding on tail-size documents, not request under-subscription)
**Confidence:** high

## Findings

- [CRITICAL] **Concurrency unit is the paper, held for the entire adjudication including all CPU gaps.** Evidence: `asyncio.Semaphore(concurrency)` at `cli.py:1112`; `async with sem:` wraps the full `_adjudicate_one` body including `judge_pdf_extraction` and ideal attach (`cli.py:1120-1238`). Within a paper, LLM calls are strictly serial: monolith (`pdf_judge.py:646-657`), metadata (`pdf_judge.py:675-684`), page loop (`pdf_judge.py:753-763`), unit loop (`unit_judge.py:389-416`). Impact: at most **32 papers** can be "in flight," but each emits **at most one HTTP request at a time**; peak client request demand is **≤32**, server serves **16** (`00-baseline.md:24-25`, `SERVICES.toml` `--max-num-seqs 16`). The 3003 s wall is dominated by **2284 calls × ~20 s / 16 slots ≈ 2855 s** (`00-baseline.md:22-25`), not by a 2× slot mismatch.

- [CRITICAL] **Measured utilization gap from paper-holding-during-idle is ~4%, already closed by c=32 overfill.** Evidence: full-corpus A/B server=16: client c=16 → **722.4 s**, c=32 → **692.3 s (-4.2%)** (`cli.py:123-125`, `research/slots-32-regression/SYNTHESIS.md:10-11,50-53`). That delta is the empirical ceiling for "more papers in flight fixes server idleness" without adding slots or cutting calls. Impact: decoupling paper vs call semaphores might recover **≤~30 s (~1%)** on the 3003 s cold run beyond what c=32 already captures; **not a path to 5–10 min**. Quality risk: none from semaphore shape alone.

- [CRITICAL] **A call-level semaphore at 48 in-flight requests would not keep the server fuller and increases tail risk.** Evidence: vLLM schedules at most **16 simultaneous decodes** regardless of HTTP admission (`research/concurrency-381/10-vllm-scheduler.md:8-12`; `00-baseline.md:83-85`: server 16→32 slots **+57% wall**). Extra client requests beyond 16 sit in vLLM FCFS queue without adding GPU parallelism. RunPod HTTP proxy kills connections whose **time-to-first-byte exceeds ~100 s** while queued (`research/concurrency-381/12-runpod-proxy.md:9-13`); c=381 measured **257/381 proxy errors** (`00-baseline.md:81`, `research/concurrency-381/`). Impact: sem(48) adds **32 deep-queued idle HTTP connections** with **0 additional decode slots**; projected saving **0 s**, tail **524/APIConnectionError** risk **HIGH**. Quality risk: LOW directly; operational errors masquerade as coverage gaps.

- [HIGH] **Inter-call CPU idle fraction is negligible on median papers, material only on tail-size documents.** Evidence: runtime benchmark on golden snapshots (2026-07-23, local): median paper **~0.10–0.29 s** total CPU per cascade vs **~120 s** LLM (6×20 s) → **~0.1% idle fraction**; tail `p2728r11.md` (2479 KB) **~13.7 s CPU / ~120 s LLM → ~10%** per-paper idle. CPU phases map to code: pre-monolith `screen_pages` + metrics (`pdf_judge.py:628-636`, `296-321`); post-monolith `ground_spans` + `classify_candidate_evidence` (`pdf_judge.py:696-697`, `grounding.py:248-335`, `419-434`); post-unit batch `verify_unit_evidence` (`unit_judge.py:425`, `681-753`). Impact: fleet-weighted idle **≪4%** (median corpus is tens of KB, not MB); even perfect call-level scheduling saves **≪120 s** on 3003 s. Quality risk: none.

- [HIGH] **Sync CPU between awaits blocks the asyncio event loop and can transiently starve all 32 paper workers.** Evidence: **zero** `asyncio.to_thread` / `run_in_executor` in `packages/whisker` tapetum_llm (`grep` 2026-07-23); `screen_pages` calls `content_recall(tomd_md, page)` per page, tokenizing the **full candidate markdown** each time (`pdf_judge.py:316`, `metrics.py:376-393`). Measured: `p2728r11.md` **17.36 s** for `screen_pages` alone (40 pages × 2.5 MB md). During that stretch no other paper can dispatch the next `await run_judge_task` (`judge_task.py:68`). Impact: tail papers inject **multi-second to ~20 s global stalls**; with mixed fleet this explains **micro-bubbles below the 4% c=16→c32 gain**, not the 50 min budget. Fix lever: `asyncio.to_thread(screen_pages, ...)` / executor around `ground_spans` — est. **≤1–2% wall (~30–60 s)** unless many MB-class papers cluster. Quality risk: none.

- [MED] **`judge_task.py` documents a stale invariant: "Each paper issues at most one judge call."** Evidence: `judge_task.py:63-66` vs median **7 PDF calls** / **6 HTML calls** (`10-call-graph-accountant.md:11-14`). Dispatch correctly bypasses pipeline `Semaphore(1)` (`judge_task.py:10-15`), but the comment misstates the bound: paper-level sem limits **papers**, not **requests**; request duty cycle is **~120 s LLM / ~120 s wall per paper** serial. Impact: operators mis-tune toward "one call per paper slot" when the real serial depth is **6–7**; scheduling fixes must target **call release during CPU**, not raising paper count above 32. Quality risk: none (documentation only).

- [MED] **Memory cost of loading more papers concurrently scales with `(md + pdf_text + page_units)` per held paper, safe at 32, unsafe unbounded.** Evidence: per paper `judge_pdf_extraction` loads `backend.get_paper_md(pid)` (`pdf_judge.py:612`), full text layer via `extract_textlayer` (`pdf_judge.py:596-609`), `extract_page_units` (`pdf_judge.py:662-663`), plus `route_pdf_units` counters over full md (`source_router.py:167-183`). All live for the `async with sem` lifetime (`cli.py:1120`). Cap `MAX_PAPER_MD_CHARS = 500_000` (`constants.py:61`). Rough bound: **32 × (2× md + pdf_text) ≈ 32 × 1 MB ≈ 32 MB** at median ~50 KB md; **32 × ~5 MB ≈ 160 MB** if all slots held 2.5 MB tails simultaneously. Unbounded papers with sem(48) on requests only: **100 papers × 500 KB ≈ 50 MB** strings minimum before PyMuPDF overhead — manageable on workstation, but **381 simultaneous loads ≈ 380 MB–1 GB+** with no backpressure. Impact: **call-level sem with unbounded paper prefetch is an OOM/latency hazard**; keep paper cap ≤32 or stream-load per call. Quality risk: none; OOM → error tombstones (`cli.py:1382-1387`).

- [LOW] **Correct topology for fuller server without more slots: release the request slot during CPU, not raise HTTP fan-out above 16.** Evidence: optimal proven pairing **server 16 + client papers 32** (`research/slots-32-regression/SYNTHESIS.md:53-54`); wall model insensitive to in-paper parallel reshuffling when slot-saturated (`20-in-paper-parallelist.md:12-13`). Pattern: `async with call_sem:` only around `await run_judge_task(...)` (`judge_task.py:52-74`), CPU outside; `call_sem=16` matches server, `paper_sem=32+` keeps pipeline full. Impact: same **~4%** class as c=32 overfill unless event-loop blocking is also offloaded. Quality risk: LOW.

## False-pass hypothesis

Raising call-level concurrency to 48 while papers stay unbounded: tail papers sit **>100 s** in vLLM queue (`research/concurrency-381/12-runpod-proxy.md:29-31`), proxy returns **524**, exception firewall writes error tombstone with partial progress (`cli.py:1382-1387`), incremental fingerprint skips the paper on retry (`cli.py:1175-1202`) — operator sees a "clean" skipped corpus while **6–7 calls never ran**, silently weakening advisory coverage on the failed PIDs.

## False-fail hypothesis

Offloading `screen_pages` to a thread pool without preserving deterministic token order in `content_recall` could theoretically reorder multiset ties; in practice `content_recall` uses sorted Counter iteration over hashable tokens (`metrics.py:388-393`) and is order-independent — **no false-fail from threading alone**. A real false-fail would require changing grounding thresholds (`constants.py:67-73`), not semaphore topology.

## What would change my mind

Sidecar timestamps showing **>10% of fleet wall time** with `<16` active decodes on the pod (via `vllm:num_requests_running` / queue metrics per `05-web.md:65-66`) **after** c=32 and **after** `screen_pages`/grounding are moved off the event loop — would upgrade the idle-gap estimate from "~4% ceiling" to "material lever worth call/paper semaphore split."
