# 45 - Guard-Tag-Cryptanalyst

**Verdict:** usable-with-conditions — per-paper secret-derived guard tag is security-equivalent to today's per-call random tag for the paper-author threat model; persona 15's prefix-cache lever is safe only with HMAC(key, pid), not bare hash(pid) or fully static tags without contract amendment.
**Confidence:** high

## Findings

- [CRITICAL] **Delimiter forgery is blocked by escaping, not by tag randomness.** `escape_guard_delimiters` replaces exact forged opener/closer strings before wrapping: `<<<tag>>>` → `<<\<tag>>>`, `<<<END_tag>>>` → `<<\<END_tag>>>` (`pipeline/tools.py:38-46`); `inject_untrusted` applies escape then wraps (`pipeline/tools.py:49-52`). Test asserts inner content contains no literal `<<<TEST>>>` after wrap (`packages/pipeline/tests/test_tools.py:19-26`). The attack randomness *also* targets is envelope escape: paper text embedding delimiter literals to spoof an "outside instructions" region. Random tag adds author-time unpredictability (paper fixed before `secrets.token_hex(4)` is drawn at `unit_judge.py:767`, `pdf_judge.py:638`) so adversaries cannot pre-embed the *exact* runtime delimiter; escaping handles the case where they can (static/predictable tag). Impact: randomness is belt-and-suspenders; **dropping per-call random does not remove the primary control** if escape stays in place. Quality risk: none.

- [CRITICAL] **Per-paper HMAC(secret, pid) is security-equivalent to per-call random for paper authors; hash(pid) alone is not.** Paper authors know `pid` but not fleet/session key. `SRC{hmac[:8]}` stable across ~6 calls enables identical `guard_instruction(tag)` suffix (`pipeline/tools.py:55-61`) and identical `<<<{tag}>>>` openers on shared blocks — required for APC across the paper cascade (`15-prefix-cache-enabler.md:8-10`, `00-baseline.md:48-52`). Bare `sha256(pid)[:8]` is predictable at authoring time: attacker can embed `<<<SRC{hash}>>>` strings; still escaped, but a future escape gap (unicode homoglyph, partial replace, double-unescape) hits **all 6 calls** instead of one. Secret-keyed tag matches pipeline's own contract: one `_guard_tag` per pipeline run (`pipeline/runner.py:117-126`), not per call. Impact: est. **+30-60 s** wall on 3003 s cold run from system+delimiter identity alone (`15-prefix-cache-enabler.md:22`); quality risk none; security risk low with HMAC, medium with pid-only hash.

- [HIGH] **Per-call random limits blast radius of escape failure; per-paper tag trades that for cache.** Tapetum draws fresh `f"SRC{secrets.token_hex(4)}"` at monolith, metadata, page, and each unit call (`pdf_judge.py:387-388`, `pdf_judge.py:638-639`, `unit_judge.py:244-245`, `unit_judge.py:767-768`). A delimiter bypass on call *k* cannot reuse tag namespace on call *k+1*. One tag per paper collapses that isolation: same `candidate_md` wrapped 5× in unit checks (`unit_judge.py:774-776`, `00-baseline.md:43-47`) shares one forge target. Acceptable because escape is tested and the eval corpus includes forged-delimiter adversarial markdown (`packages/whisker/tests/test_tapetum_llm_eval.py:240-256`, rule `injection_forged_guard_delimiter`). Impact: per-paper tag is the correct speed/security tradeoff. Quality risk: none.

- [HIGH] **Fully static tag (e.g. always `SRC`) is sufficient against literal forgery if escaping holds, but weakens the defense contract.** With static `SRC`, authors deliberately embed `<<<SRC>>>` / `<<<END_SRC>>>` at write time; escape neutralizes exact matches (`pipeline/tools.py:38-46`). Random/per-secret tags additionally ensure raw paper bytes almost never equal runtime delimiters (collision ~1/2^32 for 4-byte hex). Static tag enables **cross-paper** system-prompt identity (~52-token suffix, `pipeline/tools.py:55-61`) beyond per-paper reuse — marginal extra APC vs per-paper tag (`05-web.md:69-77`). Contradicts documented intent: pipeline CLAUDE.md requires tag "randomized per pipeline run" (`packages/pipeline/src/pipeline/CLAUDE.md` source-delimiter bullet); root CLAUDE.md names `wrap_source` (alias for `inject_untrusted` / `escape_guard_delimiters`, `pipeline/tools.py:49-52`). Impact: static tag saves at most the incremental cross-paper system suffix hits on top of per-paper tag; **not recommended** without explicit contract + red-team pass. Quality risk: none; security risk: low-moderate (defense-in-depth removal).

- [MED] **Random tag in the system suffix is what breaks KV prefix identity, not escaping logic.** `guard_instruction(tag)` embeds the tag twice in the system tail (`pipeline/tools.py:57-60`), appended after ~3.7k-char `CONVERSION_CONTRACT` (`00-baseline.md:48-52`). User payloads open with `<<<{tag}>>>\n` (`pipeline/tools.py:52`). Per-call random diverges both suffix and user opener on every one of ~2284 calls. Per-paper secret tag fixes suffix+opener for all 6 calls of one paper; user-block APC still needs reorder (shared `candidate_md` before per-unit source, `15-prefix-cache-enabler.md:10-11`). Impact: guard-tag change unlocks **~600-1100 s** envelope with server APC + reorder (`15-prefix-cache-enabler.md:22`); tag change alone ~30-60 s. Quality risk: none for tag; low-unmeasured for reorder.

- [MED] **Two-tag pattern (ideal_verify) shows tag randomness is independent of escape correctness.** `ideal_verify.py` uses separate `CANDIDATE_{token_hex}` and `IDEAL_{token_hex}` tags per call (`packages/whisker/src/whisker/tapetum_llm/ideal_verify.py:142-143`, `50-57`) with the same `inject_untrusted`/`guard_instruction` primitives (`pipeline/tools.py:49-61`). Security does not require per-call rotation when blocks are distinguished by tag name; it requires unpredictable or escaped delimiters per block. Impact: tapetum can use one tag per paper for all `SRC`-wrapped blocks without new attack surface. Quality risk: none.

- [LOW] **WebResearcher session uses one `_guard_tag` per session** (`pipeline/session.py:137`, `_random_tag` at `pipeline/tools.py:33-35`), confirming framework intent is run-stable, not call-stable. Tapetum's per-call `secrets.token_hex(4)` is stricter than pipeline default and strictly anti-cache. Impact: aligning tapetum to per-paper tag is a **relaxation** of isolation, not a new vulnerability class. Quality risk: none.

## False-pass hypothesis

Deploy per-paper `sha256(pid)[:8]` without secret: a motivated author pre-seeds `candidate_md` with delimiter-adjacent unicode homoglyphs (e.g. fullwidth less-than) that survive `escape_guard_delimiters` literal `.replace` (`pipeline/tools.py:44-45`) but visually parse as `<<<END_{tag}>>>` to the judge model, causing a unit check to honor injected "pass" text. Rare, but blast radius is all 6 calls on that paper; fleet wall drops while one adversarial holdout silently clears.

## False-fail hypothesis

Keep per-call random tags "for security" while enabling server APC: zero cross-call delimiter identity persists (`15-prefix-cache-enabler.md:30-31`), operators conclude prefix caching failed, and reject persona 15's **~500-900 s** user-block savings (`15-prefix-cache-enabler.md:22`) even though security review would have approved per-paper HMAC tags.

## What would change my mind

A red-team fixture where `inject_untrusted` + per-paper HMAC tag fails on the existing `injection_forged_guard_delimiter` eval paper (`test_tapetum_llm_eval.py:240-256`) or a newly added homoglyph/unicode-normalization bypass against `escape_guard_delimiters` (`pipeline/tools.py:38-46`) with verdict flip on the 48-paper holdout — that would force retaining per-call random or blocking persona 15's tag lever entirely.
