# 129 - nougat-Postprocess-Checks

**Verdict:** usable-with-conditions — Nougat's string-level degeneration detectors (tail repetition, fuzzy duplicate lines, table absurdity) port cleanly as cheap pre/post gates on markdown and LLM outputs, but its core logit-variance guard needs per-token decoder scores we do not expose today, and every check is output-self-consistency with zero markdown-vs-source comparison, so it cannot substitute for source-aware unit checks or persona-35's zero-defect skip logic.
**Confidence:** high

## Findings

- [CRITICAL] **Two-layer logit-variance repetition guard (not perplexity).** During generation, `StoppingCriteriaScores` tracks per-step max logit, maintains a sliding variance over the last L=15 steps (normalized by L), then variance-of-variance over window_size=200; when `varvar < 0.015` it schedules an early stop index (`model.py:418-474`, `model.py:606-608`). After decode, `logits = torch.stack(decoder_output.scores, 1).cpu().max(-1)` takes vocab-max logit per step; for each sequence, `var = [np.var(s)/len(s) for s in batch(values, b=15)]` (15-token sliding windows), then `varvar = [np.var(v) for v in subdiv(var[::-1], b=10)]` (prefix-growing windows of 10); consecutive indices where `varvar < 0.045` with `np.all(np.diff(small_var) < 2)` trigger truncation at `idx = int(min(max(small_var[0], 1) * 1.08 + minlen, 4095))` with `minlen=120` (`model.py:614-647`). If EOS appears before end, or `idx/N > 0.9`, repetition is cleared; if `small_var[0] < 30`, `idx=0` (out-of-domain, not repetition) (`model.py:629-643`).
  Impact: Requires `output_scores=True` from the decoder; tapetum's pydantic-ai/vLLM judge path does not surface per-step logits today. If logprobs were enabled (~0 LLM-cost arithmetic per call), could abort degenerate judge generations early (saves ~20 s × stuck calls) but thresholds are GPU/device-sensitive (`README.md:83-84`). Quality risk: false positives on repetitive WG21 boilerplate (revision history, numbered clauses) → premature truncation.

- [CRITICAL] **Failure routing is sentinel insertion, not retry.** CLI maps three outcomes with no regeneration loop: `output.strip() == "[MISSING_PAGE_POST]"` → `[MISSING_PAGE_EMPTY:n]` (postprocess-only uncaught repetition); `repeats[j] > 0` → `[MISSING_PAGE_FAIL:n]` (logit-detected repetition, page rejected); `repeats[j] == 0` with `repeats[j] is not None` → `[MISSING_PAGE_EMPTY:n]` (out-of-domain); else accept (`predict.py:178-195`). API variant keeps truncated text with disclaimer blocks instead of sentinels (`app.py:132-149`). `--no-skipping` disables logit gates entirely (`predict.py:74-77`, `predict.py:168`).
  Impact: Pattern portable for tapetum sidecar: persist explicit `status: error` with failure class instead of silent absence (baseline fact: 6 error papers leave no sidecar verdict). Zero wall-clock saving from retry elimination because nougat never retries; olmOCR's 12% retry (`05-web.md:41`) is the contrasting model. Quality risk: none from routing itself; risk is misclassification into EMPTY vs FAIL.

- [HIGH] **String-level tail-repetition detector (fully portable).** `truncate_repetitions(s, min_len=30)`: scan `rep_len` from 30 to `s_len/2`; if the last `rep_len` chars repeat continuously at the tail, strip all but one copy; extend cut to next punctuation boundary if the last sentence still repeats in the tail (`postprocessing.py:102-165`, invoked at `postprocessing.py:361`). Pure character arithmetic, case-insensitive, no model access.
  Impact: ~30 lines, <1 ms per page. Could post-validate tapetum LLM unit-check JSON/markdown reasoning for repetition collapse without an extra LLM call. On the 3003 s cold run, if integrated as fail-fast on judge output: saves at most a handful of stuck 120 s timeout calls (55 retries ≈ 100 s total already). As pre-filter before unit checks: only fires on degenerate converter output (rare in our pipeline since tomd is deterministic, not autoregressive). Quality risk: low for post-validation; as skip trigger for unit checks → false-pass on token-preserving corruption (the 70% zero-defect population our unit checks exist to catch).

- [HIGH] **Fuzzy duplicate-line hallucination detector (partially portable).** `get_slices`: consecutive non-empty lines (3–200 chars, numbers stripped) with `ratio > 0.9` (rapidfuzz) or exact match, excluding `[MISSING_PAGE` lines, merged into slices when gap ≤3 and slice length >15 lines (`postprocessing.py:190-229`). Matching blocks replaced with `[MISSING_PAGE_POST]` (`postprocessing.py:301-329`). Also drops absurd table rows: `\begin{tabular} > 15`, `\multicolumn > 60`, or `& > 400` per line (`postprocessing.py:451-457`); strips likely hallucinated trailing `#` headings (`postprocessing.py:353-359`).
  Impact: Bibliography/reference hallucination detection ports to WG21 markdown if references sections are present (many WG21 papers lack formal bib blocks → low recall). Table-absurdity heuristics useful for LaTeX-heavy tomd output. Cannot detect markdown-vs-source fidelity gaps. Pre-filtering unit checks on "no duplicate lines" would NOT safely predict zero-defect: a clean-looking page can still have cell swaps or missing rows (baseline: 70% of 1510 unit checks return zero groups, but those pages passed the deterministic recall screen). Estimated saving if used to skip unit checks on "clean" pages: 0 s with acceptable quality (would skip the wrong 70%).

- [MED] **Eval metrics are reference-comparison, separate from runtime guards.** `compute_metrics(pred, gt, minlen=4)` returns char-NED, BLEU, METEOR, word-set precision/recall/F1; samples below 4 chars return `{}` and are omitted from means (`metrics.py:27-44`). Modality split (Text/Math/Tables) via regex strip before scoring (`metrics.py:63-83`). These run offline in `test.py`, not during inference.
  Impact: Confirms runtime guards are NOT markdown-vs-source checks. The set-F1 pattern (word-bag overlap) is weaker than our `content_recall` / per-page screen but could inspire a cheap "candidate slice vs source slice" pre-score before unit checks — that would be our own math, not nougat's. No direct wall-clock lever.

- [MED] **Zero-defect predictor relevance: negative for skip, positive for veto.** Nougat detects autoregressive degeneration (repetition loops, OOD pages, hallucinated bib blocks). Tapetum unit checks detect source-vs-candidate fidelity defects (70% zero-defect rate, baseline `00-baseline.md:29-30`). The signal classes are orthogonal: a page with zero conversion defects can trigger nougat's varvar guard on repetitive standard wording; a page passing all nougat string checks can still fail a unit check on table cell swap. Portable role: **veto** (fail-closed when markdown or LLM output looks degenerate), not **skip** (predict zero-defect without source comparison). Aligns with `05-web.md:93-96` deterministic-floor pattern (30–60% failure catch) but applied post-generation, not pre-judge.
  Impact: Realistic saving: post-validate LLM outputs → avoid persisting repetition-corrupted sidecars (quality, not large wall-clock). Pre-gate unit checks on `truncate_repetitions` pass → unsafe; would need pairing with existing `screen_pages` recall floor (`pdf_judge.py:296+`, `constants.py:177`) for any skip logic. Combined veto on degenerate markdown before monolith: saves 1–6 calls × ~20 s only on broken converter output (estimate <60 s on 3003 s run, ~2%).

- [LOW] **Whisker already has an adjacent pattern not yet wired.** `auto_baseline_checks` in `facts.py:648-689` uses regex `(.{3,})\1{4,}` for repeated n-grams (olmOCR pattern), plus minimum alnum count; callable but not in guard/fleet path. Nougat's `truncate_repetitions` is more precise for tail-continuous repeats; the two are complementary.
  Impact: Lowest-friction port is extending `auto_baseline_checks` or a tapetum pre-call hook with nougat's tail-repetition + duplicate-line slice logic. Implementation cost hours, not days; wall-clock impact modest unless paired with logprobs-based early stop.

## False-pass hypothesis

A WG21 paper with a table row swap (same words, wrong row) passes `truncate_repetitions`, `remove_hallucinated_references`, and logit-variance checks because the markdown is non-degenerate and self-consistent; persona-35's zero-defect predictor built on nougat heuristics skips the unit check; the merged verdict stays pass while the deterministic gate's order-blind `unigram_coverage` also passes — the exact false-pass class tapetum exists to catch (`00-baseline.md:29-30`).

## False-fail hypothesis

A valid WG21 page with dense numbered proposal clauses (`1.2.3`, `1.2.4`, …) triggers consecutive low `varvar` windows (`model.py:635-637`) or `[MISSING_PAGE_FAIL]` routing (`predict.py:181-185`); a nougat-style pre-gate marks the page degenerate and caps the paper at review/fail even though tomd captured the content correctly — the same failure mode documented for CPU inference (`README.md:83-84`, issues #11/#67).

## What would change my mind

Evidence that vLLM/pydantic-ai on `alliance-pod` exposes per-token logprobs or scores on judge calls AND a calibration run on ≥50 tapetum papers shows logit-varvar (thresholds retuned) catches ≥80% of the 55 model-retry degenerations (`00-baseline.md:60-61`) with ≤5% false flags on clean WG21 conversions — would upgrade logit guard from "conditional" to a primary early-abort lever worth ~100–300 s on the cold run.
