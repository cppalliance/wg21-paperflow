# 87 - langextract-Retry-Handling

**Verdict:** usable-with-conditions (+ Gemini per-chunk transport retry and index-ordered parallel yield are portable; default silent chunk drops and whole-batch inference abort are anti-patterns for tapetum — keep our unit-level continue-on-failure, not langextract's split semantics)
**Confidence:** high

## Findings

- [CRITICAL] **Two-layer failure semantics: transport retry is per-chunk; parse failure is silent skip by default.** Gemini `_process_single_prompt` retries transient API/429/timeout errors up to `max_retries + 1` attempts (`providers/gemini.py:45-47`, `351-391`) with exponential backoff capped at `max_retry_delay` and per-attempt jitter `random.uniform(0.5, 1.5)` (`providers/gemini.py:376-377`). OpenAI realtime has **no** equivalent loop — any exception becomes `InferenceRuntimeError` immediately (`providers/openai.py:244-261`). After inference succeeds, `Resolver.resolve` with default `suppress_parse_errors=True` (`extraction.py:365`, `resolver.py:276-320`) logs and returns `[]` on `FormatError` or schema `ValueError`, and the document run continues. Impact: langextract optimizes **conversion yield** (hide bad chunks); tapetum must **never** adopt this default — equivalent would silently pass units with zero defect signal (~70% of our unit checks already return zero groups, `00-baseline.md:29-30`). Quality risk: **HIGH** if ported.

- [CRITICAL] **Parallel realtime inference is all-or-nothing: one failed prompt aborts the whole batch; no sibling cancellation, no partial envelope.** When `len(batch_prompts) > 1 and max_workers > 1`, Gemini submits all prompts to `ThreadPoolExecutor` (`providers/gemini.py:476-485`), fills index slots from `as_completed` (`providers/gemini.py:487-493`), and on **any** worker exception raises `InferenceRuntimeError('Parallel inference error: ...')` immediately (`providers/gemini.py:494-497`); unfilled slots raise `'Failed to process one or more prompts'` (`providers/gemini.py:499-503`). OpenAI mirrors the pattern (`providers/openai.py:355-384`). There is **no** `future.cancel()` on siblings; the executor context manager waits for outstanding threads on exit. Prior completed **batches** are already resolved (`annotation.py:366-440` serial batch loop); the **current** batch contributes nothing. Impact: for persona-20 in-paper parallel dispatch, **do not** copy langextract's abort-whole-wave rule for **independent unit checks** — that would orphan successful siblings. Our serial path already does better: `unit_judge.py:419-423` catches per-unit exceptions, appends `failed_unit_ids`, continues. Recommended parallel policy: **`asyncio.gather` per unit with index-ordered fold**, continue-on-unit-failure, set `coverage_complete=false` (`unit_judge.py:460-464`). Expected wall saving: **0 s on 3003 s cold fleet** (persona 20 slot accounting); quality risk: **LOW** for unit continue-on-fail vs langextract batch abort.

- [HIGH] **Recommended per-call failure policy for parallel in-paper dispatch (if persona 20 lands).** (1) **Hard gates (monolith, metadata, page escalation):** keep `PdfLaneError` paper abort — same fail-fast shape as langextract inference abort (`pdf_judge.py:658-659`, `686-688`, `761-763`; `pdf_judge.py:586`). (2) **Scoped unit checks (parallel wave):** per-unit try/except → `failed_unit_ids`, siblings finish (`unit_judge.py:419-423`); post-wave `coverage_complete = not failed_unit_ids` caps verdict at `review` (`unit_judge.py:460-477`, `pdf_judge.py:895-902`). (3) **Transport retry:** keep backend **2-attempt** fixed-temperature retry (`model_backends.py:300-350`), not langextract's **4-attempt** jittered Gemini loop (`providers/gemini.py:356-387`) — olmocr persona 73 shows temperature ramps forbidden (D5); jitter under parallel workers amplifies 429 storms (`providers/gemini.py:49`, `376-377`). (4) **Schema/parse exhaustion:** count as **unit failure**, never `suppress_parse_errors` silent `[]` (`resolver.py:309-320`). (5) **Ordering:** index-keyed materialize-before-fold (`annotation.py:392-396`, `providers/gemini.py:487-504`) ≈ `runner.py:133-162` `gather_concurrent`; do **not** copy `ThreadPoolExecutor` + shared sync client (`providers/gemini.py:477-491`). Impact: preserves fail-closed coverage semantics while allowing W-wide unit fan-out; avoids langextract false-complete documents.

- [HIGH] **Batch API failure path pads missing items as empty strings → silent chunk drop under default suppress flag.** Vertex batch extract returns `outputs_by_idx.get(i, "")` for missing indices (`providers/gemini_batch.py:649-651`, `703-704`); empty input hits `FormatParseError` (`core/format_handler.py:169-170`) and, with default suppress, becomes zero extractions (`resolver.py:309-312`). Per-item errors raise when `ignore_item_errors=False` (default `providers/gemini_batch.py:88`, `616-619`); OpenAI batch intentionally fails the whole job on per-item errors (`providers/openai_batch.py:57-58`). Impact: not our hot path (realtime vLLM), but confirms Google treats **batch** as fail-hard and **parse** as optionally fail-soft — we should stay fail-hard on both. Quality risk: **HIGH** if batch-style padding ever appears in tapetum sidecars.

- [HIGH] **Rate-limit behavior under parallel workers: independent jittered backoff, no global throttle.** Retryable codes include **429** (`providers/gemini.py:49`); message regex matches `rate[ _]limit|quota exceeded` (`providers/gemini.py:53-56`). Each parallel worker in the pool runs its own retry sleep (`providers/gemini.py:351-387`) with no shared semaphore across workers — at shipped defaults `batch_length=10`, `max_workers=10` (`extraction.py:57-58`) up to ten threads can simultaneously hit 429 and retry with uncorrelated jitter. Impact: under persona-20 W≤12 parallel unit burst on one MoE pod (`20-in-paper-parallelist.md:10`), langextract-style per-worker retry storms risk **slot hoarding** and tail latency (persona 20 false-fail: timeout under contention → `failed_unit_ids`). Mitigation: cap in-paper concurrency below pod `--max-num-seqs 16`, serialize retry backoff at paper level, or use global 429 circuit-breaker — **do not** copy langextract's per-thread independent backoff. Cold fleet impact: **0 s** unless parallel units ship; quality risk: **MED** (timeout-induced review caps).

- [MED] **Alignment failures pass through ungrounded extractions; no document-level partial flag.** Failed alignment leaves extractions in output with `char_interval=None` / `alignment_status=None` (`resolver.py:1017-1019`, `1021-1068`); all aligned yields append regardless (`annotation.py:431-432`). No `AnnotatedDocument.partial` field exists. Impact: structurally valid but unverified spans — opposite of tapetum dropping ungrounded quotes. Quality risk: **MED** if conflated with grounded evidence.

- [MED] **Compare olmocr (personas 73/78): post-hoc document discard vs our tombstones; langextract has neither.** olmOCR runs all pages concurrently then discards the document if fallback rate > 0.004 (`olmocr/pipeline.py:557-563`, cited in `73-olmocr-retry-economics.md:14-15`) — **post-batch**, no mid-flight sibling cancel (`78-olmocr-fallback-design.md:10-11`). langextract: no document-level discard gate; either silent chunk omission or whole-batch inference abort. Tapetum: paper exception → `status="error"` tombstone, batch continues (`cli.py:747-769`, `1397-1406`); unit partial failure → completed sidecar with `coverage_complete=false`, not tombstone (`unit_judge.py:460-477`). Impact: for parallel units, **olmocr discard is irrelevant**; **langextract batch abort is the hazard**; our tombstone + unit-failure split is the correct hybrid. Cold-run savings from error-path tuning remain **<1%** (`78-olmocr-fallback-design.md:16-17`).

- [LOW] **Timeout handling is delegated to HTTP client / batch poll, not application per-chunk budgets.** Gemini batch `BatchConfig.timeout` default 3600 s poll cap (`providers/gemini_batch.py:86`); realtime relies on `httpx.TimeoutException` as retryable (`providers/gemini.py:334-340`). No per-chunk wall budget in `annotate_text`. Our `UNIT_CHECK_TIMEOUT_SECONDS=120` (`constants.py:197`) is stricter and becomes the binding limit under parallel slot contention (persona 20 false-fail). Impact: parallel fan-out needs timeout budget scaled for queue depth, not langextract's open-ended retry loop.

## False-pass hypothesis

Parallel in-paper unit dispatch copies langextract defaults: `suppress_parse_errors=True` equivalent — one unit returns malformed JSON, handler treats it as zero defects, `coverage_complete` stays true because the unit landed in `checked_unit_ids` without defects, and a table swap on that page false-passes advisory `pass` while deterministic whisker stays green.

## False-fail hypothesis

Parallel in-paper unit dispatch copies langextract's `infer()` batch abort: five unit tasks run concurrently, one hits schema exhaustion after two backend attempts (`model_backends.py:394-406`), implementation raises `PdfLaneError` and tombstones the whole paper (`cli.py:1382-1387`) even though four siblings succeeded — false-fail vs current serial path that records `failed_unit_ids` and caps at `review` (`unit_judge.py:419-423`, `460-464`).

## What would change my mind

langextract HEAD adding `AnnotatedDocument.failed_chunk_indices` (or flipping default `suppress_parse_errors=False`) **and** a parallel-mode flag that returns partial batch results instead of raising `InferenceRuntimeError`, with tests proving index-ordered partial collection — would make their failure envelope comparable to our unit coverage model and upgrade the parallel-abort finding from "anti-pattern" to "optional strict mode."
