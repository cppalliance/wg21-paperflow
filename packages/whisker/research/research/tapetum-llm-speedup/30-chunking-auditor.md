Impact: **0 s** wall saving from chunk parallelism on the 3003 s cold run today; the prior "7 chunks × 30 s" tail is **historical**, not current fleet state.

Raw sizes exceed 500k for at least P2728R11 (**2,538,982** chars), P2728R12 (**2,552,961**), P3045R8 (**706,242**), P4215R0 (**547,119**), but `strip_binary_payloads` collapses megabyte data-URI/base64 lines before `chunk_markdown` (`chunking.py:54-103`), leaving **0/381** above threshold. - [HIGH] **Serial chunk triage cites D11 for determinism, but the fold is already order-independent and D11 explicitly exempts this lane.** Serial loop: `for index, chunk in enumerate(chunks): parts.append(await run_agent(...))` (`adjudicate.py:248-252`) with docstring "D11: one in-flight request at a time, no parallelism" (`adjudicate.py:236-237`). Contradicting authority: "D11 binds dissect, not this lane" (`tapetum_llm.md:31`); advisory lane may run **32 papers concurrently** (`cli.py:119-127`, `whisker/CLAUDE.md:689-691`); `judge_task.py:17-23` documents the sanctioned per-package concurrency bypass of pipeline `Semaphore(1)`. Fold function `aggregate_adjudications` is pure: max-severity per axis with **sorted axis names** (`chunking.py:250-256`), `confidence = min(...)` (`chunking.py:259`), verdict via `worst_axis_verdict` (`chunking.py:106-123`, `258`), evidence union with dedup (`chunking.py:268-275`). **Parallel execution with the same fold cannot change aggregated verdict**; only completion order of independent LLM draws differs (already a documented MoE variance budget at `tapetum_llm.md:31`).

- [HIGH] **Per-chunk latency × chunk count defines single-paper tier-1 wall; this was the fleet tail only when chunking fired.** Timeout budget assumes worst chain "7 chunks × ~30 s" plus tier-2 (`cli.py:134-137`, `_PAPER_TIMEOUT_SECONDS = 900.0` at `cli.py:138`). Baseline implied per-call latency **~20 s** at 16 server slots (`00-baseline.md:24-25`). For an N-chunk paper, tier-1 serial wall ≈ **N × 20–30 s** (monolith triage only; tier-2 skipped when chunked at `adjudicate.py:287-291`). Example: N=7 → **140–210 s** tier-1 alone vs **~20–30 s** if all chunks decode concurrently within one paper's slot budget. Impact on **current** 3003 s fleet: **0 s** (no chunked papers). Latent worst-case single-paper saving if chunking returns: **(N−1) × ~25 s** ≈ **150 s** for N=7.

- [MED] **Proposed parallel chunk execution: `ctx.gather_concurrent` + unchanged `aggregate_adjudications`.** Replace serial loop at `adjudicate.py:248-252` with bounded parallel dispatch returning `(index, Adjudication)` pairs, then `aggregate_adjudications([adj for _, adj in sorted_results], len(chunks))`. Existing helper preserves deterministic **output order** regardless of completion order (`runner.py:133-162`: "Results are sorted by index"). Concurrency bound: `min(len(chunks), K)` where K ≤ server `--max-num-seqs 16` (`00-baseline.md:66`); typical N ≤ 7 (`constants.py:60`). Implementation stays whisker-local (`judge_task.py:17-23` precedent); no pipeline edit. Quantified tail saving (if N-chunk papers reappear): tier-1 wall **N×T → T** (one decode wave), e.g. **210 s → 30 s** for N=7, T=30 s; **180 s saved per chunked paper**. Fleet contribution = **180 s × (number of chunked papers / 381)**; at 0 chunked papers today → **0 s**; if 6 papers at N=2 each → **~6 × 25 s ≈ 150 s** (~0.05% of 3003 s).

- [MED] **Chunked papers permanently skip tier-2, amplifying any triage miss.** When `state.chunked`, `_custom_adjudicate` returns without deep-model re-read because full markdown would 413 (`adjudicate.py:287-291`). Chunk parallelization does not restore tier-2; it only shortens tier-1. Partial hard-split sections force review, never pass (`adjudicate.py:358-362`, `chunking.py:136-150`). Impact: speed lever is safe for fold semantics; quality ceiling for oversize papers remains **single-tier triage + aggregate** regardless of serial vs parallel execution.

- [LOW] **Tests lock serial chunk behavior but not fold determinism under reorder.** `test_oversize_chunks_serially_and_skips_tier2` patches `MAX_PAPER_MD_CHARS=80` and asserts `mock_run.call_count > 1` plus tier-2 skip (`test_tapetum_llm.py:1391-1424`); no test asserts parallel-safe aggregation (though `aggregate_adjudications` has separate unit coverage at `test_tapetum_llm.py:1291+`). Impact: parallel adoption needs one test mirroring serial fold outputs with shuffled mock return order.

## False-pass hypothesis

Parallel chunk triage on a 2-chunk paper where chunk 1 is clean and chunk 2 contains a **major** structure fail: `aggregate_adjudications` still takes worst-axis max severity (`chunking.py:250-255`, `_finding_rank` at `chunking.py:295-302`) regardless of call order, so parallelization does not dilute a major fail. A false pass would require **MoE batch-composition variance** (different expert routing when N chunk calls co-schedule with other papers' prefills) to flip one chunk from fail→pass, not reordering of the fold — same variance class already tolerated at paper-level c=32 (`tapetum_llm.md:31`, `whisker/CLAUDE.md` advisory instability section).

## False-fail hypothesis

One chunk in a parallel wave times out or returns malformed JSON while others succeed; today the serial loop would fail the whole `_custom_triage` step. Parallel execution with `gather_concurrent` and fail-closed semantics would behave identically unless partial results are incorrectly aggregated — if implemented as "gather all or raise", no new false-fail. If implemented as best-effort partial aggregation without setting `state.partial`, a failed chunk could masquerade as a clean pass; mitigated by existing `partial` flag path (`adjudicate.py:358-362`) when hard-split applies, not when a call fails (gap: failed chunk ≠ `partial=True` today).

## What would change my mind

A post-strip paper in the live 381-paper set exceeding `MAX_PAPER_MD_CHARS` (or a deliberate reintroduction without stripping on a golden holdout) that chunks into N≥3 **and** appears in sidecar `reasoning` with `"aggregated over N chunks"`, demonstrating chunking is fleet-relevant again — would upgrade chunk parallel from "0 s fleet lever" to "quantifiable tail trim" worth prioritizing alongside unit-check parallel.
