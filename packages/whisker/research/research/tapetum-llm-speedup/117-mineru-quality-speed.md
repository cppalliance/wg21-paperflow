# 117 - mineru-Quality-Speed

**Verdict:** usable-with-conditions — MinerU documents a sharp quality-speed Pareto (hybrid `effort` + backend choice + formula/table toggles) with OmniDocBench numbers per mode, but it is a **generation** pipeline with no post-conversion QA; its tiering informs our cascade design, not a license to drop judge coverage.
**Confidence:** high

## Findings

- [CRITICAL] **Three-backend surface with documented OmniDocBench v1.6 accuracy per mode.** Evidence: README deployment table — pipeline **86.47**, hybrid-engine **95.26 (medium)** / **95.39 (high)**, vlm-engine **95.30** End-to-End Overall (`research/repos/mineru/README.md:241-246`); footnote cites OmniDocBench v1.6 (`README.md:286`). Backend enum and default: `DEFAULT_BACKEND = BACKEND_HYBRID_ENGINE` (`mineru/cli/backend_options.py:3-11`). CLI/API help: pipeline = "More general… hallucination-free", vlm/hybrid = "High accuracy" (`mineru/cli/client.py:1085-1092`, `mineru/cli/api_request.py:111-116`). Impact: MinerU's **9-point** pipeline→hybrid gap quantifies what a full quality tier costs; our tapetum judge cannot swap backends, but a **cascade** (dense 32B unit checks, DeepSeek only on flags) should cite similar measured deltas, not guess. Quality risk: treating MinerU hybrid scores as transferable to WG21 defect detection without holdout replay.

- [CRITICAL] **Tiering pattern: quality-family default with explicit fast sub-tier (not fast-default + quality opt-in).** Evidence: bare `mineru -p … -o …` uses hybrid-engine + `DEFAULT_HYBRID_EFFORT = "medium"` (`backend_options.py:8-11`, `client.py:1095-1106`); v3.3 changelog: default Hybrid uses `effort=medium`, **−0.13** OmniDocBench vs `high`, **+35%–+220%** speed by platform/scenario (`README.md:103-109`); medium **forces** `image_analysis=False` regardless of CLI flag (`mineru/backend/hybrid/hybrid_analyze.py:117-121`, `903`); high runs full `batch_two_step_extract` with optional image analysis (`hybrid_analyze.py:1005-1025`), medium runs layout→scoped `batch_extract_with_layout` (`965-986`). Pipeline/fast path is **opt-in** via `-b pipeline` for CPU (`README.md:334-336`). Impact: portable pattern = **fast default within the accurate backend**, quality opt-in via `--effort high` / `-b vlm-engine`; mirrors LLMTrace/SAJA cascades in `05-web.md:88-100`. For tapetum: default unit lane on dense 32B, escalate changed-verdict band to DeepSeek — do **not** invert to "fast judge default + optional quality." Quality risk: medium effort drops image/chart analysis; analogous tapetum tier must not silently skip defect classes.

- [HIGH] **Per-stage toggles: formula, table, OCR mode, image analysis — all default ON, env-overridable, stage-skipping in pipeline.** Evidence: CLI `-f/--formula`, `-t/--table` default `True` (`client.py:1148-1162`); API form defaults `formula_enable=True`, `table_enable=True` (`api_request.py:139-146`); env `MINERU_FORMULA_ENABLE` / `MINERU_TABLE_ENABLE` override (`config_reader.py:140-149`); `MineruPipelineModel` skips MFR/table model init when disabled (`model_init.py:233-274`); `batch_analyze` gates formula MFR block (`batch_analyze.py:434-465`) and table inline extraction (`473-480` when `table_enable` false); `parse_method` auto|txt|ocr for pipeline/hybrid (`client.py:1064-1075`, `pipeline_analyze.py:88-93`); VLM/hybrid get formula/table via env in `do_parse` (`common.py:731-732`, `748-749`). Impact: disabling formula/table is a **proven stage-skip lever** (no MFR/table GPU time); for tapetum, **cannot** disable formula/table checks by fidelity rules, but **can** skip unit categories when deterministic pre-gate says N/A (persona 35/05-web deterministic floor). Estimated wall saving: stage-skip analogue is call elimination, not MinerU's 100% OCR pipeline speedup (`README.md:88-90`). Quality risk: `-f false` drops LaTeX entirely — false-pass on formula defects if copied blindly.

- [HIGH] **Hybrid medium vs high: measured accuracy/speed trade with distinct code paths.** Evidence: OmniDocBench **95.26 vs 95.39** (−0.13) and platform speedups **35%–220%** (`README.md:105-109`); medium maps pipeline layout labels → partial VLM block types via `MEDIUM_EFFORT_LAYOUT_LABEL_TO_VLM_TYPE` (`hybrid_analyze.py:83-107`) and calls `batch_extract_with_layout`; high calls `batch_two_step_extract` (`965-1033`). `effort=medium` disables image/chart analysis even when `--image-analysis true` (`hybrid_analyze.py:117-121`). Impact: MinerU proves **sub-point benchmark loss buys multiplicative wall** — direct precedent for tapetum holding 5–10 min target while accepting ≤0.5 pt oracle-agreement loss on unit lane (cf. SLMJury 10-token verdicts, `05-web.md:88-89`). Quality risk: medium skips image analysis (`README.md:110`); our analogue must map skipped classes to explicit fail-closed or deterministic checks.

- [MED] **Pipeline backend: deterministic fast lane, still high-ish accuracy, zero VLM calls.** Evidence: README "Fast & stable, no hallucination, runs on CPU or GPU" (`README.md:72-76`); pipeline **86.47** vs hybrid **95.26+** (`README.md:241-246`); v3.0 claims **86.2** on OmniDocBench v1.5, beating prior VLM (`README.md:141-144`); PP-OCRv6 upgrade **+11%** OCR on v1.6 (`README.md:87-90`). `doc_analyze_streaming` uses layout/OCR/MFR/table atom models only (`pipeline_analyze.py:157-165`, `batch_analyze.py:425-450`). Impact: same pattern as Docling default (0 LLM calls) — speed by **not invoking** the expensive model; tapetum's 2284-call judge fleet has no MinerU-style "turn off the LLM" path without replacing checks with deterministic code. Quality risk: none for tiering study; pipeline scores do not validate our judge rubric.

- [MED] **No post-conversion verification / output QA — only in-pipeline confidence filtering and optional human visualization.** Evidence: README lists "visualization… for efficient **confirmation** of output quality" — human, not automated (`README.md:182`); no markdown re-read, no LLM judge, no fail-closed output gate in repo search. In-pipeline only: `OcrConfidence.min_confidence = 0.5` drops low-score OCR (`ocr_utils.py:10-11`, `380-381`; `model_json_to_middle_json.py:185-193`; `batch_analyze.py:897-919`); PaddleOCR `drop_score` filter (`pytorch_paddle.py:287-288`); table wired/wireless routing when `cls_score < 0.9` (`batch_analyze.py:667-669`); scores written to middle JSON (`docs/zh/reference/output_files.md:73+`) but **never** trigger document-level fail/retry. Optional `llm-aided-config` title leveling is post-process **enhancement**, disabled unless config enables (`title_level_postprocess.py:17-38`, `llm_aided.py:352+`) — not conversion QA. Impact: MinerU ships output after deterministic assembly; **we are comparing against systems that skip verification entirely** — our 3003 s cold run buys defensible verdicts they do not attempt. Cannot "match MinerU speed" by dropping judge without accepting silent defect escape. Quality risk: N/A for MinerU; HIGH if we mimic their no-QA posture.

- [LOW] **VLM formula/table toggles affect emit only; hybrid hardcodes VLM formula env true.** Evidence: `get_formula_enable` / `get_table_enable` used at markdown emit (`vlm_middle_json_mkcontent.py:277,361`); hybrid path sets `MINERU_VLM_FORMULA_ENABLE="true"` regardless of CLI formula flag (`common.py:748-749`), while pipeline respects `formula_enable`/`table_enable` end-to-end. Impact: toggle semantics differ by backend — tapetum cascade must keep toggle semantics consistent across lanes. Quality risk: low.

## False-pass hypothesis

Adopt MinerU-style `effort=medium` cascade on tapetum without mapping skipped capabilities: disable image/chart-related unit checks (MinerU medium drops `image_analysis`) while still emitting pass — cross-page figure caption or chart-table defects escape, matching MinerU's accepted blind spot (`hybrid_analyze.py:117-121`, `README.md:110`).

## False-fail hypothesis

Run hybrid `high` or full DeepSeek on all 1510 unit checks when medium-tier dense judge agrees with monolith on 70% zero-defect papers (`00-baseline.md:29-30`): no new findings, ~2× decode cost — false economy if we treat MinerU's −0.13 benchmark gap as requiring the slow tier everywhere.

## What would change my mind

Holdout replay showing tapetum unit lane on h200-qwen3-32b with monolith/metadata short-circuit matches DeepSeek fused verdicts at ≥99% with ≤0.3 pt defect recall loss — would justify MinerU-style medium-default / high-escalation as primary path to 5–10 min.
