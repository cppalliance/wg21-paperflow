# 07 - Retry-Timeout-Auditor

**Verdict:** usable-with-conditions — retries and timeouts priced tonight; they explain ~130 s (~4.5%) of 2883 s wall, not the 4.2× regression vs 692 s.
**Confidence:** high

## Findings

- [CRITICAL] **54 model retries add ~101 s fleet wall, not hundreds.** Evidence: footer in `00-baseline.md:27-28` (`54 model retries) in 2883.0s`); `_RetryCountFilter` counts swallowed warnings matching `_RETRY_WARNING_MARKERS` (`cli.py:220-238`); baseline per-call decode ~25–28 s of ~30 s mean (`00-baseline.md:58-59`, `17-latency-decomposer.md`). Arithmetic: 54 × 30 s / 16 server slots ≈ **101 s** (3.5% of 2883 s). Impact: retry storms are real (vs **1 retry** on the 2026-07-08 c=32 381-paper run, `20-sweep-results.md:82`) but are a rounding error on the 2191 s regression delta.

- [CRITICAL] **Retries are backend-level re-issues, not pydantic-ai `output_retries` or `ModelRetry`.** Evidence: tapetum lane has zero `output_retries` / `ModelRetry` / `output_validator` usage under `packages/whisker/src/whisker/tapetum_llm/`; `judge_task.py:68-74` and `unit_judge.py:257-266` call `AgentBackend.run` → `VllmThinkingBackend.run` (`model_backends.py:300-410`). Retry cap: **`max_attempts = min(2, request_limit)`** (`model_backends.py:300`), default `request_limit=500` (`model_backends.py:53`). Triggers: transient API errors (`APITimeoutError`, connection/5xx, `model_backends.py:341-350`), JSON parse/validation failure (`model_backends.py:371-406`), truncation grow-path (`finish_reason=length`, `model_backends.py:377-393`). Ideal verifier uses `run_task` (`ideal_verify.py:151-158`) and inherits the same backend retry budget. Impact: each counted retry is at most **one extra full HTTP completion** (~30 s), capped at **1 retry per call** (2 attempts total).

- [HIGH] **Zero papers hit a wall-clock timeout tonight; generous budgets never fired.** Evidence: grep of `_scratch/whisker-fullrun/llm-stderr.txt` — no `timeout`, `Timed out`, or `asyncio.TimeoutError`. Paper budgets: `_PAPER_TIMEOUT_SECONDS = 900` (`cli.py:135`); PDF path `asyncio.wait_for(..., timeout=_pdf_judge_timeout_seconds(...))` (`cli.py:1188-1203`); fleet default (`unit_count=None`) = 900 + 5×120 + 6×120 = **2220 s** (`cli.py:151-158`, `constants.py:191-241`); text lane **1620 s** (`cli.py:195-198`). Ideal attach capped at 900 s (`cli.py:1129-1136`). Per-call HTTP: `AsyncOpenAI(...)` with **default 600 s read timeout**, no override (`model_backends.py:283`; documented `cli.py:131-134`, `15-concurrency-safety.md:8`). Observed mean 7.6 s/paper (`00-baseline.md:41-42`). Impact: timeout inflation is **latent ceiling**, not tonight's cost; a hung request would hold a concurrency slot until HTTP timeout or paper `wait_for` fires (`cli.py:1098-1099` holds `sem` for the whole `_adjudicate_one` chain).

- [HIGH] **Four errors identified; two are post-cascade IdealVerification waste.** Evidence: `llm-stderr.txt:63` **P3400R3** `PdfLaneError: metadata/outline check failed` (tombstone `phase: metadata`, `page_count: 90`); `:150` **P3977R0** `PdfLaneError: judge call failed: Raw JSON completion failed after 2 attempt(s)` — schema `missing_content` list `too_long` (6 > 5); `:336` **P4182R0** `IdealVerificationError` after `:323` `pdf-judge verdict=review` (full PDF cascade logged in `pdf_judge.py:1001-1008`); `:356` **P4228R0** `IdealVerificationError` on text lane. All four write **`status="error"` tombstones** via `_write_error_tombstone` (`cli.py:725-757`, `:1348-1353`); never partial pass. Impact: **IdealVerificationError runs after all lane LLM calls** (`ideal_verify.py:151-159` post-`run_task` grounding check; PDF path `_attach_ideal` after `judge_pdf_extraction` returns, `cli.py:1205`).

- [MED] **Error waste priced at ~14–17 LLM calls (~420–510 s serial, ~26–32 s fleet-equivalent).** Evidence: P3400R3 tombstone `phase: metadata`, `checked_unit_ids: []` → monolith + failed metadata ≈ **2 calls**; P3977R0 `phase: monolith` → **2 calls** (retry exhausted, matches log); P4182R0 `checked_unit_ids` length 5 + ideal → monolith + metadata + 5 units + ideal ≈ **8 calls** (verdict logged before ideal fail); P4228R0 no `partial_progress` → triage + metadata + routed units + ideal ≈ **4–7 calls** (log `:342` unit warning only). At ~30 s/call, 16 slots: **~26–32 s** fleet wall. Impact: error tombstones are honest fail-not-partial but burn full chains; Ideal cases dominate wasted work.

- [MED] **Retries/errors are not late-phase concentrated; timestamps unavailable for per-retry correlation.** Evidence: ERROR line positions 63 / 150 / 336 / 356 of 361 log lines (~17%, 42%, 93%, 99%); throughput buckets flat ~8 papers/min (`00-baseline.md:37-39`). - [LOW] **07-09 benchmark had near-zero retry/error tax; tonight's overhead is new but small.** Evidence: 381-paper c=32 run **692.3 s, 1 transient error, 1 model retry** (`20-sweep-results.md:78-82`); Phase-0 sweep **0 retries at c=8/16/32** (`20-sweep-results.md:29-30`). Impact: reliability regressed slightly; throughput regression remains call-volume dominated (~4× calls/persona envelope, `00-baseline.md:104-108`).
