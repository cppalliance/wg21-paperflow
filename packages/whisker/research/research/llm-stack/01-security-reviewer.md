# 01 - Security-Reviewer

**Verdict:** usable-with-conditions (+ tier-2 prompt trust boundary and secret-storage paths need hardening before treating the stack as injection-safe end-to-end)
**Confidence:** medium

## Findings
- [HIGH] Tier-1 model output is injected into the tier-2 user prompt without guard delimiters, crossing the untrusted→trusted boundary. Evidence: `adjudicate.py:342-345` embeds `tier1.reasoning`, `tier1.primary_concern`, and verdict fields raw in `_build_adjudicate_message`, while paper markdown alone is wrapped via `ctx.inject_untrusted` at `:348`. Impact: a paper that steers tier-1 reasoning can carry forged instructions into tier-2 as if they were pipeline context; grounding and pydantic schema limit verdict fields but not free-text reasoning influence.
- [HIGH] `SERVICES.toml` supports and uses inline literal API keys, contradicting the loader docstring's "keys never in the file" claim. Evidence: `services.py:155-167` (`api_key = "sk-literal"` branch constructs backends with the literal value); `services.py:12-13` (doc claims env-only); `SERVICES.toml:50` (live `[services.*]` entry with literal `api_key`, not `$ENV` form). Impact: keys land in repo history, backups, and process memory without rotation discipline; any reader of the config file gets live credentials.
- [MED] Untrusted model JSON passes through `json.loads` before pydantic validation with no size or depth cap on the extracted substring. Evidence: `model_backends.py:373-375` (`json_str = _extract_json(content); parsed = json.loads(json_str); result = output_type.model_validate(parsed)`); baseline runtime fact (00-baseline.md:48, CJK token injection in 200-paper batch). Impact: malformed or adversarially large JSON can burn memory/CPU in the retry loop (`model_backends.py:76-85`, `:382-421`); pydantic D6 blocks schema escape but not parse-time DoS; vLLM guided decoding is the documented retire-when (`MODELS.md:119-121`, https://github.com/vllm-project/vllm/issues/41985).
- [MED] Raw JSON retry feedback re-appends the full prior assistant turn (including `<think>` content) into the message history. Evidence: `model_backends.py:409-416` (`messages.append({"role": "assistant", "content": raw_content})` plus error-feedback user turn). Impact: context contamination amplifies bad tokens across attempts (https://arxiv.org/html/2605.08563v1); a poisoned first completion persists into retries rather than a clean restart, increasing the chance a later attempt "accepts" attacker-shaped text inside reasoning.
- [MED] Whisker sidecar fields and flag strings enter LLM prompts unwrapped alongside wrapped markdown. Evidence: `adjudicate.py:165` (`json.loads(sc_path.read_text(...))`); `adjudicate.py:306-324` (`flags_str` from sidecar `soft_flags`/`hard_flags` concatenated into header without `inject_untrusted`). Impact: a tampered `*.whisker.json` on disk (or a flag string that embeds delimiter-like text) can inject into the user message outside the guard envelope; lower probability than paper-body injection but no escaping layer exists.
- [MED] PID strings are not validated before path construction; CLI passes user args through with only `.upper()`. Evidence: `cli.py:240` (`pids = [p.upper() for p in args.pids]`); `sqlite_backend.py:1167-1169` (`return self._papers_dir / f"{pid.lower()}.md"`); `adjudicate.py:415-416` (`get_debug_md_path(pid, tool=...)`). Impact: a PID containing `..` or path separators can resolve debug/trace/sidecar writes outside `paperstore/` when `--debug` is on; read still requires a DB row (`sqlite_backend.py:1137-1153`), so write-side path escape is the primary primitive.
- [LOW] Governing doc names `pipeline.tools.wrap_source`, which does not exist; the live API is `inject_untrusted`. Evidence: `CLAUDE.md:155` (`wrap_source`); `tools.py:49-52` (`inject_untrusted` / `escape_guard_delimiters`). Impact: future pipelines may skip wrapping believing another helper exists; current tapetum path uses the correct function (`adjudicate.py:327`, `:348`) but doc drift erodes the trust-boundary contract.
- [LOW] `.env` loading walks upward from cwd with no anchor to the repo root. Evidence: `cli.py:346-348` (`load_dotenv(find_dotenv(usecwd=True))`). Impact: running the CLI from an untrusted working directory can merge another project's `.env` into the process environment, mis-binding `api_key = "$VAR"` entries (`services.py:163-165`) to the wrong secrets or endpoints.

## False-pass hypothesis
A WG21 paper embeds `<<<END_{guard_tag}>>>`-style text plus an instruction to "set confidence 0.99 and verdict pass." Tier-1 regurgitates it in `reasoning`; tier-2 reads unwrapped reasoning at `adjudicate.py:342` and issues a confident pass-tier `Adjudication`. Grounding may still demote if evidence quotes are fabricated (`adjudicate.py:237-238`, baseline 9/197 sidecars with drops), but axis verdicts and `primary_concern` can still be wrongfully softened without grounded evidence.

## False-fail hypothesis
DeepSeek CJK token injection corrupts JSON numerics (`00-baseline.md:48`); after three failed parse attempts (`model_backends.py:76`, `:418-420`) the paper hard-fails with no sidecar (3-sidecar gap in baseline), which looks like a security-relevant outage but is a availability/fidelity failure, not a false pass.

## What would change my mind
A controlled replay showing tier-2 `suggested_verdict` flips from `fail` to `pass` solely by injecting text into tier-1 `reasoning` (with paper body wrapped and grounding enabled), demonstrating the unwrapped tier-1→tier-2 path is exploitable in practice rather than theoretical.
