# 03 - Determinism-Auditor

**Verdict:** usable-with-conditions (+ client-side serial execution, sampling pins, and sorted persistence are sound, but identical reruns on the shared `alliance-pod` vLLM server cannot guarantee identical advisory verdicts without server-side batch invariance and despite sporadic DeepSeek JSON corruption retries)
**Confidence:** high

## Findings
- [CRITICAL] Client sampling pins (`temperature=0.0`, `seed=0`, `top_p=1.0` at `model_backends.py:321-323`, `:344-346`) do not bound server-side nondeterminism on a continuously batched vLLM pod. vLLM documents that `temperature=0` and `seed` alone do not guarantee deterministic output under continuous batching; batch size and request order can flip token choices unless `VLLM_BATCH_INVARIANCE=1` is enabled (~50% throughput cost). Evidence: `05-web.md` Q4 Batch Invariance card, https://docs.vllm.ai/en/stable/features/batch_invariance/; baseline RQ1 open sub-question on shared-pod batch interference (`00-baseline.md:70`). Impact: two serial reruns of the same paper on `alliance-pod` can diverge in confidence, axis findings, and suggested verdict even with identical prompts and pins.
- [HIGH] DeepSeek-v4-pro sporadic CJK/garbage token injection into JSON bifurcates the completion path: a clean first attempt vs a malformation retry with accumulated assistant+user turns (`model_backends.py:76-85`, `:382-417`). Baseline confirms the artifact in production transcripts and 9/200 papers hitting corruption twice at the old 2-attempt budget (`00-baseline.md:48-49`). Evidence also in `05-web.md` Q2 (vLLM Issue #41985). Impact: identical inputs can yield different structured outputs depending on whether attempt 1 parses cleanly; retry context changes what the model sees on attempt 2+.
- [HIGH] RQ4 seed confirmed: per-step `**max-output:**` and `**thinking-budget:**` are parsed (`prompt.py:389-390`, authority doc `tapetum_llm.md:117-118`, `:138-139`) but `run_agent` never forwards them to `AgentBackend.run` (`runner.py:266-272`; `AgentBackend.run` docstring at `agents.py:128-133` promises runner forwarding). Tapetum constructs agents at flat `max_tokens=4096`, `thinking_budget=None` (`adjudicate.py:388-395`). Impact: thinking is effectively off for all steps (`VllmThinkingBackend` only sets `thinking_token_budget` when `thinking_budget is not None`, `model_backends.py:305-309`); triage runs at 4096 not 2048, changing truncation/retry probability vs the documented cascade. Stable mis-wiring, but it decouples observed behavior from the authority doc and from any future per-step tuning meant to stabilize outputs.
- [MED] Each pipeline run draws a fresh guard delimiter tag via `secrets.token_hex` (`tools.py:33-35`), injected into the framework floor system prompt (`runner.py:117`, `tools.py:55-62`, composed at `runner.py:205-216`). Impact: identical paper content reruns with different system-prompt floor text; intentional injection-defense tradeoff, but it violates strict prompt identity across reruns and can shift model behavior at the margin.
- [MED] The raw-JSON malformation retry appends the full prior assistant output plus an error-feedback user turn (`model_backends.py:409-416`), so success after retry is not equivalent to success on attempt 1. Truncation retries correctly re-issue the original messages with a grown budget (`model_backends.py:388-404`). Evidence on retry context contamination: `05-web.md` Q5 (arXiv 2605.08563, pydantic-ai Issue #4908). Impact: papers that intermittently corrupt once get a different effective prompt than papers that parse on first try; verdict distribution can split on corruption luck, not paper quality.
- [LOW] `flags_str` concatenates `soft_flags + hard_flags` without an explicit sort in the prompt builder (`adjudicate.py:306`, `:337`). Refuted as a run-to-run defect under the current whisker sidecar contract: `WhiskerResult.to_dict` persists both lists sorted (`score.py:111-112`), so JSON reload order is stable for a given sidecar. Impact: no current variance source, but the prompt path does not enforce D7 locally; a sidecar producer that stopped sorting would silently change LLM prompts.
- [LOW] RQ4 seeds `select_candidates` sorted (`adjudicate.py:94`), `TapetumResult.to_dict` sorted spans/axes (`models.py:116-119`), and `aggregate_adjudications` sorted axes (`chunking.py:184`): verified good. `services`/`agents` dict construction at `adjudicate.py:382-396` follows insertion order from `prompt.services` through `resolve_pipeline_models` (`services.py:495`); not a nondeterminism source across runs for a fixed authority doc.

## False-pass hypothesis
A paper with a short generic evidence quote (e.g. `"the following"`) that fuzzy-grounds via `rapidfuzz.partial_ratio >= 0.90` against the whole markdown (`grounding.py:24-56`, `constants.py:50`) could keep a model-assigned non-pass verdict through grounding and demote logic, masking a fabricated span; this is an RQ3 grounding issue adjacent to determinism, not an ordering bug.

## False-fail hypothesis
Intermittent CJK token injection on attempt 1 triggers a retry; attempt 2 succeeds with a harsher axis finding because the accumulated error-feedback context biases the model toward reporting the prior parse error as a conversion defect (`model_backends.py:409-416`), producing `review`/`fail` on the unlucky corruption path where the clean path would `pass`.

## What would change my mind
Two back-to-back serial reruns of the same 20-paper tapetum subset on an isolated vLLM instance with `VLLM_BATCH_INVARIANCE=1`, no other clients on the pod, and guided JSON enabled for DeepSeek-v4-pro, producing byte-identical `*.tapetum.json` sidecars (or documented semantic equivalence with zero retry-path splits in debug transcripts).
