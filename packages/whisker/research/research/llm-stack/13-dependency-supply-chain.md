# 13 - Dependency-Supply-Chain

**Verdict:** usable-with-conditions — `uv.lock` pins today's graph reproducibly, but manifest-level constraints on pydantic-ai/openai are absent and the full `pydantic-ai` meta-package inflates transitive surface; any lock refresh without a deliberate bump is a determinism roulette.
**Confidence:** high

## Findings
- [HIGH] **pydantic-ai is declared without any version floor in every LLM consumer package.** Evidence: `packages/agora/pyproject.toml:11`, `packages/assay/pyproject.toml:13`, `packages/cli/pyproject.toml:15`, `packages/whisker/pyproject.toml:28` all list bare `"pydantic-ai"`; only `uv.lock:2882-2883` pins `1.89.1`. Impact: `uv lock --upgrade-package pydantic-ai` or a lock regen on a fresh machine can silently adopt breaking API churn; the stack is deeply coupled via `Agent`, `UsageLimits`, `ModelSettings`, `OpenAIChatModel`, `OpenAIProvider` imports at `packages/pipeline/src/pipeline/model_backends.py:446-451`, `:466-480`, `:538-543`, `:573`, `:630-635`, `:668`, `:720-723`, `:746`.
- [HIGH] **The `pydantic-ai` meta-package resolves with all 19 optional extras, bloating the supply chain far beyond what we use.** Evidence: `uv.lock:2885-2886` shows `pydantic-ai` depending on `pydantic-ai-slim` with extras `ag-ui`, `anthropic`, `bedrock`, `cli`, `cohere`, `evals`, `fastmcp`, `google`, `groq`, `huggingface`, `logfire`, `mcp`, `mistral`, `openai`, `retries`, `spec`, `temporal`, `ui`, `vertexai`, `xai`; contrast `packages/pipeline/pyproject.toml:11` which declares only `pydantic-ai-slim`. Impact: unrelated SDKs (boto3/bedrock, temporalio, MCP stacks, etc.) enter the install graph and inherit their own churn; security/review surface scales with extras we never call.
- [HIGH] **Live upstream retry-history bloat (pydantic-ai #4908) intersects our D10 retry budget.** Evidence: `05-web.md:100-102` documents that after `ModelRetry`/validation failure the next request includes full accumulated history; our backends set `retries=3` on `Agent(...)` at `model_backends.py:470` (and parallel sites `:566`, `:661`, `:739`); D10 requires finite retry pairing at `CLAUDE.md:87`. Impact: a pydantic-ai upgrade that changes history retention can blow context windows mid-repair, perturb retry convergence, and break the semantic-stability bar without a compile-time signal.
- [MED] **openai SDK is unpinned in the manifest but on two independent call paths.** Evidence: `packages/pipeline/pyproject.toml:10` lists bare `"openai"`; lock resolves `openai==2.34.0` at `uv.lock:2357-2358`. `VllmThinkingBackend` calls `client.chat.completions.create` directly at `model_backends.py:318`, `:341`; pydantic-ai tool backends construct `AsyncOpenAI` + `OpenAIProvider` at `:454-456`. Impact: an openai 2.x minor that changes streaming chunk shape (`finish_reason` handling `:336-338`) or message schema can fail the raw-JSON path while pydantic-ai paths still work (or vice versa), splitting behavior across backends on one lock bump.
- [MED] **Past pydantic-ai API footgun (D9) documents silent constructor drops — same class of supply-chain risk.** Evidence: `CLAUDE.md:86` states `UsageLimits(...)` passed to `Agent(...)` is silently dropped; current code correctly passes to `agent.run(...)` at `model_backends.py:478-480`. Impact: pydantic-ai refactors that relocate or rename `usage_limits`/`UsageLimits` would fail open (no request cap) rather than fail loud; no manifest pin means CI won't catch it until runtime.
- [MED] **Core pipeline deps beyond LLM wrappers are also unpinned, including a heavy ML stack.** Evidence: `packages/pipeline/pyproject.toml:9-14` lists bare `httpx`, `openai`, `pydantic-ai-slim`, `sentence-transformers`, `trafilatura`; lock resolves `sentence-transformers==5.5.1` at `uv.lock:3845-3856` with transitive `torch`, `transformers`, `scikit-learn`. Impact: classifier backends (`packages/pipeline/src/pipeline/CLAUDE.md` classifier section) inherit torch/transformers semver churn on every lock refresh; unrelated to tapetum but shares the workspace venv the LLM lane runs in.
- [LOW] **rapidfuzz is the positive counterexample — upper-bound pinned where algorithm stability matters.** Evidence: `packages/whisker/pyproject.toml:17` declares `rapidfuzz>=3.14.5,<4`; lock at `rapidfuzz==3.14.5` (`uv.lock:3355`); consumed by tapetum grounding at `packages/whisker/src/whisker/tapetum_llm/grounding.py:17`, `:51` with floor `EVIDENCE_FUZZY_FLOOR = 0.90` at `constants.py:50`. Impact: shows the repo already knows how to cap churn-sensitive deps; pydantic-ai/openai lack the same discipline.
- [LOW] **python-dotenv for tapetum-llm is low-risk: floor-only, actively maintained.** Evidence: `packages/whisker/pyproject.toml:30` `python-dotenv>=1.0`; lock `python-dotenv==1.2.2` at `uv.lock:3257-3258`; loaded at `packages/whisker/src/whisker/tapetum_llm/cli.py:348`. Impact: not a supply-chain weak point relative to pydantic-ai; included for completeness per mandate.

## False-pass hypothesis
A pydantic-ai minor release changes ModelRetry history semantics (fixing or worsening #4908): the raw-JSON retry loop at `model_backends.py:311-313` exhausts its budget with bloated context, pydantic-ai accepts a schema-valid but semantically wrong `Adjudication`, and grounding at `grounding.py:49-52` still fuzzy-matches a generic quote — the lane emits `pass` where today's pinned stack would have retried or demoted to `review`.

## False-fail hypothesis
An unpinned `openai` bump alters streaming `finish_reason` delivery on the terminal chunk (`model_backends.py:336-338`), causing `_extract_json` to run on truncated content; the 3-attempt budget at `model_backends.py:76-85` exhausts with `"Raw JSON completion failed after N attempt(s)"` on papers that pass under `openai==2.34.0` (`uv.lock:2358`).

## What would change my mind
Manifest-level exact pins (or tight `~=` ranges) for `pydantic-ai`, `pydantic-ai-slim[openai]`, and `openai` in every declaring `pyproject.toml`, plus a CI check that fails when `uv lock` drift changes those versions without an explicit bump PR — demonstrating the supply chain is gated, not accidental.
