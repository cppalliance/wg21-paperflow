# 11 - False-Positive-Hunter

**Verdict:** usable-with-conditions — the lane catches real table/wording corruption on whisker-review papers, but 79% of its `review` outcomes are structure-axis heading cosmetics the prompt itself labels minor and shippable; there is no decide-step fold from that class to `pass`, so the 54% review rate is mostly self-inflicted noise, not miscalibrated demotion gates.
**Confidence:** high

## Findings

- [CRITICAL] **Structure-only minor heading reviews dominate the review bucket: 84 / 106 suggested `review` sidecars have exactly one non-pass axis (`structure`, `review`, `minor`) with no table/code/wording defect.** Evidence: reproduced parse of all 198 `data/whisker/*.tapetum.json` sidecars; sample PIDs N5034, N5035, N5037, N5043, N5045, P1000R7 (primary_concern explicitly says "cosmetic heading-level jump", confidence 0.95). The prompt instructs the model that heading-level jumps are "cosmetic: severity `minor`, verdict `review` at most, never `fail`" (`tapetum_llm.md:55`), and `worst_axis_verdict` correctly folds non-major structure fails to `review` (`chunking.py:34-51`, applied at `adjudicate.py:229-230`) — but there is no further fold from `structure/minor/review` to overall `pass`. Impact: a faithful conversion whose only defect is H2→H3 or H1→H3 nesting (common on N-papers and RESCUE population) still surfaces as `review`, inflating the 106/198 (53.5%) review rate with cases a human would ship.

- [HIGH] **The decide-step demotion stack is not what drives over-review; `CONFIDENCE_DECISION_FLOOR` never fired in production.** Evidence: `constants.py:28` (`CONFIDENCE_DECISION_FLOOR = 0.50`); demotion at `adjudicate.py:237-240` (ungrounded non-pass → `review`; sub-floor confidence → `review`); reproduced 0 / 198 sidecars with confidence < 0.50; review confidence min/median = 0.85 / 0.95, 105 / 106 reviews at ≥ 0.90. Impact: the 54% review rate is not caused by stacking demotion rules — the model confidently chooses `review` for cosmetic structure and Python faithfully propagates it via worst-axis fold. Raising or lowering the floor is irrelevant until self-reported confidence enters a meaningful range (see persona 21: 0 / 198 in `[0.35, 0.65]`).

- [HIGH] **Whisker pass-tier papers are rarely false-positived: only 3 / 74 tapetum `pass`-channel outcomes become `review`.** Evidence: reproduced cross-tab; P3440R3 and P3724R3 (structure/minor heading jump, whisker `pass`); P4211R0 (wording/minor mojibake in member names, whisker `pass`). Candidate selection (`adjudicate.py:82-84`, `_has_pass_risk_signals`) forwards pass-tier papers only when lossy tables, mojibake, or cov-unigram gap signals exist — so most pass-tier risk candidates still tapetum-pass. Impact: the lane's false-positive problem is concentrated in whisker-`review` and RESCUE populations (94 + 9 of 106 reviews), not in wholesale overruling whisker passes.

- [MED] **RESCUE works but still leaves heading-only fails at `review`, not `pass`.** Evidence: whisker `fail` → tapetum outcomes reproduced as 9 / 9 `review`, 0 `pass`, 0 `fail`; RESCUE selector at `adjudicate.py:90-92`, `_is_heading_only_fail` at `adjudicate.py:124-130`; prompt RESCUE case at `tapetum_llm.md:66-68` ("adjudicate `review` (likely shippable), not `fail`"). Sample N5035 (whisker `fail`, tapetum `review`, primary_concern: "Heading-level jump from H1 to H3 is cosmetic… all content faithfully preserved"). Impact: the lane prevents false-`fail` on heading quirk (good) but cannot signal "ship it" — every RESCUE paper still consumes human review budget.

- [MED] **Remaining 22 / 106 reviews carry substantive (non-heading-only) concerns; table reviews look real, not noise.** Evidence: 13 reviews worst on `tables` axis; samples P2583R0 (column association broken), P3978R2 (straw-poll columns missing), P3978R3 (poll questions embedded in header row), P3874R1 (merged header flattening) — all whisker `review`, severity `minor` or `major` with concrete table notes. Prompt table rules at `tapetum_llm.md:70-81` distinguish "faithful but lossy" (`review`) from "meaning unreconstructable" (`fail`). Impact: roughly 21% of reviews (22 / 106) are plausibly warranted human-look cases; conflating them with the 84 heading-only reviews makes the 54% headline rate misleading.

- [MED] **One N-paper false-`fail` shows the model still punishes document type despite the admin-doc prompt fix.** Evidence: N5044 sidecar — whisker `review`, tapetum `fail`, structure axis note: "The input is not a C++ standards proposal. It is a travel guide…" with severity `major`; contradicts `tapetum_llm.md:31` ("The document TYPE is never a defect… administrative document converted faithfully is a `pass`"). Impact: even post-fix, a single admin-doc misread becomes a hard advisory `fail`; if the 200-paper batch predates the fix, re-run needed; if post-fix, prompt compliance gap remains.

- [LOW] **Chunk worst-axis fold is structurally capable of dragging a huge paper to `review` from one minor axis in one chunk, but the batch barely exercises it.** Evidence: `aggregate_adjudications` takes max-severity finding per axis across chunks and min confidence (`chunking.py:154-187`, `_finding_rank` at `chunking.py:223-230`); 4 / 198 sidecars show `[aggregated over N chunks]` reasoning, 0 of those are `review`. Baseline notes ~6 corpus papers exceed `MAX_PAPER_MD_CHARS = 500_000` (`constants.py:44`). Impact: low current false-positive volume, but the aggregation rule guarantees one cosmetic structure hit anywhere in a multi-chunk paper becomes overall `review` — same gap as finding 1, amplified for oversize papers.

## False-pass hypothesis

A faithful conversion with an H2→H4 heading skip (whisker `heading_monotone` fail, RESCUE population) where the model correctly labels `structure: review, minor` at confidence 0.95, `worst_axis_verdict` yields overall `review`, and a human ships after five seconds because prose/tables/code are intact. The lane cannot emit `pass` for this population despite the prompt calling it "likely shippable" (`tapetum_llm.md:66-68`).

## False-fail hypothesis

N5044: an administrative N-paper travel/venue doc where tapetum `fail` on structure/`major` because "not a C++ proposal" — a faithful conversion wrongly flagged `fail` for document type, violating the N-paper rule at `tapetum_llm.md:31`. Re-run after the prompt fix should flip this; if it persists, it is a hard false-fail on admin content.

## What would change my mind

A labeled holdout (≥30 papers) where blind human adjudicators mark the 84 structure-only-minor `review` sidecars: if ≥80% are human-`pass` (shippable), add a decide-step fold (`structure` + `minor` + sole non-pass axis → overall `pass`) and re-measure review rate. If human pass rate is ≤50%, the 54% review rate is appropriate conservatism, not over-review noise, and my verdict flips to `usable`.
