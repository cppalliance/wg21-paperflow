# 04 - Exact-Span Alignment Specialist

**Verdict:** usable-with-conditions — the langextract monotonic exact-occurrence DP port in `grounding.py` is structurally faithful and adds a post-alignment guard langextract lacks, but the PDF lane still runs it one-sided on `pdf_text` only, duplicate quotes re-ground as interval-less fuzzy, and fuzzy tiers carry no `char_interval`, so two-document verification cannot yet prove candidate absence from alignment geometry alone.
**Confidence:** high

## Findings

- [CRITICAL] **Two-document verification is blocked at the call site, not the aligner.** `judge_pdf_extraction` calls `ground_spans(spans, pdf_text)` once (`pdf_judge.py:513-520`) and never invokes the same function on `tomd_md`; the sidecar hardcodes `"present in PDF text layer, absent from markdown"` for every survivor (`pdf_judge.py:401-404`). Baseline replay: **8/20** quotes genuinely absent, **12/20** already in candidate markdown (`00-baseline.md:14-24`). Impact: exact-span machinery cannot improve evidence precision until a symmetric candidate pass records independent `(start, end)` or `dropped` per haystack.

- [HIGH] **Monotonic exact DP matches langextract's `_select_monotonic_matches` line-for-line.** Whisker `_select_monotonic_matches` (`grounding.py:102-168`) mirrors langextract `resolver.py:1113-1185` (Pareto frontier, `best_ending_at_or_before`, token-weight maximization, earliest-ending tie-break). Oracle parity: `test_repeated_quote_maps_to_successive_occurrences` (`tests/test_tapetum_llm.py:1273-1288`) matches langextract `test_repeated_mention_aligns_to_successive_occurrences` (`resolver_test.py:2480-2490`). Impact: the source leg of a two-sided verifier can reuse this DP unchanged; repeated judge quotes map to successive non-overlapping PDF occurrences instead of first-hit collapse.

- [HIGH] **Post-alignment guard closes langextract exact-tier wrong-span acceptance.** Whisker rejects any DP selection whose raw slice fails `normalized_text(markdown[start:end]) == norm_quote` (`grounding.py:221-228`); langextract sets `char_interval` from tokenizer token bounds without this check (`resolver.py:1235-1241`). Impact: porting intervals to candidate-side `present_in_candidate` is safer in whisker than trusting langextract `MATCH_EXACT` alone; guard should run on both haystacks.

- [HIGH] **Duplicate quotes with a single source occurrence over-count evidence.** Langextract leaves the second extraction at the first `char_interval` with `MATCH_FUZZY` (`resolver_test.py:2564-2574`). Whisker runtime on `"Only aspirin appears here."` + two `"aspirin"` spans: `[('exact', 5, 12), ('fuzzy', None, None)]`, `dropped=0` — both quotes count as grounded, but only one has a locatable interval. Impact: a two-sided verifier aggregating grounded quote counts without `(quote, start)` dedupe will inflate source-support and miss that the second mention has no distinct provenance.

- [HIGH] **Out-of-order model quotes break monotonic chaining; fuzzy fallback is whole-document and interval-less.** Runtime: model order `["ibuprofen", "aspirin"]` on `"aspirin was given before ibuprofen..."` yields ibuprofen `fuzzy` (no interval), aspirin `exact` at `(0, 7)`. Langextract's `_align` still assigns both `MATCH_EXACT` with `char_interval` (`resolver_test.py:2576-2588`). Whisker per-span loop only exact-aligns indices in the DP selection dict (`grounding.py:216-228`); others fall through to normalized substring / global `partial_ratio` (`grounding.py:230-237`). Impact: source and candidate legs can disagree on which quotes are `exact` vs `fuzzy` when the LLM lists quotes out of document order; tri-state policy must not treat interval-less fuzzy as `verified_missing` on the candidate leg (`03-bidirectional-design.md:42`).

- [MED] **Overlapping token runs are correctly rejected by the DP; non-overlapping repeats are not.** Runtime on `"foo bar baz foo bar baz"` with quotes `"foo bar"` then `"bar baz"`: `[('exact', 0, 7), ('exact', 16, 23)]` — second quote maps to the second non-overlapping occurrence, not the overlapping `bar`-shared window at index 1. Langextract clinical-note test (`resolver_test.py:2492-2528`) expects the same successive-occurrence behavior for repeated entities. Impact: overlap/ordering bugs are not present in the exact tier; the risk is applying one-sided exact intervals to infer cross-document absence.

- [MED] **Char intervals are token-bounded, not byte-exact on punctuation, and fuzzy tiers emit `start=None`.** Exact intervals span `md_tokens[start_tok][1]` through `md_tokens[start_tok + n_tok - 1][2]` (`grounding.py:217-220`); `test_punctuation_differences_still_ground_exactly` accepts commas inside the slice (`tests/test_tapetum_llm.py:1310-1318`). Fuzzy survivors set `start=None, end=None` (`grounding.py:230-237`, `53-60`). Langextract maps intervals via `RegexTokenizer` `char_interval` (`resolver.py:1235-1240`). Impact: two-document provenance comparison needs paired `(source_start, candidate_start)` only for exact tier; fuzzy-only agreement cannot localize a miss to a page or block (`06-token-window.md:18`).

- [LOW] **`ground_page_quotes` omits monotonic DP entirely.** Page escalation grounds each quote independently with first-hit substring/fuzzy (`grounding.py:264-277`); no successive-occurrence constraint (also flagged in `27-determinism.md:14`). Langextract applies the same DP per chunk via `_apply_monotonic_exact_matches` (`resolver.py:1188-1243`). Impact: page-scoped two-sided checks should either call `ground_spans` on the page slice or inherit DP before comparing source page vs full candidate markdown (`03-bidirectional-design.md:40`).

## False-pass hypothesis

PR #285 class: five date-line quotes already present in candidate markdown (`00-baseline.md:17-18`). `ground_spans` grounds each in `pdf_text` with exact or fuzzy (`pdf_judge.py:519`); runtime shows the same quotes also ground in `tomd_md` (`two_doc: pdf 1 cand 1` on shared `"constexpr keyword"` substring). No candidate pass runs; sidecar labels all five absent (`pdf_judge.py:401-404`). Exact-span alignment on the source leg reproducibly certifies false missing-content.

## False-fail hypothesis

Model emits two identical `"The proposal is sound"` quotes but the PDF text layer contains only one dehyphenated occurrence while markdown has two (PR #290 duplicate-date class, `00-baseline.md:18`). Monotonic DP maps the first quote exact and the second to interval-less fuzzy (`duplicate: exact + fuzzy, dropped 0`). A naive two-sided rule treating fuzzy source + candidate `dropped` as `verified_missing` would false-fail the second quote even when both markdown occurrences are present; mitigation: require exact source interval AND candidate `dropped` before `verified_missing`, demote dual-fuzzy to `ambiguous`.

## What would change my mind

A whisker-local replay of the nine-PR quote set running `ground_spans(quotes, pdf_text)` and `ground_spans(quotes, tomd_md)` independently, emitting sorted per-quote records `{source_status, source_start, source_end, candidate_status, candidate_start, candidate_end, entailment}`, showing candidate-absence precision above **8/20** with zero duplicate-interval false counts (second single-occurrence quote demoted or deduped), would flip to **usable** for production two-sided exact alignment.
