# 16 - Reading-Order and Duplication Specialist

**Verdict:** usable-with-conditions — whisker already splits content recall from reading order at the metric layer, but the PDF-judge evidence path is one-sided anywhere-match on the source only; a two-sided verifier must distinguish page-local grounding, document-wide presence, and explicit `ambiguous` when duplicates or reordering explain the hit.
**Confidence:** high

## Findings

- [CRITICAL] **Missing candidate-side verification turns reorder-tolerant presence into false "absent" claims.** The nine-PR replay found candidate-absence precision 8/20 (40%): PR #285 0/5 genuinely absent, PR #290 0/5 (date lines already present, some twice) (`00-baseline.md:14-19`). `pdf_judge.py:513-520` grounds quotes with `ground_spans(spans, pdf_text)` only; `to_sidecar_dict()` labels every quote `"present in PDF text layer, absent from markdown"` without checking markdown (`pdf_judge.py:401-404`). Impact: the highest-volume false-evidence class is text that exists somewhere in the candidate after legitimate front-matter migration, reflow, or duplication — not reading-order loss.

- [CRITICAL] **Per-page recall screen uses document-wide anywhere-match, not page-local alignment.** `screen_pages()` computes `content_recall(tomd_md, dehyphenated_page)` (`pdf_judge.py:287-312`; `metrics.py:372-389`): reference tokens are the page, candidate is the full markdown, and recall is multiset presence anywhere with no position constraint. Impact: (a) **false pass** — page-13 tokens appearing under page-12's heading satisfy recall even when boundary placement is wrong (`19-false-pass-hunter.md:22-23`); (b) **false screen clear** — a whole-page hole can hide when other pages' tokens dominate the document average while a localized page still looks "recalled" if its vocabulary appears elsewhere (`19-false-pass-hunter.md:10-11`, p0957r8 class). Page-local shape is preserved in `clean_pages()` for token counting (`test_pdf_judge.py:287-290`) but never used to constrain where in markdown the match must land.

- [HIGH] **Moved text is intentionally non-gating on content axes; order is a separate advisory signal.** `content_recall` ignores extra/duplicated candidate tokens and is order-invariant (`metrics.py:372-381`; `CLAUDE.md` verdict model). `block_text_nid` Hungarian-matches blocks so paragraph reorder keeps `nid=1.0` while `reading_order` rises (`match.py:240-265`; `test_bench.py:140-146`). opendataloader-bench `evaluator_reading_order.py:22-40` scores full-document `fuzz.ratio` (order-sensitive NID) plus table-stripped NID-S — same split whisker already mirrors. Impact: absence verification must not use `content_recall` or `normalized_text` substring alone as the candidate oracle; reorder-only defects need `reading_order_ned`, shingle `coverage`, or olmOCR-style `order` facts (`19-false-pass-hunter.md:8`).

- [HIGH] **Duplicated TOCs and repeated boilerplate break naive presence/absence symmetry.** Deterministic `no_toc_leak` catches standalone `Contents` labels and page-numbered heading pairs (`gates.py:132-185`; PR #290/#293). That gate does not stop the LLM from quoting TOC lines or migrated header dates as "missing" when one copy lives in YAML front matter and another in body — PR #290's date lines were present twice (`00-baseline.md:18`). `content_recall` and anywhere substring search **reward** duplication (`metrics.py:380-381`; `19-false-pass-hunter.md:14-15`). olmOCR `BaselineTest` penalizes repeated n-grams (`19-false-pass-hunter.md:14`; `facts.py:651+` `auto_baseline_checks` exists but is not wired). Impact: candidate verify needs duplicate-aware semantics: second copy satisfies `present`; extra copies should route to `ambiguous`, not `absent`.

- [HIGH] **Source grounding is split across two scopes; candidate check must mirror both.** `ground_spans()` searches the whole document with monotonic DP so repeated quotes map to successive occurrences (`grounding.py:171-241`) — correct for markdown-side grounding, wrong scope for page-attributed PDF quotes. `ground_page_quotes()` restricts to one page's normalized text with length-relative fuzzy threshold (`grounding.py:244-278`; `constants.py:176-181`). Page escalations ground source quotes page-locally (`pdf_judge.py:572-574`) but still never test markdown absence. Impact: portable pattern from `05-web.md` olmOCR `TextPresenceTest`: same machinery for `PRESENT` and `ABSENT`, plus optional `first_n`/`last_n` positional windows (`05-web.md:14-18`; `19-false-pass-hunter.md:16`) — page-local for page-attributed evidence, document-wide for unattributed quotes.

- [MED] **opendataloader-bench confirms structural order metrics do not solve quote-level absence.** Local clone `evaluator_reading_order.py` implements document-level NID/NID-S only; `evaluator.py:107-113` averages `{nid, teds, mhs}` with null-eligibility — no page boundaries, no duplicate penalty, no quote verification (`repo-scan/opendataloader-bench-tmp.md:19-46`). Impact: validates whisker's axis separation (`bench.py` reports `reading_order` advisory-only) but offers no candidate-absence primitive; OmniDocBench block-window rescue in `match.py:_sub_gt_fuzzy_matching` is the right tool for `ambiguous` reformats, not for binary absence (`05-web.md:88-94`).

- [MED] **GROBID evaluates field slots, not reading order or cross-page duplication.** `EndToEndEvaluation.java:1121-1144` applies length-relative Levenshtein `(max_len - dist) / max_len >= 0.8` after `basicNormalization` (`:2090-2096`) per XPath field — order across fields is not scored; instance-level "all fields correct" is the strictest unit (`repo-scan/grobid.md:15-17`). Segmentation zones (`17-grobid-unstructured-analyst.md:8`) are prior art for scoping checks to header/body/reference blocks, not for page-local markdown alignment. Impact: adopt GROBID's tiered normalization + relative edit threshold as a secondary candidate match band; do not expect TEI field eval to detect WG21-style paragraph reorder or duplicated TOC furniture.

- [LOW] **Fuzzy candidate tiers must stay length-gated to avoid document-wide false presence on short phrases.** `ground_spans` fuzzy tier requires `EVIDENCE_MIN_FUZZY_CHARS` against the whole markdown (`grounding.py:186-189`). A date line or document number normalized to a short alnum string can `partial_ratio`-match unrelated regions — the inverse of PR #290 false absence (present but missed) and a risk for false `present` if candidate check copies the flat ratio without olmOCR's length guard (`05-web.md:18`). Impact: candidate-side check should prefer exact → normalized substring → length-relative fuzzy, matching page-quote grounding semantics.

## False-pass hypothesis

Converter moves section B before section A (pages 4–6 swapped in markdown). Every page's vocabulary appears somewhere in the 25k-token candidate. Per-page screen: each page `content_recall >= 0.90` because tokens are anywhere in `tomd_md`. Monolith judge returns `pass`; no candidate-side absence check runs. Deterministic sidecar shows `unigram_coverage=0.98`, `coverage=0.52` — order scramble visible only on advisory shingle axis (`19-false-pass-hunter.md:26-27`). Evidence sidecar stays empty of useful quotes while document ships.

## False-fail hypothesis

WG21 paper with `date: 2024-01-15` in YAML and the same date line repeated in the cover block body (intentional duplicate). LLM quotes the body date as "missing from markdown." Source `ground_spans` finds it in PDF text layer; without candidate `ground_spans(spans, tomd_md)`, the quote is retained as absent (`00-baseline.md:28-38`). Exact normalized substring would find at least one copy; a page-local check scoped to page 1 only might miss the YAML copy and falsely confirm absence unless front-matter migration is a sanctioned `present` path (`CLAUDE.md` conversion contract).

## What would change my mind

Replaying PR #290's five date-line quotes through a prototype two-sided verifier — `ground_spans(quote, pdf_text)` AND `ground_spans(quote, tomd_md)` with outcomes recorded as `present | absent | ambiguous` — showing all five classify `present` (or `ambiguous` on duplicate) without suppressing PR #293's five genuine `constexpr` misses. That ablation would downgrade the duplicate/reorder findings from blocking to advisory-only tuning.
