# 06 - Token-Window Retrieval Designer

**Verdict:** usable-with-conditions — global `partial_ratio` over the whole candidate document is the wrong retrieval primitive for bidirectional evidence; whisker already ships a localized token-window path in `facts.py` and a page-scoped olmOCR variant in `ground_page_quotes`, and marker/OmniDocBench block-window rescue belongs only on the `ambiguous` branch, not as the default locate.
**Confidence:** high

## Findings

- [CRITICAL] **Global `partial_ratio` cannot decide candidate absence and directly explains the 40% evidence-precision miss.** `ground_spans` tier 3 scores `partial_ratio(norm_quote, norm_md)` against the entire normalized markdown (`grounding.py:206-237`, `constants.py:67-73`); `pdf_judge.py` uses this only for source-side PDF presence (`00-baseline.md:28-38`), so a quote grounded in the PDF text layer says nothing about markdown absence. Replayed PRs: 8/20 quotes were already present in candidate markdown while labeled absent (`00-baseline.md:14-24`). Impact: any two-sided verifier must replace document-level fuzzy with localized window retrieval on the candidate; keeping tier 3 global for absence would preserve the false-missing class.

- [HIGH] **The simplest reusable locate primitive already exists: `facts.py:_best_match` (exact → `partial_ratio_alignment` window → bounded substring DP).** Pipeline: `haystack.find(needle)` (`facts.py:309-311`), else `fuzz.partial_ratio_alignment` yields `(dest_start, dest_end)` (`facts.py:314-318`), widen by `max_diffs`, verify with free-start/free-end `_substring_edit_distance` (`facts.py:276-296`, `319-320`). Same pattern as olmOCR `TextPresenceTest` (`05-web.md:12-18`, `research/per-page-judging/10-olmocr-bench-analyst.md:10-12`) and LitRAG locate-before-judge (`05-web.md:55-61`). Impact: candidate-side verification should be a thin wrapper around `_best_match` (or a moved shared helper), not a new algorithm.

- [HIGH] **Page-scoped retrieval is already proven superior to document-global fuzzy for quotes.** `ground_page_quotes` restricts haystack to one page's normalized text and uses length-relative threshold `1.0 - PAGE_QUOTE_MAX_DIFFS / len(quote)` instead of flat `EVIDENCE_FUZZY_FLOOR` (`grounding.py:261-274`, `constants.py:176-181`). Document-global fuzzy accepts short WG21 boilerplate at ≥0.90 (`research/llm-stack/22-grounding-robustness-auditor.md:7-8`, `grounding.py:232-236`). Impact: default candidate locate should be page- or block-bounded before document-wide fallback; global partial_ratio is a last-resort abstention path, not the primary gate.

- [HIGH] **Marker `HeuristicScorer` is per-block `partial_ratio_alignment`, not global ratio — and returns localization.** For each GT block, `find_fuzzy_alignments` calls `fuzz.partial_ratio_alignment(substr, main_string, score_cutoff=70)` and records `dest_start`/`dest_end` plus score (`packages/whisker/research/repos/marker-v1.10.2/benchmarks/overall/scorers/heuristic.py:77-99`); corpus score is length-weighted block mean ×0.8 + Kendall-τ order ×0.2 (`heuristic.py:35-42`). Portable detail from `05-web.md:20-27`: deterministic pairing first, fuzzy-align GT units into candidate. Impact: treat each LLM "missing" quote as a pseudo-GT block; align into candidate markdown with the same alignment API, then verify with substring DP — yields both verdict and char window for provenance.

- [MED] **Block split/merge rescue is a second-stage `ambiguous` resolver, not the default locate.** Whisker `match.py` ports OmniDocBench Hungarian block match plus `_sub_gt_fuzzy_matching` sliding-window rescue for embedded GT (`match.py:119-138`, `186-209`, thresholds `constants.py:136-137`); adjacency-merge for split paragraphs is explicitly not ported (`match.py:24-28`). Marker aligns blocks independently with no merge step (`heuristic.py:77-99`). Web synthesis: block-window rescue only for `ambiguous` quote matches (`05-web.md:88-94`). Impact: when `_best_match` fails on full candidate but source presence passes, run quote against `split_paragraph_blocks(candidate)` windows (and optionally `_sub_gt_fuzzy_matching` per block) before declaring `absent`; avoids whole-doc false-pass without paying O(doc²) on every quote.

- [MED] **Exact monotonic token DP gives localization; fuzzy tiers do not — and that gap matters for provenance.** `ground_spans` exact tier returns `(start, end)` char intervals via `_select_monotonic_matches` + post-alignment guard (`grounding.py:171-228`); fuzzy substring/ratio tiers emit `GroundedSpan` with `start=None` (`grounding.py:230-237`, `53-60`). `normalized_text` collapses `^`, `_`, `|`, `$` (`metrics.py:115-126`), so localized fuzzy windows on normalized surfaces cannot distinguish math/table corruption (`22-grounding-robustness-auditor.md:8-9`). Impact: candidate locate should return `present_exact | present_fuzzy | absent | ambiguous` with char interval when exact or alignment-backed; demote interval-less fuzzy hits per CRAG ambiguous band (`05-web.md:152-159`).

- [LOW] **Performance: windowed locate is cheap; block rescue is bounded.** Whole-document `partial_ratio` is ~37 ms at 80k chars / 3 spans, ~269 ms at 500k (`research/llm-stack/06-performance-scalability.md:19`); `_sub_gt_fuzzy_matching` is O(pred_len × gt_len) capped by `BLOCK_FUZZY_MAX_PRED_LEN` (`match.py:131-137`, `constants.py:148-151`). Impact: token-window retrieval adds negligible cost vs LLM judge; rescue runs only on ambiguous quotes, keeping the hot path to one alignment + small DP.

## False-pass hypothesis

PDF judge quotes `"constexpr int x = 0;"` as missing-content; source `ground_spans` grounds it in the PDF text layer (`00-baseline.md:28-32`). Candidate markdown contains the same line inside a longer paragraph after dehyphenation. Document-level `partial_ratio(norm_quote, norm_md) >= 0.90` (`grounding.py:232-236`) passes without a char interval; sidecar label `"absent from markdown"` (`00-baseline.md:37-38`) ships a false missing claim — the PR #285 class (0/5 genuinely absent, `00-baseline.md:17-18`).

## False-fail hypothesis

Faithful markdown reformats a date line across a line break (`"2024-01-15"` → `"2024-\n01-15"`). Exact normalized substring fails; `_best_match` with `max_diffs=0` returns -1 (`facts.py:312-313`). Without olmOCR length-relative slack (`threshold = 1.0 - max_diffs/len`, `grounding.py:272-273`) or block-window rescue (`match.py:119-138`), a two-sided verifier marks `absent` though content is present — the legitimate-reformat class the baseline architecture must tolerate (`00-baseline.md:7-8`, `61-68`).

## What would change my mind

A labeled replay of the nine-PR quote set showing that the proposed stack — `_best_match` on candidate (page-bounded first, block-rescue on ambiguity) with olmOCR thresholds, emitting `present|absent|ambiguous` per quote — recovers candidate-absence precision above 0.85 while false-failing fewer than 1/20 genuinely absent quotes (PR #293 `constexpr` class, `00-baseline.md:19`), without reintroducing document-global `partial_ratio` as the primary candidate decision.
