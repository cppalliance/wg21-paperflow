# 20 - Retrieval-Augmented Verification Analyst

**Verdict:** usable-with-conditions — quote-level absence does not need BM25 or a chunk index; whisker already ships retrieval-augmented locate primitives (`facts._best_match`, `ground_spans` exact tier, `ground_page_quotes`, optional H2-chunk enumeration) but the PDF lane never runs them on the candidate before labeling absent.
**Confidence:** high

## Findings

- [CRITICAL] **The PDF lane skips the retrieval step entirely: source locate runs, candidate retrieve-and-verify does not.** Evidence: `pdf_judge.py:513-520` builds `EvidenceSpan`s and calls `ground_spans(spans, pdf_text)` (source haystack only); `pdf_judge.py:401-404` labels every retained quote `"present in PDF text layer, absent from markdown"` with no second haystack. Baseline replay: 12/20 quotes already present in candidate markdown, evidence precision 8/20 = 40% (`00-baseline.md:14-24`). Impact: "retrieval-augmented verification" for this bug is wiring an existing locate pass on `tomd_md`, not inventing RAG infrastructure.

- [HIGH] **Token-window candidate search already exists and is the correct retrieval primitive for short quotes.** Evidence: `facts.py:299-321` — `_best_match` does exact substring, then `fuzz.partial_ratio_alignment` to retrieve a `(dest_start, dest_end)` window, widens by `max_diffs`, confirms with free-start/free-end `_substring_edit_distance` (`facts.py:276-296`); olmOCR `TextPresenceTest` uses the same length-relative `partial_ratio` budget on the candidate only (`packages/whisker/research/repos/olmocr/olmocr/bench/tests.py:167-182`). LitRAG and Ragas patterns in `05-web.md:55-68` match this locate-before-judge shape. Impact: candidate-side verification should call `_present_within` (or a shared helper extracted from `facts.py`), not build a separate retriever.

- [HIGH] **BM25 / dense chunk retrieval is not implemented in whisker and is not justified for v1 quote verification.** Evidence: no BM25 in `packages/whisker/src` (`22-ir-metrics.md:22-23`); web survey concludes olmOCR-style deterministic locate from existing `ground_spans`, `ground_page_quotes`, `rapidfuzz` (`05-web.md:192-194`); MDKeyChunker BM25 Recall@5 gains (`05-web.md:135-139`, HiChunk hierarchical chunking) target LLM *passage* retrieval for QA, not 20–200 char verbatim quote locate. Repo-local BM25 exists only in `cpp-mcp` FTS5 section search (`packages/cpp-mcp/src/cpp_mcp/sqlite_backend.py:635-644`), unrelated to paper conversion. Impact: adding BM25 indexes, tokenizers, and rank cutoffs would duplicate `_best_match` on WG21 quote lengths without addressing the 60% false-absence rate caused by missing candidate pass.

- [HIGH] **H2 chunk enumeration is sufficient when whole-document haystack is too large or ambiguous; it is already in production for LLM triage, not yet for quote locate.** Evidence: `chunking.py:129-164` splits on H2 boundaries up to `MAX_PAPER_MD_CHARS` (500_000, `constants.py:54-61`); `adjudicate.py:215-229` triages chunks serially. Retrieval-augmented verify pattern: for each quote, run `_best_match(q, chunk)` across chunks (union: present if any chunk hits), only then fall back to block rescue (`match.py:74-80` `split_paragraph_blocks`, `119-138` fuzzy rescue). ~6 corpus papers exceed the budget (`constants.py:59-60`). Impact: chunk retrieval is a bounded loop over existing splits, not a new dependency; use only when monolith `_best_match` returns `-1` or lands in the ambiguous band (`06-token-window.md:16-17`).

- [MED] **Local converter clones provide no portable retrieval-verification stack.** Evidence: `pdf-to-markdown` (Mozilla pdf.js pipeline) — `rg` over `src/` finds only conversion-time headline/TOC matchers (`HeadlineFinder.jsx:14-31`, `DetectTOC.jsx:276-277` fuzzy word match ≥0.5), no post-hoc quote locate or BM25. `mdream` (HTML→Markdown) — `bench/README.md` measures conversion latency only; no evidence-alignment or absence tests in `crates/` or `bench/`. Impact: neither local clone offers a pattern to adopt beyond "convert only"; whisker must stay self-contained per `00-baseline.md:90-91`.

- [MED] **Whisker block matching (`match.py`) is retrieval at paragraph granularity, suitable as ambiguous rescue only.** Evidence: OmniDocBench port — Hungarian assignment on normalized blocks, accept NED ≤0.70, `_sub_gt_fuzzy_matching` sliding-window rescue for embedded GT (`match.py:8-28`, `119-138`); Marker `HeuristicScorer.find_fuzzy_alignments` uses per-block `partial_ratio_alignment` with `dest_start`/`dest_end` (`packages/whisker/research/repos/marker-v1.10.2/benchmarks/overall/scorers/heuristic.py:77-99`). Web synthesis: block-window rescue for `ambiguous` only (`05-web.md:88-94`). Impact: treat each missing-content quote as a pseudo-GT block, align into candidate markdown, then DP-verify; do not run full `match_blocks` on every quote (O(gt×pred) matrix, `match.py:24-28` shortcut documents missing adjacency-merge).

- [MED] **Page-scoped retrieval outperforms document-global fuzzy and should bound quote search when page attribution exists.** Evidence: `ground_page_quotes` restricts haystack to one page with length-relative threshold `1.0 - PAGE_QUOTE_MAX_DIFFS / len(quote)` (`grounding.py:244-278`, `constants.py:176-181`); `screen_pages` + page escalation supply page numbers (`pdf_judge.py:489-592`). olmOCR zone-scoped `first_n`/`last_n` on presence (`tests.py:139-165`, `research/llm-readability/repo-scan/olmocr.md:46-48`). Impact: candidate retrieve order should be (1) page-bounded markdown slice if `[pN]` or screen page known, (2) H2 chunk union, (3) full document `_best_match` as last resort — never primary whole-doc `partial_ratio` (`grounding.py:232-237`, `05-fuzzy-thresholds.md:8-9`).

- [LOW] **Global `partial_ratio` in `ground_spans` tier 3 is retrieval without localization and must not drive candidate absence.** Evidence: `grounding.py:232-237` compares quote to entire normalized haystack; `EVIDENCE_MIN_FUZZY_CHARS=20` gates ratio only (`constants.py:69-73`); fuzzy tiers emit no char interval (`grounding.py:230-237`, `53-60`). Impact: acceptable as source-side last resort for long quotes; for candidate refute, alignment-backed window + DP is mandatory (`06-token-window.md:8-10`).

## False-pass hypothesis

PR #285 class: judge quotes body prose already in markdown. Source `ground_spans` retrieves the quote in `pdf_text` (`pdf_judge.py:519-520`). Without candidate retrieval, sidecar ships `"absent from markdown"` (`00-baseline.md:17-18`). Running `_best_match` on `tomd_md` would retrieve the window and refute the absence claim — the fix is plumbing, not new retrieval technology.

## False-fail hypothesis

PR #293 `constexpr` class: five declarations genuinely absent (`00-baseline.md:19`). If retrieval uses whole-document `partial_ratio >= 0.90` without DP confirmation, scattered token overlap in a long WG21 paper could retrieve a wrong window and false-refute. Window-local `_substring_edit_distance` with strict `max_diffs=0` for short quotes and ambiguous band for near-misses prevents this (`05-fuzzy-thresholds.md:40-43`, `facts.py:312-320`).

## What would change my mind

A labeled nine-PR replay showing that monolith `_best_match` + optional H2-chunk union fails to retrieve present quotes that BM25-over-structural-chunks (MDKeyChunker-style, `05-web.md:135-139`) finds at ≥0.90 precision with ≤1 false refute on PR #293 absent quotes — OR runtime proof that `_best_match` exceeds 500 ms p95 on the largest corpus paper, forcing a ranked chunk pre-filter before window DP.
