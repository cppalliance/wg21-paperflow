# 21 - NLI and Entailment Analyst

**Verdict:** usable-with-conditions — NLI can resolve a narrow `ambiguous` semantic-equivalence band, but it is the wrong first instrument for whisker's 40% evidence-precision failure and should be deferred until a two-sided deterministic verifier exists and a labeled holdout proves a persistent ambiguous residue.
**Confidence:** high

## Findings

- [CRITICAL] **The live failure is one-sided verification, not ambiguous entailment.** The nine-PR replay found candidate-absence precision **8/20 = 40%** because quotes are grounded against the PDF text layer only (`pdf_judge.py:513-520`; `grounding.py:171-241`), while the sidecar still labels every retained quote `"present in PDF text layer, absent from markdown"` (`pdf_judge.py:401-404`). Twelve of twenty false positives were already present in Markdown via substring or normalized match — a missing candidate-side `ground_spans` pass, not a semantic-equivalence gray zone. Impact: adding NLI before bidirectional deterministic locate would not fix the dominant error mode and would add cost/complexity on the wrong layer.

- [HIGH] **RefChecker's NLI checker solves a different task than quote equivalence.** Amazon RefChecker decomposes LLM output into claim-triplets, then runs `NLIChecker` with `ynie/roberta-large-snli_mnli_fever_anli_R1_R2_R3-nli`: premise = reference segment, hypothesis = claim, **512-token truncation**, **argmax** over `{Entailment, Neutral, Contradiction}` (`refchecker/checker/nli_checker.py`, fetched 2026-07-16). Long references are split into segments (default 200 tokens in `checker_base.py`) and merged with "any Entailment wins." That pipeline checks whether a *generated claim* is supported by a *reference passage* in RAG/summarization settings — not whether a PDF quote is absent from converted Markdown after dehyphenation, markup, or reorder. Impact: porting RefChecker's pattern would require re-framing whisker quotes as hypotheses and candidate windows as premises, plus bidirectional scoring RefChecker does not implement.

- [HIGH] **verifiable-rag / HHEM patterns confirm heavy dependency and calibration burden.** `verifiable-rag` (firish/rag-rack) ships `DualNLIVerifier` (HHEM-2.1-open ~600M + MiniCheck-Flan-T5-Large ~770M, ~1.4 GB lazy download) behind `pip install verifiable-rag[hhem,minicheck]` which pulls **torch + transformers**. Production threshold is **not portable**: blog reports train-fit `threshold=0.0562` on RAGTruth (46% hallucination base rate), while HHEM's own README defaults to **0.5** for binary consistent/hallucinated (`vectara/hallucination_evaluation_model`, hhem-1.0-open). Per-task AUROC varies widely (HHEM QA 0.874 vs Data2txt 0.566 on RAGTruth; `blog/03_verified_rag.md`). Impact: whisker has no WG21 quote-labeled holdout (`00-baseline.md:74-72` proposes olmOCR-bench schema but none exists locally); adopting HHEM would require GPU inference, domain refit, and dual-model ops — contradicting `00-baseline.md:92` ("no new dependency without demonstrated need").

- [HIGH] **Whisker constraints fence NLI out of the gate path.** Core invariants: deterministic gate (`CLAUDE.md`: tapetum "never gates"), library returns data with no network in `grounding.py`, named constants not vibes (`constants.py:63-73`), model sovereignty for analytical pipelines. NLI fits only as an optional advisory resolver on the `ambiguous` routing state (`05-web.md:187-188`), same tier as tapetum_llm — never `whisker --gate`, never CI-hard. A torch/transformers cross-encoder also conflicts with whisker core's deliberate thin deps (stdlib + rapidfuzz + apted). Impact: even a "small" NLI add is a new heavyweight optional extra (`tapetum-llm`-class), not a stdlib extension.

- [MED] **NLI is plausibly useful only after deterministic tiers exhaust.** The recurring production pattern in `05-web.md:182-190` is: (1) source locate, (2) candidate locate, (3) `present | absent | ambiguous`, (4) optional LLM/NLI for ambiguous only. Whisker already has tiers 1 (exact monotonic DP, fuzzy substring, partial_ratio; `grounding.py:179-237`) and olmOCR-style length-relative page quotes (`grounding.py:244-277`). Markdown-aware normalization (dehyphenation, markup strip, front-matter migration) should be deterministic extensions of tier 2 — the olmOCR `TextPresenceTest` bidirectional pattern (`05-web.md:14-18`; `substring-anchors.md:116-118`) is the direct port. NLI's value proposition is disambiguating cases where normalized+fuzzy returns `ambiguous` (e.g., paraphrased date lines, pipe-table vs prose restatement) — a secondary resolver, not the absence oracle.

- [MED] **Absence detection literature argues against NLI-first.** AbsenceBench (`05-web.md:37-43`) shows strong models systematically fail surface-form absence even with both documents in context. RefChecker's own paper notes NLI checkers "require extra techniques to handle lengthy context and lag behind GPT-4 checker in accurate/noisy-context settings" (Amazon Science blog, 2024). FActScore / CRAG patterns (`05-web.md:153-168`) require **dual independent signals** (retrieve + judge + abstain), not a single entailment score. Impact: for "quote absent from markdown," deterministic candidate miss should demote the quote; NLI should not overrule a candidate locate hit (LitRAG pattern, `05-web.md:59-61`).

- [LOW] **HHEM v2 improvements do not change the defer calculus.** HHEM-2.1-open removes the 512-token cap (HHEM-1.0 was capped; Vectara blog 2024) and reports calibrated probabilities — better for long WG21 passages. But training distribution remains summarization/RAG faithfulness, not PDF-to-Markdown conversion equivalence. Without a conversion-specific labeled set, better AUROC on RAGTruth does not transfer to whisker's quote-evidence task.

## False-pass hypothesis

PDF quote `"January 15, 2024"` is present in Markdown as YAML `date: 2024-01-15` after front-matter migration. Deterministic normalized substring misses (different tokenization). HHEM scores premise=(markdown front matter) hypothesis=(PDF quote) as **Neutral** (~0.3–0.5 range on date-format mismatches in NLI benchmarks). Whisker retains the quote as "missing" or routes to NLI-abstain without demoting the LLM verdict — human still chases a false absence. A deterministic date/ISO normalization tier would pass; raw NLI would not reliably entail.

## False-fail hypothesis

PDF quote spans a three-item bullet list in reading order; Markdown contains the same three items under an H2 with `-` bullets but in reversed order after column reflow. Candidate `ground_spans` fuzzy tier returns `ambiguous` (high partial_ratio, no exact interval). HHEM premise=(full markdown section) hypothesis=(PDF quote) scores **Contradiction** or low consistent because order and list markers differ, even though `unigram_coverage` is ~1.0 and no content is actually absent. NLI-as-resolver would false-fail a legitimate reformat that olmOCR-style bidirectional presence with reorder tolerance should mark `present`.

## What would change my mind

A labeled replay holdout (≥50 quotes from the four false-positive papers in `00-baseline.md:16-19` plus ≥20 genuine absences), where a two-sided deterministic verifier (`source present AND candidate absent|present|ambiguous`) leaves **>15%** of quotes in `ambiguous` after Markdown-aware normalization, AND a whisker-local evaluation shows dual-NLI (HHEM + MiniCheck, min aggregation, threshold fit on train) correctly resolves **≥80%** of that ambiguous band against human labels without increasing false-absence rate above the deterministic baseline. Until that residue is measured, NLI is speculative overhead.

## Recommendation: defer

| Dimension | Assessment |
|-----------|------------|
| **Useful for ambiguous quote equivalence?** | Conditionally yes — only as tier-4 resolver on `ambiguous`, never as absence oracle or source-grounding substitute. |
| **Threshold burden** | High. No universal default (0.5 HHEM vs 0.0562 verifiable-rag RAGTruth). Requires WG21-specific calibration; argmax RefChecker has no calibrated threshold at all. |
| **Data burden** | High. Need quote-level `present/absent/ambiguous` labels on conversion pairs; olmOCR-bench schema is the template (`05-web.md:124-129`) but no local holdout exists. |
| **Dependency burden** | High. torch + transformers + ~1.4 GB models; GPU inference; non-deterministic on some backends — acceptable only in advisory `tapetum-llm` extra, not core. |
| **Defer?** | **Yes, for the first fix.** Ship olmOCR-style candidate-side `ground_spans` + explicit tri-state + provenance reason codes (`05-web.md:192-194`). Revisit NLI only if ambiguous-band rate on the replay holdout justifies an optional `tapetum-nli` extra. |

**Model boundary:** This deferral would be revised if (a) deterministic two-sided matching is implemented and ambiguous residue stays above 15% on the labeled holdout, or (b) a stdlib-only entailment proxy (e.g., bidirectional token-window coverage without neural NLI) matches dual-NLI accuracy on that holdout — making the neural dependency unnecessary.
