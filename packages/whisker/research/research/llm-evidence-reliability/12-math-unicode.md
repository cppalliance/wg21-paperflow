# 12 - Math and Unicode Specialist

**Verdict:** usable-with-conditions — whisker already owns the right math surface for Lane 3 (`_math_surface` in `facts.py`) and LaTeX folding for metrics (`textblock2unicode`), but the tapetum evidence path (`ground_spans`, `pdf_judge`) uses `normalized_text`, which strips `^`/`_`/`=` and never checks the candidate; math/Unicode quotes must route to `ambiguous` and abstain from exact absence, not force binary missing.
**Confidence:** high

## Findings

- [CRITICAL] **Candidate-side absence is unverified; PDF-side grounding alone cannot prove "missing from markdown" for math or symbols.** Evidence: `pdf_judge.py:513-520` grounds quotes only against `pdf_text`; sidecar labels every retained quote `"present in PDF text layer, absent from markdown"` without a candidate locate (`pdf_judge.py:401-404`; `00-baseline.md:28-44`). Impact: PDF text layer may emit `α`, `≥`, or `fi` ligatures while markdown holds `$\\alpha$`, `\\geq`, or `fi`; source-presence succeeds, candidate-presence is never tested, and the LLM's absence claim is promoted as fact — the dominant false-absence class in the nine-PR replay (12/20 quotes present on candidate, `00-baseline.md:16-24`).

- [CRITICAL] **`ground_spans` exact/fuzzy tiers use `normalized_text`, which erases math structure before compare.** Evidence: `normalized_text` = `clean_string(textblock2unicode(text))` keeps only alnum + CJK (`metrics.py:115-126`, `338-340`); `ground_spans` normalizes both quote and markdown through it for substring and `partial_ratio` tiers (`grounding.py:206-237`). Impact: quotes like `x^{2k} \\geq 0` and `x2kgeq0` collapse to the same alnum skeleton; exponent/operator defects become unassertable on the evidence path even though Lane 3 `math` facts deliberately preserve `^`/`_`/`=` via `_math_surface` (`facts.py:238-255`, `test_facts.py:84-86`). Exact matching on this surface must abstain for any quote containing LaTeX delimiters, superscript/subscript markers, or Unicode math blocks.

- [HIGH] **No Unicode normalization (NFC/NFD) on grounding tokens; olmOCR and langextract both treat this as a first-class failure mode.** Evidence: `_TOKEN_RE = re.compile(r"\w+", re.UNICODE)` lowercases raw code units with no `unicodedata.normalize` (`grounding.py:49-67`); olmOCR runs NFC before every presence/absence check (`05-web.md:14-18`, `tests.py:47-80` cited in `research/redteam/olmocr.md:27`); langextract NFD `"e\u0301"` vs NFC `"é"` fails all tiers (`research/langextract/12-false-negative-hunter.md:10`). Impact: PDF extraction often yields decomposed accents or compatibility glyphs; markdown may store composed forms — exact token DP misses, fuzzy substring may also miss if `clean_string` folds differently per side. **Abstain** when quote or candidate slice contains combining marks (Unicode category Mn) or when NFC(normalized quote) != NFD(normalized quote).

- [HIGH] **LaTeX folding is asymmetric and guard-gated; false absence when one side folds and the other does not.** Evidence: `textblock2unicode` only replaces `$...$` / `\(...\)` matches that pass `_should_skip_inline_textblock_formula` (skips complex envs, unbalanced braces, len>128) (`metrics.py:299-335`); `safe_latex_to_text` returns raw fallback on `_likely_bad_latex` / weak-input guards (`metrics.py:274-296`). `_math_surface` additionally folds `\[...\]` display math to inline before folding (`facts.py:220-255`) but **tapetum grounding does not call `_math_surface`**. Impact: PDF quote `E = mc^2` vs markdown `$E=mc^{2}$` may match on alnum-normalized grounding while semantically divergent; conversely `$\\sum_{i=1}^n$` skipped by guards vs unicode `∑` in PDF yields false absence. **Abstain** when either side still contains `$`, `\`, `^`, `_` after fold attempt, or when `safe_latex_to_text` would fallback (malformed/unbalanced LaTeX).

- [HIGH] **Nougat stratifies math and scores it independently; whisker evidence path has no math stratum.** Evidence: local clone `nougat/metrics.py:22-24,63-83` splits inline `\(...\)`, display `\[...\]`, and `tabular` via regex before metrics; Text/Math/Tables each get char-NED and set-F1 separately (`metrics.py:27-44`, `104-117`; `research/redteam/nougat.md:25-33`). Post-hoc `remove_numbers` strips digits and underscores from similarity strings (`nougat/postprocessing.py:178-187`), which would destroy subscript fidelity if ported blindly. Impact: document-level `normalized_text` nid (`pdf_judge.py:482`) hides localized math loss; a two-sided verifier must compare math quotes on `_math_surface` or a dedicated LaTeX-preserving lane, not prose `normalized_text`. Adopt Nougat's **stratum split** concept, reject its **digit/underscore stripping** for absence checks.

- [MED] **PDF-Extract-Kit normalizes formula whitespace and can omit whole modalities; scalar text match would false-pass modality loss.** Evidence: `latex_rm_whitespace` compacts formula LaTeX before emit (`PDF-Extract-Kit/project/pdf2markdown/scripts/pdf2markdown.py:23-39`, `:187-188`); demo `convert2md` skips `figure` and `table` blocks entirely (`pdf2markdown.py:320-321`; `research/redteam/PDF-Extract-Kit.md:39-45`). Impact: whitespace-normalized LaTeX vs pretty-printed markdown is a reformat, not absence — exact match must abstain and classify `present` under whitespace-stripped `_math_surface`. Table/formula dropped upstream is genuine absence, but only detectable with modality flags, not substring match on prose.

- [MED] **Ligatures and font-encoded symbols in PDF text layers break exact `\w+` token alignment.** Evidence: PyMuPDF text extraction commonly emits single-codepoint ligatures (`ﬁ`, `ﬂ`) or PUA glyphs; grounding tokenizes on `\w+` without NFKC ligature expansion (`grounding.py:49-67`). `clean_string` drops non-alnum, so `ﬁle` → `file` only if both sides fold the same way; PDF `ﬁ` vs markdown `fi` may yield different token streams for exact DP. Impact: short ligature-heavy quotes (WG21 "Specification", author names) need fuzzy tier or NFKC pre-pass; if NFKC(quote) != NFKC(candidate_window), **abstain** rather than call absent.

- [LOW] **Lane 1 exact lane intentionally avoids Unicode folding; do not reuse for evidence absence.** Evidence: `normalize_for_exact_lane` only normalizes line endings and trailing whitespace (`golden.py:79-90`); golden diff stays byte-meaningful for symbols. Impact: evidence absence must not inherit golden's minimal normalizer nor bench's aggressive `clean_string`; pick a third surface (`_math_surface`, `raw` + NFC, or olmOCR-style `normalize_text` with math carve-out per `05-web.md:14-18`).

## When exact text matching must abstain

Use **`present | absent | ambiguous`** (per `05-web.md:182-190`, `00-baseline.md:61-68`). Exact/substring matching may decide **only** when all guards pass; otherwise emit **`ambiguous`** and demote the quote (CRAG/auditRAG abstention pattern, `05-web.md:153-178`).

| Guard | Trigger | Action |
| --- | --- | --- |
| **G1 — No candidate check** | Absence claim, candidate markdown not yet located at chosen surface | `ambiguous`; never label absent (`00-baseline.md:33-44`) |
| **G2 — Math/LaTeX surface** | Quote or match window contains `$`, `\`, `^`, `_`, `=`, `\begin`, `\[` after `_math_surface` fold | `ambiguous` on exact tier; retry on `_math_surface` with length-relative `max_diffs` (olmOCR pattern, `05-web.md:14-18`) |
| **G3 — Unicode normalization** | `unicodedata.normalize("NFC", a) != unicodedata.normalize("NFC", b)` for quote vs best window | `ambiguous`; optional NFKC pass for ligatures only |
| **G4 — Combining marks** | Any Mn category codepoint in quote | `ambiguous` on token-exact tier (`grounding.py:49-67`) |
| **G5 — Fold failure** | `safe_latex_to_text` returns fallback/raw on either side (`metrics.py:274-296`) | `ambiguous`; do not treat as absent |
| **G6 — Short math string** | Normalized quote length `< EVIDENCE_MIN_FUZZY_CHARS` (20) AND contains math signals (`metrics.py:149`, `grounding.py:232-234`) | `ambiguous`; exact/fuzzy ratio unsafe on short formulas |
| **G7 — Stratum mismatch** | PDF unicode math vs markdown LaTeX delimiters for same semantic token | `ambiguous` until `_math_surface` parity or dual locate both pass |
| **G8 — Modality drop** | GT/baseline expects tables or display math; candidate count zero | `absent` via modality flag, not substring (`PDF-Extract-Kit` table skip, `pdf2markdown.py:320-321`) |

**Anchors:** `00-baseline.md:61-68` (two-sided verifier), `05-web.md:14-18` (olmOCR bidirectional fuzzy), `grounding.py:171-241` (current tiers), `facts.py:238-255` (`_math_surface`), `metrics.py:314-340` (`textblock2unicode` / `normalized_text`), `pdf_judge.py:513-520` (one-sided grounding), `nougat/metrics.py:63-83` (math stratum split).

## False-pass hypothesis

PDF text layer extracts `E = mc2` (caret lost in extraction). Markdown faithfully has `$E = mc^{2}$`. `ground_spans` folds both through `textblock2unicode` → `clean_string` → identical alnum `emc2` (`metrics.py:314-340`, `grounding.py:230-231`); source grounding passes; without candidate locate the sidecar still claims `"absent from markdown"` (`pdf_judge.py:401-404`). Verdict demotion may not fire if the model's overall narrative cites other grounded prose. A two-sided check on `_math_surface` would classify **`present`** (both fold to `E = mc^2` structurally) — current path **false-passes** the absence claim.

## False-fail hypothesis

PDF text layer emits NFC `"café"` in a prose quote; markdown holds NFD `"cafe\u0301"` inside a code span or raw surface fact. `ground_spans` exact token DP fails on code-unit mismatch (`grounding.py:216-228`); if the quote is short prose without math, normalized substring may still match after `clean_string` strips accents to alnum `cafe` (`metrics.py:118-126`). **False-fail** on exact tier only; fuzzy substring saves it — but an absence verifier that treats fuzzy source hit + exact candidate miss as **`absent`** would wrongly flag reformatting. Correct route: **`ambiguous`** under G3, not absent.

## What would change my mind

A labeled holdout (≥20 math/Unicode quote pairs from WG21 papers, human-labeled `present/absent/ambiguous`) showing that a two-sided verifier using `_math_surface` + NFC + olmOCR length-relative `max_diffs` (`05-web.md:14-18`) achieves ≥90% evidence precision on absence claims with ≤5% false-fail on legitimate LaTeX/unicode reformatting — would flip verdict to **usable** without conditions. Failure to beat 40% absence precision (`00-baseline.md:21-24`) on that holdout would flip to **garbage** for math-bearing quotes on the current one-sided `normalized_text` path.
