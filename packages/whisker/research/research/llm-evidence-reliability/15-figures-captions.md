# 15 - Figure and Caption Specialist

**Verdict:** usable-with-conditions — tomd's caption-band contract (`_CAPTION_LABEL_RE` → `![alt](path)` + body drop) and surya's `Caption` vs `Figure`/`Picture` layout split give a deterministic figure-text vs caption-prose taxonomy, but the PDF judge's blanket "text inside a figure" sanction (`pdf_judge.py:147-149`) plus one-sided grounding misclassifies PR #284's 2/5 false-absent caption quotes until candidate-side checks search image alt and sub-caption surfaces, not body prose alone.
**Confidence:** high

## Findings

- [CRITICAL] **tomd defines two non-interchangeable figure text classes: caption prose (must remain) vs interior diagram text (may be imaged only).** Evidence: `_CAPTION_LABEL_RE` matches `Figure|Fig.|Listing|Diagram|Image|Source code` + number + separator (`images.py:131-134`); `_caption_for` attributes matching lines to `suggested_alt` and the pipeline drops the same lines from body prose via predicate-equal `_line_in_caption_band` (`tomd/CLAUDE.md:77-100`, `images.py:312-346`). Sub-captions `(a)/(b)` render as italic paragraphs below the image, never as alt (`tomd/CLAUDE.md:79-80`). Impact: a two-sided verifier must treat caption-shaped PDF quotes as **present** when found in `![...](...)` alt or `*...*` sub-caption lines, and **absent** only when missing from both surfaces — not when the body paragraph is gone (that is sanctioned).

- [CRITICAL] **The PDF judge sanctions all "text rendered INSIDE a figure or image" without distinguishing caption-band prose from diagram labels.** Evidence: `_CONVERSION_CONTRACT` (`pdf_judge.py:147-149`) tells the model never to flag interior figure text as missing; the same contract is inherited by page escalation (`pdf_judge.py:218`, `PAGE_JUDGE_SYSTEM_PROMPT`). No bbox or `_CAPTION_LABEL_RE` gate is applied post-hoc. Impact: misclassified caption lines sitting visually near a figure (or vector-cluster overlap) can be LLM-sanctioned as imaged while still being load-bearing reader content; mirrors `09-false-negative-hunter.md:18` false-pass class. Dolphin/surya avoid this by **layout label**, not prompt trust alone.

- [HIGH] **Surya separates `Caption` (text-bearing, must transcribe) from `Figure`/`Picture`/`Diagram` (visual, interior optional).** Evidence: `TEXT_LABELS` includes `Caption` but excludes `Picture`/`Figure`/`Diagram`/`Table` (`surya/layout/label.py:6-18`); layout drops blank hallucinations only for `TEXT_LABELS` blocks (`layout/__init__.py:103-115`). `LAYOUT_PRED_RELABEL` maps model outputs to canonical `Caption`, `Figure`, `Picture`, `Diagram` (`label.py:24-44`). Impact: portable rule for whisker evidence routing — quotes whose source span maps to a `Caption` layout box (or matches `_CAPTION_LABEL_RE` in the PDF text layer outside an image bbox) are **caption-prose**; quotes inside `Figure`/`Picture` crops are **imaged-text** candidates for `sanctioned_imaged`, not absence.

- [HIGH] **Dolphin treats `fig` regions as image assets, not transcribed interior text.** Evidence: `label == "fig"` saves a PNG and emits `![Figure](figures/{file})` without an OCR pass (`demo_page.py:231-240`); interior text OCR runs only on non-`fig` crops via `"Read text in the image."` for `text_elements` (`demo_page.py:280-282`). `MarkdownConverter` routes `label == 'fig'` through `_handle_figure` (`markdown_utils.py:330-331`, `:240-269`). Impact: Dolphin never conflates caption transcription with figure interior — captions would need a separate layout label (not present in Dolphin's `fig` path). Whisker should not treat Dolphin-style image-only output as evidence that caption prose may be dropped.

- [HIGH] **PR #284 (p0957r8 defective ideal) is the calibration anchor: 3/5 quotes genuinely absent, 2/5 false-absent because captions already live in markdown alt text.** Evidence: nine-PR replay (`00-baseline.md:16-17`); live simulation flagged page 13 at recall 0.881 and escalated five quotes including Figure 1/2 captions (`tapetum-golden-review-findings-2026-07-14.md:200-209`); tomd cites p0957r8 `"Figure 1 - Expected memory layout"` as the `_CAPTION_LABEL_RE` dash-separator case (`images.py:128-129`). Impact: the 2/5 false-absent cluster is exactly **caption-in-alt, body-dropped** — a candidate-side locate on `![...](...)` (olmOCR bidirectional pattern, `05-web.md:14-18`) would mark `refuted_present`; the 3/5 true misses (captions/table header absent from alt too) stay `confirmed_absent`. Evidence precision on figure quotes cannot rise without this surface split.

- [MED] **Per-page `content_recall` screen cannot separate caption loss from sanctioned body-drop.** Evidence: `screen_pages` compares multiset tokens of full `tomd_md` against dehyphenated page text (`pdf_judge.py:287-311`); caption lines removed from body but preserved in alt still lower recall when alt is also missing (p0957r8 page 13 → 0.881, `constants.py:149-154`, `tapetum-golden-review-findings-2026-07-14.md:201`). Impact: screen correctly flags page 13 but cannot tell **which** tokens are caption vs imaged interior; escalation still depends on LLM + one-sided grounding. A caption-aware recall auxiliary (tokens from `_CAPTION_LABEL_RE` lines → alt/sub-caption surfaces only) would sharpen quote routing without new dependencies.

- [MED] **Lane 3 `image_ref` facts check markdown image syntax, not PDF caption prose — complementary, not substitutable.** Evidence: `FACT_IMAGE_REF` passes on `![...](...)` presence with optional alt/path needle (`facts.py:478-487`); `corpus_tools.py:252-259` drafts empty-text image facts; images stratum has zero verified corpus coverage (`whisker/CLAUDE.md:726`). Impact: evidence verifier should reuse `image_ref` semantics for caption quotes (search raw markdown image alt) rather than `normalized_text` body matching (`02-candidate-absence.md:18-23`). Table captions remain on the `tables` axis (`tapetum_llm.md:87`), not the figure regex (`images.py:131`, `Table N:` excluded).

- [LOW] **Vector-figure and data-URI markers are disclosures, not figure/caption defects.** Evidence: `<!-- tomd:vector-extraction-uncertain: ... -->` (`tapetum_llm.md:97`); `<!-- tapetum:data-uri-stripped ... -->` with alt preserved (`tapetum_llm.md:98`, `test_tapetum_llm.py:1186-1190`). Impact: absence checks must skip stripped payload markers; caption alt text after strip is still the candidate surface for `confirmed_absent` / `refuted_present`.

## Figure-text vs caption-prose routing (evidence verifier)

Apply **`present | absent | ambiguous | sanctioned_imaged`** per quote after source grounding (`00-baseline.md:61-68`, `05-web.md:182-190`).

| Class | Source signal | Candidate locate surfaces | Outcome if missing on surfaces |
| --- | --- | --- | --- |
| **Caption prose** | PDF line matches `_CAPTION_LABEL_RE` (`images.py:131-134`) OR surya `Caption` box | `![alt](path)` alt (raw), optional `*sub-caption*` below image (`tomd/CLAUDE.md:79-80`) | `confirmed_absent` only if absent from **both** alt and sub-caption |
| **Table caption** | `Table N:` heading row (table axis, not image regex) | Pipe/HTML table caption row + heading (`tapetum_llm.md:87`) | `confirmed_absent` on tables axis |
| **Imaged interior** | Text only inside `Figure`/`Picture`/`Diagram` bbox OR Dolphin `fig` crop with no separate text label | N/A (not expected in markdown body) | `sanctioned_imaged` — never count as missing (`pdf_judge.py:147-149`) |
| **Body prose near figure** | Paragraph lines in caption band but **outside** image bbox (`tomd/CLAUDE.md:98`, P4003R1) | Normalized body prose (`02-candidate-absence.md:18-23`) | Standard tri-state |
| **Ambiguous** | Quote matches `_CAPTION_LABEL_RE` and appears both in caption band and inside cluster bbox | — | `ambiguous`; demote, do not promote to absent |

**PR #284 routing:** Figure 1/2 caption quotes → caption-prose row; if defective ideal lacks alt, `confirmed_absent` (3/5 bucket); if golden carries `![Figure 1 - Expected memory layout](...)`, candidate locate → `refuted_present` (2/5 bucket, `00-baseline.md:17`, `02-candidate-absence.md:8`).

**Anchors:** `00-baseline.md:16-19` (PR #284 precision), `05-web.md:14-18` (bidirectional locate), `pdf_judge.py:147-149` (figure sanction), `pdf_judge.py:287-311` (page screen), `images.py:131-134` (`_CAPTION_LABEL_RE`), `tomd/CLAUDE.md:71-100` (caption invariant), `surya/layout/label.py:6-44` (Caption vs Figure), `Dolphin/demo_page.py:231-240` (fig asset path), `tapetum-golden-review-findings-2026-07-14.md:200-209` (p0957r8 replay), `facts.py:478-487` (`image_ref`), `02-candidate-absence.md:8` (2/5 false-absent).

## False-pass hypothesis

p0957r8 page 13: PDF text layer still contains `"Figure 1 - Expected memory layout"` in the caption band, but the converter correctly moved it to `![Figure 1 - Expected memory layout](p0957r8-fig13-1.png)` and dropped the body duplicate (`tomd/CLAUDE.md:97-100`). The PDF judge quotes the caption from RAW text, source-grounding passes, one-sided sidecar labels it absent (`pdf_judge.py:401-404`), and `_CONVERSION_CONTRACT` does not instruct the model to search alt text — yielding a phantom missing-caption quote on an otherwise faithful conversion (PR #284 false-absent class, `00-baseline.md:17`).

## False-fail hypothesis

A diagram-heavy NB paper where axis labels (`"Node A"`, `"edge weight"`) exist only in the PDF text layer inside a vector figure cluster (`vector_images.py:10-16`, `pdf_judge.py:147-149`). A naive candidate-absence check on those strings fails because markdown correctly has only `![Figure 3: swim lane](path)` with no interior transcription. Without `sanctioned_imaged` routing, the verifier false-fails faithful output; surya would classify the spans as `Figure`/`Diagram` interior, not `Caption` (`label.py:6-18`).

## What would change my mind

Replay of PR #284's five page-13 quotes through a caption-aware two-sided contract (source ground → classify via `_CAPTION_LABEL_RE` → candidate locate on `![...]` alt + sub-captions → tri-state) showing ≥4/5 agreement with manual labels (3 absent, 2 refuted_present) and zero false-fail on ten golden PDFs with faithful caption-in-alt conversions — would flip verdict to **usable**; if caption-shaped quotes still false-absent at >20% after alt-surface locate, verdict stays **usable-with-conditions** and the figure sanction must be narrowed by layout/bbox, not prompt text alone.
