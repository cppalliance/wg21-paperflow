# 11 - The Security Reviewer

**Verdict:** usable-with-conditions — no LLM prompt path, no eval/exec, no classic XXE, and pid-based reads are DB-gated on the score path; the default markitdown oracle and unbounded TEDS/Levenshtein work on attacker-shaped PDF/HTML/markdown make local CPU/memory DoS the main real risk on `--all`, not integrity compromise.
**Confidence:** high

## Findings

- [HIGH] **Default oracle doubles untrusted parsing with no resource envelope.** Evidence: `reference.py:42-64` (`MarkItDown(enable_plugins=False)` then `.convert(str(source_path))` on staged PDF/HTML); `__main__.py:194` (oracle on unless `--no-reference`); `00-EVIDENCE-BASELINE.md` §3a (382 papers scored ref-free in 86.1s; oracle path is slower and runs a second full conversion per paper). Impact: every WG21 source is parsed twice (tomd + pdfminer/markdownify via markitdown). `enable_plugins=False` correctly blocks third-party plugins, network hooks, and LLM clients (`reference.py:39-41`), but the remaining parsers are still attacker-controlled input surfaces. A malicious PDF/HTML can hang or exhaust memory inside markitdown while whisker treats the corpus as data, not trust.

- [HIGH] **Full-document Levenshtein has no size cap on the default oracle path.** Evidence: `score.py:212` (`text_nid(normalized_text(md_text), normalized_text(reference_md))`); `metrics.py:64-78` (`rapidfuzz` Levenshtein over entire strings, `distance / max(len)`); contrast `match.py:253-255` (`BLOCK_MATRIX_CELL_BUDGET = 400_000` fallback documented in `constants.py:121-128`). Impact: block matching is budgeted, but the production oracle path is not. A crafted multi-megabyte conversion (or oracle output) forces O(n×m) time and memory on every scored paper with the default reference engine. Real WG21 papers are tens of thousands of chars (baseline: full-document compare "milliseconds" per `metrics.py:71-72`), so this is latent until someone stages an oversized artifact.

- [HIGH] **TEDS/table scoring has no row/column/node budget; APTED runs on attacker-shaped HTML.** Evidence: `bench.py:125-127` (unbounded `while j < len(lines)` row accumulation into HTML); `bench.py:145` (cell text interpolated raw: `f"<td>{c}</td>"` with no escaping); `metrics.py:503-513` (`n_nodes = max(len(pred.xpath(".//*")), ...)` then `APTED(...).compute_edit_distance()`); `score.py:213` (`ref_teds = table_score(md_text, reference_md)` on every oracle score). Impact: a pipe-table bomb (millions of rows/columns or deeply nested markup injected via cell text) can blow memory and CPU during lxml parse + tree edit distance. `BLOCK_MATRIX_CELL_BUDGET` protects `match.py` only, not TEDS. This is availability (DoS), not a verdict-integrity bypass, but `--all` on 382 real papers (`00` §3a) would amplify one bad staging.

- [MED] **lxml TEDS uses `html.fromstring` on markdown-derived fragments; XXE is low, entity bombs are not fully ruled out.** Evidence: `metrics.py:494-496,532-533` (`lxml_html.HTMLParser(remove_comments=True, encoding="utf-8")` + `fromstring` on table HTML built from markdown, not raw WG21 HTML). Impact: this is the HTML parser, not `etree.XMLParser` with external DTD resolution, so classic XXE/file exfiltration is unlikely. Residual risk is algorithmic: deeply nested tags or enormous DOMs from cell-injected markup (`bench.py:145`) before APTED. No `huge_tree=False` or explicit `no_network` hardening is set; reliance is on libxml2 HTML recovery semantics. Acceptable for a local QA tool on a trusted WG21 corpus; insufficient for scanning arbitrary uploads without sandbox memory limits.

- [MED] **Anchor regex patterns are attacker-controlled if corpus JSON is compromised.** Evidence: `anchors.py:50-56,172-173` (`re.search(pat.regex, haystack, _compile_flags(...))` over full normalized markdown; `anchor_spec_from_dict` validates syntax at load `anchors.py:229-232` but not complexity); `CLAUDE.md:46-48` (anchors are hand-authored trusted config). Impact: ReDoS is realistic from a malicious `<pid>.anchors.json` (e.g. nested quantifiers + `DOTALL` over a large candidate), not from PDF content directly. Lane 3 `facts.py` uses fixed patterns only (`facts.py:72-74`; no user regex). Severity is MED because the threat model is repo/operator compromise, not mailing-list PDF injection.

- [MED] **pylatexenc normalization lacks the OmniDocBench timeout harness.** Evidence: `metrics.py:134-138` (shortcut: multiprocessing timeout "dropped"); `metrics.py:209-210,292-296` (`_likely_bad_latex` length cap 8000 per snippet, but `textblock2unicode` scans the full document at `metrics.py:318-334`); `score.py:212` (normalization on both sides for oracle NID). Impact: pathological inline LaTeX that passes guards can still hang `LatexNodes2Text` inside `safe_latex_to_text` (exceptions caught, hangs not). CPU DoS on scoring, not silent wrong verdict.

- [LOW] **`get_paper_md_path` joins `pid` into filenames without rejecting path separators; mitigated by DB lookup on the hot path.** Evidence: `sqlite_backend.py:1167-1169` (`return self._papers_dir / f"{pid.lower()}.md"`); `score.py:280-281` (`get_paper_md` / `get_source_path` query DB first); `__main__.py:192` (CLI uppercases pid but does not strip `..`). Impact: traversal via CLI pid alone fails at DB unless a poisoned `paper_id` exists in `papers`. Sidecar writes use the same stem (`score.py:313-314`, `__main__.py:234-236`). Low for WG21-normal IDs; document "never insert raw CLI pid into DB."

- [LOW] **No LLM, eval, exec, subprocess, or outbound network in whisker scoring code (verified).** Evidence: grep across `packages/whisker/src` shows no `eval`/`exec`/`subprocess`; `reference.py:39-42` (`enable_plugins=False`); `facts.py:20-21,30-31` ("NO LLM in the scoring loop"); `tomd/lib/check_content.py` and `tomd/lib/pdf/qa.py` have no LLM imports on the paths `score.py:202-203` calls. Impact: positive — whisker honors the determinism/no-LLM invariant (`CLAUDE.md:278-280`). Downstream LLM consumption of markdown is out of scope; whisker does not assemble prompts.

## False-pass hypothesis

**Silent corpus omission, not a green verdict:** a zip-bomb or parser-hang PDF causes `score_paper` to raise inside markitdown or metrics; `__main__.py:210-215` catches `Exception`, logs, and **skips** the paper. The footer still reports pass/review/fail for scored papers only (`00` §3a: 382 scored). Impact: operators can believe the corpus was fully vetted when one staged paper never received a verdict — a **coverage false confidence**, not `verdict=pass` on broken content.

## False-fail hypothesis

**Resource exhaustion on a benign giant paper:** a legitimately huge table-heavy WG21 paper (within mailing norms but at the tail of size) triggers TEDS APTED or full-document Levenshtein slowdown/timeouts in CI, producing `error scoring ... (skipped)` (`__main__.py:215`) or wall-clock failure of the batch — a good conversion never gets a verdict. No structural false-fail flag is emitted; the paper simply disappears from the rollup.

## What would change my mind

A committed fuzz run (malformed PDF/HTML + markdown table bombs) with **RSS and wall-clock ceilings** per paper, reporting whether `--no-reference` vs default oracle stays under agreed limits (e.g. <30s and <2GiB on worst case), plus a patch adding explicit caps (`MAX_TABLE_ROWS`, `MAX_DOCUMENT_CHARS` for NID) with tests — would flip to **usable** without conditions if all cases either pass within bounds or fail closed with a typed `STATUS_INVALID`-style error instead of skip-and-forget.
