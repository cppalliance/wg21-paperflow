# 22 - The Reference-Oracle Skeptic

**Verdict:** usable-with-conditions — markitdown is a legitimate *disagreement* probe, not a correctness oracle; default-on at `REF_NID_ADVISORY_EDGE=0.85` floods review with redundant flags (147/382) while only 28/382 papers change tier, so operators should treat `--no-reference` as the triage default until the edge is corpus-fitted or the overlay is demoted to report-only.
**Confidence:** high

## Findings

- [CRITICAL] **The advisory edge sits below the corpus mean, so "low agreement" is the statistical norm, not an anomaly.** Evidence: stale schema-1 run `ref_nid` mean **0.8362**, **147/382** below `REF_NID_ADVISORY_EDGE=0.85` (`00` §3b; runtime re-verify on `data/whisker/report.json`: mean=0.8362, below085=147/382); edge borrowed from edgeparse NID CI floor (`constants.py:85-87`). Impact: ~38% of papers trip `reference text agreement … low (advisory)` (`score.py:175-178`) on a threshold that flags *typical* cross-converter disagreement; precision is unknown (`00` §5: no labeled TPR/FPR).

- [HIGH] **81% of oracle flags are redundant: they fire on papers already in review for ref-free reasons.** Evidence: same schema-1 report — **147** papers carry the advisory flag, but simulating ref-free verdicts on that run (strip ref soft flags, re-apply `_decide` logic) yields **154 pass / 208 review** vs actual **126 / 236**; **oracle-only pass→review = 28** (154−126). Impact: the flag rollup shows 147 oracle hits but only **28/382 (7.3%)** incremental triage; the other **119/147** add noise to an already 62%-review pile (`00` §3b) without changing tier.

- [HIGH] **markitdown is a weak structural peer: pdfminer emits no reliable headings and erratic blocks, so two of three reported oracle axes are explicitly no-ops.** Evidence: `CLAUDE.md:250-253` ("oracle (pdfminer for PDF) also emits no reliable heading hierarchy and structures tables differently, so teds/mhs carry no signal"); `score.py:213-214,175-178` (`ref_teds`/`ref_mhs` computed but never flag; only `ref_nid` soft-flags); `score.py:207-212` (whole-document `text_nid` on `normalized_text`, block matching deliberately avoided — block path under-scores up to **0.57** vs full-doc per `CLAUDE.md:169-173`). Impact: the oracle comparison is **text-extraction agreement only**; table/heading regressions markitdown would catch in its own CI (`markitdown.md` §1.1–1.4: anchors, ordered sections, anti-duplication) are **not** exercised against tomd output.

- [HIGH] **"Agreement != correctness" is implemented correctly but neuters interpretability: low `ref_nid` means "two fallible converters disagree," not "tomd is wrong."** Evidence: `score.py:142-147,175-178` (advisory soft only, never hard-fail); `reference.py:10-14` ("Rather than hand-label gold Markdown, we run … converter … treat its Markdown as the reference"); `CLAUDE.md:247-250` (CE-OCR / Infinity-Parser: agreement != correctness). Runtime bands on schema-1 report: **47** papers `ref_nid < 0.70`, **100** in 0.70–0.85, **173** in 0.85–0.95 — no label ties low NID to human-needed fixes. Impact: operators sorting by `nid=` (`report.py:75`) cannot infer direction of error; high agreement (`ref_nid ≥ 0.95`, **62** papers) equally allows **shared** omissions (both miss scanned text).

- [MED] **The 0.85 edge is a category error: edgeparse's NID floor targets human-GT, block-matched bench scores, not markitdown-vs-tomd whole-doc text on WG21 papers.** Evidence: `constants.py:53-58` (`NID_FLOOR = 0.90` for labeled bench vs `REF_NID_ADVISORY_EDGE = 0.85` for oracle); `NID_FLOOR` comment cites OmniDocBench human gold (`constants.py:53-55`); oracle path uses `text_nid(normalized_text(...))` without block matching (`score.py:212`). `calibrate` fits only `unigram_coverage`, not `ref_nid` (`redteam-synthesis.md` Tier 3; `markitdown.md` §2). Impact: transplanting a **stricter** benchmark constant onto a **noisier** comparison axis guarantees over-flagging; lowering edge without labels trades noise for missed signal blindly.

- [MED] **Default-on oracle doubles batch cost for marginal tier movement.** Evidence: `score_paper` default `reference_engine="markitdown"` (`score.py:268,283-284`); `reference.py:64-65` (full second conversion per paper); `CLAUDE.md:100-101` ("`--all` is slower … `--no-reference` is the fast path"); tier delta on same run: **+28 review, −28 pass**, **0 fail changes** (schema-1 simulation above). Impact: CI/operators pay per-paper markitdown cost (`00` §3a ref-free 86.1s vs oracle run not re-timed here) mostly to re-sort papers already flagged by misaligned regions (**184** soft, `00` §3b).

- [MED] **Normalization asymmetries depress `ref_nid` on faithful tomd output (front matter, markdown syntax), triggering advisory review without content loss.** Evidence: `clean_string` keeps alnum+CJK only, does not strip YAML front matter (`metrics.py:118-126`; `CLAUDE.md:149-150`); `test_score.py:232-250` (formatting-only delta passes when body dominates); persona 06 runtime: front-matter vs plain-body pair `text_nid≈0.31`. Impact: papers where tomd adds structured front matter and markitdown emits plain extraction text land below 0.85 even when body prose is faithful — advisory flag reads as "suspicious" for **better** formatting, not worse content.

- [LOW] **Oracle wiring is tested for plumbing only, not corpus quality.** Evidence: `test_reference.py:29-43` (tiny HTML → markitdown returns body text); `test_score.py:167-251` (synthetic identical/divergent strings). No test asserts markitdown-on-WG21-PDF agrees with tomd above 0.85. Impact: code is correct; the **operating point** is unvalidated — consistent with `00` §2 ("353 passing tests is a quality signal for the CODE, not for the VERDICT's real-world accuracy").

## False-pass hypothesis

A **scanned or image-heavy WG21 page** where both tomd and markitdown (pdfminer) extract little or no body text: both sides normalize to short, similar garbage strings, `ref_nid` stays high (`test_score.py:167-177` — identical refs → 1.0), `unigram_coverage` may still pass if the PDF text layer is equally empty (`00` §3b mean unigram **0.966**), structural gates green → **pass** with oracle on. Neither converter is labeled correct; agreement masks shared failure.

## False-fail hypothesis

A **faithful tomd conversion** with full YAML front matter and pipe tables scored against markitdown plain text (no YAML, different table serialization): `ref_nid` depressed by metadata/syntax tokens surviving `normalized_text` (`metrics.py:118-126`, `score.py:212`), below **0.85** → advisory review (`score.py:175-178`) while `unigram_coverage ≥ 0.95` and gates pass — human would ship; whisker adds a "look" flag indistinguishable from genuine divergence. Contributes to the **28** oracle-only pass→review cases and the **147** advisory flags on schema-1.

## What would change my mind

A **single schema-3 run** with oracle on (`whisker --all --no-write --stats`) plus **30–50 human labels** adjudicating: (a) do the **28** oracle-only tier changes correlate with human-needed fixes at precision ≥50%, and (b) does a **percentile-fitted** advisory edge (e.g. flag bottom decile of `ref_nid` or `calibrate` on cross-converter disagreement labels) beat fixed 0.85 on holdout FPR ≤10% — demonstrating the overlay adds signal beyond ref-free review, not just volume.
