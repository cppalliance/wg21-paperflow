# 05 - The TEDS Port-Fidelity Reviewer

**Verdict:** usable-with-conditions — the core `teds()` evaluator is a faithful port of OmniDocBench/PubTabNet `table_metric.py` on normalized HTML-in/HTML-out inputs, but the markdown bench wrapper and missing upstream golden vectors mean published leaderboard numbers are not yet directly comparable from `whisker bench` on WG21 markdown.
**Confidence:** high

## Findings

- [HIGH] **Core `_TEDS.evaluate` matches the PubTabNet/OmniDocBench algorithm** (lxml DOM → `_TableTree` → APTED, char-token cell content, xpath `.//*` denominator, td-only tokenization, tag/colspan/rowspan rename = 1.0). Evidence: side-by-side read of whisker `metrics.py:402-516` vs upstream `table_metric.py` (OmniDocBench `src/metrics/table_metric.py`, IBM PubTabNet `src/metric.py`); runtime inline reimplementation with the same APTED config scored **bit-identical** on 8 hand cases including the frozen 0.5 missing-row vector (`test_metrics.py:91-101`, runtime 2026-06-25). Impact: calling `teds(html_a, html_b)` on two already-normalized HTML table strings reproduces the reference TEDS formula; the "verbatim port" claim holds for the evaluator kernel.

- [HIGH] **`_normalize_table_html` is mandatory and matches OmniDocBench preprocess intent** (`th`→`td`, `thead`/`tbody`/`tfoot` strip, `<html><body>` wrap). Evidence: `metrics.py:519-537`; opendataloader fork `_convert_headers_to_cells` + string thead/tbody removal (`research/repos/opendataloader-bench-tmp/src/evaluator_table.py:149-150,174-177,200-203`); runtime: without normalize, `<th>Header</th>` vs `<td>Header</td>` scores **0.667** on raw `_TEDS.evaluate`, with whisker normalize scores **1.0**; thead/tbody fixture scores **1.0** (matches opendataloader `test_evaluator_table.py:44-49`). Impact: leaderboard parity requires this preprocess; whisker applies it inside `teds()` so callers cannot forget it on fragments.

- [HIGH] **Bench integration is NOT leaderboard-equivalent**: markdown pipe tables are converted to minimal HTML and mean-TEDS'd by **document-order index**, not the OmniDocBench HTML-native path. Evidence: `_extract_md_tables` / `_rows_to_html` / `_table_score` (`bench.py:98-163`) emit all-`<td>` rows with no colspan/rowspan, `border="1"`, and pair `max(n_cand, n_ref)` tables padding misses with `<table></table>`; opendataloader wraps all extracted tables then `evaluate` takes only **`body/table[0]`** (`evaluator_table.py:146-148,239-246`). Impact: a paper with two tables gets **mean per-table TEDS** in whisker vs **first-table-only** in opendataloader; markdown GT vs HTML GT (Party-List fixture in `test_evaluator_table.py:90-166`) will diverge from published OmniDocBench numbers even when the kernel is correct.

- [MED] **Cell-content rename uses raw char-token lists; no whitespace/html-unescape normalization** (unlike the opendataloader fork). Evidence: whisker `_TedsConfig.rename` calls `normalized_distance(node1.content, node2.content)` on token lists (`metrics.py:439-442`); opendataloader joins tokens then `_normalize()` (unescape, `<br>`→newline, whitespace collapse) before Levenshtein (`evaluator_table.py:76-83,167-171`). Runtime: whitespace-only HTML cell diff scores **0.8** in whisker vs opendataloader expecting **1.0** (`test_evaluator_table.py:169-178`); trailing-space cell scores **0.963**. Impact: whisker matches **OmniDocBench `table_metric.py`** (which also uses raw lists) but **not** opendataloader/marker leaderboard forks that added content normalization; cross-tool threshold comparisons at 0.80 (`constants.py:56-58`) may disagree on formatting-only diffs.

- [MED] **Levenshtein backend swapped to rapidfuzz** with string/int parity frozen but no TEDS-specific char-list golden suite against the GPL `levenshtein` package OmniDocBench imports. Evidence: `_TedsConfig.normalized_distance` uses `rapidfuzz.distance.Levenshtein` (`metrics.py:428-429`); OmniDocBench upstream uses `Levenshtein.distance` on the same lists; `test_edit_distance_parity.py:26-53` covers strings and int tuples only, not inline-tag cell tokens like `<b>bold</b> text` vs `bold text` (runtime score **0.939**, same on both sides so internally consistent). Impact: low risk given same maintainer lineage and identical scores on tested sequences, but leaderboard audit trail lacks a direct OmniDocBench import comparison.

- [MED] **Test coverage pins one hand-checkable PubTabNet case; no upstream fixture import.** Evidence: single golden vector `1 - 2/4 = 0.5` (`test_metrics.py:91-101`); `test_invariants.py:73-91` checks identity/bounds/monotonicity only; 353 tests green (`00` §2) but Lane 2 corpus empty (`00` §4: `whisker bench --corpus` errors). Impact: code regressions would likely be caught, but **numeric parity with OmniDocBench leaderboards is asserted in comments, not proven by a cross-library golden file**.

- [LOW] **Zero-denominator guard** returns 1.0 when `max(xpath('.//*')) == 0`; upstream divides by zero. Evidence: `metrics.py:506-510` (documented deviation); runtime empty `<table></table>` self-score **1.0**. Impact: benign on real corpora (OmniDocBench comment: row-less tables never appear); does not affect leaderboard comparability in practice.

- [LOW] **`structure_only` (TEDS-S) is exposed but not wired into bench/guard.** Evidence: `teds(..., structure_only=True)` (`metrics.py:540-551`); `test_metrics.py:83-88`; bench reports full TEDS only (`bench.py:150-163`); redteam-synthesis Tier 3 noted TEDS-S deferral. Impact: OmniDocBench publishes Table TEDS-S separately; whisker cannot reproduce that leaderboard column without a one-line bench extension.

## False-pass hypothesis

A candidate that **swaps the order of two markdown pipe tables** while keeping each table internally correct: `_table_score` pairs by index (`bench.py:156-162`), so table 1 is scored against ref table 2 and vice versa; localized errors can **cancel in the mean** and yield a middling TEDS (~0.5–0.8) that still clears `TEDS_FLOOR` 0.80 if one pair is perfect and the other merely bad, not catastrophic. Evidence: pairing loop `for k in range(max(len(cand), len(ref)))` with no Hungarian alignment; opendataloader/markitdown redteam notes order sensitivity (`research/redteam/markitdown.md:53`).

## False-fail hypothesis

Two HTML tables **identical in rendered content** but differing in insignificant whitespace/newlines inside `<td>` cells score **0.8** in whisker (runtime 2026-06-25) where opendataloader's normalized fork scores **1.0** (`test_evaluator_table.py:169-178`). On a labeled bench run this would depress TEDS and trip `TEDS_FLOOR` 0.80 (`constants.py:56-58`, `guard.py:107`) despite semantic equivalence under the fork used by some leaderboard tooling.

## What would change my mind

A committed **golden-vector file** (≥20 HTML pairs) scored by both whisker `teds()` and a pinned import of OmniDocBench `table_metric.py` + opendataloader `evaluator_table.py`, asserting bit-identical or documented deltas on: missing-row (0.5), thead/tbody, whitespace-only cells, inline tags, colspan/rowspan, and multi-table pages — run in CI. Until that exists, treat core `teds()` as faithful and **`whisker bench` table axis as integration-unverified for leaderboard claims**.
