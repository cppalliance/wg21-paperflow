# 29 - The Product / Decision Skeptic

**Verdict:** usable-with-conditions — whisker names three decisions (ship / look / block) but the default CI contract only blocks 3.7% (14/382), the 54% review tier is mostly expected furniture-stripping noise, and pass carries no measured precision; useful as a **hard-fail filter** and **spot-check accelerator**, not as a triage oracle you would ship on blindly.
**Confidence:** high

## Findings

- [CRITICAL] **The trichotomy is not one product: default `--gate review` collapses pass and review into the same CI outcome (exit 0), so "review" is not a merge-blocking decision at all.** Evidence: ref-free distribution **163 pass / 205 review / 14 fail** (`00` §3a); `_GATE_ACCEPTS["review"] = {pass, review}` (`__main__.py:80-84`); `_verdict_exit_code` returns `EXIT_FAIL` (5) only for fail verdicts when gate is review (`__main__.py:114-120`, `constants.py:136-139`). Impact: operators who run default CI get a **binary** (14 papers blocked, 368 green), not a three-way triage. The yellow "review" tier exists in terminal color and sidecars but **does not change the release decision** unless someone tightens to `--gate pass` (which would reject 219/382 papers per `09-ci-release-engineer.md`).

- [CRITICAL] **Review is a dumping ground, not a precision queue: 186/205 review papers (91%) trip the dominant soft flag the spec declares benign on clean papers.** Evidence: flag rollup **186 misaligned region(s)** vs **205 review** total (`00` §3a); `REGION_SOFT_COUNT = 1` fires on a single region (`constants.py:43-47`); `score.py:164-166` (`region_total >= REGION_SOFT_COUNT` → soft review); `CLAUDE.md:233-236` ("Misaligned regions are soft only … some regions are **expected on clean papers**"). Impact: a human told "205 papers need review" is mostly told "tomd stripped headers/footers as designed." Triage math: skipping eyeball on 163 passes saves 163 inspections only if those passes are trustworthy; forcing 205 reviews where ~91% are spec-expected noise **does not beat eyeballing all 382** — it replaces uniform sampling with a biased queue whose top signal is documented false alarm.

- [HIGH] **Pass tier is necessary-but-not-sufficient for "ship": no labeled TPR/FPR, Lane 3 dead, and thresholds explicitly provisional.** Evidence: **0 labeled corpus members** (`00` §4); `calibrate` never run (`00` §5); `constants.py:11-15` ("PROVISIONAL … not yet a value fitted on a labeled corpus"); Lane 3 facts errors on real data (`00` §4). Pass requires `unigram_coverage >= 0.95`, zero soft flags including zero misaligned regions (`score.py:161-184`). Impact: **163 pass papers** are structurally clean with high token recall and no furniture deltas — a reasonable **pre-filter**, but whisker admits it cannot catch table-cell scrambles or formula exponent drops without Lane 3 (`CLAUDE.md:37-44`). I would not wholesale-ship on pass without spot audits; I might skip full read on pass **only** with periodic sampling.

- [HIGH] **Fail tier mixes broken content with heading pedantry, so "block" is not a uniform fix decision.** Evidence: **9/14** ref-free fails are `heading_monotone` (H2→H4 jumps); **3/14** are genuine `unigram coverage < 0.85`; **2/14** are `no_empty_table` (`00` §3c, `gates.py:96-112`). Example **P3941R2/R3/R4**: `uni=0.999`, `drift=0.001`, fail solely on heading jump (`00` §3c). Impact: a release engineer cannot treat all 14 fails as "content missing — reconvert"; **64%** are structural heading policy that may be acceptable WG21 prose. Fail is actionable for **3 papers with missing content**; the rest need a separate "cosmetic vs broken" judgment whisker does not encode.

- [HIGH] **The user's actual decision tree is underspecified: three verdict strings map to at least five real actions with no guidance in output.** Evidence: `CLAUDE.md:8-10` promises "safe to ship / needs human / broken"; `render_summary` shows metrics + flag strings, capped at 15 lines per section (`report.py:166-190`, `constants.py:145`); pass section hidden by default (`report.py:289-291`). Soft flags sorted alphabetically, not by actionability (`report.py:45-47`). Impact: from a **review** line like `uni=0.982 cov=0.91 drift=0.04 qa=85  2 misaligned region(s)`, the operator must infer: ignore (expected furniture)? spot-check page snippet? compare to PDF? whisker does not say **look at WHAT** or **how long** — it emits a ruff-style rollup, not a decision brief.

- [MED] **Triage ROI is negative at current operating point: 54% human queue vs 43% auto-pass with unmeasured false-pass risk.** Evidence: **205/382 (53.7%)** in review, **163/382 (42.7%)** pass (`00` §3a); dominant review driver is expected misalignment (above). Compare to naive eyeball-all-382: whisker saves at most **163** full reads if pass precision is 100%, but adds **~186** low-value reviews the spec calls expected. Net expected human load ≈ **205 + ε false passes from 163** vs **382 uniform** — only wins if pass false-pass rate ε ≪ 0.57 and review queue is fast-dismiss. With no labels (`00` §5), ε is unknown. Impact: as a **product**, whisker today is a **fail filter** (14 papers) plus an **unprioritized inbox** (205), not a 57% workload cut.

- [MED] **Oracle-on default worsens decision fatigue without changing fail count.** Evidence: schema-1 with oracle: **236 review (62%)**, **147** advisory `ref_nid < 0.85`, mean ref_nid **0.836** below the 0.85 edge (`00` §3b); persona 22: **28/382** oracle-only tier changes, **119/147** advisory flags redundant on already-review papers. `score.py:175-178` (advisory never fails). Impact: default run inflates review section and sorts by `ovr=`/`nid=` (`report.py:72-77`) on a signal the code labels "LOOK, not tomd is wrong" (`CLAUDE.md:254-255`). Decision cost rises; **0 fail-tier changes** from oracle (`22-reference-oracle-skeptic.md`). Operators should use `--no-reference` for triage decisions until the edge is fitted (`00` §3a is the trustworthy hard-gate baseline).

- [LOW] **Pass hidden by default reinforces false confidence.** Evidence: `render_summary` omits pass section unless `-v` (`report.py:289-291`); footer shows `163 passed` without listing them. Impact: a green footer (`=== 14 failed, 205 review, 163 passed ===`) reads like success while **more than half** the corpus is in the human queue — fine for pytest-style "worst first," poor for a product dashboard where pass is the claim you are selling.

## False-pass hypothesis

A conversion that **permutes one table cell** or **drops a formula exponent** while preserving ≥95% unigram token recall and zero misaligned regions (PDF text layer still contains the words, just wrong association): passes all gates, `unigram_coverage >= 0.95`, no soft flags → **pass** at `--gate pass`. Lane 3 facts would catch it but **cannot run** (`00` §4). Evidence: hard gate stops at `UNIGRAM_COVERAGE_REVIEW_EDGE` (`score.py:161-162`); only **3/382** fail on unigram floor in production (`00` §3a).

## False-fail hypothesis

**P3941R2** (and R3/R4): `uni=0.999`, `drift=0.001`, **fail** solely on `gate:heading_monotone:heading level jumps H2 -> H4` (`00` §3c, `gates.py:105-109`). Content is present; a human would ship or fix one heading level. At default `--gate review` this is exit **5** (blocked); at `--gate fail` it is exit **0** (shipped broken-by-policy-only). The trichotomy forces a content verdict on a presentation invariant.

## What would change my mind

A **labeled holdout** (30–50 papers, human ship/fix/reject) reporting: (a) **pass-tier precision ≥95%** (≤5% of passes need human fix), (b) **review-tier precision ≥50%** after demoting misaligned-region-only flags to informational (or raising `REGION_SOFT_COUNT` / furniture-aware filtering so review rate drops toward the 54 unigram-band + 88 drift papers that signal real ambiguity), and (c) a documented **decision playbook** wired into output (pass → spot-sample 5%; review+regions-only → auto-dismiss; review+unigram band → open PDF; fail+heading → cosmetic queue). That would flip this to **usable** as a triage product, not just a hard-fail linter.
