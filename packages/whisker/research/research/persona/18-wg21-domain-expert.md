# 18 - The WG21 Domain Expert

**Verdict:** usable-with-conditions — whisker catches gross truncation and empty artifacts, but its hard gate punishes normal WG21 heading conventions (wording stable-names, issue lists, minutes) while leaving the failure modes that actually break committee papers (unfenced grammar/C++, lossy feature-test tables, ins/del fidelity) at soft review or unchecked.
**Confidence:** high

## Findings

- [CRITICAL] **`heading_monotone` hard-fails document shapes WG21 uses on purpose.** tomd maps section numbering depth to ATX level (`structure.py:922-931`: `4.0.1` → `####`, depth+1 with `#` reserved for title). Wording papers jump from `## 4 Wording Changes` directly to stable-name headings like `#### 4.0.1 execution::get_start_scheduler [exec.get.start.scheduler]` — verified in `data/paperstore/p3941r2.md` (H2→H4 at that line). Same pattern in CWG issue lists (`p4160r0.md`: `## Core Language…` then `#### 2609. Padding…`). Admin telecons (`n5035.md`) use `#` meeting title then `### Teleconference information` (H1→H3). Runtime: **9/382** papers hard-fail this gate alone; **9/14** ref-free hard fails are `heading_monotone` (`00` §3a). tomd's own QA applies the identical MD001 rule but only as a **soft** penalty capped at 15 points (`qa.py:435-438`), while whisker hard-fails (`gates.py:105-109`, `score.py:152-154`). Impact: the dominant hard-fail axis rejects shippable WG21 markdown with `uni≥0.997` (P3941R2/R3/R4, P4160R0) while a committee reader cares about wording diff fidelity, not an intermediate `###` stub.

- [HIGH] **WG21-critical modalities have no hard gate on the default path.** Grammar productions, stable-name tags (`[rand.req.urng]`), ins/del wording (`:::wording-*`, `<ins>`/`<del>`), and feature-test macro tables are emitted by tomd but not structurally enforced by whisker. tomd QA counts `wording_section_count`, `unfenced_code_lines`, `lossy_table_count`, and `table_parse_errors` (`qa.py:99-105,397-413`) — whisker folds only `qa_score` into **soft** review at `<70` (`score.py:170-171`, `constants.py:51`). Corpus scan: **P3596R1** has **112** unfenced-code paragraphs with `qa_score=70` and **62** fenced blocks — typical of grammar-heavy wording — yet passes all hard gates. **P3982R0/R1/R2** each carry **2** lossy-table markers at `qa_score=100`. Impact: a conversion that leaves normative C++ as unfenced prose or mangles a `__cpp_lib_*` table can still `pass` when multiset token recall stays high.

- [HIGH] **Table fidelity (TEDS / GriTS) is absent from production scoring despite WG21's table-heavy corpus.** Feature-test macro tables, straw polls (SF/F/N/A/SA), and wording comparison tables are first-class WG21 content. `score.py:19-20` explicitly excludes TEDS/MHS from `score_paper`; they live only in `bench`/`guard` against hand-labeled `<pid>.gt.md` (`00` §4: Lane 2 non-operational). The oracle reports `ref_teds` but never flags (`score.py:175-178`). Impact: swapped macro names, collapsed poll columns, or pipe-table structural loss invisible to the gate that actually runs on **382/382** papers; only **2/382** hit `no_empty_table` hard-fail, and that gate misfires too (next finding).

- [MED] **`no_empty_table` false-fails legitimate WG21 poll layout.** WG21 straw-poll tables often insert a blank row between the separator and numeric data. `p3290r4.md` lines 80–81 show `| --- | … |` followed by `|  |  |  |  |  |` then data on the next row — `_gate_no_empty_table` treats the empty pipe row as "no data row" (`gates.py:147-149`). P3290R4 fails with `uni=0.982`, `qa=95`. Impact: one of only **2** structural table fails is tripped by minutes/poll formatting, not a missing table.

- [MED] **Review tier is dominated by furniture stripping, not WG21 semantic defects.** **186/382** papers get "misaligned region(s)" on ref-free run (`00` §3a); spec declares these expected when tomd strips headers, footers, page numbers, and TOCs (`constants.py:43-47`, `CLAUDE.md:233-236`). P2583R3 (wording-heavy, 108 `:::wording` blocks) lands `review` on **4 misaligned regions** with `uni=0.957`, `qa=100` — missing p.1 furniture tokens, not botched ins/del. HTML papers leak stylesheet/table markup into extra regions (P3100R6: `"style table th td border…"`). Impact: triage queue is ~54% of corpus (`00` §3a) without ranking papers where grammar, wording diffs, or macro tables broke.

- [MED] **`unigram_coverage` is the right content axis for WG21 but fires rarely and misses structural word preservation.** Hard fail below **0.85** catches dropped sections (**3/382** ref-free fails, `00` §3a); mean **0.966** (`00` §3b). Order-invariant recall correctly ignores multi-column reflow (`score.py:130-137`). It does not detect: table cell transposition (all tokens still present), `$x^2$` → `x2` (folded before compare in bench's `normalized_text`, `metrics.py:147-148`), or broken cross-ref `[P1234R5]` vs `[P1234R6]` when both tokens exist elsewhere. Impact: content-loss hard gate sensitivity ~**0.8%** while WG21 semantic failures cluster in the soft/unchecked band.

- [LOW] **Heading gate uses line-regex, not mistune AST — acceptable for WG21 but diverges from tomd QA.** `_gate_heading_monotone` skips fenced code (`gates.py:78-94`) but counts any `^#{1,6}\s+\S` line; tomd `_heading_level_skips` uses mistune top-level heading tokens only (`qa.py:277-301`, same MD001 semantics). For WG21 papers headings do not nest in blockquotes (`qa.py:288-289`), so divergence is rare; the real mismatch is **hard vs soft severity**, not detection method.

## False-pass hypothesis

**P3596R1**: **112** unfenced-code paragraphs (`qa.py:172-174` structural-code heuristic), **62** proper fenced blocks, `qa_score=70` (at the review threshold, not below it). A wording/grammar-heavy paper where large blocks of EBNF or C++ grammar sit as unfenced prose — exactly the failure mode that breaks downstream search and LLM citation of productions. Structural gates pass (`gates.py:153-161`); `unigram_coverage` stays high because the tokens are present; hard gate returns **`pass`** unless another soft flag fires.

## False-fail hypothesis

**P3941R2** (and R3/R4): runtime `uni=0.999`, `cov=0.997`, `drift=0.002`, `qa=95`, **fail solely** on `gate:heading_monotone:heading level jumps H2 -> H4` at `#### 4.0.1 execution::get_start_scheduler [exec.get.start.scheduler]` immediately under `## 4 Wording Changes` (`gates.py:105-109`; verified heading walk on `data/paperstore/p3941r2.md`). Content and tomd QA are excellent; the failure is markdownlint pedantry applied as a ship blocker to a normative wording section whose PDF never had an intermediate `### 4.0` heading.

## What would change my mind

A **WG21-stratified label set** (≥30 papers spanning wording diffs, feature-test tables, admin minutes, and grammar-heavy proposals) with human ship/no-ship adjudication, measuring **FPR of `heading_monotone` and `no_empty_table` on approved conversions** and **TPR of unfenced-code / lossy-table / TEDS floor on rejected ones**. If heading skips on shippable wording papers are >10% FPR, demote `heading_monotone` to soft (matching tomd QA) or exempt numbered stable-name headings (`[…]` suffix). Until then, treat whisker **`pass` as "no catastrophic loss"**, not "WG21-faithful."
