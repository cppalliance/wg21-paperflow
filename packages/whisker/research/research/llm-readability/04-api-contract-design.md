# 04 - API-Contract-Design

**Verdict:** usable-with-conditions (+ core facts/CLI shapes are coherent and mostly self-documenting, but two contract footguns — vacuous-green on guard/facts paths and tapetum pass-with-dropped-evidence — break promises the CI and advisory docs imply)
**Confidence:** high

## Findings
- [CRITICAL] `FactReport.passed` is vacuously true when a facts file has zero `checked: verified` rows, and neither `whisker guard` nor `whisker facts` rejects that case. Evidence: `packages/whisker/src/whisker/facts.py:128-130` (docstring: "a paper with no verified facts passes"); `packages/whisker/src/whisker/__main__.py:452-466` (guard fails only on `r.failed`, which is false); `packages/whisker/src/whisker/__main__.py:735-740` (facts CLI same); `packages/whisker/tests/test_facts.py:200-202` (explicit unit test locks the behavior). Impact: the "no vacuous green" claim in baseline/CLAUDE applies only to the hermetic pytest gate (`test_comprehension_corpus.py:67-70`), not to the production CLI/guard conjunctive path — a corpus member can ship an all-draft `.facts.jsonl` and get exit 0 on both `whisker facts` and the facts leg of `whisker guard`.
- [CRITICAL] Tapetum advisory demotion contract is asymmetric: ungrounded evidence demotes non-pass verdicts to `review`, but a confident `pass` with all evidence spans dropped is not demoted, contradicting #277 blocking condition 1 still open at this SHA. Evidence: baseline `00-baseline.md:71-76`; `packages/whisker/src/whisker/tapetum_llm/adjudicate.py:237-238` (`if suggested_verdict != VERDICT_PASS and not grounded`); `packages/whisker/src/whisker/CLAUDE.md` ("Evidence quotes are grounded verbatim… ungrounded quotes are dropped; an ungrounded non-pass or sub-floor confidence demotes to review"). Impact: sidecar `suggested_verdict: pass` with `grounded_evidence: []` and high `ungrounded_dropped` is schema-valid and contract-permitted, so downstream `--inspect` consumers cannot treat advisory pass as evidence-backed clearance (corroborates AbstentionBench non-abstention pattern in `05-web.md` Q4).
- [HIGH] `FactCheck.verified` in JSON output means "source fact was `checked: verified`" (enforced), not "assertion passed evaluation." Evidence: `packages/whisker/src/whisker/facts.py:102-116` (`verified: bool` set from `fact.checked` at line 387); `packages/whisker/corpus/README.md:48-49` documents `checked` provenance but never names the serialized `verified` field on checks. Impact: a consumer reading `checks[].verified` as "fact held" will misread draft rows and cannot distinguish enforcement status from pass/fail without also reading `passed`.
- [HIGH] CI comprehension gate and `whisker facts` CLI evaluate different substrates for the same corpus files. Evidence: `packages/whisker/tests/test_comprehension_corpus.py:10-14,62-65` (hermetic: `corpus/<pid>.expected.md`); `packages/whisker/src/whisker/__main__.py:708-718` (CLI: `backend.get_paper_md(pid)` from paperstore). Impact: contract "facts file + corpus member" does not mean the same pass/fail off-CI vs in-CI; a drift between live conversion and blessed snapshot yields green CI with red CLI or vice versa without any schema error.
- [MED] Tapetum sidecar JSON lacks `schema_version` / `kind` versioning present on whisker and facts outputs. Evidence: `packages/whisker/src/whisker/score.py:82-90` (`schema_version` on whisker sidecar); `packages/whisker/src/whisker/__main__.py:724-726` (`kind: whisker-facts`); `packages/whisker/src/whisker/tapetum_llm/models.py:106-124` (`TapetumResult.to_dict` — no version field, only `"advisory": true`). Impact: tooling cannot evolve tapetum fields or detect stale sidecars the way it can for `.whisker.json` / facts reports.
- [MED] `parse_facts_jsonl(text, pid="")` accepts `pid` but never uses it (symmetry docstring vs behavior). Evidence: `packages/whisker/src/whisker/facts.py:458-463,478-493` (`pid` documented "accepted for symmetry" in `facts_from_records`; loader ignores it entirely). Impact: callers passing `pid` for error context or duplicate-id scoping get no contract benefit; mismatched pid + file content fails silently.
- [MED] Facts JSONL schema silently ignores unknown top-level keys; typos in optional fields are not rejected. Evidence: `packages/whisker/src/whisker/facts.py:408-455` (`_fact_from_record` reads only known keys). Impact: an author typo like `"sequencee"` on an `order` fact fails the `sequence` required check (good), but a stray `"max_diff": 1` instead of `"max_diffs"` falls back to default 0 with no warning — contract says fuzzy budget applies, behavior is exact-match only.
- [LOW] Module-level exit-code contract (0/1/3/5 + `--gate`) is scoped to the default `whisker [PID]` scorer, not subcommands. Evidence: `packages/whisker/src/whisker/__main__.py:36-37,122-128,275` (gate + review exit 3); `packages/whisker/src/whisker/__main__.py:679-740` (`whisker facts` returns only `EXIT_OK` / `EXIT_ERROR` / `EXIT_FAIL`, no review tier). Impact: CI scripts copying the top-level exit contract onto `whisker facts` or `whisker guard` will mis-handle review semantics (guard is binary pass/fail only).

## False-pass hypothesis
Add `corpus/P9999.facts.jsonl` containing five `checked: "draft"` `present` facts whose `text` values are absent from the candidate markdown, plus a matching `P9999.gt.md` corpus member. `check_facts` returns `passed=True` (`facts.py:128-130`); `whisker guard --corpus …` exits 0 on the facts leg (`__main__.py:452-466`) even though zero comprehension assertions gate — the CI anti-vacuous assert (`test_comprehension_corpus.py:69-70`) never runs because P9999 lacks a paired `.expected.md` in the hermetic parametrization (`test_comprehension_corpus.py:36-44` skips facts-only pairs).

## False-fail hypothesis
An author runs `whisker facts --strict` while iterating on draft facts: failing drafts gate exit 5 (`__main__.py:736-737`) even though `corpus/README.md:72-73` positions `--strict` as "useful while authoring" — the contract is consistent but the ergonomics promise ("authoring helper") conflicts with default CI semantics (verified-only), so a draft-heavy file fails locally in strict mode while the same file would pass CI and non-strict guard.

## What would change my mind
A single integration test (or guard/facts CLI check) mirroring `test_comprehension_corpus.py:67-70` — fail when any processed `.facts.jsonl` has `verified_count == 0` — plus a one-line adjudicate fix demoting `pass` when `evidence_spans` were emitted but `grounded` is empty; either would flip this persona to **usable** for the public contract surface.
