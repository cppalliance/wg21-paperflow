# 20 - Reading-Order-Auditor

**Verdict:** usable-with-conditions — Lane 3 `order` facts and the advisory `reading_order_ned` / shingle `coverage` axes catch gross section inversion but deliberately never hard-gate reading order; the only gated checkpoint is one sparse 5-anchor chain per corpus paper, so multi-column reflow failures and large intra-section permutations can still pass all lanes.
**Confidence:** high (code + runtime probe on corpus); medium on downstream LLM tolerance (no direct 05-web card)

## Findings
- [CRITICAL] **`order` facts verify five monotonic anchor positions, not document reading order.** Evidence: `facts.py:353-365` requires strictly increasing `_position_within` hits across `fact.sequence`; runtime probe on P4182R0 (412 lines, `00-baseline.md:53-57` corpus member): wp1→wp5 span 91.8% of normalized doc, with zone 3→4 alone 8,598 chars (46.1%) fully permutable between anchors. Impact: swapping paragraphs, table blocks, or entire subsections inside a zone leaves the verified `section-flow` fact green while downstream LLMs read a scrambled narrative.
- [HIGH] **First-match wins: duplicated or forward-referenced anchor phrases satisfy order at the wrong location.** Evidence: `_position_within` delegates to `_best_match`, which returns `haystack.find(needle)` before any later occurrence (`facts.py:224-226`, `facts.py:244-246`); P4182R0 anchor wp2 `"consolidates a single, citeable inventory"` matches Motivation prose at `:31`, not the Abstract lead at `:13-15`, and wp4 `"The table lists toolchain families"` is a distinct substring from the Abstract's `"matching rows for toolchain families"` at `:15` — a converter that drops Section 6 but leaves an earlier partial mention could still pass if anchors are chosen from surviving prose. Impact: WG21 papers that repeat proposal language in a Wording section (common pattern) can bind order checks to the proposal mention while the canonical section body is misplaced or missing.
- [HIGH] **Multi-column PDF reflow — tomd's primary reading-order failure mode — has zero corpus exercise.** Evidence: baseline lists no multi-column adversarial member (`00-baseline.md:77-78`); both corpus PDFs are single-column-ish inventory/math papers; olmOCR-bench dedicates 884 reading-order tests to 231 multi-column PDFs (https://huggingface.co/datasets/allenai/olmOCR-bench, `05-web.md` Q1). Impact: the fleet's highest-risk layout class is untested by Lane 3; a reflow that interleaves left/right columns into lexical order can pass `present`/`table` facts while destroying causal reading order.
- [HIGH] **Reading order is explicitly excluded from every hard gate; only order-invariant content recall fails.** Evidence: `_decide` hard-fails on `unigram_coverage < UNIGRAM_COVERAGE_FAIL_EDGE` (0.85) and never on shingle `coverage` (`score.py:130-137`, `score.py:156-160`); shingle `coverage` documented as reading-order proxy only (`constants.py:32-33`); `reading_order_ned` "never gates content" (`match.py:279-285`); calibration records 43 papers that correctly reflowed multi-column text with `unigram_coverage` ≈95% but shingle `coverage` ≈66% (`CLAUDE.md:313-314`). Impact: the deliberate design closes the false-fail path for faithful reflow but opens the mandated false-pass class: scrambled order with full word multiset.
- [MED] **Corpus order coverage is one verified fact per paper (~5 waypoints), vs olmOCR's 1,061 reading-order tests.** Evidence: P4182R0 `section-flow` 5-item chain (`P4182R0.facts.jsonl:6`); P4185R0 5 heading strings (`P4185R0.facts.jsonl:9`); olmOCR technical report Table 3: 1,061 reading-order cases across 1,403 PDFs (https://olmocr.allenai.org/papers/olmocr.pdf, `05-web.md` Q1). Impact: whisker proves coarse section skeleton on two papers; it does not bound per-page or intra-section order errors olmOCR treats as first-class.
- [MED] **Shingle `coverage` would flag reordering but is sidecar-only; `unigram_coverage` is provably blind to it.** Evidence: `test_check_content.py:479-489` — fully reversed word order yields `coverage < 0.5` while `unigram_coverage == 1.0`; `ContentCheckResult` docstring states large `unigram_coverage - coverage` gap means faithful reflow (`check_content.py:142-146`). Impact: operators see `cov=` in summaries (`CLAUDE.md:225-227`) but CI `--gate review` never fails on it; reorder-only corruption is invisible to the hard gate.
- [LOW] **Lane 2 `reading_order` axis is advisory and undefined on oversized papers.** Evidence: `bench.py:27-28`, `match.py:253-255` (matrix budget fallback sets `reading_order=0.0`); never in `below_floor` (`bench.py:261-268`). Impact: even the resemblance lane's order signal is unavailable on large papers and never blocks ship.

## False-pass hypothesis
tomd reflows a two-column WG21 PDF into single-column markdown with every word present (`unigram_coverage` ≥ 0.85) but interleaves column A and column B sentences; shingle `coverage` drops (~0.66 per `CLAUDE.md:313-314`) without gating; the five sparse `order` anchors still appear in document order because section headings and abstract boilerplate survive (`facts.py:353-365`); `reading_order_ned` is not computed on the reference-free path (`score.py:130-137`). Result: **pass** on `--gate review` with scrambled body text dissect/agora must read.

## False-fail hypothesis
A faithful conversion that front-loads a forward reference or TOC line containing a later order anchor phrase (e.g. Motivation cites `"The schema below states baseline capabilities"` before Section 3.1 renders it) inverts `_position_within` monotonicity (`facts.py:361-362`) and fails the single verified `order` fact on otherwise LLM-readable markdown — the mirror failure already noted for false-positive hunting (`11-false-positive-hunter.md:12`).

## What would change my mind
A comprehension-corpus member drawn from olmOCR-bench's 231 multi-column PDFs (≥10 verified order facts with section-scoped anchors, not document-global first-match), plus a blind read-back on holdout papers showing ≥90% fact recovery when shingle `coverage` < 0.70 but `unigram_coverage` ≥ 0.85 — demonstrating downstream LLMs tolerate the reordering the gate deliberately allows. **Absent that:** no published 2025–2026 card in `05-web.md` directly tests LLM QA accuracy under scrambled paragraph order; adjacent evidence only shows structure helps retrieval (HiChunk evidence recall +7 pp with heading-aware chunking, https://aclanthology.org/2026.acl-long.1372/, `05-web.md` Q5) and that benchmarks treat reading order as a separate downstream dimension (ParseBench 141K+ text rules incl. reading order, https://arxiv.org/abs/2604.08538, `05-web.md` Q3) — not that LLMs are robust to column interleaving.
