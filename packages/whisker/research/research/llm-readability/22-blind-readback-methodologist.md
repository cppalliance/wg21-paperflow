# 22 - Blind-Readback-Methodologist

**Verdict:** garbage (+ the one-time blind read-back does not license the repo-wide inference that converted markdown is "practically confirmed" LLM-readable or that deterministic facts are an empirically validated LLM proxy)
**Confidence:** high

## Findings
- [CRITICAL] Runs 1–2 never read the committed substrate; only Run 3 did. Evidence: `packages/whisker/corpus/P4182R0.validation.md:45-47` (Run 1 "verbatim excerpt", Run 2 "~330 lines", Run 3 "byte-exact" `expected.md`). Impact: two of three P4182 "8/8" anchors used experimenter-prepared excerpts that are not archived, so success could reflect excerpt curation, not reproducible read-back on the CI gate file.
- [CRITICAL] No adversarial LLM control: corrupted markdown is never shown to a reader model. Evidence: `packages/whisker/tests/test_comprehension_corpus.py:77-96` and `:98-116` (canaries scramble table/formula then call `check_facts`, not an LLM); `packages/whisker/research/comprehension-poc-report.md:150-151` (canary confirms the deterministic gate only). Impact: 17/17 LLM passes prove agreement on good markdown, not that the LLM read-back would fail when markdown is broken—the inference "facts track what LLMs recover" is untested in the failure direction.
- [HIGH] Question design embeds answer lexemes, making substring retrieval trivial. Evidence: `P4182R0.validation.md:35-38` (Q4 "Pigweed… coroutines"; Q7 row `"GPU device code (CUDA, SYCL)"`; Q8 row `"Game consoles (Xbox, PS5)"`) vs `P4182R0.facts.jsonl:4,7-8` (identical strings in fact assertions) and `P4182R0.expected.md:200,55,77`; `P4185R0.validation.md:47` ("two-word name… Expected `temperature trap`") vs `P4185R0.expected.md:39,79`. Impact: a model can pass by matching question wording to markdown without demonstrating table-coordinate comprehension (TabVerse cell lookup ~9.9% baseline in `05-web.md` Q2).
- [HIGH] Training-data contamination is uncontrolled for public WG21 papers. Evidence: `P4182R0.expected.md:3-4` (`document: P4182R0`, `date: 2026-04-17`, open-std links throughout); read-back uses 2026 frontier models (`P4185R0.validation.md:34`, gpt-5.5-medium). Impact: 8/8 or 9/9 can reflect memorized paper content, not consumption of the converted markdown artifact.
- [HIGH] Sample size cannot support a population claim over ~200 converted papers. Evidence: `00-baseline.md:61-64` (4 manual runs, 2 corpus members, 17 questions total); `00-baseline.md:77-78` (~200 papers in sighting run vs 2 comprehension members). Impact: treating 17/17 as confirmation of fleet LLM-readability is a selection-biased anecdote; Wilson 95% lower bound on per-question success with 17/17 is roughly 82%, and that assumes exchangeable trials (same markdown, overlapping runs).
- [MED] P4182 model and prompt provenance are incomplete versus the "2 models" framing. Evidence: `P4182R0.validation.md:25,43-47` (anonymous "subagent", no model id); `P4185R0.validation.md:34,53-54` (single named model, single run). Impact: cross-model replication—the usual antidote to judge variance (`05-web.md` Q4)—is not documented for the table-heavy anchor paper.
- [MED] External benchmarks do not use a one-shot LLM read-back to license deterministic gates. Evidence: olmOCR `05-web.md` Q1 (7,010 human-reviewed deterministic assertions over 1,403 PDFs; "Explicitly avoids LLM-as-judge"); RealDocBench `05-web.md` Q3 (1,356 field-level questions over 581 documents with a fixed extraction LLM on every parser output). Impact: the repo's read-back sits far below published verification loops; it cannot inherit olmOCR's rigor by analogy.
- [LOW] Order-fact documentation is internally inconsistent, weakening blind scoring auditability. Evidence: `P4182R0.validation.md:37` ("Abstract -> References"); `comprehension-poc-report.md:100` ("Abstract -> Motivation -> Platform schema -> Compiler schema -> Acknowledgments"); `P4182R0.facts.jsonl:6` (content-phrase sequence from abstract/motivation body). Impact: "deckungsgleich with verified facts" is not reproducible without knowing which rubric was applied.

## False-pass hypothesis
A 2026 frontier model receives `P4182R0.expected.md` whose front matter names `P4182R0` (`P4182R0.expected.md:3`), is asked Q7 with the exact row label from `P4182R0.facts.jsonl:7`, and answers "No" from training recall of the public WG21 table—or by locating the substring `(CUDA, SYCL) | No |` (`P4182R0.expected.md:55`)—without reliable pipe-table coordinate reasoning; the experiment records 8/8 and licenses the deterministic proxy anyway.

## False-fail hypothesis
none found (the read-back protocol has no documented false-fail path; all recorded runs passed, and questions skew toward copy-from-markdown tasks rather than paraphrase-sensitive probes).

## What would change my mind
A pre-registered holdout set (papers not in model training, or synthetic documents), archived full prompts and markdown bytes for every run, at least one blind LLM pass on deliberately corrupted `expected.md` that fails while `check_facts` also fails, and ≥30 papers with questions authored independently of fact `text`/`cell` strings—matching the scale and separation RealDocBench and olmOCR use (`05-web.md` Q1/Q3)—would flip the anchor from anecdote to evidence.
