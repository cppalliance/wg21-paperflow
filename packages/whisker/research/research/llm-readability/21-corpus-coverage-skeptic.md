# 21 - Corpus-Coverage-Skeptic

**Verdict:** usable-with-conditions — Lane 3's olmOCR-style architecture is the right pattern, but 17 verified facts on 2 near-perfect converts cannot represent a ~200-paper fleet or catch silent corruption in the paper classes WG21 actually ships.
**Confidence:** high

## Findings

- [CRITICAL] **Selection bias: both corpus members were chosen because they convert cleanly, not because they stress comprehension.** Evidence: `comprehension-poc-report.md:66-70` (P4182R0 picked after confirming it "converts close to 100%"; whisker ref-free `uni=0.954`, `qa=100` at `comprehension-poc-report.md:167-174`); P4185R0 added as the first `math`-type exerciser (`comprehension-poc-report.md:215`) with a single 9/9 read-back (`P4185R0.validation.md:53-54`), not because it failed other lanes. Impact: CI proves comprehension on the easy head of the distribution; the hard tail (~198 papers with zero facts, `00-baseline.md:77-78`) can regress without tripping Lane 3.

- [CRITICAL] **Six WG21 paper classes have zero comprehension coverage; any corruption in them ships silently.** Evidence: `00-baseline.md:77-79` (no multi-column, merged-cell, display-math, or code-heavy members); `00-baseline.md:80-83` (no `code`, `xref`, or `image-ref` fact types). Class-by-class: (1) **multi-column PDFs** — olmOCR allocates 884 reading-order tests across 231 multi-column PDFs (`05-web.md:27-28`); corpus has 1 `order` fact each on reflowed single-column markdown, no multi-column subject. (2) **merged-cell / nested tables** — olmOCR table tests require HTML for rowspan/colspan (`05-web.md:13-14`); whisker pipe-table neighbor checks (`facts.py:309-335`, cited in `00-baseline.md:46-49`) cannot express merged geometry; corpus tables are simple pipe grids (`P4182R0.facts.jsonl:7-8`, `P4185R0.facts.jsonl:5-6`). (3) **display math / aligned environments** — deferred explicitly (`comprehension-poc-report.md:219`); P4185R0's four `math` facts are inline `\(...\)` only (`P4185R0.facts.jsonl:1-4`), zero `\begin{align}` / display blocks in the substrate (repo grep on `P4185R0.expected.md`). (4) **code-heavy proposals** — P4185R0 carries ~95 fenced code blocks (~190 triple-backtick lines) but **0** code facts; P4182R0 has **0** fenced blocks (repo grep). (5) **footnote-dense papers** — zero `[^` footnote markers across `packages/whisker/corpus/` (repo grep); no footnote fact type. (6) **image-bearing papers** — zero `![` image refs in corpus (repo grep); Lane 3 has no image assertion surface (`00-baseline.md:80-83`). Impact: each class is a documented false-pass vector where Lane 2 fidelity and order-blind `unigram_coverage` stay green.

- [HIGH] **Fact density is orders of magnitude below the adopted benchmark.** Evidence: olmOCR-bench = 7,010 tests / 1,403 single-page PDFs ≈ **5.0 facts per page** (`05-web.md:18-20`); baseline counts **17 verified facts on 2 papers** (`00-baseline.md:53-57`). Per-paper: 8.5 facts/paper average vs olmOCR's per-source stratification (e.g. 1,020 table tests / 188 table PDFs ≈ 5.4/page-class, `05-web.md:27-28`). Per-line on committed substrates: P4182R0 8/411 lines = 0.019 facts/line (`comprehension-poc-report.md:76`, line count from `P4182R0.expected.md`); P4185R0 9/2180 = 0.004 (`P4185R0.expected.md`); combined **0.0066 facts/line**. Rough page proxy (~50 lines/page): P4182R0 ≈ **1.0 facts/page** (5× below olmOCR); P4185R0 ≈ **0.20 facts/page** (25× below). Impact: even perfect pass rate on 17 facts cannot bound fleet error rate; TabVerse reports cell-lookup structural accuracy ~9.9% (`05-web.md:46-48`), a regime our 4 table facts (2 per paper) do not sample.

- [HIGH] **Population coverage is 1% of the converted fleet with no stratification.** Evidence: **2 / ~196** adjudicated papers in the tapetum sighting run (`00-baseline.md:65-66`, `tapetum-sighting-run-2026-07-01.md:17-18`); **2 / 201** candidates. Impact: Wilson-style extrapolation from 17/17 read-back successes (`00-baseline.md:61-64`) cannot certify the other ~98% of papers; comprehension QA is structurally optional for non-corpus members (`facts.py:128-130` vacuous pass when no verified facts, per `00-baseline.md:80-83`).

- [MED] **Issue #254's scale question remains unanswered in-repo.** Evidence: driving issue `#254` asks whether converted output is "read -> understood -> correct" fleet-wide (`00-baseline.md:15-17`); the POC closes methodology on 2 papers but lists only qualitative deferrals (`comprehension-poc-report.md:217-227`) — no paper count, no facts-per-paper target, no stratification plan tied to comprehension. Adjacent #277 research proposes a **labeled mini-eval of 30–50 WG21 papers** for tapetum calibration (`packages/whisker/research/deepseek-v4-pro/14-tapetum-lane-fit.md:69`, `SYNTHESIS.md:43`); whisker's own `CLAUDE.md:310-311` repeats "label 30-50 papers" for threshold calibration but not yet for Lane 3 corpus design. **Proposed defensible first signal:** a **stratified comprehension mini-corpus of 30–50 papers** drawn from the ~200-paper fleet (not near-100% converts), with **≥8–10 verified facts per paper** covering at least one assertion each from `{table, math, order, present}` plus **≥2 load-bearing checks in the paper's dominant risk class** (code block identifier + neighbor for code-heavy; multi-column `order` chain for reflow papers; display-math surface check for math papers), **≥5 papers per zero-coverage class above**, and a **holdout 20%** for blind read-back without fact-id leakage. Target macro: ≥90% verified-fact pass on live `paperstore` markdown (not snapshot-only), matching the #277 mini-eval's labeled-audit bar (`SYNTHESIS.md:43`). This yields ~300–500 fleet facts vs today's 17 — still 14× below olmOCR's 7,010, but enough for a first measured false-pass upper bound per class.

- [MED] **Authoring + verifying one paper's facts is human-source-bound; POC scale implies multi-hour marginal cost per member.** Evidence: provenance requires reading the **SOURCE pdf/html**, not converter output (`corpus/README.md:35-37`); separate **draft → verified** promotion (`corpus/README.md:48-49`, `comprehension-poc-report.md:130-131`); each verified fact manually mapped to a source location (`comprehension-poc-report.md:91-102` table). Delivered POC: **17 facts across 2 papers** with one-time read-back validation docs (`comprehension-poc-report.md:155-163`, `P4185R0.validation.md:33-37`); olmOCR scales authorship as **"LLM-assisted then human-reviewed"** (`05-web.md:17`). P4185R0 — **2180 lines**, ~95 code fences, **9 facts** — shows the practical ratio: ~4.1 facts per 1,000 lines of substrate, implying **~8–10 verified facts ≈ one focused human session per medium paper** (source read + JSONL authoring + verify pass + canary check), and **~2–4× that for adversarial strata** where table/code facts require hunting failure modes the converter already hid. `CLAUDE.md:43-44` claims facts are "cheap"; the POC evidence supports "cheap per fact type once engineered," not "cheap to cover a code-heavy 2,000-line proposal." Growth from 2 → 30 stratified papers is therefore **~28 human authoring cycles** before the first statistically meaningful fleet signal, absent LLM-assisted fact drafting.

- [LOW] **CI substrate mismatch widens the representativeness gap.** Evidence: hermetic gate reads frozen `corpus/<pid>.expected.md` (`00-baseline.md:58-59`, `test_comprehension_corpus.py` cited in baseline); live `whisker facts` reads paperstore (`00-baseline.md:36-38`). Impact: even perfect corpus coverage would not gate today's converter output until facts run against live markdown or snapshots are continuously rebased.

## False-pass hypothesis

A code-heavy WG21 proposal (dominant genre: ` ```cpp ` blocks, `requires` clauses, cross-paper `[[P####Rx]]` links) converts with a transposed straw-poll table row and a garbled `requires` expression that preserves all word tokens: it **`pass`es ref-free whisker** (`unigram_coverage` order-invariant, `00-baseline.md:71-88`), has **no `<pid>.facts.jsonl`**, so Lane 3 is vacuously green (`facts.py:128-130`), and none of the 17 corpus facts (zero `code`/`xref` types, `00-baseline.md:80-83`) fire — dissect reads wrong poll numbers and a syntactically invalid constraint as ground truth.

## False-fail hypothesis

A shippable conversion fails a hand-authored `table` fact because the human verified the cell text against the PDF while the markdown uses a Unicode cross mark (`✗` in `P4185R0.facts.jsonl:6`) that normalizes differently under `_norm_cell` than the author's source reading; with default `max_diffs: 0` (`corpus/README.md:50-55`), the gate rejects readable markdown on a normalization edge not exercised by the current 4 table facts.

## What would change my mind

A stratified **30–50 paper** comprehension mini-corpus (per the proposed target above) with **≥300 verified facts**, **≥5 papers per previously zero-coverage class**, blind read-back on a holdout at **≥90%** on the production self-hosted model stack, and a measured report of **how many of the 163 ref-free passes** (`00-baseline.md:77-78` context) fail at least one verified `table`/`math`/`order` fact when authored from source — demonstrating a finite false-pass upper bound instead of the current **2/196 (1%)** paper coverage.
