# 18 - Table-Semantics-Auditor

**Verdict:** usable-with-conditions (+ Lane 3 table facts work on simple pipe grids but miss entire emission classes and parser edge cases that olmOCR-bench explicitly covers with HTML.)
**Confidence:** high

## Findings
- [CRITICAL] `_parse_pipe_tables` is the sole table input to `_check_table`; emitted HTML tables are invisible to Lane 3. Evidence: `packages/whisker/src/whisker/facts.py:261-295` (pipe-only parser, no `<table` handling); `packages/tomd/src/tomd/lib/pdf/table.py:124-133` (`CODE_COMPARISON`, `SPEC_TABLE`, `NB_BALLOT` → `html_table`); `packages/tomd/src/tomd/lib/pdf/table.py:2410-2419` (any newline in a pipe-eligible cell forces `HTML_TABLE`); `packages/whisker/corpus/P4185R0.expected.md:760-784` (committed corpus member contains `<!-- tomd:mixed-table -->` + full HTML table with `<br/>` code cells, zero table facts). Impact: Tony Tables, spec/requirement tables, NB-ballot grids, and mixed-code tables can corrupt silently while all verified table facts pass; directly contradicts olmOCR-bench's "HTML needed for rowspan/colspan" design (https://github.com/allenai/olmocr/tree/main/olmocr/bench, 05-web Q1).
- [HIGH] `_split_cells` naively splits on raw `|` with no markdown unescape, so `\|`-escaped cell content becomes extra phantom columns and neighbor checks attach to the wrong grid coordinates. Evidence: `packages/whisker/src/whisker/facts.py:252-258`; `packages/tomd/src/tomd/lib/html/render.py:1065,1295` (tomd emits `\|` escapes); `packages/tomd/tests/test_html_render.py:692-702`; `packages/whisker/src/whisker/tapetum_llm/tapetum_llm.md:77` (documents pipe-in-cell as a known failure mode). Impact: false-fail on correct conversions with literal pipes in cells; false-pass if corruption happens to preserve the mis-split neighbor the fact accidentally reads.
- [HIGH] Cell location is first document-order exact match with no table index or `(row,col)` disambiguation. Evidence: `packages/whisker/src/whisker/facts.py:313-323`; `00-baseline.md:49` ("First-match-wins cell location"). Impact: duplicate cell text across tables or rows (P4182R0 has many `No` cells: `P4182R0.expected.md:53-55,191-192,...`) binds the first occurrence; a fact on a later duplicate checks neighbors in the wrong table/row and can pass after a swap that broke the intended row.
- [HIGH] `heading` neighbor is always `grid[0][c]` (first row, same column), so multi-row header blocks and denormalized colspan headers misrepresent semantic column labels. Evidence: `packages/whisker/src/whisker/facts.py:300-301`; `packages/tomd/src/tomd/lib/html/render.py:1076-1080` (colspan fills all spanned columns with duplicated header text); `packages/tomd/tests/test_html_render.py:544-554` (`colspan="2"` → `| Header | Header |`). Impact: facts authored against PDF/HTML source headers can fail on correct denormalized pipe output, or pass when row-0 text drifts while data cells stay plausible; olmOCR uses explicit neighbor relations partly because pipe markdown cannot preserve span semantics (05-web Q1).
- [MED] `<br>` handling is asymmetric across the stack: single-`<br>` cells collapse to spaces in pipe tables, but 2+ `<br>` cells route to HTML tables Lane 3 never parses; PDF pipe emit also flattens newlines to spaces. Evidence: `packages/tomd/src/tomd/lib/html/render.py:974-984,1280-1281`; `packages/tomd/tests/test_html_render.py:602-627`; `packages/tomd/src/tomd/lib/pdf/emit.py:907-919` (`replace("\n", " ")`). Impact: intra-cell line structure is lossy or untested depending on emission path; `_norm_cell` (`facts.py:184-185`) cannot recover `<br>` semantics because the checker never sees HTML cells.
- [MED] Corpus table sampling is far below external benchmarks and the measured LLM cell-lookup collapse rate. Evidence: `00-baseline.md:53-57` (2 corpus papers, 4 verified table facts total: 2 in P4182R0, 2 in P4185R0); `00-baseline.md:78` (no adversarial merged/nested table paper); https://arxiv.org/html/2606.09578v1 (TabVerse mean cell lookup 9.9%, row retrieval 5.0%, 05-web Q2); https://github.com/allenai/olmocr/tree/main/olmocr/bench (1,020 table tests over 188 table PDFs ≈ 5.4 tests/table-PDF, 05-web Q1). Impact: 2 pipe-table spot checks per paper cannot bound the failure modes TabVerse and olmOCR-bench were built to catch; P4182 blind read-back 8/8 (`00-baseline.md:61-64`) validates only the authored fact set, not table-class coverage.
- [LOW] P4182R0/P4185R0 table facts exercise only clean single-header pipe matrices, not the risky paths above. Evidence: `packages/whisker/corpus/P4182R0.facts.jsonl:7-8` (unique cells `GPU device code (CUDA, SYCL)`, `Arenas common` with single-row `Category`/`Alloc` headings); `packages/whisker/corpus/P4185R0.facts.jsonl:5-6` (facts target lines 674-682 pipe grid, not the HTML table at 760+); `packages/whisker/corpus/P4182R0.expected.md:47-55` (simple pipe, no spans). Impact: CI canary (`test_comprehension_corpus.py:77-95`) proves one cell scramble fails but does not exercise HTML-table blindness or `\|` split corruption.

## False-pass hypothesis
Swap the `Coro` column values between the "Lightweight RTOS" and "GPU device code" rows in P4182R0's first matrix (`P4182R0.expected.md:53-55`) while leaving the uniquely identified cells (`GPU device code (CUDA, SYCL)`, `Arenas common`) and their authored neighbors intact: both verified table facts still pass (`facts.py:313-335`), but a downstream LLM answering "Does GPU device code support coroutines?" reads the wrong column for every non-fact-checked row.

## False-fail hypothesis
A WG21 HTML paper emits a denormalized pipe table where a colspan header duplicated across columns reads `| Requirements | Requirements |` (`test_html_render.py:544-554`). A human-verified fact asserts `cell="expr"`, `heading="return type"` (second header row in source HTML): `_neighbor_value(..., "heading")` returns `grid[0][c]` (`facts.py:300-301`) which is the first header row text, not the semantic column label, so a correct conversion fails the fact.

## What would change my mind
A corpus member whose primary table is emitted as `html_table` (Tony/spec/NB-ballot) with ≥5 verified table facts including rowspan/colspan or multi-`<br>` cells, parsed by an HTML-aware grid builder (or olmOCR-compatible HTML neighbor checks), passing in CI and failing on a deliberate cell-neighbor scramble in that HTML table.
