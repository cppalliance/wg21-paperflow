# 23 - Fact-Assertion-Design

**Verdict:** usable-with-conditions — the five olmOCR-aligned fact types cover tables, math, and coarse prose/order, but four tapetum_llm axes (code, stable_names, xrefs, structure) and olmOCR baseline checks have no assertable Lane 3 counterpart, leaving WG21's highest-value payloads under-gated.
**Confidence:** high

## Findings

- [CRITICAL] No `code` fact type while tapetum_llm adjudicates a dedicated **code** axis (`models.py:30-37`, `tapetum_llm.md:49-50`). WG21 papers are code-heavy; Lane 3 cannot assert fenced-block fidelity, indentation, or operator correctness. Impact: semantic code corruption is an explicit false-pass class the deterministic gate cannot express.
- [CRITICAL] `present`/`absent`/`order` facts evaluate on `normalized_text`, which runs `clean_string` and keeps only alnum + CJK (`facts.py:342-358`, `metrics.py:115-126`, `metrics.py:338-340`). Runtime verification at this SHA: `normalized_text('x != y') == normalized_text('x == y') == 'xy'`; `normalized_text('C++') == 'C'`. Impact: operator swaps, `requires` clause corruption, and `C++` vs `C` distinctions are indistinguishable to present/absent/order facts — the core WG21 payload can pass while wrong.
- [HIGH] No `xref` or `stable_names` fact types while tapetum_llm axes 3 and 5 cover `[P1234R5]` paper refs and `[expr.prim]` / `[container.requirements]` labels (`models.py:30-37`, `tapetum_llm.md:50-52`). Baseline finding #3 confirms the gap (`00-baseline.md:80-83`). Impact: wrong revision letters and broken standard cross-refs have no deterministic comprehension assertion; only the opt-in LLM lane can catch them.
- [HIGH] No `image-ref` fact type while the conversion contract requires `![alt](path)` survival with caption-derived alt (`tapetum_llm.md:42`). Baseline finding #3 lists image-ref alongside code and xref as uncovered (`00-baseline.md:80-83`). Impact: dropped figures, wrong paths, or empty alt text cannot be gated in Lane 3; downstream dissect/agora lose diagram context silently.
- [HIGH] No heading-structure fact type; `order` facts only assert strictly increasing positions of normalized text snippets (`facts.py:353-365`), not parent/child hierarchy. Lane 2 `mhs` compares candidate to a reference document (`metrics.py:678-693`, `bench.py:228`) — resemblance, not an assertable fact. The POC blind read-back found `### 1. Disclosure` nested under Revision History instead of its own `##` section and noted it "could become a tomd observation or an `order`/structure fact" — it could not be expressed (`comprehension-poc-report.md:161-163`, `:226-227`). Impact: section-tree defects (wrong depth, permuted siblings) pass Lane 3 when anchor phrases and linear order still hold.
- [MED] olmOCR-bench's per-page **Baseline** checks (non-empty output, no repeating n-grams, no unexpected CJK/emoji scripts; `05-web.md:15-16`, `:38-39`) have no Lane 3 equivalent. `gates.py:153-162` covers structural non-emptiness and fence/table well-formedness only; `mojibake_count` is computed from tomd QA and reported on `WhiskerResult` (`score.py:66`, `:248`) but never consumed by `check_facts` or hard gates — it only triggers tapetum candidate selection (`adjudicate.py:103-104`, `tapetum_llm/constants.py:62-64`). Impact: repetition loops and script garbage that olmOCR auto-tests per page can pass whisker comprehension unchanged.
- [MED] Math facts use `_math_surface` (pylatexenc fold, keeps `^`/`_`/`=`; `facts.py:173-181`) rather than olmOCR's KaTeX bounding-box layout match (`05-web.md:20-21`). Corpus has 4 math facts on one paper, zero display/aligned-environment coverage (`00-baseline.md:54-57`, `:79`). Impact: layout-sensitive formula corruption olmOCR catches may pass whisker math facts; math is olmOCR's largest class (3,385 / 7,010 tests per `05-web.md:20`).
- [LOW] Provenance workflow (`checked: verified` gates; `facts.py:68`, `:124-130`) scales linearly but is labor-bound: 17 verified facts across 2 corpus members (~8–9 each; `00-baseline.md:53-57`) vs ~200 converted papers (`00-baseline.md:77-79`). olmOCR used LLM-assisted authoring then human review (`05-web.md:17`). Impact: reaching 50 papers at current density (~400–450 human-verified facts) is feasible but unproven without tooling; draft facts are evaluated but advisory (`facts.py:379-388`), so blessing cost is the bottleneck, not schema size.

## False-pass hypothesis

A wording paper corrupts `requires x == y` to `requires x != y` inside a fenced `cpp` block. A `present` fact on the phrase `requires x == y` (or even separate present facts on identifiers) passes because `normalized_text` collapses both forms to `requiresxy` (`facts.py:342-343`, `metrics.py:118-126`). Lane 3 reports pass; tapetum **code** axis would flag it; no fact type can assert the operator.

## False-fail hypothesis

An `order` fact listing section titles that also appear in a stripped TOC remnant or front-matter boilerplate could fail on position ordering when the prose sections are correct but duplicate headings exist earlier in the document (`facts.py:353-365` uses first-match positions with no heading-level or fence awareness). No corpus member currently exercises this; hypothesis only.

## What would change my mind

A `code` fact type (or `present`/`absent` with a `surface: raw|normalized|code` selector matching anchors' raw mode at `anchors.py:121-124`) validated on one code-heavy WG21 paper in the comprehension corpus, with a canary proving operator-swap detection — demonstrating Lane 3 can gate the failure class `present` currently cannot distinguish.
