# 09 - Error-Handling-Robustness

**Verdict:** usable-with-conditions — Lane 3 fact loading fails loud on malformed records and callers consistently use `utf-8-sig`, but batch scoring and tapetum advisory paths leave audit holes where failures can disappear from machine-readable output or masquerade as ordinary `review`.
**Confidence:** medium

## Findings
- [CRITICAL] `whisker --all` drops errored papers from `report.json`, sidecars, and `--json` stdout while still exiting on the verdicts of papers that did score; only the human footer mentions `N errored`. Evidence: `__main__.py:218-223`, `__main__.py:228-251`, `__main__.py:259-261`, `report.py:242-243`. Impact: a broken conversion that trips an upstream exception vanishes from the machine-readable batch artifact; an operator or downstream script counting sidecars can treat "not present" as "never run" or implicitly OK, which is a silent coverage hole against ~200 converted papers (00-baseline:77-78).
- [HIGH] Missing `<pid>.facts.jsonl` is a silent Lane 3 skip, not a fail: guard and `whisker facts` only glob existing files and never require comprehension coverage per corpus member. Evidence: `__main__.py:495-507`, `__main__.py:706-718`, `facts.py:129-130`. Impact: a paper in the guard corpus with `*.gt.md` but no facts file passes Lane 3 vacuously (`FactReport.passed` is True when zero verified facts); comprehension QA can read green while exercising zero assertions (00-baseline:77-78, corpus size 2).
- [HIGH] The tapetum `_result is None` fallback persists as a normal advisory sidecar: `suggested_verdict=review`, `confidence=0.0`, empty axis findings, distinguishable only by `primary_concern="pipeline did not produce a result"`. Evidence: `adjudicate.py:217-219`, `adjudicate.py:427-439`, `cli.py:207-216`, `inspect_report.py:55-67`. Impact: batch footer increments `review`, inspect report renders `(agree, confidence 0.00)` like a content-driven demotion; pipeline abort is not tagged `error`/`failed`, so it can masquerade as a real verdict downstream (05-web.md Q4 Overconfidence in LLM-as-a-Judge supports confidence-floor demotion, but here 0.0 review is structurally identical to low-confidence content review).
- [MED] Partial-read protection is narrower than documented: `state.partial` is set only by `chunk_markdown` hard-split (`chunking.py:76-78`, `adjudicate.py:178-185`), while comments also claim "chunk call failed" (`adjudicate.py:147-148`); a failed chunk LLM call raises through `dispatch()` and is handled as CLI `error`, not partial+review. Decide only demotes `pass` to `review` on partial (`adjudicate.py:245-246`), not `fail`; an oversized hard-split paper could still surface `suggested_verdict=fail` despite incomplete reads. Impact: partial coverage can still read as a hard advisory fail; no test covers `state.partial` demotion (`test_tapetum_llm.py` has chunking tests but none for decide+partial).
- [MED] `aggregate_adjudications([])` returns `verdict=review`, `confidence=0.0` with concern `"paper produced no readable chunks"` (`chunking.py:167-176`), same shape as a substantive review. Impact: empty chunk aggregation is indistinguishable from a low-confidence human-facing review in sidecar JSON and inspect output.
- [LOW] BOM handling is delegated to callers, not the loader: `parse_facts_jsonl` uses plain `json.loads` on stripped lines (`facts.py:485-492`); all CLI/guard/corpus paths read with `encoding="utf-8-sig"` (`__main__.py:506`, `__main__.py:714`, `test_comprehension_corpus.py:63`). Impact: direct library callers using `utf-8` on Windows-edited JSONL get `ValueError` on line 1 (fail-loud, not silent loss); olmOCR bench normalizes NFC at scoring time (05-web.md Q1 olmOCR paper), whisker does not NFC-normalize fact text in the loader.
- [LOW] Malformed facts files fail loud and abort the command (good): `ValueError` with 1-based line numbers (`facts.py:491-492`), `whisker facts` returns `EXIT_ERROR` on first invalid file (`__main__.py:715-717`), `whisker guard` same (`__main__.py:449-451`). Impact: typos cannot silently disable comprehension checks; contrasts favorably with silent skip on missing files.

## False-pass hypothesis
A guard-corpus paper staged in the paperstore with `PXXXX.gt.md` but no `PXXXX.facts.jsonl`: Lane 2 metrics and anchors may run, Lane 3 never executes (`__main__.py:501-507`), and `FactReport.passed` would be vacuously True even if a facts file existed with only `checked: draft` entries (`facts.py:129-130`). Separately, `whisker --all --json` after one paper raises in `score_paper`: the errored PID is absent from the JSON array (`__main__.py:218-261`) while siblings may show `pass`, so automated consumers can treat the batch as fully scored.

## False-fail hypothesis
Authoring `*.facts.jsonl` with a UTF-8 BOM but feeding `parse_facts_jsonl(path.read_text(encoding="utf-8"))` (not `utf-8-sig`) raises `ValueError: facts line 1: invalid JSON` (`facts.py:491-492`); the check is disabled until encoding is fixed. This is loud, not silent, but a portability footgun on Windows-edited JSONL unless every caller keeps using `utf-8-sig`.

## What would change my mind
A batch run artifact (sidecar stub or explicit `status: error` row per PID) proving every requested paper appears in `report.json`/`--json` with scored, skipped, or errored status — and a tapetum sidecar field (e.g. `pipeline_status: aborted`) consumed by `--inspect` — would flip this to **usable** for the batch/advisory lanes while keeping Lane 3 loader behavior as-is.
