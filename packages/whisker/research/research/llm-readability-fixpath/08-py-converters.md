# 08 - python-converters+pandoc

**Verdict:** usable-with-conditions — converter repos are the gold standard for Lane 1 golden/regression harness design, but none verify LLM comprehension; our `facts.py` / `tables.py` / `corpus_tools.py` fix-path is strictly ahead on discrete fact assertions and table-neighbor geometry.
**Confidence:** high

## Findings

- [HIGH] **Pandoc golden discipline (copy for Lane 1 wave, not Lane 3).** Three parallel layers: auto-discovered command goldens (`test/Tests/Command.hs:83-87`, `117-118`), reader/writer `.native` golden pairs via `goldenTest` with `\r` stripping and lawful normalizers (`test/Tests/Old.hs:380-403`, `test/Tests/Helpers.hs:70-85`), and QuickCheck round-trip laws on **internal** representations (`test/Tests/Writers/Native.hs:10-12`, `test/Tests/XML.hs:24-25`). Refresh is explicit `--accept`, never CI-auto (`Makefile:50-51`). Whisker should adopt fail-closed fixture discovery, documented pre-diff normalization at the golden boundary, and multi-entry-point parity (library + CLI); markdown-output round-trip is **explicitly abandoned** (`test/Tests/Readers/Markdown.hs:452-455`: "the round-trip properties frequently fail"), so WG21 goldens must stay snapshot-based, not parse→render→parse identity.
  Impact: shapes the planned golden-file wave; do not treat pandoc RT as a comprehension substitute (00-baseline Lane 3 remains authoritative).

- [HIGH] **Fact-assertion analog: only markitdown uses discrete checks; others gate whole strings.** Markitdown `FileTestVector` carries `must_include` / `must_not_include` (`packages/markitdown/tests/_test_vectors.py:11-12`) asserted per conversion path (`test_module_vectors.py:65-68`); PDF suite adds monotonic `find()` section-order chains and negative structural caps (`test_pdf_tables.py:225-271`, `287-291`, `609-618`). html2text, markdownify, and htmbench use **full-output** equality: paired `.html`/`.md` after `cleanup_eol` + `.rstrip()` (`html2text/test/test_html2text.py:14-21`, `191`), inline `assert md(html) == '...'` (`markdownify/tests/test_tables.py:288-289`), or oracle snapshot byte-compare (`html-to-markdown-py/tools/benchmark-harness/src/oracle.rs:161-168`). Whisker `facts.py` is stronger than all of them on table semantics: all-occurrence cell match + directional neighbors (`facts.py:341-369`, `tables.py:44-77`) vs markitdown's "substring appears somewhere" or goldens that encode one blessed string.
  Impact: markitdown's order/substring pattern complements Lane 3; whole-output goldens alone cannot catch cell-neighbor swaps that leave document-level strings intact.

- [MED] **Property-based testing: pandoc QuickCheck only; Python repos have none; htmb uses deterministic properties.** Pandoc: `testProperty "p_write_rt"` on Native AST (`Native.hs:10-12`), XML RT (`XML.hs:24-25`), HTML RT with sanitized stubs for tables/code/raw (`HTML.hs:33-40`, `47-56`, `141-144`), annotated-table invariants (`AnnotatedTable.hs:137-151`). Zero `hypothesis` / QuickCheck in html2text, markdownify, markitdown (grep). htmbench `tier1_property_test.rs:1-54` is 50+ hand-curated snippets with bail-or-match Tier1==Tier2, not fuzz. Fuzzing `_present_within` / pipe-table parsers (`facts.py:323-325`, `tables.py:44-77`) would be **novel** in this cohort; pandoc's own disabled markdown QC (`Markdown.hs:452-455`) warns that lossy markdown RT properties are unstable on real dialects.
  Impact: a small Hypothesis suite on table-separator regex and `_present_within` boundary edits is worth adding to whisker tests; do not expect converter repos to supply a template.

- [MED] **Corpus selection: adversarial strata + issue-tracked fixtures; gaps vs `corpus_tools.py`.** htmbench groups fixtures by size and failure mode (`fixtures/groups.toml:1-10`, `114-134`: `spec_rules`, `adversarial`, `fallthrough_bare_lt`, `fallthrough_custom_elements`) and surveys feature coverage (`survey.rs:16-67`: CDATA, custom elements, bare `<`, `table_no_tbody`). html2text encodes option permutations in filenames (`test_html2text.py:32-151`: `table_bypass`, `pad_table`, `unicode_snob`). markdownify's inline table battery covers colspan, missing head, caption, thead/tbody variants (`test_tables.py:288-321`) but is not a committed corpus. `corpus_tools.py` strata (`corpus_tools.py:46-51`, `70-94`) cover pipe/HTML tables, display math, code fences, `[^footnote]` refs, images — but miss: **nested tables**, **definition lists** (pandoc tests extensively at `Markdown.hs:456-496`), **footnote body/syntax variants** (markitdown/pandoc footnote writers; we only count ref markers), **multi-column / reading-order stress** (markitdown PDF order tests; no WG21 stratum), **colspan/rowspan** (markdownify tests; not a stratum), **CDATA / custom elements / bare `<`** (htmb survey; absent from `classify_paper`).
  Impact: golden wave and comprehension corpus should add strata for nested/colspan tables and definition lists before claiming WG21 edge coverage.

- [LOW] **Regression provenance from git log (shallow clones).** Local pandoc/markitdown clones retain minimal history (pandoc: one commit touching `test/`; markitdown: version bump `#1914`). Regression catching is evidenced by **test names and structure**, not recent commit messages: pandoc command tests label stderr/exit (`Command.hs:28-31`, `67-69`); markitdown PDF tests name sections explicitly (`test_pdf_tables.py:252-254`: assert each section `!= -1`); html2text issue-linked state tests (`test_memleak.py`, `test_newlines_on_multiple_calls.py` per prior scan). Whole-output goldens catch formatting regressions when blessed; markitdown order chains catch section reordering that substring-only checks might miss if all anchors still present.
  Impact: adopt naming + layered gates; do not rely on upstream git archaeology in shallow vendored clones.

## False-pass hypothesis

Pandoc HTML round-trip replaces `Table{}` blocks with the placeholder `"table block was here"` before RT (`HTML.hs:40`), so table markdown consumability can regress while QC stays green. Markitdown `must_include` passes if a substring appears anywhere in the document (`test_module_vectors.py:65-66`) with no cell-neighbor or positional constraint — a decoy table row could satisfy a table fact analog.

## False-fail hypothesis

html2text and pandoc command goldens require byte-exact stdout after normalization (`test_html2text.py:191`, `Command.hs:117-118`) — benign reflow or whitespace policy changes fail despite semantically preserved content that whisker `normalized_text` / metric slack would accept. htmbench oracle treats known panics as skip-not-fail (`oracle.rs:151-158`), which avoids noise but can mask unfixed crashes on `kimbrain.html` / `rbloggers.html`.

## Adoption candidate

**Markitdown monotonic section-order gate** — `test_pdf_tables.py:225-271`: collect anchor positions via `find()` / regex, assert strict increasing order after backslash strip. License: MIT (Microsoft). Maps directly to whisker `order` facts and `anchors.py` `ordered` chains; weaker than `facts.py` table neighbors but highest-leverage **portable** pattern in the Python cohort. **Not adoptable verbatim from pandoc:** `Command.hs` / `Helpers.hs` golden harness is GPL-2.0 (`Command.hs:5`, `Helpers.hs:7`); study the pattern, reimplement in whisker under BSL.

## What would change my mind

Any of these repos shipping a committed corpus of **human-verified** discrete facts (table cell + neighbor, math surface, reading order) on real technical documents at scale — matching olmOCR / whisker Lane 3 — would flip the verdict to "equal" on comprehension and make their QA directly portable.
