# 05 - nougat+grobid

**Verdict:** usable-with-conditions — Our Lane 3 implementation (discrete verified facts in `facts.py` + blind readback in `readback.py`) is strictly better for LLM-readability verification; Nougat and GROBID contribute bench/guard regression patterns only, not comprehension proof.
**Confidence:** high (Nougat `metrics.py` read in clone); medium (GROBID Java eval engine absent from shallow clone, anchored via committed `doc/` + prior scan cross-check at `research/llm-readability/repo-scan/grobid.md`)

## Findings

- [CRITICAL] Nougat math scoring is page-level gold-string similarity, never per-formula structural compare. Evidence: `split_text` regex-strips inline `\(...\)`, display `\[...\]`, and `\begin{tabular}` into separate channels (`packages/whisker/research/repos/nougat/nougat/metrics.py:22-24,63-83`); `compute_metrics` returns char-NED `edit_distance/max_len`, BLEU, METEOR, and word-**set** P/R/F1 (`:27-44`); `get_metrics` runs that per page-pair and `__main__` prints independent corpus means for Text/Math/Tables, never merged (`:86-96,104-117`). Impact: a scrambled-order math channel with all tokens present can score high on set-F1 while failing comprehension; nothing here beats whisker `_math_surface` (pylatexenc fold + display-math delimiter fold + backslash undoubling at `facts.py:190-254`) plus `_present_within` structural substring DP (`facts.py:275-326,428-430`).

- [HIGH] GROBID field-level P/R/F1 is RealDocBench-shaped slot recovery over TEI/XML gold, not markdown comprehension. Evidence: `FieldSpecification` XPath fields (title/authors/abstract, prior scan `FieldSpecification.java:36-80`); four parallel matchers (strict/soft/Levenshtein≥0.8/Ratcliff≥0.95, `EndToEndEvaluation.java:453-461,66-67` per prior scan); committed PMC tables show per-field micro/macro P/R/F1 with support (`doc/benchmarks/Benchmarking-pmc.md:42-51,68-81`) and instance-level all-fields-correct recall (`:98-110`). Impact: closer to whisker Lane 2 fidelity + typed checks than Lane 3; GROBID cannot gate "can an LLM recover table cell (row 3, col 2)" the way `facts.py` `table` neighbor checks (`facts.py:449-450`, `tables.py:44-135`) do.

- [HIGH] Neither repo implements blind LLM readback; whisker is alone on that axis. Evidence: Nougat scan confirms zero QA/LLM-judge modules (`research/llm-readability/repo-scan/nougat.md:29`); GROBID documents Markdown/JSON only as optional lossy client-side projection "for feeding an LLM" with zero in-repo verification (`doc/Grobid-service.md:137-143`, `doc/Frequently-asked-questions.md:276-278`). Impact: `readback.py` question generation without answer lexemes (`:106-177`), deterministic `_evaluate_answer` per fact type (`:180-205`), and `--corrupt` adversarial control (`:284,297-313`) have no analog in either target repo; 00-baseline live 37/37 readback after fix-path fixes is evidence Nougat/GROBID metrics would not have caught display-math/backslash/table-question bugs.

- [MED] GROBID corpus scales via publisher gold XML; whisker corpus_tools scales authoring, not verification throughput. Evidence: GROBID maintains thousands of annotated docs from HuggingFace datasets (`doc/End-to-end-evaluation.md:15-39`, one-dir-per-article PDF+gold XML at `:49-67`, CC-BY sub-structure annotations at `:15-16`); eval is manual Gradle ritual with committed snapshot tables (`:78-88`, `doc/benchmarks/Benchmarking-pmc.md:1-32`). Whisker: `classify_paper` strata heuristics + `stratify_candidates` zero-coverage picker + `draft_facts_scaffold` draft skeletons (`corpus_tools.py:70-259`); 00-baseline: 5 papers, 37 gated verified facts. Impact: GROBID gold scales when external publisher XML exists; whisker human `checked: verified` blessing (`facts.py:25-28,82-84`) remains the bottleneck — `draft_facts_scaffold` bootstraps but does not replace source-PDF verification.

- [MED] Field-level scoring would add regression visibility to whisker facts, not comprehension depth. Evidence: GROBID reports per-label P/R/F1 + support (`Benchmarking-pmc.md:42-48`) and instance-level strict recall (`:98-102`); whisker `FactReport.by_type` macro-averages pass_rate per assertion type only (`facts.py:156-173`), conjunctive per-fact pass/fail (`:474-490`). Impact: adopting GROBID-style per-type P/R/F1 + support counts in guard reports would localize collapses (e.g. `table` facts degrading while `present` holds) without replacing discrete neighbor/math assertions; multi-tier fuzzy match (Levenshtein 0.8 after normalization, `End-to-end-evaluation.md:118-128`) could reduce formatting false-fails on `present` facts with `max_diffs=0`.

- [LOW] Nougat `minlen=4` eligibility gate is portable to whisker bench. Evidence: `compute_metrics` returns `{}` when pred or gt length `< 4`, omitted from stratum averages (`nougat/metrics.py:27-30,93-96`). Impact: prevents empty/short conversions from polluting math/table axis means; whisker already null-eligible axes in bench but has no analogous content-floor on fact types.

- [LOW] GROBID explicitly disclaims absolute downstream usability scoring. Evidence: `doc/End-to-end-evaluation.md:187` — eval tracks version-to-version progress, not "how good GROBID will extract valid and usable structures from PDF." Impact: aligns with 00-baseline framing: GROBID P/R/F1 is regression telemetry, not LLM-consumability proof (same category as whisker Lane 2 `nid`/`teds`).

## False-pass hypothesis

Nougat Math-channel set-F1 passes when all formula tokens appear anywhere in the concatenated math block regardless of order or structure: `reference = set(gt.split())` / `hypothesis = set(pred.split())` (`nougat/metrics.py:39-43`) on the channel produced by joining all `\(...\)` and `\[...\]` matches per page (`:72-79`). A conversion that permutes subexpressions within a page's math channel keeps high F1 while `_math_surface` + `_present_within` on a single `math` fact (`facts.py:237-254,428-430`) would fail if exponent/subscript structure diverges.

## False-fail hypothesis

GROBID strict field match fails on formatting-only churn that whisker `present` facts with `max_diffs > 0` or `_math_surface` display-math fold would pass: GROBID strict tier requires exact match after `basicNormalization` (`End-to-end-evaluation.md:120-121`; soft tier only strips punctuation/case/space at `:122-123`), while whisker folds `\[...\]` to `\(...\)` before unicode fold (`facts.py:213-234`) and allows bounded substring edits (`facts.py:323-326`). A formula rendered inline vs display would false-fail GROBID's strict slot compare but pass whisker `math` facts after `_fold_display_math_delims`.

## Adoption candidate

`split_text` in `packages/whisker/research/repos/nougat/nougat/metrics.py:63-83` (MIT, `LICENSE` at repo root). Port modality strip (inline math, display math, tabular blocks) before whisker bench text-axis `nid` scoring so math delimiter churn does not false-regress the text channel; pair with `minlen` gate at `:27-30`. Highest leverage for the fix-path bench layer; does not replace Lane 3 facts. Alternative for guard only: GROBID relative Levenshtein pass `(max_len - dist) / max_len >= 0.8` (`EndToEndEvaluation.java:1126-1134`, Apache-2.0 per grobid repo LICENSE) as secondary tier beneath axis slack — valuable for Lane 2, not comprehension.

## What would change my mind

Finding per-formula structural math assertions or blind LLM Q&A validation inside either target repo (not aggregate edit distance or XPath field P/R/F1), with `file:line` in the shallow clones, would flip the verdict toward "equal" on math fidelity or readback and reopen adoption beyond `split_text`.
