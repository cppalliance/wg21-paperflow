# 12 - olmocr-Orchestrator

**Verdict:** usable-with-conditions — olmocr's dual-layer throttle (work consumers vs LLM inflight cap) and pre-flight server probe are directly portable; the S3 work-queue, raw-socket HTTP client, and vLLM-log queue-depth hook are not.
**Confidence:** high

## Findings

- [CRITICAL] olmocr decouples **work consumers** from **LLM inflight cap**: `--workers` default 20 (`pipeline.py:1223`) pulls `WorkItem`s off `asyncio.Queue`, while `--max_concurrent_requests` default **1600** (`pipeline.py:1224`) sets `max_concurrent_requests_limit = asyncio.BoundedSemaphore(args.max_concurrent_requests)` (`pipeline.py:1287-1289`) and every inference call acquires it (`pipeline.py:184-185`). Inside a worker, pages fan out unbounded via `TaskGroup` (`pipeline.py:548-551`), so burst = workers × pages/PDF, capped only by the 1600 semaphore. **Impact:** our single `--concurrency 3` paper semaphore (`cli.py:158-163,409-416`) is the only whisker throttle; measured 10.8 s/paper at c=3 (`00-baseline.md:12-14`) suggests the pod absorbs more. **Adopt:** add whisker-only `--max-inflight` (default 16–32) as a second `BoundedSemaphore` around `adjudicate_paper` LLM calls, independent of paper-level `--concurrency`; lets us raise paper parallelism without unbounded HTTP burst when tier-2 escalations (13/197, `00-baseline.md:24`) double inflight.

- [HIGH] Work queue is a **distributed resume** system, not just asyncio fan-out: `WorkQueue` (`work_queue.py:82-235`) backs onto Local/S3 with worker locks (`work_queue.py:62-74,323-337`), done flags (`work_queue.py:77-79,377-389`), stale-lock timeout 1800 s (`work_queue.py:174,323-337`), and `random.shuffle` on init (`work_queue.py:165`). Workers loop `get_work` → process → `mark_done` (`pipeline.py:698-804`). **Impact:** crash-mid-batch on 200 papers currently relies on per-paper sidecar idempotency, not a batch checkpoint. **Not-applicable** for a single-machine 200-paper RunPod run (sidecars already persist per paper in `cli.py:436-437`); **adopt** only if we shard across pods or need multi-process resume — whisker port would be a `tapetum_batch_index.json` with done-PID flags, mirroring `done_flags/` semantics without S3.

- [HIGH] **Pre-flight server health gate** before any work: `vllm_server_ready` polls `GET {server}/models` up to `--max_server_ready_timeout` (default 600 s, `pipeline.py:929-953`) using a one-shot `httpx.AsyncClient` (`pipeline.py:940-941`); only after 200 does `asyncio.gather(*worker_tasks)` start (`pipeline.py:1451-1462`). **Impact:** our batch fires immediately with no probe; a cold/restarting pod wastes the first N papers as connection errors. **Adopt:** whisker `cli.py` pre-batch `GET {base_url}/models` (or `/health`) with 30–60 s timeout and fail-loud before `gather`; reuse `SERVICES.toml` resolved URL, no pipeline edit.

- [HIGH] **Per-request retry with connection backoff** is layered: `try_single_page` returns `None` on HTTP≠200 (`pipeline.py:187-191`) and re-raises connection/timeout errors (`pipeline.py:225-227`); `try_single_page_with_backoff` sleeps `10 * 2**count` up to 10 attempts then `sys.exit(1)` (`pipeline.py:264-278`); page-level retries up to `--max_page_retries` 8 with temperature escalation `TEMPERATURE_BY_ATTEMPT` (`pipeline.py:85,289-291`). Non-rotation failures switch to **parallel retries when vLLM queue depth == 0** (`pipeline.py:343-363`), driven by `vllm_queued_requests` parsed from local vLLM stderr (`pipeline.py:868-880`). **Impact:** pipeline `model_backends.py` already retries transient API errors with `2**(attempt+1)` (`model_backends.py:341-350`) — **already-have** for connection/transient. Queue-depth parallel retry is **not-applicable**: `vllm_queued_requests` is only updated when olmocr spawns local vLLM (`pipeline.py:1447-1449`); with external `--server` (our RunPod) it stays `None`, so `None == 0` is False and parallel retry never fires (`pipeline.py:345`).

- [MED] **Poison-page handling** degrades gracefully: exhausted retries call `make_fallback_result` (pdftotext anchor, `pipeline.py:233-250,372-375`); document discarded if fallback rate > `--max_page_error_rate` 0.004 (`pipeline.py:559-563`). Worker-level exceptions log but do **not** `mark_done` (`pipeline.py:803-804`), leaving a stale lock until 1800 s (`work_queue.py:323-337`). **Impact:** our per-paper `try/except` firewall (`cli.py:451-462`) already isolates failures — **already-have**. olmocr's lock-or-retry poison semantics **not-applicable** (we do not use a shared work queue).

- [MED] **HTTP transport deliberately avoids pooling**: custom `apost()` uses raw `asyncio.open_connection` with `Connection: close` per request (`pipeline.py:378-477`), citing httpx/aiohttp deadlock at 100M+ scale (`pipeline.py:379-381`); httpx is used only for the readiness probe (`pipeline.py:940`). **Impact:** our path constructs fresh `AsyncOpenAI` per call (`00-baseline.md:52-55`, pipeline read-only). olmocr's raw-socket approach is **not-applicable** to adopt inside whisker (would require pipeline changes). Raising `--concurrency` without a shared client still opens N simultaneous TCP streams — acceptable short-term; long-term pooling remains a pipeline/infrastructure ask.

- [LOW] **Observability loop**: `metrics_reporter` logs queue size + token rates every 10 s (`pipeline.py:983-989`); `WorkerTracker` prints per-worker state table (`metrics.py:104-159`, `pipeline.py:988`). **Impact:** our batch footer already reports pass/review/fail/error + retries + elapsed (`cli.py:488-497`) — **already-have** at summary granularity. **Adopt (optional):** mid-run inflight count + papers-remaining line every 30 s for knee-finding during concurrency sweeps.

## False-pass hypothesis

Raising concurrency to olmocr-scale defaults (1600 inflight) without olmocr's per-page validity gates (`finish_reason == "stop"`, token budget, rotation YAML, `pipeline.py:202-206,210-212`) could let truncated or malformed JSON through if our model backend exhausts `output_retries` on a subset of concurrent calls and the batch firewall swallows the error as `counts["error"]` rather than retrying the paper (`cli.py:478-479`). Higher parallelism increases the chance of simultaneous transient 5xx storms that correlate across papers.

## False-fail hypothesis

Adopting olmocr's connection-backoff `sys.exit(1)` on max attempts (`pipeline.py:277-278`) would abort the entire 200-paper batch on a brief pod blip; our per-paper firewall correctly continues. A pre-flight `/models` probe that is too strict (e.g., requiring model name match when the pod is warming KV cache) could false-fail the whole run before any paper is tried.

## What would change my mind

A whisker-only concurrency sweep (c=3,8,16,32) with per-phase latency and error rate, run against the live RunPod `/metrics` or response headers if vLLM 0.24 exposes queue depth without stderr access, showing the knee is below 8 — that would downgrade the dual-semaphore recommendation from CRITICAL to MED and confirm c=3 was already near optimal for our pod's `--max-num-seqs`.
