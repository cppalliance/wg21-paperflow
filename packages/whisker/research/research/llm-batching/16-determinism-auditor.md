# 16 - Determinism-Auditor

**Verdict:** usable-with-conditions — tapetum may raise paper-level concurrency under D11's per-package carve-out, but hosted vLLM batch/MoE non-invariance is already active at c=3; higher N increases distribution drift risk unless the pod enables batch-invariant kernels or we accept a documented variance budget for the advisory lane.
**Confidence:** medium

## Findings

- [CRITICAL] vLLM continuous batching is batch-non-invariant at the token level: matmul/attention/RMSNorm reduction order depends on batch size, so greedy (`temperature=0`) decode can flip argmax tokens when co-scheduled requests change. Evidence: `MODELS.md:77-78` ("flip tokens because ... kernels are not batch-invariant"); server fix `VLLM_BATCH_INVARIANT_LEVEL` noted same paragraph and `00-baseline.md:78`. Impact: rerunning the same paper can change axis verdicts at decision boundaries; this is the failure class we hunt, not wall-clock ordering bugs.

- [HIGH] Batch non-invariance is **already in play at c=3**, not introduced only at c=16. Evidence: `00-baseline.md:12-14` (200 papers at `--concurrency 3`); `cli.py:416-472` fires up to N concurrent `adjudicate_paper` HTTP workers; community H200×8 DeepSeek-V4 config caps `--max-num-seqs 8` (`00-baseline.md:36`, `05a-web-concurrency-knee.md` Finding 3), so three client workers already co-batch on the server scheduler. Impact: marginal determinism cost of c=16 is **incremental** (more in-flight sequences, more batch reshaping, longer queue depth), **not ~zero**; baseline corpus numbers already embed some batch interference.

- [HIGH] DeepSeek-V4-Pro is MoE; concurrent load changes expert routing, an independent variance source from FP reduction order. Evidence: `MODELS.md:69-70` ("batch composition affects which experts route"; serial semaphores "remove this entirely"); `deepseek-v4-pro/_index.md` (49B active / 1.6T total). Impact: raising c=3→16/32 amplifies MoE routing variance beyond what dense-model batch-invariance docs describe; verdict distributions on borderline table/structure axes can drift without any whisker-side bug.

- [HIGH] Project rules **permit** tapetum N>1; they **forbid** raising it for dissect. Evidence: `CLAUDE.md:74-88` (D11 binds dissect via `_parallel_semaphore` / `_task_semaphore`; "New packages ... opt into concurrent execution ... leaves dissect on the serial path"); `cli.py:46-51,158-163` (explicit D11 carve-out, `--concurrency N`); `00-baseline.md:74-77`. Impact: no rule violation to raise N; **do** violate the spirit of `CLAUDE.md:74` ("concurrent in-flight requests" as defect) if interpreted globally — baseline resolves this: advisory lane trades throughput for a documented distribution-variance budget, not gating fidelity.

- [MED] Client-side ordering and isolation are sound: no cross-paper state leak, persistence in input order. Evidence: `cli.py:474-475` ("gather() returns results in argument (= input) order regardless of completion order"); `cli.py:414-415,429-435` (per-paper firewall, own sidecar); `adjudicate.py:140-156,465-472` (fresh `_PipelineState` per paper, `default_concurrency=1` inside cascade); `adjudicate.py:189-210` (chunk triage serial per paper). Impact: concurrency speedups cannot scramble **which** sidecar belongs to **which** PID; they can only change **what verdict** the model returns for a given PID across reruns.

- [MED] Thinking/reasoning levers are the largest **semantic** stability movers, separate from batch concurrency. Evidence: `05e-web-thinking-control.md` (V4-Pro needs `enable_thinking`; `thinking_token_budget` hard-caps reasoning); `model_backends.py:294-298` (budget forwarded only when caller sets `thinking_budget`; tapetum hardcodes none at `adjudicate.py:450-457`); `00-baseline.md:57-59` (authority doc 2048/1024 budgets parsed but not forwarded). Impact: enabling/disabling/capping thinking can flip adjudication outcomes more than raising N alone; current pod-default thinking state is UNKNOWN (`00-baseline.md:34`).

- [MED] Speedup levers ranked by **semantic verdict stability** (material → immaterial): (1) thinking toggle/`thinking_token_budget`/`max_tokens` truncation — HIGH; (2) client concurrency c=3→16/32 — MED-HIGH incremental over baseline; (3) dual-pod sharding — MED (independent batch landscapes); (4) guided JSON / XGrammar — MED (corridor change, may stabilize or shift); (5) prefix caching — LOW-MED (latency-first, minor temp=0 variance per `#40896`); (6) HTTP client pooling — NONE. Evidence: `05e-web-thinking-control.md`, `05c-web-prefix-guided.md`, `MODELS.md:35-51,69-78`, `00-baseline.md:52-56`. Impact: prioritize thinking/output caps in regression plans before chasing N=32.

- [MED] `tapetum_llm.md` must be updated to stay honest. Evidence: `tapetum_llm.md:23` (`concurrency: 1` only — omits `--concurrency` CLI and c=3 production runs); Steps 1–2 declare `max-output`/`thinking-budget` but `adjudicate.py:450-457` forwards neither; no advisory-lane determinism doctrine (quality-stability, batch/MoE variance, `VLLM_BATCH_INVARIANT` as infra ask). Required wording: (a) Config block — document CLI `--concurrency`, default 1, note rerun distribution drift rises with N on non-batch-invariant pods; (b) new short "Determinism (advisory)" subsection — client ordering deterministic (`cli.py:474-475`), server tokens not bit-stable (`MODELS.md:77-78`), dissect D11 does not apply; (c) Steps 1–2 — mark budget fields as "authority intent; not yet forwarded" or wire them before claiming them; (d) optional CTO note — batch-invariant mode for corpus regression baselines (~50% throughput cost per `00-baseline.md:78`).

## False-pass hypothesis

Higher client concurrency (c=16+) increases MoE routing and batch-composition churn on the alliance-pod. On a PRIMARY candidate with a token-preserving table row swap (whisker's blind spot), an unlucky batch routes experts differently, tier1 returns `pass` with high confidence and empty evidence, escalation signals do not fire (`adjudicate.py:213-236`), and decide keeps `pass` because demotion requires non-pass verdict without grounded evidence (`adjudicate.py:279-285`). Whisker gate stays green; advisory lane silently misses the defect **more often on rerun B than rerun A** — a distribution shift, not a single-paper ordering bug.

## False-fail hypothesis

Concurrent load lengthens decode tails (p99 inflation under CB — `05a-web-concurrency-knee.md` Finding 5). Combined with a future thinking-cap or lowered `max_tokens`, truncated JSON triggers raw-JSON retries (`cli.py:70-73`, `_RETRY_WARNING_MARKERS`); retry success parses a **different** Adjudication than attempt 1, spuriously firing `ungrounded_evidence` or `axis_conflict`, escalating 13/197 → higher, inflating `review` counts without improving conversion-fidelity signal — looks like "more careful" output, is run-variance noise.

## What would change my mind

A controlled triple rerun of the same 200-paper candidate set on the same pod snapshot: (A) c=3, (B) c=16, (C) c=16 with CTO-enabling `VLLM_BATCH_INVARIANT` (or equivalent), reporting per-PID verdict flip rate and aggregate pass/review/fail histogram diff. Flip rate ≈0 between A and B would downgrade batch/MoE concern to LOW; flip rate ≈0 only in C would confirm infra-gated usability and mandate doc + pod policy updates.
