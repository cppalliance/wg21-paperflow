# 13 - docling-analyst

**Verdict:** usable — Docling is the strongest non-LLM per-page quality-score precedent: four named per-page axes, pessimistic parse tail aggregation (10th percentile at cell and page levels), dual document grades (`mean_grade`/`low_grade`), and explicit page-level status separate from advisory confidence; port aggregation reducers and grade bands, not the deterministic signal definitions.
**Confidence:** high

## Findings

- [CRITICAL] **Unit of scoping is the PDF page; scores live in `ConfidenceReport.pages[page_no]`.** Each page gets a `PageConfidenceScores` bucket (`parse_score`, `layout_score`, `table_score`, `ocr_score`, default NaN) at `docling/datamodel/base_models.py:539-543`. Writers: **`parse_score`** during page preprocessing from PDF text cells (`page_preprocessing_model.py:75-89`); **`layout_score`** and **`ocr_score`** during layout postprocessing (`layout_model.py:233-239`, duplicate path `layout_object_detection_model.py:125-138`); **`table_score`** never written (schema-only). Invalid backend pages are yielded without parsing (`page_preprocessing_model.py:42-43`), so failed pages may carry no per-page scores. Impact: direct analog for whisker storing `pages[i]` sidecars before document fold; page is the natural boundary matching our existing `extract_textlayer()` list.

- [CRITICAL] **Per-page score semantics (all deterministic, no LLM).** **`parse_score`**: 10th percentile (`np.nanquantile(..., q=0.10)`) of `rate_text_quality(text)` over all page cells — comment says "emphasise problems" (`page_preprocessing_model.py:85-88`). `rate_text_quality` returns `0.0` on blacklist chars (`�`), `GLYPH<...>`, slash-G garbage, slash-number patterns; else `max(1.0 - penalty, 0.0)` with `+0.1` per fragmented-word match when ≥3 matches (`page_preprocessing_model.py:120-145`). **`layout_score`**: mean confidence of postprocessed layout clusters (`layout_model.py:233-235`); `0.0` if no clusters (`layout_object_detection_model.py:130-131`). **`ocr_score`**: mean confidence of `processed_cells` where `from_ocr=True` (`layout_model.py:237-239`); omitted (stays NaN) when no OCR cells (`layout_object_detection_model.py:133-138`). **`table_score`**: documented "not yet implemented" (`docs/concepts/confidence_scores.md:42`); only aggregated as NaN at doc level (`standard_pdf_pipeline.py:1079-1082`). Impact: measures pipeline self-consistency, not external oracle agreement — parallel to whisker deterministic `ref_*` metrics, not tapetum LLM verdicts.

- [CRITICAL] **Document-level aggregation is axis-specific; baseline "worst 10% pages" is real for `parse_score` only.** After all pages process, `standard_pdf_pipeline._assemble_document` sets root axis scores (`standard_pdf_pipeline.py:1060-1088`): **`layout_score`** = `np.nanmean` over page `layout_score` values (`1068-1071`); **`parse_score`** = `np.nanquantile(..., q=0.1)` over page `parse_score` values with comment "worst 10% of pages" (`1073-1077`); **`table_score`** = `np.nanmean` over page values (all NaN today) (`1079-1082`); **`ocr_score`** = `np.nanmean` over page values (`1084-1087`). Legacy pipeline mirrors the same formulas (`legacy_standard_pdf_pipeline.py:251-269`). Summary grades use separate computed fields on `ConfidenceReport`: when `pages` is non-empty, **`mean_score`** = `np.nanmean([page.mean_score ...])` and **`low_score`** = `np.nanmean([page.low_score ...])` (`base_models.py:650-674`), where each page's `mean_score`/`low_score` are derived from that page's four axes via `nanmean` and `nanquantile(q=0.05)` respectively (`579-606`). Impact: whisker should not use one reducer for every axis; adopt parse-style tail (worst-page or worst-chunk) for absence-sensitive axes and mean for stable axes — matches tapetum `worst_axis` intent (`00-baseline.md:34-36`).

- [HIGH] **Grade mapping is fixed thresholds on computed scores, exposed as `mean_grade` and `low_grade`.** `_score_to_grade` maps: `<0.5` → `POOR`, `<0.8` → `FAIR`, `<0.9` → `GOOD`, `>=0.9` → `EXCELLENT` (`base_models.py:557-567`). Applied to both `mean_score` and `low_score` via computed fields (`571-577`). Docs instruct users to rely on document-level `mean_grade`/`low_grade`, not raw scores (`docs/concepts/confidence_scores.md:11-13,48-49`). API wire type `ConfidenceScores` snapshots stored grades plus nullable floats (`service/responses.py:27-61`). Test fixture asserts `mean_grade == EXCELLENT` on a sample doc (`tests/test_options.py:544-552`). Impact: portable grade-band table for whisker merged sidecar; keep deterministic verdict authoritative (C1).

- [HIGH] **Low confidence does not reject or downgrade conversion status — scores are advisory metadata only.** No code path gates `ConversionStatus`, export, or pipeline routing on `mean_grade`, `low_grade`, or any axis score (grep across `docling/` shows grades only in models, service responses, docs, and tests). Confidence is persisted on `ConversionResult.confidence` (`document.py:382`), written to `confidence.json` in conversion ZIP (`document.py:466`), and exposed via remote API (`service_client/client.py:396-399`), but conversion completes regardless. Low-scoring pages still contribute to assembled document output. Impact: Docling separates **quality telemetry** from **fidelity status**; whisker per-page judge should emit scores/grades alongside tapetum verdict without replacing it.

- [HIGH] **Page failures and partial success use `ConversionStatus`, independent of confidence scores.** Status enum: `PENDING`, `STARTED`, `FAILURE`, `SUCCESS`, `PARTIAL_SUCCESS`, `SKIPPED` (`base_models.py:85-91`). Standard PDF pipeline sets `PARTIAL_SUCCESS` on timeout (`standard_pdf_pipeline.py:966-979`) or any failed/incomplete pages (`982-983`); `FAILURE` on complete failure (`980-981`); else `SUCCESS` (`984-985`). Failed pages recorded in `proc.failed_pages` with structured `ErrorItem` (`953-965`, `870-872`); placeholder `PageItem` entries added to preserve page numbering (`1098-1134`). Base pipeline promotes `SUCCESS` → `PARTIAL_SUCCESS` when any page backend is invalid (`base_pipeline.py:353-374`) or when errors exist after assembly (`84-87`). VLM pipeline adds `PARTIAL_SUCCESS` for missing VLM output or `stop_reason` in `{LENGTH, CONTENT_FILTERED}` (`vlm_pipeline.py:236-274`); VLM path does **not** populate `ConfidenceReport.pages`. `raises_on_error=True` still accepts `PARTIAL_SUCCESS` (`document_converter.py:529-532`). Tests: skipped pages → `PARTIAL_SUCCESS` with full page numbering preserved (`tests/test_failed_pages.py:99-102`). Impact: page failure model is status+errors, not score demotion; whisker should mirror "partial document + explicit page errors" rather than silently omitting failed pages.

- [MED] **Per-page quality gates affect extraction content before scoring, but are not folded into `ConfidenceReport`.** Layout postprocessor drops clusters below per-label thresholds 0.45–0.5 (`layout_postprocessor.py:175-193`, filter at `267`). EasyOCR drops lines below `confidence_threshold=0.5` (`easyocr_model.py:193`, default `pipeline_options.py:400-408`). Picture VLM description skips below `classification_min_confidence` (`picture_description_base_model.py:147-179`). These gates change what gets extracted; page scores reflect surviving elements' mean confidences. Impact: portable cascade-threshold pattern for tapetum candidate selection, distinct from document-grade aggregation.

- [LOW] **VLM / LLM pipelines have no per-page numeric confidence.** `vlm_pipeline.py` determines status only (`236-274`); no `confidence.pages` writes. Confidence scores are a standard-PDF deterministic-lane artifact. Impact: no upstream precedent for LLM-lane numeric confidence merge; whisker must define LLM per-page confidence separately and fold via our own `aggregate_adjudications()` pattern.

## False-pass hypothesis

A 33-page WG21 paper with one bad page (p0957r8-style missing Table 2 on page 13) but high layout/OCR on all other pages: Docling document `mean_grade` stays `GOOD`/`EXCELLENT` because `mean_score` averages page means and `parse_score` doc aggregation uses only the 10th percentile of *page-level* parse scores (one bad page in 33 ≈ 4th percentile, may not pull doc parse below 0.8). Conversion status remains `SUCCESS` with no error. Mapped to whisker: adopting Docling `mean_grade`-only merge without a worst-page or worst-chunk tail on the LLM absence axis would false-pass the same monolithic-judge failure (`00-baseline.md:12-16`).

## False-fail hypothesis

A born-digital PDF with no OCR cells: page `ocr_score` stays NaN; `np.nanmean` over pages ignores NaN axes, but page-level `low_score` uses `nanquantile(q=0.05)` across four axes — a single low `parse_score` from one penalized header/footer cell (fragment regex, `page_preprocessing_model.py:136-138`) can drag page `low_grade` to `FAIR`/`POOR` while layout is excellent. Document `low_grade` = mean of page `low_grade` values, intentionally biasing toward worst areas (`docs/concepts/confidence_scores.md:48-49`). Mapped to whisker: porting Docling `low_grade` without axis-specific NaN handling or WG21-tuned parse heuristics would false-fail clean papers into unnecessary review.
