# 12 - marker-analyst

**Verdict:** usable-with-conditions — marker is the strongest open-source precedent for BLOCK-scoped multimodal LLM calls with structured schemas and reject-and-keep-original merge gates, but it refines conversion blocks rather than emitting pass/review/fail verdicts; port unit boundaries, prompt+schema shapes, and sanity gates, not the in-place rewrite pipeline or default concurrency.
**Confidence:** high

## Findings

- [CRITICAL] **Unit of scoping is a typed layout block (`BlockTypes`), not a page.** Default complex processors iterate every page and every block whose `block_type` matches `self.block_types` via `page.contained_blocks(document, self.block_types)` (`marker/processors/llm/__init__.py:163-168`, `marker/schema/blocks/base.py:257-273`). Simple processors use the same boundary in `inference_blocks` (`__init__.py:193-198`). Exceptions raise the unit: **document-wide** section-header batch (all `SectionHeader` blocks, one LLM call, no image) (`llm_sectionheader.py:147-162`, `125-127`); **page-wide** correction (full lowres page image + JSON of all structure blocks) (`llm_page_correction.py:150-159`, `268-270`); **table sub-region** (row batches of `max_rows_per_batch=60` cropped from the block highres image) (`llm_table.py:144-174`); **table-pair** merge (two adjacent `Table` blocks, two lowres images) (`llm_table_merge.py:244-270`). Global gate: `use_llm=False` short-circuits all processors at init (`__init__.py:64-65`, `137-139`). Impact: whisker per-page judge can adopt block-type or page-chunk units, but marker proves sub-block cropping (table rows) and cross-block pairing are first-class; our text lane lacks exported bboxes, so page/H2 chunk is the pragmatic v1.

- [CRITICAL] **Prompt shape is multimodal compare-then-correct, not verify-only.** Per-block pattern: cropped **highres** block image (`extract_image(..., highres=True)` at `__init__.py:75-79`, `builders/document.py:22-25` DPI 192) plus deterministic extraction embedded in prompt (`block_html`, `extracted_text`, or `equation` placeholder). No surrounding page context for simple/complex block processors. Table prompt explicitly instructs image-vs-html comparison then output corrected html or `"No corrections needed"` (`llm_table.py:47-64`, `197-199`). Form/complex/equation/handwriting follow the same image+extraction template (`llm_form.py:14-24,82-83`, `llm_complex.py:14-33,57-59`, `llm_equation.py:28-46,91-93`, `llm_handwriting.py:17-34,56-57`). Section headers: **text-only** JSON list of all headers with normalized bboxes 0-1000, no image (`llm_sectionheader.py:18-33,122-127`). Page correction: **lowres** full-page image + all page blocks JSON + user prompt (`llm_page_correction.py:37-48,152-158`). **Return schema** is Pydantic per processor, enforced at the service layer via `response_schema` (`gemini.py:64-67,86-93`): e.g. `TableSchema` (`comparison`, `corrected_html`, `analysis`, `score`) at `llm_table.py:323-327`; `FormSchema` (`comparison`, `corrected_html`) at `llm_form.py:116-118`; `ComplexSchema` (`corrected_markdown`) at `llm_complex.py:92-93`; `EquationSchema` (`analysis`, `corrected_equation`) at `llm_equation.py:130-132`; `SectionHeaderSchema` (`analysis`, `correction_type`, `blocks`) at `llm_sectionheader.py:172-175`; `PageSchema` at `llm_page_correction.py:302-305`; `MergeSchema` at `llm_table_merge.py:344-349`. Impact: for whisker judge, invert role: keep image+source-text comparison steps and schemas, replace rewrite fields with axis verdicts + grounded evidence quotes.

- [HIGH] **Reject/sanity gate: validate LLM output before merge; on rejection keep deterministic original.** Service exhaustion returns `{}` after `max_retries=2` (`services/__init__.py:14-17`, `gemini.py:51-53,131`); processors treat empty/missing keys as failure, increment `llm_error_count`, and return without mutating (`llm_table.py:201-203`, `llm_form.py:98-100`, `llm_equation.py:110-112`, `llm_complex.py:73-75`). **No-op accept:** substring `"no corrections needed"` (tables/forms/equations) or `"no corrections"` (complex) or `correction_type == "no_corrections"` (section/page) preserves original (`llm_table.py:207-209`, `llm_form.py:104-106`, `llm_equation.py:116-117`, `llm_complex.py:79-81`, `llm_sectionheader.py:134-136`, `llm_page_correction.py:166-168`). **Pre-merge structural rejection (tables):** after LLM html accepted, `parse_html_table` must yield `>1` cells and html must end with `</table>` or reject (`llm_table.py:227-238`). **Length-ratio guards:** form html `<33%` of original (`llm_form.py:108-111`); equation html `<30%` or unbalanced `<math>` tags (`llm_equation.py:119-126`); complex markdown `<50%` of extracted text (`llm_complex.py:83-86`); math-block html `<60%` (`llm_mathblock.py:191-193`); handwriting markdown `<50%` of raw (`llm_handwriting.py:77-79`); image description `<10` chars (`llm_image_description.py:79-81`). **Page reorder gate:** response block-ID set must equal page structure set before reorder applied (`llm_page_correction.py:221-242`). **Table merge gate:** LLM `merge` must contain `"true"` and `validate_merge` row/col counts within tolerance (`llm_table_merge.py:276-287`, `295-305`). **Only iterative retry:** table self-score `<4` re-prompts up to `max_table_iterations=2` (`llm_table.py:214-225`). Impact: directly portable for whisker fidelity — structured output + reject-and-keep-deterministic matches "fail not partial" at the unit level; document never aborts, failed blocks silently retain OCR/layout output.

- [HIGH] **Concurrency and ordering: serial processor pipeline, parallel within each LLM processor.** `PdfConverter.default_processors` runs deterministic processors then LLM processors in fixed order (`converters/pdf.py:74-103`): `LLMTableProcessor` → `LLMTableMergeProcessor` → simple blocks (via meta) → `LLMSectionHeaderProcessor` → `LLMPageCorrectionProcessor`. Simple LLM processors (`LLMFormProcessor`, `LLMComplexRegionProcessor`, `LLMImageDescriptionProcessor`, `LLMEquationProcessor`, `LLMHandwritingProcessor`) are collapsed into one `LLMSimpleBlockMetaProcessor` inserted at the last simple-processor slot (`converters/__init__.py:48-62`). Inside each LLM step: `ThreadPoolExecutor(max_workers=max_concurrency)` with default `max_concurrency=3` (`__init__.py:42-45`, `163-172`; `llm_meta.py:44-49`; `llm_page_correction.py:283-291`; `llm_mathblock.py:149-157`; `llm_table_merge.py:234-240`). Meta processor submits all simple-block prompts to the pool, then calls `rewrite_block` as futures complete — **completion order is nondeterministic** (`llm_meta.py:51-59`). Impact: marker's parallel block calls conflict with whisker D11 serial tapetum; adopt block-scoped unit boundaries but run per-page or per-block calls serially.

- [MED] **Per-block selection heuristics (skip logic) gate which blocks reach the LLM.** Tables: skip when `row_count > max_table_rows` (175) or no `TableCell` children (`llm_table.py:125-135,122-127`). Forms: skip blocks without `TableCell` children (`llm_form.py:65-74`). Equations: skip when block height `< min_equation_height` (0.06 of page) unless `redo_inline_math` (`llm_equation.py:78-84`). Image descriptions: skip entirely when `extract_images=True` (default) (`llm_image_description.py:42-46`). Handwriting: skip `Text` blocks that already have lines or nonempty raw text (`llm_handwriting.py:43-48`). Math blocks: only when `redo_inline_math=True`; page-level math-density ratio `inlinemath_min_ratio=0.4` expands candidate set (`llm_mathblock.py:76-78,127-131`). Page correction: only when `block_correction_prompt` is set (`llm_page_correction.py:268-270`). Table merge: geometric adjacency thresholds (`table_height_threshold=0.6`, `table_start_threshold=0.2`, distance thresholds, etc. at `llm_table_merge.py:22-49,209`). Impact: whisker can mirror candidate gating (like tapetum `select_candidates`) but marker has no coverage/recall floors — gating is structural/heuristic only.

- [MED] **Confidence/threshold constants governing accept vs reject.** Table self-score retry threshold: `score < 4` on 1-5 scale (`llm_table.py:215-218`, prompt at `:65`). No other processor uses model-reported confidence. Structural ratio floors: `0.33` (form), `0.30` (equation), `0.50` (complex, handwriting), `0.60` (math-block), `10` chars (image description) — see reject gates above. Table merge validation: row count delta `<5` for right merge, column count delta `<2` for bottom merge (`llm_table_merge.py:300-305`). Service-level: `temperature=0`, bumped to `0.2` only on `JSONDecodeError` (`gemini.py:62-63,112-113`); `timeout=30`, `retry_wait_time=3` (`services/__init__.py:13-17`). Block metadata accumulates `llm_request_count`, `llm_error_count`, `llm_tokens_used` on pass/fail (`schema/blocks/base.py:16-19,324-331`). Impact: whisker's `CONFIDENCE_DECISION_FLOOR=0.50` and recall/nid demotions have no marker analog; adopt table-style bounded retry for specific axes, not as document merge logic.

- [LOW] **Document-level aggregation: no verdict fold — conversion always completes.** Failed units increment per-block `llm_error_count` and leave deterministic content; there is no worst-block document fail, error-rate threshold, or union-of-evidence policy in the conversion path. Optional benchmark `LLMScorer` (separate from `--use_llm` processors) scores page 0 image vs markdown on 0-5 axes but does not gate output (`benchmarks/overall/scorers/llm.py` per prior research `21-marker-refinement-analyst.md`). Impact: marker teaches per-unit reject-and-keep, not per-document adjudication; whisker must supply `aggregate_adjudications()`-style folding ourselves (`00-baseline.md:34-36`).

## False-pass hypothesis

Table processor accepts `"No corrections needed"` when the 192 DPI row-batch crop omits column boundaries or header row (`llm_table.py:207-209`, batch crop at `:154-169`), or when self-score `>=4` after a wrong rewrite on retry (`:215-225`). Mapped to whisker: a per-page judge that only checks token presence in a page chunk (not column/header alignment) would false-pass p0957r8 Table 2 header permutation — the same failure mode as our monolithic judge (`00-baseline.md:12-16`).

## False-fail hypothesis

Equation processor rejects when corrected html length `<30%` of original (`llm_equation.py:119-124`) even when the image-backed fix legitimately condenses malformed OCR into compact `<math>` tags. Mapped to whisker: porting marker length-ratio merge guards into a judge that requires corrected text length would false-fail faithful reflow/normalization unless verdicts are axis-only and never require replacement text length to exceed extraction length.

## What would change my mind

Finding a marker conversion code path that scores extraction fidelity per block (pass/review/fail) and gates document output on aggregated unit verdicts without mutating blocks. Current evidence: all `--use_llm` processors rewrite or no-op (`llm_table.py:227-240`, `llm_sectionheader.py:138-139`); benchmark `LLMScorer` is eval-only and not wired into `verify_scores.py` CI gates.
