# 17 - grobid-unstructured-analyst

**Verdict:** usable-with-conditions — Both repos scope work to element/block units with rich post-model sanity checks, but neither derives a runtime document-level quality verdict from per-element signals; adopt their segmentation and validation patterns, not their output-as-truth posture.
**Confidence:** high

## Findings

- [CRITICAL] GROBID's full-paper pipeline is a **cascade of model-scoped zones**, not one monolithic pass: `Segmentation` labels every layout line into 13 zones (`<header>`, `<body>`, `<references>`, etc., `Segmentation.java:46-64`), then downstream parsers consume only their zone. `FullTextParser.processing()` runs: segmentation → header (`processingHeaderSection`) → citation/reference segmenter → fulltext body label → per-figure/per-table sub-models → annex repeat (`FullTextParser.java:157-166`, `:228-332`, `:337-398`). Each stage calls `labelAndCapture()` on featurized token lines (`AbstractParser.java:63-66`). Impact: strong prior art for **scoping QA to pre-segmented units** (header block, reference string, body paragraph cluster) instead of whole-document prompts.

- [HIGH] GROBID sequence-labeling models (Wapiti, DeLFT, CRF++) emit **hard labels only** — no per-token or per-field confidence in the standard scientific-PDF path. `WapitiTagger.label()` and `DeLFTTagger.label()` return a label string with no score tuple (`WapitiTagger.java:28-30`, `DeLFTTagger.java:27-29`). `BibDataSet` carries a `confidence` field defaulting to `1.0` (`BibDataSet.java:26`, `:56-57`), but only the **patent** `ReferenceExtractor` path parses probability suffixes from labels and calls `setConfidence()` (`ReferenceExtractor.java:639-643`, `:849`). Impact: GROBID's "quality signal" at extraction time is **deterministic post-rules**, not model confidence — do not expect CRF/DL scores to gate a per-page judge.

- [HIGH] GROBID applies **per-element consistency checks after model output**, silently dropping or downgrading bad units. Examples: `Person.sanityCheck()` drops authors without last names (`Person.java:757-774`, called `HeaderParser.java:245`); `DateParser.cleaning()` strips out-of-bounds day/month/year (`DateParser.java:318-342`, used in `HeaderParser.java:314-345`); `BiblioItem.rejectAsReference()` rejects citations missing title/author/identifier cores (`BiblioItem.java:4515-4527`, gated `CitationParser.java:306`); `getBadFigures()` / `getBadTables()` filter incomplete TEI figures/tables and **revert labels to `<paragraph>`** (`FullTextParser.java:291-319`, `:445-466`; `Table.validateTable()` `Table.java:399-417`). `TextUtilities.filterLine()` drops `@IMAGE`/`@PAGE` noise before labeling (`TextUtilities.java:1203-1210`, used `Segmentation.java:497`). Impact: portable pattern for **per-unit demotion** (figure→paragraph) rather than whole-doc fail; matches our need to flag missing captions without aborting the paper.

- [MED] GROBID has **no document-level quality verdict** derived from element signals at extraction time. The pipeline always emits TEI; quality is measured only by external `EndToEndEvaluation` benchmark P/R/F1 tiers (see `research/redteam/grobid.md`, `EndToEndEvaluation.java` — not invoked in `Engine.fullTextToTEI()` `Engine.java:616-627`). Impact: confirms the research gap — even a mature non-LLM extractor does not aggregate per-field sanity into pass/review/fail; our per-page judge must build that layer ourselves.

- [CRITICAL] Unstructured's **element type system** is a two-tier taxonomy: string constants in `ElementType` (`elements.py:657-701`) mapped to Python classes (`Title`, `NarrativeText`, `Table`, `ListItem`, etc., `elements.py:952-1084`, `TYPE_TO_TEXT_ELEMENT_MAP` `elements.py:1052-1084`). **hi_res** path: layout model assigns `type` + `prob` per bounding box; `normalize_layout_element()` maps `prob` → `ElementMetadata.detection_class_prob` and `type` → element class (`common.py:54-102`, `pdf.py:1449-1464`). **fast** path: `element_from_text()` uses coordinate heuristics + regex (`Header`/`Footer` by y-position, `ListItem` by bullet patterns, `Title` by `is_possible_title()`, else `NarrativeText`/`Text`, `text.py:111-166`). Impact: element boundaries are explicit and iterable — good substrate for per-element QA calls — but classification quality varies sharply by `PartitionStrategy` (`strategies.py:24-46`).

- [HIGH] Unstructured attaches **per-element metadata, not a per-element pass/fail verdict**. `ElementMetadata` carries `detection_class_prob` (hi_res only, `elements.py:167-168`), `detection_origin`, `page_number`, `coordinates`, `category_depth` for headlines (`common.py:98-101`), `languages`, etc. (`elements.py:150-200`). No `confidence` or `quality` field gates emission; elements are always returned. `detection_class_prob` is marked DROP on chunk consolidation (`elements.py:529-533`). Impact: metadata can **inform** downstream judging but is not an aggregation input today.

- [HIGH] Unstructured **chunking strategies use element boundaries as chunk boundaries**. `chunk_by_title()` closes pre-chunks on `is_title()` (instanceof `Title`, `base.py:1877-1879`) and optionally `is_on_next_page()` when `multipage_sections=False` (`title.py:145-157`, `:67-68`). `chunk_elements()` (basic) sequences elements into `PreChunker` windows by char/token hard/soft limits with no semantic boundary (`basic.py:24-119`, `chunking/base.py` PreChunker). Both wired via `@add_chunking_strategy` decorator on `partition_pdf()` (`pdf.py:126-127`, `dispatch.py:141-142`). Impact: `by_title` is direct prior art for **H2/section-aligned judge scoping**; maps cleanly to our planned per-page + per-section split.

- [MED] Unstructured has **no runtime document-level quality verdict** from element signals. `partition()` / `partition_pdf()` return `list[Element]` with no aggregate score (`auto.py:30-57`, `pdf.py:127-150`). Quality lives only in offline `metrics/evaluate.py` (text-extraction, element-type, table-structure strategies compared via committed TSV snapshots — see `research/redteam/unstructured.md`). Impact: same absence finding as GROBID — per-element metadata exists, document verdict does not; aggregation is an external CI concern, not an extraction concern.

## False-pass hypothesis

GROBID: a table labeled by the fulltext model but failing `validateTable()` is **reverted to `<paragraph>`** and still emitted in TEI (`FullTextParser.java:318-319`, `revertResultsForBadItems`). A per-page judge comparing only markdown structure would see paragraph text where a table existed in the PDF, with no extraction-time alarm — analogous to our p0957r8 false-pass (content present in source, absent in output, no flag).

## False-fail hypothesis

Unstructured fast strategy: a short bold line near the top of a page becomes `Header` via `_is_in_header_position()` (`text.py:116-121`), then `by_title` treats every `Title` as a section break (`base.py:1877-1879`), fragmenting a single narrative into many tiny chunks. A judge scoped to those chunks could flag "missing context" on each fragment even though the full text is present — false fail from mis-boundary, not mis-content.

## What would change my mind

A `file:line` showing GROBID's standard `header`/`fulltext`/`citation` Wapiti or DeLFT inference returning per-token log-probabilities or confidences that are persisted on each `BiblioItem` field or TEI `@confidence` attribute in the main `fullTextToTEI()` path (`Engine.java:616-627`) — not just the patent `ReferenceExtractor` prob-suffix hack (`ReferenceExtractor.java:639-643`).
