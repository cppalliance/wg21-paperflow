# 14 - mineru-dolphin-analyst

**Verdict:** usable-with-conditions — both repos scope model work per page and per layout region, but they are **extraction** pipelines (transcribe/parse), not per-unit **verification** judges; adopt their unit boundaries and aggregation patterns, not their QA semantics, for tapetum per-page judging.
**Confidence:** high

## Findings

- [CRITICAL] Neither MinerU nor Dolphin implements presence/absence **verification** ("does markdown X match source Y?"); both issue **extraction** prompts ("Parse/Read X in the image") and always emit output. Dolphin stage-1 prompt is fixed at `demo_page.py:186` (`"Parse the reading order of this document."`); stage-2 element prompts are modality literals at `demo_page.py:269-281` (`"Parse the table in the image."`, `"Read formula in the image."`, `"Read code in the image."`, `"Read text in the image."`). MinerU VLM path calls `predictor.batch_two_step_extract(...)` per page window at `vlm_analyze.py:479` (prompt text lives in external `mineru_vl_utils`, not in-repo). Impact: these repos do not solve the p0957r8 false-pass root cause (absence over long contexts); they only show how to **scope extraction**, not how to **judge fidelity** per unit.

- [HIGH] Dolphin unit boundary: **page** → **layout region (bbox crop)**. PDF pages are rasterized one-by-one (`utils/utils.py:69-83`), each page runs `process_single_image` (`demo_page.py:140-150`), layout string is parsed into `(coords, label, tags)` tuples (`utils/utils.py:172-201`), each region is cropped (`demo_page.py:226-228`) and batched by label (`demo_page.py:251-258`, `289-320`). Impact: direct prior art for tapetum per-page judge paired with per-region crops if we add a vision lane; reading order is assigned at layout-parse time (`demo_page.py:216-260`), not re-derived later.

- [HIGH] Dolphin two-stage reassembly: layout pass assigns monotonic `reading_order` while iterating `layout_results_list` (`demo_page.py:216-260`); element batches append results with that field (`demo_page.py:312-317`); final list is sorted `recognition_results.sort(key=lambda x: x.get("reading_order", 0))` at `demo_page.py:284`. Multi-page PDFs concatenate sorted per-page element lists with `---` separators (`utils/utils.py:124-137`); `MarkdownConverter.convert` walks the sorted list in order (`markdown_utils.py:315-345`). Impact: reading order is **layout-model output order**, stabilized by an integer key; no cross-page reorder pass.

- [HIGH] MinerU pipeline unit boundary: **page** (batched in configurable windows, default 64 via `get_processing_window_size`) → **layout detection regions** → **per-region specialist models**. Window loop loads page images (`pipeline_analyze.py:240-246`), `batch_image_analyze` runs layout per page (`batch_analyze.py:426-430`), then `get_res_list_from_layout_res` splits each page's `layout_res` into OCR text regions, tables, and formula boxes (`model_utils.py:148-180`). Per-region calls follow: formula recognition (`batch_analyze.py:445-457`), table OCR+HTML (`batch_analyze.py:519-699`), text OCR det/rec (`batch_analyze.py:702-841`). Impact: page is the streaming accumulator unit (`middle_json["pdf_info"].append` at `model_json_to_middle_json.py:102`); region is the inference batch unit inside `BatchAnalyze.__call__`.

- [HIGH] MinerU per-page output validation before document assembly uses **deterministic confidence gates**, not LLM self-check. `OcrConfidence.min_confidence = 0.5` (`ocr_utils.py:10-12`); spans below threshold are removed or restored from fallback (`batch_analyze.py:897-919`, `model_json_to_middle_json.py:185-193`). Empty OCR text blocks pruned per page (`batch_analyze.py:166-179`, invoked at `973-976`). Layout detection carries `score` on inline table objects (`batch_analyze.py:373-397`). External e2e QA asserts per-block `fuzz.ratio > 90` and table substring hit-rates (`test_e2e.py:163-201`) plus `len(type_set) >= 4` modality coverage (`test_e2e.py:220`). Impact: MinerU's closest analogue to per-unit QA is **post-OCR score + typed substring anchors**, not holistic pass/fail; VLM path uses looser table gate (`0.7` vs `0.9` at `test_e2e.py:198-201`).

- [MED] Document aggregation in both repos is **append-all-pages, no worst-page veto**. MinerU: each processed page appends to `middle_json["pdf_info"]` (`model_json_to_middle_json.py:102`, `vlm/model_output_to_middle_json.py:101`), then `finalize_middle_json` runs cross-page table merge and title leveling (`model_json_to_middle_json.py:225-231`; VLM variant at `vlm/model_output_to_middle_json.py:106-117`); `union_make` concatenates per-page `para_blocks` into markdown/content_list (`pipeline_middle_json_mkcontent.py:968-1008`), skipping only pages with empty `paras_of_layout` (`979-980`). Dolphin: `all_results` list grows per page (`demo_page.py:153-157`), combined JSON written unconditionally (`utils/utils.py:109-118`). Impact: a single bad page **degrades** output silently; neither repo fails the whole document on one page's low confidence.

- [MED] Skip / trivial-unit logic is explicit but local. Dolphin: crops smaller than 3×3 px skipped (`demo_page.py:230-231`); empty element text skipped in markdown (`markdown_utils.py:323-325`); high bbox overlap triggers `distorted_page` holistic fallback (`demo_page.py:207-209`, `utils/utils.py:489-533`). MinerU: headers/footers/page numbers routed to `discarded_blocks` (`pipeline_magic_model.py:203-210`); broken PDF pages skipped at ingest (`cli/common.py:218-221`); zero-page docs finalize empty (`pipeline_analyze.py:199-205`); native text char count >65535 forces post-OCR (`span_pre_proc.py:54-62`); sparse/PUA spans forced to OCR fallback (`span_pre_proc.py:291-294`, `353-362` from prior read). Impact: both skip **structural noise** and **unreadable units**, but do not skip pages for "already good enough" and do not surface skip counts to the user.

- [LOW] Dolphin parallel element decode is **intra-page, same-modality batching** only: `process_element_batch` batches crops sharing one prompt (`demo_page.py:289-320`, `max_batch_size` default 4 at `demo_page.py:336-337`); modalities run serially (tabs, then equs, then codes, then text at `268-282`). MinerU batches across pages within a window but uses specialist models, not a single VLM prompt per page (except VLM/hybrid backends). Impact: parallelism patterns help throughput, not verification coverage.

## False-pass hypothesis

A 33-page WG21 paper where page 13 loses Figure 1/2 captions and Table 2 in markdown but all other pages convert cleanly: Dolphin would still emit a combined `.md` (`utils/utils.py:136-145`) with no page-level fail flag; MinerU would still `union_make` all `para_blocks` (`pipeline_middle_json_mkcontent.py:973-982`). Neither pipeline compares output against a reference text layer, so both would **pass** structurally while page 13 is wrong — same failure class as tapetum's monolithic judge, just with smaller per-region extraction calls instead of one 40k-token judge call.

## False-fail hypothesis

MinerU `batch_analyze.py:897-919` drops OCR spans with `ocr_score < 0.5` or known garbage tokens with `ocr_score < 0.8` on tall narrow boxes; a valid narrow margin note on page 1 could be removed, yielding empty `para_blocks` for that page (`union_make` skips empty pages at `979-980`), which looks like missing content in downstream diff but is a **silent drop**, not an explicit fail. Dolphin `distorted_page` fallback (`demo_page.py:207-209`) re-parses the full page as one region when layout overlap exceeds 25% (`utils/utils.py:529-531`), which can scramble reading order for dense two-column WG21 pages without failing the run.
