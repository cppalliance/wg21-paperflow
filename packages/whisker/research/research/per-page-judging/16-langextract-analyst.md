# 16 - langextract-analyst

**Verdict:** usable-with-conditions — strongest open-source precedent for chunk-scoped LLM extraction with per-chunk `char_interval` grounding and graded alignment tiers, but unit is character-buffer chunks (not pages), unaligned extractions are kept not dropped, and LCS fuzzy can mis-ground gapped spans.
**Confidence:** high

## Findings

- [CRITICAL] **Chunk unit, not page.** Documents are split by `ChunkIterator` on sentence/token boundaries up to `max_char_buffer` (default 200 in `Annotator.annotate_documents`, 1000 in `extract()`). Evidence: `chunking.py:343-506` (greedy sentence packing, newline/token splits for oversized sentences, single-token overflow chunks), `annotation.py:213` (`max_char_buffer: int = 200`), `extraction.py:53` (`max_char_buffer: int = 1000`), `_document_chunk_iterator` at `annotation.py:118-160`. Impact: adoptable pattern for our per-page judge is structural (small unit → LLM → ground → fold), but boundary logic is char-budget not page index; we must keep `textlayer.py` page list as the unit boundary.

- [CRITICAL] **No inference overlap; optional prompt-only context.** Chunks are disjoint token intervals with no shared source bytes between LLM calls. Evidence: `ChunkIterator.__next__` advances `SentenceIterator` cursor to `curr_chunk.end_index` without rewind (`chunking.py:474-476`, `493-495`); optional `context_window_chars` injects only the previous chunk's tail into the prompt via `ContextAwarePromptBuilder` (`prompting.py:258-261`, `annotation.py:242-244`, `360-363`). Impact: eliminates cross-chunk attention bleed in the model input (good for our p0957r8 failure mode), but coreference across chunk/page boundaries needs explicit context injection like langextract's `context_window_chars`, not overlapping source windows.

- [HIGH] **Three-tier per-chunk grounding with monotonic exact DP verified at `resolver.py:1113-1185`.** After each chunk's LLM parse, `resolver.align()` calls `WordAligner.align_extractions` with chunk-local offsets (`annotation.py:411-428`, `resolver.py:327-398`). Tier 1: `_apply_monotonic_exact_matches` → `_select_monotonic_matches` (`resolver.py:948-959`, `1188-1243`, `1113-1185`) picks non-overlapping exact occurrences in model output order, maximizing matched token weight. Tier 2: `difflib.SequenceMatcher` blocks assign `MATCH_EXACT` or `MATCH_LESSER` (`resolver.py:962-1019`, `1005-1014`). Tier 3: LCS fuzzy (default) or legacy sliding-window difflib on remaining unaligned only (`resolver.py:1027-1065`, `_lcs_fuzzy_align_extraction` `717-787`, `_fuzzy_align_extraction` `591-715`). Thresholds: `_FUZZY_ALIGNMENT_MIN_THRESHOLD = 0.75`, `_FUZZY_ALIGNMENT_MIN_DENSITY = 1/3` (`resolver.py:57-58`); `_accept_lcs_match` gates coverage and density (`resolver.py:1377-1404`). `char_interval` = tokenizer token char spans + `char_offset` (`resolver.py:1237-1239`, `782-785`; offset from `annotation.py:416-419`). Impact: Tier 1 monotonic DP is the highest-value transplant for tapetum evidence-quote disambiguation; Tier 3 must not be copied wholesale (gapped subsequence spans).

- [HIGH] **Unaligned extractions (`char_interval=None`) are kept, not dropped.** When all tiers fail, extraction remains in output with `char_interval=None`, `alignment_status=None`. Evidence: `core/data.py:74-76` (docstring), `resolver.py:811-813` (`align_extractions` docstring), test oracle `tests/resolver_test.py:1611-1617` ("headache and fever" → `char_interval=None`), `annotation.py:431-432` (append all aligned yields without filter). `prompt_validation.py:59` labels `alignment_status is None` as `FAILED` for few-shot validation only (`prompt_validation.py:174-187`), not pipeline drop. Impact: opposite of tapetum `ground_spans` drop-if-ungrounded (`grounding.py:49-52`); per-page judge must explicitly demote or reject `char_interval=None` extractions or risk false-pass from hallucinated entities.

- [HIGH] **Single-pass chunk fold: append in chunk order, no dedup.** Within one pass, each chunk's aligned extractions append to `per_doc[document_id]` in processing order (`annotation.py:431-432`, `307-346` emit cursor). No cross-chunk deduplication or worst-unit aggregation. Impact: document-level result is union of chunk extractions; our per-page judge needs an explicit fold (cf. tapetum `aggregate_adjudications` worst-axis) because langextract provides none.

- [MED] **Multi-pass recall via full re-extraction; first-pass-wins overlap merge.** `extraction_passes > 1` reruns the entire single-pass pipeline N times (`annotation.py:259-283`, `447-530`, `477-501`). Merge: `_merge_non_overlapping_extractions` keeps pass-0 extractions; later-pass items append only if `char_interval` does not overlap any kept interval (`annotation.py:46-84`, `87-115`). Unaligned (`char_interval=None`) never overlap (`annotation.py:99-100`), so all later-pass unaligned items always merge (`annotation_test.py:1095-1114`). Test: overlapping pass-2 extraction excluded, non-overlapping kept (`annotation_test.py:1029-1049`). Impact: recall improvement is brute-force re-prompting, not targeted gap-fill; conflict policy is first-pass-wins on spans, not confidence or severity.

- [MED] **Prompt shape is extraction, not verification.** Per chunk, `QAPromptGenerator` renders few-shot Q/A with chunk text as the question (`prompting.py:115-138`, `annotation.py:370-375`). No presence/absence check against a second document. Impact: langextract solves "extract entities from this chunk" not "does markdown preserve PDF text"; our per-page judge prompt must stay verification-shaped, borrowing only the scoping/grounding mechanics.

- [LOW] **Per-chunk failure: parse drop or raise, no schema retry.** `resolver.resolve(..., suppress_parse_errors=True)` logs and returns `[]` for parse/schema errors (`resolver.py:309-321`); default raises. Empty LLM output raises `InferenceOutputError` (`annotation.py:399-402`). HTTP retries are provider-level only. Impact: fidelity posture is partial (empty chunk silently skipped with suppress flag); our invariant is fail-the-paper, not skip-chunk.

## False-pass hypothesis

Multi-pass merge admits every later-pass extraction with `char_interval=None` because overlap check returns False when either side is None (`annotation.py:99-100`). A hallucinated entity from pass 2 that fails all alignment tiers still lands in the final `AnnotatedDocument.extractions` list alongside grounded pass-1 items. Our monolithic judge false-pass (p0957r8: `pass, missing_content: []`) would partially persist if we copied langextract's keep-ungrounded policy without a tapetum-style drop or demotion gate.

## False-fail hypothesis

LCS fuzzy rejects `"headache and fever"` against `"Patient reports back pain and a fever."` at 2/4 token coverage < 0.75 (`resolver_test.py:1601-1619`, `_accept_lcs_match` `resolver.py:1400-1404`). A valid extraction with reordering or synonym substitution that clears our document-level `partial_ratio ≥ 0.90` floor (`constants.py:50`) could still fail langextract's per-chunk token gates, losing recall at chunk boundaries.

## What would change my mind

Evidence that langextract (or a fork) filters `char_interval=None` extractions at document emit by default, with tests proving zero ungrounded items in `AnnotatedDocument.extractions` under `extract()` — would flip to **usable** for direct adoption of the full chunk→align→fold pipeline into tapetum's per-page judge.
