# 21 - steelman-monolith

**Verdict:** usable-with-conditions — keep the monolithic PDF-text judge and patch it incrementally; per-page LLM judging is not justified until a labeled holdout shows det+fusion misses defect classes that scoped calls catch at acceptable false-fail cost.
**Confidence:** medium

## Findings

- [CRITICAL] **The one verified failure (p0957r8) is already caught end-to-end without per-page LLM.** Deterministic `check_content` emitted `missing_region_count=2` on page 13 (Figure 1/2, Table 2 samples in sidecar); live re-run still has the monolith saying `pass, confidence 0.98, missing_content: []`, but fusion rule `clear_blocked_missing_region` preserves `combined_verdict=review` (`fusion.py:166-184`, `test_fusion.py:366-371`, `tapetum-golden-review-findings-2026-07-14.md:141-145`). Impact: the production false-pass that motivated per-page redesign is closed by deterministic detection + fusion guardrail; per-page LLM adds no incremental safety on this exact class.

- [CRITICAL] **Defect-class overlap: det already owns content absence; per-page LLM only plausibly adds semantic-preservation checks det cannot see.** `check_content.py` computes order-invariant `unigram_coverage`, shingle drift, and `MisalignedRegion` lists via `difflib.SequenceMatcher` inside low-coverage windows, with PDF page attribution (`check_content.py:624-650`, `_regions_from_opcodes:516-555`). Whisker hard-fails on `unigram_coverage < 0.85`; pdf_judge demotes pass→review on `content_recall < 0.85` and `text_nid < 0.80` (`pdf_judge.py:340-351`, `constants.py`). **Det catches:** dropped sections/prose/tables (token multiset gaps), localized absence with page+sample (`missing_regions`), extra markdown (`extra_regions`), structural gate failures. **Det does not catch (per-page LLM might):** token-preserving table cell swaps, wrong numeric values, math exponent collapse, code token garble with preserved lexemes, heading-level drift on PDF (HTML outline fix is HTML-only, `html_outline.py:8-14`). **Per-page LLM does not beat det on:** bulk content loss (p0957r8), TOC/furniture stripping (contract in prompt), reflow/dehyphenation (order-invariant metrics). Impact: per-page scope targets a narrow residual class; it is not the fix for the verified incident.

- [HIGH] **Latency scales ~linearly with page count under D11 serial discipline; corpus wall-clock goes from minutes to many hours.** PDF-text judge injects full RAW + full markdown in one call (~40k tokens on p0957r8, `00-baseline.md:9-12`). Authority doc documents ~28 s/call decode-dominated text-lane adjudication and states PDF-judge workload is **prefill-bound** on the doubled input (`tapetum_llm.md:31`, `:192`). Observed operator band ~8–20 s per call on alliance-pod. Per-page at 33 pages serially: **264–660 s (4.4–11 min)** at 8–20 s/call, **~924 s (~15 min)** at 28 s/call, versus **~20 s** monolith on p0957r8. Full PDF corpus (189 papers, `vlm-pdf-qa/SYNTHESIS.md:38`): if median ~20 pages, **189 × 20 × 15 s ≈ 15.8 h** per-page vs **189 × 25 s ≈ 1.3 h** monolith (incremental skip aside). Pod is hourly-billed (`whisker/CLAUDE.md:521-524`), so token cost is irrelevant, but operator iteration, re-runs after prompt changes, and debug review scale with wall-clock. Impact: per-page is an overnight-batch architecture, not a same-session QA loop.

- [HIGH] **Monolith preserves global checks per-page scoping destroys; our prompt explicitly requires them.** `JUDGE_SYSTEM_PROMPT` instructs the model to flag "real content loss, corruption, or **reordering**" and assigns `fail` when content is "substantial content missing, corrupted, or **reordered**" (`pdf_judge.py:112-116`, `:144-147`). Cross-page section order, duplicated body blocks split across pages, TOC→body heading replacement, and front-matter→YAML mapping all require seeing the whole document once. Per-page calls with page-local RAW slices cannot verify that section N on page 5 precedes section N+1 on page 6 unless aggregation reintroduces a global pass (extra complexity). Chunking precedent already warns partial views: triage chunk notes tell the model not to flag chunk-boundary artifacts (`adjudicate.py:388-392`). Impact: per-page wins local presence checks, loses reordering and global-structure fidelity the monolith prompt is written to enforce.

- [HIGH] **Per-page multiplies hallucination surface and worst-unit aggregation amplifies noise.** Monolith: one structured call, at most 5 missing-content quotes, grounded against the **whole** text layer (`pdf_judge.py:148-151`, `:326-333`, `MAX_MISSING_QUOTES=5`). Per-page: N page calls each may emit missing-content quotes → up to **5×N** candidate hallucinations before grounding; `aggregate_adjudications` folds with **worst-axis, min confidence, union of evidence** (`chunking.py:226-287`), so one spurious page-level `fail` or `review` poisons the document verdict. Single-call design caps blast radius at one completion; hybrid-llm-scoring documented 18/18 fails at confidence ≥0.95 (`00-baseline.md:54-55`), so false flags at high confidence are empirically plausible. Impact: per-page trades one attention failure for many independent false-alarm opportunities.

- [MED] **Determinism and operability regress: 33 serial calls, retries, and debug volume vs one.** D11 requires at most one in-flight LLM request (`CLAUDE.md` D11); per-page is inherently 33× serial round trips with 33× `output_retries` budgets (D10). Failure modes multiply: any page `PdfLaneError` fails the paper (fidelity policy, `pdf_judge.py:269-270`) vs one failure today. Debug/trace artifacts scale linearly with calls (`CLAUDE.md` trace/debug rules). Existing chunk aggregation (`aggregate_adjudications`) is precedent for folding, but adds code paths, page→markdown alignment, empty-page skip policy, and schema `page` provenance (`vlm-pdf-qa/SYNTHESIS.md:44`). Impact: engineering and diagnosis cost is O(pages) for marginal recall on a subset of defect classes.

- [MED] **Middle path at 1–2 monolith calls likely captures most per-page benefit without 33× cost.** (a) **In-lane coverage windows:** recompute low-coverage regions inside `judge_pdf_extraction` from the same RAW+markdown pair (same math as `check_content`, no whisker sidecar read) and either auto-demote or add a second micro-prompt listing "verify these RAW spans in markdown" — mirrors Fix 4 floors already partially wired (`content_recall`, `text_nid`). (b) **Two-pass inventory:** call 1 structured extraction from RAW only (`figures`, `tables`, numbered sections); call 2 presence-check each item against markdown — olmOCR BasePDFTest presence pattern (`00-baseline.md:49-50`) at **2×** latency not **33×**. (c) **Det-hint injection:** injecting whisker `missing_regions` into the LLM prompt **violates** text-lane independence (`adjudicate.py:378-380`: "no deterministic-lane signals (verdict, flags, metrics)"); `html_outline.py` precedent allows **source-derived metadata only** ("NOT a verdict signal", `:13-14`). Recomputing regions from source+markdown inside the PDF lane is admissible; reading det sidecar fields is not if fusion should compare independent lanes. Impact: targeted monolith patches address enumeration failure (root cause of p0957r8 in `tapetum-golden-review-findings-2026-07-14.md:21-24`) without page-sharded architecture.

- [LOW] **Prior art direction (SYNTHESIS) already chose per-page VLM transcription + deterministic diff, not per-page text judge.** `research/vlm-pdf-qa/SYNTHESIS.md` adopts olmOCR per-page **conversion** compared deterministically afterward (contender C), rejecting markdown-grounded judges that swallow image-only defects. The current per-page text-judge proposal is a TEXT-lane stopgap (`00-baseline.md:46-48`) while vision pod is absent; it duplicates det's text comparison in LLM form rather than adding an independent pixel path. Impact: per-page LLM-on-text-layer is the heaviest variant of a pattern det already implements deterministically.

## False-pass hypothesis

Per-page judge on p0957r8 page 13 with only page-13 RAW + a markdown slice that omits captions but includes nearby prose tokens false-passes Table 2: local token overlap looks adequate, column/header alignment is unchecked (same risk noted for marker table crops, `12-marker-analyst.md:23-24`), and aggregation never sees cross-page context that the full markdown lacks the entire table block.

## False-fail hypothesis

Per-page calls on pages that are mostly page furniture (running headers, "Document number:" footers) false-flag missing content when the model treats stripped furniture as defects, despite the monolith contract that furniture is "never missing content" (`pdf_judge.py:127-128`); worst-page aggregation promotes one furniture false-flag to document `review`.

## What would change my mind

A >=30-paper labeled WG21 holdout where (1) det+fusion+current pdf_judge floors miss >=10% of verified conversion defects, (2) per-page text judge catches a majority of those misses, and (3) false-fail rate stays <=~10% — measured on the same pod with serial per-page calls. Without that recall delta, monolith + in-lane two-pass inventory is the smaller honest fix.
