# P4182R0 - one-time LLM read-back validation

This is a one-time, manual empirical record. It is NOT a CI gate and is inert to
every whisker corpus loader (no `.gt.md` / `.expected.md` / `.facts.jsonl` /
`.anchors.json` suffix match). The enforced gate is the deterministic, LLM-free
`check_facts` run in `tests/test_comprehension_corpus.py` over
`P4182R0.facts.jsonl` against `P4182R0.expected.md`.

## Why this exists

The Lane 3 facts are a deterministic PROXY for "what a downstream LLM must be able to
read from the converted markdown." This document closes the loop that the
deterministic test cannot: it confirms ONCE, empirically, that a real LLM given
only the converted markdown answers the same questions the facts assert. After
this anchor, the deterministic facts stand in for the LLM in CI (determinism,
reproducibility, cost, model-sovereignty: no LLM in the scoring loop).

A round-trip "regenerate similar text" check was deliberately rejected: LLMs
paraphrase, so resemblance measures fidelity, not comprehension. The test is
question answering ("row X, column Y reads what?"), which is read -> understood
-> correct.

## Method

A fresh, isolated LLM context (subagent) received ONLY the converted markdown
(no source PDF, no facts file, no authoring rationale) plus 8 questions, and
answered blind. Answers were compared to the 8 `checked: verified` facts in
`P4182R0.facts.jsonl`.

## Questions (mapped to fact ids)

- Q1 `title-survives` (present): full document title.
- Q2 `edg-frontend` (present): who supplies the EDG C++ front end.
- Q3 `pmr-term` (present): the term for PMR / `<memory_resource>`.
- Q4 `pigweed-coro` (present): what Pigweed provides re: coroutines.
- Q5 `docnumber-label-consumed` (absent, surfaced as Q): the document number (proves front-matter metadata is readable; the absent fact itself guards that the bare label "Document Number" did not leak into the body).
- Q6 `section-flow` (order): top-level section order, Abstract -> References.
- Q7 `tableA-gpu-coro-no` (table): Table A, row "GPU device code (CUDA, SYCL)", Coro column.
- Q8 `tableB-console-alloc` (table): Table B, row "Game consoles (Xbox, PS5)", Exc and Alloc columns.

## Runs

Three blind runs, each a fresh context:

- Run 1: verbatim excerpt (tables + core sections). Result: 8/8.
- Run 2: expanded (~330 lines: all compiler-table rows, both legends, a field/value schema table as distractors). Result: 8/8.
- Run 3: byte-exact, the subagent read the real committed `P4182R0.expected.md` directly (single file confirmed, 412 lines). Result: 8/8.

All three: the blind LLM's answers were deckungsgleich with the verified facts.
The two `table` facts (Q7/Q8) are the load-bearing cases (row/column reads that
fidelity metrics can wave through); both read correctly even amid multiple
tables and legends.

## Conclusion

The converted markdown is LLM-readable for these facts, and the deterministic
facts are a faithful proxy for what the LLM actually recovers. The deterministic
gate may stand in for the LLM in CI.

## Bonus finding (not a comprehension failure)

The blind reader noted that `### 1. Disclosure` renders as a `###` subheading
under "Revision History" rather than its own `##` top-level section, despite the
"1." numbering. The LLM read it correctly and flagged the structure; this is a
candidate tomd heading-nesting observation, not a read-back failure.

## Reproduce

Deterministic gate (LLM-free, this is what CI runs):

```
uv run pytest packages/whisker/tests/test_comprehension_corpus.py
```

The blind read-back is manual: hand the contents of `P4182R0.expected.md` (only
that) plus the 8 questions above to a fresh LLM context and compare its answers
to the verified facts.
